26.4 — 类模板特化

● 机器译文 课程 26.4 查看英文原文

在上一节课 26.3 -- 函数模板特化我们看到了如何特化函数以便为特定数据类型提供不同的功能。事实证明，不仅可以特化函数，还可以特化类！

考虑这样一种情况：你想要一个存储8个对象的类。下面是一个简化的类模板来实现这一点：

#include <iostream>

template <typename T>
class Storage8
{
private:
    T m_array[8];

public:
    void set(int index, const T& value)
    {
        m_array[index] = value;
    }

    const T& get(int index) const
    {
        return m_array[index];
    }
};

int main()
{
    // 为整数定义 Storage8
    Storage8<int> intStorage;

    for (int count{ 0 }; count < 8; ++count)
        intStorage.set(count, count);

    for (int count{ 0 }; count < 8; ++count)
        std::cout << intStorage.get(count) << '\n';

    // 为 bool 定义 Storage8
    Storage8<bool> boolStorage;
    for (int count{ 0 }; count < 8; ++count)
        boolStorage.set(count, count & 3);

	std::cout << std::boolalpha;

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << boolStorage.get(count) << '\n';
    }

    return 0;
}

虽然这个类完全可用，但事实证明， Storage8<bool> 的实现效率比需要的要低。因为所有变量都必须有一个地址，而CPU无法寻址小于一个字节的内容，所以所有变量至少需要一个字节的大小。因此，一个 bool 类型的变量最终会占用整个字节，尽管从技术上讲它只需要一个位来存储其真或假值！因此，一个 bool 是1位有用信息和7位浪费空间。我们的 Storage8<bool> 类包含8个 bool，是1字节有用信息和7字节浪费空间。

事实证明，使用一些基本的位逻辑，可以将所有8个bool压缩到一个字节中，完全消除浪费的空间。然而，为了做到这一点，我们需要在使用 bool类型时重新设计类，将8个 bool 的数组替换为一个单字节大小的变量。虽然我们可以创建一个全新的类来实现这一点，但这有一个主要缺点：我们必须给它一个不同的名称。然后程序员必须记住 Storage8<T> 用于非bool类型，而 Storage8Bool （或我们命名的新类）用于 bool。这是我们宁愿避免的不必要的复杂性。幸运的是，C++为我们提供了一种更好的方法：类模板特化。

类模板特化

类模板特化允许我们为特定数据类型（或多个数据类型，如果有多个模板参数）特化一个模板类。在这种情况下，我们将使用类模板特化来编写一个自定义版本的 Storage8<bool> ，它将优先于通用的 Storage8<T> 类。

类模板特化被视为完全独立的类，尽管它们以与模板类相同的方式实例化。这意味着我们可以更改特化类的任何内容，包括其实现方式甚至其公开的函数，就像它是一个独立的类一样。

与所有模板一样，编译器必须能够看到特化的完整定义才能使用它。此外，定义类模板特化需要先定义非特化的类。

下面是一个特化的 Storage8<bool> 类：

#include <cstdint>

// 首先定义我们的非特化类模板
template <typename T>
class Storage8
{
private:
    T m_array[8];

public:
    void set(int index, const T& value)
    {
        m_array[index] = value;
    }

    const T& get(int index) const
    {
        return m_array[index];
    }
};

// 现在定义我们的特化类模板
template <> // 以下是一个没有模板参数的模板类
class Storage8<bool> // 我们正在为 bool 特化 Storage8
{
// 接下来只是标准的类实现细节

private:
    std::uint8_t m_data{};

public:
    // 不用担心这些函数实现的细节
    void set(int index, bool value)
    {
        // 找出我们要设置/清除的位
        // 这将在我们感兴趣的位上放置一个 1
        auto mask{ 1 << index };

        if (value)  // 如果我们要设置一个位
            m_data |= mask;   // 使用按位或来打开该位
        else  // 如果我们要关闭一个位
            m_data &= ~mask;  // 按位与反掩码来关闭该位
	}
	
    bool get(int index)
    {
        // 找出我们要获取的位
        auto mask{ 1 << index };
        // 按位与获取我们感兴趣的位的值
        // 然后隐式转换为布尔值
        return (m_data & mask);
    }
};

// 与之前相同的例子
int main()
{
    // 为整数定义 Storage8（实例化 Storage8<T>，其中 T = int）
    Storage8<int> intStorage;

    for (int count{ 0 }; count < 8; ++count)
    {
        intStorage.set(count, count);
	}

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << intStorage.get(count) << '\n';
    }

    // 为 bool 定义 Storage8（实例化 Storage8<bool> 特化）
    Storage8<bool> boolStorage;
    
    for (int count{ 0 }; count < 8; ++count)
    {
        boolStorage.set(count, count & 3);
    }

	std::cout << std::boolalpha;

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << boolStorage.get(count) << '\n';
    }

    return 0;
}

首先，注意我们的特化类模板以 template<>开头。template关键字告诉编译器接下来是一个模板，而空的尖括号表示没有任何模板参数。在这种情况下，没有模板参数，因为我们正在用特定类型（T）替换唯一的模板参数（bool)。

）。接下来，我们在类名后面加上 <bool> 来表示我们正在特化一个 bool 版本的 class Storage8。

所有其他更改只是类实现细节。你不需要理解位逻辑如何工作就能使用这个类（不过如果你想弄清楚，但需要复习位运算符的工作原理，可以查看 O.2 -- 位运算符 ）。

注意，这个特化类使用了一个 std::uint8_t （1字节无符号整数）而不是8个 bool 的数组（8字节）。

现在，当我们实例化一个类型为 Storage<T>，其中 T 不是 bool的对象时，我们将得到一个从通用模板化的 Storage8<T> 类中生成的版本。当我们实例化一个类型为 Storage8<bool>的对象时，我们将得到我们刚刚创建的特化版本。注意，我们保持了两个类的公开接口相同——虽然C++允许我们自由地添加、删除或更改 Storage8<bool> 的函数，但保持一致的接口意味着程序员可以以完全相同的方式使用任何一个类。

特化成员函数

在上一课中，我们介绍了这个例子：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

int main()
{
    // 定义一些存储单位
    Storage i { 5 };
    Storage d { 6.7 };

    // 打印一些值
    i.print();
    d.print();
}

我们的愿望是特化 print() 函数，使其以科学计数法打印 double。使用类模板特化，我们可以为 Storage<double>：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

// Storage<double> 的显式类模板特化
// 注意这有多冗余
template <>
class Storage<double>
{
private:
    double m_value {};
public:
    Storage(double value)
      : m_value { value }
    {
    }

    void print();
};

// 我们将在类外部定义它，原因很快就会明了
// 这是一个普通（非特化）成员函数定义（针对特化类 Storage<double> 的成员函数 print）
void Storage<double>::print()
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    // 定义一些存储单位
    Storage i { 5 };
    Storage d { 6.7 }; // 使用显式特化 Storage<double>

    // 打印一些值
    i.print(); // 调用 Storage<int>::print（从 Storage<T> 实例化而来）
    d.print(); // 调用 Storage<double>::print（从 Storage<double> 的显式特化中调用）
}

然而，请注意这里有多少冗余。我们重复了整个类定义，仅仅是为了改变一个成员函数！

幸运的是，我们可以做得更好。C++ 并不要求我们显式特化 Storage<double> 显式特化 Storage<double>::print()。相反，我们可以让编译器隐式特化 Storage<double> 从 Storage<T>，并仅提供 Storage<double>::print()的显式特化！如下所示：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

// 这是一个特化的成员函数定义
// 显式函数特化不是隐式内联的，因此如果放在头文件中，请将其设为内联
template<>
void Storage<double>::print()
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    // 定义一些存储单位
    Storage i { 5 };
    Storage d { 6.7 }; // 将导致 Storage<double> 被隐式实例化

    // 打印一些值
    i.print(); // 调用 Storage<int>::print（从 Storage<T> 实例化而来）
    d.print(); // 调用 Storage<double>::print（从 Storage<double>::print() 的显式特化中调用）
}

就是这样！

正如前一课（26.3 -- 函数模板特化）所述，显式函数特化不是隐式内联的，因此如果我们在头文件中定义 Storage<double>::print() 的特化，应将其标记为 inline。

在哪里定义类模板特化

为了使用特化，编译器必须能够看到非特化类和特化类的完整定义。如果编译器只能看到非特化类的定义，它将使用非特化版本而不是特化版本。

因此，特化类和函数通常定义在头文件中，紧接在非特化类定义的下方，这样包含单个头文件就同时包含了非特化类和任何特化。这确保了只要非特化类可见，特化也始终可见。

如果特化仅在一个翻译单元中需要，它可以定义在该翻译单元的源文件中。由于其他翻译单元无法看到特化的定义，它们将继续使用非特化版本。

要警惕将特化放在单独的头文件中，意图在需要特化的翻译单元中包含该特化头文件。设计代码透明地根据头文件的存在与否改变行为是一个坏主意。例如，如果你打算使用特化但忘记包含特化头文件，你可能会最终使用非特化版本。如果你打算使用非特化版本，但其他头文件作为传递包含包含了特化，你可能会意外使用特化。
