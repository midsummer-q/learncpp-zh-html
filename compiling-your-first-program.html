0.7 — 编译你的第一个程序

● 机器译文 课程 0.7 查看英文原文

在我们编写第一个程序之前，需要学习如何在集成开发环境（IDE）中创建新程序。在本课中，我们将介绍具体方法，你还会编译并执行你的第一个程序！

项目

要在 IDE 中编写 C++ 程序，我们通常从创建一个新项目开始（稍后会演示具体操作）。一个 项目 是一个容器，用于存放生成可执行文件（或库、网站等）所需的所有源代码文件、图像、数据文件等。项目还会保存各种 IDE、编译器和链接器设置，以及记录你上次的工作位置，这样当你稍后重新打开项目时，IDE 的状态可以恢复到上次离开的地方。当你选择编译程序时，项目中的所有 .cpp 文件都会被编译并链接。

每个项目对应一个程序。当你准备创建第二个程序时，要么创建一个新项目，要么覆盖现有项目中的代码（如果你想保留原有内容则不能这样做）。项目文件通常与特定 IDE 绑定，因此为一个 IDE 创建的项目需要在另一个 IDE 中重新创建。

最佳实践

为每个新程序创建一个新项目。

控制台项目

创建新项目时，通常会被询问要创建什么类型的项目。本教程中我们将创建的所有项目都是控制台项目。一个 控制台项目 意味着我们将创建可以在 Windows、Linux 或 Mac 控制台中运行的程序。

下面是 Windows 控制台的截图：

默认情况下，控制台应用程序没有图形用户界面（GUI），它们向控制台输出文本、从键盘读取输入，并编译成独立的可执行文件。这对学习 C++ 非常理想，因为它将复杂性降到最低，并确保在各种系统上都能工作。

如果你从未使用过控制台，或者不知道如何访问它，也不必担心。我们将通过 IDE 编译和启动程序（必要时 IDE 会调用控制台）。

工作区/解决方案

当你为程序创建新项目时，许多 IDE 会自动将项目添加到“工作区”或“解决方案”（术语因 IDE 而异）。工作区或解决方案是一个容器，可以包含一个或多个相关项目。例如，如果你正在编写一个游戏，并且希望为单人模式和多人模式分别创建独立的可执行文件，就需要创建两个项目。这两个项目完全独立并不合理——毕竟它们属于同一个游戏。很可能，每个项目都会配置为同一个工作区/解决方案中的独立项目。

虽然你可以将多个项目添加到同一个解决方案中，但我们通常建议为每个程序创建一个新的工作区或解决方案，尤其是在学习阶段。这样更简单，出错的可能性也更小。

问：什么是预编译头？我们为什么要关闭它们？

在大型项目（即包含许多代码文件的项目）中，预编译头可以通过避免大型项目中容易发生的一些冗余编译来提高编译速度。

然而，使用预编译头需要额外的工作，对于小型项目（例如您在本教程中创建的项目），对编译时间几乎没有影响。

因此，我们建议最初关闭预编译头，只有当您发现编译时间变慢时才启用它们。

如果编译失败

没关系，深呼吸一下。我们很可能能解决它。:)

首先，查看编译器给出的错误信息。最常情况下，它会包含一个行号，指示哪一行出错。检查该行及其周围的行，确保没有拼写错误或打字错误。同时确保你没有在代码中包含行号（你的编辑器应该会提供这些）。

其次，查看课程中的问答部分 0.8 -- 一些常见的C++问题，你的问题可能在那里有覆盖。

第三，阅读包含你正在编译的示例课程下方的评论——可能有人遇到过相同的问题并提供了解决方案。

最后，如果上述方法都失败了，尝试在你喜欢的搜索引擎上搜索你的错误信息。很可能之前有人遇到过这个问题并找到了解决方法。

如果你的程序运行但控制台窗口一闪而过并立即关闭

当一个控制台程序运行时，控制台窗口会打开，程序的任何输出都会被写入控制台窗口。

当程序运行完毕后，大多数现代IDE会保持控制台打开（直到你按下一个键），以便你在继续之前检查程序的结果。然而，一些较旧的IDE会在程序运行结束时自动关闭控制台窗口。这通常不是你想要的。

如果你的IDE自动关闭控制台窗口，可以使用以下两个步骤来确保控制台在程序结束时暂停。

首先，添加或确保以下代码行位于程序顶部附近：

#include <iostream>
#include <limits>

其次，在main()函数的末尾（就在return语句之前）添加以下代码：

std::cin.clear(); // 重置任何错误标志
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // 忽略输入缓冲区中的所有字符，直到找到换行符
std::cin.get(); // 从用户处获取一个字符（等待用户按下回车）

这将导致你的程序在继续之前等待用户按下回车键（你可能需要按两次回车键），这会使你有时间在IDE关闭控制台窗口之前检查程序的输出。

其他解决方案，例如通常建议的 system("pause") 方案可能只适用于某些操作系统，应避免使用。

如果控制台窗口根本没有打开，并且你的程序似乎没有运行，那么你的防病毒或反恶意软件可能也在阻止程序的执行。如果是这种情况，请尝试暂时禁用扫描器，看看问题是否解决，或者将项目目录排除在扫描范围之外。

提示

如果你正在使用防病毒或反恶意软件，建议将项目目录排除在扫描范围之外，因为编译和调试可能会引起误报。

我的 IDE 中编译、构建、重新生成、清理和运行/启动选项之间有什么区别？

在课程 0.5 -- 编译器、链接器和库简介中，我们展示了为了生成一个可运行的可执行文件，程序中的每个代码文件被编译成一个目标文件，然后这些目标文件被链接成一个可执行文件。

当代码文件被编译时，你的 IDE 可能会缓存（保存）生成的目标文件到磁盘。 缓存 （发音类似“cash”）是一种存储位置，用于存储经常访问的数据，以便后续快速检索。这样，如果将来再次编译程序，任何未修改的代码文件都不需要重新编译——上次的缓存目标文件可以被重用（而不必重新生成）。这可以显著加快编译速度（代价是占用一点磁盘空间）。

考虑到这一点，以下是每个选项通常的作用：

  • 构建 编译项目或工作区/解决方案中所有 修改过的 代码文件，然后将目标文件链接成一个可执行文件。如果自上次构建以来没有代码文件被修改，该选项不做任何事情。
  • 清理 删除所有缓存的目标文件和可执行文件，使得下次构建项目时所有文件都将被重新编译并生成一个新的可执行文件。
  • 重新生成 执行一次“清理”，然后执行一次“构建”。
  • 编译 重新编译单个代码文件（无论之前是否被缓存）。此选项不会调用链接器或生成可执行文件。
  • 运行/启动 执行先前构建生成的可执行文件。某些IDE（例如Visual Studio）会在执行“运行”前先调用“构建”以确保你运行的是最新版本的代码。其他IDE（例如Code::Blocks）则只会直接执行先前生成的可执行文件。

虽然我们非正式地谈论“编译”我们的程序，但实际上要编译程序，我们通常会选择IDE中的“构建”（或“运行”）选项来完成。
