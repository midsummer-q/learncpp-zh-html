F.3 — Constexpr函数（第三部分）和consteval

● 机器译文 课程 F.3 查看英文原文

强制constexpr函数在编译时求值

没有办法告诉编译器，constexpr函数应尽可能在编译时求值（例如，当constexpr函数的返回值用于非常量表达式时）。

然而，我们可以通过确保返回值用于需要常量表达式的地方，来强制一个符合编译时求值条件的constexpr函数实际在编译时求值。这需要在每次调用时单独处理。

最常见的方法是使用返回值初始化一个constexpr变量（这就是为什么我们在之前的例子中一直使用变量'g'）。不幸的是，这需要我们在程序中引入一个新变量来确保编译时求值，这既丑陋又降低了代码的可读性。

人们尝试过几种hacky的方法来解决每次强制编译时求值时引入新constexpr变量的问题。参见 这里 和 这里。

然而，在C++20中，有一个更好的解决方案来解决这个问题，我们稍后将介绍。

Consteval C++20

C++20引入了关键字 consteval，用于指示函数 必须 必须在编译时求值，否则将导致编译错误。这样的函数称为 立即函数。

#include <iostream>

consteval int greater(int x, int y) // Constexpr 函数（第 4 部分）
{
    return (x > y ? x : y);
}

int main()
{
    constexpr int g { greater(5, 6) };              // 函数现在是 consteval
    std::cout << g << '\n';

    std::cout << greater(5, 6) << " is greater!\n"; // 函数现在是 consteval

    int x{ 5 }; // 不是 constexpr
    std::cout << greater(x, 6) << " is greater!\n"; // ok：将在编译时求值

    return 0;
}

在上面的例子中，前两次调用 greater() 将在编译时求值。对 greater(x, 6) 的调用无法在编译时求值，因此会导致编译错误。

最佳实践

使用 consteval 如果你有一个函数由于某种原因必须在编译时求值（例如，因为它执行只能在编译时完成的操作）。

也许令人惊讶的是，consteval函数的参数不是constexpr（即使consteval函数只能在编译时求值）。这个决定是为了保持一致性。

判断constexpr函数调用是在编译时还是运行时求值

C++目前没有提供任何可靠的机制来实现这一点。

那么 std::is_constant_evaluated 或 if consteval？ 高级

这两种能力都不能告诉你函数调用是在编译时还是运行时求值。

std::is_constant_evaluated() （定义在<type_traits>头文件中）返回一个 bool ，指示当前函数是否在常量求值上下文中执行。 常量求值上下文 （也称为 常量上下文）定义为需要常量表达式的上下文（例如constexpr变量的初始化）。因此，在编译器必须在编译时求值常量表达式的情况下 std::is_constant_evaluated() 会 true 如预期的那样。

这旨在允许你执行类似以下操作：

#include <type_traits> // for std::is_constant_evaluated()

constexpr int someFunction()
{
    if (std::is_constant_evaluated()) // 错误：consteval 函数必须在编译时求值
        doSomething();
    else
        doSomethingElse();
}

然而，编译器也可能在不需要常量表达式的上下文中选择在编译时求值constexpr函数。在这种情况下， std::is_constant_evaluated() 将返回 false ，即使函数确实在编译时求值。所以 std::is_constant_evaluated() 实际上意味着“编译器被强制在编译时求值”，而不是“正在编译时求值”。

关键提示

虽然这看起来可能很奇怪，但有以下几个原因：

  1. 正如 提出该特性的论文 所指出的，标准实际上并没有区分“编译时”和“运行时”。定义涉及这种区别的行为将是一个更大的变化。
  2. 优化不应改变程序的可观察行为（除非标准明确允许）。如果 std::is_constant_evaluated() 在函数因任何原因在编译时求值时返回 true ，那么优化器决定在编译时而不是运行时求值函数可能会改变函数的可观察行为。因此，你的程序可能会根据编译时的优化级别而有截然不同的行为！

虽然这可以通过多种方式解决，但这些方式会给优化器增加额外的复杂性，和/或限制其优化某些情况的能力。

C++23 引入， if consteval 是 if (std::is_constant_evaluated()) 的替代品，提供了更简洁的语法并修复了一些其他问题。然而，它的求值方式相同。

使用 consteval 强制 constexpr 在编译时执行 C++20

consteval 函数的缺点是此类函数不能在运行时求值，这使得它们不如 constexpr 函数灵活，后者可以两者兼顾。因此，仍然需要一种方便的方法来强制 constexpr 函数在编译时求值（即使返回值用于不需要常量表达式的地方），以便我们可以在可能时显式强制编译时求值，而在不能时使用运行时求值。

下面是一个示例，展示了如何实现这一点：

#include <iostream>

#define CONSTEVAL(...) [] consteval { return __VA_ARGS__; }()               // 如果在常量上下文中求值
#define CONSTEVAL11(...) [] { constexpr auto _ = __VA_ARGS__; return _; }() // C++20 版本，作者 Jan Scultke (https://stackoverflow.com/a/77107431/460250)

// C++11 版本，作者 Justin (https://stackoverflow.com/a/63637573/460250)
// 如果在常量上下文中执行，此函数返回两个数中的较大者
constexpr int compare(int x, int y) // 否则返回较小者
{
    if (std::is_constant_evaluated())
        return (x > y ? x : y);
    else
        return (x < y ? x : y);
}

int main()
{
    int x { 5 };
    std::cout << compare(x, 6) << '\n';                  // 函数是 constexpr

    std::cout << compare(5, 6) << '\n';                  // 将在运行时执行并返回 5
    std::cout << CONSTEVAL(compare(5, 6)) << '\n';       // 可能或可能不在编译时执行，但总是返回 5
    

    return 0;
}

对于 gcc 用户

以下方法也应该有效（并且更简洁，因为它不使用预处理器宏）：

#include <iostream>

// 将始终在编译时执行并返回 6
// 使用缩写函数模板（C++20）和 `auto` 返回类型使此函数适用于任何类型的值
// 有关更多信息，请参阅下面的“相关内容”框（你不需要了解这些函数的工作原理即可使用此函数）
consteval auto CONSTEVAL(auto value)
{
    return value;
}

// C++11 版本，作者 Justin (https://stackoverflow.com/a/63637573/460250)
// 如果在常量上下文中执行，此函数返回两个数中的较大者
constexpr int compare(int x, int y) // 否则返回较小者
{
    if (std::is_constant_evaluated())
        return (x > y ? x : y);
    else
        return (x < y ? x : y);
}

int main()
{
    std::cout << CONSTEVAL(compare(5, 6)) << '\n';       // 我们选择使用大写名称以与前面的示例保持一致，但也更容易看到调用

    return 0;
}
