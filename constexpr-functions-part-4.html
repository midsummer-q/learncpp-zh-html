F.4 — Constexpr 函数（第 4 部分）

● 机器译文 课程 F.4 查看英文原文

Constexpr/consteval 函数可以使用非常量局部变量

在 constexpr 或 consteval 函数内部，我们可以使用不是 constexpr 的局部变量，并且这些变量的值可以被改变。

举一个简单的例子：

#include <iostream>

consteval int doSomething(int x, int y) // 函数是 consteval
{
    x = x + 2;       // 我们可以修改非 const 函数参数的值

    int z { x + y }; // 我们可以实例化非 const 局部变量
    if (x > y)
        z = z - 1;   // 然后修改它们的值

    return z;
}

int main()
{
    constexpr int g { doSomething(5, 6) };
    std::cout << g << '\n';

    return 0;
}

当此类函数在编译时求值时，编译器将本质上“执行”该函数并返回计算出的值。

Constexpr/consteval 函数可以使用函数参数和局部变量作为 constexpr 函数调用的参数

上面我们提到，“当 constexpr（或 consteval）函数在编译时求值时，它调用的任何其他函数都必须在编译时求值。”

也许令人惊讶的是，constexpr 或 consteval 函数可以使用其函数参数（不是 constexpr）甚至局部变量（可能根本不是 const）作为 constexpr 函数调用的参数。当 constexpr 或 consteval 函数在编译时求值时，所有函数参数和局部变量的值必须对编译器已知（否则无法在编译时求值）。因此，在这种特定上下文中，C++ 允许将这些值用作 constexpr 函数调用的参数，并且该 constexpr 函数调用仍然可以在编译时求值。

#include <iostream>

constexpr int goo(int c) // goo() 现在是 constexpr
{
    return c;
}

constexpr int foo(int b) // 在 foo() 中，b 不是常量表达式
{
    return goo(b);       // 如果 foo() 在编译时解析，那么 `goo(b)` 也可以在编译时解析
}

int main()
{
    std::cout << foo(5);
    
    return 0;
}

在上面的例子中， foo(5) 可能会或可能不会在编译时求值。如果是，那么编译器知道 b 等于 5。尽管 b 不是 constexpr，但编译器可以将对 goo(b) 的调用视为 goo(5) 并在编译时求值该函数调用。如果 foo(5) 在运行时解析，那么 goo(b) 也将在运行时解析。

constexpr 函数可以调用非 constexpr 函数吗？

答案是肯定的，但仅当 constexpr 函数在非常量上下文中求值时。当 constexpr 函数在常量上下文中求值时，不能调用非 constexpr 函数（因为那样 constexpr 函数将无法产生编译时常量值），这样做会产生编译错误。

允许调用非 constexpr 函数是为了让 constexpr 函数可以执行类似这样的操作：

#include <type_traits> // for std::is_constant_evaluated

constexpr int someFunction()
{
    if (std::is_constant_evaluated()) // 错误：consteval 函数必须在编译时求值
        return someConstexprFcn();
    else
        return someNonConstexprFcn();
}

现在考虑这个变体：

constexpr int someFunction(bool b)
{
    if (b)
        return someConstexprFcn();
    else
        return someNonConstexprFcn();
}

这是合法的，只要 someFunction(false) 从未在常量表达式中被调用。

顺便说一句……

在 C++23 之前，C++ 标准规定 constexpr 函数必须至少对一组参数返回 constexpr 值，否则在技术上是不良格式的。在 constexpr 函数中无条件调用非 constexpr 函数会使该 constexpr 函数成为不良格式。然而，编译器不需要为此类情况生成错误或警告——因此，除非你尝试在常量上下文中调用这样的 constexpr 函数，否则编译器可能不会报错。在 C++23 中，这一要求被撤销了。

为了获得最佳效果，我们建议如下：

  1. 如果可能，避免在 constexpr 函数内部调用非 constexpr 函数。
  2. 如果你的 constexpr 函数需要为常量上下文和非常量上下文提供不同的行为，请使用 if (std::is_constant_evaluated()) （C++20 中）或 if consteval （C++23 起）来条件化行为。
  3. 始终在常量上下文中测试你的 constexpr 函数，因为它们在非常量上下文中调用时可能工作，但在常量上下文中可能失败。

何时应该将函数设为 constexpr？

作为一般规则，如果一个函数可以作为所需常量表达式的一部分求值，那么它应该被设为 constexpr。

一个 纯函数 是满足以下条件的函数：

  • 给定相同的参数，该函数总是返回相同的结果
  • 该函数没有副作用（例如，它不改变静态局部变量或全局变量的值，不进行输入或输出等）。

纯函数通常应该被设为 constexpr。

顺便说一句……

Constexpr 函数并不总是需要是纯函数。在 C++23 中，constexpr 函数可以使用和修改静态局部变量。由于静态局部变量的值在函数调用之间持续存在，修改静态局部变量被视为副作用。

也就是说，如果你的程序很简单或是一次性的，并且你没有将函数设为 constexpr，世界也不会因此毁灭。希望如此。

最佳实践

除非你有特定的理由不这样做，否则一个可以作为常量表达式一部分求值的函数应该被设为 constexpr （即使它当前没有以那种方式使用）。

一个不能作为所需常量表达式一部分求值的函数不应被标记为 constexpr。

为什么不把每个函数都设为 constexpr？

有几个原因你可能不想把 constexpr 一个函数：

  1. constexpr 表明一个函数可以在常量表达式中使用。如果你的函数不能作为常量表达式的一部分求值，它就不应该被标记为 constexpr。
  2. constexpr 是函数接口的一部分。一旦一个函数被设为 constexpr，它就可以被其他 constexpr 函数调用，或者在需要常量表达式的上下文中使用。移除 constexpr 以后会破坏这样的代码。
  3. constexpr 函数可能更难调试，因为你不能在调试器中设置断点或单步执行它们。

如果一个函数实际上不在编译时求值，为什么还要把它设为 constexpr？

新程序员有时会问：“如果一个函数只在运行时求值（例如，因为函数调用中的参数是非 const 的），为什么我还要把它设为 constexpr？”

有几个原因：

  1. 使用 constexpr 几乎没有缺点，而且它可能帮助编译器优化你的程序，使其更小更快。
  2. 仅仅因为你目前没有在编译时可求值的上下文中调用该函数，并不意味着当你修改或扩展程序时你不会在这样的上下文中调用它。如果你还没有把函数设为 constexpr，当你开始在这样的上下文中调用它时，你可能不会想到要这样做，然后你就会错过性能提升。或者，当你需要在某个需要常量表达式的上下文中使用返回值时，你可能被迫以后才把它设为 constexpr。
  3. 重复有助于巩固最佳实践。

在一个非平凡的项目中，以函数将来可能被重用（或扩展）的心态来实现它们是一个好主意。每次修改现有函数时，你都有破坏它的风险，这意味着它需要重新测试，这需要时间和精力。花一两分钟“第一次就做对”通常是值得的，这样你以后就不必重做（并重新测试）了。
