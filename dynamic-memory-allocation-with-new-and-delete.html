19.1 — 使用 new 和 delete 进行动态内存分配

● 机器译文 课程 19.1 查看英文原文

动态内存分配的必要性

C++ 支持三种基本的内存分配方式，其中你已经见过两种。

  • 静态内存分配 发生在静态变量和全局变量上。这些类型的变量在程序运行时分配一次内存，并在程序的整个生命周期中持续存在。
  • 自动内存分配 发生在函数参数和局部变量上。这些类型的变量在进入相关块时分配内存，在退出块时释放内存，根据需要重复多次。
  • 动态内存分配 是本文的主题。

静态分配和自动分配有两个共同点：

  • 变量/数组的大小必须在编译时已知。
  • 内存分配和释放自动发生（当变量被实例化/销毁时）。

大多数情况下，这没问题。然而，你会遇到一些情况，其中一个或两个约束会导致问题，通常是在处理外部（用户或文件）输入时。

例如，我们可能想用一个字符串来存储某人的名字，但在他们输入之前我们不知道名字有多长。或者我们可能想从磁盘读取一些记录，但事先不知道有多少条记录。或者我们可能正在创建一个游戏，其中有数量可变的怪物（随着时间推移，一些怪物死亡，新的怪物生成）试图杀死玩家。

如果我们必须在编译时声明所有内容的大小，我们最多只能尝试猜测所需变量的最大尺寸，并希望这足够：

char name[25]; // 希望他们的名字少于25个字符！
Record record[500]; // 希望记录少于500条！
Monster monster[40]; // 最多40个怪物
Polygon rendering[30000]; // 这个3D渲染最好不超过30,000个多边形！

这是一个糟糕的解决方案，至少有四个原因：

首先，如果变量实际上没有被使用，会导致内存浪费。例如，如果我们为每个名字分配 25 个字符，但名字平均只有 12 个字符长，那么我们使用的内存是实际需要的两倍多。或者考虑上面的渲染数组：如果一次渲染只使用 10,000 个多边形，那么我们有 20,000 个多边形的内存没有被使用！

其次，我们如何判断哪些内存位实际上被使用了？对于字符串来说很容易：以 \0 开头的字符串显然没有被使用。但是 monster[24] 呢？它现在是活着还是死了？它甚至是否已经被初始化？这需要某种方式来告诉每个怪物的状态，这增加了复杂性，并且可能消耗额外的内存。

第三，大多数普通变量（包括固定数组）分配在内存的一个称为 栈的区域中。程序的栈内存量通常相当小——Visual Studio 默认栈大小为 1MB。如果超过这个数字，就会发生栈溢出，操作系统可能会关闭程序。

在 Visual Studio 上，运行这个程序时你可以看到这种情况发生：

int main()
{
    int array[1000000]; // 分配100万个整数（大概4MB内存）
}

对于许多程序，尤其是那些处理图形的程序，限制在 1MB 内存内会有问题。

第四，也是最重要的，它可能导致人为限制和/或数组溢出。当用户试图从磁盘读取 600 条记录，但我们只为最多 500 条记录分配了内存时，会发生什么？要么我们必须给用户一个错误，只读取 500 条记录，或者（在最坏的情况下，我们没有处理这种情况）溢出记录数组并看到一些不好的事情发生。

幸运的是，这些问题可以通过动态内存分配轻松解决。 动态内存分配 是运行中的程序在需要时向操作系统请求内存的一种方式。这种内存不是来自程序有限的栈内存——而是来自一个更大的由操作系统管理的内存池，称为 堆。在现代机器上，堆的大小可以达到千兆字节。

动态分配单个变量

要动态分配一个 单个 变量，我们使用 新建 运算符的标量（非数组）形式：

new int; // 动态分配一个整数（并丢弃结果）

在上面的例子中，我们向操作系统请求一个整数的内存。new 运算符使用该内存创建对象，然后返回一个包含已分配内存 地址 地址的指针。

大多数情况下，我们会将返回值赋给我们自己的指针变量，以便稍后访问分配的内存。

int* ptr{ new int }; // 动态分配一个整数并将地址赋给ptr以便稍后访问

然后我们可以解引用指针来访问内存：

*ptr = 7; // 将值7赋给分配的内存

如果之前还不清楚，现在应该至少明白指针在一种情况下的用处了。如果没有指针来保存刚刚分配的内存的地址，我们将无法访问刚刚为我们分配的内存！

注意，访问堆分配的对象通常比访问栈分配的对象慢。因为编译器知道栈分配对象的地址，它可以直接到该地址获取值。堆分配的对象通常通过指针访问。这需要两步：一步获取对象的地址（从指针），另一步获取值。

动态内存分配是如何工作的？

你的计算机有内存（可能很多）可供应用程序使用。当你运行一个应用程序时，你的操作系统将应用程序加载到部分内存中。应用程序使用的这块内存被分成不同的区域，每个区域有不同的用途。一个区域包含你的代码。另一个区域用于正常操作（跟踪哪些函数被调用，创建和销毁全局和局部变量等）。我们稍后会详细讨论这些。然而，大部分可用内存只是闲置在那里，等待分配给请求它的程序。

当你动态分配内存时，你是在请求操作系统为你的程序保留一些内存。如果它能满足这个请求，它将返回该内存的地址给你的应用程序。从那时起，你的应用程序可以随意使用这块内存。当你的应用程序用完内存后，它可以将内存返回给操作系统，以便分配给另一个程序。

与静态或自动内存不同，程序本身负责请求和释放动态分配的内存。

关键提示

栈对象的分配和释放是自动完成的。我们无需处理内存地址——编译器编写的代码可以为我们完成这些工作。

堆对象的分配和释放不是自动完成的。我们需要参与其中。这意味着我们需要一种明确的方式来引用特定的堆分配对象，以便在准备好时请求销毁它。而引用这类对象的方式就是通过内存地址。

当我们使用 operator new 时，它会返回一个包含新分配对象内存地址的指针。我们通常希望将其存储在一个指针中，以便稍后使用该地址访问对象（并最终请求销毁它）。

初始化动态分配的变量

当你动态分配一个变量时，你也可以通过直接初始化或统一初始化来初始化它：

int* ptr1{ new int (5) }; // 使用直接初始化
int* ptr2{ new int { 6 } }; // 使用统一初始化

删除单个变量

当我们用完一个动态分配的变量时，需要明确告诉 C++ 释放内存以供重用。对于单个变量，这是通过标量（非数组）形式的 delete 运算符的标量（非数组）形式：

// 假设ptr之前已通过operator new分配
delete ptr; // 将ptr指向的内存归还给操作系统
ptr = nullptr; // 将ptr设置为空指针

删除内存意味着什么？

delete 运算符并不 实际 删除任何东西。它只是将所指向的内存返回给操作系统。然后操作系统可以自由地将该内存重新分配给另一个应用程序（或稍后再次分配给此应用程序）。

虽然语法看起来像是在删除一个 变量，但事实并非如此！指针变量仍然具有与之前相同的作用域，并且可以像任何其他变量一样被赋予新值（例如 nullptr）。

请注意，删除一个不指向动态分配内存的指针可能会导致不良后果。

悬空指针

C++ 不保证已释放内存的内容或正在删除的指针的值会发生什么。在大多数情况下，返回给操作系统的内存将包含与返回前相同的值，并且指针将指向现在已释放的内存。

指向已释放内存的指针称为 悬空指针。解引用或删除悬垂指针将导致未定义行为。考虑以下程序：

#include <iostream>

int main()
{
    int* ptr{ new int }; // 动态分配一个整数
    *ptr = 7; // 在该内存位置放入一个值

    delete ptr; // 将内存归还给操作系统。ptr现在是一个悬空指针。

    std::cout << *ptr; // 解引用悬空指针会导致未定义行为
    delete ptr; // 再次尝试释放该内存也会导致未定义行为。

    return 0;
}

在上面的程序中，之前分配给该内存的值 7 可能仍然存在，但该内存地址的值可能已经改变。该内存也可能被分配给另一个应用程序（或操作系统自身使用），尝试访问该内存将导致操作系统关闭程序。

释放内存可能会创建多个悬垂指针。考虑以下示例：

#include <iostream>

int main()
{
    int* ptr{ new int{} }; // 动态分配一个整数
    int* otherPtr{ ptr }; // otherPtr现在指向同一个内存位置

    delete ptr; // 将内存归还给操作系统。ptr和otherPtr现在都是悬空指针。
    ptr = nullptr; // ptr现在是一个nullptr

    // 然而，otherPtr仍然是一个悬空指针！

    return 0;
}

这里有一些最佳实践可以提供帮助。

首先，尽量避免多个指针指向同一块动态内存。如果无法避免，要明确哪个指针“拥有”该内存（并负责删除它），哪些指针只是访问它。

其次，当你删除一个指针时，如果该指针不会立即超出作用域，请将其设置为 nullptr。我们稍后会详细讨论空指针以及它们为什么有用。

最佳实践

将已删除的指针设置为 nullptr，除非它们即将超出作用域。

Operator new 可能失败

当向操作系统请求内存时，在极少数情况下，操作系统可能没有内存来满足请求。

默认情况下，如果 new 失败，会抛出 bad_alloc 异常。如果这个异常没有被正确处理（由于我们尚未涉及异常或异常处理，它不会被处理），程序将因未处理的异常错误而终止（崩溃）。

在许多情况下，让 new 抛出异常（或让程序崩溃）是不可取的，因此可以使用 new 的另一种形式，告诉 new 在无法分配内存时返回空指针。这通过在 new 关键字和分配类型之间添加常量 std::nothrow 来实现：

int* value { new (std::nothrow) int }; // 如果整数分配失败，value 将被设置为空指针

在上面的示例中，如果 new 无法分配内存，它将返回一个空指针而不是分配的内存地址。

请注意，如果你随后尝试解引用此指针，将导致未定义行为（很可能程序会崩溃）。因此，最佳实践是在使用分配的内存之前检查所有内存请求以确保它们实际成功。

int* value { new (std::nothrow) int{} }; // 请求一个整数的内存空间
if (!value) // 处理 new 返回空的情况
{
    // 在此处进行错误处理
    std::cerr << "Could not allocate memory\n";
}

因为向 new 请求内存很少失败（在开发环境中几乎从不失败），所以很容易忘记进行此检查！

空指针和动态内存分配

空指针（设置为 nullptr 的指针）在处理动态内存分配时特别有用。在动态内存分配的上下文中，空指针基本上表示“没有内存分配给这个指针”。这允许我们做诸如条件分配内存之类的事情：

// 如果 ptr 尚未分配，则分配它
if (!ptr)
    ptr = new int;

删除空指针没有效果。因此，不需要以下代码：

if (ptr) // 如果 ptr 不是空指针
    delete ptr; // 删除它
// 否则什么也不做

相反，你可以直接写：

delete ptr;

如果 ptr 非空，动态分配的内存将被删除。如果 ptr 为空，什么也不会发生。

最佳实践

删除空指针是安全的，并且什么也不做。无需对 delete 语句进行条件判断。

内存泄漏

动态分配的内存会一直保持分配状态，直到被显式释放或程序结束（操作系统会清理它，假设你的操作系统会这样做）。然而，用于保存动态分配内存地址的指针遵循局部变量的正常作用域规则。这种不匹配可能会引发有趣的问题。

考虑以下函数：

void doSomething()
{
    int* ptr{ new int{} };
}

这个函数动态分配了一个整数，但从未使用 delete 释放它。由于指针变量只是普通变量，当函数结束时，ptr 将超出作用域。而因为 ptr 是唯一保存动态分配整数地址的变量，当 ptr 被销毁时，就没有对动态分配内存的引用了。这意味着程序现在“丢失”了动态分配内存的地址。因此，这个动态分配的整数无法被删除。

这被称为 内存泄漏。当你的程序在将动态分配的内存归还给操作系统之前丢失了它的地址时，就会发生内存泄漏。发生这种情况时，你的程序无法删除动态分配的内存，因为它不再知道它在哪里。操作系统也无法使用这块内存，因为该内存被认为仍被你的程序使用。

内存泄漏会在程序运行时消耗空闲内存，不仅使本程序可用的内存减少，也使其他程序可用的内存减少。存在严重内存泄漏问题的程序可能会耗尽所有可用内存，导致整个机器运行缓慢甚至崩溃。只有程序终止后，操作系统才能清理并“回收”所有泄漏的内存。

虽然内存泄漏可能由指针超出作用域引起，但也有其他方式导致内存泄漏。例如，如果保存动态分配内存地址的指针被赋予另一个值，就会发生内存泄漏：

int value = 5;
int* ptr{ new int{} }; // 分配内存
ptr = &value; // 旧地址丢失，导致内存泄漏

这可以通过在重新赋值前删除指针来修复：

int value{ 5 };
int* ptr{ new int{} }; // 分配内存
delete ptr; // 将内存返回给操作系统
ptr = &value; // 将指针重新赋值为值的地址

类似地，通过双重分配也可能导致内存泄漏：

int* ptr{ new int{} };
ptr = new int{}; // 旧地址丢失，导致内存泄漏

第二次分配返回的地址覆盖了第一次分配的地址。因此，第一次分配变成了内存泄漏！

同样，这可以通过确保在重新赋值前删除指针来避免。

总结

运算符 new 和 delete 允许我们为程序动态分配单个变量。

动态分配的内存具有动态持续时间，会一直保持分配状态，直到你释放它或程序终止。

注意不要解引用悬空指针或空指针。
