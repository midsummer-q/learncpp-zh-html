2.7 — 前向声明与定义

● 机器译文 课程 2.7 查看英文原文

来看看这个看似无害的示例程序：

#include <iostream>

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

int add(int x, int y)
{
    return x + y;
}

你可能期望这个程序输出结果：

The sum of 3 and 4 is: 7

但实际上，它根本不能编译！Visual Studio 会生成以下编译错误：

add.cpp(5) : error C3861: 'add': identifier not found

该程序无法编译的原因是编译器按顺序处理代码文件的内容。当编译器到达函数调用 add() 的第 5 行时 main它不知道 add 是什么，因为我们尚未定义 add 直到第 9 行！这就产生了错误： 未找到标识符。

旧版 Visual Studio 还会生成一个额外错误：

add.cpp(9) : error C2365: 'add'; : redefinition; previous definition was 'formerly unknown identifier'

这有些误导，因为 add 从未被定义过。尽管如此，一般注意这一点是有用的：单个错误常常会产生许多冗余或相关的错误或警告。有时很难判断第一个错误之后的任何错误或警告是第一个问题的后果，还是需要单独解决的独立问题。

最佳实践

在处理程序中的编译错误或警告时，先解决列表中的第一个问题，然后重新编译。

要解决这个问题，我们需要处理编译器不知道 add 是什么的事实。有两种常见的方法来解决这个问题。

选项 1：重新排列函数定义

解决这个问题的一种方法是重新排列函数定义，使得 add 定义在之前 main：

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

这样，当 main 调用 add时，编译器已经知道 add 是。因为这是一个非常简单的程序，所以这种改动相对容易。然而在大型程序中，要搞清楚哪些函数调用了哪些其他函数（以及调用顺序）以便按顺序声明它们，可能会非常繁琐。

此外，这种方案并非总是可行。假设我们编写的程序中有两个函数 一个 和 B。如果函数 一个 调用函数 B，而函数 B 调用函数 一个，那么就没有办法以让编译器满意的方式排列函数顺序。如果你先定义 一个 ，编译器会报错说它不知道 B 是什么。如果你先定义 B ，编译器会报错说它不知道 一个 是什么。

方案二：使用前向声明

我们也可以通过使用前向声明来解决这个问题。

一个 前向声明 允许我们在实际定义标识符之前告诉编译器某个标识符的存在。 在 实际定义标识符之前。

对于函数而言，这允许我们在定义函数体之前告诉编译器函数的存在。这样一来，当编译器遇到对该函数的调用时，它就能理解我们在进行函数调用，并能检查我们是否正确地调用了该函数，即使它还不知道该函数如何定义或定义在哪里。

要为函数编写前向声明，我们使用 函数声明 语句（也称为 函数原型）。函数声明由函数的返回类型、名称和参数类型组成，以分号结尾。参数名称可以可选地包含。函数体不包含在声明中。

以下是一个函数声明，适用于 add 函数：

int add(int x, int y); // 函数声明包含返回类型、名称、参数和分号。没有函数体！

现在，这是我们最初无法编译的程序，使用函数声明作为函数的前向声明 add：

#include <iostream>

int add(int x, int y); // add()的前向声明（使用函数声明）

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n'; // 这之所以有效是因为我们在上面前向声明了add()
    return 0;
}

int add(int x, int y) // 即使add()的函数体直到这里才被定义
{
    return x + y;
}

现在，当编译器到达对 add 在 main 中的调用时，它将知道 add 的样子（一个接受两个整数参数并返回整数的函数），并且它不会报错。

值得注意的是，函数声明不需要指定参数的名称（因为它们不被视为函数声明的一部分）。在上述代码中，你还可以像这样前向声明你的函数：

int add(int, int); // 有效的函数声明

然而，我们更倾向于为参数命名（使用与实际函数相同的名称）。这样，仅通过查看声明你就能理解函数参数的含义。例如，如果你看到声明 void doSomething(int, int, int)，你或许以为自己记得每个参数代表什么，但也可能弄错。

此外，许多自动化文档生成工具会根据头文件的内容生成文档，而声明通常放在头文件中。我们在第 2.11 -- 头文件。

最佳实践

在函数声明中保留参数名称。

提示

你可以通过复制/粘贴函数头部并添加分号来轻松创建函数声明。

为什么使用前向声明？

你可能会想，如果我们可以通过重新排序函数来使程序工作，为什么还要使用前向声明呢？

大多数情况下，前向声明用于告知编译器某个在另一个代码文件中定义的函数的存在。这种情况下无法重新排序，因为调用者和被调用者位于完全不同的文件中！我们将在下一课（2.8 -- 包含多个代码文件的程序)。

前向声明也可以用于以不依赖顺序的方式定义函数。这允许我们以最大化组织性（例如通过将相关函数聚类）或读者理解度的任意顺序定义函数。

较少见的情况下，有时我们会遇到两个函数相互调用。这种情况下也无法重新排序，因为无法将函数排序使得每个都在另一个之前。前向声明为我们提供了一种解决这种循环依赖的方法。

忘记函数体

编程新手常常想知道：如果前向声明了一个函数却没有定义它，会发生什么？

答案是：视情况而定。如果进行了前向声明，但从未调用该函数，程序将正常编译和运行。但如果进行了前向声明并且调用了该函数，但程序从未定义该函数，程序虽然能编译通过，但链接器会报错，称无法解析该函数调用。

考虑以下程序：

#include <iostream>

int add(int x, int y); // add()的前向声明

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

// 注意：函数add没有定义

在这个程序中，我们前向声明了 add，并调用了 add，但从未定义 add 当我们尝试编译这个程序时，Visual Studio 会产生以下信息：

Compiling...
add.cpp
Linking...
add.obj : error LNK2001: unresolved external symbol "int __cdecl add(int,int)" (?add@@YAHHH@Z)
add.exe : fatal error LNK1120: 1 unresolved externals

如你所见，程序编译通过了，但在链接阶段失败了，因为 int add(int, int) 从未被定义。

其他类型的前向声明

前向声明最常用于函数。然而，前向声明也可以用于 C++ 中的其他标识符，例如变量和类型。变量和类型的前向声明语法不同，我们将在后续课程中介绍这些内容。

声明 vs. 定义

在 C++ 中，你经常会听到“声明”和“定义”这两个词，而且它们经常被混用。它们是什么意思呢？现在你已经有了足够的基础知识来理解两者的区别。

一个 声明 告诉 编译器 关于 存在 一个标识符及其关联的类型信息。以下是一些声明的例子：

int add(int x, int y); // 告诉编译器有一个名为"add"的函数，它接收两个int参数并返回一个int。没有函数体！
int x;                 // 告诉编译器有一个名为x的整型变量

一个 定义 是一种声明，它实际实现了（对于函数和类型）或实例化了（对于变量）该标识符。

以下是一些定义的例子：

// 因为这个函数有函数体，所以它是函数add()的实现
int add(int x, int y)
{
    int z{ x + y };   // 实例化变量z

    return z;
}

int x;                // 实例化变量x

在C++中，所有定义都是声明。因此 int x; 既是定义又是声明。

反过来，并非所有声明都是定义。不是定义的声明被称为 纯声明。纯声明的类型包括函数、变量和类型的前向声明。

术语

在日常用语中，术语“声明”通常用来表示“纯声明”，而“定义”用来表示“同时作为声明的定义”。因此，我们通常称 int x; 一个定义，即使它既是定义又是声明。

当编译器遇到一个标识符时，它会检查以确保该标识符的使用是有效的（例如，标识符在作用域内，以语法有效的方式使用等）。

在大多数情况下，声明足以让编译器确保标识符被正确使用。例如，当编译器遇到函数调用 add(5, 6)，如果它已经看到了声明 add(int, int)int add ，那么它可以验证 int 实际上是一个接受两个 add 参数。它实际上不需要看到函数的定义

（可能存在于其他文件中）。

然而，在某些情况下，编译器必须能看到完整定义才能使用标识符（例如模板定义和类型定义，我们将在后续课程中讨论这两种情况）。

单一定义规则（ODR）

浮点类型的 单一定义规则 （简称 ODR）是 C++ 中众所周知的规则。ODR 包含三部分：

  1. 在同一个 文件在同一个文件中，给定作用域内的每个函数、变量、类型或模板只能有一个定义。出现在不同作用域（例如不同函数内定义的局部变量，或不同命名空间内定义的函数）中的定义不违反此规则。
  2. 在同一个 程序中，给定作用域内的每个函数或变量只能有一个定义。这条规则之所以存在，是因为程序可以有多个文件（我们将在下一课中介绍）。对链接器不可见的函数和变量不受此规则限制（将在课程 7.6 -- 内部链接)。
  3. 类型、模板、内联函数和内联变量允许在不同文件中有重复定义，前提是每个定义完全相同。我们还没有涉及这些内容的大部分，所以现在不用担心——当相关时我们会重新提及。

相关内容

我们将在以下课程中进一步讨论 ODR 第三部分的例外情况：

  • 类型（13.1 -- 程序定义（用户定义）类型简介)。
  • 函数模板（11.6 -- 函数模板 和 11.7 -- 函数模板实例化)。
  • 内联函数和变量（7.9 -- 内联函数和变量)。

违反 ODR 第一部分会导致编译器发出重定义错误。违反 ODR 第二部分会导致链接器发出重定义错误。违反 ODR 第三部分会导致未定义行为。

下面是一个违反第一部分的例子：

int add(int x, int y)
{
     return x + y;
}

int add(int x, int y) // 违反ODR，我们已经定义了函数add(int, int)
{
     return x + y;
}

int main()
{
    int x{};
    int x{ 5 }; // 违反ODR，我们已经定义了x
}

在这个例子中，函数 add(int, int) 被定义了两次（在全局作用域中），局部变量 int x 被定义了两次（在 main()的作用域中）。因此，Visual Studio 编译器发出以下编译错误：

project3.cpp(9): error C2084: function 'int add(int,int)' already has a body
project3.cpp(3): note: see previous definition of 'add'
project3.cpp(16): error C2086: 'int x': redefinition
project3.cpp(15): note: see declaration of 'x'

然而，对于 main() 拥有一个定义为 int x 和 add() 还定义了函数参数为 int x。这些定义出现在不同的作用域中（各自函数的作用域内），因此被视为两个不同对象的独立定义，而不是同一对象的定义与重定义。

进阶读者

共享同一标识符但具有不同参数集的函数也被视为不同的函数，因此这些定义不违反ODR。我们将在课程中进一步讨论 11.1 -- 函数重载介绍。

小测验时间

问题 #1

什么是函数原型？

显示答案

函数原型是一个声明语句，包含函数名、返回类型、参数类型，以及可选的参数名。它不包含函数体。它告诉编译器在函数定义之前该函数的存在。

问题 #2

什么是前向声明？

显示答案

前向声明告诉编译器某个标识符在实际定义之前已经存在。

问题 #3

如何为函数声明前向声明？

显示答案

对于函数，函数声明/原型即充当前向声明。

写出这个函数的函数声明（使用带名称的首选形式）：

int doMath(int first, int second, int third, int fourth)

     return first + second * third / fourth;

问题 #5

对于以下每个程序，说明它们是编译失败、链接失败还是编译链接成功。如果不确定，请尝试编译它们！

a)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y)
{
    return x + y;
}

显示答案

无法编译。编译器会报错，提示找不到匹配的 add() 接受3个参数的函数。前向声明 add() 只有两个参数。

b)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}

显示答案

无法编译。编译器会报错，提示找不到匹配的 add() 接受3个参数的函数。前向声明 add() 只有两个参数，而函数定义 add() 有3个参数的函数定义尚未被看到。

c)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 = " << add(3, 4) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}

显示答案

链接失败。编译器会将add的前向声明与main()中add()的函数调用匹配。然而，从未实现接受两个参数的add()函数（我们只实现了一个接受3个参数的），因此链接器会报错。

d)

#include <iostream>
int add(int x, int y, int z);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int z, int y, int x) // 名称与声明不匹配
{
    return x + y + z;
}

显示答案

编译链接成功。add()函数调用中的类型与前向声明匹配，且add()的定义也匹配。参数名与声明不匹配无关紧要，因为声明中的参数名是可选的（如果提供，编译器会忽略）。

e)

#include <iostream>
int add(int, int, int); // 无参数名称

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}

显示答案

编译并链接。这与前一种情况相同。函数声明不需要指定参数的名称（尽管我们通常更倾向于包含它们）。

f)

#include <iostream>

int add(int x, int y);

int add(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

显示答案

编译并链接。带有两个参数的add()的前向声明未被使用。
