8.12 — 终止（提前退出程序）

● 机器译文 课程 8.12 查看英文原文

本章要介绍的最后一类流程控制语句是终止。 终止 是一种终止程序的流程控制语句。在C++中，终止是通过函数（而非关键字）实现的，因此我们的终止语句将是函数调用。

我们先简短回顾一下程序正常退出时会发生什么。当 main() 函数返回时（无论是到达函数末尾，还是通过 return statement），会发生一系列事情。

首先，由于我们离开了函数，所有局部变量和函数参数都会被销毁（照常）。

接下来，一个名为 std::exit() 的特殊函数会被调用，并将 main() 的返回值（即 status code）作为参数传入。那么 std::exit()？

是什么？std::exit() 函数

std::exit() 是一个导致程序正常终止的函数。 正常终止 意味着程序以预期的方式退出。注意，“正常”一词 normal termination 并不暗示程序是否成功（那是 status code 的用途）。例如，假设你编写了一个程序，期望用户输入要处理的文件名。如果用户输入了无效的文件名，你的程序可能会返回一个非零的 status code 来表示失败状态，但它仍然是 normal termination。

std::exit() 执行一些清理工作。首先，具有静态存储期的对象被销毁。然后，如果使用了任何文件，会进行一些其他文件清理。最后，控制权返回给操作系统，同时传递给 std::exit() 的参数被用作 status code。

显式调用 std::exit()

尽管 std::exit() 在函数 main() 返回后隐式调用， std::exit() 也可以显式调用，以便在程序正常终止之前提前终止。当以这种方式调用 std::exit() 时，你需要包含 cstdlib 头文件中。

关键提示

std::exit 在 main() 返回时隐式调用。

下面是一个显式使用 std::exit() 的例子：

#include <cstdlib> // for std::exit()
#include <iostream>

void cleanup()
{
    // 此处代码用于执行任何所需的清理工作
    std::cout << "cleanup!\n";
}

int main()
{
    std::cout << 1 << '\n';
    cleanup();

    std::exit(0); // 终止并向操作系统返回状态码0

    // 以下语句永远不会执行
    std::cout << 2 << '\n';

    return 0;
}

std::atexit

因为 std::exit() 立即终止程序，你可能希望在终止前手动进行一些清理工作。在此上下文中，清理指的是诸如关闭数据库或网络连接、释放已分配的内存、将信息写入日志文件等操作。

顺便说一句……

当应用程序退出时，现代操作系统通常会清理应用程序未正确清理的任何内存。这就引出了一个问题：“那么为什么还要在退出时进行清理呢？”至少有两点原因：

  1. 清理已分配的内存是一种“好习惯”，在应用程序运行时需要用它来避免内存泄漏。在某些情况下清理而在其他情况下不清理是不一致的，并且可能导致错误。不正确地清理内存还可能影响某些工具（如内存分析器）的行为（它们可能无法区分你无意中未清理的内存和你故意不清理的内存，因为你不必清理）。
  2. 还有其他类型的清理可能对于程序的可预测行为是必要的。例如，如果你将数据写入文件然后意外退出，这些数据可能尚未刷新到文件中，并在程序退出时丢失。在关闭前关闭文件有助于确保所有缓存数据首先被写入。或者你可能希望在关闭实际发生之前，将关于用户会话或程序关闭原因的数据发送到服务器。

在上面的例子中，我们调用了函数 cleanup() 来处理我们的清理任务。然而，在每次调用 exit() 之前记住手动调用清理函数会增加程序员的负担，并且容易出错。

为了帮助解决这个问题，C++ 提供了 std::atexit() 函数，它允许你指定一个函数，该函数将在程序通过 std::exit()。

相关内容

终止时自动调用。我们在第 20.1 -- 函数指针。

下面是一个示例：

#include <cstdlib> // for std::exit()
#include <iostream>

void cleanup()
{
    // 此处代码用于执行任何所需的清理工作
    std::cout << "cleanup!\n";
}

int main()
{
    // 注册cleanup()，使其在调用std::exit()时自动被调用
    std::atexit(cleanup); // 注意：我们使用cleanup而不是cleanup()，因为我们现在不是要调用cleanup()函数

    std::cout << 1 << '\n';

    std::exit(0); // 终止并向操作系统返回状态码0

    // 以下语句永远不会执行
    std::cout << 2 << '\n';

    return 0;
}

何时应该使用终止？

简短的回答是“几乎从不”。销毁局部对象是C++的重要组成部分（特别是当我们进入类时），而上述函数都不会清理局部变量。异常是处理错误情况的更好、更安全的机制。

最佳实践

只有在没有安全或合理的方式从main函数正常返回时，才使用终止。如果你没有禁用异常，优先使用异常来安全地处理错误。

提示

尽管应尽量减少显式使用终止，但程序还有许多其他方式可能意外关闭。例如：

  • 应用程序可能因错误而崩溃（此时操作系统会将其关闭）。
  • 用户可能以各种方式终止应用程序。
  • 用户可能关闭（或失去）计算机电源。
  • 太阳可能变成超新星，将地球吞噬在巨大的火球中。

设计良好的程序应该能够在任何时刻被关闭，且影响最小。

一个常见的例子是，现代游戏通常会定期自动保存游戏状态和用户设置，这样如果游戏在没有保存的情况下意外关闭，用户可以使用之前的自动存档继续游戏，而不会丢失太多进度。
