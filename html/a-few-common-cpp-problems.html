0.8 — 几个常见的C++问题

● 机器译文 课程 0.8 查看英文原文

在本节中，我们将讨论一些新程序员似乎相当频繁遇到的一些常见问题。这并不是要成为编译或执行问题的全面列表，而是一份针对非常基本问题的实用解决方案列表。如果您有任何其他问题建议添加到这个列表中，请在下面的评论区中发布。

常见运行时问题

问：执行程序时，控制台窗口闪烁后立即关闭。

首先，添加或确保以下行位于程序顶部附近（Visual Studio 用户，请确保这些行出现在 #include “pch.h” 或 #include “stdafx.h” 之后，如果存在的话）：

#include <iostream>
#include <limits>

其次，在 main() 函数的末尾（紧接在 return 语句之前）添加以下代码：

std::cin.clear(); // 重置任何错误标志
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // 忽略输入缓冲区中的任何字符，直到找到回车字符
std::cin.get(); // 从用户处再获取一个字符

这将使程序在继续之前等待用户按键，从而让您有时间在操作系统关闭控制台窗口之前检查程序的输出。

其他解决方案，例如常被建议的 system(“pause”) 解决方案，可能仅适用于某些操作系统，应避免使用。

较旧版本的 Visual Studio 在运行于 开始调试 (F5) 模式时可能不会暂停。请尝试运行于 开始执行(不调试) (Ctrl-F5) 模式。

问：我运行程序后出现窗口但没有输出。

您的病毒扫描程序或反恶意软件可能阻止了执行。请尝试暂时禁用它，看看是否是这个问题。

问：我的程序编译成功但运行不正确。我该怎么办？

调试它！第3章后面有一些关于如何诊断和调试程序的技巧。

常见编译时问题

问：编译程序时，出现关于未解析的外部符号 _main 或 _WinMain@16 的错误

这意味着编译器找不到您的 main() 函数。所有程序都必须包含一个 main() 函数。

有几件事需要检查：
a) 你的代码是否包含一个名为 main 的函数？
b) main 的拼写是否正确？
c) 编译程序时，是否看到包含 main() 函数的文件被编译？如果没有，要么将 main() 函数移动到一个会被编译的文件中，要么将该文件添加到你的项目中（参见课程 2.8 -- 包含多个代码文件的程序 了解更多关于如何操作的信息）。
d) 你是否创建了一个控制台项目？尝试创建一个新的控制台项目。

问：编译程序时，我收到一个错误，提示 main 已经定义，或者关于 main 的多重定义

一个 C++ 程序只允许有一个名为 main. 你的 C++ 程序有多个。 main 函数，只保留一个。

问：我尝试使用 C++11/14/17/XX 功能，但它不起作用

如果你的编译器较旧，可能不支持这些较新的语言特性。在这种情况下，请升级你的编译器。

对于现代 IDE/编译器，你的编译器可能默认使用较旧的语言标准。我们在课程中介绍了如何更改语言标准 0.12 -- 配置你的编译器：选择语言标准。

问：编译程序时，我收到一个错误，提示无法打开 .exe 文件进行写入

这意味着链接器正在尝试创建你的可执行文件，但无法完成。这可能是由于多种原因：

  • 最常见的情况是 .exe 当前正在运行。正在运行的可执行文件无法被替换。关闭正在运行的 .exe 并重新编译。
  • 你的防病毒或恶意软件防护阻止了可执行文件的创建或替换。
  • 该 .exe 文件已存在，且由于其他原因被锁定。尝试重启（以强制释放所有锁定），然后重新编译。

在 Visual Studio 中，这是错误 LNK1168。

问：尝试使用 cin、cout 或 endl 时，编译器提示 cin、cout 或 endl 是“未声明的标识符”

首先，请确认在文件顶部附近包含了以下这行代码：

#include <iostream>

其次，确保每次使用 cin、cout 和 endl 时都加上“std::”前缀。例如：

std::cout << "Broccoli" << std::endl;

如果这样未能解决问题，可能是编译器版本过旧或安装文件损坏。请尝试重新安装或升级到最新版本的编译器。

问：尝试使用 endl 结束打印行时，编译器提示 end1 是“未声明的标识符”

请确认不要将 endl 中的字母 l（小写 L）误认为数字 1。endl 全为字母。确保编辑器使用的字体能清晰区分小写字母 L、大写字母 I 和数字 1。另外，在许多非编程字体中，大写字母 O 和数字 0 也容易混淆。

Visual Studio 相关问题

问：使用 Microsoft Visual C++ 编译时，出现 C1010 致命错误，错误信息类似：“c:\vcprojects\test.cpp(263) : fatal error C1010: unexpected end of file while looking for precompiled header directive”

此错误发生在 Microsoft Visual C++ 编译器设置为使用预编译头文件，但一个（或多个）C++ 代码文件未将 #include “stdafx.h” 或 #include “pch.h” 作为文件第一行的情况下。

我们建议的解决方法是关闭预编译头，具体操作方式在课程 0.7 -- 编译你的第一个程序。

如果你希望保持预编译头开启，要解决此问题，只需找到产生错误的文件（以上错误中 test.cpp 是罪魁祸首），并在文件最顶部添加以下这行代码：

#include "pch.h"

旧版 Visual Studio 使用“stdafx.h”而不是“pch.h”，因此如果 pch.h 无法解决问题，请尝试 stdafx.h。

注意，对于包含多个文件的程序，每个 C++ 代码文件都需要以这一行开头。

问：Visual Studio 显示类似错误：“1MSVCRTD.lib(exe_winmain.obj) : error LNK2022: unresolved external symbol _WinMain@16 referenced in function "int __cdecl invoke_main(void)" (?invoke_main@@YAHXZ)”

你可能创建的是 Windows 图形界面应用程序，而非控制台应用程序。请重新创建项目，并确保将其创建为 Windows（或 Win32） 控制台 项目。

问：编译程序时，收到关于“无法找到或打开 PDB 文件”的警告

这是一个警告，而不是错误，所以它不应该影响您的程序。不过，它很烦人。要解决它，请进入调试菜单 -> 选项和设置 -> 符号，然后勾选“Microsoft Symbol Server”。

其他内容

问：我有其他问题无法解决。如何快速获得答案？

在学习过程中，您无疑会遇到问题或意外难题。下一步该怎么做取决于您的问题。但通常来说，您可以尝试几种方法。

首先， 向搜索引擎提问。找到合适的措辞来表述您的问题并进行搜索。如果您在搜索错误消息，请用引号粘贴确切的错误消息（排除任何文件名或行号）。很可能已经有人问过相同的问题，答案就在那里等着您。

其次， 向人工智能提问 比如 ChatGPT via Bing。以“In C++,”开头，以获得针对C++的答案。一些您可以询问的内容建议：

  • 对某个概念的解释（例如：“In C++, what is a local variable?”）。
  • 两个事物之间的区别（例如：“In C++, what is the difference between a pointer and a reference?”）
  • 对一个概念的演示（例如：“In C++, write a short program that adds two numbers”）

请注意，人工智能可能返回不准确或过时的信息，它们编写的程序也可能不遵循现代最佳实践。

如果上述方法都失败了， 在问答平台上提问。有一些专门针对编程问答的网站，比如 Stack Overflow。请尝试在那里发布您的问题。记得详细描述您的问题，并包含所有相关信息，比如您的操作系统和使用的IDE。
