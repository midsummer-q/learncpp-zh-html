23.4 — 关联

● 机器译文 课程 23.4 查看英文原文

在前两节课中，我们学习了两种对象组合：组合和聚合。对象组合用于建模复杂对象由一个或多个更简单的对象（部分）构建的关系。

在本节课中，我们将探讨两个原本无关的对象之间的一种较弱的关系，称为关联。与对象组合关系不同，在关联中，不存在隐含的整体/部分关系。

关联

要成为 关联，一个对象和另一个对象必须满足以下关系：

  • 关联对象（成员）与对象（类）原本无关
  • 关联对象（成员）可以同时属于多个对象（类）
  • 关联对象（成员）的 不是 存在不由对象（类）管理
  • 关联对象（成员）可能知道也可能不知道对象（类）的存在

与组合或聚合不同（其中部分是整体对象的一部分），在关联中，关联对象与对象原本无关。就像聚合一样，关联对象可以同时属于多个对象，并且不受这些对象的管理。然而，与聚合（关系总是单向的）不同，关联中的关系可以是单向或双向的（两个对象彼此知道对方的存在）。

医生和患者之间的关系是关联的一个很好的例子。医生显然与他的患者有关系，但从概念上讲，这不是部分/整体（对象组合）关系。医生一天可以看很多患者，而一个患者也可以看很多医生（也许他们想寻求第二意见，或者他们正在看不同类型的医生）。两个对象的生命周期都不依赖于对方。

我们可以说关联建模的是“使用”关系。医生“使用”患者（来赚取收入）。患者使用医生（为了他们需要的任何健康目的）。

实现关联

由于关联是一种广泛的关系类型，它们可以通过多种方式实现。然而，大多数情况下，关联是使用指针实现的，其中对象指向关联对象。

在这个例子中，我们将实现一个双向的医生/患者关系，因为让医生知道他们的患者是谁，反之亦然，是有意义的。

#include <functional> // reference_wrapper
#include <iostream>
#include <string>
#include <string_view>
#include <vector>

// 由于 Doctor 和 Patient 存在循环依赖，我们将前置声明 Patient
class Patient;

class Doctor
{
private:
	std::string m_name{};
	std::vector<std::reference_wrapper<const Patient>> m_patient{};

public:
	Doctor(std::string_view name) :
		m_name{ name }
	{
	}

	void addPatient(Patient& patient);
	
	// 我们将在 Patient 下方实现此函数，因为我们需要先定义 Patient
	friend std::ostream& operator<<(std::ostream& out, const Doctor& doctor);

	const std::string& getName() const { return m_name; }
};

class Patient
{
private:
	std::string m_name{};
	std::vector<std::reference_wrapper<const Doctor>> m_doctor{}; // 以便在此处使用它

	// 我们将把 addDoctor 设为私有，因为我们不希望公众使用它。
	// 他们应该使用公开暴露的 Doctor::addPatient() 代替
	void addDoctor(const Doctor& doctor)
	{
		m_doctor.push_back(doctor);
	}

public:
	Patient(std::string_view name)
		: m_name{ name }
	{
	}

	// 我们将在下方实现此函数，以与 operator<<(std::ostream&, const Doctor&) 对应
	friend std::ostream& operator<<(std::ostream& out, const Patient& patient);

	const std::string& getName() const { return m_name; }

	// 我们将把 Doctor::addPatient() 声明为友元，以便它能访问私有函数 Patient::addDoctor()
	friend void Doctor::addPatient(Patient& patient);
};

void Doctor::addPatient(Patient& patient)
{
	// 我们的医生将添加此患者
	m_patient.push_back(patient);

	// 并且患者也将添加此医生
	patient.addDoctor(*this);
}

std::ostream& operator<<(std::ostream& out, const Doctor& doctor)
{
	if (doctor.m_patient.empty())
	{
		out << doctor.m_name << " has no patients right now";
		return out;
	}

	out << doctor.m_name << " is seeing patients: ";
	for (const auto& patient : doctor.m_patient)
		out << patient.get().getName() << ' ';

	return out;
}

std::ostream& operator<<(std::ostream& out, const Patient& patient)
{
	if (patient.m_doctor.empty())
	{
		out << patient.getName() << " has no doctors right now";
		return out;
	}

	out << patient.m_name << " is seeing doctors: ";
	for (const auto& doctor : patient.m_doctor)
		out << doctor.get().getName() << ' ';

	return out;
}

int main()
{
	// 在 Doctor 的作用域外创建一个 Patient
	Patient dave{ "Dave" };
	Patient frank{ "Frank" };
	Patient betsy{ "Betsy" };

	Doctor james{ "James" };
	Doctor scott{ "Scott" };

	james.addPatient(dave);

	scott.addPatient(dave);
	scott.addPatient(betsy);

	std::cout << james << '\n';
	std::cout << scott << '\n';
	std::cout << dave << '\n';
	std::cout << frank << '\n';
	std::cout << betsy << '\n';

	return 0;
}

这会打印：

James is seeing patients: Dave
Scott is seeing patients: Dave Betsy
Dave is seeing doctors: James Scott
Frank has no doctors right now
Betsy is seeing doctors: Scott

一般来说，如果单向关系可行，你应该避免双向关联，因为它们会增加复杂性，并且往往更难编写而不出错。

自反关联

有时对象可能与同一类型的其他对象有关系。这称为 自反关联。自反关联的一个很好的例子是大学课程与其先修课程（也是大学课程）之间的关系。

考虑简化的情况，一门课程只能有一个先修课程。我们可以这样做：

#include <string>
#include <string_view>

class Course
{
private:
    std::string m_name{};
    const Course* m_prerequisite{};

public:
    Course(std::string_view name, const Course* prerequisite = nullptr):
        m_name{ name }, m_prerequisite{ prerequisite }
    {
    }

};

这可能导致关联链（一门课程有一个先修课程，该先修课程又有一个先修课程，等等……）

关联可以是间接的

在之前的所有情况中，我们使用指针或引用来直接链接对象。然而，在关联中，这并不是严格必需的。任何允许你链接两个对象的数据都足够了。在下面的例子中，我们展示了 Driver 类如何与 Car 建立单向关联，而不实际包含 Car 指针或引用成员：

#include <iostream>
#include <string>
#include <string_view>

class Car
{
private:
	std::string m_name{};
	int m_id{};

public:
	Car(std::string_view name, int id)
		: m_name{ name }, m_id{ id }
	{
	}

	const std::string& getName() const { return m_name; }
	int getId() const { return m_id; }
};

// 我们的 CarLot 本质上只是一个静态的 Car 数组和一个用于检索它们的查找函数。
// 因为它是静态的，我们不需要分配 CarLot 类型的对象来使用它
namespace CarLot
{
    Car carLot[4] { { "Prius", 4 }, { "Corolla", 17 }, { "Accord", 84 }, { "Matrix", 62 } };

	Car* getCar(int id)
	{
		for (auto& car : carLot)
        {
			if (car.getId() == id)
			{
				return &car;
			}
		}
		
		return nullptr;
	}
};

class Driver
{
private:
	std::string m_name{};
	int m_carId{}; // 我们通过 ID 而不是指针与 Car 关联

public:
	Driver(std::string_view name, int carId)
		: m_name{ name }, m_carId{ carId }
	{
	}

	const std::string& getName() const { return m_name; }
	int getCarId() const { return m_carId; }
};

int main()
{
	Driver d{ "Franz", 17 }; // Franz 正在驾驶 ID 为 17 的汽车

	Car* car{ CarLot::getCar(d.getCarId()) }; // 从汽车场获取那辆车
	
	if (car)
		std::cout << d.getName() << " is driving a " << car->getName() << '\n';
	else
		std::cout << d.getName() << " couldn't find his car\n";

	return 0;
}

在上面的例子中，我们有一个 CarLot 来存放我们的汽车。需要汽车的 Driver 没有指向他的 Car 的指针——相反，他拥有汽车的 ID，当我们需要时，可以使用该 ID 从 CarLot 中获取 Car。

在这个特定的例子中，这样做有点傻，因为从 CarLot 中取出 Car 需要低效的查找（连接两者的指针要快得多）。然而，通过唯一 ID 而不是指针来引用事物有一些优点。例如，你可以引用当前不在内存中的事物（也许它们在文件中，或者在数据库中，并且可以按需加载）。此外，指针可能占用 4 或 8 字节——如果空间非常宝贵且唯一对象的数量相当少，通过 8 位或 16 位整数来引用它们可以节省大量内存。

组合 vs 聚合 vs 关联总结

这里有一个总结表，帮助你记住组合、聚合和关联之间的区别：

属性组合聚合关联
关系类型整体/部分整体/部分原本无关
成员可以属于多个类否是是
成员的存在由类管理是否否
方向性单向单向单向或双向
关系动词是……的一部分拥有使用-a
