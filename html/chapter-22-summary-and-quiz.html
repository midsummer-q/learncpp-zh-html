22.x — 第22章 总结与测验

● 机器译文 课程 22.x 查看英文原文

智能指针类是一种组合类，旨在管理动态分配的内存，并确保当智能指针对象离开作用域时内存被释放。

拷贝语义允许我们的类被拷贝。这主要通过拷贝构造函数和拷贝赋值运算符实现。

移动语义意味着类将转移对象的所有权而不是进行拷贝。这主要通过移动构造函数和移动赋值运算符实现。

std::auto_ptr 已被弃用，应避免使用。

右值引用是一种旨在用右值初始化的引用。右值引用使用双&符号创建。编写接受右值引用参数的函数是可以的，但几乎不应该返回右值引用。

如果我们构造一个对象或进行赋值，且参数是左值，我们能合理做的唯一事情就是拷贝该左值。我们不能假设修改左值是安全的，因为它可能在程序后面再次被使用。如果我们有表达式“a = b”，我们不会合理地期望b以任何方式被改变。

然而，如果我们构造一个对象或执行赋值操作，且参数是右值，那么我们知道该右值只是某种临时对象。与其拷贝它（这可能很昂贵），我们可以简单地将它的资源转移（这很廉价）到我们正在构造或赋值的对象中。这样做是安全的，因为临时对象无论如何都会在表达式结束时被销毁，所以我们知道它再也不会被使用！

你可以使用 delete 关键字通过删除拷贝构造函数和拷贝赋值运算符来禁用你创建的类的拷贝语义。

std::move 允许你将左值当作右值处理。当我们想对左值调用移动语义而不是拷贝语义时，这很有用。

std::unique_ptr 是你可能应该使用的智能指针类。它管理单个不可共享的资源。应该优先使用 std::make_unique()（C++14中）来创建新的 std::unique_ptr。std::unique_ptr 禁用了拷贝语义。

std::shared_ptr 是当你需要多个对象访问同一资源时使用的智能指针类。资源将一直存在，直到管理它的最后一个 std::shared_ptr 被销毁。应优先使用 std::make_shared() 来创建新的 std::shared_ptr。对于 std::shared_ptr，应使用拷贝语义来创建指向同一对象的其他 std::shared_ptr。

std::weak_ptr 是当你需要一个或多个对象能够查看和访问由 std::shared_ptr 管理的资源，但与 std::shared_ptr 不同，std::weak_ptr 在决定资源是否应被销毁时不被考虑时使用的智能指针类。

小测验时间

  1. 解释何时应使用以下类型的指针。

1a) std::unique_ptr

显示答案

当你想要一个智能指针管理一个不会被共享的动态对象时，应使用 std::unique_ptr。

1b) std::shared_ptr

显示答案

当你想要一个智能指针管理一个可能被共享的动态对象时，应使用 std::shared_ptr。该对象将不会被释放，直到所有持有该对象的 std::shared_ptr 被销毁。

1c) std::weak_ptr

显示答案

当你想要访问一个由 std::shared_ptr 管理的对象，但又不希望 std::shared_ptr 的生命周期与 std::weak_ptr 的生命周期绑定时，应使用 std::weak_ptr。

1d) std::auto_ptr

显示答案

std::auto_ptr 已被弃用，并在 C++17 中被移除。不应使用它。

  1. 解释为什么移动语义围绕右值展开。

显示答案

因为右值是临时对象，我们知道它们在使用后会被销毁。当按值传递或返回右值时，先复制再销毁原对象是一种浪费。相反，我们可以简单地移动（窃取）右值的资源，这通常更高效。

  1. 以下代码有什么问题？更新程序以符合最佳实践。

3a)

#include <iostream>
#include <memory> // for std::shared_ptr
 
class Resource
{
public:
	Resource() { std::cout << "Resource acquired\n"; }
	~Resource() { std::cout << "Resource destroyed\n"; }
};
 
int main()
{
	auto* res{ new Resource{} };
	std::shared_ptr<Resource> ptr1{ res };
	std::shared_ptr<Resource> ptr2{ res };

	return 0;
}

显示答案

ptr2 是从 res 创建的，而不是从 ptr1。这意味着你现在有两个 std::shared_ptr 各自独立地试图管理 Resource （它们彼此不知道对方）。当其中一个离开作用域时，另一个将留下一个悬空指针。

ptr2 应改为使用 ptr1 创建的，而不是从 res初始化。这将允许 ptr1 和 ptr2 共享 res。 std::make_shared() 的所有权，应使用它代替手动动态分配。

#include <iostream>
#include <memory> // for std::shared_ptr
 
class Resource
{
public:
	Resource() { std::cout << "Resource acquired\n"; }
	~Resource() { std::cout << "Resource destroyed\n"; }
};
 
int main()
{
	auto ptr1{ std::make_shared<Resource>() };
	auto ptr2{ ptr1 };

	return 0;
}
