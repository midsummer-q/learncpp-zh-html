0.11 — 配置你的编译器：警告和错误级别

● 机器译文 课程 0.11 查看英文原文

当你编写程序时，编译器会检查你是否遵循了C++语言的规则（假设你已经按照课程 0.10 -- 配置你的编译器：编译器扩展)。如果你做了明确违反语言规则的事情，那么你的程序就是 不合法的。

在大多数情况下，当编译器遇到某种问题时，它会发出 诊断消息 （通常称为 诊断 的简称）。C++标准没有定义诊断消息应该如何分类、措辞，或者这些问题应该如何影响程序的编译。然而，现代编译器通常采用以下约定：

  • 一个 诊断错误 (错误 的简称）意味着编译器已决定停止编译，因为它要么无法继续，要么认为错误足够严重以至于停止。编译器生成的诊断错误常被称为 编译错误， 编译器错误，或 编译错误。
  • 一个 诊断警告 (警告 的简称）意味着编译器已决定不停止编译。在这种情况下，问题被简单地忽略，编译继续进行。

关键提示

编译器决定一个非阻塞问题属于警告还是错误。虽然它们通常在分类上保持一致，但在某些情况下，编译器可能意见不一致——对于同一个问题，一个编译器发出错误，而另一个发出警告。

为了帮助您定位问题所在，诊断信息通常包含编译器发现问题的文件名和行号，以及关于期望内容与实际发现内容的说明。实际的问题可能出现在该行，也可能出现在前一行。一旦解决了引发诊断的问题，您可以尝试重新编译，看看对应的诊断信息是否不再出现。

在某些情况下，编译器可能会识别出虽不违反语言规则、但被认为可能有误的代码。此时，编译器可能会决定发出警告，作为通知程序员某些地方似乎异常的提示。此类问题可以通过修复警告所指出的问题来解决，也可以将引发警告的代码行重写为不再触发警告的形式。

进阶读者

我们在课程中展示了一个技术上合法但现代编译器认为可疑的语句示例： 7.7 -- 外部链接与变量前向声明。

在极少数情况下，可能需要明确告诉编译器不要针对特定代码行生成某个警告。C++ 并没有提供官方的做法，但许多编译器（包括 Visual Studio 和 GCC）都提供了解决方案（通过不可移植的 #pragma 指令）来临时禁用警告。

最佳实践

不要让警告堆积起来。遇到警告就要像对待错误一样及时解决。否则，一个关于严重问题的警告可能会淹没在大量非严重问题的警告之中。

如果链接过程中出现无法解决的问题，链接器也可能会生成诊断错误。

提高警告级别

默认情况下，大多数编译器只对最明显的问题生成警告。不过，您可以要求编译器在提供警告方面更加积极，这通常是一个好主意。

最佳实践

调高警告级别，尤其是在学习期间。额外的诊断信息有助于发现可能导致程序出错的编程错误。

从 项目 对话框中，首先确保 配置 字段设置为 所有配置。

然后选择 C/C++ > 常规选项卡 并设置 警告等级 切换到 Level4 (/W4)：

注意：不要选择 EnableAllWarnings (/Wall) 否则您将被 C++ 标准库生成的警告所淹没。

Visual Studio 默认禁用了有符号/无符号转换警告，而这些警告很有用，因此如果您使用的是 Visual Studio 2019 或更新版本，让我们启用它们：

  • 从 C/C++ > 命令行选项卡在 附加选项，添加 /w44365这会告诉编译器在警告等级4（你在上面已启用）启用有符号/无符号转换警告。
  • 从 C/C++ > 外部包含选项卡设置 外部头文件警告等级 切换到 Level3 (/external:W3)这会告诉编译器以警告等级3（而不是4）编译标准库头文件，这样编译这些头文件就不会触发这个警告。

上面的图示中没有显示“外部包含”选项卡，但在VS Community 2019或更新版本中，它出现在“浏览信息”和“高级”选项卡之间。参见 此链接，其中包含一个含有“外部包含”选项卡的对话框的最新照片。

将警告视为错误

您也可以告诉编译器将所有警告视为错误（在这种情况下，如果发现任何警告，编译器将停止编译）。这是强制执行应修复所有警告这一建议的好方法（如果您缺乏自律，而我们大多数人都缺乏）。

最佳实践

启用“将警告视为错误”。这将迫使您解决所有导致警告的问题。
