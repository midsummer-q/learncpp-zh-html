5.5 — 常量表达式

● 机器译文 课程 5.5 查看英文原文

在课程 1.10 -- 表达式简介中，我们介绍了表达式。默认情况下，表达式在运行时求值。在某些情况下，它们必须如此：

std::cin >> x;
std::cout << 5 << '\n';

因为输入和输出不能在编译时执行，所以上面的表达式需要在运行时求值。

在之前的课程 5.4 -- 如同规则与编译时优化中，我们讨论了如同规则，以及编译器如何通过将工作从运行时转移到编译时来优化程序。在如同规则下，编译器可以选择在运行时还是编译时求值某些表达式：

const double x { 1.2 };
const double y { 3.4 };
const double z { x + y }; // x + y 可能在运行时或编译时求值

表达式 x + y 通常会在运行时求值，但由于 x 和 y 的值在编译时已知，编译器可以选择进行编译时求值，并用编译时计算出的值初始化 z 4.6。

在其他一些情况下，C++语言要求表达式能够在编译时求值。例如，constexpr变量需要一个可以在编译时求值的初始化器：

int main()
{
    constexpr int x { expr }; // 因为变量 x 是 constexpr，expr 必须在编译时可求值
}

在需要常量表达式但未提供的情况下，编译器将报错并停止编译。

我们将在下一课（5.6 -- Constexpr 变量）中讨论constexpr变量，届时将涵盖constexpr变量。

进阶读者

一些需要编译时可求值表达式的常见情况：

  • constexpr变量的初始化器（5.6 -- Constexpr 变量)。
  • 非类型模板参数（11.9 -- 非类型模板参数)。
  • 定义的长度 std::array (17.1 -- std::array简介）或C风格数组（17.7 -- C风格数组简介)。

在本课中，我们将进一步探讨C++在编译时求值方面的能力，并了解C++如何将最后一种情况与前两种情况区分开来。

编译时编程的好处

虽然如同规则对提高性能很有帮助，但它让我们依赖于编译器的复杂程度来决定哪些内容可以在编译时求值。这意味着如果我们有一段代码确实希望在编译时执行，它可能执行也可能不执行。同样的代码在不同的平台上、使用不同的编译器、不同的编译选项或稍作修改，可能会产生不同的结果。由于如同规则对我们不可见，我们无法从编译器那里得到关于它决定在编译时求值哪些代码部分以及原因的任何反馈。我们期望在编译时求值的代码可能甚至不符合条件（由于拼写错误或误解），而我们可能永远不知道。

为了改善这种情况，C++语言提供了让我们明确指定哪些代码部分希望在编译时执行的方法。使用导致编译时求值的语言特性称为 编译时编程。

这些特性可以在多个方面帮助改进软件：

  • 性能：编译时求值使我们的程序更小、更快。我们能够确保在编译时求值的代码越多，获得的性能提升就越大。
  • 多功能性：我们可以在需要编译时常量的地方使用此类代码。依赖如同规则在编译时求值的代码不能用于此类地方（即使编译器选择在编译时求值该代码）——做出这个决定是为了确保今天能编译的代码明天不会因为编译器决定采用不同的优化方式而无法编译。
  • 可预测性：如果编译器确定代码无法在编译时执行，我们可以让编译器停止编译（而不是默默地选择让该代码在运行时求值）。这使我们能够确保我们真正希望在编译时执行的代码段确实会在编译时执行。
  • 质量：我们可以让编译器在编译时可靠地检测某些类型的编程错误，并在遇到它们时停止构建。这比试图在运行时检测并优雅地处理同样的错误要有效得多。
  • 质量：也许最重要的是，未定义行为在编译时是不允许的。如果我们在编译时做了导致未定义行为的事情，编译器应该停止构建并要求我们修复它。请注意，这对编译器来说是一个难题，它们可能无法捕捉所有情况。

总之，编译时求值使我们能够编写既性能更高又质量更好（更安全、更少错误）的程序！因此，虽然编译时求值确实给语言增加了一些额外的复杂性，但其好处是巨大的。

以下C++特性是编译时编程最基础的：

  • Constexpr变量（在即将到来的课程 5.6 -- Constexpr 变量)。
  • Constexpr函数（在即将到来的课程 F.1 -- Constexpr函数)。
  • 模板（在课程 11.6 -- 函数模板)。
  • static_assert（在课程 9.6 -- Assert 和 static_assert)。

所有这些特性都有一个共同点：它们都使用了常量表达式。

常量表达式

也许令人惊讶的是，C++标准几乎不提及“编译时”。相反，标准定义了“常量表达式”，这是一种必须在编译时可求值的表达式，以及决定编译器应如何处理这些表达式的规则。常量表达式构成了C++中编译时求值的基石。

在课程 1.10 -- 表达式简介，我们将表达式定义为“字面量、变量、运算符和函数调用的非空序列”。 常量表达式 是字面量、常量变量、运算符和函数调用的非空序列，所有这些都必须在编译时可求值。关键区别在于，在常量表达式中，表达式的每个部分都必须在编译时可求值。

关键提示

在常量表达式中，表达式的每个部分都必须在编译时可求值。

不是常量表达式的表达式通常称为非常量表达式，并且可以非正式地称为 运行时表达式 （因为此类表达式通常在运行时求值）。

可选阅读

C++20语言标准（在[expr.const]节中）指出“常量表达式可以在翻译期间求值”。正如我们在课程 2.10 -- 预处理器简介中所介绍的，翻译是构建程序的整个过程（包括预处理、编译和链接）。因此，在编译程序中，常量表达式可以作为编译过程的一部分进行求值。在解释程序中，翻译发生在运行时。

由于C++程序通常是编译的，我们将假设常量表达式可以在编译时求值。

常量表达式中可以包含什么？

作者注

从技术上讲，常量表达式相当复杂。在本节中，我们将更深入地探讨它们可以包含什么和不能包含什么。你不需要记住大部分内容。如果在某个地方需要常量表达式而你未提供，编译器会愉快地指出你的错误，届时你可以修复它。

最常见的是，常量表达式包含以下内容：

  • 字面量（例如 '5'、'1.2'）
  • 大多数带有常量表达式操作数的运算符（例如 3 + 4， 2 * sizeof(int))。
  • 带有常量表达式初始化器的const整型变量（例如 const int x { 5 };）。这是一个历史例外——在现代C++中，更推荐使用constexpr变量。
  • Constexpr变量（在即将到来的课程 5.6 -- Constexpr 变量)。
  • 带有常量表达式参数的constexpr函数调用（参见 F.1 -- Constexpr函数)。

进阶读者

常量表达式还可以包含：

  • 非类型模板参数（参见 11.9 -- 非类型模板参数)。
  • 枚举器（参见 13.2 -- 无作用域枚举)。
  • 类型特征（参见 类型特征的cppreference页面)。
  • constexpr lambda表达式（参见 20.6 -- lambda（匿名函数）简介)。

提示

值得注意的是，以下内容不能用于常量表达式：

  • 非常量变量。
  • const非整型变量，即使它们有常量表达式初始化器（例如 const double d { 1.2 };）。要在常量表达式中使用此类变量，请将它们定义为constexpr变量（参见课程 5.6 -- Constexpr 变量)。
  • 非constexpr函数的返回值（即使返回表达式是常量表达式）。
  • 函数参数（即使函数是constexpr）。
  • 操作数不是常量表达式的运算符（例如 x + y 当 x 或 y 不是常量表达式，或 std::cout << "hello\n" 为 std::cout 不是常量表达式时）。
  • 运算符 new， delete， throw， typeid、和 operator, （逗号）。

包含上述任何内容的表达式都是运行时表达式。

相关内容

关于常量表达式的精确定义，请参见 cppreference 上关于常量表达式的页面。注意，常量表达式是通过它不是什么来定义的。这意味着我们需要推断它是什么。祝你好运！

术语

在讨论常量表达式时，通常使用两种表述方式：

  • “X 可在常量表达式中使用”常用于强调 X 是什么。例如，“5 可在常量表达式中使用”强调字面量 5 可以在常量表达式中使用。
  • “X 是一个常量表达式”有时用于强调整个表达式（由 X 组成）是一个常量表达式。例如，“5 是一个常量表达式”强调表达式 5 是一个常量表达式。

后一种表述在说“字面量是常量表达式”时可能听起来有些别扭（因为它们实际上是值）。但这只是意味着由字面量组成的表达式是一个常量表达式。

顺便说一句……

当常量表达式被定义时， const 整型被保留了下来，因为它们在语言中已经被视为常量表达式。

委员会讨论了是否 const 具有常量表达式初始化器的非整型也应该被视为常量表达式（为了与 const 整型的情况保持一致）。最终，他们决定不这样做，以促进更一致地使用 constexpr。

常量表达式和非常量表达式的示例

在下面的程序中，我们查看一些表达式语句，并指出每个表达式是常量表达式还是运行时表达式：

#include <iostream>

int getNumber()
{
    std::cout << "Enter a number: ";
    int y{};
    std::cin >> y; // 只能在运行时执行

    return y;      // 这个返回表达式是一个运行时表达式
}

// 非 constexpr 函数的返回值是一个运行时表达式
// 即使返回表达式是一个常量表达式
int five()
{
    return 5;      // 这个返回表达式是一个常量表达式
}

int main()
{
    // 字面量可以在常量表达式中使用
    5;                           // 常量表达式            
    1.2;                         // 常量表达式
    "Hello world!";              // 常量表达式

    // 大多数具有常量表达式操作数的运算符可以在常量表达式中使用
    5 + 6;                       // 常量表达式
    1.2 * 3.4;                   // 常量表达式
    8 - 5.6;                     // 常量表达式（即使操作数类型不同）
    sizeof(int) + 1;             // 常量表达式（sizeof 可以在编译时确定）

    // 非 constexpr 函数的返回值只能在运行时表达式中使用
    getNumber();                 // 运行时表达式
    five();                      // 运行时表达式（即使返回表达式是常量表达式）

    // 没有常量表达式操作数的运算符只能在运行时表达式中使用
    std::cout << 5;              // 运行时表达式（std::cout 不是常量表达式操作数）

    return 0;
}

在下面的代码片段中，我们定义了一堆变量，并指出它们是否可以在常量表达式中使用：

    // 具有常量表达式初始化器的 const 整型变量可以在常量表达式中使用：
    const int a { 5 };           // a 可在常量表达式中使用
    const int b { a };           // b 可在常量表达式中使用（根据前一条语句，a 是常量表达式）
    const long c { a + 2 };      // c 可在常量表达式中使用（operator+ 具有常量表达式操作数）

    // 其他变量不能在常量表达式中使用（即使它们有常量表达式初始化器）：
    int d { 5 };                 // d 不能在常量表达式中使用（d 不是 const）
    const int e { d };           // e 不能在常量表达式中使用（初始化器不是常量表达式）
    const double f { 1.2 };      // f 不能在常量表达式中使用（不是 const 整型变量）

常量表达式何时在编译时求值

由于常量表达式总是能够在编译时求值，你可能认为常量表达式总是会在编译时求值。但反直觉的是，情况并非如此。

编译器只在 需要 常量表达式的上下文中才 必须 在编译时求值常量表达式。

术语

必须在编译时求值的表达式的技术名称是 明显常量求值的表达式。你可能只在技术文档中遇到这个术语。

在不需要常量表达式的上下文中，编译器可以选择在编译时或运行时求值常量表达式。

const int x { 3 + 4 }; // 常量表达式 3 + 4 必须在编译时求值
int y { 3 + 4 };       // 常量表达式 3 + 4 可以在编译时或运行时求值

变量 x 的类型为 const int 并且具有常量表达式初始化器， x 可在常量表达式中使用。它的初始化器必须在编译时求值（否则 x 的值在编译时未知，并且 x 不能在常量表达式中使用）。另一方面，变量 y 是非常量，所以 y 不能在常量表达式中使用。尽管它的初始化器是一个常量表达式，但编译器可以决定在编译时或运行时求值该初始化器。

即使不是必须的，现代编译器也会在启用优化时 通常 在编译时求值常量表达式。

关键提示

编译器只在 需要 常量表达式的上下文中才 必须 一个常量表达式。在其他情况下，它可能会也可能不会这样做。

提示

表达式在编译时完全求值的可能性可以分类如下：

  • 从不：编译器无法在编译时确定所有值的非常量表达式。
  • 可能：编译器能够在编译时确定所有值的非常量表达式（根据 as-if 规则进行优化）。
  • 很可能：在不要求常量表达式的上下文中使用的常量表达式。
  • 总是：在要求常量表达式的上下文中使用的常量表达式。

进阶读者

那么为什么 C++ 不要求所有常量表达式都在编译时求值呢？至少有两个充分的理由：

  1. 编译时求值会使调试更加困难。如果我们的代码中存在一个在编译时求值的错误计算，我们诊断问题的工具将非常有限。允许非必需的常量表达式在运行时求值（通常在关闭优化时）可以对我们的代码进行运行时调试。能够在程序运行时逐步检查其状态，可以使发现错误变得更加容易。
  2. 为编译器提供灵活性，使其能够根据自身判断（或受编译器选项影响）进行优化。例如，编译器可能希望提供一个选项，将所有非必需的常量表达式求值推迟到运行时，以改善开发者的编译时间。

为什么编译时表达式必须是常量 可选

你可能想知道为什么编译时表达式只能包含常量对象（以及可以在编译时求值为常量的运算符和函数）。

考虑以下程序：

#include <iostream>

int main()
{
    int x { 5 };
    // 此时编译器已知 x

    std::cin >> x; // 从用户读取 x 的值
    // 编译器不再已知 x

    return 0;
}

首先， x 用值 5。的值 x 初始化，此时编译器已知该值。但随后 x 被赋予来自用户的值。编译器无法在编译时知道用户将提供什么值，因此在此之后， x 的值对编译器来说是未知的。因此，表达式 x 并不总是可以在编译时求值，这违反了此类表达式必须始终能够在编译时求值的要求。

因为常量不能改变其值，所以初始值在编译时可求值的常量变量将始终具有编译时已知的值。这保持了简单性。

虽然语言设计者本可以将编译时表达式定义为所有值当前在编译时已知的表达式（而不是必须始终能够在编译时求值的表达式），但这会给编译器增加显著的复杂性（因为编译器现在需要负责确定每个变量何时可能被更改为编译时未知的值）。添加一行代码（例如 std::cin >> x）可能会破坏程序的其他部分（如果 x 被用于任何需要编译时已知值的上下文中）。

小测验时间

问题 #1

对于每个语句，请识别：

  • 初始值设定项是常量表达式还是非常量表达式。
  • 变量是常量表达式还是非常量表达式。

a)

    char a { 'q' };

显示答案

'q' 是常量表达式，因为它是字面量。
a 是非常量表达式，因为它被定义为非常量。

b)

    const int b { 0 };

显示答案

0 是常量表达式，因为它是字面量。
b 是常量表达式，因为它是 const 整型，且具有常量表达式初始值设定项。

c)

    const double c { 5.0 };

显示答案

'5.0' 是常量表达式，因为它是字面量。
c 是非常量表达式，因为它被定义为 const ，但不是整型。

根据编译时常量的定义，只有 const 整型 变量且具有常量表达式初始值设定项才是编译时常量。 c 是 double 类型，不是整型，因此不符合此定义。

d)

    const int d { a * 2 }; // a 定义为 char a { 'q' };

显示答案

a 不是常量表达式，因此 a * 2 是非常量表达式。
d 是非常量表达式，因为初始值设定项不是常量表达式。

e)

    int e { c + 1.0 }; // c 定义为 const double c { 5.0 };

显示答案

c 是非常量表达式，因此 c + 1.0 是非常量表达式。
e 是非常量表达式，因为它没有被定义为 const ，并且没有常量表达式初始值设定项。

f)

    const int f { d * 2 }; // d 定义为 const int d { 0 };

显示答案

两者都 d 和 2 是常量表达式，因此 d * 2 是一个常量表达式。
f 是常量表达式，因为它是 const 整型，且具有常量表达式初始值设定项。

g)

    const int g { getNumber() }; // getNumber 按值返回一个 int

显示答案

getNumber() 返回一个非常量值，因此它是一个非常量表达式。
g 是一个非常量表达式，因为初始化器是一个非常量表达式。

h)
额外加分：

    const int h{};

显示答案

{} 调用值初始化。这里没有显式初始化器。
h 是常量表达式，因为它是 const 具有常量表达式初始化器的整数类型（值初始化将初始化 h 切换到 0，这是一个常量表达式）。
