14.16 — 转换构造函数与explicit关键字

● 机器译文 课程 14.16 查看英文原文

在课程 10.1 -- 隐式类型转换我们介绍了类型转换和隐式类型转换的概念，即当需要时，如果存在这样的转换，编译器会将一种类型的值隐式转换为另一种类型的值。

这允许我们做这样的事情：

#include <iostream>

void printDouble(double d) // 有一个 double 参数
{
    std::cout << d;
}

int main()
{
    printDouble(5); // 我们提供了一个 int 参数

    return 0;
}

在上面的例子中，我们的 printDouble 函数有一个 double 参数，但我们传入了一个类型为 int的参数。由于参数类型和实参类型不匹配，编译器会检查是否可以将实参的类型隐式转换为参数的类型。在这种情况下，使用数值转换规则，int值 5 将被转换为 double 值 5.0 ，并且由于我们按值传递，参数 d 将用这个值进行拷贝初始化。

用户定义转换

现在考虑以下类似的例子：

#include <iostream>

class Foo
{
private:
    int m_x{};
public:
    Foo(int x)
        : m_x{ x }
    {
    }

    int getX() const { return m_x; }
};

void printFoo(Foo f) // 有一个 Foo 参数
{
    std::cout << f.getX();
}

int main()
{
    printFoo(5); // 我们提供了一个 int 参数

    return 0;
}

在这个版本中， printFoo 有一个 Foo 参数，但我们传入了一个类型为 int的参数。由于这些类型不匹配，编译器会尝试将int值 5 转换为 Foo 对象，以便可以调用该函数。

与第一个例子不同，其中我们的参数和实参类型都是基本类型（因此可以使用内置的数值提升/转换规则进行转换），在这个例子中，我们的类型之一是程序定义类型。C++标准没有特定的规则告诉编译器如何将值转换为（或从）程序定义类型。

相反，编译器会查看我们是否定义了某个函数，可以用来执行这样的转换。这样的函数称为 用户定义转换。

转换构造函数

在上面的例子中，编译器会找到一个函数，允许它将int值 5 转换为 Foo 对象。这个函数就是 Foo(int) 构造函数。

到目前为止，我们通常使用构造函数来显式构造对象：

    Foo x { 5 }; // 显式将 int 值 5 转换为 Foo

想想这是做什么：我们提供一个 int 值（5）并得到一个 Foo 对象作为返回。

在函数调用的上下文中，我们试图解决同样的问题：

    printFoo(5); // 隐式将 int 值 5 转换为 Foo

我们提供一个 int 值（5），并且我们想要一个 Foo 对象作为返回。 Foo(int) 构造函数正是为此设计的！

所以在这种情况下，当 printFoo(5) 被调用时，参数 f 使用 Foo(int) 构造函数进行拷贝初始化，以 5 作为参数！

顺便说一句……

在C++17之前，当 printFoo(5) 被调用时， 5 被隐式转换为一个临时的 Foo 对象，使用 Foo(int) 构造函数。然后这个临时的 Foo 对象被拷贝构造到参数 f。

从C++17开始，拷贝被强制省略。参数 f 通过值 5进行拷贝初始化，并且不需要调用拷贝构造函数（即使拷贝构造函数被删除也能工作）。

可用于执行隐式转换的构造函数称为 转换构造函数。默认情况下，所有构造函数都是转换构造函数。

只能应用一个用户定义的转换

现在考虑以下示例：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name{};

public:
    Employee(std::string_view name)
        : m_name{ name }
    {
    }

    const std::string& getName() const { return m_name; }
};

void printEmployee(Employee e) // 有一个 Employee 参数
{
    std::cout << e.getName();
}

int main()
{
    printEmployee("Joe"); // 我们正在提供一个字符串字面量参数

    return 0;
}

在这个版本中，我们将 Foo 类替换为 Employee 类。 printEmployee 有一个 Employee 参数，我们传入一个C风格字符串字面量。并且我们有一个转换构造函数： Employee(std::string_view)。

你可能会惊讶地发现这个版本无法编译。原因很简单：执行隐式转换时只能应用一个用户定义的转换，而这个示例需要两个。首先，我们的C风格字符串字面量必须转换为 std::string_view （使用 std::string_view 转换构造函数），然后我们的 std::string_view 必须转换为 Employee （使用 Employee(std::string_view) 转换构造函数）。

有两种方法可以使这个示例工作：

  1. 的快速指南本指南并非全面，但旨在突出最常见的情况： std::string_view 字面量：
int main()
{
    using namespace std::literals;
    printEmployee( "Joe"sv); // 现在是一个 std::string_view 字面量

    return 0;
}

这之所以有效，是因为现在只需要一个用户定义的转换（从 std::string_view 切换到 Employee)。

  1. 显式构造一个 Employee 而不是隐式创建一个：
int main()
{
    printEmployee(Employee{ "Joe" });

    return 0;
}

这也有效，因为现在只需要一个用户定义的转换（从字符串字面量到用于初始化 std::string_view 对象的 Employee ）。将显式构造的 Employee 对象传递给函数不需要进行第二次转换。

后一个示例提出了一种有用的技术：将隐式转换转换为显式定义是很容易的。我们将在本课后面看到更多这样的例子。

关键提示

通过使用直接列表初始化（或直接初始化），可以轻松地将隐式转换转换为显式定义。

当转换构造函数出错时

考虑以下程序：

#include <iostream>

class Dollars
{
private:
    int m_dollars{};

public:
    Dollars(int d)
        : m_dollars{ d }
    {
    }

    int getDollars() const { return m_dollars; }
};

void print(Dollars d)
{
    std::cout << "$" << d.getDollars();
}

int main()
{
    print(5);

    return 0;
}

当我们调用 print(5)， Dollars(int) 转换构造函数将用于将 5 转换为 Dollars 对象。因此，该程序输出：

$5

尽管这可能是调用者的意图，但很难判断，因为调用者没有提供任何迹象表明这确实是他们想要的。完全有可能调用者假设这会输出 5，并且没有预料到编译器会静默地隐式转换我们的 int 值转换为 Dollars 对象以满足这个函数调用。

虽然这个例子很简单，但在更大更复杂的程序中，很容易被编译器执行一些你没有预料到的隐式转换所惊讶，从而导致运行时出现意外行为。

如果我们的 print(Dollars) 函数只能通过 Dollars 对象，而不是任何可以隐式转换为 Dollars （尤其是像 int这样的基本类型）的值。这将减少意外错误的可能性。

explicit 关键字

为了解决此类问题，我们可以使用 显式 关键字告诉编译器某个构造函数不应被用作转换构造函数。

将构造函数设为 explicit 有两个显著后果：

  • explicit 构造函数不能用于执行拷贝初始化或拷贝列表初始化。
  • explicit 构造函数不能用于执行隐式转换（因为这使用了拷贝初始化或拷贝列表初始化）。

让我们将之前示例中的 Dollars(int) 构造函数更新为 explicit 构造函数：

 #include <iostream>

class Dollars
{
private:
    int m_dollars{};

public:
    explicit Dollars(int d) // 现在是显式的
        : m_dollars{ d }
    {
    }

    int getDollars() const { return m_dollars; }
};

void print(Dollars d)
{
    std::cout << "$" << d.getDollars();
}

int main()
{
    print(5); // 编译错误，因为 Dollars(int) 是显式的

    return 0;
}

由于编译器不能再将 Dollars(int) 用作转换构造函数，它无法找到将 5 转换为 Dollars的方法。因此，它将生成一个编译错误。

对于声明（在类内部）和定义（在类外部）分开的构造函数， explicit 关键字仅用于声明。

explicit 构造函数可用于直接初始化和直接列表初始化

explicit 构造函数仍然可以用于直接初始化和直接列表初始化：

// 假设 Dollars(int) 是显式的
int main()
{
    Dollars d1(5); // ok
    Dollars d2{5}; // ok
}

现在，让我们回到之前的示例，我们将 Dollars(int) 构造函数设为 explicit，因此以下代码生成了一个编译错误：

    print(5); // 编译错误，因为 Dollars(int) 是显式的

如果我们实际上想要调用 print() 替换为 int 值 5 但构造函数是 explicit 的呢？解决方法很简单：与其让编译器隐式转换 5 转换为 Dollars 传递给 print()，我们可以显式定义 Dollars 对象本身：

    print(Dollars{5}); // ok：显式创建一个 Dollars

这是允许的，因为我们仍然可以使用 explicit 构造函数来列表初始化对象。既然我们已经显式构造了一个 Dollars，参数类型与参数类型匹配，因此不需要转换！

这不仅编译并运行，而且更好地记录了我们的意图，因为它明确表明我们打算用 Dollars 播种），我们将其用作全局

注意 static_cast 返回一个直接初始化的对象，因此它在执行转换时会考虑 explicit 构造函数：

    print(static_cast<Dollars>(5)); // ok：static_cast 会使用显式构造函数

按值返回与 explicit 构造函数

当我们从函数返回值时，如果该值与函数的返回类型不匹配，将发生隐式转换。与按值传递一样，此类转换不能使用 explicit 构造函数。

以下程序展示了返回值的几种变体及其结果：

#include <iostream>

class Foo
{
public:
    explicit Foo() // 注意：显式（仅为了示例）
    {
    }

    explicit Foo(int x) // 注意：显式
    {
    }
};

Foo getFoo()
{
    // 显式 Foo() 的情况
    return Foo{ };   // ok
    return { };      // 错误：无法隐式转换初始化列表为Foo

    // explicit Foo(int) 的情况
    return 5;        // 错误：无法隐式转换int为Foo
    return Foo{ 5 }; // ok
    return { 5 };    // 错误：无法隐式转换初始化列表为Foo
}

int main()
{
    return 0;
}

也许令人惊讶的是， return { 5 } 被认为是一种转换。

使用 explicit

的最佳实践是默认将任何接受单个参数的构造函数设为 explicit 这包括具有多个参数且其中大部分或全部具有默认值的构造函数。这将禁止编译器使用该构造函数进行隐式转换。如果需要隐式转换，只会考虑非 explicit 构造函数。如果找不到非 explicit 构造函数来执行转换，编译器将报错。

如果在特定情况下确实需要这样的转换，可以轻松地将隐式转换转换为使用直接列表初始化的显式定义。

以下 不应该 应显式声明：

  • 拷贝（和移动）构造函数（因为它们不执行转换）。

以下 通常不 应显式声明：

  • 无参数的默认构造函数（因为它们仅用于转换为默认对象，通常不需要限制）。 {} 只接受多个参数的构造函数（因为它们通常不是转换的候选）。

  • 接受单个参数的构造函数。

有些情况下，让单参数构造函数非显式是有意义的。当以下所有条件都成立时，这可能很有用：

  • 构造的对象在语义上等价于参数值。
  • 转换是高效的。

例如，接受C风格字符串参数的 std::string_view 构造函数不是显式的，因为不太可能出现我们不希望将C风格字符串视为 std::string_view 的情况。相反，接受 std::string 的 std::string_view 构造函数被标记为显式，因为虽然 std::string 值在语义上等价于 std::string_view 值，但构造一个 std::string 性能不佳。

最佳实践

默认情况下，使任何接受单个参数的构造函数 explicit 如果类型之间的隐式转换在语义上等价且性能良好，可以考虑使构造函数非显式。

不要使拷贝或移动构造函数显式，因为它们不执行转换。
