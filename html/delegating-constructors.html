14.12 — 委托构造函数

● 机器译文 课程 14.12 查看英文原文

只要有可能，我们都希望减少冗余代码（遵循 DRY 原则——不要重复自己）。

考虑以下函数：

void A()
{
    // 执行任务 A 的语句
}

void B()
{
    // 执行任务 A 的语句
    // 执行任务 B 的语句
}

两个函数都有一组执行完全相同操作的语句（任务 A）。在这种情况下，我们可以这样重构：

void A()
{
    // 执行任务 A 的语句
}

void B()
{
    A();
    // 执行任务 B 的语句
}

这样，我们就删除了函数中存在的冗余代码 A() 和 B()。这使得我们的代码更易于维护，因为只需要在一个地方进行更改。

当一个类包含多个构造函数时，每个构造函数中的代码通常非常相似甚至完全相同，存在大量重复。我们也希望尽可能消除构造函数中的冗余。

考虑以下示例：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name { "???" };
    int m_id { 0 };
    bool m_isManager { false };

public:
    Employee(std::string_view name, int id) // 员工必须有姓名和 id
        : m_name{ name }, m_id { id }
    {
        std::cout << "Employee " << m_name << " created\n";
    }

    Employee(std::string_view name, int id, bool isManager) // 他们可以选择成为经理
        : m_name{ name }, m_id{ id }, m_isManager { isManager }
    {
        std::cout << "Employee " << m_name << " created\n";
    }
};

int main()
{
    Employee e1{ "James", 7 };
    Employee e2{ "Dave", 42, true };
}

每个构造函数的主体都有完全相同的打印语句。

作者注

通常，让构造函数打印内容并不是一个好主意（除非用于调试目的），因为这意味着在不需要打印的情况下无法使用该构造函数创建对象。我们在此示例中这样做是为了帮助说明发生了什么。

构造函数可以调用其他函数，包括类的其他成员函数。所以我们可以这样重构：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name { "???" };
    int m_id{ 0 };
    bool m_isManager { false };

    void printCreated() const // 我们的新辅助函数
    {
        std::cout << "Employee " << m_name << " created\n";
    }

public:
    Employee(std::string_view name, int id)
        : m_name{ name }, m_id { id }
    {
        printCreated(); // 我们在这里调用它
    }

    Employee(std::string_view name, int id, bool isManager)
        : m_name{ name }, m_id{ id }, m_isManager { isManager }
    {
        printCreated(); // 以及这里
    }
};

int main()
{
    Employee e1{ "James", 7 };
    Employee e2{ "Dave", 42, true };
}

虽然这比之前的版本更好（因为冗余语句被替换为冗余函数调用），但它需要引入一个新函数。而且我们的两个构造函数也都在初始化 m_name 和 m_id。理想情况下，我们也应该消除这种冗余。

我们能做得更好吗？可以。但这也是许多新手程序员遇到麻烦的地方。

在函数主体中调用构造函数会创建一个临时对象

类似于上面例子中函数 B() 调用函数 A() ，显而易见的解决方案似乎是从 Employee(std::string_view, int) 的主体中调用 Employee(std::string_view, int, bool) 构造函数来初始化 m_name， m_id并打印语句。如下所示：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name { "???" };
    int m_id { 0 };
    bool m_isManager { false };

public:
    Employee(std::string_view name, int id)
        : m_name{ name }, m_id { id } // 这个构造函数初始化 name 和 id
    {
        std::cout << "Employee " << m_name << " created\n"; // 我们的打印语句回到了这里
    }

    Employee(std::string_view name, int id, bool isManager)
        : m_isManager { isManager } // 这个构造函数初始化 m_isManager
    {
        // 调用 Employee(std::string_view, int) 来初始化 m_name 和 m_id
        Employee(name, id); // 这不会按预期工作！
    }

    const std::string& getName() const { return m_name; }
};

int main()
{
    Employee e2{ "Dave", 42, true };
    std::cout << "e2 has name: " << e2.getName() << "\n"; // 打印 e2.m_name
}

但这并不能正确工作，因为程序输出如下：

Employee Dave created
e2 has name: ???

尽管 Employee Dave created 打印后，在 e2 完成构造后， e2.m_name 似乎仍然设置为其初始值 "???"。这怎么可能？

我们期望 Employee(name, id) 调用构造函数以继续初始化当前的隐式对象（e2）。但是类对象的初始化在成员初始化列表执行完毕后就已经完成了。当我们开始执行构造函数的主体时，再进行初始化已经太晚了。

当从函数主体中调用时，看起来像构造函数调用的函数调用通常会创建并直接初始化一个临时对象（在另一种情况下，你会得到编译错误）。在上面的例子中， Employee(name, id); 创建了一个临时的（未命名的）Employee 对象。这个临时对象的 m_name 被设置为 Dave被设置，并且它打印了 Employee Dave created。然后临时对象被销毁。 e2 的 m_name 或 m_id 从未从默认值改变。

最佳实践

不应直接从另一个函数的主体中调用构造函数。这样做要么导致编译错误，要么直接初始化一个临时对象。
如果你确实想要一个临时对象，优先使用列表初始化（这清楚地表明你打算创建一个对象）。

那么，如果我们不能从另一个构造函数的主体中调用构造函数，我们该如何解决这个问题呢？

委托构造函数

构造函数可以委托（转移责任）初始化给同一类类型的另一个构造函数。这个过程有时被称为 构造函数链 ，这样的构造函数被称为 委托构造函数。

要让一个构造函数委托另一个构造函数进行初始化，只需在成员初始化列表中调用该构造函数：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name { "???" };
    int m_id { 0 };

public:
    Employee(std::string_view name)
        : Employee{ name, 0 } // 将初始化委托给 Employee(std::string_view, int) 构造函数
    {
    }

    Employee(std::string_view name, int id)
        : m_name{ name }, m_id { id } // 实际初始化成员
    {
        std::cout << "Employee " << m_name << " created\n";
    }

};

int main()
{
    Employee e1{ "James" };
    Employee e2{ "Dave", 42 };
}

当 e1 { "James" } 被初始化，匹配的构造函数 Employee(std::string_view) 被调用，参数 name 设置为 "James"。该构造函数的成员初始化列表将初始化委托给另一个构造函数，因此 Employee(std::string_view, int) 被调用。值 name ("James"作为第一个参数传递，字面量 0 作为第二个参数传递。被委托构造函数的成员初始化列表随后初始化成员。然后执行被委托构造函数的函数体。接着控制权返回给初始构造函数，执行其（空的）函数体。最后，控制权返回给调用者。

这种方法的缺点是有时需要重复初始化值。在委托给 Employee(std::string_view, int) 构造函数时，我们需要为 int 参数提供一个初始化值。我们不得不硬编码字面量 0，因为无法引用默认成员初始化器。

关于委托构造函数还有几点补充说明。首先，委托给另一个构造函数的构造函数不允许自己进行任何成员初始化。因此，你的构造函数要么委托，要么初始化，但不能同时进行。

顺便说一句……

注意，我们让 Employee(std::string_view) （参数较少的构造函数）委托给 Employee(std::string_view name, int id) （参数较多的构造函数）。通常让参数较少的构造函数委托给参数较多的构造函数。

如果我们选择让 Employee(std::string_view name, int id) 委托给 Employee(std::string_view)，那么我们将无法初始化 m_id using id，因为构造函数只能委托或初始化，不能同时进行。

其次，一个构造函数可能委托给另一个构造函数，而后者又委托回第一个构造函数。这形成了无限循环，会导致程序耗尽栈空间并崩溃。你可以通过确保所有构造函数最终都解析到一个非委托构造函数来避免这种情况。

最佳实践

如果你有多个构造函数，考虑是否可以使用委托构造函数来减少重复代码。

使用默认参数减少构造函数

默认值有时也可以用来将多个构造函数减少为更少的构造函数。例如，通过为我们的 id 参数设置默认值，我们可以创建一个单一的 Employee 构造函数，它需要一个名称参数，但可选地接受一个 id 参数：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name{};
    int m_id{ 0 }; // 默认成员初始化器

public:

    Employee(std::string_view name, int id = 0) // id 的默认参数
        : m_name{ name }, m_id{ id }
    {
        std::cout << "Employee " << m_name << " created\n";
    }
};

int main()
{
    Employee e1{ "James" };
    Employee e2{ "Dave", 42 };
}

由于默认值必须附加在函数调用中最右边的参数上，定义类时的一个好做法是：先定义用户必须提供初始化值的成员（并将它们作为构造函数最左边的参数）。用户可以选择提供初始化值的成员（因为默认值是可接受的）应后定义（并将它们作为构造函数最右边的参数）。 必须 用户必须提供初始化值的成员应首先定义（并作为构造函数最左边的参数）。用户可以选择提供初始化值的成员（因为默认值是可接受的）应其次定义（并作为构造函数最右边的参数）。

最佳实践

用户必须提供初始化值的成员应首先定义（并作为构造函数最左边的参数）。用户可以选择提供初始化值的成员（因为默认值是可接受的）应其次定义（并作为构造函数最右边的参数）。

注意，这种方法也需要重复默认初始化值 m_id （'0'）：一次作为默认成员初始化器，一次作为默认参数。

一个难题：冗余构造函数 vs 冗余默认值

在上面的例子中，我们使用了委托构造函数和默认参数来减少构造函数冗余。但这两种方法都要求我们在不同地方重复成员的初始化值。不幸的是，目前没有办法指定委托构造函数或默认参数应使用默认成员初始化器的值。

关于是拥有更少的构造函数（重复初始化值）还是更多的构造函数（不重复初始化值）更好，存在各种观点。我们的观点是，通常更简单的做法是拥有更少的构造函数，即使这会导致初始化值的重复。

进阶读者

当我们有一个在多个地方使用的初始化值（例如，作为默认成员初始化器和构造函数参数的默认参数）时，我们可以定义一个命名常量，并在需要初始化值的地方使用它。这样可以将初始化值定义在一个地方。

虽然你可以为此使用 constexpr 全局变量，但更好的选择是在类内部使用一个 static constexpr 成员：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    static constexpr int default_id { 0 }; // 定义一个命名常量，包含我们想要的初始化值
    
    std::string m_name {};
    int m_id { default_id }; // 我们可以在这里使用它

public:

    Employee(std::string_view name, int id = default_id) // 我们也可以在这里使用它
        : m_name { name }, m_id { id }
    {
        std::cout << "Employee " << m_name << " created\n";
    }
};

int main()
{
    Employee e1 { "James" };
    Employee e2 { "Dave", 42 };
}

在此上下文中使用 static 关键字允许我们拥有一个单一的 default_id 所有对象共享的成员。如果没有 Employee ，每个 static对象都会有自己的独立 Employee 成员（这虽然可行，但会浪费内存）。 default_id 这种方法的缺点是每个额外的命名常量都会增加一个需要理解的名字，使你的类变得更加杂乱和复杂。是否值得这样做取决于需要多少这样的常量，以及初始化值在多少个地方被使用。

小测验时间

问题 #1

编写一个名为 Ball 的类。Ball 应该有两个私有成员变量，一个用于保存颜色（默认值： black），另一个用于保存半径（默认值： 10.0）。添加 4 个构造函数，分别处理以下情况：

int main()
{
    Ball def{};
    Ball blue{ "blue" };
    Ball twenty{ 20.0 };
    Ball blueTwenty{ "blue", 20.0 };

    return 0;
}

程序应产生以下结果：

Ball(black, 10)
Ball(blue, 10)
Ball(black, 20)
Ball(blue, 20)

显示答案

#include <iostream>
#include <string>
#include <string_view>

class Ball
{
private:
	std::string m_color{ "black" };
	double m_radius{ 10.0 };

public:
	// 默认构造函数（颜色和半径将使用默认值）
	Ball()
	{
            print();
	}

	// 只有半径参数的构造函数（颜色将使用默认值）
	Ball(double radius)
		: m_radius{ radius }
	{
            print();
	}

	// 只有颜色参数的构造函数（半径将使用默认值）
	Ball(std::string_view color)
		: m_color{ color }
	{
            print();
	}

	// 同时有颜色和半径参数的构造函数
	Ball(std::string_view color, double radius)
		: m_color{ color }
		, m_radius{ radius }
	{
            print();
	}

    void print() const
    {
        std::cout << "Ball(" << m_color << ", " << m_radius << ")\n";
    }
};

int main()
{
    Ball def{};
    Ball blue{ "blue" };
    Ball twenty{ 20.0 };
    Ball blueTwenty{ "blue", 20.0 };

    return 0;
}

问题 #2

通过使用默认参数和委托构造函数，减少上述程序中的构造函数数量。

显示答案

#include <iostream>
#include <string>
#include <string_view>

class Ball
{
private:
	std::string m_color{ "black" };
	double m_radius{ 10.0 };

public:
	// 处理 Ball(radius)
	Ball(double radius)
		: Ball{ "black", radius } // 委托给另一个构造函数
	{
		// 我们不需要在这里调用 print()，因为它会被
		// 我们委托的构造函数		
	}

	// 处理 Ball(color, radius)、Ball(color) 和 Ball()
	Ball(std::string_view color="black", double radius=10.0)
		: m_color{ color }
		, m_radius{ radius }
	{
		print();
	}

	void print() const
	{
		std::cout << "Ball(" << m_color << ", " << m_radius << ")\n";
	}
};

int main()
{
    Ball def{};
    Ball blue{ "blue" };
    Ball twenty{ 20.0 };
    Ball blueTwenty{ "blue", 20.0 };

    return 0;
}
