11.4 — 删除函数

● 机器译文 课程 11.4 查看英文原文

在某些情况下，编写的函数在使用特定类型的值调用时可能不会按预期行为执行。

考虑以下示例：

#include <iostream>

void printInt(int x)
{
    std::cout << x << '\n';
}

int main()
{
    printInt(5);    // // 可以：输出 5
    printInt('a');  // // 输出 97 -- 这合理吗？
    printInt(true); // // 输出 1 -- 这合理吗？
    
    return 0;
}

此示例输出：

5
97
1

虽然 printInt(5) 显然没问题，但对 printInt() 的另外两次调用则更值得商榷。对于 printInt('a')，编译器会确定可以将 'a' 提升为 int 值 97 以匹配函数调用与函数定义。并且它会将 true 提升为 int 值 1提升。而且它会在不报错的情况下执行此操作。

假设我们认为使用 printInt() 类型的值调用 char 或 bool没有意义。我们能做什么？

使用 = delete 说明符删除函数

当我们有一个明确不希望被调用的函数时，可以通过使用 = delete 说明符将该函数定义为已删除。如果编译器将函数调用匹配到已删除函数，编译将停止并产生编译错误。

以下是使用此语法的上述示例的更新版本：

#include <iostream>

void printInt(int x)
{
    std::cout << x << '\n';
}

void printInt(char) = delete; // // 对此函数的调用将导致编译停止
void printInt(bool) = delete; // // 对此函数的调用将导致编译停止

int main()
{
    printInt(97);   // 好的

    printInt('a');  // 编译错误：函数已删除
    printInt(true); // 编译错误：函数已删除

    printInt(5.0);  // 编译错误：匹配歧义
    
    return 0;
}

让我们快速查看其中一些。首先， printInt('a') 与 printInt(char)直接匹配，而后者已被删除。因此编译器会产生编译错误。 printInt(true) 与 printInt(bool)，它已被删除，因此也会产生编译错误。

printInt(5.0) 是一个有趣的案例，可能产生意想不到的结果。首先，编译器检查是否存在精确匹配 printInt(double) 不存在。接下来，编译器尝试找到最佳匹配。尽管 printInt(int) 是唯一未删除的函数，但已删除的函数仍然被视为函数重载解析中的候选。由于这些函数中没有一个是明确的最佳匹配，编译器将发出模糊匹配编译错误。

关键提示

= delete 意味着“我禁止这个”，而不是“这个不存在”。

已删除函数参与函数重载解析的所有阶段（不仅仅是精确匹配阶段）。如果选择了已删除函数，则会导致编译错误。

进阶读者

其他类型的函数也可以类似地被删除。

我们在课程 14.14 -- 拷贝构造函数简介中讨论删除成员函数，并在课程 11.7 -- 函数模板实例化。

删除所有不匹配的重载 高级

逐个删除多个函数重载虽然可行，但可能冗长。有时我们希望某个函数仅当参数类型与函数参数完全匹配时才被调用。我们可以通过使用函数模板（在即将到来的课程 11.6 -- 函数模板中介绍）来实现，如下所示：

#include <iostream>

// 此函数将优先处理 int 类型的参数
void printInt(int x)
{
    std::cout << x << '\n';
}

// 此函数模板将优先处理其他类型的参数
// 由于此函数模板已被删除，调用它将导致编译停止
template <typename T>
void printInt(T x) = delete;

int main()
{
    printInt(97);   // 好的
    printInt('a');  // 编译错误
    printInt(true); // 编译错误
    
    return 0;
}
