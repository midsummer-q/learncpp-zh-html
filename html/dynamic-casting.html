25.10 — 动态转换

● 机器译文 课程 25.10 查看英文原文

早在课程 10.6 -- 显式类型转换（强制转换）和 static_cast我们探讨了转换的概念，以及使用 static_cast 将变量从一种类型转换为另一种类型。

在本节课中，我们将继续探讨另一种转换：dynamic_cast。

dynamic_cast 的必要性

在处理多态时，你经常会遇到这样的情况：你有一个指向基类的指针，但你想访问仅存在于派生类中的某些信息。

考虑以下（略显刻意）的程序：

#include <iostream>
#include <string>
#include <string_view>

class Base
{
protected:
	int m_value{};

public:
	Base(int value)
		: m_value{value}
	{
	}
	
	virtual ~Base() = default;
};

class Derived : public Base
{
protected:
	std::string m_name{};

public:
	Derived(int value, std::string_view name)
		: Base{value}, m_name{name}
	{
	}

	const std::string& getName() const { return m_name; }
};

Base* getObject(bool returnDerived)
{
	if (returnDerived)
		return new Derived{1, "Apple"};
	else
		return new Base{2};
}

int main()
{
	Base* b{ getObject(true) };

	// 我们如何在这里打印 Derived 对象的名称，只拥有一个 Base 指针？

	delete b;

	return 0;
}

在这个程序中，函数 getObject() 总是返回一个 Base 指针，但该指针可能指向 Base 对象或 Derived 对象。当 Base 指针实际上指向 Derived 对象时，我们如何调用 Derived::getName()？

一种方法是向 Base 添加一个名为 getName() 的虚函数（这样我们就可以通过 Base 指针/引用来调用它，并让它动态解析为 Derived::getName()）。但是，如果你通过实际指向 Base 对象的 Base 指针/引用来调用它，这个函数会返回什么？实际上没有任何合理的值。此外，我们会用本应只属于 Derived 类关注的东西来污染 Base 类。

我们知道 C++ 会隐式地允许你将 Derived 指针转换为 Base 指针（实际上，getObject() 就是这么做的）。这个过程有时被称为 向上转换。然而，如果有办法将 Base 指针转换回 Derived 指针呢？那么我们就可以直接使用该指针调用 Derived::getName()，而完全不必担心虚函数解析。

dynamic_cast

C++ 提供了一种名为 dynamic_cast 的转换运算符，正是用于此目的。虽然 dynamic_cast 有几种不同的功能，但到目前为止，dynamic_cast 最常见的用途是将基类指针转换为派生类指针。这个过程称为 向下转换。

使用 dynamic_cast 就像使用 static_cast 一样。下面是我们上面例子中的 main() 函数，使用 dynamic_cast 将 Base 指针转换回 Derived 指针：

int main()
{
	Base* b{ getObject(true) };

	Derived* d{ dynamic_cast<Derived*>(b) }; // 使用 dynamic_cast 将 Base 指针转换为 Derived 指针

	std::cout << "The name of the Derived is: " << d->getName() << '\n';

	delete b;

	return 0;
}

这会打印：

The name of the Derived is: Apple

dynamic_cast 失败

上面的例子之所以有效，是因为 b 实际上指向一个 Derived 对象，因此将 b 转换为 Derived 指针是成功的。

然而，我们做了一个相当危险的假设：b 指向一个 Derived 对象。如果 b 没有指向 Derived 对象呢？这很容易通过将 getObject() 的参数从 true 改为 false 来测试。在这种情况下，getObject() 将返回一个指向 Base 对象的 Base 指针。当我们尝试将其 dynamic_cast 为 Derived 时，转换会失败，因为无法进行转换。

如果 dynamic_cast 失败，转换的结果将是一个空指针。

由于我们没有检查空指针结果，我们访问了 d->getName()，这将尝试解引用空指针，导致未定义行为（可能是崩溃）。

为了使这个程序安全，我们需要确保 dynamic_cast 的结果确实成功：

int main()
{
	Base* b{ getObject(true) };

	Derived* d{ dynamic_cast<Derived*>(b) }; // 使用 dynamic_cast 将 Base 指针转换为 Derived 指针

	if (d) // 确保 d 非空
		std::cout << "The name of the Derived is: " << d->getName() << '\n';

	delete b;

	return 0;
}

规则

始终通过检查空指针结果来确保你的 dynamic_cast 确实成功。

请注意，由于 dynamic_cast 在运行时进行一些一致性检查（以确保转换可以进行），使用 dynamic_cast 会带来性能损失。

另外请注意，在某些情况下，使用 dynamic_cast 进行向下转换将不起作用：

  1. 对于私有或受保护的继承。
  2. 对于没有声明或继承任何虚函数（因此没有虚表）的类。
  3. 在某些涉及虚基类的情况下（参见 此页面 了解其中一些情况的示例以及如何解决它们）。

使用 static_cast 进行向下转换

事实证明，向下转换也可以使用 static_cast 完成。主要区别在于 static_cast 不进行运行时类型检查来确保你所做的事情有意义。这使得使用 static_cast 更快，但更危险。如果你将 Base* 转换为 Derived*，即使 Base 指针没有指向 Derived 对象，它也会“成功”。当你尝试访问结果 Derived 指针（实际上指向 Base 对象）时，这将导致未定义行为。

如果你绝对确定要向下转换的指针会成功，那么使用 static_cast 是可以接受的。确保你知道所指向对象类型的一种方法是使用虚函数。以下是一种（不太好的）方法：

#include <iostream>
#include <string>
#include <string_view>

// 类标识符
enum class ClassID
{
	base,
	derived
	// 其他可以稍后添加
};

class Base
{
protected:
	int m_value{};

public:
	Base(int value)
		: m_value{value}
	{
	}

	virtual ~Base() = default;
	virtual ClassID getClassID() const { return ClassID::base; }
};

class Derived : public Base
{
protected:
	std::string m_name{};

public:
	Derived(int value, std::string_view name)
		: Base{value}, m_name{name}
	{
	}

	const std::string& getName() const { return m_name; }
	ClassID getClassID() const override { return ClassID::derived; }

};

Base* getObject(bool bReturnDerived)
{
	if (bReturnDerived)
		return new Derived{1, "Apple"};
	else
		return new Base{2};
}

int main()
{
	Base* b{ getObject(true) };

	if (b->getClassID() == ClassID::derived)
	{
		// 我们已经证明 b 指向一个 Derived 对象，所以这应该总是成功
		Derived* d{ static_cast<Derived*>(b) };
		std::cout << "The name of the Derived is: " << d->getName() << '\n';
	}

	delete b;

	return 0;
}

但如果你要费这么大劲来实现它（并承担调用虚函数和处理结果的开销），那么还不如直接使用 dynamic_cast。

另外，考虑一下如果我们的对象实际上是某个从 Derived 派生的类（我们称之为 D2）。上面的检查 b->getClassID() == ClassID::derived 会失败，因为 getClassId() 会返回 ClassID::D2，它不等于 ClassID::derived。而动态转换 D2 切换到 Derived 会成功，因为 D2 我们还调用了 Derived！

dynamic_cast 和引用

尽管上述所有示例都展示了指针的动态转换（这更常见），但 dynamic_cast 也可以用于引用。其工作方式与指针的 dynamic_cast 类似。

#include <iostream>
#include <string>
#include <string_view>

class Base
{
protected:
	int m_value;

public:
	Base(int value)
		: m_value{value}
	{
	}

	virtual ~Base() = default; 
};

class Derived : public Base
{
protected:
	std::string m_name;

public:
	Derived(int value, std::string_view name)
		: Base{value}, m_name{name}
	{
	}

	const std::string& getName() const { return m_name; }
};

int main()
{
	Derived apple{1, "Apple"}; // 创建一个苹果
	Base& b{ apple }; // 将基类引用设置为对象
	Derived& d{ dynamic_cast<Derived&>(b) }; // 使用引用而不是指针进行 dynamic_cast

	std::cout << "The name of the Derived is: " << d.getName() << '\n'; // 我们可以通过 d 访问 Derived::getName

	return 0;
}

由于 C++ 没有“空引用”，dynamic_cast 在失败时无法返回空引用。相反，如果引用的 dynamic_cast 失败，则会抛出 std::bad_cast 类型的异常。我们将在本教程后面讨论异常。

dynamic_cast 与 static_cast

新手程序员有时会困惑何时使用 static_cast 与 dynamic_cast。答案很简单：除非进行向下转换，否则使用 static_cast；在向下转换的情况下，dynamic_cast 通常是更好的选择。然而，你也应该考虑完全避免转换，而使用虚函数。

向下转换与虚函数

有些开发者认为 dynamic_cast 是邪恶的，表明类设计不良。这些程序员说你应该使用虚函数。

通常，使用虚函数 应该 应优先于向下转换。然而，有时向下转换是更好的选择：

  • 当你无法修改基类以添加虚函数时（例如，因为基类是标准库的一部分）
  • 当你需要访问派生类特有的内容时（例如，仅存在于派生类中的访问函数）
  • 当向基类添加虚函数没有意义时（例如，基类没有合适的返回值）。如果你不需要实例化基类，使用纯虚函数可能是一个选择。

关于 dynamic_cast 和 RTTI 的警告

运行时类型信息（RTTI）是 C++ 的一个特性，它在运行时暴露对象数据类型的信息。dynamic_cast 利用了这种能力。由于 RTTI 有相当大的空间性能开销，一些编译器允许你关闭 RTTI 作为优化。不用说，如果你这样做，dynamic_cast 将无法正常工作。
