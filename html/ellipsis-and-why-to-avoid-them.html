20.5 — 省略号（以及为何避免使用它们）

● 机器译文 课程 20.5 查看英文原文

在我们目前看到的所有函数中，函数将接受的参数数量必须事先已知（即使它们有默认值）。然而，在某些情况下，能够向函数传递可变数量的参数会很有用。C++ 提供了一个特殊的指定符，称为省略号（即“…”），它允许我们精确地做到这一点。

由于省略号很少使用，具有潜在危险，并且我们建议避免使用它们，因此本节可视为可选阅读内容。

使用省略号的函数采用以下形式：

return_type function_name(argument_list, ...)

浮点类型的 argument_list 是一个或多个普通函数参数。请注意，使用省略号的函数必须至少有一个非省略号参数。传递给函数的任何参数必须首先匹配 argument_list 参数。

省略号（以连续三个句点表示）必须始终是函数中的最后一个参数。省略号捕获任何额外的参数（如果有的话）。虽然不太准确，但从概念上可以将省略号视为一个数组，它保存 argument_list 之外的任何额外参数。

一个省略号示例

学习省略号的最佳方法是通过示例。因此，让我们编写一个使用省略号的简单程序。假设我们想编写一个计算一组整数平均值的函数。我们可以这样做：

#include <iostream>
#include <cstdarg> // needed to use ellipsis

// // 省略号必须是最后一个参数
// // count 是我们传递的额外参数的数量
double findAverage(int count, ...)
{
    int sum{ 0 };

    // // 我们通过 va_list 访问省略号，所以让我们声明一个
    std::va_list list;

    // // 我们使用 va_start 初始化 va_list。第一个参数是
    // // 要初始化的列表。第二个参数是最后一个非省略号
    // // 参数。
    va_start(list, count);

    // // 循环遍历所有省略号值
    for (int arg{ 0 }; arg < count; ++arg)
    {
         // // 我们使用 va_arg 从省略号中获取值
         // // 第一个参数是我们正在使用的 va_list
         // // 第二个参数是值的类型
         sum += va_arg(list, int);
    }

    // // 完成后清理 va_list。
    va_end(list);

    return static_cast<double>(sum) / count;
}

int main()
{
    std::cout << findAverage(5, 1, 2, 3, 4, 5) << '\n';
    std::cout << findAverage(6, 1, 2, 3, 4, 5, 6) << '\n';

    return 0;
}

这段代码打印：

3
3.5

如您所见，这个函数接受可变数量的参数！现在，让我们看看构成这个示例的各个部分。

首先，我们必须包含 cstdarg 头文件。这个头文件定义了 va_list、va_arg、va_start 和 va_end，这些是我们需要用来访问省略号中参数的宏。

然后我们声明使用省略号的函数。请记住，参数列表必须是一个或多个固定参数。在这种情况下，我们传递一个整数，告诉我们要平均多少个数字。省略号始终放在最后。

注意，省略号参数没有名称！相反，我们通过一种称为 va_list 的特殊类型来访问省略号中的值。从概念上，可以将 va_list 视为指向省略号数组的指针。首先，我们声明一个 va_list，为简单起见，我们将其称为“list”。

接下来我们需要做的是让 list 指向我们的省略号参数。我们通过调用 va_start() 来实现。va_start() 接受两个参数：va_list 本身，以及函数中最后一个非省略号参数的名称。 最后一个 一旦调用了 va_start()，va_list 就指向省略号中的第一个参数。

要获取 va_list 当前指向的参数的值，我们使用 va_arg()。va_arg() 也接受两个参数：va_list 本身，以及我们试图访问的参数的类型。注意，va_arg() 还会将 va_list 移动到省略号中的下一个参数！

最后，为了在完成时进行清理，我们调用 va_end()，并将 va_list 作为参数。

注意，我们可以随时再次调用 va_start() 来重置 va_list，使其再次指向省略号中的第一个参数。

为什么省略号危险：类型检查被暂停

省略号为程序员提供了很大的灵活性来实现可以接受可变数量参数的函数。然而，这种灵活性也带来了一些缺点。

对于常规函数参数，编译器使用类型检查来确保函数参数的类型与函数参数的类型匹配（或者可以隐式转换以匹配）。这有助于确保你不会在函数期望字符串时传递整数，反之亦然。然而，请注意，省略号参数没有类型声明。使用省略号时，编译器完全暂停对省略号参数的类型检查。这意味着可以将任何类型的参数发送到省略号！但缺点是，如果你使用没有意义的省略号参数调用函数，编译器将无法再警告你。使用省略号时，完全由调用者负责确保函数被调用时传递的省略号参数是函数能够处理的。显然，这留下了相当大的错误空间（特别是如果调用者不是编写该函数的人）。

让我们看一个相当微妙的错误示例：

    std::cout << findAverage(6, 1.0, 2, 3, 4, 5, 6) << '\n';

虽然乍一看这可能看起来无害，但请注意，第二个参数（第一个省略号参数）是 double 而不是整数。这可以正常编译，并产生一个有点令人惊讶的结果：

1.78782e+008

这是一个非常大的数字。这是怎么发生的？

正如你在之前的课程中学到的，计算机将所有数据存储为位序列。变量的类型告诉计算机如何将该位序列转换为有意义的值。然而，你刚刚了解到省略号丢弃了变量的类型！因此，从省略号中获取有意义值的唯一方法是手动告诉 va_arg() 下一个参数的预期类型是什么。这就是 va_arg() 的第二个参数的作用。如果实际参数类型与预期参数类型不匹配，通常会发生不好的事情。

在上面的 findAverage 程序中，我们告诉 va_arg() 我们的变量都预期具有 int 类型。因此，每次调用 va_arg() 都会返回下一个位序列，并将其解释为整数。

在这种情况下，问题在于我们作为第一个省略号参数传递的 double 是 8 字节，而 va_arg(list, int) 每次调用只会返回 4 字节的数据。因此，第一次调用 va_arg 只会读取 double 的前 4 个字节（产生垃圾结果），第二次调用 va_arg 会读取 double 的后 4 个字节（产生另一个垃圾结果）。因此，我们的整体结果是垃圾。

由于类型检查被暂停，即使我们做一些完全荒谬的事情，编译器也不会抱怨，比如：

    int value{ 7 };
    std::cout << findAverage(6, 1.0, 2, "Hello, world!", 'G', &value, &findAverage) << '\n';

信不信由你，这实际上可以正常编译，并在作者的机器上产生以下结果：

1.79766e+008

这个结果体现了“垃圾进，垃圾出”这句话，这是一句流行的计算机科学短语，“主要用于提醒人们注意，计算机与人类不同，会不加质疑地处理最无意义的输入数据并产生无意义的输出”（维基百科)。

所以，总结一下，参数的类型检查被暂停，我们必须信任调用者传递正确类型的参数。如果他们不这样做，编译器不会抱怨——我们的程序只会产生垃圾（或者可能崩溃）。

为什么省略号危险：省略号不知道传递了多少参数

省略号不仅丢弃了参数的 类型 类型，还丢弃了省略号中参数的 数量 这意味着我们必须设计自己的解决方案来跟踪传递到省略号中的参数数量。通常，这通过三种方式之一完成。

方法 1：传递一个长度参数

方法 #1 是让一个固定参数表示传递的可选参数的数量。这是我们在上面的 findAverage() 示例中使用的解决方案。

然而，即使在这里我们也会遇到麻烦。例如，考虑以下调用：

    std::cout << findAverage(6, 1, 2, 3, 4, 5) << '\n';

在作者撰写本文时的机器上，这产生了结果：

699773

发生了什么？我们告诉 findAverage() 我们将提供 6 个额外的值，但我们只给了它 5 个。因此，va_arg() 返回的前五个值是我们传入的值。它返回的第六个值是栈中某处的垃圾值。因此，我们得到了一个垃圾答案。

一个更隐蔽的情况：

    std::cout << findAverage(6, 1, 2, 3, 4, 5, 6, 7) << '\n';

这产生了答案 3.5，乍一看可能正确，但省略了平均值中的最后一个数字，因为我们只告诉它我们将提供 6 个额外的值（然后实际上提供了 7 个）。这类错误很难发现。

方法 2：使用哨兵值

方法 #2 是使用哨兵值。 哨兵 是一个特殊值，当遇到它时用于终止循环。例如，对于字符串，空终止符用作哨兵值来表示字符串的结束。对于省略号，哨兵通常作为最后一个参数传入。以下是 findAverage() 重写为使用哨兵值 -1 的示例：

#include <iostream>
#include <cstdarg> // needed to use ellipsis

// // 省略号必须是最后一个参数
double findAverage(int first, ...)
{
	// 我们必须特殊处理第一个数字
	int sum{ first };

	// // 我们通过 va_list 访问省略号，所以让我们声明一个
	std::va_list list;

	// // 我们使用 va_start 初始化 va_list。第一个参数是
	// // 要初始化的列表。第二个参数是最后一个非省略号
	// // 参数。
	va_start(list, first);

	int count{ 1 };
	// 无限循环
	while (true)
	{
		// // 我们使用 va_arg 从省略号中获取值
		// // 第一个参数是我们正在使用的 va_list
		// // 第二个参数是值的类型
		int arg{ va_arg(list, int) };

		// 如果此参数是我们的哨兵值，则停止循环
		if (arg == -1)
			break;

		sum += arg;
		++count;
	}

	// // 完成后清理 va_list。
	va_end(list);

	return static_cast<double>(sum) / count;
}

int main()
{
	std::cout << findAverage(1, 2, 3, 4, 5, -1) << '\n';
	std::cout << findAverage(1, 2, 3, 4, 5, 6, -1) << '\n';

	return 0;
}

注意，我们不再需要将显式长度作为第一个参数传递。相反，我们将哨兵值作为最后一个参数传递。

然而，这里有几个挑战。首先，C++ 要求我们至少传递一个固定参数。在前面的例子中，这是我们的计数变量。在这个例子中，第一个值实际上是要求平均值的数字的一部分。因此，我们不将第一个要求平均值的值作为省略号参数的一部分，而是将其显式声明为普通参数。然后我们需要在函数内部对其进行特殊处理（在这种情况下，我们将 sum 设置为 first 而不是 0 开始）。

其次，这要求用户将哨兵值作为最后一个值传入。如果用户忘记传入哨兵值（或传入了错误的值），函数将无限循环，直到遇到与哨兵匹配的垃圾值（或崩溃）。

最后，注意我们选择了 -1 作为哨兵。如果我们只想求正数的平均值，这没问题，但如果我们想包括负数呢？哨兵值只有在存在一个值超出您要解决的问题的有效值集合时才有效。

方法 3：使用解码字符串

方法 #3 涉及传递一个“解码字符串”，它告诉程序如何解释参数。

#include <iostream>
#include <string_view>
#include <cstdarg> // needed to use ellipsis

// // 省略号必须是最后一个参数
double findAverage(std::string_view decoder, ...)
{
	double sum{ 0 };

	// // 我们通过 va_list 访问省略号，所以让我们声明一个
	std::va_list list;

	// // 我们使用 va_start 初始化 va_list。第一个参数是
	// // 要初始化的列表。第二个参数是最后一个非省略号
	// // 参数。
	va_start(list, decoder);

	for (auto codetype: decoder)
	{
		switch (codetype)
		{
		case 'i':
			sum += va_arg(list, int);
			break;

		case 'd':
			sum += va_arg(list, double);
			break;
		}
	}

	// // 完成后清理 va_list。
	va_end(list);

	return sum / std::size(decoder);
}

int main()
{
	std::cout << findAverage("iiiii", 1, 2, 3, 4, 5) << '\n';
	std::cout << findAverage("iiiiii", 1, 2, 3, 4, 5, 6) << '\n';
	std::cout << findAverage("iiddi", 1, 2, 3.5, 4.5, 5) << '\n';

	return 0;
}

在这个例子中，我们传递一个字符串，它编码了可选变量的数量和类型。酷的是这让我们可以处理不同类型的参数。然而，这种方法也有缺点：解码字符串可能有点晦涩，如果可选参数的数量或类型与解码字符串不完全匹配，可能会发生不好的事情。

对于来自 C 的读者，这就是 printf 所做的！

更安全使用省略号的建议

首先，如果可能，根本不要使用省略号！通常，即使需要稍微多做一些工作，也有其他合理的解决方案。例如，在我们的 findAverage() 程序中，我们可以传入一个动态大小的整数数组。这将提供强类型检查（确保调用者不会尝试做一些无意义的事情），同时保留传递可变数量的整数进行平均的能力。

其次，如果您确实使用省略号，最好传递给省略号参数的所有值都是相同的类型（例如，全部是 int，或全部是 double，而不是混合类型）。混合不同类型会大大增加调用者无意中传入错误类型数据以及 va_arg() 产生垃圾结果的可能性。

第三，使用计数参数或解码字符串参数通常比使用哨兵值更安全。这迫使用户为计数/解码参数选择合适的值，从而确保省略号循环在合理次数的迭代后终止，即使它产生了垃圾值。

进阶读者

为了改进类似省略号的功能，C++11 引入了 parameter packs 和 variadic templates，它提供了类似于省略号的功能，但具有强类型检查。然而，显著的可用性挑战阻碍了该特性的采用。

在 C++17 中， 折叠表达式 被添加，这显著提高了参数包的可使用性，使其现在成为一个可行的选择。
