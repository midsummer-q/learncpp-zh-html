6.4 — 自增/自减运算符与副作用

● 机器译文 课程 6.4 查看英文原文

自增和自减变量

自增（加1）和自减（减1）变量非常常见，因此它们有自己的运算符。

运算符符号形式操作
前缀自增（前自增）++++x自增 x，然后返回 x
前缀自减（前自减）––––x自减 x，然后返回 x
后缀自增（后自增）++x++复制 x，然后自增 x，然后返回副本
后缀自减（后自减）––x––复制 x，然后自减 x，然后返回副本

注意每个运算符都有两个版本——前缀版本（运算符位于操作数之前）和后缀版本（运算符位于操作数之后）。

前缀自增和自减

前缀自增/自减运算符非常直接。首先，操作数被自增或自减，然后表达式求值为操作数的值。例如：

#include <iostream>

int main()
{
    int x { 5 };
    int y { ++x }; // x 递增到 6，x 求值为 6，6 被赋值给 y

    std::cout << x << ' ' << y << '\n';
    return 0;
}

这会打印：

6 6

后缀自增和自减

后缀自增/自减运算符更棘手。首先，创建操作数的一个副本。然后操作数（不是副本）被自增或自减。最后，副本（而不是原始值）被求值。例如：

#include <iostream>

int main()
{
    int x { 5 };
    int y { x++ }; // x 递增到 6，x 的原始副本求值为 5，并将 5 赋值给 y

    std::cout << x << ' ' << y << '\n';
    return 0;
}

这会打印：

6 5

让我们更详细地检查第6行是如何工作的。首先，创建一个 x 的临时副本，其初始值与 x （5）相同。然后实际的 x 从 5 切换到 6自增到6。然后 x 的副本（仍然具有值 55）被返回并赋值给 y。然后临时副本被丢弃。

因此， y 最终得到值 5 6（自增后的值），而 x 最终得到值 6 5（自增前的值）。

注意后缀版本需要更多步骤，因此可能不如前缀版本高效。

更多示例

下面是另一个示例，展示前缀和后缀版本之间的区别：

#include <iostream>

int main()
{
    int x { 5 };
    int y { 5 };
    std::cout << x << ' ' << y << '\n';
    std::cout << ++x << ' ' << --y << '\n'; // 前缀
    std::cout << x << ' ' << y << '\n';
    std::cout << x++ << ' ' << y-- << '\n'; // 后缀
    std::cout << x << ' ' << y << '\n';

    return 0;
}

这将产生输出：

5 5
6 4
6 4
6 4
7 3

在第8行，我们执行前缀自增和自减。在这一行， x 和 y 被自增/自减 在 之后，它们的值被发送到 std::cout，因此我们看到 std::cout 反映了它们更新后的值。

在第10行，我们执行后缀自增和自减。在这一行， x 和 y 的副本（具有自增前和自减前的值）被发送到 std::cout，因此我们在这里看不到自增和自减的效果。这些变化直到下一行才显现，当 x 和 y 会被再次求值。

何时使用前缀 vs 后缀

在许多情况下，前缀和后缀运算符产生相同的行为：

int main()
{
    int x { 0 };
    ++x; // 将 x 递增到 1
    x++; // 将 x 递增到 2

    return 0;
}

在代码既可以写成使用前缀也可以使用后缀的情况下，优先选择前缀版本，因为它们通常性能更高，并且不太可能引起意外。

最佳实践

优先使用前缀版本，因为它们性能更高且不太可能引起意外。

当使用后缀版本能产生比使用前缀版本编写的等效代码更简洁或更易理解的代码时，才使用后缀版本。

副作用

如果一个函数或表达式除了产生返回值之外还有某种可观察的效果，则称其具有 副作用 副作用。

副作用的常见示例包括改变对象的值、执行输入或输出、或更新图形用户界面（例如启用或禁用按钮）。

大多数情况下，副作用是有用的：

x = 5; // 赋值运算符具有改变 x 值的副作用
++x; // operator++ 具有递增 x 的副作用
std::cout << x; // operator<< 具有修改控制台状态的副作用

上面示例中的赋值运算符具有永久改变 x 值的副作用。即使语句执行完毕后， x 仍然具有值 5。类似地，对于 operator++，即使语句求值完毕后， x 的值也被改变了。输出 x 也具有修改控制台状态的副作用，因为你现在可以看到 x 的值被打印到控制台。

关键提示

赋值运算符、前缀运算符和后缀运算符具有永久改变对象值的副作用。
其他运算符（例如算术运算符）返回一个值，并且不修改它们的操作数。

副作用可能导致求值顺序问题

在某些情况下，副作用可能导致求值顺序问题。例如：

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int main()
{
    int x { 5 };
    int value{ add(x, ++x) }; // 未定义行为：这是 5 + 6，还是 6 + 6？
    // 这取决于编译器评估函数参数的顺序

    std::cout << value << '\n'; // 值可能是 11 或 12，具体取决于上面一行的评估方式！

    return 0;
}

C++ 标准没有定义函数参数的求值顺序。如果先求值左参数，则变为对 add(5, 6) 的调用，结果为 11。如果先求值右参数，则变为对 add(6, 6) 的调用，结果为 12！注意，这仅仅是因为函数 add() 的一个参数具有副作用才成为问题。

顺便说一句……

C++ 标准故意不定义这些事情，以便编译器可以对给定架构做最自然（因此性能最高）的事情。

副作用的顺序

在许多情况下，C++ 也没有指定运算符的副作用何时必须应用。这可能导致在同一个语句中多次使用具有副作用的对象时出现未定义行为。

例如，表达式 x + ++x 是未指定行为。当 x 被初始化为 1时，Visual Studio 和 GCC 将其求值为 2 + 2，而 Clang 将其求值为 1 + 2！这是由于编译器应用递增 x。

的副作用的时间点不同。 所有 可以通过确保任何具有副作用的变量在给定语句中最多使用一次来避免这些问题。

警告

C++ 没有定义函数参数或运算符操作数的求值顺序。

警告

不要在给定语句中多次使用具有副作用的变量。如果这样做，结果可能是未定义的。

一个例外是简单的赋值表达式，例如 x = x + y （这基本上等同于 x += y)。
