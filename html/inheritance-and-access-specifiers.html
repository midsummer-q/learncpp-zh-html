24.5 — 继承与访问说明符

● 机器译文 课程 24.5 查看英文原文

在本章的前几课中，你已经了解了基类继承的一些基本知识。到目前为止，我们所有的示例都使用了公有继承。也就是说，我们的派生类公有地继承基类。

在本课中，我们将更深入地探讨公有继承，以及另外两种继承方式（私有继承和保护继承）。我们还将研究不同类型的继承如何与访问说明符交互，以允许或限制对成员的访问。

到目前为止，你已经见过私有和公有访问说明符，它们决定了谁能访问类的成员。快速回顾一下：公有成员可以被任何人访问。私有成员只能被同一个类的成员函数或友元访问。这意味着派生类不能直接访问基类的私有成员！

class Base
{
private:
    int m_private {}; // 只能被 Base 的成员和友元访问（不能是派生类）
public:
    int m_public {}; // 可以被任何人访问
};

这很简单，你现在应该已经很熟悉了。

保护访问说明符

当涉及继承类时，情况会变得稍微复杂一些。

C++ 有第三个访问说明符，我们还没有讨论过，因为它只在继承上下文中才有用。 受保护 访问说明符允许成员所属的类、友元和派生类访问该成员。但是，保护成员不能在类外部访问。

class Base
{
public:
    int m_public {}; // 可以被任何人访问
protected:
    int m_protected {}; // 可以被 Base 的成员、友元和派生类访问
private:
    int m_private {}; // 只能被 Base 的成员和友元访问（但不能是派生类）
};

class Derived: public Base
{
public:
    Derived()
    {
        m_public = 1; // 允许：可以从派生类访问公有基类成员
        m_protected = 2; // 允许：可以从派生类访问受保护基类成员
        m_private = 3; // 不允许：不能从派生类访问私有基类成员
    }
};

int main()
{
    Base base;
    base.m_public = 1; // 允许：可以从类外部访问公有成员
    base.m_protected = 2; // 不允许：不能从类外部访问受保护成员
    base.m_private = 3; // 不允许：不能从类外部访问私有成员

    return 0;
}

在上面的例子中，你可以看到保护基类成员 m_protected 可以被派生类直接访问，但不能被公众访问。

那么什么时候应该使用保护访问说明符呢？

如果基类中有一个保护属性，派生类可以直接访问该成员。这意味着如果你以后更改了该保护属性的任何内容（类型、值的含义等），你可能需要同时修改基类和所有派生类。

因此，当你（或你的团队）将要从自己的类派生，并且派生类的数量合理时，使用保护访问说明符最为有用。这样，如果你对基类的实现进行了更改，并且因此需要更新派生类，你可以自己进行更新（并且由于派生类数量有限，不会花费太长时间）。

将成员设为私有意味着公众和派生类不能直接修改基类。这有利于使公众或派生类免受实现更改的影响，并确保不变量得到正确维护。然而，这也意味着你的类可能需要更大的公有（或保护）接口来支持公众或派生类操作所需的所有功能，这本身就有构建、测试和维护的成本。

一般来说，如果可能的话，最好将成员设为私有，并且只在计划有派生类且构建和维护这些私有成员接口的成本过高时才使用保护。

最佳实践

优先使用私有成员而非保护成员。

不同类型的继承及其对访问的影响

首先，类从其他类继承有三种不同的方式：公有、保护和私有。

要做到这一点，只需在选择要继承的类时指定所需的访问类型：

// 公有继承自 Base
class Pub: public Base
{
};

// 受保护继承自 Base
class Pro: protected Base
{
};

// 私有继承自 Base
class Pri: private Base
{
};

class Def: Base // 默认为私有继承
{
};

如果你没有选择继承类型，C++ 默认使用私有继承（就像成员如果没有指定访问权限则默认为私有访问一样）。

这样我们就有了 9 种组合：3 种成员访问说明符（公有、私有和保护）和 3 种继承类型（公有、私有和保护）。

那么它们之间有什么区别呢？简而言之，当成员被继承时，继承成员的访问说明符可能会根据所使用的继承类型而改变（仅在派生类中）。换句话说，基类中公有或保护的成员在派生类中可能会改变访问说明符。

这可能看起来有点令人困惑，但其实并不难。我们将用本课剩余部分详细探讨这一点。

在逐步分析示例时，请记住以下规则：

  • 一个类总是可以访问它自己的（非继承的）成员。
  • 公众根据所访问类的访问说明符来访问该类的成员。
  • 派生类根据从父类继承的访问说明符来访问继承的成员。这取决于访问说明符和所使用的继承类型。

公有继承

公有继承是目前最常用的继承类型。事实上，你很少会看到或使用其他类型的继承，因此你的主要精力应该放在理解这一部分上。幸运的是，公有继承也是最容易理解的。当你公有地继承一个基类时，继承的公有成员保持公有，继承的保护成员保持保护。继承的私有成员，由于在基类中是私有的而无法访问，仍然无法访问。

基类中的访问说明符公有继承时的访问说明符
公有公有
受保护受保护
私有不可访问

下面是一个示例，展示了它是如何工作的：

class Base
{
public:
    int m_public {};
protected:
    int m_protected {};
private:
    int m_private {};
};

class Pub: public Base // 注意：公有继承
{
    // 公有继承意味着：
    // 公有继承的成员保持公有（因此 m_public 被视为公有）
    // 受保护继承的成员保持受保护（因此 m_protected 被视为受保护）
    // 私有继承的成员保持不可访问（因此 m_private 不可访问）
public:
    Pub()
    {
        m_public = 1; // 可以：m_public 作为公有继承
        m_protected = 2; // 可以：m_protected 作为受保护继承
        m_private = 3; // 不可以：m_private 从派生类不可访问
    }
};

int main()
{
    // 外部访问使用被访问类的访问说明符。
    Base base;
    base.m_public = 1; // okay: m_public 在 Base 中是 public
    base.m_protected = 2; // not okay: m_protected 在 Base 中是 protected
    base.m_private = 3; // not okay: m_private 在 Base 中是 private

    Pub pub;
    pub.m_public = 1; // okay: m_public 在 Pub 中是 public
    pub.m_protected = 2; // not okay: m_protected 在 Pub 中是 protected
    pub.m_private = 3; // not okay: m_private 在 Pub 中不可访问

    return 0;
}

这与上面介绍保护访问说明符时的示例相同，只是我们还实例化了派生类，以展示在公有继承下，基类和派生类中的行为完全相同。

除非你有特定的理由不这样做，否则你应该使用公有继承。

最佳实践

除非你有特定的理由不这样做，否则请使用公有继承。

保护继承

保护继承是最不常见的继承方法。除了非常特殊的情况外，几乎从不使用。使用保护继承时，公有和保护成员变为保护，私有成员仍然不可访问。

由于这种继承形式非常罕见，我们将跳过示例，仅用表格总结：

基类中的访问说明符保护继承时的访问说明符
公有受保护
受保护受保护
私有不可访问

私有继承

使用私有继承时，基类的所有成员都以私有方式继承。这意味着私有成员不可访问，而受保护成员和公有成员变为私有。

注意，这并不影响派生类访问从父类继承的成员的方式！它只影响试图通过派生类访问这些成员的代码。

class Base
{
public:
    int m_public {};
protected:
    int m_protected {};
private:
    int m_private {};
};

class Pri: private Base // 注意：私有继承
{
    // 私有继承意味着：
    // 公有继承的成员变为私有（因此 m_public 被视为私有）
    // 保护继承的成员变为私有（因此 m_protected 被视为私有）
    // 私有继承的成员保持不可访问（因此 m_private 不可访问）
public:
    Pri()
    {
        m_public = 1; // okay: m_public 现在在 Pri 中是私有
        m_protected = 2; // okay: m_protected 现在在 Pri 中是私有
        m_private = 3; // not okay: 派生类不能访问基类中的私有成员
    }
};

int main()
{
    // 外部访问使用被访问类的访问说明符。
    // 在这种情况下，基类的访问说明符
    Base base;
    base.m_public = 1; // okay: m_public 在 Base 中是 public
    base.m_protected = 2; // not okay: m_protected 在 Base 中是 protected
    base.m_private = 3; // not okay: m_private 在 Base 中是 private

    Pri pri;
    pri.m_public = 1; // not okay: m_public 现在在 Pri 中是私有
    pri.m_protected = 2; // not okay: m_protected 现在在 Pri 中是私有
    pri.m_private = 3; // not okay: m_private 在 Pri 中不可访问

    return 0;
}

用表格总结如下：

基类中的访问说明符私有继承时的访问说明符
公有私有
受保护私有
私有不可访问

当派生类与基类没有明显关系，但在内部使用基类进行实现时，私有继承可能很有用。在这种情况下，我们可能不希望基类的公有接口通过派生类的对象暴露出来（就像公有继承那样）。

在实践中，私有继承很少使用。

最后一个例子

class Base
{
public:
	int m_public {};
protected:
	int m_protected {};
private:
	int m_private {};
};

Base 可以无限制地访问自己的成员。公有可以访问 m_public。派生类可以访问 m_public 和 m_protected。

class D2 : private Base // 注意：私有继承
{
	// 私有继承意味着：
	// 公有继承的成员变为私有
	// 保护继承的成员变为私有
	// 私有继承的成员保持不可访问
public:
	int m_public2 {};
protected:
	int m_protected2 {};
private:
	int m_private2 {};
};

D2 可以无限制地访问自己的成员。D2 可以访问 Base 的 m_public 和 m_protected 成员，但不能访问 m_private。由于 D2 私有继承了 Base，m_public 和 m_protected 现在在通过 D2 访问时被视为私有。这意味着公有不能在使用 D2 对象时访问这些变量，任何从 D2 派生的类也不能。

class D3 : public D2
{
	// 公有继承意味着：
	// 公有继承的成员保持公有
	// 保护继承的成员保持保护
	// 私有继承的成员保持不可访问
public:
	int m_public3 {};
protected:
	int m_protected3 {};
private:
	int m_private3 {};
};

D3 可以无限制地访问自己的成员。D3 可以访问 D2 的 m_public2 和 m_protected2 成员，但不能访问 m_private2。由于 D3 公有继承了 D2，m_public2 和 m_protected2 在通过 D3 访问时保持其访问说明符。D3 无法访问 Base 的 m_private，它在 Base 中已经是私有的。它也无法访问 Base 的 m_protected 或 m_public，这两者在 D2 继承时都变成了私有。

总结

访问说明符、继承类型和派生类之间的交互方式引起了很多混淆。为了尽可能澄清：

首先，一个类（及其友元）总是可以访问自己的非继承成员。访问说明符只影响外部和派生类是否可以访问这些成员。

其次，当派生类继承成员时，这些成员在派生类中的访问说明符可能会改变。这并不影响派生类自己的（非继承）成员（它们有自己的访问说明符）。它只影响外部和从该派生类派生的类是否可以访问这些继承的成员。

以下是所有访问说明符和继承类型组合的表格：

基类中的访问说明符公有继承时的访问说明符私有继承时的访问说明符保护继承时的访问说明符
公有公有私有受保护
受保护受保护私有受保护
私有不可访问不可访问不可访问

最后注意，尽管在上面的例子中，我们只展示了使用成员变量的例子，但这些访问规则适用于所有成员（例如，成员函数和类内部声明的类型）。
