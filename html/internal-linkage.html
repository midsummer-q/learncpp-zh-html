7.6 — 内部链接

● 机器译文 课程 7.6 查看英文原文

在课程 7.3 -- 局部变量，我们说：“标识符的链接性决定了该名称的其他声明是否引用同一个对象”，并讨论了局部变量如何具有 no linkage。

全局变量和函数标识符可以具有 internal linkage 或 external linkage。我们将在本课中介绍内部链接的情况，并在课程 7.7 -- 外部链接与变量前向声明。

具有 内部链接 的标识符可以在单个翻译单元内被看到和使用，但不能从其他翻译单元访问。这意味着如果两个源文件具有相同名称的内部链接标识符，这些标识符将被视为独立的（并且不会因为重复定义而导致ODR违规）。

关键提示

具有内部链接的标识符可能对链接器完全不可见。或者，它们可能对链接器可见，但标记为仅在特定翻译单元中使用。

相关内容

我们在课程 2.10 -- 预处理器简介。

具有内部链接的全局变量

具有内部链接的全局变量有时被称为 内部变量。

要使非常量全局变量成为内部变量，我们使用 static 关键字。

#include <iostream>

static int g_x{}; // // 非常量全局变量默认具有外部链接，但可以通过 static 关键字赋予内部链接

const int g_y{ 1 }; // // const 全局变量默认具有内部链接
constexpr int g_z{ 2 }; // // constexpr 全局变量默认具有内部链接

int main()
{
    std::cout << g_x << ' ' << g_y << ' ' << g_z << '\n';
    return 0;
}

const和constexpr全局变量默认具有内部链接（因此不需要 static 关键字——如果使用它，它将被忽略）。

以下是多个文件使用内部变量的示例：

a.cpp：

[[maybe_unused]] constexpr int g_x { 2 }; // // 这个内部 g_x 只能在 a.cpp 内访问

main.cpp:

#include <iostream>

static int g_x { 3 }; // // 这个独立的内部 g_x 只能在 main.cpp 内访问

int main()
{
    std::cout << g_x << '\n'; // // 使用 main.cpp 的 g_x，打印 3

    return 0;
}

该程序打印出：

3

因为 g_x 对每个文件是内部的， main.cpp 不知道 a.cpp 也有一个名为 g_x 的变量（反之亦然）。

进阶读者

上面使用 static 关键字是 存储类说明符的一个例子，它同时设置了名称的链接性和存储持续时间。最常用的 storage class specifiers 是 static， extern、和 mutable。术语 storage class specifier 主要用于技术文档中。

进阶读者

C++11标准（附录C）提供了为什么const变量默认具有内部链接的理由：“因为const对象可以在C++中用作编译时值，这一特性促使程序员为每个const提供显式的初始值。这一特性允许用户将const对象放在包含在许多编译单元中的头文件中。”

C++的设计者意图实现两件事：

  • const对象应该可以在常量表达式中使用。为了能在常量表达式中使用，编译器必须看到定义（而不是声明），以便在编译时求值。
  • const对象应该能够通过头文件传播。

具有外部链接的对象只能在单个翻译单元中定义而不违反ODR——其他翻译单元必须通过前向声明访问这些对象。如果const对象默认具有外部链接，它们将只能在包含定义的单个翻译单元中用于常量表达式，并且无法通过头文件有效传播，因为将头文件#include到多个源文件中会导致ODR违规。

具有内部链接的对象可以在每个需要它们的翻译单元中有一个定义而不违反ODR。这允许将const对象放在头文件中，并根据需要#include到任意数量的翻译单元中而不违反ODR。而且由于每个翻译单元都有定义而不是声明，这确保了这些常量可以在翻译单元内的常量表达式中使用。

内联变量（可以具有外部链接而不导致ODR违规）直到C++17才引入。

具有内部链接的函数

如上所述，函数标识符也具有链接性。函数默认具有外部链接（我们将在下一课中介绍），但可以通过 static 关键字成为常量：

add.cpp:

// // 此函数声明为 static，现在只能在此文件中使用
// // 尝试通过函数前向声明从另一个文件访问它将失败
[[maybe_unused]] static int add(int x, int y)
{
    return x + y;
}

main.cpp:

#include <iostream>

int add(int x, int y); // // 函数 add 的前向声明

int main()
{
    std::cout << add(3, 4) << '\n';

    return 0;
}

这个程序无法链接，因为函数 add 在 add.cpp。

之外不可访问。

在课程 2.7 -- 前向声明和定义，我们指出单一定义规则规定一个对象或函数不能有多个定义，无论是在文件内还是在程序中。

然而，值得注意的是，定义在不同文件中的内部对象（和函数）被视为独立的实体（即使它们的名称和类型相同），因此不违反单一定义规则。每个内部对象只有一个定义。

static vs 未命名命名空间

在现代 C++ 中，使用 static 关键字为标识符赋予内部链接的做法已逐渐失宠。未命名命名空间可以为更广泛的标识符（例如类型标识符）赋予内部链接，并且更适合为多个标识符赋予内部链接。

我们在课程中介绍未命名命名空间 7.14 -- 未命名和内联命名空间。

为什么要费心赋予标识符内部链接？

通常有两个原因赋予标识符内部链接：

  • 有一个标识符我们希望确保其他文件无法访问。这可能是一个我们不想被弄乱的全局变量，或者一个我们不想被调用的辅助函数。
  • 为了避免命名冲突而过于谨慎。因为具有内部链接的标识符不会暴露给链接器，它们只能与同一翻译单元中的名称冲突，而不是整个程序。

许多现代开发指南建议为每个不打算从其他文件使用的变量和函数赋予内部链接。如果你有自律性，这是一个好建议。

目前，我们建议采用一种更轻量级的方法作为最低要求：为任何你有明确理由禁止从其他文件访问的标识符赋予内部链接。

最佳实践

当你明确有理由禁止从其他文件访问时，赋予标识符内部链接。

考虑为所有你不希望其他文件访问的标识符赋予内部链接（使用未命名命名空间来实现）。

快速总结

// // 内部全局变量定义：
static int g_x;          // // 定义未初始化的内部全局变量（默认零初始化）
static int g_x{ 1 };     // // 定义已初始化的内部全局变量

const int g_y { 2 };     // // 定义已初始化的内部全局 const 变量
constexpr int g_y { 3 }; // // 定义已初始化的内部全局 constexpr 变量

// // 内部函数定义：
static int foo() {};     // // 定义内部函数
