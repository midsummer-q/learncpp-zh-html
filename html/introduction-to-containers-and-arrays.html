16.1 — 容器和数组简介

● 机器译文 课程 16.1 查看英文原文

变量可扩展性挑战

考虑一个场景：我们想记录30名学生的考试成绩，并计算班级平均分。为此，我们需要30个变量。我们可以这样定义：

// 分配30个整数变量（每个变量有不同的名称）
int testScore1 {};
int testScore2 {};
int testScore3 {};
// ...
int testScore30 {};

这需要定义很多变量！而要计算班级平均分，我们需要这样做：

int average { (testScore1 + testScore2 + testScore3 + testScore4 + testScore5
     + testScore6 + testScore7 + testScore8 + testScore9 + testScore10
     + testScore11 + testScore12 + testScore13 + testScore14 + testScore15
     + testScore16 + testScore17 + testScore18 + testScore19 + testScore20
     + testScore21 + testScore22 + testScore23 + testScore24 + testScore25
     + testScore26 + testScore27 + testScore28 + testScore29 + testScore30)
     / 30; };

这不仅输入量大，而且非常重复（并且很容易输错某个数字而不被发现）。如果我们想对这些值做任何操作（比如打印到屏幕），我们必须再次输入所有这些变量名。

现在假设我们需要修改程序以容纳另一个刚加入班级的学生。我们必须扫描整个代码库，并在相关位置手动添加 testScore31 任何时候修改现有代码，我们都有引入新错误的风险。例如，很容易忘记在计算平均值时更新除数，从 30 切换到 31！

而这仅仅只有30个变量。想想我们有成百上千个对象的情况。当我们需要多个相同类型的对象时，定义单个变量根本无法扩展。

我们可以将数据放入结构体中：

struct testScores
{
// 分配30个整数变量（每个变量有不同的名称）
int score1 {};
int score2 {};
int score3 {};
// ...
int score30 {};
}

虽然这为我们的分数提供了一些额外的组织（并允许我们更容易地将它们传递给函数），但它并没有解决核心问题：我们仍然需要单独定义和访问每个考试分数对象。

正如你可能已经猜到的，C++有解决上述挑战的方案。在本章中，我们将介绍其中一种方案。在接下来的章节中，我们将探讨该方案的其他变体。

容器

当你去杂货店买一打鸡蛋时，你（可能）不会单独挑选12个鸡蛋放进购物车（你不会这样做，对吧？）。相反，你可能会选择一盒鸡蛋。盒子是一种容器，容纳一定数量的鸡蛋（通常是6个、12个或24个）。再考虑早餐麦片，包含许多小片麦片。你肯定不想把这些碎片单独存放在食品柜里！麦片通常装在盒子里，这是另一种容器。我们在现实生活中经常使用容器，因为它们使管理一组物品变得容易。

容器也存在于编程中，以便更容易地创建和管理（可能很大的）对象集合。在一般编程中， 容器 是一种数据类型，为一系列未命名对象（称为 元素)。

关键提示

我们通常在处理一组相关值时使用容器。

事实上，你已经使用过一种容器类型：字符串！字符串容器提供存储一系列字符的能力，然后可以输出为文本：

#include <iostream>
#include <string>

int main()
{
    std::string name{ "Alex" }; // 字符串是字符的容器
    std::cout << name; // 将字符串作为字符序列输出

    return 0;
}

容器的元素是未命名的

虽然容器对象本身通常有一个名称（否则我们如何使用它？），但容器的元素是未命名的。这样我们就可以在容器中放入任意多的元素，而无需为每个元素赋予唯一名称！这种缺少命名元素的特点很重要，也是区分容器与其他类型数据结构的标志。这就是为什么普通结构体（那些只是数据成员的集合，比如我们上面的 testScores 结构体）通常不被视为容器——它们的数据成员需要唯一名称。

在上面的例子中，我们的字符串容器有一个名称（name），但容器内的字符（'A'， 'l'， 'e'， 'x'）没有。

但如果元素本身是未命名的，我们如何访问它们？每个容器提供一种或多种方法来访问其元素——但具体方法取决于容器的类型。我们将在下一课中看到第一个例子。

关键提示

容器的元素没有自己的名称，这样容器就可以拥有任意多的元素，而无需为每个元素赋予唯一名称。

每个容器提供某种方法来访问这些元素，但具体方法取决于容器的特定类型。

容器的长度

在编程中，容器中元素的数量通常称为它的 长度 （有时也称为 计数)。

在课程 5.7 -- std::string 简介，我们展示了如何使用 length 成员函数 std::string 来获取字符串容器中字符元素的数量：

#include <iostream>
#include <string>

int main()
{
    std::string name{ "Alex" };
    std::cout << name << " has " << name.length() << " characters\n";

    return 0;
}

这会打印：

Alex has 4 characters

在C++中，术语 大小 也常用于表示容器中元素的数量。这是一个不幸的命名选择，因为术语“大小”也可以指对象占用的内存字节数（由 sizeof 运算符返回）。

我们更倾向于使用术语“长度”来指代容器中元素的数量，并使用术语“大小”来指代对象所需的存储量。

容器操作

暂时回到我们的鸡蛋盒。你能用这样的盒子做什么？首先，你可以获得一盒鸡蛋。你可以打开鸡蛋盒，选择一个鸡蛋，然后对这个鸡蛋做任何你想做的事。你可以从盒中取出一个现有的鸡蛋，或者将一个新鸡蛋放入空位。你还可以数一数盒子里有多少个鸡蛋。

类似地，容器通常实现以下操作的一个重要子集：

  • 创建容器（例如，空容器、为一定数量的初始元素分配存储空间、从值列表创建）。
  • 访问元素（例如，获取第一个元素、获取最后一个元素、获取任意元素）。
  • 插入和删除元素。
  • 获取容器中的元素数量。

容器还可能提供其他操作（或上述操作的变体），以帮助管理元素集合。

现代编程语言通常提供多种不同的容器类型。这些容器类型在它们实际支持的操作以及这些操作的性能方面有所不同。例如，一种容器类型可能提供对容器中任何元素的快速访问，但不支持插入或删除元素。另一种容器类型可能提供快速的插入和删除操作，但只允许按顺序访问元素。

每个容器都有一组优点和局限性。为你要解决的任务选择正确的容器类型，会对代码的可维护性和整体性能产生巨大影响。我们将在未来的课程中进一步讨论这个话题。

元素类型

在大多数编程语言（包括 C++）中，容器是 同质的，这意味着容器的元素必须具有相同的类型。

一些容器使用预设的元素类型（例如，字符串通常具有 char 元素），但更常见的是，元素类型可以由容器的用户设置。在 C++ 中，容器通常作为类模板实现，以便用户可以将所需的元素类型作为模板类型参数提供。我们将在下一课中看到一个例子。

这使得容器非常灵活，因为我们不需要为每种不同的元素类型创建新的容器类型。相反，我们只需用所需的元素类型实例化类模板，就可以开始使用了。

顺便说一句……

与同质容器相对的是 异质 容器，它允许元素具有不同的类型。异质容器通常由脚本语言（如 Python）支持。

C++ 中的容器

浮点类型的 容器库 是C++标准库的一部分，包含实现某些常见容器类型的各种类类型。实现容器的类类型有时被称为 容器类。容器库中的完整容器列表记录在 这里。

在 C++ 中，“容器”的定义比一般编程定义更窄。只有容器库中的类类型才被认为是 C++ 中的容器。当我们一般性地谈论容器时，我们将使用术语“容器”；当具体谈论作为容器库一部分的容器类类型时，我们将使用“容器类”。

进阶读者

以下类型在一般编程定义下是容器，但 C++ 标准不认为它们是容器：

  • C 风格数组
  • std::string
  • std::vector<bool>

要在 C++ 中成为容器，容器必须实现列出的所有要求 这里。注意，这些要求包括实现某些成员函数——这意味着 C++ 容器必须是类类型！上面列出的类型并未实现所有这些要求。

然而，因为 std::string 和 std::vector<bool> 实现了大部分要求，它们在大多数情况下表现得像容器。因此，它们有时被称为“伪容器”。

在提供的容器类中， std::vector 和 std::array 使用最为广泛，我们将把大部分注意力集中在这上面。其他容器类通常只在更特殊的情况下使用。

数组简介

一种 数组 是一种容器数据类型，它连续存储一系列值 （意味着每个元素放置在相邻的内存位置，没有间隙）。数组允许快速直接访问任何元素。 （意味着每个元素都放置在相邻的内存位置，没有间隙）。数组允许快速、直接访问任何元素。它们在概念上简单且易于使用，因此当我们需要创建和处理一组相关值时，它们是首选。

容器类和 std::vector 容器类。 std::array 容器类。

（C 风格）数组继承自 C 语言。为了向后兼容，这些数组被定义为 C++ 核心语言的一部分（很像基本数据类型）。C++ 标准称它们为“数组”，但在现代 C++ 中，它们通常被称为 C 数组 或 C 风格数组 ，以便与同名的 std::array区分开来。C 风格数组有时也被称为“裸数组”、“固定大小数组”、“固定数组”或“内置数组”。我们更倾向于使用“C 风格数组”这一术语，并在一般讨论数组类型时使用“数组”。按照现代标准，C 风格数组行为怪异且危险。我们将在未来的章节中探讨原因。

为了帮助在 C++ 中使数组更安全、更易用， std::vector 容器类在 C++03 中被引入。 std::vector 是三种数组类型中最灵活的，并且具有许多其他数组类型没有的有用功能。

最后， std::array 容器类在 C++11 中被引入，作为 C 风格数组的直接替代品。它比 std::vector更受限制，但也可以更高效，特别是对于较小的数组。

所有这些数组类型在现代C++中仍以不同能力被使用，因此我们将不同程度地涵盖所有三种。

向前迈进

在下一课中，我们将介绍第一个容器类， std::vector，并开始展示它如何高效解决本课开头提出的挑战。我们将花大量时间学习 std::vector，因为我们需要介绍相当多的新概念，并在此过程中解决一些额外的挑战。

一个好处是，所有容器类都有相似的接口。因此，一旦你学会了如何使用一个容器（例如 std::vector），学习其他容器（例如 std::array）就简单得多。对于未来的容器（例如 std::array），我们将介绍显著的差异（并重申最重要的点）。
