2.5 — 局部作用域简介

● 机器译文 课程 2.5 查看英文原文

局部变量

在函数体内定义的变量被称为 局部变量 （与之相对的是 全局变量，我们将在后续章节中讨论）：

int add(int x, int y)
{
    int z{ x + y }; // z 是一个局部变量

    return z;
}

函数参数通常也被视为局部变量，我们将它们一并归入：

int add(int x, int y) // 函数参数 x 和 y 是局部变量
{
    int z{ x + y };

    return z;
}

在本课中，我们将更详细地了解局部变量的一些属性。

局部变量的生命周期

在课程 1.3 -- 对象与变量简介，我们讨论了变量定义如 int x; 会导致变量在该语句执行时被实例化。函数参数在进入函数时被创建并初始化，函数体内的变量在定义点被创建并初始化。

例如：

int add(int x, int y) // 在这里创建并初始化 x 和 y
{ 
    int z{ x + y };   // 在这里创建并初始化 z

    return z;
}

接下来的自然问题是：“那么实例化的变量何时被销毁？” 局部变量在定义它的花括号集合结束时以创建顺序的相反顺序销毁（对于函数参数，则在函数结束时销毁）。

int add(int x, int y)
{ 
    int z{ x + y };

    return z;
} // 在这里销毁 z、y 和 x

就像人的生命周期被定义为其出生与死亡之间的时间一样，对象的 生命周期 被定义为其创建与销毁之间的时间。请注意，变量的创建和销毁发生在程序运行时（称为运行时），而不是编译时。因此，生命周期是一个运行时属性。

进阶读者

上述关于创建、初始化和销毁的规则是保证。也就是说，对象必须在不晚于定义点被创建和初始化，并且不得早于定义它的花括号集合结束（对于函数参数，则在函数结束时）被销毁。

实际上，C++ 规范赋予编译器很大的灵活性来决定局部变量的创建和销毁时机。为了优化，对象可能会被提前创建或延后销毁。最常见的做法是，局部变量在进入函数时被创建，并在退出函数时以创建顺序的相反顺序销毁。我们将在未来关于调用堆栈的课程中更详细地讨论这一点。

下面是一个稍复杂的程序，演示名为 x：

#include <iostream>

void doSomething()
{
    std::cout << "Hello!\n";
}

int main()
{
    int x{ 0 };    // x 的生命周期从这里开始

    doSomething(); // 在此函数调用期间 x 仍然存活

    return 0;
} // x 的生命周期在这里结束

在上述程序中， x 从定义点开始到函数末尾为止 main. 这包括函数执行期间的时间 doSomething。

对象被销毁时会发生什么？

在大多数情况下，什么也不会发生。被销毁的对象只是变成无效。

进阶读者

如果对象是类类型对象，在销毁之前，会调用一个称为析构函数的特殊函数。在许多情况下，析构函数什么也不做，因此不会产生额外开销。我们在课程 15.4 -- 析构函数简介。

在对象被销毁后对其进行任何使用都将导致未定义行为。

在销毁后的某个时刻，对象所使用的内存将被 释放 （腾出以供重用）。

局部作用域（块作用域）

标识符的 作用域 决定了标识符在源代码中可见和可用的位置。当一个标识符可见且可用时，我们说它 在作用域内当一个标识符不可见时，我们就不能使用它，我们说它 超出作用域. 作用域是编译时属性，尝试在标识符不在作用域内时使用它会导致编译错误。

局部变量的标识符具有局部作用域。具有 局部作用域 （技术上称为 块作用域) 从定义点到包含该标识符的最内层大括号对结束（对于函数参数，到函数结束）都可用。这确保了局部变量不能在定义点之前（即使编译器选择在此之前创建它们）或销毁之后使用。在一个函数中定义的局部变量也不在调用的其他函数的作用域内。

下面是一个程序，演示名为 x：

#include <iostream>

// 在此函数中的任何位置，x 都不在作用域内
void doSomething()
{
    std::cout << "Hello!\n";
}

int main()
{
    // 这里不能使用 x，因为它尚未进入作用域

    int x{ 0 }; // x 在此处进入作用域，现在可以在该函数中使用

    doSomething();

    return 0;
} // x 在此处离开作用域，不能再使用

在上面的程序中，变量 x 在定义点进入作用域。 x 在包含该标识符的最内层大括号对结束处离开作用域，即函数 main()的右花括号。注意，变量 x 在函数 doSomething内部的任何地方都不在作用域内。函数 main 调用函数 doSomething 在这一上下文中无关紧要。

“超出作用域”与“离开作用域”

术语“超出作用域”和“离开作用域”可能会让新程序员感到困惑。

标识符在代码中无法访问的任何地方都是超出作用域的。在上面的例子中，标识符 x 从其定义点到 main 函数结束都处于作用域内。标识符 x 在该代码区域之外是超出作用域的。

术语“离开作用域”通常应用于对象而非标识符。我们说一个对象在其被实例化的作用域结束处（右花括号）离开作用域。在上面的例子中，名为 x 的对象在函数 main。

局部变量的生命周期在其离开作用域时结束，因此局部变量此时被销毁。

请注意，并非所有类型的变量在超出作用域时都会被销毁。我们将在后续课程中看到这些例子。

另一个示例

这里有一个稍微复杂的例子。请记住，生命周期是运行时属性，而作用域是编译时属性，因此尽管我们在同一程序中讨论两者，但它们在不同的时刻生效。

#include <iostream>

int add(int x, int y) // x 和 y 被创建并在此处进入作用域
{
    // x 和 y 仅在 add() 内可用
    return x + y;
} // y 和 x 离开作用域并在此处被销毁

int main()
{
    int a{ 5 }; // a 被创建、初始化并在此处进入作用域
    int b{ 6 }; // b 在此处创建、初始化并进入作用域

    // a 和 b 仅在 main() 内可用

    std::cout << add(a, b) << '\n'; // 调用 add(5, 6)，其中 x=5, y=6

    return 0;
} // b 和 a 在此处离开作用域并被销毁

参数 x 和 y 在函数被调用时创建 add 函数被调用，只能在函数内部看到/使用 add并在函数结束时销毁 add。变量 a 和 b 在函数内部创建 main只能在函数内部看到/使用 main并在函数结束时销毁 main。

为了加深你对所有这些如何配合的理解，让我们更详细地追踪这个程序。以下是按顺序发生的情况：

  • 执行从顶部开始 main。
  • main 变量 a 被创建并赋予值 5。
  • main 变量 b 被创建并赋予值 6。
  • 函数 add 被调用，参数值为 5 和 6。
  • add 参数 x 和 y 被创建并使用值初始化 5 和 6
  • 表达式 x + y 被求值以产生值 11。
  • add 将值复制 11 返回给调用者 main。
  • add 参数 y 和 x 被销毁。
  • main 打印 11 到控制台。
  • main 返回 0 给操作系统。
  • main 变量 b 和 a 被销毁。

我们就完成了。

注意，如果函数 add 被调用两次，参数 x 和 y 会被创建和销毁两次——每次调用各一次。在一个包含许多函数和函数调用的程序中，变量会频繁地创建和销毁。

函数分离

在上面的例子中，很容易看出变量 a 和 b 是与...不同的变量 x 和 y。

现在考虑以下类似的程序：

#include <iostream>

int add(int x, int y) // add 的 x 和 y 在此处创建并进入作用域
{
    // add 的 x 和 y 仅在此函数内可见/可用
    return x + y;
} // add 的 y 和 x 在此处离开作用域并被销毁

int main()
{
    int x{ 5 }; // main 的 x 在此处创建、初始化并进入作用域
    int y{ 6 }; // main 的 y 在此处创建、初始化并进入作用域

    // main 的 x 和 y 仅在此函数内可用
    std::cout << add(x, y) << '\n'; // 以 x=5, y=6 调用函数 add()

    return 0;
} // main 的 y 和 x 在此处离开作用域并被销毁

在这个例子中，我们只是改变了变量 a 和 b 在函数内部 main 切换到 x 和 y。这个程序编译和运行完全相同，尽管函数 main 和 add 都有名为...的变量 x 和 y。为什么这样可行？

首先，我们需要认识到，尽管函数 main 和 add 都有名为...的变量 x 和 y，这些变量是不同的。 x 和 y 在函数 main 与...无关 x 和 y 在函数 add ——它们只是恰好共享相同的名称。

第二，当在函数 main内部时，名字 x 和 y 指的是main的局部作用域变量 x 和 y。这些变量只能在 main内部被看到（和使用）。类似地，当在函数 add内部时，名字 x 和 y 内部时，名字 x 和 y指的是函数参数，这些参数只能在 add。

内部被看到（和使用）。简而言之，既不是 add 也不是 main 知道另一个函数有相同名字的变量。因为作用域不重叠，编译器始终清楚哪个 x 和 y 在任何时候被引用。

关键提示

用于函数参数或在函数体内声明的变量的名称仅在该函数内部可见。这意味着函数内的局部变量可以命名，而无需考虑其他函数中变量的名称。这有助于保持函数的独立性。

我们将在未来的章节中进一步讨论局部作用域以及其他类型的作用域。

在哪里定义局部变量

在现代C++中，最佳实践是函数体内的局部变量应在合理的情况下尽可能靠近其首次使用处定义：

#include <iostream>

int main()
{
	std::cout << "Enter an integer: ";
	int x{};       // x 在此处定义
	std::cin >> x; // 并在此处使用

	std::cout << "Enter another integer: ";
	int y{};       // y 在此处定义
	std::cin >> y; // 并在此处使用

	int sum{ x + y }; // sum 可以用预期值初始化
	std::cout << "The sum is: " << sum << '\n';

	return 0;
}

在上面的例子中，每个变量都在首次使用前定义。对此不必过于严格——如果你喜欢交换第5行和第6行，那也是可以的。

最佳实践

在合理的情况下，将局部变量定义在尽可能靠近其首次使用的地方。

顺便说一句……

由于较老、较原始的编译器的限制，C语言曾要求所有局部变量在函数顶部定义。使用那种风格的等效C++程序如下所示：

#include <iostream>

int main()
{
	int x{}, y{}, sum{}; // 这些是如何使用的？

	std::cout << "Enter an integer: ";
	std::cin >> x;

	std::cout << "Enter another integer: ";
	std::cin >> y;

	sum = x + y;
	std::cout << "The sum is: " << sum << '\n';

	return 0;
}

这种风格因以下几个原因而并非最佳：

  • 这些变量的预期用途在定义点并不明显。你必须扫描整个函数才能确定每个变量在哪里以及如何使用。
  • 预期的初始化值可能在函数顶部不可用（例如，我们无法初始化 sum 为其预期的值，因为我们不知道 x 和 y 还不知道）。
  • 在变量的初始化器与其首次使用之间可能有很多行代码。如果我们不记得它被初始化为什么值，就必须滚动回函数顶部，这会分散注意力。

这一限制在C99语言标准中被解除。

何时使用函数参数 vs 局部变量

由于函数参数和局部变量都可以在函数体中使用，初学者有时难以理解何时应使用它们。当调用者将传入初始化值作为实参时，应使用函数参数。否则，应使用局部变量。

当应该使用局部变量时却使用了函数参数，会导致代码像这样：

#include <iostream>

int getValueFromUser(int val) // val 是一个函数参数
{
    std::cout << "Enter a value: ";
    std::cin >> val;
    return val;
}

int main()
{
    int x {};
    int num { getValueFromUser(x) }; // main 必须将 x 作为参数传递

    std::cout << "You entered " << num << '\n';

    return 0;
}

在上面的例子中， getValueFromUser() 定义了 val 作为一个函数参数。因此， main() 必须定义 x 以便有东西可以作为实参传递。然而，实际的值 x 从未被使用，而 val 被初始化的值也从未被使用。让调用者定义并传递一个从未使用的变量增加了不必要的复杂性。

正确的写法如下：

#include <iostream>

int getValueFromUser()
{
    int val {}; // val 是一个局部变量
    std::cout << "Enter a value: ";
    std::cin >> val;
    return val;
}

int main()
{
    int num { getValueFromUser() }; // main 不需要传递任何内容

    std::cout << "You entered " << num << '\n';

    return 0;
}

在这个例子中， val 现在是一个局部变量。 main() 现在更简单，因为它不需要定义或传递变量来调用 getValueFromUser()。

最佳实践

当函数内部需要一个变量时：

  • 当调用者将变量的初始化值作为实参传递时，请使用函数参数。
  • 否则使用局部变量。

临时对象简介

一个 临时对象 （有时也称为 匿名对象）是一种未命名的对象，用于仅需短暂持有的值。临时对象在需要时由编译器生成。

有多种方式可以创建临时值，但以下是一种常见情况：

#include <iostream>

int getValueFromUser()
{
 	std::cout << "Enter an integer: ";
	int input{};
	std::cin >> input;

	return input; // 将 input 的值返回给调用者
}

int main()
{
	std::cout << getValueFromUser() << '\n'; // 返回的值存储在哪里？

	return 0;
}

在上述程序中，函数 getValueFromUser() 返回存储在局部变量 input 中的值给调用者。由于 input 会在函数结束时被销毁，调用者会收到该值的副本，这样即使在 input 被销毁后，它也能拥有一个可用的值。

但是复制给调用者的值存储在哪里？我们并没有在 main()中定义任何变量。答案是返回值存储在一个临时对象中。然后这个临时对象被传递给 std::cout 以进行打印。

关键提示

按值返回会将一个临时对象（包含返回值的副本）返回给调用者。

临时对象完全没有作用域（这很合理，因为作用域是标识符的属性，而临时对象没有标识符）。

临时对象在创建它们的完整表达式结束时被销毁。这意味着临时对象总是在下一条语句执行之前被销毁。

在我们上面的例子中，用于保存 getValueFromUser() 返回值的临时对象在之后被销毁。 std::cout << getValueFromUser() << '\n' 执行。

当使用临时对象初始化变量时，初始化发生在临时对象销毁之前。

在现代C++（尤其是自C++17起），编译器有许多技巧可以避免生成以前需要生成的临时对象。例如，当我们使用返回值初始化变量时，通常会产生一个包含返回值的临时对象，然后用该临时对象初始化变量。然而，在现代C++中，编译器通常会跳过创建临时对象，直接使用返回值初始化变量。

类似地，在上例中，由于 getValueFromUser() 的返回值被立即输出，编译器可以跳过中临时对象的创建和销毁 main()，并使用的返回值 getValueFromUser() 直接初始化参数 operator<<。

小测验时间

问题 #1

以下程序会打印什么？

#include <iostream>

void doIt(int x)
{
    int y{ 4 };
    std::cout << "doIt: x = " << x << " y = " << y << '\n';

    x = 3;
    std::cout << "doIt: x = " << x << " y = " << y << '\n';
}

int main()
{
    int x{ 1 };
    int y{ 2 };

    std::cout << "main: x = " << x << " y = " << y << '\n';

    doIt(x);

    std::cout << "main: x = " << x << " y = " << y << '\n';

    return 0;
}

显示答案

main: x = 1 y = 2
doIt: x = 1 y = 4
doIt: x = 3 y = 4
main: x = 1 y = 2

以下是该程序中的执行过程：

  • 执行从顶部开始 main
  • main的变量 x 被创建并初始化为值 1
  • main的变量 y 被创建并初始化为值 2
  • std::cout 打印 main: x = 1 y = 2
  • doIt 被调用，参数为 1
  • doIt的参数 x 被创建并初始化为值 1
  • doIt的变量 y 被创建并初始化为值 4
  • doIt 打印 doIt: x = 1 y = 4
  • doIt的变量 x 被赋值为新值 3
  • std::cout 打印 doIt: x = 3 y = 4
  • doIt的 y 和 x 被销毁
  • std::cout 打印 main: x = 1 y = 2
  • main 返回 0 给操作系统
  • main的 y 和 x 被销毁

注意，尽管 doIt的变量 x 和 y 其值被初始化或赋值为不同于 main 's, main的 x 和 y 不受影响，因为它们是不同的变量。
