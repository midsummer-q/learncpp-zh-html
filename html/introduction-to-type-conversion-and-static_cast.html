4.12 — 类型转换与static_cast介绍

● 机器译文 课程 4.12 查看英文原文

隐式类型转换

考虑以下程序：

#include <iostream>

void print(double x) // print 接受一个 double 参数
{
	std::cout << x << '\n';
}

int main()
{
	print(5); // 当我们传入一个 int 值时会发生什么？

	return 0;
}

在上面的例子中， print() 函数有一个类型为 double 但调用者传入的值是 5 其类型为 int。这种情况下会发生什么？

在大多数情况下，C++ 允许我们将一种基本类型的值转换为另一种基本类型。将数据从一种类型转换为另一种类型的过程称为 类型转换。因此，int 参数 5 将被转换为 double 值 5.0 然后复制到参数 x。这些 print() 函数将打印此值，得到如下输出：

5

提醒

默认情况下，小数部分为 0 的浮点值打印时不带小数位（例如 5.0 打印为 5)。

当编译器代表我们进行类型转换，而我们没有明确要求时，我们称之为 隐式类型转换。上面的例子说明了这一点——我们从未明确告诉编译器将整数值 5 转换为 double 值 5.0。相反，函数期望一个 double 值，而我们传入了一个整型参数。编译器会注意到不匹配，并隐式地将整数转换为 double。

下面是一个类似的例子，其中我们的参数是一个 int 变量而不是 int 字面量：

#include <iostream>

void print(double x) // print 接受一个 double 参数
{
	std::cout << x << '\n';
}

int main()
{
	int y { 5 };
	print(y); // y 的类型是 int

	return 0;
}

这与上述操作完全相同。int 变量持有的值 y (5将被转换为 double 值 5.0，然后复制到参数 x。

值的类型转换会产生一个新值

类型转换过程不会修改提供要转换数据的值（或对象）。相反，转换过程使用该数据作为输入，并产生转换后的结果。

关键提示

将一个值转换为另一种类型的值，其行为很像调用一个返回类型与转换目标类型匹配的函数。要转换的数据作为参数传入，转换后的结果（在临时对象中）返回给调用者使用。

在上面的例子中，转换不会改变变量 y 的类型 int 切换到 double 或 y 从 5 切换到 5.0的值。相反，转换使用 y (5的值作为输入，并返回一个类型为 double 、值为 5.0的临时对象。然后这个临时对象被传递给函数 print。

进阶读者

一些高级类型转换（例如涉及 const_cast 或 reinterpret_cast的转换）不会返回临时对象，而是重新解释现有值或对象的类型。

隐式类型转换警告

尽管隐式类型转换在大多数需要类型转换的情况下已经足够，但也有一些情况并不适用。考虑以下程序，它与上面的例子类似：

#include <iostream>

void print(int x) // print 现在接受一个 int 参数
{
	std::cout << x << '\n';
}

int main()
{
	print(5.5); // 警告：我们传入了一个 double 值

	return 0;
}

在这个程序中，我们将 print() 改为接受一个 int 参数，并且对 print() 的函数调用现在传入 double 值 5.5。与上面类似，编译器将使用隐式类型转换将 double 值 5.5 转换为类型为 int的值，以便将其传递给函数 print()。

与最初的例子不同，当编译这个程序时，你的编译器会生成某种关于可能丢失数据的警告。并且因为你开启了“将警告视为错误”（你开启了，对吧？），你的编译器将中止编译过程。

提示

如果你想要编译这个例子，你需要暂时禁用“将警告视为错误”。有关此设置的更多信息，请参阅课程 0.11 -- 配置编译器：警告和错误级别

编译并运行时，该程序打印以下内容：

5

注意，尽管我们传入了值 5.5，程序却打印了 5。因为整型值不能保存小数部分，当 double 值 5.5 被隐式转换为 int时，小数部分被丢弃，只保留整数值。

因为将浮点值转换为整型值会导致任何小数部分被丢弃，所以当编译器进行从浮点到整型的隐式类型转换时，它会警告我们。即使我们传入一个没有小数部分的浮点值，比如 5.0 ——在这种特定情况下，转换为整型值并没有实际的值损失——编译器仍然可能警告我们该转换不安全。 5

关键提示

某些类型转换（例如从 char 到 int）总是保留被转换的值，而其他转换（例如从 double 切换到 int）可能导致值在转换过程中发生变化。不安全的隐式转换通常会产生编译器警告，或者（在花括号初始化的情况下）产生错误。

这是花括号初始化成为首选初始化形式的主要原因之一。花括号初始化将确保我们不会尝试用一个在隐式类型转换时会丢失值的初始化器来初始化变量：

int main()
{
    double d { 5 }; // 可以：int 到 double 是安全的
    int x { 5.5 }; // 错误：double 到 int 不安全

    return 0;
}

相关内容

隐式类型转换是一个内容丰富的主题。我们将在后续课程中更深入地探讨这个主题，从课程 10.1 -- 隐式类型转换。

通过 static_cast 运算符进行显式类型转换的介绍

回到我们最近的 print() 例子，如果我们 故意 想要将一个 double 值传递给一个接受整数的函数（知道转换后的值会丢弃任何小数部分）？仅仅为了让程序编译通过而关闭“将警告视为错误”是一个坏主意，因为这样每次编译时都会有警告（我们很快就会学会忽略它们），并且我们可能会忽略关于更严重问题的警告。

C++ 支持第二种类型转换方法，称为显式类型转换。 显式类型转换 允许我们（程序员）明确告诉编译器将一个值从一种类型转换为另一种类型，并且我们对该转换的结果承担全部责任。如果这种转换导致值丢失，编译器不会警告我们。

要执行显式类型转换，大多数情况下我们会使用 static_cast 运算符。 static cast 的语法看起来有点奇怪：

static_cast<new_type>(expression)

static_cast 接受来自表达式的值作为输入，并返回该值转换为由 new_type （例如 int、bool、char、double）指定的类型后的值。

关键提示

每当你看到 C++ 语法（不包括预处理器）使用尖括号（<>）时，尖括号之间的内容很可能是一个类型。这通常是 C++ 处理需要参数化类型的代码的方式。

让我们使用 static_cast：

#include <iostream>

void print(int x)
{
	std::cout << x << '\n';
}

int main()
{
	print( static_cast<int>(5.5) ); // 显式将 double 值 5.5 转换为 int

	return 0;
}

更新我们之前的程序。 5.5 由于我们现在明确要求将 double 值 int 转换为一个 int 值，编译器不会在编译时生成关于可能丢失数据的警告（这意味着我们可以保持“将警告视为错误”启用）。

相关内容

C++ 支持其他类型的转换。我们在未来的课程中会更多地讨论不同类型的转换： 10.6 -- 显式类型转换（强制转换）和 static_cast。

使用 static_cast 将 char 转换为 int

在关于 char 的课程中 4.11 -- 字符，我们看到使用 std::cout 打印 char 值会导致该值以 char 形式打印：

#include <iostream>

int main()
{
    char ch{ 97 }; // 97 是 'a' 的 ASCII 码
    std::cout << ch << '\n';

    return 0;
}

这会打印：

a

如果我们想打印整数值而不是字符，可以通过使用 static_cast 将值从 char 到 int：

#include <iostream>

int main()
{
    char ch{ 97 }; // 97 是 'a' 的 ASCII 码
    // 将变量 ch 的值作为 int 打印
    std::cout << ch << " has value " << static_cast<int>(ch) << '\n';

    return 0;
}

这会打印：

a has value 97

值得注意的是， 静态转换 的参数作为一个表达式求值。当我们传入一个变量时，该变量被求值以产生其值，然后该值被转换为新类型。变量本身 不是 不受将其值转换为新类型的影响。在上面的例子中，变量 ch 仍然是一个 char，并且在我们将它的值转换为 int 后仍然保持相同的值。 int。

使用 static_cast 进行符号转换

有符号整数值可以转换为无符号整数值，反之亦然，使用 static_cast。

如果被转换的值可以在目标类型中表示，则转换后的值将保持不变（仅类型改变）。例如：

#include <iostream>

int main()
{
    unsigned int u1 { 5 };
    // 将 u1 的值转换为 signed int 
    int s1 { static_cast<int>(u1) };
    std::cout << s1 << '\n'; // 打印 5

    int s2 { 5 };
    // 将 s2 的值转换为 unsigned int
    unsigned int u2 { static_cast<unsigned int>(s2) };
    std::cout << u2 << '\n'; // 打印 5

    return 0;
}

这会打印：

5
5

由于值 5 在有符号 int 和无符号 int 的范围内，值 5 可以无问题地转换为任一类型。

如果被转换的值无法在目标类型中表示：

  • 如果目标类型是无符号的，该值将进行模数回绕。我们在第 4.5 -- 无符号整数，以及为什么要避免使用它们。
  • 如果目标类型是有符号的，在 C++20 之前该值是由实现定义的，而从 C++20 开始将进行模数回绕。

下面是一个转换两个无法在目标类型中表示的值的例子（假设为 32 位整数）：

#include <iostream>

int main()
{
    int s { -1 };
    std::cout << static_cast<unsigned int>(s) << '\n'; // 打印 4294967295 

    unsigned int u { 4294967295 }; // 最大的 32 位 unsigned int
    std::cout << static_cast<int>(u) << '\n'; // C++20 之前是实现定义的，C++20 起为 -1
    
    return 0;
}

从 C++20 开始，这将产生以下结果：

4294967295
-1

有符号整数值 -1 无法表示为无符号整数。结果模数回绕为无符号整数值 4294967295。

无符号整数值 4294967295 无法表示为有符号整数。在 C++20 之前，结果是由实现定义的（但很可能是 -1）。从 C++20 开始，结果将模数回绕为 -1。

警告

在 C++20 之前，如果被转换的值无法在有符号类型中表示，将无符号整数值转换为有符号整数值会导致由实现定义的行为。

std::int8_t 和 std::uint8_t 可能像 char 而不是整数一样行为

如第 4.6 课 -- 固定宽度整数和 size_t所述，大多数编译器将 std::int8_t 和 std::uint8_t （以及相应的 fast 和 least 固定宽度类型）分别与类型 signed char 和 unsigned char 等同定义和处理。现在我们已经介绍了 char 是什么，我们可以演示这可能在哪里出现问题：

#include <cstdint>
#include <iostream>

int main()
{
    std::int8_t myInt{65};      // 用值 65 初始化 myInt
    std::cout << myInt << '\n'; // 你可能期望打印 65

    return 0;
}

因为 std::int8_t 描述自身为 int，你可能会被误导认为上述程序将打印整数值 65。然而，在大多数系统上，该程序将打印 A （将 myInt 视为 signed char）。但这并不保证（在某些系统上，它可能实际上打印 65)。

如果你想确保 std::int8_t 或 std::uint8_t 对象被当作整数处理，你可以使用 static_cast：

#include <cstdint>
#include <iostream>

int main()
{
    std::int8_t myInt{65};
    std::cout << static_cast<int>(myInt) << '\n'; // 将始终打印 65

    return 0;
}

将值转换为整数。 std::int8_t 在

#include <cstdint>
#include <iostream>

int main()
{
    std::cout << "Enter a number between 0 and 127: ";
    std::int8_t myInt{};
    std::cin >> myInt;

    std::cout << "You entered: " << static_cast<int>(myInt) << '\n';

    return 0;
}

被视为 char 的情况下，来自控制台的输入也可能导致问题：

Enter a number between 0 and 127: 35
You entered: 51

该程序的一个示例运行： std::int8_t 以下是发生的事情。当 35被视为 char 时，输入例程将我们的输入解释为字符序列，而不是整数。因此，当我们输入 '3' 和 '5'时，我们实际上输入了两个字符， '3' 因为 char 对象只能容纳一个字符，所以 '5' 被提取（ '3' 留在输入流中供以后可能提取）。因为字符 51 的 ASCII 码点是 51，所以值 myInt被存储在

中，然后我们稍后将其作为 int 打印。

小测验时间

问题 #1

编写一个简短的程序，要求用户输入一个字符。使用 static_cast。

打印该字符的值及其 ASCII 码。程序的输出应与以下内容匹配：

Enter a single character: a
You entered 'a', which has ASCII code 97.

显示答案

#include <iostream>

int main()
{
	std::cout << "Enter a single character: ";
	char c{};
	std::cin >> c;
	std::cout << "You entered '" << c << "', which has ASCII code " << static_cast<int>(c) << ".\n";

	return 0;
}

问题 #2

修改你在测验 #1 中编写的程序，使用隐式类型转换而不是 static_cast你能想到多少种不同的方法来实现这一点？

注意：你应该优先使用显式转换而不是隐式转换，所以实际上不要在真实程序中这样做——这只是为了测试你对隐式转换可能发生位置的理解。

显示答案

有几种简单的方法可以实现这一点。

首先，我们可以创建一个 int 变量，并用我们的 char 值初始化它。这将在初始化时进行隐式转换。

#include <iostream>

int main()
{
	std::cout << "Enter a single character: ";
	char c{};
	std::cin >> c;

	int ascii{ c };
	std::cout << "You entered '" << c << "', which has ASCII code " << ascii << ".\n";

	return 0;
}

或者，我们可以使用一个函数来返回 char 值作为 int。这将在返回点进行隐式转换。

#include <iostream>

int charAsInt(char c)
{
	return c;
}

int main()
{
	std::cout << "Enter a single character: ";
	char c{};
	std::cin >> c;

	std::cout << "You entered '" << c << "', which has ASCII code " << charAsInt(c) << ".\n";

	return 0;
}

我们也可以使用一个函数，让隐式转换发生在参数被复制到函数参数的点：

#include <iostream>

int getInt(int c)
{
	return c;
}

int main()
{
	std::cout << "Enter a single character: ";
	char c{};
	std::cin >> c;

	std::cout << "You entered '" << c << "', which has ASCII code " << getInt(c) << ".\n";

	return 0;
}
