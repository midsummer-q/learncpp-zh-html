14.6 — 访问函数

● 机器译文 课程 14.6 查看英文原文

在上一节课中 14.5 -- 公有和私有成员及访问说明符，我们讨论了 public 和 private 访问级别。提醒一下，类通常将其数据成员设为 private，而 private 成员不能被外部直接访问。

考虑以下 Date 类：

#include <iostream>

class Date
{
private:
    int m_year{ 2020 };
    int m_month{ 10 };
    int m_day{ 14 };

public:
    void print() const
    {
        std::cout << m_year << '/' << m_month << '/' << m_day << '\n';
    }
};

int main()
{
    Date d{};  // 创建一个 Date 对象
    d.print(); // 打印日期

    return 0;
}

虽然这个类提供了一个 print() 成员函数来打印整个日期，但这可能不足以满足用户的需求。例如，如果某个 Date 对象的用户想要获取年份？或者将年份改为不同的值？他们将无法做到，因为 m_year 是 private 的（因此不能被外部直接访问）。

对于某些类，允许我们获取或设置私有成员变量的值是合适的（在类所做的事情的上下文中）。

访问函数

一种 访问函数 是一个简单的公有成员函数，其工作是检索或更改私有成员变量的值。

访问函数有两种形式：getter 和 setter。 Getter 类型推导 （accessor）是返回私有成员变量值的公有成员函数。 Setter 类型推导 （mutator）是设置私有成员变量值的公有成员函数。

术语

术语“mutator”通常与“setter”互换使用。但更广泛地说， mutator 是任何修改（改变）对象状态的成员函数。根据这个定义，setter 是一种特定的 mutator。然而，也可能存在非 setter 函数也属于 mutator。

Getter 通常被设为 const，以便可以在 const 和非 const 对象上调用。Setter 应该是非 const 的，以便它们可以修改数据成员。

为了说明，让我们更新我们的 Date 类，使其拥有一整套 getter 和 setter：

#include <iostream>

class Date
{
private:
    int m_year { 2020 };
    int m_month { 10 };
    int m_day { 14 };

public:
    void print()
    {
        std::cout << m_year << '/' << m_month << '/' << m_day << '\n';
    }

    int getYear() const { return m_year; }        // 年份的 getter
    void setYear(int year) { m_year = year; }     // 年份的 setter

    int getMonth() const  { return m_month; }     // 月份的 getter
    void setMonth(int month) { m_month = month; } // 月份的 setter

    int getDay() const { return m_day; }          // 日期的 getter
    void setDay(int day) { m_day = day; }         // 日期的 setter
};

int main()
{
    Date d{};
    d.setYear(2021);
    std::cout << "The year is: " << d.getYear() << '\n';

    return 0;
}

这会打印：

The year is: 2021

访问函数命名

访问函数的命名没有通用约定。然而，有几种命名约定比其他更流行。

  • 以“get”和“set”为前缀：
    int getDay() const { return m_day; }  // getter
    void setDay(int day) { m_day = day; } // setter

使用“get”和“set”前缀的好处是，它清楚地表明这些是访问函数（并且调用开销应该很小）。

  • 无前缀：
    int day() const { return m_day; }  // getter
    void day(int day) { m_day = day; } // setter

这种风格更简洁，并且对 getter 和 setter 使用相同的名称（依靠函数重载来区分两者）。C++ 标准库使用这种约定。

无前缀约定的缺点是，不太明显这是在设置 day 成员的值：

d.day(5); // 这看起来像是在将 day 成员设置为 5 吗？

关键提示

给私有数据成员加“m_”前缀的最佳原因之一是避免数据成员和 getter 同名（C++ 不支持这一点，尽管其他语言如 Java 支持）。

  • 仅“set”前缀：
    int day() const { return m_day; }     // getter
    void setDay(int day) { m_day = day; } // setter

选择上述哪种方式取决于个人偏好。然而，我们强烈建议对 setter 使用“set”前缀。Getter 可以使用“get”前缀或无前缀。

提示

在 setter 上使用“set”前缀，以更明显地表明它们正在改变对象的状态。

Getter 应按值或 const 左值引用返回

Getter 应提供对数据的“只读”访问。因此，最佳实践是它们应按值（如果复制成员开销小）或按 const 左值引用（如果复制成员开销大）返回。

因为通过引用返回数据成员是一个重要的话题，我们将在课程 14.7 -- 返回数据成员引用的成员函数中更详细地讨论这个话题。。

访问函数的关注点

关于何时应该使用或避免访问函数，存在相当多的讨论。许多开发者认为使用访问函数违反了良好的类设计（这个话题足以写满一整本书）。

目前，我们推荐一种务实的方法。在创建类时，请考虑以下几点：

  • 如果你的类没有不变量且需要大量访问函数，考虑使用结构体（其数据成员是公有的）并直接提供对成员的访问。
  • 优先实现行为或动作，而不是访问函数。例如，不要使用 setAlive(bool) setter，而是实现一个 kill() ，我们需要几个辅助对象（一个 revive() 函数的顶部开始。
  • 仅在公众合理需要获取或设置某个成员的值时提供访问函数。
