现在，长舒一口气之后，你可能在问：“接下来呢？”

接下来呢？

到现在，你应该对C++核心语言有了扎实的理解。这为你继续学习其他相关领域打下了良好基础。所以，如果你有特别感兴趣的东西，现在是时候看看自己是否有足够的知识去深入学习了。

不过，对大多数用户来说，我认为有几个自然的下一步。

数据结构、算法和设计模式

如果你还没有学习这些，这是我强烈推荐的。

一个 数据结构 是一个数据集合以及一组定义良好的访问或操作这些数据的方法。编程中最常用的数据结构是数组，它在连续内存中保存多个相同类型的元素。你可以通过数组索引直接访问（或修改）数组中的元素来操作数据。在课程中，我们还介绍了栈数据结构，它提供了 push、pop 和 top 函数来访问栈中的数据。

一种 算法 是一组自包含的操作，通常用于处理数据结构中的数据并计算输出。例如，当你遍历数组查找中位数时，你就在执行一个算法。二分查找是一种判断给定值是否存在于已排序数组中的算法。排序例程（如选择排序和冒泡排序）是对数据集进行排序的算法。

多年来，数学家和计算机科学家提出了一套相当标准的可重用数据结构和算法，用于构建更复杂的程序。这些都有各自的权衡。例如，数组访问和排序速度快，但添加或删除元素慢。而链表则相反，访问和排序速度慢，但添加或删除元素非常快（如果你已经知道这些元素的位置）。

为什么这很重要？打个比方。如果你要建一栋房子，你可以从头开始制造所有工具。但这会花费很长时间，而且你可能会搞砸很多事情，不得不重新开始（你曾经制造过锤子吗？我也没有）。此外，如果你用错了工具，质量就会下降（试着用扳手钉钉子）。

更可能的是，你会去当地五金店买一些工具：锤子、水平仪、直角尺等……然后阅读一些网络教程学习如何正确使用它们。这将大大加快你的建房进度。

数据结构和算法在编程中起着同样的作用：它们是工具，如果你知道如何使用它们，就能大大加快高质量完成工作的速度。

好消息是，许多数据结构和算法已经在标准库中实现了。你在前面的教程中已经遇到了一些：std::array、std::vector、std::stack、std::string 和 std::sort 等等。学习有效且恰当地使用它们是非常值得的。

如果你时间（或耐心）有限，学习如何使用最常见的数据结构和算法是最低要求。但如果你有兴趣，尝试自己从头实现这些数据结构。这是编写可重用代码的绝佳练习，并且当你需要的东西不在标准库中时，这会对你有所帮助。但之后请丢弃它们，使用标准库中的版本。:)

数据结构和算法为我们提供了存储和操作数据的好工具。然而，我们还可以在工具箱中添加另一个工具，帮助我们编写更好的程序。 设计模式 是一种可重用的解决方案，用于解决常见的软件设计问题。

例如，我们经常需要遍历某个聚合数据结构（如数组或链表）中的元素，比如查找最大值或最小值。但必须了解聚合类型的实现方式才能知道如何遍历，这增加了复杂性，尤其是如果我们必须为每种聚合类型自己编写遍历代码。迭代器（我们在本教程系列前面介绍过）是一种设计模式，它提供了一种以一致方式遍历不同聚合类型的接口，而无需知道这些聚合类型是如何实现的。更一致的代码更容易理解，也更不容易出现错误。

再举一个例子。假设你正在编写一个在线游戏，你的程序需要与服务器保持开放连接以发送和接收游戏状态更新。由于打开新连接代价高昂，你可能希望确保程序只有一个全局连接对象，并防止创建额外的服务器连接（以免意外创建大量连接对象导致服务器过载）。如果你查阅常见设计模式的参考资料，你会发现已经有一种设计模式用于确保只能创建一个全局实例（称为单例）。因此，与其创建自己可能不完善的接口，不如实现一个经过实战检验的单例设计模式，其他程序员很可能已经熟悉它。

C++ 标准库

C++ 标准库的主体是数据结构和算法。然而，标准库还包含其他内容，另一个下一步可以是探索这些内容。其中包括数值（数学）库、输入/输出例程、处理本地化和区域化的函数、正则表达式、线程和文件访问。每个新版本的 C++（大约每三年发布一次）都会向标准库添加一批新功能。了解其中所有内容并非关键，但至少知道存在什么是有价值的，这样当你需要时，可以进一步学习。 https://cppreference.com/w/cpp 是我发现现有内容的常用参考。

图形应用程序

在本教程系列中，我们开发了控制台应用程序，因为它们简单、跨平台，并且不需要安装额外的软件。与许多现代编程语言不同，C++ 本身不提供创建应用程序窗口或向这些窗口填充图形元素或图形用户界面小部件（复选框、滑块等）的功能。要在 C++ 中实现这些功能，你需要借助第三方库，或者学习使用操作系统/平台的原生 API。

让图形应用程序运行起来比控制台应用程序需要更多步骤。首先，你需要实际安装第三方库或操作系统 SDK，并将其连接到你的 IDE，以便编译到程序中。大多数图形库都应附带如何为最流行的 IDE 执行此操作的说明。接下来，你需要实例化一个操作系统窗口，这需要调用工具包中的某些函数。大多数（如果不是全部）库都应该有示例程序，如果你不确定如何做基本的事情，可以编译并分析这些程序。

有很多库可供选择，你应该根据需求选择（你需要自己研究以确定哪个适合你）。流行的选择包括 Qt、WxWidgets、SDL 和 SFML。如果你想做 3D 图形，所有这些框架都支持 OpenGL，并且互联网上有很好的 OpenGL 教程。

图形应用程序通常与控制台应用程序运行方式不同。对于控制台应用程序，程序从 main() 顶部开始执行，然后顺序运行，通常只在等待用户输入时停止。图形应用程序也从 main() 顶部开始执行，通常生成一个窗口，用图形或小部件填充它，然后进入一个无限循环，等待用户与窗口交互（通过鼠标点击或键盘）。这个无限循环称为事件循环，当发生点击或按键时，该事件被路由到处理该类型事件的函数。这称为事件处理。事件处理完成后，事件循环继续运行，等待下一个用户输入。

TCP/IP / 网络编程（即互联网）

如今，很少能找到不连接互联网、后端服务器/服务或以某种方式利用云的程序。任何要求你拥有账户并登录的程序都在连接服务器并验证用户身份。许多程序连接某些服务以检查是否有可用更新。社交应用程序与社交基础设施保持持久连接，以允许用户按需相互通信。这些都是网络编程的例子。

网络（广义上）是指让你的程序连接到其他程序，无论是在你的机器上还是在网络连接的机器上，以交换信息。网络是一个强大的工具——过去，如果你想改变应用程序的行为，你必须发布应用程序更新。现在，通过良好的程序设计，你可以简单地更新服务器上的信息，所有程序实例都可以利用这一变化。

与 C++ 中的许多事情一样，有一些库可以帮助你的 C++ 程序具备网络能力。Asio C++ 库是常用的一个（有两个变体——一个独立版本，另一个与 Boost 集成的版本，Boost 是一个提供许多不同功能的库，类似于标准库）。

多线程

本教程系列中我们看到的所有程序都是顺序执行的。一个任务完成后，下一个任务开始。如果一个任务卡住（例如，你要求用户输入，但他们还没有输入），整个程序就会暂停。这对于简单的学术程序来说没问题，但对于实际应用程序来说就不太好了。想象一下，如果你的程序因为忙于在屏幕上绘制内容而无法处理用户点击，或者当网络调用发生时整个程序暂停/冻结，程序会感觉没有响应。

幸运的是，存在一种方法允许程序同时执行多个任务。这称为线程。就像（大多数人）可以同时走路和嚼口香糖一样，线程允许程序“分散”注意力并并行执行多件事情。

例如，一些图形应用程序（如网页浏览器）将渲染（绘制图形）部分放在单独的线程上，这样更新屏幕不会在绘制过程中阻塞其他事情（如接受用户输入）。网络调用通常也在单独的线程上进行，这样如果网络调用需要一段时间才能解析，应用程序不会在等待时陷入停顿。

线程功能强大，但也引入了额外的复杂性和更多出错的空间。因此，我不建议从这里开始——但最终它是一个值得学习的领域，特别是如果你想做复杂的图形应用程序或网络编程。

另一个选择是花时间加深对最佳实践的理解。为此，我强烈推荐通读 CPP Core Guidelines，并可选择深入研究 GSL 库。

现在也是加入一个提供各种编程练习来测试你技能的网站的好时机。我们强烈推荐 Codewars，因为它免费且拥有大量创意编程挑战！ Project Euler 也有很多具有挑战性的问题需要解决。

不要在你让代码运行起来后就停止。花一些时间完善你的代码（例如重构、消除冗余）。测量你的解决方案的速度（参见 18.4 -- 计时你的代码），然后看看能否找到优化代码的方法，使其运行得更快！
