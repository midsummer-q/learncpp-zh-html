10.5 — 算术转换

● 机器译文 课程 10.5 查看英文原文

在课程 6.1 -- 运算符优先级和结合性，我们讨论了表达式如何根据运算符的优先级和结合性进行求值。

考虑以下表达式：

int x { 2 + 3 };

二元 operator+ 有两个操作数，类型均为 int。由于两个操作数类型相同，将使用该类型进行计算，返回的值也将是同一类型。因此， 2 + 3 将求值为 int 值 5。

但是，当二元运算符的操作数类型不同时会发生什么？

??? y { 2 + 3.5 };

在这种情况下， operator+ 有一个操作数是 int 类型，另一个是 double类型。运算符的结果应该返回 int、 double，还是其他类型？

在C++中，某些运算符要求其操作数类型相同。如果这些运算符之一被调用时操作数类型不同，则一个或两个操作数将根据一组称为 常用算术转换的规则隐式转换为匹配类型。由常用算术转换规则产生的匹配类型称为操作数的 公共类型

要求操作数类型相同的运算符

以下运算符要求其操作数类型相同：

  • 二元算术运算符：+、-、*、/、%
  • 二元关系运算符：<、>、<=、>=、==、!=
  • 二元位算术运算符：&、^、|
  • 条件运算符 ?:（条件除外，它应为 bool)

进阶读者

重载运算符不受常用算术转换规则的约束。

常用算术转换规则

常用算术转换规则有些复杂，因此我们简化一下。编译器有一个类型排名列表，大致如下：

  • long double（最高排名）
  • double
  • float
  • long long
  • 长整型
  • int（最低排名）

应用以下规则来找到匹配类型：

第1步：

  • 如果一个操作数是整数类型，另一个是浮点类型，则整数操作数转换为浮点操作数的类型（不进行整数提升）。
  • 否则，任何整数操作数都会进行数值提升（参见 10.2 -- 浮点数和整型提升)。

第2步：

  • 提升后，如果一个操作数是有符号的，另一个是无符号的，则应用特殊规则（见下文）
  • 否则，排名较低的操作数转换为排名较高的操作数的类型。

进阶读者

不同符号整数操作数的特殊匹配规则：

  • 如果无符号操作数的排名大于或等于有符号操作数的排名，则有符号操作数转换为无符号操作数的类型。
  • 如果有符号操作数的类型可以表示无符号操作数类型的所有值，则无符号操作数的类型转换为有符号操作数的类型。
  • 否则，两个操作数都转换为有符号操作数对应的无符号类型。

一些示例

在以下示例中，我们将使用 typeid 运算符（包含在 <typeinfo> 头文件中），用于显示表达式的结果类型。

首先，让我们添加一个 int ，我们需要几个辅助对象（一个 double：

#include <iostream>
#include <typeinfo> // for typeid()

int main()
{
    int i{ 2 };
    std::cout << typeid(i).name() << '\n'; // 显示 i 的类型名称

    double d{ 3.5 };
    std::cout << typeid(d).name() << '\n'; // 显示 d 的类型名称

    std::cout << typeid(i + d).name() << ' ' << i + d << '\n'; // 显示 i + d 的类型

    return 0;
}

在这种情况下， double 操作数具有最高优先级，因此较低优先级的操作数（类型为 int）被类型转换为 double 值 2.0。然后 double 值 2.0 和 3.5 相加得到 double 结果 5.5。

在作者的机器上，这会打印：

int
double
double 5.5

请注意，你的编译器可能显示略有不同，因为 typeid.name() 输出的名称是实现定义的。

现在让我们添加两个类型为 short：

#include <iostream>
#include <typeinfo> // for typeid()

int main()
{
    short a{ 4 };
    short b{ 5 };
    std::cout << typeid(a + b).name() << ' ' << a + b << '\n'; // 显示 a + b 的类型

    return 0;
}

的值。由于两个操作数都不在优先级列表中，它们都经历整型提升为类型 int。两个 ints 是一个 int相加的结果，正如你所期望的：

int 9

有符号与无符号问题

这种优先级层次结构和转换规则在混合有符号和无符号值时可能会导致一些有问题的情形。例如，看看下面的代码：

#include <iostream>
#include <typeinfo> // for typeid()

int main()
{
    std::cout << typeid(5u-10).name() << ' ' << 5u - 10 << '\n'; // 5u 表示将 5 视为无符号整数

    return 0;
}

你可能期望表达式 5u - 10 求值为 -5 ，因为 5 - 10 = -5。但实际结果如下：

unsigned int 4294967291

由于转换规则， int 操作数被转换为 unsigned int。并且由于值 -5 超出了 unsigned int的范围，我们得到了一个意想不到的结果。

另一个显示反直觉结果的例子：

#include <iostream>

int main()
{
    std::cout << std::boolalpha << (-3 < 5u) << '\n';

    return 0;
}

虽然我们很清楚 5 是否大于 -3，但当这个表达式求值时， -3 被转换为一个大的 unsigned int ，它大于 5。因此，上面的代码打印 false 而不是预期的结果 true。

这是避免使用无符号整数的主要原因之一——当你将它们与有符号整数混合在算术表达式中时，你面临意外结果的风险。而且编译器可能甚至不会发出警告。

std::common_type 和 std::common_type_t

在未来的课程中，我们会遇到一些情况，知道两个类型的公共类型是什么会很有用。 std::common_type 和有用的类型别名 std::common_type_t （都定义在 <type_traits> 头文件中）正是为此目的而设计的。

例如， std::common_type_t<int, double> 返回 int 和 double、和 std::common_type_t<unsigned int, long> 返回 unsigned int 和 long。
