17.11 — C风格字符串符号常量

● 机器译文 课程 17.11 查看英文原文

在前一课（17.10 -- C 风格字符串）中有更多关于指针算术的测验问题。)，我们讨论了如何创建和初始化C风格字符串对象：

#include <iostream>

int main()
{
    char name[]{ "Alex" }; // C风格字符串
    std::cout << name << '\n';

    return 0;
}

C++支持两种不同的方式来创建C风格字符串符号常量：

#include <iostream>

int main()
{
    const char name[] { "Alex" };        // 情况1：用C风格字符串字面量初始化的const C风格字符串
    const char* const color{ "Orange" }; // 情况2：指向C风格字符串字面量的const指针

    std::cout << name << ' ' << color << '\n';

    return 0;
}

这会打印：

Alex Orange

虽然上述两种方法产生相同的结果，但C++处理这些内存分配的方式略有不同。

在情况1中，“Alex”被放入（可能是只读的）内存中的某个位置。然后程序分配一个长度为5的C风格数组（四个显式字符加上空终止符）的内存，并用字符串“Alex”初始化该内存。因此我们最终得到两个“Alex”副本——一个在全局内存中的某处，另一个由 name。因为 name 是const（且永远不会被修改），因此复制是低效的。

在情况2中，编译器如何处理是由实现定义的。实际 通常 发生的是编译器将字符串“Orange”放入只读内存中的某处，然后用该字符串的地址初始化指针。

为了优化，多个字符串字面量可能会合并为一个值。例如：

const char* name1{ "Alex" };
const char* name2{ "Alex" };

这是两个具有相同值的不同字符串字面量。由于这些字面量是常量，编译器可能会选择通过将它们合并为一个共享的字符串字面量来节省内存，这样两个 name1 和 name2 指向同一个地址。

使用const C风格字符串进行类型推导

使用C风格字符串字面量进行类型推导相当直接：

    auto s1{ "Alex" };  // 类型推导为const char*
    auto* s2{ "Alex" }; // 类型推导为const char*
    auto& s3{ "Alex" }; // 类型推导为const char(&)[5]

输出指针和C风格字符串

你可能已经注意到一些有趣的事情，关于 std::cout 如何处理不同类型的指针。

考虑以下示例：

#include <iostream>

int main()
{
    int narr[]{ 9, 7, 5, 3, 1 };
    char carr[]{ "Hello!" };
    const char* ptr{ "Alex" };

    std::cout << narr << '\n'; // narr 将退化为 int* 类型
    std::cout << carr << '\n'; // carr 将退化为 char* 类型
    std::cout << ptr << '\n'; // name 已经是 char* 类型

    return 0;
}

在作者的机器上，打印了：

003AF738
Hello!
Alex

为什么int数组打印地址，而字符数组打印为字符串？

答案是输出流（例如 std::cout）对你的意图做出了一些假设。如果你传递一个非char指针，它将简单地打印该指针的内容（指针持有的地址）。然而，如果你传递一个类型为 char* 或 const char*的对象，它将假设你打算打印一个字符串。因此，它不会打印指针的值（地址），而是打印所指向的字符串！

虽然这在大多数情况下是期望的，但它可能导致意外的结果。考虑以下情况：

#include <iostream>

int main()
{
    char c{ 'Q' };
    std::cout << &c;

    return 0;
}

在这种情况下，程序员打算打印变量 c的事实。然而， &c 的类型为 char*，所以 std::cout 试图将其作为字符串打印！而且由于 c 没有以空字符结尾，我们得到了未定义行为。

在作者的机器上，打印了：

Q╠╠╠╠╜╡4;¿■A

为什么会这样？首先，它假设 &c （类型为 char*）是一个C风格字符串。所以它打印了'Q'，然后继续。内存中的下一个是一堆垃圾。最终，它遇到了一些包含 0 值的内存，它将其解释为空终止符，因此停止。你看到的内容可能不同，具体取决于变量 c。

之后的内存内容。这种情况在实际中不太可能发生（因为你不太可能真的想打印内存地址），但它说明了底层的工作原理，以及程序如何无意中偏离轨道。

如果你真的想打印char指针的地址，请将其static_cast转换为类型 const void*：

#include <iostream>

int main()
{
    const char* ptr{ "Alex" };

    std::cout << ptr << '\n';                           // 将 ptr 作为 C 风格字符串打印
    std::cout << static_cast<const void*>(ptr) << '\n'; // 打印 ptr 持有的地址
    
    return 0;
}

优先使用std::string_view作为C风格字符串符号常量

在现代C++中，几乎没有理由使用C风格字符串符号常量。相反，优先使用 constexpr std::string_view 对象，它们往往同样快（如果不是更快的话），并且行为更一致。

最佳实践

避免使用C风格字符串符号常量，优先使用 constexpr std::string_view。
