14.15 — 类初始化与复制省略

● 机器译文 课程 14.15 查看英文原文

早在课程 1.4 -- Variable assignment and initialization中，我们讨论了基本类型对象的6种基本初始化形式：

int a;         // 无初始化器（默认初始化）
int b = 5;     // 等号后的初始化器（复制初始化）
int c( 6 );    // 括号中的初始化器（直接初始化）

// 列表初始化方法（C++11）
int d { 7 };   // 花括号中的初始化器（直接列表初始化）
int e = { 8 }; // 等号后的花括号初始化器（复制列表初始化）
int f {};      // 初始化器为空花括号（值初始化）

所有这些初始化形式对于类类型对象同样有效：

#include <iostream>

class Foo
{
public:
    
    // 默认构造函数
    Foo()
    {
        std::cout << "Foo()\n";
    }

    // 普通构造函数
    Foo(int x)
    {
        std::cout << "Foo(int) " << x << '\n';
    }

    // 拷贝构造函数
    Foo(const Foo&)
    {
        std::cout << "Foo(const Foo&)\n";
    }
};

int main()
{
    // 调用Foo()默认构造函数
    Foo f1;           // 默认初始化
    Foo f2{};         // 值初始化（首选）
    
    // 调用foo(int)普通构造函数
    Foo f3 = 3;       // 复制初始化（仅非explicit构造函数）
    Foo f4(4);        // 直接初始化
    Foo f5{ 5 };      // 直接列表初始化（首选）
    Foo f6 = { 6 };   // 复制列表初始化（仅非explicit构造函数）

    // 调用foo(const Foo&)复制构造函数
    Foo f7 = f3;      // 复制初始化
    Foo f8(f3);       // 直接初始化
    Foo f9{ f3 };     // 直接列表初始化（首选）
    Foo f10 = { f3 }; // 复制列表初始化

    return 0;
}

在现代C++中，复制初始化、直接初始化和列表初始化本质上做的是同一件事——它们初始化一个对象。

对于所有类型的初始化：

  • 当初始化类类型时，会检查该类的构造函数集合，并使用重载解析来确定最佳匹配的构造函数。这可能涉及参数的隐式转换。
  • 当初始化非类类型时，使用隐式转换规则来确定是否存在隐式转换。

关键提示

这些初始化形式之间存在三个关键区别：

  • 列表初始化不允许窄化转换。
  • 复制初始化只考虑非explicit构造函数/转换函数。我们将在课程 14.16 -- 转换构造函数与 explicit 关键字。
  • 列表初始化优先匹配列表构造函数而非其他匹配的构造函数。我们将在课程 16.2 -- std::vector 与列表构造函数简介。

还值得注意的是，在某些情况下，某些形式的初始化是不允许的（例如，在构造函数成员初始化列表中，我们只能使用直接形式的初始化，而不能使用复制初始化）。

不必要的复制

考虑这个简单的程序：

#include <iostream>

class Something
{
    int m_x{};

public:
    Something(int x)
        : m_x{ x }
    {
        std::cout << "Normal constructor\n";
    }

    Something(const Something& s)
        : m_x { s.m_x }
    {
        std::cout << "Copy constructor\n";
    }

    void print() const { std::cout << "Something(" << m_x << ")\n"; }
};

int main()
{
    Something s { Something { 5 } }; // 关注这一行
    s.print();

    return 0;
}

在上面的变量 s 的初始化中，我们首先构造一个临时对象 Something，用值 5 初始化（这使用了 Something(int) 构造函数）。然后使用这个临时对象来初始化 s。由于临时对象和 s 具有相同的类型（它们都是 Something 对象）， Something(const Something&) 复制构造函数通常会被调用来将临时对象中的值复制到 s中。最终结果是 s 用值 5。

如果不进行任何优化，上述程序将输出：

Normal constructor
Copy constructor
Something(5)

然而，这个程序效率低下，因为我们必须进行两次构造函数调用：一次调用 Something(int)，一次调用 Something(const Something&)。注意，上述过程的最终结果与下面这样写是一样的：

Something s { 5 }; // 仅调用Something(int)，无复制构造函数

这个版本产生相同的结果，但效率更高，因为它只调用了一次 Something(int) （不需要复制构造函数）。

复制省略

由于编译器可以自由地重写语句以进行优化，人们可能会想，编译器是否可以优化掉不必要的复制，并将 Something s { Something{5} }; 视为我们一开始就写了 Something s { 5 }

答案是肯定的，这个过程称为 拷贝省略。 复制省略 是一种编译器优化技术，允许编译器移除不必要的对象复制。换句话说，在编译器通常会调用复制构造函数的情况下，编译器可以自由地重写代码以避免调用复制构造函数。当编译器优化掉对复制构造函数的调用时，我们说构造函数被 省略。

了。与其他类型的优化不同，复制省略不受“as-if”规则的约束。也就是说，即使复制构造函数有副作用（例如向控制台打印文本），复制省略也允许省略复制构造函数！这就是为什么复制构造函数除了复制之外不应有副作用——如果编译器省略了对复制构造函数的调用，副作用将不会执行，程序的可观察行为将会改变！

相关内容

我们在课程 5.4 -- 如同规则与编译时优化。

中讨论了as-if规则。我们可以在上面的例子中看到这一点。如果你在C++17编译器上运行该程序，它将产生以下结果：

Normal constructor
Something(5)

编译器已省略复制构造函数以避免不必要的复制，结果打印“复制构造函数”的语句没有执行！由于复制省略，我们程序的可观察行为发生了变化！

按值传递和按值返回中的复制省略

当参数与参数类型相同且按值传递或按值返回时，通常会调用复制构造函数。然而，在某些情况下，这些复制可能会被省略。以下程序演示了其中一些情况：

#include <iostream>

class Something
{
public:
	Something() = default;
	Something(const Something&)
	{
		std::cout << "Copy constructor called\n";
	}
};

Something rvo()
{
	return Something{}; // 调用 Something() 和拷贝构造函数
}

Something nrvo()
{
	Something s{}; // 调用 Something()
	return s;      // 调用拷贝构造函数
}

int main()
{
	std::cout << "Initializing s1\n";
	Something s1 { rvo() }; // 调用拷贝构造函数

	std::cout << "Initializing s2\n";
	Something s2 { nrvo() }; // 调用拷贝构造函数

        return 0;
}

在C++14或更早版本中，禁用复制省略时，上述程序会调用复制构造函数4次：

  • 一次当 rvo 返回 Something 切换到 main。
  • 一次当返回值 rvo() 用于初始化 s1。
  • 一次当 nrvo 返回 s 切换到 main。
  • 一次当返回值 nrvo() 用于初始化 s2。

然而，由于复制省略，你的编译器很可能会省略大部分或全部这些复制构造函数调用。Visual Studio 2022省略了3种情况（它没有省略 nrvo() 按值返回的情况），而GCC省略了全部4种。

记住编译器何时执行/不执行复制省略并不重要。只需知道这是一种优化，你的编译器会在可能时执行。如果你期望看到复制构造函数被调用但实际没有，复制省略可能就是原因。

C++17中的强制复制省略 C++17

在C++17之前，复制省略严格来说是编译器可以进行的可选优化。在C++17中，复制省略在某些情况下成为强制性的。在这些情况下，复制省略将自动执行（即使你告诉编译器不要执行复制省略）。

在C++17或更高版本中运行上述相同示例，当 rvo() 返回以及当 s1 用该值初始化时，本应发生的复制构造函数调用被要求省略。 s2 替换为 nvro() 的初始化不是强制省略的情况，因此这里发生的2次复制构造函数调用是否被省略取决于你的编译器和优化设置。

在可选省略的情况下，必须存在可访问的复制构造函数（例如，未被删除），即使实际对复制构造函数的调用被省略。

在强制省略的情况下，不需要存在可访问的复制构造函数（换句话说，即使复制构造函数被删除，强制省略也可以发生）。
