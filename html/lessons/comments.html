1.2 — 注释

● 机器译文 课程 1.2 查看英文原文

一个 注释 是一种程序员可读的注释，直接插入到程序的源代码中。编译器会忽略注释，仅供程序员使用。

在C++中，有两种不同风格的注释，它们都服务于相同的目的：以某种方式帮助程序员记录代码。

单行注释

浮点类型的 // // 符号开始一条C++单行注释，它告诉编译器忽略从 // // 符号到行尾的所有内容。例如：

std::cout << "Hello world!"; // 从这里到行尾的所有内容都会被忽略

通常，单行注释用于对单行代码做一个快速注释。

std::cout << "Hello world!\n"; // std::cout 位于 iostream 库中
std::cout << "It is very nice to meet you!\n"; // 这些注释使代码难以阅读
std::cout << "Yeah!\n"; // 尤其当各行的长度不同时

将注释放在代码右侧可能会使代码和注释都难以阅读，特别是当代码行较长时。如果代码行较短，可以将注释对齐（通常到制表位），如下所示：

std::cout << "Hello world!\n";                 // std::cout 位于 iostream 库中
std::cout << "It is very nice to meet you!\n"; // 这样读起来容易得多
std::cout << "Yeah!\n";                        // 你不觉得吗？

但是，如果代码行较长，将注释放在右侧会使行变得非常长。在这种情况下，单行注释通常放在被注释的代码行上方：

// std::cout 位于 iostream 库中
std::cout << "Hello world!\n";

// 这样读起来容易得多
std::cout << "It is very nice to meet you!\n";

// 你不觉得吗？
std::cout << "Yeah!\n";

作者注

在本教程系列中，我们的示例属于以下类别之一：

  • 完整程序（带有 main() main 函数的程序）。这些程序已准备好编译和运行。
  • 代码片段（小段代码），例如上面的语句。我们用它们来简洁地演示特定概念。

我们不期望你编译这些片段。但如果你愿意，你需要将它们转换成完整的程序。通常，该程序看起来像这样：

#include <iostream>

int main()
{
    // 将这一行替换为你想要编译的代码片段

    return 0;
}

多行注释

浮点类型的 /* 和 */ /* */ 符号对表示C风格的多行注释。两个符号之间的所有内容都会被忽略。

/* 这是一个多行注释。
   这一行将被忽略。
   这一行也是。 */

由于符号之间的所有内容都会被忽略，你有时会看到程序员“美化”他们的多行注释：

/* 这是一个多行注释。
 * 左侧匹配的星号
 * 可以使它更易读
 */

多行注释不能嵌套。因此，以下代码会产生意想不到的结果：

/* 这是一个多行的 /* 注释 */ this is not inside the comment */
// 上述注释在第一个 */ 处结束，而非第二个 */

当编译器尝试编译时，它会忽略从第一个 /* 开始的所有内容 /* 到第一个 */。因为 this is not inside the comment */ 不被视为注释的一部分，编译器将尝试编译它。这必然会导致编译错误。

这是使用语法高亮器非常有用的情况之一，因为注释的不同颜色可以清楚地显示哪些内容属于注释，哪些不属于。

警告

不要在其他多行注释内部使用多行注释。将单行注释包裹在多行注释内是可以的。

注释的正确使用

通常，注释应使用于三种情况。首先，对于给定的库、程序或函数，注释最好用来描述 什么 库、程序或函数的功能。这些注释通常放在文件或库的顶部，或者紧接在函数之前。例如：

// 此程序根据学生的考试和作业成绩计算最终成绩。

// 此函数使用牛顿法近似计算给定方程的根。

// 以下代码行根据稀有度、等级和权重因子生成随机物品。

所有这些注释都能让读者很好地了解库、程序或函数试图实现的目标，而无需查看实际代码。用户（可能是其他人，或者如果你试图重用之前编写的代码，也可能是你自己）可以一眼看出代码是否与其试图实现的目标相关。这在团队合作中尤其重要，因为并非每个人都会熟悉所有代码。

其次， 在 上述的库、程序或函数中，注释可以用来描述 如何 代码将如何实现其目标。

/* 为了计算最终成绩，我们将所有加权后的期中成绩和作业成绩相加，
    然后除以成绩数量得到百分比，该百分比用于计算字母成绩。 */

// 为了生成随机物品，我们将执行以下步骤：
// 1) 将所有所需稀有度的物品放入一个列表
// 2) 根据等级和权重因子计算每个物品的概率
// 3) 选择一个随机数
// 4) 确定该随机数对应的物品
// 5) 返回相应的物品

这些注释让用户了解代码将如何实现其目标，而无需理解每一行代码的具体作用。

第三，在语句级别，注释应被用来描述 为什么 代码正在做某事。糟糕的语句注释解释了 什么 代码在做什么。如果你曾经写过如此复杂的代码，以至于需要注释来解释 什么 一个语句在做什么，你可能需要重写你的语句，而不是注释它。

下面是一些糟糕的行注释和优秀的语句注释示例。

糟糕的注释：

// 将视野范围设置为0
sight = 0;

理由：只看语句，我们也能看出视线被设为0。

优秀的注释：

// 玩家刚刚喝下了失明药水，无法看到任何东西
sight = 0;

理由：现在我们知道了为什么玩家的视线被设为0。

糟糕的注释：

// 计算物品的总价
cost = quantity * 2 * storePrice;

理由：我们可以看到这是一个成本计算，但为什么数量要乘以2？

优秀的注释：

// 此处需要将数量乘以2，因为它们是成对购买的
cost = quantity * 2 * storePrice;

理由：现在我们知道了为什么这个公式有意义。

程序员经常需要在用一种方法解决问题和用另一种方法解决问题之间做出艰难抉择。注释是提醒自己（或告诉别人）你之所以选择一种方案而非另一种方案的好方式。

优秀的注释：

// 我们决定使用链表而非数组，因为
// 数组插入速度太慢。

// 我们将使用牛顿法求一个数的根，因为
// 没有确定性的方法可以解这些方程。

最后，注释的措辞应当让完全不知道代码功能的人也能理解。程序员常常会说：“这显然是在做什么！我绝对不会忘记。”你猜怎么着？它 不是 显然，并且你 会 惊讶于自己遗忘得多么快。:) 你（或其他人）以后会感谢你用人类语言写下了代码的什么、如何以及为什么。单行代码容易理解，但理解它们旨在实现什么目标并不容易。

注释掉代码

将一行或多行代码转换为注释称为 注释掉 你的代码。这提供了一种方便的方式来（暂时）排除部分代码，使其不包含在编译后的程序中。

要注释掉单行代码，只需使用 // 风格注释将一行代码暂时转换为注释：

未注释掉的：

    std::cout << 1;

注释掉的：

//    std::cout << 1;

要注释掉一个代码块，可以在多行代码上使用 //，或者使用 /* */ 风格注释将代码块暂时转换为注释。

未注释掉的：

    std::cout << 1;
    std::cout << 2;
    std::cout << 3;

注释掉的：

//    std::cout << 1;
//    std::cout << 2;
//    std::cout << 3;

或

/*
    std::cout << 1;\n    std::cout << 2;\n    std::cout << 3;
*/

你可能想这样做的原因有很多：

  1. 你正在编写一段尚不能编译的新代码，但需要运行程序。如果存在编译器错误，编译器不会让你编译代码。注释掉不能编译的代码将允许程序编译，以便你能够运行它。当你准备好时，可以取消注释代码，并继续处理它。
  2. 你编写了能编译但运行不正确的新代码，而且没有时间立即修复。注释掉有问题的代码将确保这些代码不会执行并导致问题，直到你能修复它。
  3. 为了找到错误来源。如果程序没有产生预期结果（或崩溃），有时禁用部分代码以查看是否能隔离导致问题的原因是有用的。如果你注释掉一行或多行代码，程序开始按预期工作（或停止崩溃），那么你最后注释掉的部分很可能是问题的一部分。然后你可以调查为什么那些代码行导致了问题。
  4. 你想用另一段代码替换一段代码。与其直接删除原始代码，你可以将其注释掉并保留作为参考，直到你确信新代码正常工作。一旦确定新代码工作正常，你可以删除旧的注释掉的代码。如果新代码无法正常工作，你可以随时删除新代码并取消注释旧代码，恢复到之前的状态。

在开发过程中注释掉代码是常见操作，因此许多 IDE 都提供了对高亮代码段进行注释的支持。访问此功能的方式因 IDE 而异。

适用于 Visual Studio 用户

你可以通过“编辑”菜单 > “高级” > “注释选定内容”（或“取消注释选定内容”）来注释或取消注释选定内容。

对于 Code::Blocks 用户

你可以通过“编辑”菜单 > “注释”（或“取消注释”、“切换注释”或任何其他注释工具）来注释或取消注释选定内容。

对于 VS Code 用户

你可以通过按 Ctrl+/ 来注释或取消注释选中的内容。

提示

如果日常注释总是使用单行注释，那么就可以始终使用多行注释来注释掉代码，而不会产生冲突。如果使用多行注释来记录代码，那么用注释来注释掉代码就会变得更困难。

如果你确实需要注释掉一个包含多行注释的代码块，还可以考虑使用 #if 0 预处理指令，我们在课程 2.10 -- 预处理器简介。

总结

  • 在库、程序或函数级别，使用注释来描述 什么。
  • 在库、程序或函数内部，使用注释来描述 如何。
  • 在语句级别，使用注释来描述 为什么。
