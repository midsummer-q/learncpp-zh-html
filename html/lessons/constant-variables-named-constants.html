5.1 — 常量变量（命名常量）

● 机器译文 课程 5.1 查看英文原文

常量简介

在编程中， 常量 是一个在程序执行期间不能被改变的值。

C++ 支持两种不同的常量：

  • 命名常量 是与标识符关联的常量值。它们有时也被称为 符号常量。
  • 字面常量 是不与标识符关联的常量值。

我们将从命名常量开始介绍常量。然后我们将介绍字面常量（在接下来的课程 5.2 -- 字面量)。

命名常量的类型

在 C++ 中有三种定义命名常量的方法：

  • 常量变量（在本课中介绍）。
  • 带有替换文本的类对象宏（在课程 2.10 -- 预处理器简介中介绍，并在本课中进一步讨论）。
  • 枚举常量（在课程 13.2 -- 无作用域枚举)。

常量变量是最常见的命名常量类型，所以我们先从这里开始。

常量变量

到目前为止，我们看到的所有变量都是非常量的——也就是说，它们的值可以在任何时候被改变（通常通过赋值新值）。例如：

int main()
{
    int x { 4 }; // x 是一个非常量变量
    x = 5; // 使用赋值运算符将 x 的值改为 5

    return 0;
}

然而，在很多情况下，定义值不能被改变的变量是有用的。例如，考虑地球（近地表）的重力：9.8 米/秒2。这个值不太可能在短期内改变（如果真的改变了，你可能面临比学习 C++ 更大的问题）。将这个值定义为常量有助于确保该值不会被意外更改。常量还有其他好处，我们将在后续课程中探讨。

尽管这是一个众所周知的矛盾修饰法，但一个在初始化后值不能被改变的变量被称为 常量变量。

声明一个 const 变量

要声明一个常量变量，我们将 const 关键字（称为“const 限定符”）放在对象类型旁边：

const double gravity { 9.8 };  // 首选在类型前使用 const
int const sidesInSquare { 4 }; // "east const" 风格，可以但不推荐

虽然 C++ 接受 const 限定符放在类型之前或之后，但更常见的做法是将 const 放在类型之前，因为它更符合标准英语语言习惯，即修饰语放在被修饰对象之前（例如，“一个绿色的球”，而不是“一个球绿色的”）。

顺便说一句……

由于编译器解析更复杂声明的方式，一些开发者更喜欢将 const 放在类型之后（因为这样稍微更一致）。这种风格被称为“east const”。虽然这种风格有一些支持者（和一些合理的观点），但它并没有被广泛采用。

最佳实践

将 const 放在类型之前（因为这样做更符合惯例）。

关键提示

对象的类型包括 const 限定符，所以当我们定义 const double gravity { 9.8 }; 时， gravity 等于 const double。

const 变量必须初始化

const 变量 必须 在定义时必须初始化，然后该值不能通过赋值改变：

int main()
{
    const double gravity; // 错误：const 变量必须初始化
    gravity = 9.9;        // 错误：const 变量不能被修改

    return 0;
}

注意，const 变量可以从其他变量（包括非常量变量）初始化：

#include <iostream>

int main()
{ 
    std::cout << "Enter your age: ";
    int age{};
    std::cin >> age;

    const int constAge { age }; // 使用非常量值初始化 const 变量

    age = 5;      // ok：age 是非常量，所以我们可以改变它的值
    constAge = 6; // 错误：constAge 是 const，所以我们不能改变它的值

    return 0;
}

在上面的例子中，我们用非常量变量 constAge 初始化了 const 变量 age。因为 age 仍然是非常量的，我们可以改变它的值。然而，因为 constAge 是 const 的，我们无法在初始化后更改其值。

关键提示

const 变量的初始化器可以是非常量值。

命名你的 const 变量

对于 const 变量，有多种不同的命名约定。

从 C 语言转来的程序员通常喜欢用下划线分隔的大写名称来命名 const 变量（例如 EARTH_GRAVITY）。在 C++ 中更常见的是使用带 'k' 前缀的驼峰式名称（例如 kEarthGravity)。

然而，由于 const 变量像普通变量一样工作（只是不能被赋值），它们没有理由需要特殊的命名约定。因此，我们更倾向于使用与非 const 变量相同的命名约定（例如 earthGravity)。

Const 函数参数

函数参数可以通过 const 关键字成为常量：

#include <iostream>

void printInt(const int x)
{
    std::cout << x << '\n';
}

int main()
{
    printInt(5); // 5 将用作 x 的初始化值
    printInt(6); // 6 将用作 x 的初始化值

    return 0;
}

注意我们没有为 const 参数提供显式初始化器 x ——函数调用中实参的值将用作 x。

的初始化器。将函数参数设为常量可以借助编译器确保参数的值在函数内部不被改变。然而，在现代 C++ 中，我们通常不将值参数设为 const ，因为我们通常不关心函数是否改变了参数的值（因为它只是一个副本，在函数结束时会被销毁）。 const 关键字还会给函数原型增加一些不必要的杂乱。

最佳实践

不要对值参数使用 const

在本教程系列的后面，我们将讨论另外两种向函数传递参数的方式：传引用和传地址。使用这两种方法时，正确使用 const 很重要。

Const 返回值

函数的返回值也可以设为 const：

#include <iostream>

const int getValue()
{
    return 5;
}

int main()
{
    std::cout << getValue() << '\n';

    return 0;
}

对于基本类型，返回类型上的 const 限定符会被忽略（你的编译器可能会生成警告）。

对于其他类型（我们稍后会介绍），按值返回 const 对象通常没什么意义，因为它们是临时副本，无论如何都会被销毁。返回 const 值还可能阻碍某些编译器优化（涉及移动语义），从而导致性能降低。

最佳实践

不要对值参数使用 const 当按值返回时。

为什么变量应该设为常量

如果一个变量可以设为常量，通常就应该设为常量。这很重要，原因如下：

  • 它减少了出错的可能性。通过将变量设为常量，你可以确保其值不会被意外更改。
  • 它为编译器提供了更多优化程序的机会。当编译器可以假设某个值不会改变时，它能够利用更多技术来优化程序，从而生成更小、更快的编译程序。我们将在本章后面进一步讨论这一点。
  • 最重要的是，它降低了程序的整体复杂性。当试图确定某段代码的功能或调试问题时，我们知道 const 变量的值不能被更改，因此我们不必担心它的值是否在变化、变化成什么值以及新值是否正确。

关键提示

系统中的每个运动部件都会增加复杂性和缺陷或故障的风险。非常量变量是运动部件，而常量变量则不是。

最佳实践

尽可能将变量设为常量。例外情况包括按值传递的函数参数和按值返回的类型，它们通常不应设为常量。

具有替换文本的对象式宏

在课程 2.10 -- 预处理器简介，我们讨论了带有替换文本的类对象宏。例如：

#include <iostream>

#define MY_NAME "Alex"

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n';

    return 0;
}

当预处理器处理包含此代码的文件时，它会将 MY_NAME （第 7 行）替换为 "Alex"。注意 MY_NAME 是一个名称，替换文本是一个常量值，因此带有替换文本的类对象宏也是命名常量。

优先使用常量变量而非预处理器宏

那么为什么不用预处理器宏作为命名常量呢？至少有三大问题。

最大的问题是宏不遵循正常的 C++ 作用域规则。一旦宏被 #define，当前文件中所有后续出现的宏名称都会被替换。如果该名称在其他地方被使用，你会在不希望的地方发生宏替换。这很可能导致奇怪的编译错误。例如：

#include <iostream>

void someFcn()
{
// 尽管 gravity 是在这个函数内部定义的
// 预处理器将替换文件中后续所有出现的 gravity
#define gravity 9.8
}

void printGravity(double gravity) // 包括这一处，导致编译错误
{
    std::cout << "gravity: " << gravity << '\n';
}

int main()
{
    printGravity(3.71);

    return 0;
}

编译时，GCC 产生了这个令人困惑的错误：

prog.cc:7:17: error: expected ',' or '...' before numeric constant
    5 | #define gravity 9.8
      |                 ^~~
prog.cc:10:26: note: in expansion of macro 'gravity'

其次，使用宏调试代码通常更困难。虽然你的源代码中会有宏的名称，但编译器和调试器永远不会看到宏，因为它在它们运行之前已经被替换了。许多调试器无法检查宏的值，并且在处理宏时通常功能有限。

第三，宏替换的行为与 C++ 中的其他所有内容不同。因此很容易无意中犯错。

常量变量没有这些问题：它们遵循正常的作用域规则，可以被编译器和调试器看到，并且行为一致。

最佳实践

优先使用常量变量而不是带有替换文本的类对象宏。

在多文件程序中使用常量变量

在许多应用程序中，某个命名常量需要在整个代码中使用（不仅仅在一个文件中）。这些常量可以包括不会改变的物理或数学常量（例如 π 或阿伏伽德罗常数），或者特定于应用程序的“调优”值（例如摩擦系数或重力系数）。与其每次需要时重新定义它们，不如在一个中心位置声明一次，并在需要的地方使用它们。这样，如果你需要更改它们，只需在一个地方更改即可。

在 C++ 中有多种方法可以实现这一点——我们在课程中详细讨论了这一主题 7.10 —— 跨多个文件共享全局常量（使用内联变量）。

术语：类型限定符

一个 类型限定符 （有时称为 限定符 （简称）是一个应用于类型的关键字，用于修改该类型的行为。 const 用于声明常量变量的关键字称为 const 类型限定符 （或 const 限定符 （简称）。

截至 C++23，C++ 只有两个类型限定符： const 和 volatile。

可选阅读

浮点类型的 volatile 限定符用于告诉编译器一个对象的值可能随时改变。这个很少使用的限定符会禁用某些类型的优化。

在技术文档中， const 和 volatile 限定符通常被称为 cv-限定符。以下术语也用于 C++ 标准：

  • 一个 cv-非限定 类型是没有类型限定符的类型（例如 int)。
  • 一个 cv-限定 类型是应用了一个或多个类型限定符的类型（例如 const int)。
  • 一个 可能 cv-限定 类型是可能是 cv-非限定或 cv-限定的类型。

这些术语在技术文档之外很少使用，因此这里列出仅供参考，并非需要记住的内容。
