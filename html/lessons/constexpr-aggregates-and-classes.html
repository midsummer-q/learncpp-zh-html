14.17 — Constexpr 聚合体和类

● 机器译文 课程 14.17 查看英文原文

在课程 F.1 -- Constexpr函数我们介绍了 constexpr 函数，这些函数可以在编译时或运行时求值。例如：

#include <iostream>

constexpr int greater(int x, int y)
{
    return (x > y ? x : y);
}

int main()
{
    std::cout << greater(5, 6) << '\n'; // greater(5, 6) 可以在编译时或运行时求值

    constexpr int g { greater(5, 6) };  // greater(5, 6) 必须在编译时求值
    std::cout << g << '\n';             // 表达式 2 + 3 产生值 5

    return 0;
}

在这个例子中， greater() 是一个 constexpr 函数，而 greater(5, 6) 是一个常量表达式，可以在编译时或运行时求值。因为 std::cout << greater(5, 6) 调用 greater(5, 6) 在非 constexpr 上下文中，编译器可以自由选择是在编译时还是运行时求值 greater(5, 6)。当 greater(5, 6) 用于初始化 constexpr 变量 g， greater(5, 6) 在 constexpr 上下文中被调用，并且必须在编译时求值。

现在考虑以下类似的例子：

#include <iostream>

struct Pair
{
    int m_x {};
    int m_y {};

    int greater() const
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

int main()
{
    Pair p { 5, 6 };                  // 输入是 constexpr 值
    std::cout << p.greater() << '\n'; // p.greater() 在运行时求值

    constexpr int g { p.greater() };  // 编译错误：greater() 不是 constexpr
    std::cout << g << '\n';

    return 0;
}

在这个版本中，我们有一个名为 Pair、和 greater() 现在是一个成员函数。然而，因为成员函数 greater() 不是 constexpr， p.greater() 不是一个常量表达式。当 std::cout << p.greater() 调用 p.greater() （在非 constexpr 上下文中）， p.greater() 将在运行时求值。然而，当我们尝试使用 p.greater() 来初始化 constexpr 变量 g时，我们会得到一个编译错误，因为 p.greater() 不能在编译时求值。

由于 p 的输入是 constexpr 值（5 和 6），似乎 p.greater() 应该能够在编译时求值。但我们该怎么做呢？

Constexpr 成员函数

就像非成员函数一样，成员函数可以通过使用 constexpr 关键字成为 constexpr。Constexpr 成员函数可以在编译时或运行时求值。

#include <iostream>

struct Pair
{
    int m_x {};
    int m_y {};

    constexpr int greater() const // 可以在编译时或运行时求值
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

int main()
{
    Pair p { 5, 6 };
    std::cout << p.greater() << '\n'; // 可以：p.greater() 在运行时求值

    constexpr int g { p.greater() };  // 编译错误：p 不是 constexpr
    std::cout << g << '\n';

    return 0;
}

在这个例子中，我们将 greater() 设为 constexpr 函数，因此编译器可以在运行时或编译时求值。

当我们调用 p.greater() 在运行时表达式中 std::cout << p.greater()，它在运行时求值。

然而，当 p.greater() 用于初始化 constexpr 变量 g，我们会得到一个编译错误。尽管 greater() 现在是 constexpr， p 仍然不是 constexpr，因此 p.greater() 不是一个常量表达式。

Constexpr 聚合体

好的，所以如果我们需要 p 是 constexpr，那就让它成为 constexpr：

#include <iostream>

struct Pair // Pair 是一个聚合体
{
    int m_x {};
    int m_y {};

    constexpr int greater() const
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

int main()
{
    constexpr Pair p { 5, 6 };        // 现在是 constexpr
    std::cout << p.greater() << '\n'; // p.greater() 在运行时或编译时求值

    constexpr int g { p.greater() };  // p.greater() 必须在编译时求值
    std::cout << g << '\n';

    return 0;
}

由于 Pair 是一个聚合体，并且聚合体隐式支持 constexpr，我们就完成了。这可行！由于 p 是一个 constexpr 类型，并且 greater() 是一个 constexpr 成员函数， p.greater() 是一个常量表达式，可以在只允许常量表达式的地方使用。

Constexpr 类对象和 constexpr 构造函数

现在让我们把我们的 Pair 变成一个非聚合类型：

#include <iostream>

class Pair // Pair 不再是聚合体
{
private:
    int m_x {};
    int m_y {};

public:
    Pair(int x, int y): m_x { x }, m_y { y } {}

    constexpr int greater() const
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

int main()
{
    constexpr Pair p { 5, 6 };       // 编译错误：p 不是字面类型
    std::cout << p.greater() << '\n';

    constexpr int g { p.greater() };
    std::cout << g << '\n';

    return 0;
}

这个例子几乎与前一个相同，除了 Pair 不再是一个聚合类型（由于拥有私有数据成员和一个构造函数）。

当我们编译这个程序时，我们得到一个关于 Pair 不是“字面类型”的编译器错误。什么？

在C++中， 字面类型 是指任何可能可以在常量表达式中创建对象的类型。换句话说，除非类型符合字面类型的条件，否则对象不能是 constexpr。而我们的非聚合类型 Pair 不符合条件。

术语

字面量和字面类型是不同的（但相关）概念。字面量是插入到源代码中的 constexpr 值。字面类型是可以作为 constexpr 值类型的类型。字面量总是具有字面类型。然而，具有字面类型的值或对象不一定是字面量。

字面类型的定义很复杂，可以在 cppreference上找到总结。不过，值得注意的是，字面类型包括：

  • 标量类型（持有单个值的类型，如基本类型和指针）
  • 引用类型
  • 大多数聚合类型
  • 具有 constexpr 构造函数的类

现在我们明白为什么我们的 Pair 不是字面类型了。当实例化一个类对象时，编译器会调用构造函数来初始化对象。而我们的 Pair 类中的构造函数不是 constexpr，因此不能在编译时调用。所以， Pair 对象不能是 constexpr。

解决方法很简单：我们只需将构造函数也设为 constexpr ：

#include <iostream>

class Pair
{
private:
    int m_x {};
    int m_y {};

public:
    constexpr Pair(int x, int y): m_x { x }, m_y { y } {} // 现在是 constexpr

    constexpr int greater() const
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

int main()
{
    constexpr Pair p { 5, 6 };
    std::cout << p.greater() << '\n';

    constexpr int g { p.greater() };
    std::cout << g << '\n';

    return 0;
}

这按预期工作，就像我们的聚合版本 Pair 一样。

最佳实践

如果你希望你的类能够在编译时求值，请将你的成员函数和构造函数设为 constexpr。

隐式定义的构造函数如果能够被定义为 constexpr，则它们就是 constexpr。显式默认的构造函数必须显式定义为 constexpr。

提示

Constexpr 是类接口的一部分，以后移除它会破坏在常量上下文中调用该函数的调用者。

非 constexpr/非 const 对象可能需要 constexpr 成员

在上面的例子中，由于 constexpr 变量 g 的初始化器必须是常量表达式，很明显 p.greater() 必须是常量表达式，因此 p， Pair 构造函数和 greater() 都必须为 constexpr。

然而，如果我们把 p.greater() 替换为一个 constexpr 函数，事情就变得不那么明显了：

#include <iostream>

class Pair
{
private:
    int m_x {};
    int m_y {};

public:
    constexpr Pair(int x, int y): m_x { x }, m_y { y } {}

    constexpr int greater() const
    {
        return (m_x > m_y  ? m_x : m_y);
    }
};

constexpr int init()
{
    Pair p { 5, 6 };    // 在编译时求值时要求构造函数是 constexpr
    return p.greater(); // 在编译时求值时要求 greater() 是 constexpr
}

int main()
{
    constexpr int g { init() }; // init() 在编译时上下文中求值
    std::cout << g << '\n';

    return 0;
}

记住，constexpr 函数可以在运行时或编译时求值。而当 constexpr 函数在编译时求值时，它只能调用能够在编译时求值的函数。对于类类型，这意味着 constexpr 成员函数。

由于 g 是 constexpr， init() 必须在编译时求值。在 init() 函数内部，我们定义了 p 作为非constexpr/非const（因为我们可以，而不是因为我们应当）。尽管 p 没有被定义为constexpr， p 仍然需要在编译时创建，因此需要一个constexpr构造函数。类似地，为了让 Pair 在编译时求值， p.greater() 必须是一个constexpr成员函数。如果 greater() 构造函数或 Pair 不是constexpr，编译器就会报错。 greater() 不是constexpr，编译器就会报错。

关键提示

当一个constexpr函数在编译期上下文中求值时，只能调用constexpr函数。

Constexpr成员函数可以是const或非const C++14

在C++11中，非静态constexpr成员函数隐式地为const（构造函数除外）。

然而，从C++14开始，constexpr成员函数不再隐式地为const。这意味着如果你希望一个constexpr函数是const函数，你必须显式地将其标记为const。

Constexpr非const成员函数可以修改数据成员 可选

一个constexpr非const成员函数可以修改类的数据成员，只要隐式对象不是const。即使函数在编译时求值也是如此。

这里有一个刻意构造的例子：

#include <iostream>

class Pair
{
private:
    int m_x {};
    int m_y {};

public:
    constexpr Pair(int x, int y): m_x { x }, m_y { y } {}

    constexpr int greater() const // constexpr 和 const
    {
        return (m_x > m_y  ? m_x : m_y);
    }

    constexpr void reset() // constexpr 但非 const
    {
        m_x = m_y = 0; // 非const成员函数可以修改成员
    }

    constexpr const int& getX() const { return m_x; }
};

// 此函数是constexpr
constexpr Pair zero()
{
    Pair p { 1, 2 }; // p是非const的
    p.reset();       // 可以在非const对象上调用非const成员函数
    return p;
}

int main()
{
    Pair p1 { 3, 4 };
    p1.reset();                     // 可以在非const对象上调用非const成员函数
    std::cout << p1.getX() << '\n'; // 打印 0
    
    Pair p2 { zero() };             // zero()将在运行时求值
    p2.reset();                     // 可以在非const对象上调用非const成员函数
    std::cout << p2.getX() << '\n'; // 打印 0

    constexpr Pair p3 { zero() };   // zero()将在编译时求值
//    p3.reset();                   // 编译错误：不能在const对象上调用非const成员函数
    std::cout << p3.getX() << '\n'; // 打印 0

    return 0;
}

当我们逐步分析这个例子时，请记住：

  • 非const成员函数可以修改非const对象的成员。
  • constexpr成员函数可以在运行时上下文或编译时上下文中调用。

这两件事是独立工作的。

在 p1， p1 是非const的。因此，我们被允许调用非const成员函数 p1.reset() 来修改 p1。 reset() 是constexpr这一事实在这里并不重要，因为我们所做的任何事情都不需要编译时求值。

浮点类型的 p2 情况类似。在这种情况下， p2 的初始化器是对 zero()的函数调用。尽管 zero() 是一个constexpr函数，但在这里它在运行时上下文中被调用，并且表现得像一个普通函数。在 zero()内部，我们实例化非const的 p，在其上调用非const成员函数 p.reset() ，然后返回 p。返回的 Pair 被用作 p2。 zero() 和 reset() 是constexpr这一事实在这种情况下并不重要，因为我们所做的任何事情都不需要编译时求值。

浮点类型的 p3 情况是有趣的。因为 p3 是constexpr，它必须有一个常量表达式初始化器。因此，对 zero() 的调用必须在编译时求值。并且因为我们在编译时上下文中求值，我们只能调用constexpr函数。在 zero()， p 内部， p 是非const的（这是允许的，即使我们在编译时求值）。然而，因为我们在编译时上下文中，用于创建 p2 的构造函数必须是constexpr。并且就像 p.reset() 情况一样，我们被允许在非const对象 p上调用非const成员函数 reset() 成员函数必须是 constexpr。然后该函数返回 p，用于初始化 p3。

作者注

是的，我们用一个非 const 对象初始化了一个 constexpr 对象。如果这让你的大脑短路，很可能是因为你还没有完全区分 const 和 constexpr。

constexpr 变量并不要求用 const 值初始化。之所以看起来如此，是因为大多数时候我们用字面量（它们是 const 的）或其他 constexpr 变量（它们隐式是 const 的）来初始化 constexpr 变量，而且这两个术语 const 和 constexpr 名字相似。

实际要求是 constexpr 变量必须用常量表达式初始化。对于函数（和运算符），constexpr 并不意味着 const，constexpr 函数（和运算符）可以使用非 const 对象，甚至可以返回它们。

重要的不是 const，而是编译器可以在编译时确定对象的值。对于 constexpr 函数，即使它们返回非 const 对象，这也是可能的！

返回 const 引用（或指针）的 constexpr 函数 可选

通常你不会看到 constexpr 和 const 紧挨着使用，但有一种情况是当你有返回 const 引用（或指向 const 的指针）的 constexpr 成员函数时。

在我们上面的 Pair 类中， getX() 是一个返回 const 引用的 constexpr 成员函数：

    constexpr const int& getX() const { return m_x; }

好多 const 啊！

浮点类型的 constexpr 表示该成员函数可以在编译时求值。 const int& 是函数的返回类型。最右边的 const 表示成员函数本身是 const 的，因此可以在 const 对象上调用。

顺便说一句……

返回指向 const 的 const 指针的成员函数可能看起来像这样：

constexpr const int* const getXPtr() const { return &m_x; }
