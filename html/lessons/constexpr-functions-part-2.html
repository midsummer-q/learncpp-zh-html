F.2 — Constexpr 函数（第二部分）

● 机器译文 课程 F.2 查看英文原文

非必需常量表达式中的 constexpr 函数调用

你可能期望 constexpr 函数会在可能的情况下在编译时求值，但不幸的是，情况并非如此。

在课程 5.5 -- 常量表达式，我们注意到，在不需要 必须 常量表达式的上下文中，编译器可以选择在编译时或运行时对常量表达式求值。因此，任何属于非必需常量表达式的 constexpr 函数调用都可以在编译时或运行时求值。

例如：

#include <iostream>

constexpr int getValue(int x)
{
    return x;
}

int main()
{
    int x { getValue(5) }; // 可能在运行时或编译时求值
    
    return 0;
}

在上面的例子中，因为 getValue() 是 constexpr，调用 getValue(5) 是一个常量表达式。然而，因为变量 x 不是 constexpr，它不需要常量表达式初始化器。所以即使我们提供了一个常量表达式初始化器，编译器也可以自由选择 getValue(5) 是在运行时还是编译时求值。

关键提示

只有在需要常量表达式时，才保证 constexpr 函数在编译时求值。

必需常量表达式中 constexpr 函数的诊断

编译器 不是 只有在实际编译时求值时，才需要确定 constexpr 函数是否可在编译时求值。编写一个在运行时使用可以成功编译，但在编译时求值时却失败的 constexpr 函数是相当容易的。

举一个愚蠢的例子：

#include <iostream>

int getValue(int x)
{
    return x;
}

// 此函数可以在运行时求值
// 当在编译时求值时，该函数将产生编译错误
// 因为对 getValue(x) 的调用无法在编译时解析
constexpr int foo(int x)
{
    if (x < 0) return 0; // 在 C++23 中采用 P2448R1 之前需要（见下面的注释）
    return getValue(x);  // 此处调用非 constexpr 函数
}

int main()
{
    int x { foo(5) };           // 可以：将在运行时求值
    constexpr int y { foo(5) }; // 编译错误：foo(5) 无法在编译时求值

    return 0;
}

在上面的例子中，当 foo(5) 用作非 constexpr 变量 x的初始化器时，它将在运行时求值。这可以正常工作，并返回值 5。

然而，当 foo(5)用作 constexpr 变量 y的初始化器时，它必须在编译时求值。此时，编译器将确定对 foo(5) 的调用无法在编译时求值，因为 getValue() 不是 constexpr 函数。

因此，在编写 constexpr 函数时，始终要显式测试它在编译时求值时是否能编译（通过在需要常量表达式的上下文中调用它，例如在 constexpr 变量的初始化中）。

最佳实践

所有 constexpr 函数都应在编译时可求值，因为在需要常量表达式的上下文中，它们将被要求这样做。

始终在需要常量表达式的上下文中测试你的 constexpr 函数，因为 constexpr 函数可能在运行时求值时工作，但在编译时求值时失败。

进阶读者

在 C++23 之前，如果不存在任何参数值允许 constexpr 函数在编译时求值，则程序是病式的（无需诊断）。如果没有行 if (x < 0) return 0，上面的例子将不包含任何允许函数在编译时可求值的参数集，从而使程序病式。由于不需要诊断，编译器可能不会强制执行这一点。

这个要求在 C++23 中被撤销（P2448R1)。

Constexpr/consteval 函数参数不是 constexpr

constexpr 函数的参数不是隐式 constexpr，也不能声明为 constexpr。

关键提示

constexpr 函数参数意味着该函数只能使用 constexpr 参数调用。但事实并非如此——constexpr 函数可以在运行时求值时使用非 constexpr 参数调用。

由于这些参数不是 constexpr，它们不能在函数内部的常量表达式中使用。

consteval int goo(int c)    // c 不是 constexpr，不能在常量表达式中使用
{
    return c;
}

constexpr int foo(int b)    // b 不是 constexpr，不能在常量表达式中使用
{
    constexpr int b2 { b }; // 编译错误：constexpr 变量需要常量表达式初始化器

    return goo(b);          // 编译错误：consteval 函数调用需要常量表达式参数
}

int main()
{
    constexpr int a { 5 };

    std::cout << foo(a); // 可以：常量表达式 a 可以用作 constexpr 函数 foo() 的参数
    
    return 0;
}

在上面的例子中，函数参数 b 不是 constexpr（即使参数 a 是一个常量表达式）。这意味着 b 不能在任何需要常量表达式的地方使用，例如 constexpr 变量的初始化器（例如 b2）或调用 consteval 函数（goo(b))。

constexpr 函数的参数可以声明为 const，在这种情况下，它们被视为运行时常量。

相关内容

如果你需要常量表达式的参数，请参阅 11.9 -- 非类型模板参数。

Constexpr 函数隐式内联

当 constexpr 函数在编译时求值时，编译器必须能够在函数调用之前看到 constexpr 函数的完整定义（以便自行执行求值）。在这种情况下，即使实际函数定义出现在同一编译单元中的后面，前向声明也不够。

这意味着在多个文件中调用的 constexpr 函数需要将其定义包含到每个翻译单元中——这通常违反单一定义规则。为避免此类问题，constexpr 函数隐式内联，从而不受单一定义规则约束。

因此，constexpr 函数通常定义在头文件中，以便可以 #include 到任何需要完整定义的 .cpp 文件中。

规则

编译器必须能够看到 constexpr（或 consteval）函数的完整定义，而不仅仅是前向声明。

最佳实践

在单个源文件 (.cpp) 中使用的 constexpr/consteval 函数应定义在该源文件中使用它们的位置之上。

在多个源文件中使用的 constexpr/consteval 函数应定义在头文件中，以便可以包含到每个源文件中。

对于仅在运行时求值的 constexpr 函数调用，前向声明足以满足编译器要求。这意味着你可以使用前向声明来调用定义在另一个翻译单元中的 constexpr 函数，但前提是在不需要编译时求值的上下文中调用它。

进阶读者

根据 CWG2166，对于在编译时求值的 constexpr 函数，前向声明的实际要求是“constexpr 函数必须在最终导致调用的最外层求值之前定义”。因此，这是允许的：

#include <iostream>

constexpr int foo(int);

constexpr int goo(int c)
{
	return foo(c);   // 注意 foo 尚未定义
}

constexpr int foo(int b) // 可以，因为 foo 在对 goo 的任何调用之前已定义
{
	return b;
}

int main()
{
	 constexpr int a{ goo(5) }; // 这是最外层的调用

	return 0;
}

这里的意图是允许相互递归的 constexpr 函数（两个 constexpr 函数互相调用），否则这是不可能的。

总结

将函数标记为 constexpr 意味着它可以在常量表达式中使用。这并不意味着“将在编译时求值”。

常量表达式（可能包含 constexpr 函数调用）仅在需要常量表达式的上下文中才需要在编译时求值。

在不需要常量表达式的上下文中，编译器可以选择是在编译时还是运行时求值常量表达式（可能包含 constexpr 函数调用）。

运行时（非常量）表达式（可能包含 constexpr 函数调用或非 constexpr 函数调用）将在运行时求值。

另一个示例

让我们再做一次检查，探讨 constexpr 函数如何被要求或可能进一步求值：

#include <iostream>

constexpr int greater(int x, int y)
{
    return (x > y ? x : y);
}

int main()
{
    constexpr int g { greater(5, 6) };              // 情况 1：始终在编译时求值
    std::cout << g << " is greater!\n";

    std::cout << greater(5, 6) << " is greater!\n"; // 情况 2：可能在运行时或编译时求值

    int x{ 5 }; // 不是 constexpr，但值在编译时已知
    std::cout << greater(x, 6) << " is greater!\n"; // 情况 3：可能在运行时求值

    std::cin >> x;
    std::cout << greater(x, 6) << " is greater!\n"; // 情况 4：始终在运行时求值

    return 0;
}

在情况 1 中，我们在需要常量表达式的上下文中调用 greater() 因此 greater() 必须在编译时求值。

在情况 2 中， greater() 函数在不需要常量表达式的上下文中被调用，因为输出语句必须在运行时执行。然而，由于参数是常量表达式，该函数有资格在编译时求值。因此编译器可以自由选择对 greater() 的调用是在编译时还是运行时求值。

在情况 3 中，我们调用 greater() 时有一个参数不是常量表达式。因此这通常会在运行时执行。

然而，这个参数的值在编译时是已知的。根据 as-if 规则，编译器可以决定将 x 的求值视为常量表达式，并在编译时求值对 greater() 的调用。但更可能的是，它会在运行时求值。

相关内容

我们在课程中介绍了 as-if 规则 5.5 -- 常量表达式。

注意，即使是非 constexpr 函数也可能在 as-if 规则下在编译时求值！

在情况 4 中，参数 x 的值在编译时无法知道，因此对 greater() 的调用将始终在运行时求值。

关键提示

换句话说，我们可以将函数实际在编译时求值的可能性分类如下：

总是（标准要求）：

  • Constexpr 函数在需要常量表达式的上下文中被调用。
  • Constexpr 函数从另一个正在编译时求值的函数中被调用。

很可能（几乎没有理由不这样做）：

  • Constexpr 函数在不需要常量表达式的上下文中被调用，且所有参数都是常量表达式。

可能（如果在 as-if 规则下进行了优化）：

  • constexpr 函数在不需要常量表达式的地方被调用，某些参数不是常量表达式，但它们的值在编译时已知。
  • 非 constexpr 函数能够在编译时求值，所有参数都是常量表达式。

从不（不可能）：

  • constexpr 函数在不需要常量表达式的地方被调用，某些参数的值在编译时未知。

请注意，编译器的优化级别设置可能会影响它决定在编译时还是运行时求值函数。这也意味着你的编译器可能会对调试版本和发布版本做出不同的选择（因为调试版本通常关闭优化）。

例如，gcc 和 Clang 都不会在不需要常量表达式的地方对 constexpr 函数进行编译时求值，除非告诉编译器优化代码（例如使用 -O2 编译器选项）。

进阶读者

编译器也可能选择内联函数调用，甚至完全优化掉函数调用。这两者都可能影响函数调用内容何时（或是否）被求值。
