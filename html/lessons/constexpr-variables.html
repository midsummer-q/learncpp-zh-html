5.6 — Constexpr 变量

● 机器译文 课程 5.6 查看英文原文

在上一节课 5.5 -- 常量表达式我们定义了什么是常量表达式，讨论了为什么常量表达式是可取的，并总结了常量表达式何时在编译时实际求值。

在本课中，我们将更深入地了解如何在现代 C++ 中创建可用于常量表达式的变量。我们还将探索确保代码实际在编译时执行的第一种方法。

编译时 const 挑战

在上一课中，我们注意到创建可用于常量表达式的变量的一种方法是使用 const 关键字。具有整型类型和常量表达式初始化器的 const 变量可以在常量表达式中使用。所有其他 const 变量不能在常量表达式中使用。

然而，使用 const 创建可用于常量表达式的变量存在一些挑战。

首先，使用 const 并不能立即清楚该变量是否可以在常量表达式中使用。在某些情况下，我们可以很容易地判断：

int a { 5 };       // 根本不是 const
const int b { a }; // 显然不是常量表达式（因为初始化器是非 const 的）
const int c { 5 }; // 显然是常量表达式（因为初始化器是常量表达式）

在其他情况下，可能相当困难：

const int d { someVar };    // 不清楚 d 是否可以在常量表达式中使用
const int e { getValue() }; // 不清楚 e 是否可以在常量表达式中使用

在上面的例子中，变量 d 和 e 可能可以在常量表达式中使用，也可能不行，这取决于 someVar 和 getValue() 是如何定义的。这意味着我们必须检查这些初始化器的定义并推断我们处于哪种情况。而且这甚至可能还不够——如果 someVar 是 const 并且用变量或函数调用初始化，我们还得检查它的初始化器的定义！

其次，使用 const 无法告知编译器我们需要一个可在常量表达式中使用的变量（并且如果它不能，编译器应该停止编译）。相反，它只会静默地创建一个只能在运行时表达式中使用的变量。

第三，使用 const 创建编译时常量变量的方法不适用于非整型变量。而在许多情况下，我们也希望非整型变量成为编译时常量。

浮点类型的 constexpr 关键字的类型推导

幸运的是，我们可以借助编译器的帮助，确保在我们需要的地方得到编译时常量变量。为此，我们在变量声明中使用 constexpr 关键字（它是“常量表达式”的缩写）而不是 const constexpr 变量始终是编译时常量。因此，constexpr 变量必须用常量表达式初始化，否则会导致编译错误。

例如：

#include <iostream>

// 非 constexpr 函数的返回值不是 constexpr
int five()
{
    return 5;
}

int main()
{
    constexpr double gravity { 9.8 }; // ok: 9.8 是常量表达式
    constexpr int sum { 4 + 5 };      // ok: 4 + 5 是常量表达式
    constexpr int something { sum };  // ok: sum 是常量表达式

    std::cout << "Enter your age: ";
    int age{};
    std::cin >> age;

    constexpr int myAge { age };      // 编译错误：age 不是常量表达式
    constexpr int f { five() };       // 编译错误：five() 的返回值不是 constexpr

    return 0;
}

因为函数通常在运行时执行，所以函数的返回值不是 constexpr（即使返回表达式是常量表达式）。这就是为什么 five() 不是 constexpr int f。

最佳实践

任何初始化器是常量表达式的常量变量都应声明为 constexpr。

任何初始化器不是常量表达式（使其成为运行时常量）的常量变量都应声明为 const。

注意：将来我们会讨论一些与 constexpr （包括 std::string， std::vector不完全兼容的类型，以及其他使用动态内存分配的类型。对于这些类型的常量对象，要么使用 const 而不是 constexpr，要么选择其他与 constexpr 兼容的类型（例如 std::string_view 或 std::array)。

术语

术语 constexpr 是“常量表达式”的合成词。之所以选择这个名称，是因为 constexpr 对象（和函数）可以在常量表达式中使用。

形式上，关键字 constexpr 仅适用于对象和函数。按照惯例，术语 constexpr 用作任何常量表达式的简写（例如 1 + 2)。

进阶读者

在 C 和 C++ 中，数组对象（一个对象可以保存多个值）的声明要求数组的长度（它可以保存的值的数量）在编译时已知（以便编译器确保为数组对象分配正确的内存量）。

由于字面量在编译时已知，它们可以用作数组长度：

int arr[5]; // 一个包含 5 个 int 值的数组，长度 5 在编译时已知

在许多情况下，最好使用符号常量作为数组长度（例如，避免魔法数字，并且如果数组长度在多个地方使用，更容易更改）。在 C 中，这可以通过预处理器宏或枚举器实现，但不能通过 const 变量（不包括 VLA，它们有其他缺点）。C++ 为了改进这种情况，希望允许使用 const 变量而不是宏。但变量的值通常被认为只在运行时已知，这使得它们不能用作数组长度。

为了解决这个问题，C++ 语言标准增加了一个例外，使得具有常量表达式初始化器的 const 整数类型被视为编译时已知的值，从而可以用作数组长度：

const int arrLen = 5;
int arr[arrLen]; // ok: 包含 5 个 int 的数组

当 C++11 引入常量表达式时，将具有常量表达式初始化器的 const int 纳入该定义是合理的。委员会讨论了是否也应包括其他类型，但最终决定不这样做。

Const 和 constexpr 函数参数

普通函数调用在运行时求值，提供的参数用于初始化函数的参数。由于函数参数的初始化发生在运行时，这导致两个后果：

  1. const 函数参数被视为运行时常量（即使提供的参数是编译时常量）。
  2. 函数参数不能声明为 constexpr，因为它们的初始化值直到运行时才确定。

constexpr 函数简介

一个 constexpr 函数 是一个可以在常量表达式中调用的函数。当 constexpr 函数所在的常量表达式必须在编译时求值时（例如在 constexpr 变量的初始化器中），它必须在编译时求值。否则，constexpr 函数可以在编译时（如果符合条件）或运行时求值。要符合编译时执行的条件，所有参数必须是常量表达式。

要创建 constexpr 函数，将 constexpr 关键字放在函数声明中返回类型之前：

#include <iostream>

int max(int x, int y) // 这是一个非 constexpr 函数
{
    if (x > y)
        return x;
    else
        return y;
}

constexpr int cmax(int x, int y) // 这是一个 constexpr 函数
{
    if (x > y)
        return x;
    else
        return y;
}

int main()
{
    int m1 { max(5, 6) };            // ok
    const int m2 { max(5, 6) };      // ok
    constexpr int m3 { max(5, 6) };  // 编译错误：max(5, 6) 不是常量表达式

    int m4 { cmax(5, 6) };           // ok: 可以在编译时或运行时求值
    const int m5 { cmax(5, 6) };     // ok: 可以在编译时或运行时求值
    constexpr int m6 { cmax(5, 6) }; // ok: 必须在编译时求值

    return 0;
}
