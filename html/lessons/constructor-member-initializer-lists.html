14.10 — 构造函数成员初始化列表

● 机器译文 课程 14.10 查看英文原文

本课继续介绍来自课程 14.9 -- 构造函数简介。

通过成员初始化列表进行成员初始化

要让构造函数初始化成员，我们使用 成员初始化列表 （通常称为“成员初始化列表”）。不要将其与用于用值列表初始化聚合的类似名称的“初始化列表”混淆。

成员初始化列表最好通过示例来学习。在下面的示例中，我们的 Foo(int, int) 构造函数已更新为使用成员初始化列表来初始化 m_x、和 m_y：

#include <iostream>

class Foo
{
private:
    int m_x {};
    int m_y {};

public:
    Foo(int x, int y)
        : m_x { x }, m_y { y } // 这是我们的成员初始化列表
    {
        std::cout << "Foo(" << x << ", " << y << ") constructed\n";
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ")\n";
    }
};

int main()
{
    Foo foo{ 6, 7 };
    foo.print();

    return 0;
}

成员初始化列表在构造函数参数之后定义。它以冒号（:）开头，然后列出每个要初始化的成员及其初始化值，用逗号分隔。这里必须使用直接初始化形式（最好使用花括号，但圆括号也可以）——使用拷贝初始化（带等号）在这里不起作用。还要注意，成员初始化列表不以分号结尾。

该程序产生如下输出：

Foo(6, 7) constructed
Foo(6, 7)

当 foo 被实例化时，初始化列表中的成员将使用指定的初始化值进行初始化。在这种情况下，成员初始化列表初始化 m_x 到 x （即 6），并且 m_y 到 y （即 7）。然后构造函数体运行。

当 print() 成员函数被调用时，可以看到 m_x 仍然有值 6 和 m_y 仍然有值 7。

成员初始化列表格式

C++ 提供了很大的自由度来格式化你的成员初始化列表，因为它不关心你把冒号、逗号或空格放在哪里。

以下样式都是有效的（你在实践中可能会看到所有三种）：

    Foo(int x, int y) : m_x { x }, m_y { y }
    {
    }

    Foo(int x, int y) :
        m_x { x },
        m_y { y }
    {
    }

    Foo(int x, int y)
        : m_x { x }
        , m_y { y }
    {
    }

我们的建议是使用上面的第三种样式：

  • 将冒号放在构造函数名称之后的行上，这样可以清晰地将成员初始化列表与函数原型分开。
  • 缩进你的成员初始化列表，以便更容易看到函数名称。

如果成员初始化列表很短/很简单，所有初始化器可以放在一行：

    Foo(int x, int y)
        : m_x { x }, m_y { y }
    {
    }

否则（或者如果你喜欢），每个成员和初始化器对可以放在单独的行上（以逗号开头以保持对齐）：

    Foo(int x, int y)
        : m_x { x }
        , m_y { y }
    {
    }

成员初始化顺序

因为 C++ 标准是这样规定的，成员初始化列表中的成员总是按照它们在类中定义的顺序进行初始化（而不是按照它们在成员初始化列表中定义的顺序）。

在上面的例子中，因为 m_x 定义在之前 m_y 在类定义中， m_x 将首先被初始化（即使它没有在成员初始化列表中首先列出）。

因为我们直观地期望变量从左到右初始化，这可能导致微妙的错误。考虑以下示例：

#include <algorithm> // for std::max
#include <iostream>

class Foo
{
private:
    int m_x{};
    int m_y{};

public:
    Foo(int x, int y)
        : m_y { std::max(x, y) }, m_x { m_y } // 这一行有问题
    {
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ")\n";
    }
};

int main()
{
    Foo foo { 6, 7 };
    foo.print();

    return 0;
}

在上面的示例中，我们的意图是计算传入的初始化值中较大的一个（通过 std::max(x, y) 然后使用这个值来初始化 m_x 和 m_y。然而，在作者的机器上，打印出以下结果：

Foo(-858993460, 7)

发生了什么？即使 m_y 在成员初始化列表中首先列出，但因为 m_x 在类中首先定义， m_x 首先被初始化。而 m_x 被初始化为 m_y的值，但后者尚未初始化。最后， m_y 被初始化为初始化值中较大的一个。

为了帮助防止此类错误，成员初始化列表中的成员应按照它们在类中定义的顺序列出。一些编译器会在成员以错误顺序初始化时发出警告。

最佳实践

成员初始化列表中的成员变量应按照它们在类中定义的顺序列出。

最好避免使用其他成员的值来初始化成员（如果可能）。这样，即使你在初始化顺序上犯了错误，也不会有问题，因为初始化值之间没有依赖关系。

成员初始化列表 vs 默认成员初始化器

成员可以通过几种不同的方式初始化：

  • 如果成员在成员初始化列表中，则使用该初始化值
  • 否则，如果成员有默认成员初始化器，则使用该初始化值
  • 否则，成员被默认初始化。

这意味着，如果一个成员既有默认成员初始化器，又在构造函数的成员初始化列表中，则成员初始化列表中的值优先。

下面是一个展示所有三种初始化方法的例子：

#include <iostream>

class Foo
{
private:
    int m_x {};    // 默认成员初始化器（将被忽略）
    int m_y { 2 }; // 默认成员初始化器（将被使用）
    int m_z;      // 无初始化器

public:
    Foo(int x)
        : m_x { x } // 成员初始化列表
    {
        std::cout << "Foo constructed\n";
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ", " << m_z << ")\n";
    }
};

int main()
{
    Foo foo { 6 };
    foo.print();

    return 0;
}

在作者的机器上，输出如下：

Foo constructed
Foo(6, 2, -858993460)

该程序的一个示例运行： foo 被构造时，只有 m_x 出现在成员初始化列表中，所以 m_x 首先被初始化为 6。 m_y 不在成员初始化列表中，但它有默认成员初始化器，因此被初始化为 2。 m_z 既不在成员初始化列表中，也没有默认成员初始化器，因此被默认初始化（对于基本类型，这意味着它未被初始化）。因此，当我们打印 m_z的值时，会得到未定义行为。

构造函数函数体

构造函数函数体通常为空。这是因为我们主要使用构造函数进行初始化，而初始化是通过成员初始化列表完成的。如果这就是我们需要做的全部，那么构造函数体中不需要任何语句。

然而，由于构造函数体中的语句在成员初始化列表执行之后执行，我们可以添加语句来执行任何其他所需的设置任务。在上面的例子中，我们打印一些内容到控制台以显示构造函数执行了，但我们也可以做其他事情，比如打开文件或数据库、分配内存等……

新手程序员有时会使用构造函数体来给成员赋值：

#include <iostream>

class Foo
{
private:
    int m_x { 0 };
    int m_y { 1 };

public:
    Foo(int x, int y)
    {
        m_x = x; // 错误：这是赋值，不是初始化
        m_y = y; // 错误：这是赋值，不是初始化
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ")\n";
    }
};

int main()
{
    Foo foo { 6, 7 };
    foo.print();

    return 0;
}

尽管在这个简单例子中会产生预期结果，但在成员需要被初始化的情况下（例如 const 或引用数据成员），赋值将不起作用。

关键提示

一旦成员初始化列表执行完毕，对象就被视为已初始化。一旦函数体执行完毕，对象就被视为已构造。

最佳实践

优先使用成员初始化列表来初始化成员，而不是在构造函数体中赋值。

检测和处理构造函数的无效参数

考虑以下 Fraction 类：

class Fraction
{
private:
    int m_numerator {};
    int m_denominator {};

public:
    Fraction(int numerator, int denominator):
        m_numerator { numerator }, m_denominator { denominator }
    {
    }
};

因为分数是分子除以分母，所以分母不能为零（否则会导致除以零，这在数学上是未定义的）。换句话说，这个类有一个不变量，即 m_denominator 不能是 0。

相关内容

我们在第 14.2 -- 类简介。

那么，当用户尝试创建一个分母为零的 Fraction 时（例如 Fraction f { 1, 0 };)？

在成员初始化列表中，我们检测和处理错误的工具非常有限。我们可以使用条件运算符来检测错误，但然后呢？

class Fraction
{
private:
    int m_numerator {};
    int m_denominator {};

public:
    Fraction(int numerator, int denominator):
        m_numerator { numerator }, m_denominator { denominator != 0.0 ? denominator : ??? } // 我们在这里做什么？
    {
    }
};

我们可以将分母改为一个有效值，但这样用户得到的 Fraction 将不包含他们请求的值，而且我们无法通知他们我们做了意外的事情。因此，我们通常不会尝试在成员初始化列表中进行任何验证——我们只是用传入的值初始化成员，然后尝试处理这种情况。

在构造函数体内，我们可以使用语句，因此我们有更多选项来检测和处理错误。这是一个很好的地方来 assert 或 static_assert 传入的参数在语义上是有效的，但这实际上不会在生产构建中处理运行时错误。

当构造函数无法构造一个语义上有效的对象时，我们说它失败了。

当构造函数失败时（前奏）

在课程 9.4 -- 检测和处理错误，我们介绍了错误处理的主题，并讨论了一些处理函数因错误而无法继续的情况的选项。由于构造函数也是函数，它们也容易遇到同样的问题。

在那节课中，我们提出了处理此类错误的四种策略：

  • 在函数内部解决错误。
  • 将错误传回给调用者处理。
  • 终止程序。
  • 抛出异常。

在大多数情况下，我们没有足够的信息在构造函数内部完全解决这些问题。因此，修复问题通常不是一个选项。

对于非成员函数和非特殊成员函数，我们可以将错误传回给调用者处理。但构造函数没有返回值，因此我们没有好的方法做到这一点。在某些情况下，我们可以添加一个 isValid() 成员函数（或到 bool的重载转换）来返回对象当前是否处于有效状态。例如，一个 isValid() 函数用于 Fraction 会返回 true 当 m_denominator != 0.0。但这意味着调用者必须记得在每次创建新的 Fraction 时实际调用该函数。而且，存在可访问的语义无效对象很可能导致错误。所以，虽然这比没有好，但并不是一个很好的选择。

在某些类型的程序中，我们可以直接终止整个程序，让用户用正确的输入重新运行程序……但在大多数情况下，这是不可接受的。所以可能不行。

剩下的就是抛出异常。异常会完全中止构造过程，这意味着用户永远不会得到一个语义无效的对象。因此，在大多数情况下，抛出异常是这种情况下最好的做法。

关键提示

当构造函数失败（且无法恢复）时，抛出异常通常是最好的做法。我们将在课程 27.5 -- 异常、类和继承 和 27.7 -- 函数 try 块。

中进一步讨论。目前，我们通常假设类对象的构造成功创建了一个语义有效的对象。

进阶读者

如果异常不可行或不可取（要么因为你决定不使用它们，要么因为你还没有学习它们），还有一个合理的选择。与其让用户直接创建类，不如提供一个函数，该函数要么返回类的实例，要么返回表示失败的信息。

在下面的例子中，我们的 createFraction() 函数返回一个 std::optional<Fraction> ，它可选地包含一个有效的 Fraction。如果包含，那么我们可以使用该 Fraction。如果不包含，调用者可以检测到并处理它。我们在课程 std::optional 在课程 12.15 -- std::optional 和友元函数在课程 15.8 -- 友元非成员函数。

#include <iostream>
#include <optional>

class Fraction
{
private:
    int m_numerator { 0 };
    int m_denominator { 1 };

    // 私有构造函数不能被公有调用
    Fraction(int numerator, int denominator):
        m_numerator { numerator }, m_denominator { denominator }
    {
    }

public:
    // 允许此函数访问私有成员
    friend std::optional<Fraction> createFraction(int numerator, int denominator);
};

std::optional<Fraction> createFraction(int numerator, int denominator)
{
    if (denominator == 0)
        return {};
    
    return Fraction{numerator, denominator};
}

int main()
{
    auto f1 { createFraction(0, 1) };
    if (f1)
    {
        std::cout << "Fraction created\n";
    }

    auto f2 { createFraction(0, 0) };
    if (!f2)
    {
        std::cout << "Bad fraction\n";
    }   
}

问题 #1

中介绍。编写一个名为 Ball 的类。Ball 应该有两个私有成员变量，一个用于保存颜色，一个用于保存半径。同时编写一个函数来打印球的颜色和半径。

以下示例程序应该可以编译：

int main()
{
	Ball blue { "blue", 10.0 };
	print(blue);

	Ball red { "red", 12.0 };
	print(red);

	return 0;
}

并产生结果：

Ball(blue, 10)
Ball(red, 12)

显示答案

#include <iostream>
#include <string>
#include <string_view>

class Ball
{
private:
	std::string m_color { "none" };
	double m_radius { 0.0 };

public:
	Ball(std::string_view color, double radius)
		: m_color { color }
		, m_radius { radius }
	{
	}

	const std::string& getColor() const { return m_color; }
	double getRadius() const { return m_radius; }
};

void print(const Ball& ball)
{
    std::cout << "Ball(" << ball.getColor() << ", " << ball.getRadius() << ")\n";
}

int main()
{
	Ball blue { "blue", 10.0 };
	print(blue);

	Ball red { "red", 12.0 };
	print(red);

	return 0;
}

问题 #3

为什么我们将 m_color a std::string 而不是 std::string_view？
