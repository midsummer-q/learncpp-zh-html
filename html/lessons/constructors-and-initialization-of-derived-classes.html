24.4 — 派生类的构造函数与初始化

● 机器译文 课程 24.4 查看英文原文

在过去的两个课程中，我们探讨了C++中继承的一些基础知识以及派生类初始化的顺序。在本课程中，我们将更深入地研究构造函数在派生类初始化中的作用。为此，我们将继续使用上一课程中开发的简单Base和Derived类：

class Base
{
public:
    int m_id {};
 
    Base(int id=0)
        : m_id{ id }
    {
    }
 
    int getId() const { return m_id; }
};
 
class Derived: public Base
{
public:
    double m_cost {};
 
    Derived(double cost=0.0)
        : m_cost{ cost }
    {
    }
 
    double getCost() const { return m_cost; }
};

对于非派生类，构造函数只需关心自己的成员。例如，考虑Base。我们可以像这样创建一个Base对象：

int main()
{
    Base base{ 5 }; // 使用 Base(int) 构造函数

    return 0;
}

以下是base实例化时实际发生的情况：

  1. 为base分配内存
  2. 调用适当的Base构造函数
  3. 成员初始化列表初始化变量
  4. 构造函数体执行
  5. 控制权返回给调用者

这相当直接。对于派生类，情况稍微复杂一些：

int main()
{
    Derived derived{ 1.3 }; // 使用 Derived(double) 构造函数

    return 0;
}

以下是derived实例化时实际发生的情况：

  1. 为derived分配内存（足够容纳Base和Derived部分）
  2. 调用适当的Derived构造函数
  3. 首先使用适当的Base构造函数构造Base对象。如果没有指定基类构造函数，将使用默认构造函数。
  4. 成员初始化列表初始化变量
  5. 构造函数体执行
  6. 控制权返回给调用者

这种情况与非继承情况的唯一真正区别在于，在Derived构造函数能够做任何实质性工作之前，首先调用Base构造函数。Base构造函数设置对象的Base部分，控制权返回给Derived构造函数，然后Derived构造函数完成其工作。

初始化基类成员

我们当前Derived类的一个缺点是，在创建Derived对象时无法初始化m_id。如果我们希望在创建Derived对象时同时设置m_cost（来自Derived部分）和m_id（来自Base部分），该怎么办？

新手程序员通常尝试如下解决这个问题：

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        // 不起作用
        : m_cost{ cost }
        , m_id{ id }
    {
    }

    double getCost() const { return m_cost; }
};

这是一个很好的尝试，并且几乎正确。我们确实需要向构造函数添加另一个参数，否则C++将无法知道我们想要将m_id初始化为哪个值。

然而，C++禁止类在构造函数的成员初始化列表中初始化继承的成员变量。换句话说，成员变量的值只能在属于同一类的构造函数的成员初始化列表中设置。

为什么C++要这样做？答案与const和引用变量有关。考虑如果m_id是const会发生什么。因为const变量必须在创建时用值初始化，基类构造函数必须在变量创建时设置其值。然而，当基类构造函数完成后，派生类构造函数的成员初始化列表随后执行。每个派生类将有机会初始化该变量，可能改变其值！通过将变量的初始化限制在变量所属类的构造函数中，C++确保所有变量只被初始化一次。

最终结果是上述示例不起作用，因为m_id是从Base继承的，只有非继承变量才能在成员初始化列表中初始化。

然而，继承变量仍然可以在构造函数体中使用赋值来改变其值。因此，新手程序员也经常尝试这样：

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : m_cost{ cost }
    {
        m_id = id;
    }

    double getCost() const { return m_cost; }
};

虽然这在这种情况下确实有效，但如果m_id是const或引用，它将不起作用（因为const值和引用必须在构造函数的成员初始化列表中初始化）。而且效率低下，因为m_id被赋值了两次：一次在Base类构造函数的成员初始化列表中，另一次在Derived类构造函数体中。最后，如果Base类在构造期间需要访问这个值呢？它无法访问，因为直到Derived构造函数执行（几乎最后发生）时才设置。

那么，在创建Derived类对象时，如何正确初始化m_id呢？

到目前为止的所有示例中，当我们实例化Derived类对象时，Base类部分都是使用默认的Base构造函数创建的。为什么它总是使用默认的Base构造函数？因为我们从未告诉它做其他事情！

幸运的是，C++允许我们显式选择调用哪个Base类构造函数！为此，只需在派生类的成员初始化列表中添加对Base类构造函数的调用：

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : Base{ id } // 使用值 id 调用 Base(int) 构造函数！
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

现在，当我们执行这段代码时：

#include <iostream>

int main()
{
    Derived derived{ 1.3, 5 }; // 使用 Derived(double, int) 构造函数
    std::cout << "Id: " << derived.getId() << '\n';
    std::cout << "Cost: " << derived.getCost() << '\n';

    return 0;
}

基类构造函数Base(int)将用于将m_id初始化为5，派生类构造函数将用于将m_cost初始化为1.3！

因此，程序将打印：

Id: 5
Cost: 1.3

更详细地说，以下是发生的情况：

  1. 为derived分配内存。
  2. 调用Derived(double, int)构造函数，其中cost = 1.3，id = 5。
  3. 编译器检查我们是否要求特定的Base类构造函数。我们确实要求了！因此它调用Base(int)并传入id = 5。
  4. 基类构造函数成员初始化列表将m_id设置为5。
  5. 基类构造函数体执行，什么也不做。
  6. 基类构造函数返回。
  7. 派生类构造函数成员初始化列表将m_cost设置为1.3。
  8. 派生类构造函数体执行，什么也不做。
  9. 派生类构造函数返回。

这看起来可能有些复杂，但实际上非常简单。所有发生的事情就是派生构造函数调用特定的基类构造函数来初始化对象的基类部分。因为 m_id 存在于对象的基类部分，所以基类构造函数是唯一能够初始化该值的构造函数。

注意，基类构造函数在派生构造函数成员初始化列表中的位置并不重要——它总是会先执行。

现在我们可以将成员设为私有

既然你已经知道如何初始化基类成员，就没有必要再让我们的成员变量保持公有。我们将成员变量再次设为私有，正如它们应该的那样。

快速回顾一下，公有成员可以被任何人访问。私有成员只能被同一个类的成员函数访问。注意，这意味着派生类不能直接访问基类的私有成员！派生类需要使用访问函数来访问基类的私有成员。

0, 1, 2测试

#include <iostream>

class Base
{
private: // 我们的成员现在是私有的
    int m_id {};
 
public:
    Base(int id=0)
        : m_id{ id }
    {
    }
 
    int getId() const { return m_id; }
};

class Derived: public Base
{
private: // 我们的成员现在是私有的
    double m_cost;

public:
    Derived(double cost=0.0, int id=0)
        : Base{ id } // 使用值 id 调用 Base(int) 构造函数！
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

int main()
{
    Derived derived{ 1.3, 5 }; // 使用 Derived(double, int) 构造函数
    std::cout << "Id: " << derived.getId() << '\n';
    std::cout << "Cost: " << derived.getCost() << '\n';

    return 0;
}

在上面的代码中，我们将 m_id 和 m_cost 设为私有。这没问题，因为我们使用相关的构造函数来初始化它们，并使用公有访问器来获取值。

输出结果如预期：

Id: 5
Cost: 1.3

另一个示例

让我们看看之前使用过的另一对类：

#include <string>
#include <string_view>

class Person
{
public:
    std::string m_name;
    int m_age {};

    Person(std::string_view name = "", int age = 0)
        : m_name{ name }, m_age{ age }
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }
};

// BaseballPlayer 公有继承 Person
class BaseballPlayer : public Person
{
public:
    double m_battingAverage {};
    int m_homeRuns {};

    BaseballPlayer(double battingAverage = 0.0, int homeRuns = 0)
       : m_battingAverage{ battingAverage },
         m_homeRuns{ homeRuns }
    {
    }
};

正如我们之前编写的，BaseballPlayer 只初始化自己的成员，并没有指定要使用的 Person 构造函数。这意味着我们创建的每个 BaseballPlayer 都将使用默认的 Person 构造函数，该构造函数会将姓名初始化为空，年龄初始化为 0。因为给我们的 BaseballPlayer 在创建时赋予姓名和年龄是有意义的，所以我们应该修改这个构造函数来添加这些参数。

以下是更新后的使用私有成员的类，其中 BaseballPlayer 类调用适当的 Person 构造函数来初始化继承的 Person 成员变量：

#include <iostream>
#include <string>
#include <string_view>

class Person
{
private:
    std::string m_name;
    int m_age {};

public:
    Person(std::string_view name = "", int age = 0)
        : m_name{ name }, m_age{ age }
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }

};
// BaseballPlayer 公有继承 Person
class BaseballPlayer : public Person
{
private:
    double m_battingAverage {};
    int m_homeRuns {};

public:
    BaseballPlayer(std::string_view name = "", int age = 0,
        double battingAverage = 0.0, int homeRuns = 0)
        : Person{ name, age } // 调用 Person(std::string_view, int) 来初始化这些字段
        , m_battingAverage{ battingAverage }, m_homeRuns{ homeRuns }
    {
    }

    double getBattingAverage() const { return m_battingAverage; }
    int getHomeRuns() const { return m_homeRuns; }
};

现在我们可以这样创建棒球运动员：

#include <iostream>

int main()
{
    BaseballPlayer pedro{ "Pedro Cerrano", 32, 0.342, 42 };

    std::cout << pedro.getName() << '\n';
    std::cout << pedro.getAge() << '\n';
    std::cout << pedro.getBattingAverage() << '\n';
    std::cout << pedro.getHomeRuns() << '\n';

    return 0;
}

这会输出：

Pedro Cerrano
32
0.342
42

如你所见，基类中的姓名和年龄被正确初始化，派生类中的本垒打数和击球率也是如此。

继承链

继承链中的类以完全相同的方式工作。

#include <iostream>

class A
{
public:
    A(int a)
    {
        std::cout << "A: " << a << '\n';
    }
};

class B: public A
{
public:
    B(int a, double b)
    : A{ a }
    {
        std::cout << "B: " << b << '\n';
    }
};

class C: public B
{
public:
    C(int a, double b, char c)
    : B{ a, b }
    {
        std::cout << "C: " << c << '\n';
    }
};

int main()
{
    C c{ 5, 4.3, 'R' };

    return 0;
}

在这个例子中，类 C 派生自类 B，而类 B 派生自类 A。那么当我们实例化类 C 的对象时会发生什么？

首先，main() 调用 C(int, double, char)。C 构造函数调用 B(int, double)。B 构造函数调用 A(int)。因为 A 不从任何类继承，所以这是我们将要构造的第一个类。A 被构造，打印值 5，然后将控制权返回给 B。B 被构造，打印值 4.3，然后将控制权返回给 C。C 被构造，打印值 'R'，然后将控制权返回给 main()。完成！

因此，该程序打印出：

A: 5
B: 4.3
C: R

值得一提的是，构造函数只能调用其直接父类/基类的构造函数。因此，C 构造函数不能直接调用或传递参数给 A 构造函数。C 构造函数只能调用 B 构造函数（而 B 构造函数负责调用 A 构造函数）。

析构函数

当派生类被销毁时，每个析构函数按照构造顺序的 相反 顺序被调用。在上面的例子中，当 c 被销毁时，首先调用 C 析构函数，然后调用 B 析构函数，最后调用 A 析构函数。

警告

如果你的基类有虚函数，那么你的析构函数也应该是虚的，否则在某些情况下会导致未定义行为。我们在课程 25.4 -- 虚析构函数、虚赋值和覆盖虚函数。

总结

在构造派生类时，派生类构造函数负责决定调用哪个基类构造函数。如果没有指定基类构造函数，将使用默认基类构造函数。在这种情况下，如果找不到（或无法默认创建）默认基类构造函数，编译器将显示错误。然后类按照从最基类到最派生类的顺序构造。

至此，你已经对 C++ 继承有了足够的了解，可以创建自己的继承类了！

  1. 让我们实现我们在继承介绍中讨论过的 Fruit 示例。创建一个 Fruit 基类，包含两个私有成员：名称（std::string）和颜色（std::string）。创建一个继承自 Fruit 的 Apple 类。Apple 应该有一个额外的私有成员：纤维（double）。创建一个也继承自 Fruit 的 Banana 类。Banana 没有额外的成员。

以下程序应能运行：

#include <iostream>

int main()
{
	const Apple a{ "Red delicious", "red", 4.2 };
	std::cout << a << '\n';

	const Banana b{ "Cavendish", "yellow" };
	std::cout << b << '\n';

	return 0;
}

并打印以下内容：

Apple(Red delicious, red, 4.2)
Banana(Cavendish, yellow)

提示：因为 a 和 b 是 const，所以你需要留意 const。确保你的参数和函数适当地为 const。

显示答案

#include <iostream>
#include <string>
#include <string_view>

class Fruit
{
private:
	std::string m_name;
	std::string m_color;

public:
	Fruit(std::string_view name, std::string_view color)
		: m_name{ name }, m_color{ color }
	{
	}

	const std::string& getName() const { return m_name; }
	const std::string& getColor() const { return m_color; }

};

class Apple : public Fruit
{
private:
	double m_fiber;

public:
	Apple(std::string_view name, std::string_view color, double fiber)
		:Fruit{ name, color },
		m_fiber{ fiber }
	{
	}

	double getFiber() const { return m_fiber; }

};

std::ostream& operator<<(std::ostream& out, const Apple& a)
{
	out << "Apple(" << a.getName() << ", " << a.getColor() << ", " << a.getFiber() << ')';
	return out;
}

class Banana : public Fruit
{
public:
	Banana(std::string_view name, std::string_view color)
		:Fruit{ name, color }
	{
	}
};

std::ostream& operator<<(std::ostream& out, const Banana& b)
{
	out << "Banana(" << b.getName() << ", " << b.getColor() << ')';
	return out;
}

int main()
{
	const Apple a{ "Red delicious", "red", 4.2 };
	std::cout << a << '\n';

	const Banana b{ "Cavendish", "yellow" };
	std::cout << b << '\n';

	return 0;
}
