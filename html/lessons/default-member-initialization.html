13.9 — 默认成员初始化

● 机器译文 课程 13.9 查看英文原文

当我们定义结构体（或类）类型时，可以为每个成员提供默认初始化值作为类型定义的一部分。对于未标记为 static的成员，此过程有时称为 非静态成员初始化。该初始化值称为 默认成员初始化器。

相关内容

我们在课程 15.6 -- 静态成员变量。

下面是一个示例：

struct Something
{
    int x;       // 无初始化值（不好）
    int y {};    // 默认值初始化
    int z { 2 }; // 显式默认值
};

int main()
{
    Something s1; // s1.x 未初始化，s1.y 为 0，s1.z 为 2

    return 0;
}

中介绍了静态成员和静态成员初始化。在上面的定义中， Something， x 没有默认值， y 默认进行值初始化，而 z 具有默认值 2。如果用户在实例化类型为 Something。

的对象时未提供显式初始化值，则将使用这些默认成员初始化值。我们的 s1 对象没有初始化器，因此 s1 的成员被初始化为其默认值。 s1.x 没有默认初始化器，因此保持未初始化。 s1.y 默认进行值初始化，因此获得值 0。而 s1.z 被初始化为值 2。

请注意，即使我们没有为 s1.z提供显式初始化器，由于提供了默认成员初始化器，它也被初始化为非零值。

关键提示

使用默认成员初始化器（或我们稍后将介绍的其他机制），结构体和类可以在没有提供显式初始化器的情况下自我初始化！

进阶读者

CTAD（我们在课程 13.14 -- 类模板参数推导（CTAD）和推导指南中介绍）不能在非静态成员初始化中使用。

显式初始化值优先于默认值

列表初始化器中的显式值始终优先于默认成员初始化值。

struct Something
{
    int x;       // 无默认初始化值（不好）
    int y {};    // 默认值初始化
    int z { 2 }; // 显式默认值
};

int main()
{
    Something s2 { 5, 6, 7 }; // 为 s2.x、s2.y 和 s2.z 使用显式初始化器（不使用默认值）
   
    return 0;
}

在上述情况下， s2 为每个成员提供了显式初始化值，因此根本不使用默认成员初始化值。这意味着 s2.x， s2.y 和 s2.z 被初始化为值 5， 6、和 7

存在默认值时初始化列表中缺少初始化器

在前一课（13.8 -- 结构体聚合初始化）我们指出，如果聚合被初始化但初始化值的数量少于成员数量，则所有剩余成员将进行值初始化。但是，如果为给定成员提供了默认成员初始化器，则将使用该默认成员初始化器。

struct Something
{
    int x;       // 无默认初始化值（不好）
    int y {};    // 默认值初始化
    int z { 2 }; // 显式默认值
};

int main()
{
    Something s3 {}; // 值初始化 s3.x，对 s3.y 和 s3.z 使用默认值
   
    return 0;
}

在上述情况下， s3 使用空列表进行列表初始化，因此所有初始化器都缺失。这意味着如果存在默认成员初始化器，则使用它，否则进行值初始化。因此， s3.x （没有默认成员初始化器）被值初始化为 0， s3.y 默认进行值初始化为 0、和 s3.z 默认值为 2。

回顾初始化可能性

如果聚合使用初始化列表定义：

  • 如果存在显式初始化值，则使用该显式值。
  • 如果缺少初始化器且存在默认成员初始化器，则使用默认值。
  • 如果缺少初始化器且没有默认成员初始化器，则进行值初始化。

如果聚合体定义时没有初始化列表：

  • 如果存在默认成员初始化器，则使用默认值。
  • 如果不存在默认成员初始化器，则该成员保持未初始化。

成员总是按照声明顺序初始化。

以下示例总结了所有可能性：

struct Something
{
    int x;       // 无默认初始化值（不好）
    int y {};    // 默认值初始化
    int z { 2 }; // 显式默认值
};

int main()
{
    Something s1;             // 无初始化列表：s1.x 未初始化，s1.y 和 s1.z 使用默认值
    Something s2 { 5, 6, 7 }; // 显式初始化器：s2.x、s2.y 和 s2.z 使用显式值（不使用默认值）
    Something s3 {};          // 缺少初始化器：s3.x 被值初始化，s3.y 和 s3.z 使用默认值
   
    return 0;
}

我们需要警惕的情况是 s1.x。因为 s1 没有初始化列表且 x 没有默认成员初始化器， s1.x 保持未初始化（这很糟糕，因为我们总是应该初始化变量）。

始终为成员提供默认值

为了避免未初始化成员的可能性，只需确保每个成员都有一个默认值（可以是显式默认值，也可以是一对空花括号）。这样，无论我们是否提供初始化列表，我们的成员都会被初始化为某个值。

考虑以下结构体，其所有成员都有默认值：

struct Fraction
{
	int numerator { }; // 这里我们应该使用 { 0 }，但为了示例，我们改用值初始化
	int denominator { 1 };
};

int main()
{
	Fraction f1;          // f1.numerator 值初始化为 0，f1.denominator 默认初始化为 1
	Fraction f2 {};       // f2.numerator 值初始化为 0，f2.denominator 默认初始化为 1
	Fraction f3 { 6 };    // f3.numerator 初始化为 6，f3.denominator 默认初始化为 1
	Fraction f4 { 5, 8 }; // f4.numerator 初始化为 5，f4.denominator 初始化为 8

	return 0;
}

在所有情况下，我们的成员都被初始化为值。

最佳实践

为所有成员提供默认值。这确保即使变量定义不包含初始化列表，你的成员也会被初始化。

聚合体的默认初始化与值初始化

回顾上面示例中的两行：

	Fraction f1;          // f1.numerator 值初始化为 0，f1.denominator 默认初始化为 1
	Fraction f2 {};       // f2.numerator 值初始化为 0，f2.denominator 默认初始化为 1

你会注意到 f1 是默认初始化，而 f2 是值初始化，但结果相同（numerator 被初始化为 0 和 denominator 被初始化为 1）。那么我们应该优先选择哪一种呢？

值初始化的情况（f2）更安全，因为它会确保任何没有默认值的成员被值初始化（尽管我们应该始终为成员提供默认值，但这可以防止遗漏的情况）。

优先选择值初始化还有一个好处——它与我们初始化其他类型对象的方式一致。一致性有助于防止错误。

最佳实践

对于聚合体，优先选择值初始化（使用空花括号初始化器）而不是默认初始化（不使用花括号）。

尽管如此，程序员对类类型使用默认初始化而不是值初始化的情况并不少见。这 partly 是由于历史原因（值初始化直到 C++11 才引入），partly 是因为有一种特殊情况（对于非聚合体），默认初始化可能比值初始化更高效（我们在课程 14.11 -- 默认构造函数和默认参数)。

中讨论这种情况）。因此，在本教程中，我们不会强制要求对结构体和类使用值初始化，但我们强烈推荐这样做。
