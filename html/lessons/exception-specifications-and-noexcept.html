27.9 — 异常规范与noexcept

● 机器译文 课程 27.9 查看英文原文

（感谢读者Koe为本课提供初稿！）

观察一个典型的函数声明，我们无法判断该函数是否会抛出异常：

int doSomething(); // 这个函数能否抛出异常？

在上面的例子中， doSomething() 会抛出异常吗？这并不清楚。但在某些上下文中，答案很重要。在课程 27.8 -- 异常的危险与缺点中，我们描述了在栈展开期间，从析构函数中抛出的异常会导致程序终止。如果 doSomething() 可能抛出异常，那么从析构函数（或任何不希望抛出异常的地方）调用它是有风险的。尽管我们可以让析构函数处理 doSomething() 抛出的异常（这样这些异常就不会传播出析构函数），但我们必须记住这样做，并且必须确保覆盖所有可能抛出的异常类型。

虽然注释可能有助于说明函数是否抛出异常（以及抛出何种异常），但文档可能过时，且编译器不会强制执行注释。

异常规范 是一种语言机制，最初设计用于在函数规范中记录函数可能抛出的异常类型。虽然大多数异常规范现在已被弃用或移除，但一个有用的异常规范被添加作为替代，我们将在本课中介绍。

noexcept说明符

在C++中，所有函数都被分类为 非抛出 或 潜在抛出。一个 非抛出函数 是承诺不会向调用者抛出可见异常的函数。 潜在抛出函数 可能向调用者抛出可见异常。

要将函数定义为非抛出，我们可以使用 noexcept说明符。为此，我们在函数声明中使用 noexcept 关键字，放在函数参数列表的右侧：

void doSomething() noexcept; // 此函数被指定为不抛出

注意 noexcept 实际上并不阻止函数抛出异常或调用其他潜在抛出函数。只要noexcept函数在内部捕获并处理这些异常，并且这些异常不会离开noexcept函数，这是允许的。

如果未处理的异常将离开noexcept函数， std::terminate 将被调用（即使存在某个异常处理程序可以在栈上某处处理此类异常）。如果 std::terminate 在noexcept函数内部被调用，栈展开可能发生也可能不发生（取决于实现和优化），这意味着在终止之前，你的对象可能无法正确析构。

关键提示

noexcept函数承诺不向调用者抛出可见异常，这是一个契约性承诺，而非编译器强制执行的承诺。因此，虽然调用noexcept函数应该是安全的，但noexcept函数中任何导致契约被破坏的异常处理错误都会导致程序终止！这不应该发生，但错误也不应该发生。

因此，noexcept函数最好不要涉及异常，也不要调用可能引发异常的潜在抛出函数。如果一开始就不可能引发异常，那么noexcept函数就不会有异常处理错误！

就像仅返回值不同的函数不能重载一样，仅异常规范不同的函数也不能重载。

说明noexcept函数和异常的行为

以下程序说明了各种情况下noexcept函数和异常的行为：

// 感谢读者 yellowEmu 提供此程序的初稿
#include <iostream>

class Doomed
{
public:
    ~Doomed()
    {
        std::cout << "Doomed destructed\n";
    }
};

void thrower()
{
    std::cout << "Throwing exception\n";
    throw 1;
}

void pt()
{
    std::cout << "pt (potentally throwing) called\n";
    //此对象将在栈展开期间被销毁（如果发生）
    Doomed doomed{};
    thrower();
    std::cout << "This never prints\n";
}

void nt() noexcept
{
    std::cout << "nt (noexcept) called\n";
    //此对象将在栈展开期间被销毁（如果发生）
    Doomed doomed{};
    thrower();
    std::cout << "this never prints\n";
}

void tester(int c) noexcept
{
    std::cout << "tester (noexcept) case " << c << " called\n";
    try
    {
        (c == 1) ? pt() : nt();
    }
    catch (...)
    {
        std::cout << "tester caught exception\n";
    }
}

int main()
{
    std::cout << std::unitbuf; // 每次插入后刷新缓冲区
    std::cout << std::boolalpha; // 将布尔值打印为 true/false
    tester(1);
    std::cout << "Test successful\n\n";
    tester(2);
    std::cout << "Test successful\n";

    return 0;
}

在作者的机器上，该程序打印了：

tester (noexcept) case 1 called
pt (potentially throwing) called
Throwing exception
Doomed destructed
tester caught exception
Test successful

tester (noexcept) case 2 called
nt (noexcept) called
throwing exception
terminate called after throwing an instance of 'int'

然后程序中止。

让我们更详细地探讨这里发生了什么。注意 tester 是一个noexcept函数，因此承诺不向调用者暴露任何异常（main)。

第一种情况说明noexcept函数可以调用潜在抛出函数，甚至处理这些函数抛出的任何异常。首先， tester(1) 被调用，它调用潜在抛出函数 pt ，该函数调用 thrower，这会抛出一个异常。该异常的第一个处理程序位于 tester，因此异常会展开栈（在此过程中销毁局部变量 doomed ），异常在 tester。因为 tester 内被捕获并处理。由于main没有将此异常暴露给调用者（ main。

），因此没有违反 noexcept，控制权返回给 tester(2) 第二个案例说明了当 noexcept 函数试图将异常传递回其调用者时会发生什么。首先， nt，该函数调用 thrower，这会抛出一个异常。该异常的第一个处理程序位于 tester的事实。然而， nt 被调用，它调用了非抛出函数 tester是 noexcept 的，并且要到达 nt中的处理程序，异常必须传播到 nt的调用者。这违反了 std::terminate 的 noexcept 规定，因此 doomed 被调用，我们的程序立即终止。在作者的机器上，栈没有被展开（如

未被销毁所示）。

浮点类型的 noexcept noexcept 说明符带有一个可选的布尔参数。 noexcept(true) 等价于 noexcept，表示函数是非抛出的。 noexcept(false) 表示函数是可能抛出的。这些参数通常仅在模板函数中使用，以便模板函数可以根据某个参数化值动态地创建为非抛出或可能抛出。

哪些函数是非抛出和可能抛出的

隐式非抛出的函数：

  • 析构函数

对于隐式声明或默认的函数，默认是非抛出的：

  • 构造函数：默认、拷贝、移动
  • 赋值操作：拷贝、移动
  • 比较运算符（自 C++20 起）

然而，如果这些函数中的任何一个（显式或隐式）调用了另一个可能抛出的函数，那么列出的函数也将被视为可能抛出。例如，如果一个类有一个数据成员具有可能抛出的构造函数，那么该类的构造函数也将被视为可能抛出。再如，如果拷贝赋值运算符调用了一个可能抛出的赋值运算符，那么拷贝赋值也将是可能抛出的。

可能抛出的函数（如果不是隐式声明或默认的）：

  • 普通函数
  • 用户定义的构造函数
  • 用户定义的运算符

noexcept 运算符

noexcept 运算符也可以在表达式中使用。它接受一个表达式作为参数，并返回 true 或 false ，取决于编译器认为它是否会抛出异常。noexcept 运算符在编译时静态检查，并不实际求值输入表达式。

void foo() {throw -1;}
void boo() {};
void goo() noexcept {};
struct S{};

constexpr bool b1{ noexcept(5 + 3) }; // true；整数是不抛出的
constexpr bool b2{ noexcept(foo()) }; // false；foo() 抛出异常
constexpr bool b3{ noexcept(boo()) }; // false；boo() 隐式为 noexcept(false)
constexpr bool b4{ noexcept(goo()) }; // true；goo() 显式为 noexcept(true)
constexpr bool b5{ noexcept(S{}) };   // true；结构体的默认构造函数默认是 noexcept

noexcept 运算符可用于根据函数是否可能抛出异常来有条件地执行代码。这对于满足某些 异常安全保证是必需的，我们将在下一节中讨论。

异常安全保证

一种 异常安全保证 是一个关于函数或类在发生异常时如何行为的契约性指南。有四个级别的异常安全保证：

  • 无保证——如果抛出异常，不保证会发生什么（例如，类可能处于不可用状态）
  • 基本保证——如果抛出异常，不会泄漏内存，对象仍然可用，但程序可能处于修改后的状态。
  • 强保证——如果抛出异常，不会泄漏内存，程序状态不会改变。这意味着函数必须要么完全成功，要么在失败时没有副作用。如果失败发生在任何修改之前，这很容易实现，但也可以通过回滚所有更改使程序恢复到失败前的状态来实现。
  • 不抛出/不失败保证——函数将始终成功（不失败）或失败但不向调用者抛出异常（不抛出）。异常可以在内部抛出，只要不暴露给外部。 noexcept 说明符对应此级别的异常安全保证。

让我们更详细地看看不抛出/不失败保证：

不抛出保证：如果函数失败，它不会抛出异常。相反，它会返回一个错误码或忽略问题。在栈展开期间处理异常时，需要不抛出保证；例如，所有析构函数都应该有不抛出保证（以及这些析构函数调用的任何函数）。应该是不抛出的代码示例：

  • 析构函数和内存释放/清理函数
  • 高级别不抛出函数需要调用的函数

不失败保证：函数将始终成功完成其尝试的操作（因此永远不需要抛出异常，因此不失败是不抛出的稍强形式）。应该是不失败的代码示例：

  • 移动构造函数和移动赋值（移动语义，在 第 22 章)
  • 交换函数
  • 容器上的 clear/erase/reset 函数
  • std::unique_ptr 上的操作（也在 第 22 章)
  • 高级别不失败函数需要调用的函数

何时使用 noexcept

仅仅因为你的代码没有显式抛出任何异常，并不意味着你应该开始到处使用 noexcept 默认情况下，大多数函数都是潜在抛出的，所以如果你的函数调用其他函数，很可能它调用了一个潜在抛出的函数，因此它本身也是潜在抛出的。

有几个很好的理由将函数标记为非抛出：

  • 非抛出函数可以安全地从非异常安全的函数中调用，例如析构函数
  • noexcept 函数可以使编译器执行一些否则不可用的优化。因为 noexcept 函数不能在函数外抛出异常，编译器不必担心保持运行时栈处于可展开状态，这可以使其生成更快的代码。
  • 有一些重要的情况，知道一个函数是 noexcept 允许我们在自己的代码中产生更高效的实现：标准库容器（例如 std::vector）是 noexcept 感知的，并将使用 noexcept 运算符来决定在某些地方使用 move semantics （更快）还是 copy semantics （更慢）。我们在 第 22 章中介绍移动语义，并在课程 27.10 -- std::move_if_noexcept。

中介绍这种优化。 noexcept 标准库的策略是仅在 必须不 抛出或失败的函数上使用。潜在抛出但实际上不抛出异常（由于实现）的函数通常不会被标记为 noexcept。

对于你自己的代码，始终将以下内容标记为 noexcept：

  • 移动构造函数
  • 移动赋值运算符
  • 交换函数

对于你的代码，考虑将以下内容标记为 noexcept：

  • 你想要表达不抛出或不失败保证的函数（例如，记录它们可以安全地从析构函数或其他 noexcept 函数中调用）
  • 不抛出的拷贝构造函数和拷贝赋值运算符（以利用优化）。
  • 析构函数。只要所有成员都有 noexcept 析构函数，析构函数就是隐式 noexcept 的

最佳实践

始终使移动构造函数、移动赋值和交换函数为 noexcept。

尽可能使拷贝构造函数和拷贝赋值运算符为 noexcept

使用 noexcept 在其他函数上使用以表达不失败或不抛出保证。

最佳实践

如果你不确定一个函数是否应该有不失败/不抛出保证，宁可谨慎，不要将其标记为 noexcept。撤销使用 noexcept 的决定违反了函数对用户行为做出的接口承诺，并可能破坏现有代码。通过后来向原本不是 noexcept 的函数添加 noexcept 来加强保证被认为是安全的。

动态异常规范

可选阅读

在 C++11 之前，直到 C++17， 动态异常规范 被用来替代 noexcept。这些 动态异常规范 语法使用 throw 关键字来列出函数可能直接或间接抛出的异常类型：

int doSomething() throw(); // 不抛出异常
int doSomething() throw(std::out_of_range, int*); // 可能抛出 std::out_of_range 或指向整数的指针
int doSomething() throw(...); // 可能抛出任何东西

由于编译器实现不完整、与模板函数不兼容、对它们工作原理的普遍误解以及标准库大多不使用它们等因素，动态异常规范在 C++11 中被弃用，并在 C++17 和 C++20 中从语言中移除。参见 本文 了解更多背景。
