7.7 — 外部链接与变量前向声明

● 机器译文 课程 7.7 查看英文原文

在上一课（7.6 -- 内部链接）中，我们讨论了 internal linkage 如何将标识符的使用限制在单个文件中。在本课中，我们将探讨 external linkage。

具有 外部链接 的概念。具有外部链接的标识符既可以在其定义的文件中看到和使用，也可以从其他代码文件中通过前向声明看到和使用。从这个意义上说，具有外部链接的标识符是真正的“全局”标识符，因为它们可以在程序的任何地方使用！

关键提示

具有外部链接的标识符对链接器可见。这使得链接器能够做两件事：

  • 将一个翻译单元中使用的标识符与另一个翻译单元中的适当定义连接起来。
  • 去重内联标识符，只保留一个规范定义。我们在第 7.9 -- 内联函数和变量。

课中讨论了内联变量和函数。

在课程 2.8 -- 包含多个代码文件的程序中，你了解到可以从一个文件调用在另一个文件中定义的函数。这是因为函数默认具有外部链接。

为了调用在另一个文件中定义的函数，你必须在任何希望使用该函数的其他文件中放置一个 forward declaration 前向声明。前向声明告诉编译器函数的存在，链接器将函数调用连接到实际的函数定义。

下面是一个示例：

a.cpp：

#include <iostream>

void sayHi() // 此函数具有外部链接性，可以被其他文件看到
{
    std::cout << "Hi!\n";
}

main.cpp:

void sayHi(); // 函数 sayHi 的前向声明，使 sayHi 在此文件中可访问

int main()
{
    sayHi(); // 调用定义在另一个文件中的函数，链接器会将此调用连接到函数定义

    return 0;
}

上面的程序打印：

Hi!

在上面的例子中，函数 sayHi() 在 main.cpp 的前向声明允许 main.cpp 访问在 sayHi() 中定义的 a.cpp函数。前向声明满足了编译器的要求，链接器能够将函数调用链接到函数定义。

如果函数 sayHi() 具有内部链接，链接器将无法将函数调用连接到函数定义，从而导致链接错误。

具有外部链接的全局变量

具有外部链接的全局变量有时被称为 外部变量。要使全局变量具有外部链接（从而可以被其他文件访问），我们可以使用 extern 关键字：

int g_x { 2 }; // 非常量全局变量默认是外部的（无需使用 extern）

extern const int g_y { 3 }; // const 全局变量可以定义为 extern，使其成为外部变量
extern constexpr int g_z { 3 }; // constexpr 全局变量可以定义为 extern，使其具有外部链接（但这几乎没用，请参阅下一节中的警告）

int main()
{
    return 0;
}

非 const 全局变量默认是外部的，所以我们不需要将它们标记为 extern。

通过 extern 关键字进行变量前向声明

要实际使用在另一个文件中定义的外部全局变量，你还必须在任何希望使用该变量的其他文件中放置一个 forward declaration 前向声明。对于变量，创建前向声明也是通过 extern 关键字（不带初始化值）完成的。

下面是一个使用变量前向声明的例子：

main.cpp:

#include <iostream>

extern int g_x;       // 这个 extern 是一个名为 g_x 的变量的前向声明，该变量在其他地方定义
extern const int g_y; // 这个 extern 是一个名为 g_y 的 const 变量的前向声明，该变量在其他地方定义

int main()
{
    std::cout << g_x << ' ' << g_y << '\n'; // 打印 2 3

    return 0;
}

以下是这些变量的定义：

a.cpp：

// 全局变量定义
int g_x { 2 };              // 非常量全局变量默认具有外部链接
extern const int g_y { 3 }; // 这个 extern 赋予 g_y 外部链接

在上面的例子中， a.cpp 和 main.cpp 都引用同一个名为 g_x的全局变量。所以尽管 g_x 是在 a.cpp中定义和初始化的，我们仍然可以通过 main.cpp 的前向声明在 g_x。

中使用它的值。 extern 注意， extern 关键字在不同上下文中具有不同的含义。在某些上下文中， extern 意思是“这是一个外部变量的前向声明，该变量在其他地方定义”。是的，这令人困惑，因此我们在课程中总结了所有这些用法 7.12 -- 作用域、持续时间和链接总结。

警告

如果你想定义一个未初始化的非 const 全局变量，不要使用 extern 关键字，否则 C++ 会认为你试图对该变量进行前向声明。

警告

尽管 constexpr 变量可以通过 extern 关键字赋予外部链接，但它们不能作为 constexpr 进行前向声明。这是因为编译器需要在编译时知道 constexpr 变量的值。如果该值在其他文件中定义，编译器无法看到该文件中定义的值。

但是，你可以将 constexpr 变量前向声明为 const，编译器会将其视为运行时 const。这并不特别有用。

注意，函数前向声明不需要 extern 关键字——编译器能够根据你是否提供函数体来判断你是在定义新函数还是进行前向声明。变量前向声明 do 需要 extern 关键字来帮助区分未初始化变量定义和变量前向声明（它们看起来相同）：

// 非常量 
int g_x;        // 变量定义（无初始化器）
int g_x { 1 };  // 变量定义（有初始化器）
extern int g_x; // 前向声明（无初始化器）

// 常量
extern const int g_y { 1 }; // 变量定义（常量需要初始化器）
extern const int g_y;       // 前向声明（无初始化器）

避免使用 extern 在带有初始化器的非常量全局变量上

以下两行在语义上是等价的：

int g_x { 1 };        // 默认是 extern
extern int g_x { 1 }; // 显式 extern（可能导致编译器警告）

然而，你的编译器可能会对后一条语句发出警告，尽管它在技术上是有效的。

还记得我们说过编译器有权对它们认为可疑的内容发出诊断吗？这就是其中一种情况。按照惯例， extern 应用于非常量变量时，表示我们希望进行前向声明。然而，添加初始化器会使该语句变成定义。编译器在告诉你有些不对劲。要修正它，要么移除初始化器（如果你打算进行前向声明），要么移除 extern （如果你打算进行定义）。

最佳实践

仅将 extern 用于全局变量的前向声明或常量全局变量的定义。
不要使用 extern 用于非常量全局变量的定义（它们隐式地 extern)。

快速总结

// 全局变量前向声明（extern 且无初始化器）：
extern int g_y;                 // 非常量全局变量的前向声明
extern const int g_y;           // 常量全局变量的前向声明
extern constexpr int g_y;       // 不允许：constexpr 变量不能前向声明

// 外部全局变量定义（无 extern）
int g_x;                        // 定义未初始化的外部全局变量（默认零初始化）
int g_x { 1 };                  // 定义已初始化的外部全局变量

// 外部 const 全局变量定义（带初始化器的 extern）
extern const int g_x { 2 };     // 定义已初始化的 const 外部全局变量
extern constexpr int g_x { 3 }; // 定义已初始化的 constexpr 外部全局变量

我们在课程中提供了全面的总结 7.12 -- 作用域、持续时间和链接总结。

小测验时间

问题 #1

变量的作用域、生存期和链接性之间有什么区别？全局变量具有什么样的作用域、生存期和链接性？

显示答案

作用域决定变量在何处可访问。生存期决定变量何时创建和销毁。链接性决定变量是否可以导出到另一个文件。

全局变量具有全局作用域（也称为文件作用域），这意味着它们可以从声明点开始到声明它们的文件末尾被访问。

全局变量具有静态生存期，这意味着它们在程序启动时创建，在程序结束时销毁。

全局变量可以具有内部或外部链接性，分别通过 static 和 extern 关键字实现。
