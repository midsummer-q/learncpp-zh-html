15.8 — 友元非成员函数

● 机器译文 课程 15.8 查看英文原文

在本章和上一章的大部分内容中，我们一直在宣扬访问控制的好处，它提供了一种机制来控制谁能访问类的各个成员。私有成员只能由类的其他成员访问，而公有成员可以被所有人访问。在课程 14.6 -- 访问函数中，我们讨论了保持数据私有并为非成员创建公共接口的好处。

然而，有些情况下这种安排要么不够充分，要么不够理想。

例如，考虑一个专注于管理某些数据集的存储类。现在假设你还想显示这些数据，但处理显示的代码会有很多选项，因此很复杂。你可以将存储管理函数和显示管理函数都放在同一个类中，但这会使事情变得混乱，并导致接口复杂。你也可以将它们分开：存储类管理存储，而另一个显示类管理所有显示功能。这创建了很好的职责分离。但显示类将无法访问存储类的私有成员，可能无法完成其工作。

或者，在某些情况下，从语法上讲，我们可能更倾向于使用非成员函数而不是成员函数（我们将在下面展示一个例子）。这在重载运算符时很常见，我们将在未来的课程中讨论这个主题。但非成员函数也有同样的问题——它们无法访问类的私有成员。

如果访问函数（或其他公有成员函数）已经存在并且对于我们试图实现的功能足够，那么很好——我们可以（并且应该）直接使用它们。但在某些情况下，这些函数并不存在。那该怎么办呢？

一种选择是向类中添加新的成员函数，以允许其他类或非成员函数执行它们原本无法完成的工作。但我们可能不想允许公共访问这些内容——也许这些内容高度依赖于实现，或者容易被误用。

我们真正需要的是某种方式，可以在个案基础上绕过访问控制系统。

友谊就是魔法

我们挑战的答案就是友谊。

在类的内部， 友元声明 （使用 friend 关键字）可以用来告诉编译器某个其他类或函数现在是友元。在C++中， 友元 是一个被授予对另一个类的私有和受保护成员完全访问权限的类或函数（成员或非成员）。通过这种方式，一个类可以有选择地授予其他类或函数对其成员的完全访问权限，而不影响其他任何东西。

关键提示

友谊总是由将被访问成员的类授予（而不是由希望访问的类或函数）。通过访问控制和授予友谊，类始终保留控制谁能访问其成员的能力。

例如，如果我们的存储类将显示类设为友元，那么显示类将能够直接访问存储类的所有成员。显示类可以利用这种直接访问来实现存储类的显示，同时在结构上保持分离。

友元声明不受访问控制的影响，因此它在类体内的放置位置无关紧要。

既然我们知道了什么是友元，让我们看一些具体的例子，其中友谊被授予非成员函数、成员函数和其他类。我们将在本课中讨论友元非成员函数，然后在下一课 15.9 -- 友元类和友元成员函数。

友元非成员函数

一个 友元函数 是一个可以像类的成员一样访问该类的私有和受保护成员的函数（成员或非成员）。在其他所有方面，友元函数都是一个普通函数。

让我们看一个简单类将非成员函数设为友元的例子：

#include <iostream>

class Accumulator
{
private:
    int m_value { 0 };

public:
    void add(int value) { m_value += value; }

    // 这里是友元声明，使非成员函数 void print(const Accumulator& accumulator) 成为 Accumulator 的友元
    friend void print(const Accumulator& accumulator);
};

void print(const Accumulator& accumulator)
{
    // 因为 print() 是 Accumulator 的友元
    // 它可以访问 Accumulator 的私有成员
    std::cout << accumulator.m_value;
}

int main()
{
    Accumulator acc{};
    acc.add(5); // 向累加器加 5

    print(acc); // 调用非成员函数 print()

    return 0;
}

在这个例子中，我们声明了一个名为 print() 的非成员函数，它接受一个 Accumulator。因为 print() 不是 Accumulator 类的成员，它通常无法访问私有成员 m_value。然而，Accumulator 类有一个友元声明，将 print(const Accumulator& accumulator) 设为友元，因此现在允许访问。

注意，因为 print() 是一个非成员函数（因此没有隐式对象），我们必须显式地将一个 Accumulator 对象传递给 print() 来操作。

在类内部定义友元非成员函数

就像成员函数可以在类内部定义一样，友元非成员函数也可以在类内部定义。下面的例子在 print() 内部定义了友元非成员函数 Accumulator 类：

#include <iostream>

class Accumulator
{
private:
    int m_value { 0 };

public:
    void add(int value) { m_value += value; }

    // 在类内部定义的友元函数是非成员函数
    friend void print(const Accumulator& accumulator)
    {
        // 因为 print() 是 Accumulator 的友元
        // 它可以访问 Accumulator 的私有成员
        std::cout << accumulator.m_value;
    }
};

int main()
{
    Accumulator acc{};
    acc.add(5); // 向累加器加 5

    print(acc); // 调用非成员函数 print()

    return 0;
}

尽管你可能认为因为 print() 是在 Accumulator内部定义的，这使得 print() 成为 Accumulator的一个成员，但事实并非如此。因为 print() 被定义为友元，它将被视为非成员函数（就像在外部定义一样） Accumulator)。

语法上优先选择友元非成员函数

在本课的引言中，我们提到有时我们可能更倾向于使用非成员函数而不是成员函数。现在让我们展示一个例子。

#include <iostream>

class Value
{
private:
    int m_value{};

public:
    explicit Value(int v): m_value { v }  { }

    bool isEqualToMember(const Value& v) const;
    friend bool isEqualToNonmember(const Value& v1, const Value& v2);
};

bool Value::isEqualToMember(const Value& v) const
{
    return m_value == v.m_value;
}

bool isEqualToNonmember(const Value& v1, const Value& v2)
{
    return v1.m_value == v2.m_value;
}

int main()
{
    Value v1 { 5 };
    Value v2 { 6 };

    std::cout << v1.isEqualToMember(v2) << '\n';
    std::cout << isEqualToNonmember(v1, v2) << '\n';

    return 0;
}

在这个例子中，我们定义了两个类似的函数，用于检查两个 Value 对象是否相等。 isEqualToMember() 是一个成员函数，而 isEqualToNonmember() 是一个非成员函数。让我们关注这些函数的定义方式。

在 isEqualToMember()，我们隐式传递一个对象，显式传递另一个。函数的实现反映了这一点，我们必须从心理上协调 m_value 属于隐式对象，而 v.m_value 属于显式参数。

在 isEqualToNonmember()，两个对象都是显式传递的。这导致函数实现中更好的并行性，因为 m_value 成员总是显式地以显式参数为前缀。

你可能仍然更喜欢调用语法 v1.isEqualToMember(v2) 而不是 isEqualToNonmember(v1, v2)。但当我们讨论运算符重载时，我们会再次看到这个主题。

多个友元

一个函数可以同时是多个类的友元。例如，考虑以下示例：

#include <iostream>

class Humidity; // Humidity 的前向声明

class Temperature
{
private:
    int m_temp { 0 };
public:
    explicit Temperature(int temp) : m_temp { temp } { }

    friend void printWeather(const Temperature& temperature, const Humidity& humidity); // 此行需要前向声明
};

class Humidity
{
private:
    int m_humidity { 0 };
public:
    explicit Humidity(int humidity) : m_humidity { humidity } {  }

    friend void printWeather(const Temperature& temperature, const Humidity& humidity);
};

void printWeather(const Temperature& temperature, const Humidity& humidity)
{
    std::cout << "The temperature is " << temperature.m_temp <<
       " and the humidity is " << humidity.m_humidity << '\n';
}

int main()
{
    Humidity hum { 10 };
    Temperature temp { 12 };

    printWeather(temp, hum);

    return 0;
}

关于这个示例，有三点值得注意。首先，因为 printWeather() 平等地使用 Humidity 和 Temperature ，将其作为任一类的成员都没有太大意义。非成员函数效果更好。其次，因为 printWeather() 是 Humidity 和 Temperature两者的友元，它可以访问两个类对象的私有数据。最后，注意示例顶部的以下行：

class Humidity;

这是 class Humidity的前向声明。类的前向声明与函数的前向声明作用相同——它们告诉编译器一个稍后定义的标识符。然而，与函数不同，类没有返回类型或参数，因此类的前向声明总是简单的 class ClassName （除非它们是类模板）。

没有这一行，编译器在解析 Humidity 内部的友元声明时会告诉我们它不知道 Temperature。

是什么。

友元是否违反了数据隐藏原则？不。友元是由进行数据隐藏的类授予的，期望友元访问其私有成员。将友元视为类本身的扩展，具有相同的访问权限。因此，访问是预期的，而不是违反。

正确使用友元可以使程序更易于维护，因为它允许从设计角度合理地将功能分离（而不是为了访问控制而将它们保持在一起）。或者当使用非成员函数比成员函数更有意义时。

然而，由于友元可以直接访问类的实现，类的实现更改通常也需要更改友元。如果一个类有很多友元（或者这些友元又有友元），这可能导致连锁反应。

在实现友元函数时，尽可能优先使用公共接口而不是直接访问成员。这将有助于使友元函数免受未来实现更改的影响，并减少以后需要修改和/或重新测试的代码量。

最佳实践

友元函数应尽可能优先使用类接口而不是直接访问。

优先选择非友元函数而非友元函数

在课程 14.8 -- 数据隐藏（封装）的好处，我们提到应该优先选择非成员函数而非成员函数。出于同样的原因，我们应该优先选择非友元函数而非友元函数。

例如，在以下示例中，如果 Accumulator 的实现被更改（例如，我们将 m_value重命名为 print() ），那么

#include <iostream>

class Accumulator
{
private:
    int m_value { 0 }; // 如果我们重命名这个

public:
    void add(int value) { m_value += value; } // 我们需要修改这个

    friend void print(const Accumulator& accumulator);
};

void print(const Accumulator& accumulator)
{
    std::cout << accumulator.m_value; // 并且我们需要修改这个
}

int main()
{
    Accumulator acc{};
    acc.add(5); // 向累加器加 5

    print(acc); // 调用非成员函数 print()

    return 0;
}

的实现也需要更改：

#include <iostream>

class Accumulator
{
private:
    int m_value { 0 };

public:
    void add(int value) { m_value += value; }
    int value() const { return m_value; } // 添加了这个合理的访问函数
};

void print(const Accumulator& accumulator) // 不再是 Accumulator 的友元
{
    std::cout << accumulator.value(); // 使用访问函数而不是直接访问
}

int main()
{
    Accumulator acc{};
    acc.add(5); // 向累加器加 5

    print(acc); // 调用非成员函数 print()

    return 0;
}

在这个例子中， print() 使用访问函数 value() 获取 m_value 的值，而不是直接访问 m_value 现在如果 Accumulator 的实现发生改变， print() 就不需要更新。

最佳实践

在可能且合理的情况下，优先将函数实现为非友元。

在向现有类的公有接口添加新成员时要谨慎，因为每个函数（即使是简单的函数）都会增加一定程度的杂乱和复杂性。对于上面的 Accumulator ，拥有一个访问函数来获取当前累计值是合理的。在更复杂的情况下，可能更倾向于使用友元而不是向类的接口添加许多新的访问函数。
