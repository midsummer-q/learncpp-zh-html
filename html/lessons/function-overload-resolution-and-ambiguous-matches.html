11.3 — 函数重载解析与歧义匹配

● 机器译文 课程 11.3 查看英文原文

在前一课（11.2 -- 函数重载区分我们讨论了函数的哪些属性用于区分重载函数。如果重载函数没有与同名其他重载正确区分，编译器将发出编译错误。

然而，拥有一组区分开的重载函数只是问题的一半。当进行任何函数调用时，编译器还必须确保能找到匹配的函数声明。

对于非重载函数（具有唯一名称的函数），只有一个函数可能匹配函数调用。该函数要么匹配（或在应用类型转换后可以匹配），要么不匹配（导致编译错误）。对于重载函数，可能有多个函数可能匹配函数调用。由于一个函数调用只能解析为其中之一，编译器必须确定哪个重载函数是最佳匹配。将函数调用匹配到特定重载函数的过程称为 重载解析。

在简单情况下，当函数参数的类型与函数参数的类型完全匹配时，这（通常）是直接的：

#include <iostream>

void print(int x)
{
     std::cout << x << '\n';
}

void print(double d)
{
     std::cout << d << '\n';
}

int main()
{
     print(5); // 5 是 int，因此匹配 print(int)
     print(6.7); // 6.7 是 double，因此匹配 print(double)

     return 0;
}

但是，当函数调用中的参数类型与任何重载函数的参数类型不完全匹配时，会发生什么？例如：

#include <iostream>

void print(int x)
{
     std::cout << x << '\n';
}

void print(double d)
{
     std::cout << d << '\n';
}

int main()
{
     print('a'); // char 不匹配 int 或 double，那么会发生什么？
     print(5L); // long 不匹配 int 或 double，那么会发生什么？

     return 0;
}

没有精确匹配并不意味着找不到匹配——毕竟，一个 char 或 long 可以隐式类型转换为 int 变为 double。但在每种情况下，哪种转换是最佳选择？

在本课中，我们将探讨编译器如何将给定的函数调用匹配到特定的重载函数。

解析重载函数调用

当对重载函数进行函数调用时，编译器会按一系列规则逐步确定哪个（如果有）重载函数是最佳匹配（我们将在下一节中介绍这些步骤）。

在每一步中，编译器对函数调用中的参数应用一组不同的类型转换。对于应用的每个转换，编译器检查是否有任何重载函数现在匹配。在所有不同的类型转换应用并检查匹配后，该步骤完成。结果将是三种可能结果之一：

  • 未找到匹配的函数。编译器进入序列中的下一步。
  • 找到一个匹配的函数。该函数被认为是最佳匹配。匹配过程现在完成，后续步骤不执行。
  • 找到多个匹配的函数。编译器将发出歧义匹配编译错误。我们稍后将讨论这种情况。

如果编译器到达整个序列的末尾仍未找到匹配，它将生成一个编译错误，指出无法为函数调用找到匹配的重载函数。

参数匹配序列

步骤1）编译器尝试找到精确匹配。这分两个阶段进行。首先，编译器将查看是否存在一个重载函数，其中函数调用中的参数类型与重载函数中的参数类型完全匹配。例如：

void foo(int)
{
}

void foo(double)
{
}

int main()
{
    foo(0);   // 与 foo(int) 精确匹配
    foo(3.4); // 与 foo(double) 精确匹配

    return 0;
}

由于 0 在函数调用 foo(0) 中是一个int，编译器将查看是否声明了一个 foo(int) 重载。由于已声明，编译器确定 foo(int) 是精确匹配。

其次，编译器将对函数调用中的参数应用一些琐碎转换。 琐碎转换 是一组特定的转换规则，它们会修改类型（而不修改值）以寻找匹配。这些包括：

  • 左值到右值的转换
  • 限定转换（例如非const到const）
  • 非引用到引用的转换

例如：

void foo(const int)
{
}

void foo(const double&) // double& 是对 double 的引用
{
}

int main()
{
    int x { 1 };
    foo(x); // x 从 int 平凡转换为 const int

    double d { 2.3 };
    foo(d); // d 从 double 平凡转换为 const double&（非引用到引用的转换）

    return 0;
}

在上面的例子中，我们调用了 foo(x)，其中 x 是一个 int。编译器将把 x 从 int 转换为 const int琐碎转换为 foo(const int)，然后匹配 foo(d)，其中 d 我们还调用了 double。编译器将把 d 是一个 double 转换为 const double&琐碎转换为 foo(const double&)。

通过琐碎转换进行的匹配被认为是精确匹配。这意味着以下程序会导致歧义匹配：10.1 -- 隐式类型转换步骤2）如果未找到精确匹配，编译器尝试通过对参数应用数值提升来找到匹配。在课程中（ int 或 double如果在数值提升后找到了匹配，则函数调用被解析。

例如：

void foo(int)
{
}

void foo(double)
{
}

int main()
{
    foo('a');  // 提升以匹配 foo(int)
    foo(true); // 提升以匹配 foo(int)
    foo(4.5f); // 提升以匹配 foo(double)

    return 0;
}

对于 foo('a')，因为在前一步中找不到 foo(char) 的精确匹配，编译器将 char 'a' 到 int提升，并寻找匹配。这匹配了 foo(int)，因此函数调用解析为 foo(int)。

步骤 3) 如果通过数值提升未找到匹配，编译器尝试通过应用数值转换（10.3 -- 数值转换）到参数来寻找匹配。

例如：

#include <string> // for std::string

void foo(double)
{
}

void foo(std::string)
{
}

int main()
{
    foo('a'); // 'a' 转换以匹配 foo(double)

    return 0;
}

在这种情况下，因为没有 foo(char) （精确匹配），也没有 foo(int) （提升匹配）， 'a' 被数值转换为 double 并与 foo(double)。

关键提示

通过应用数值提升得到的匹配优先于通过应用数值转换得到的任何匹配。

步骤 4) 如果通过数值转换未找到匹配，编译器尝试通过任何用户定义的转换来寻找匹配。虽然我们还没有介绍用户定义的转换，但某些类型（例如类）可以定义到其他类型的转换，这些转换可以被隐式调用。这里有一个例子，只是为了说明这一点：

// 我们还没有介绍类，所以如果这看起来不合理，不必担心
class X // 这定义了一个名为 X 的新类型
{
public:
    operator int() { return 0; } // 这里是一个从 X 到 int 的用户定义转换
};

void foo(int)
{
}

void foo(double)
{
}

int main()
{
    X x; // 这里，我们正在创建一个类型为 X 的对象（名为 x）
    foo(x); // x 使用从 X 到 int 的用户定义转换转换为 int 类型

    return 0;
}

在这个例子中，编译器将首先检查是否存在 foo(X) 的精确匹配。我们没有定义这样的匹配。接下来编译器将检查 x 是否可以被数值提升，但它不能。然后编译器将检查 x 是否可以被数值转换，它也不能。最后，编译器将寻找任何用户定义的转换。因为我们定义了一个从 X 切换到 int的用户定义转换，编译器将把 X 到 int 转换为匹配 foo(int)。

在应用用户定义的转换后，编译器可能会应用额外的隐式提升或转换来找到匹配。所以如果我们的用户定义转换是到类型 char 而不是 int，编译器将使用用户定义的转换到 char ，然后将结果提升为 int 以匹配。

步骤 6) 如果到这一步还没有找到匹配，编译器将放弃并发出编译错误，指出无法找到匹配的函数。

歧义匹配

对于非重载函数，每个函数调用要么解析为一个函数，要么找不到匹配，编译器将发出编译错误：

void foo()
{
}

int main()
{
     foo(); // okay：找到匹配
     goo(); // 编译错误：未找到匹配

     return 0;
}

对于重载函数，存在第三种可能的结果：可能找到 ambiguous match 歧义匹配 发生在编译器找到两个或更多可以在同一步骤中匹配的函数时。当这种情况发生时，编译器将停止匹配并发出编译错误，指出找到了歧义的函数调用。

由于每个重载函数必须被区分才能编译，你可能想知道函数调用怎么可能导致多个匹配。让我们看一个例子来说明这一点：

void foo(int)
{
}

void foo(double)
{
}

int main()
{
    foo(5L); // 5L 是 long 类型

    return 0;
}

由于字面量 5L 的类型是 long，编译器将首先查看是否能找到 foo(long)的精确匹配，但找不到。接下来，编译器将尝试数值提升，但类型 long 无法提升，因此这里也没有匹配。

接着，编译器会尝试通过对实参应用数值转换来寻找匹配。 long 在检查所有数值转换规则的过程中，编译器会找到两个潜在的匹配。如果 long 实参被数值转换为 int，那么函数调用将匹配 foo(int)。如果 long 实参被转换为 double，那么它将匹配 foo(double) 由于通过数值转换找到了两个可能的匹配，该函数调用被视为具有二义性。

在 Visual Studio 2019 上，这会导致以下错误消息：

error C2668: 'foo': ambiguous call to overloaded function
message : could be 'void foo(double)'
message : or       'void foo(int)'
message : while trying to match the argument list '(long)'

关键提示

如果编译器在某个步骤中找到多个匹配，则会导致二义性函数调用。这意味着同一步骤中的任何匹配都不被认为优于其他匹配。

下面是另一个产生二义性匹配的例子：

void foo(unsigned int)
{
}

void foo(float)
{
}

int main()
{ 
    foo(0);       // int 可以数值转换为 unsigned int 或 float
    foo(3.14159); // double 可以数值转换为 unsigned int 或 float

    return 0;
}

尽管你可能期望 0 解析为 foo(unsigned int) 和 3.14159 解析为 foo(float)，但这两个调用都会导致二义性匹配。 int 值 0 可以数值转换为 unsigned int 变为 float，因此两个重载匹配程度相同，结果是二义性函数调用。

同样适用于将 double 转换为 float 或 unsigned int。两者都是数值转换，因此两个重载匹配程度相同，结果再次具有二义性。

解决二义性匹配

  1. 由于二义性匹配是编译时错误，因此在程序编译之前需要消除二义性。有几种方法可以解决二义性匹配：
  2. 通常，最好的方法是定义一个新的重载函数，其参数类型恰好是你试图调用函数时使用的类型。这样 C++ 就能为函数调用找到精确匹配。 foo(0) 或者，显式地将有歧义的实参强制转换为你要调用的函数所需的类型。例如，要使 foo(unsigned int) 匹配
int x{ 0 };
foo(static_cast<unsigned int>(x)); // 将调用 foo(unsigned int)
  1. 在上面的例子中，你可以这样做：
foo(0u); // 将调用 foo(unsigned int)，因为 'u' 后缀表示 unsigned int，所以现在是精确匹配

如果你的实参是字面量，可以使用字面量后缀来确保你的字面量被解释为正确的类型： 5.2 -- 字面量。

多参数的匹配

例如：

#include <iostream>

void print(char, int)
{
	std::cout << 'a' << '\n';
}

void print(char, double)
{
	std::cout << 'b' << '\n';
}

void print(char, float)
{
	std::cout << 'c' << '\n';
}

int main()
{
	print('x', 'a');

	return 0;
}

如果有多个参数，编译器会依次对每个参数应用匹配规则。选择的函数是这样一个函数：每个参数至少与其他所有函数匹配得一样好，并且至少有一个参数比其他所有函数匹配得更好。换句话说，所选函数必须至少在一个参数上比其他所有候选函数匹配得更好，并且在所有其他参数上不差于它们。 print(char, int) 如果找到了这样的函数，那么它显然是且无歧义的最佳选择。如果找不到这样的函数，则调用将被视为二义性（或不匹配）。
