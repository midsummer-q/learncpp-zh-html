11.7 — 函数模板实例化

● 机器译文 课程 11.7 查看英文原文

在前一课（11.6 -- 函数模板我们介绍了函数模板，并将一个普通的 max() 函数转换为 max<T> 函数模板中：

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

在本节课中，我们将重点讨论函数模板的使用方式。

使用函数模板

函数模板实际上并不是函数——它们的代码不会直接被编译或执行。相反，函数模板只有一个任务：生成函数（这些函数会被编译和执行）。

要使用我们的 max<T> 函数模板，我们可以使用以下语法进行函数调用：

max<actual_type>(arg1, arg2); // actual_type is some actual type, like int or double

这看起来很像普通的函数调用——主要区别在于尖括号中增加了类型（称为 模板实参），它指定了将用于替换模板类型 T。

的实际类型。让我们通过一个简单的例子来看一下：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // 实例化并调用函数 max<int>(int, int)

    return 0;
}

当编译器遇到函数调用 max<int>(1, 2)时，它会确定 max<int>(int, int) 的函数定义尚不存在。因此，编译器会隐式地使用我们的 max<T> 函数模板来创建一个。

从函数模板（带有模板类型）创建函数（带有特定类型）的过程称为 函数模板实例化 （或 实例化 ）。当函数因函数调用而被实例化时，称为 隐式实例化。从模板实例化出的函数在技术上称为 特化，但在日常用语中通常称为 函数实例。产生特化的模板称为 主模板。函数实例在所有方面都是普通的函数。

术语

术语“特化”更常用于指代显式特化，它允许我们显式地定义一个特化（而不是从主模板隐式实例化）。我们在课程 26.3 -- 函数模板特化。

中介绍显式特化。实例化函数的过程很简单：编译器基本上克隆主模板，并将模板类型（T）替换为我们指定的实际类型（int)。

因此，当我们调用 max<int>(1, 2)时，实例化的函数特化看起来像这样：

template<> // 暂时忽略这个
int max<int>(int x, int y) // 生成的函数 max<int>(int, int)
{
    return (x < y) ? y : x;
}

以下是上面的相同示例，展示了所有实例化完成后编译器实际编译的内容：

#include <iostream>

// 函数模板的声明（我们不再需要定义）
template <typename T> 
T max(T x, T y);

template<>
int max<int>(int x, int y) // 生成的函数 max<int>(int, int)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // 实例化并调用函数 max<int>(int, int)

    return 0;
}

你可以自己编译并看到它有效。函数模板仅在每个翻译单元中第一次进行函数调用时实例化。后续对该函数的调用将路由到已实例化的函数。

相反，如果没有对函数模板进行函数调用，则该函数模板不会在该翻译单元中被实例化。

让我们再举一个例子：

#include <iostream>

template <typename T>
T max(T x, T y) // 函数模板 max(T, T)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n';    // 实例化并调用函数 max<int>(int, int)
    std::cout << max<int>(4, 3) << '\n';    // 调用已实例化的函数 max<int>(int, int)
    std::cout << max<double>(1, 2) << '\n'; // 实例化并调用函数 max<double>(double, double)

    return 0;
}

这与前面的示例类似，但我们的函数模板这次将用于生成两个函数：一次替换 T 替换为 int，另一次替换 T 替换为 double。所有实例化完成后，程序将看起来像这样：

#include <iostream>

// 函数模板的声明（我们不再需要定义）
template <typename T>
T max(T x, T y); 

template<>
int max<int>(int x, int y) // 生成的函数 max<int>(int, int)
{
    return (x < y) ? y : x;
}

template<>
double max<double>(double x, double y) // 生成的函数 max<double>(double, double)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n';    // 实例化并调用函数 max<int>(int, int)
    std::cout << max<int>(4, 3) << '\n';    // 调用已实例化的函数 max<int>(int, int)
    std::cout << max<double>(1, 2) << '\n'; // 实例化并调用函数 max<double>(double, double)

    return 0;
}

这里还有一点需要注意：当我们实例化 max<double>，实例化的函数具有类型为 double的参数。由于我们提供了 int 实参，这些实参将被隐式转换为 double。

模板实参推导

在大多数情况下，我们想要用于实例化的实际类型会与函数参数的类型匹配。例如：

std::cout << max<int>(1, 2) << '\n'; // 指定我们要调用 max<int>

在这个函数调用中，我们指定了要替换 T 替换为 int，但我们也用 int 实参调用了该函数。

在实参类型与我们想要的实际类型匹配的情况下，我们不需要指定实际类型——相反，我们可以使用 模板实参推导 让编译器从函数调用中的实参类型推导出应该使用的实际类型。

例如，与其像这样进行函数调用：

std::cout << max<int>(1, 2) << '\n'; // 指定我们要调用 max<int>

我们可以改为执行以下任一操作：

std::cout << max<>(1, 2) << '\n';
std::cout << max(1, 2) << '\n';

无论哪种情况，编译器都会看到我们没有提供实际类型，因此它会尝试从函数实参推导出一个实际类型，以生成一个所有模板参数都与提供的实参类型匹配的 max() 函数。在此示例中，编译器将推导出使用实际类型 max<T> 的函数模板 int 可以实例化函数 max<int>(int, int)，这样两个函数参数的类型（int）与提供的实参类型（int)。

）匹配。这两种情况之间的区别在于编译器如何从一组重载函数中解析函数调用。在第一种情况（带有空尖括号）中，编译器在确定调用哪个重载函数时只会考虑 max<int> 模板函数重载。在第二种情况（没有尖括号）中，编译器会同时考虑 max<int> 模板函数重载和 max 非模板函数重载。当第二种情况导致模板函数和非模板函数同样可行时，将优先选择非模板函数。

关键提示

普通的函数调用语法会优先选择非模板函数，而不是同样可行的从模板实例化的函数。

例如：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    std::cout << "called max<int>(int, int)\n";
    return (x < y) ? y : x;
}

int max(int x, int y)
{
    std::cout << "called max(int, int)\n";
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // 调用 max<int>(int, int)
    std::cout << max<>(1, 2) << '\n';    // 推导出 max<int>(int, int)（不考虑非模板函数）
    std::cout << max(1, 2) << '\n';      // 调用 max(int, int)

    return 0;
}

注意，第二种情况的语法看起来与普通函数调用完全相同！在大多数情况下，我们将使用这种普通函数调用语法来调用从函数模板实例化的函数。

这有几个原因：

  • 语法更简洁。
  • 我们很少会同时拥有匹配的非模板函数和函数模板。
  • 如果我们确实有匹配的非模板函数和匹配的函数模板，我们通常会更倾向于调用非模板函数。

最后一点可能不太明显。函数模板的实现适用于多种类型——但因此，它必须是通用的。非模板函数只处理特定的类型组合。它可以拥有比函数模板版本更优化或更专门针对这些特定类型的实现。例如：

#include <iostream>

// 这个函数模板可以处理多种类型，因此其实现是通用的
template <typename T>
void print(T x)
{
    std::cout << x; // 按常规方式打印 T
}

// 这个函数只需要考虑如何打印 bool，因此它可以专门处理
// bool 的打印
void print(bool x)
{
    std::cout << std::boolalpha << x; // 将 bool 打印为 true 或 false，而不是 1 或 0
}

int main()
{
    print<bool>(true); // 调用 print<bool>(bool) -- 打印 1
    std::cout << '\n';

    print<>(true);     // 推导出 print<bool>(bool)（不考虑非模板函数）-- 打印 1
    std::cout << '\n';

    print(true);       // 调用 print(bool) -- 打印 true
    std::cout << '\n';

    return 0;
}

最佳实践

在调用从函数模板实例化的函数时，优先使用普通函数调用语法（除非你需要函数模板版本优先于匹配的非模板函数）。

带有非模板参数的函数模板

可以创建同时具有模板参数和非模板参数的函数模板。类型模板参数可以匹配任何类型，而非模板参数的工作方式与普通函数的参数类似。

例如：

// T 是一个类型模板参数
// double 是一个非模板参数
// 我们不需要为这些参数提供名称，因为它们未被使用
template <typename T>
int someFcn(T, double)
{
    return 5;
}

int main()
{
    someFcn(1, 3.4); // 匹配 someFcn(int, double)
    someFcn(1, 3.4f); // 匹配 someFcn(int, double) -- float 被提升为 double
    someFcn(1.2, 3.4); // 匹配 someFcn(double, double)
    someFcn(1.2f, 3.4); // 匹配 someFcn(float, double)
    someFcn(1.2f, 3.4f); // 匹配 someFcn(float, double) -- float 被提升为 double

    return 0;
}

这个函数模板有一个模板化的第一个参数，但第二个参数固定为类型 double。注意，返回类型也可以是任何类型。在这种情况下，我们的函数将始终返回一个 int 值。

实例化的函数可能并不总是能编译

考虑以下程序：

#include <iostream>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne(1) << '\n';
    std::cout << addOne(2.3) << '\n';

    return 0;
}

编译器将有效地编译并执行以下代码：

#include <iostream>

template <typename T>
T addOne(T x);

template<>
int addOne<int>(int x)
{
    return x + 1;
}

template<>
double addOne<double>(double x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne(1) << '\n';   // 调用 addOne<int>(int)
    std::cout << addOne(2.3) << '\n'; // 调用 addOne<double>(double)

    return 0;
}

这将产生结果：

2
3.3

但如果我们尝试类似这样的操作呢？

#include <iostream>
#include <string>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::string hello { "Hello, world!" };
    std::cout << addOne(hello) << '\n';

    return 0;
}

当编译器尝试解析 addOne(hello) 它不会找到非模板函数匹配 addOne(std::string)，但会找到我们的函数模板用于 addOne(T)，并确定它可以从中生成一个 addOne(std::string) 函数。因此，编译器将生成并编译以下代码：

#include <iostream>
#include <string>

template <typename T>
T addOne(T x);

template<>
std::string addOne<std::string>(std::string x)
{
    return x + 1;
}

int main()
{
    std::string hello{ "Hello, world!" };
    std::cout << addOne(hello) << '\n';

    return 0;
}

然而，这会产生编译错误，因为 x + 1 在 x 我们还调用了 std::string时没有意义。明显的解决方案是不要用 addOne() 类型的参数调用 std::string。

实例化的函数在语义上可能并不总是有意义

只要语法上合理，编译器就能成功编译实例化的函数模板。然而，编译器无法检查这样的函数在语义上是否真正有意义。

例如：

#include <iostream>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne("Hello, world!") << '\n';

    return 0;
}

在这个例子中，我们在C风格字符串字面量上调用 addOne() 这在语义上到底意味着什么？谁知道呢！

也许令人惊讶的是，因为C++在语法上允许将整数值加到字符串字面量上（我们在未来的课程 17.9 -- 指针算术和下标中介绍），上面的例子可以编译，并产生以下结果：

ello, world!

警告

只要语法有效，编译器就会实例化并编译在语义上没有意义的函数模板。你有责任确保调用这样的函数模板时使用的参数是有意义的。

进阶读者

我们可以告诉编译器，应该禁止使用某些参数实例化函数模板。这可以通过函数模板特化来实现，它允许我们为一组特定的模板参数重载函数模板，并结合 = delete，它告诉编译器任何对该函数的使用都应产生编译错误。

#include <iostream>
#include <string>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

// 使用函数模板特化告诉编译器 addOne(const char*) 应该产生编译错误
// const char* 将匹配字符串字面量
template <>
const char* addOne(const char* x) = delete;

int main()
{
    std::cout << addOne("Hello, world!") << '\n'; // 编译错误

    return 0;
}

函数模板和非模板参数的默认参数

就像普通函数一样，函数模板可以为非模板参数提供默认参数。从模板实例化的每个函数都将使用相同的默认参数。

例如：

#include <iostream>

template <typename T>
void print(T val, int times=1)
{
    while (times--)
    {
        std::cout << val;        
    }
}

int main()
{
    print(5);      // 打印 5 1 次
    print('a', 3); // 打印 'a' 3 次

    return 0;
}

这会打印：

5aaa

注意带有可修改静态局部变量的函数模板

在课程 7.11 -- 静态局部变量中，我们讨论了静态局部变量，即具有静态存储期（在程序生命周期内持续存在）的局部变量。

当在函数模板中使用静态局部变量时，从该模板实例化的每个函数都将拥有该静态局部变量的独立版本。如果静态局部变量是const的，这很少成为问题。但如果静态局部变量是可修改的，结果可能不如预期。

例如：

#include <iostream>

// 这是一个带有被修改的静态局部变量的函数模板
template <typename T>
void printIDAndValue(T value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

int main()
{
    printIDAndValue(12);
    printIDAndValue(13);

    printIDAndValue(14.5);

    return 0;
}

这会产生以下结果：

1) 12
2) 13
1) 14.5

你可能期望最后一行打印 3) 14.5。然而，编译器实际编译和执行的是：

#include <iostream>

template <typename T>
void printIDAndValue(T value);

template <>
void printIDAndValue<int>(int value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

template <>
void printIDAndValue<double>(double value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

int main()
{
    printIDAndValue(12);   // 调用 printIDAndValue<int>()
    printIDAndValue(13);   // 调用 printIDAndValue<int>()

    printIDAndValue(14.5); // 调用 printIDAndValue<double>()

    return 0;
}

注意 printIDAndValue<int> 和 printIDAndValue<double> 各自拥有自己独立的静态局部变量 id，而不是共享一个。

泛型编程

由于模板类型可以被任何实际类型替换，模板类型有时被称为 泛型类型。而且，由于模板可以独立于特定类型编写，使用模板进行编程有时被称为 泛型编程。C++通常非常注重类型和类型检查，相比之下，泛型编程让我们专注于算法的逻辑和数据结构的设计，而不必过多担心类型信息。

总结

一旦你习惯了编写函数模板，你会发现它们实际上并不比编写具有实际类型的函数花费更多时间。函数模板可以通过减少需要编写和维护的代码量，显著降低代码维护成本和错误。

函数模板确实有一些缺点，我们不得不提一下。首先，对于每次具有唯一参数类型集的函数调用，编译器都会创建（并编译）一个函数。因此，虽然函数模板编写起来很紧凑，但它们可能会扩展成大量的代码，导致代码膨胀和编译时间变慢。函数模板更大的缺点是它们往往会产生看起来奇怪、几乎不可读的错误信息，比普通函数的错误信息更难解读。这些错误信息可能相当吓人，但一旦你理解了它们试图告诉你什么，它们指出的问题通常很容易解决。

与模板为你的编程工具箱带来的强大功能和安全性相比，这些缺点相对较小，因此在你需要类型灵活性的地方，可以自由地使用模板！一个好的经验法则是先创建普通函数，如果发现需要针对不同参数类型的重载，再将其转换为函数模板。

最佳实践

当你需要时，使用函数模板编写可以适用于多种类型的泛型代码。
