26.3 — 函数模板特化

● 机器译文 课程 26.3 查看英文原文

当为给定类型实例化函数模板时，编译器会复制一份模板函数，并将模板类型参数替换为变量声明中使用的实际类型。这意味着对于每个实例化的类型，特定函数将具有相同的实现细节（只是使用不同的类型）。虽然大多数情况下这正是你想要的，但偶尔也会出现这样的情况：对于特定的数据类型，以稍微不同的方式实现模板函数是有用的。

使用非模板函数

考虑以下示例：

#include <iostream>

template <typename T>
void print(const T& t)
{
    std::cout << t << '\n';
}

int main()
{
    print(5);
    print(6.7);
    
    return 0;
}

这会打印：

5
6.7

现在，假设我们希望 double 值（且仅 double 值）以科学计数法输出。

为给定类型获得不同行为的一种方法是定义一个非模板函数：

#include <iostream>

template <typename T>
void print(const T& t)
{
    std::cout << t << '\n';
}

void print(double d)
{
    std::cout << std::scientific << d << '\n';
}

int main()
{
    print(5);
    print(6.7);
    
    return 0;
}

当编译器解析 print(6.7)时，它会发现 print(double) 已经由我们定义，并使用该函数，而不是从 print(const T&)。

这会产生以下结果：

5
6.700000e+000

以这种方式定义函数的一个好处是，非模板函数不需要与函数模板具有相同的签名。注意， print(const T&) 使用传 const 引用，而 print(double) 使用传值。

通常，如果可用，优先定义非模板函数。

函数模板特化

另一种实现类似结果的方法是使用显式模板特化。 显式模板特化 （常简称为 模板特化是一种允许我们为特定类型或值显式定义不同模板实现的功能。当所有模板参数都被特化时，称为 完全特化。当只有部分模板参数被特化时，称为 部分特化。

让我们创建一个 print<T> 当 T 我们还调用了 double：

#include <iostream>

// 这是我们的主模板（必须放在前面）
template <typename T>
void print(const T& t)
{
    std::cout << t << '\n';
}

// 主模板 print<T> 针对 double 类型的完全特化
// 完全特化不是隐式内联的，所以如果放在头文件中，请将其设为内联
template<>                          // 不包含模板参数的模板参数声明 
void print<double>(const double& d) // 针对 double 类型特化
{
    std::cout << std::scientific << d << '\n'; 
}

int main()
{
    print(5);
    print(6.7);
    
    return 0;
}

为了特化一个模板，编译器必须首先看到主模板的声明。上面例子中的主模板是 print<T>(const T&)。

现在，让我们仔细看看我们的函数模板特化：

template<>                          // 不包含模板参数的模板参数声明 
void print<double>(const double& d) // 针对 double 类型特化

首先，我们需要一个模板参数声明，以便编译器知道我们在做与模板相关的事情。然而，在这种情况下，我们实际上不需要任何模板参数，所以我们使用一对空的尖括号。由于特化中没有模板参数，这是一个完全特化。

在下一行， print<double> 告诉编译器我们正在特化 print 主模板函数，针对类型 double。特化必须与主模板具有相同的签名（除了特化将 double 替换为主模板使用 T的任何地方）。因为主模板有一个类型为 const T&的参数，特化必须有一个类型为 const double&的参数。特化不能在主模板使用传引用时使用传值（反之亦然）。

此示例打印与上面相同的结果。

注意，如果同时存在匹配的非模板函数和匹配的模板函数特化，非模板函数将优先。此外，完全特化不是隐式内联的，所以如果你在头文件中定义了一个，请确保 inline 它以避免 ODR 违规。

警告

完全特化不是隐式内联的（部分特化是隐式内联的）。如果你在头文件中放置一个完全特化，它应该被标记为 inline ，这样当包含到多个翻译单元时不会导致 ODR 违规。

就像普通函数一样，函数模板特化可以被删除（使用 = delete），如果你希望任何解析到该特化的函数调用产生编译错误。

通常，你应该尽可能避免函数模板特化，而使用非模板函数。

成员函数的函数模板特化？

现在考虑以下类模板：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

int main()
{
    // 定义一些存储单位
    Storage i { 5 };
    Storage d { 6.7 };

    // 打印一些值
    i.print();
    d.print();
}

这会打印：

5
6.7

假设我们再次想要创建一个 print() 函数的版本，以科学记数法打印 double。但这次 print() 是一个成员函数，所以我们不能定义非成员函数。那么我们应该怎么做呢？

虽然看起来我们可能需要在这里使用函数模板特化，但那是错误的工具。注意 i.print() 调用 Storage<int>::print() 和 d.print() 调用 Storage<double>::print()。因此，如果我们想要改变这个函数在 T 是 double 时的行为，我们需要特化 Storage<double>::print()，这是一个类模板特化，而不是函数模板特化！

那么我们应该怎么做呢？我们将在下一课中介绍类模板特化。
