11.8 — 具有多种模板类型的函数模板

● 机器译文 课程 11.8 查看英文原文

在课程 11.6 -- 函数模板，我们编写了一个函数模板来计算两个值的最大值：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(1, 2) << '\n';   // 将实例化 max(int, int)
    std::cout << max(1.5, 2.5) << '\n'; // 将实例化 max(double, double)

    return 0;
}

现在考虑以下类似的程序：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n';  // 编译错误

    return 0;
}

你可能会惊讶地发现这个程序无法编译。相反，编译器会发出一堆（可能看起来很奇怪）的错误信息。在 Visual Studio 上，作者得到了以下信息：

Project3.cpp(11,18): error C2672: 'max': no matching overloaded function found
Project3.cpp(11,28): error C2782: 'T max(T,T)': template parameter 'T' is ambiguous
Project3.cpp(4): message : see declaration of 'max'
Project3.cpp(11,28): message : could be 'double'
Project3.cpp(11,28): message : or       'int'
Project3.cpp(11,28): error C2784: 'T max(T,T)': could not deduce template argument for 'T' from 'double'
Project3.cpp(4): message : see declaration of 'max'

在我们的函数调用 max(2, 3.5)中，我们传递了两个不同类型的参数：一个 int 和一个 double。由于我们在进行函数调用时没有使用尖括号指定实际类型，编译器首先会查找是否存在非模板匹配的 max(int, double)。它找不到。

接下来，编译器会检查是否能找到函数模板匹配（使用模板实参推导，我们在课程 11.7 -- 函数模板实例化中介绍过）。然而，这也会失败，原因很简单： T 只能表示单一类型。没有类型 T 能让编译器将函数模板 max<T>(T, T) 实例化为具有两个不同参数类型的函数。换句话说，由于函数模板中的两个参数都是类型 T，它们必须解析为相同的实际类型。

由于既找不到非模板匹配也找不到模板匹配，函数调用无法解析，我们就会得到一个编译错误。

你可能想知道为什么编译器没有生成函数 max<double>(double, double) ，然后使用数值转换将 int 参数转换为 double。答案很简单：类型转换只在解析函数重载时进行，而不是在执行模板实参推导时。

这种缺乏类型转换是有意为之，至少有两个原因。首先，它有助于保持简单：我们要么在函数调用参数和模板类型参数之间找到精确匹配，要么找不到。其次，它允许我们创建函数模板，用于确保两个或多个参数具有相同类型的情况（如上例所示）。

我们必须找到另一种解决方案。幸运的是，我们至少可以用三种方法解决这个问题。

使用 static_cast 将参数转换为匹配的类型

第一种解决方案是将转换参数为匹配类型的负担交给调用者。例如：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(static_cast<double>(2), 3.5) << '\n'; // 将 int 转换为 double，以便调用 max(double, double)

    return 0;
}

现在两个参数都是类型 double，编译器将能够实例化 max(double, double) 来满足这个函数调用。

然而，这种解决方案既笨拙又难以阅读。

提供显式的类型模板实参

如果我们编写了一个非模板的 max(double, double) 函数，那么我们可以调用 max(int, double) 并让隐式类型转换规则将我们的 int 参数转换为 double ，从而解析函数调用：

#include <iostream>

double max(double x, double y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n'; // int 参数将被转换为 double

    return 0;
}

然而，当编译器进行模板实参推导时，它不会进行任何类型转换。幸运的是，如果我们指定一个显式的类型模板实参来使用，就不必使用模板实参推导：

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    // 我们显式指定了类型 double，因此编译器不会使用模板参数推导
    std::cout << max<double>(2, 3.5) << '\n';

    return 0;
}

在上面的例子中，我们调用 max<double>(2, 3.5)。由于我们显式指定了 T 应被替换为 double，编译器不会使用模板实参推导。相反，它只会实例化函数 max<double>(double, double)，然后类型转换任何不匹配的参数。我们的 int 参数将被隐式转换为 double。

虽然这比使用 static_cast更易读，但如果我们甚至不必在调用 max 时考虑类型，那就更好了。

具有多个模板类型参数的函数模板

我们问题的根源在于，我们只为函数模板定义了一个模板类型（T），然后指定两个参数必须都是同一类型。

解决这个问题的最佳方法是重写我们的函数模板，使得参数可以解析为不同的类型。而不是使用一个模板类型参数 T，我们现在使用两个（T 和 U)：

#include <iostream>

template <typename T, typename U> // 我们使用两个模板类型参数，名为 T 和 U
T max(T x, U y) // x 可以解析为类型 T，y 可以解析为类型 U
{
    return (x < y) ? y : x; // 哦，这里存在窄化转换问题
}

int main()
{
    std::cout << max(2, 3.5) << '\n'; // 解析为 max<int, double>

    return 0;
}

因为我们将 x 定义为模板类型 T、和 y 定义为模板类型 U， x 和 y 现在可以独立地解析它们的类型。当我们调用 max(2, 3.5)， T 可以是 int 和 U 可以是 double。编译器会愉快地为 max<int, double>(int, double) 实例化。

关键提示

因为 T 和 U 是独立的模板参数，它们彼此独立地解析类型。这意味着 T 和 U 可以解析为不同的类型，也可以解析为相同的类型。

然而，这个例子并不正确。如果你编译并运行程序（关闭“将警告视为错误”），它将产生以下结果：

这是怎么回事？ 2 和 3.5 的最大值怎么可能是 3？

，这是正确的。 T。当 T 是一个 int 和 U 我们还调用了 double，函数的返回类型是 int。我们的值 3.5 正在经历一个窄化转换到 int 值 3，导致数据丢失（可能还有编译器警告）。

那么如何解决这个问题呢？将返回类型改为 U 并不能解决问题，因为 max(3.5, 2) has U 作为 int 并且会出现同样的问题。

在这种情况下，返回类型推导（通过 auto）可能很有用——我们将让编译器从返回语句中推导出返回类型：

#include <iostream>

template <typename T, typename U>
auto max(T x, U y) // 让编译器找出相关的返回类型
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n';

    return 0;
}

这个版本的 max 现在可以很好地处理不同类型的操作数。只需注意，具有 auto 返回类型的函数需要在使用之前完全定义（前向声明是不够的），因为编译器必须检查函数实现以确定返回类型。

进阶读者

如果我们需要一个可以前向声明的函数，我们必须明确返回类型。由于我们的返回类型需要是 T 和 U，我们可以使用 std::common_type_t （在课程 10.5 -- 算术转换中讨论）来获取 T 和 U 的公共类型，作为我们的显式返回类型：

#include <iostream>
#include <type_traits> // for std::common_type_t

template <typename T, typename U>
auto max(T x, U y) -> std::common_type_t<T, U>; // 返回 T 和 U 的公共类型

int main()
{
    std::cout << max(2, 3.5) << '\n';

    return 0;
}

template <typename T, typename U>
auto max(T x, U y) -> std::common_type_t<T, U>
{
    return (x < y) ? y : x;
}

缩写函数模板 C++20

C++20 引入了 auto 关键字的新用法：当 auto 关键字在普通函数中用作参数类型时，编译器会自动将函数转换为函数模板，每个 auto 参数成为独立的模板类型参数。这种创建函数模板的方法称为 缩写函数模板。

例如：

auto max(auto x, auto y)
{
    return (x < y) ? y : x;
}

在 C++20 中是以下内容的简写：

template <typename T, typename U>
auto max(T x, U y)
{
    return (x < y) ? y : x;
}

这与我们上面编写的 max 函数模板相同。

在希望每个模板类型参数都是独立类型的情况下，这种形式更受青睐，因为去掉模板参数声明行使代码更简洁、更易读。

当希望多个 auto 参数为同一类型时，没有简洁的方式使用缩写函数模板。也就是说，对于类似下面的情况，没有简单的缩写函数模板：

template <typename T>
T max(T x, T y) // 两个相同类型的参数
{
    return (x < y) ? y : x;
}

最佳实践

可以随意使用带有单个 auto 参数的缩写函数模板，或者每个 auto 参数应为独立类型的情况（并且语言标准设置为 C++20 或更新版本）。

函数模板可以重载

就像函数可以重载一样，函数模板也可以重载。这样的重载可以具有不同数量的模板类型和/或不同数量或类型的函数参数：

#include <iostream>

// 添加两个匹配类型的值
template <typename T>
auto add(T x, T y)
{
    return x + y;
}

// 添加两个不匹配类型的值
// 从 C++20 开始，我们也可以使用 auto add(auto x, auto y)
template <typename T, typename U>
auto add(T x, U y)
{
    return x + y;
}

// 添加三个任意类型的值
// 从C++20开始，我们也可以使用auto add(auto x, auto y, auto z)
template <typename T, typename U, typename V>
auto add(T x, U y, V z)
{
    return x + y + z;
}

int main()
{
    std::cout << add(1.2, 3.4) << '\n'; // 实例化并调用add<double>()
    std::cout << add(5.6, 7) << '\n';   // 实例化并调用add<double, int>()
    std::cout << add(8, 9, 10) << '\n'; // 实例化并调用add<int, int, int>()

    return 0;
}

一个有趣的注意点是，对于调用 add(1.2, 3.4)，编译器会优先选择 add<T>(T, T) 而不是 add<T, U>(T, U) ，尽管两者都可能匹配。

确定多个匹配函数模板中哪个应优先选择的规则称为“函数模板的部分排序”。简而言之，哪个函数模板更受限/更特化，就会被优先选择。 add<T>(T, T) 在这种情况下是更受限的函数模板（因为它只有一个模板参数），所以它被优先选择。

如果多个函数模板可以匹配调用，并且编译器无法确定哪个更受限，编译器将报错，提示存在歧义匹配。
