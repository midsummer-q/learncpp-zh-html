8.14 — 使用梅森旋转算法生成随机数

● 机器译文 课程 8.14 查看英文原文

在上一节课 8.13 -- 随机数生成简介中，我们介绍了随机数生成的概念，并讨论了PRNG算法通常如何用于在程序中模拟随机性。

在本节课中，我们将探讨如何在程序中生成随机数。要使用C++中的任何随机化功能，我们需要包含标准库的 <random> 头文件。

在C++中使用梅森旋转算法生成随机数

梅森旋转算法PRNG，除了名字好听之外，可能是所有编程语言中最流行的PRNG。虽然以今天的标准来看它有点老，但它通常能产生高质量的结果，并且性能不错。random库支持两种梅森旋转算法类型：

  • mt19937 是生成32位无符号整数的梅森旋转算法
  • mt19937_64 是生成64位无符号整数的梅森旋转算法

使用梅森旋转算法很简单：

#include <iostream>
#include <random> // for std::mt19937

int main()
{
	std::mt19937 mt{}; // 实例化一个32位梅森旋转算法

	// 打印一堆随机数
	for (int count{ 1 }; count <= 40; ++count)
	{
		std::cout << mt() << '\t'; // 生成一个随机数

		// 如果已经打印了5个数字，开始新的一行
		if (count % 5 == 0)
			std::cout << '\n';
	}

	return 0;
}

首先，我们包含<random>头文件，因为所有随机数功能都在那里。接下来，我们通过语句 std::mt19937 mt实例化一个32位梅森旋转算法引擎。然后，每次我们想要生成一个随机的32位无符号整数时，我们调用 mt()。

顺便说一句……

由于 mt 是一个变量，你可能想知道 mt() 是什么意思。

在课程 5.7 -- std::string 简介中，我们展示了一个调用函数 name.length()的例子，它调用了 length() 上的 std::string 变量 name。

mt() 是调用函数 mt.operator()的简洁语法，对于这些PRNG类型，该函数被定义为返回序列中的下一个随机结果。使用 operator() 而不是命名函数的好处是，我们不需要记住函数名，而且简洁的语法减少了打字量。

使用梅森旋转算法掷骰子

一个32位PRNG会生成0到4,294,967,295之间的随机数，但我们并不总是需要这个范围内的数字。如果我们的程序模拟的是棋盘游戏或骰子游戏，我们可能希望模拟一个六面骰子的投掷，生成1到6之间的随机数。如果我们的程序是一个地牢冒险游戏，玩家有一把对怪物造成7到11点伤害的剑，那么当玩家击中怪物时，我们希望生成7到11之间的随机数。

不幸的是，PRNG不能做到这一点。它们只能生成使用完整范围的数字。我们需要某种方法将PRNG输出的数字转换为我们想要的较小范围的值（每个值出现的概率相等）。虽然我们可以自己编写一个函数来实现这一点，但以产生无偏结果的方式来做这件事并不简单。

幸运的是，random库可以在这里帮助我们，以随机数分布的形式。 随机数分布 将PRNG的输出转换为其他数字分布。

顺便说一句……

对于统计极客：随机数分布只是一种概率分布，旨在将PRNG值作为输入。

random库有许多随机数分布，其中大多数除非你进行某种统计分析，否则永远不会用到。但有一种随机数分布非常有用： 均匀分布 是一种随机数分布，它在两个数字X和Y之间（包括边界）以相等的概率产生输出。

下面是一个与上面类似的程序，使用均匀分布来模拟六面骰子的投掷：

#include <iostream>
#include <random> // for std::mt19937 and std::uniform_int_distribution

int main()
{
	std::mt19937 mt{};

	// 创建一个可重用的随机数生成器，生成1到6之间的均匀数
	std::uniform_int_distribution die6{ 1, 6 }; // 对于C++14，使用 std::uniform_int_distribution<> die6{ 1, 6 };

	// 打印一堆随机数
	for (int count{ 1 }; count <= 40; ++count)
	{
		std::cout << die6(mt) << '\t'; // 在这里生成一次掷骰子

		// 如果已经打印了10个数字，开始新的一行
		if (count % 10 == 0)
			std::cout << '\n';
	}

	return 0;
}

这个例子与上一个相比只有两个值得注意的区别。首先，我们创建了一个均匀分布变量（名为 die6）来生成1到6之间的数字。其次，我们不再调用 mt() 来生成32位无符号整数随机数，而是调用 die6(mt) 来生成1到6之间的值。

上面的程序并不像看起来那么随机

虽然上面掷骰子示例的结果相当随机，但该程序有一个主要缺陷。运行程序3次，看看你是否能发现它是什么。去吧，我们等着。

危险边缘音乐

如果你多次运行该程序，你会注意到它每次都打印相同的数字！虽然序列中的每个数字相对于前一个数字是随机的，但整个序列根本不是随机的！每次运行程序都会产生完全相同的结果。

想象一下，你正在编写一个猜数字游戏，用户有10次机会猜一个随机选取的数字，计算机会告诉用户猜高了还是低了。如果计算机每次都选同一个随机数，那么游戏玩过一次之后就没意思了。所以，让我们深入探讨一下为什么会这样，以及如何解决。

在上一课（8.13 -- 随机数生成简介我们提到过，PRNG序列中的每个数字都是以确定的方式生成的。并且PRNG的状态是从种子值初始化的。因此，给定任何起始种子数，PRNG总是会从该种子生成相同的数字序列。

因为我们是对梅森旋转算法进行值初始化，所以每次程序运行时它都用相同的种子初始化。由于种子相同，生成的随机数也相同。

为了让整个序列在每次程序运行时都随机化，我们需要选择一个不是固定数字的种子。首先想到的答案可能是我们需要一个随机数作为种子！这是个好主意，但如果我们需要随机数来生成随机数，那就陷入了两难境地。事实证明，我们并不真的需要种子是随机数——我们只需要选择一些每次程序运行时都会变化的东西。然后我们可以用PRNG从那个种子生成一个唯一的伪随机数序列。

有两种常用的方法来实现这一点：

  • 使用系统时钟
  • 使用系统的随机设备

使用系统时钟播种

每次运行程序时，有什么东西是不同的？除非你碰巧在同一时刻运行程序两次，否则答案是当前时间不同。因此，如果我们使用当前时间作为种子值，那么程序每次运行时都会产生一组不同的随机数。C和C++长期以来一直使用当前时间（通过 std::time() 函数）来播种PRNG，所以你可能会在很多现有代码中看到这种做法。

幸运的是，C++有一个chrono库，包含各种时钟，我们可以用来生成种子值。为了最小化程序快速连续运行时两个时间值相同的可能性，我们希望使用变化尽可能快的时间度量。为此，我们将询问时钟自其可测量的最早时间以来经过了多少时间。这个时间以“滴答”为单位，这是一个非常小的时间单位（通常是纳秒，但也可能是毫秒）。

#include <iostream>
#include <random> // for std::mt19937
#include <chrono> // for std::chrono

int main()
{
	// 使用steady_clock播种我们的梅森旋转算法
	std::mt19937 mt{ static_cast<std::mt19937::result_type>(
		std::chrono::steady_clock::now().time_since_epoch().count()
		) };

	// 创建一个可重用的随机数生成器，生成1到6之间的均匀数
	std::uniform_int_distribution die6{ 1, 6 }; // 对于C++14，使用 std::uniform_int_distribution<> die6{ 1, 6 };

	// 打印一堆随机数
	for (int count{ 1 }; count <= 40; ++count)
	{
		std::cout << die6(mt) << '\t'; // 在这里生成一次掷骰子

		// 如果已经打印了10个数字，开始新的一行
		if (count % 10 == 0)
			std::cout << '\n';
	}

	return 0;
}

上面的程序与之前相比只有两个变化。首先，我们包含了<chrono>，它让我们能够访问时钟。其次，我们使用时钟的当前时间作为梅森旋转算法的种子值。

这个程序生成的结果现在每次运行时应该都不同，你可以通过多次运行来实验验证。

这种方法的缺点是，如果程序在短时间内连续运行多次，每次运行生成的种子不会有太大差异，这可能会从统计角度影响随机结果的质量。对于普通程序来说，这无关紧要，但对于需要高质量、独立结果的程序，这种播种方法可能不够。

提示

std::chrono::high_resolution_clock 是更受欢迎的选择，而不是 std::chrono::steady_clock。 std::chrono::high_resolution_clock 是使用最精细时间单位的时钟，但它可能使用系统时钟作为当前时间，而系统时钟可以被用户更改或回拨。 std::chrono::steady_clock 可能具有较粗的滴答时间，但它是唯一保证用户无法调整的时钟。

使用随机设备播种

随机库包含一个类型，称为 std::random_device 它是一个实现定义的PRNG。通常我们避免使用实现定义的功能，因为它们没有质量或可移植性的保证，但这是一个例外情况。通常 std::random_device 会向操作系统请求一个伪随机数（具体方式取决于操作系统）。

#include <iostream>
#include <random> // for std::mt19937 and std::random_device

int main()
{
	std::mt19937 mt{ std::random_device{}() };

	// 创建一个可重用的随机数生成器，生成1到6之间的均匀数
	std::uniform_int_distribution die6{ 1, 6 }; // 对于C++14，使用 std::uniform_int_distribution<> die6{ 1, 6 };

	// 打印一堆随机数
	for (int count{ 1 }; count <= 40; ++count)
	{
		std::cout << die6(mt) << '\t'; // 在这里生成一次掷骰子

		// 如果已经打印了10个数字，开始新的一行
		if (count % 10 == 0)
			std::cout << '\n';
	}

	return 0;
}

在上面的程序中，我们用一个临时实例生成的随机数来播种梅森旋转算法。 std::random_device如果你多次运行这个程序，它每次也应该产生不同的结果。

一个潜在的问题是 std::random_device：它不要求是非确定性的，这意味着它 可能在某些系统上每次运行程序时产生相同的序列，而这正是我们试图避免的。曾经有一个 MinGW中的bug （在GCC 9.2中修复）会完全这样，使得 std::random_device 无用。

然而，最新版本的主流编译器（GCC/MinGW、Clang、Visual Studio）都支持正确的实现。 std::random_device。

最佳实践

使用 std::random_device 来播种你的PRNG（除非对于你的目标编译器/架构实现不正确）。

问： std::random_device{}() 是什么意思？

std::random_device{} 创建一个值初始化的临时对象，类型为 std::random_device。这些 () 然后调用 operator() 在该临时对象上，返回一个随机值（我们用它作为梅森旋转算法的初始化器）。

它等价于调用以下函数，该函数使用你应该更熟悉的语法：

unsigned int getRandomDeviceValue()
{
   std::random_device rd{}; // 创建一个值初始化的std::random_device对象
   return rd(); // 将operator()的结果返回给调用者
}

使用 std::random_device{}() 允许我们在不创建命名函数或命名变量的情况下获得相同的结果，因此更加简洁。

问：如果std::random_device本身是随机的，为什么我们不直接使用它而不是梅森旋转算法？

由于 std::random_device 是由实现定义的，我们无法对其做太多假设。访问它可能代价高昂，或者可能导致程序暂停以等待更多随机数可用。它从中抽取的数字池也可能很快耗尽，从而影响其他通过相同方法请求随机数的应用程序的随机结果。因此，std::random_device 更适合用于为其他 PRNG 提供种子，而不是作为 PRNG 本身使用。

只对 PRNG 播种一次

许多 PRNG 在初始播种后可以重新播种。这本质上是重新初始化随机数生成器的状态，使其从新的种子状态开始生成结果。除非有特定原因，否则通常应避免重新播种，因为这可能导致结果随机性降低，甚至完全不随机。

最佳实践

只对给定的伪随机数生成器播种一次，并且不要重新播种。

下面是一个新手程序员常犯错误的例子：

#include <iostream>
#include <random>

int getCard()
{
    std::mt19937 mt{ std::random_device{}() }; // 每次调用函数时都会创建并播种
    std::uniform_int_distribution card{ 1, 52 };
    return card(mt);
}

int main()
{
    std::cout << getCard() << '\n';

    return 0;
}

在 getCard() 函数中，每次调用该函数时都会创建并播种随机数生成器。这至少是低效的，并且很可能导致随机结果不佳。

梅森旋转算法与种子不足问题

梅森旋转算法的内部状态需要 19937 位（2493 字节），即 624 个 32 位值或 312 个 64 位值。因此， std::mt19937 分配 624 个整数，而 std::mt19937_64 分配 312 个整数。

顺便说一句……

由 std::mt19937 分配的整数被定义为类型 std::uint_fast32_t，根据架构的不同，它可能是 32 位或 64 位整数。如果 std::uint_fast32_t 解析为 64 位整数， std::mt19937 将使用 624 个 64 位整数，使其大小翻倍。

在上面的例子中，我们使用时钟或 std::random_device 为我们的 std::mt19937 播种，我们的种子只是一个整数。这意味着我们实际上是用一个整数初始化 624 个整数，这严重地使梅森旋转算法 PRNG 种子不足。随机库尽力用“随机”数据填充剩余的 623 个值……但它无法创造奇迹。种子不足的 PRNG 生成的结果对于需要最高质量结果的应用来说可能不是最优的。例如，用单个 32 位值为 std::mt19937 播种将永远不会生成数字 42 作为其第一个输出。

那么如何解决这个问题呢？截至 C++20，没有简单的方法。但我们有一些建议。

首先，我们来谈谈 std::seed_seq （代表“种子序列”）。在上一课中，我们提到理想情况下我们希望种子数据与 PRNG 的状态位数一样多，否则我们的 PRNG 将种子不足。但在许多情况下（尤其是当我们的 PRNG 状态很大时），我们没有那么多随机化的种子数据位。

std::seed_seq 是一种旨在帮助解决这个问题的类型。我们可以向它传递尽可能多的随机化值，然后它会生成尽可能多的额外无偏种子值来初始化 PRNG 的状态。如果你用一个值（例如来自 std::seed_seq ）初始化 std::random_device，然后用该 std::seed_seq 对象初始化梅森旋转算法， std::seed_seq 将生成 623 个额外的种子数据值。这不会增加随机性，但会给我们更好的 0 和 1 位混合。然而，我们能提供给 std::seed_seq的随机数据越多，它为我们做得越好。所以最简单的想法就是使用 std::random_device 给 std::seed_seq 提供更多数据。如果我们用来自 std::seed_seq 的 8 个值而不是 1 个来初始化 std::random_device ，那么由 std::seed_seq 生成的剩余值应该会好得多：

#include <iostream>
#include <random>

int main()
{
	std::random_device rd{};
	std::seed_seq ss{ rd(), rd(), rd(), rd(), rd(), rd(), rd(), rd() }; // 从std::random_device获取8个整数作为种子
	std::mt19937 mt{ ss }; // 用std::seed_seq初始化我们的梅森旋转算法

	// 创建一个可重用的随机数生成器，生成1到6之间的均匀数
	std::uniform_int_distribution die6{ 1, 6 }; // 对于C++14，使用 std::uniform_int_distribution<> die6{ 1, 6 };

	// 打印一堆随机数
	for (int count{ 1 }; count <= 40; ++count)
	{
		std::cout << die6(mt) << '\t'; // 在这里生成一次掷骰子

		// 如果已经打印了10个数字，开始新的一行
		if (count % 10 == 0)
			std::cout << '\n';
	}

	return 0;
}

这非常简单，所以至少这样做没有太多理由不这么做。

问：为什么不给 std::seed_seq 提供来自 std::random_device？

的 624 个值？你可以这样做，但这可能很慢，并且有耗尽 std::random_device 使用的随机数池的风险。

你也可以使用其他“随机”输入给 std::seed_seq。我们已经向你展示了如何从时钟获取一个值，所以你可以轻松地将其加入。其他有时使用的东西包括当前线程 ID、特定函数的地址、用户 ID、进程 ID 等。这样做超出了本文的范围，但 这篇文章 有一些上下文和链接指向 randutils.hpp 实现了这一点。

另一种方法是使用状态更小的不同PRNG。许多好的PRNG使用64或128位状态，可以通过 std::seed_seq 填充8次调用 std::random_device。

预热PRNG

当PRNG被赋予低质量的种子（或种子不足）时，PRNG的初始结果可能质量不高。因此，一些PRNG受益于“预热”，这是一种丢弃PRNG生成的前N个结果的技术。这允许PRNG的内部状态充分混合，使得后续结果质量更高。通常丢弃几百到几千个初始结果。PRNG的周期越长，应丢弃的初始结果越多。

顺便说一句……

Visual Studio实现的 rand() 曾经（或仍然？）有一个bug，导致第一个生成的结果不够随机。你可能会看到旧程序使用 rand() 丢弃一个结果来避免这个问题。

浮点类型的 seed_seq 初始化使用的 std::mt19937 执行了预热，所以我们不需要显式预热 std::mt19937 对象。

调试使用随机数的程序

使用随机数的程序可能难以调试，因为程序每次运行时可能表现出不同的行为。在这种情况下，错误行为可能发生，也可能不发生。这可能会浪费大量时间。调试时，确保程序每次以相同（错误）的方式执行是有帮助的。这样，你可以根据需要多次运行程序来隔离错误所在。

因此，在调试时，一种有用的技术是用一个特定的固定值（例如 5）来播种PRNG，该值会导致错误行为发生。如果给定的种子没有导致程序出现错误，继续递增种子值直到找到一个能导致错误的种子。这将确保你的程序每次生成相同的结果，使调试更容易。一旦找到错误，你可以使用正常的播种方法再次开始生成随机结果。

随机数常见问题

问：救命！我的随机数生成器每次生成相同的随机数序列。

如果你的随机数生成器每次程序运行时生成相同的随机数序列，你可能没有正确播种（或根本没有播种）。确保你用一个每次程序运行时都会改变的值来播种。

问：救命！我的随机数生成器不断生成相同的数字。

如果你的随机数生成器每次请求随机数时都生成相同的数字，那么你可能在生成随机数之前重新播种了随机数生成器，或者为每个随机数创建了一个新的随机生成器。
