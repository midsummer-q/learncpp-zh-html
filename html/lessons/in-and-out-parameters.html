12.13 — 输入和输出参数

● 机器译文 课程 12.13 查看英文原文

函数及其调用者通过两种机制相互通信：参数和返回值。当函数被调用时，调用者提供实参，函数通过其形参接收这些实参。这些实参可以通过值、引用或地址传递。

通常，我们会通过值或 const 引用传递实参。但有时我们可能需要以其他方式传递。

输入参数

在大多数情况下，函数形参仅用于接收来自调用者的输入。仅用于接收调用者输入的形参有时被称为 输入参数。

#include <iostream>

void print(int x) // x 是输入参数
{
    std::cout << x << '\n';
}

void print(const std::string& s) // s 是输入参数
{
    std::cout << s << '\n';
}

int main()
{
    print(5);
    std::string s { "Hello, world!" };
    print(s);

    return 0;
}

输入参数通常通过值或 const 引用传递。

输出参数

通过非 const 引用（或指向非 const 的指针）传递的函数实参允许函数修改作为实参传入的对象的值。这提供了一种方式，使得在由于某种原因使用返回值不足够的情况下，函数可以将数据返回给调用者。

仅用于向调用者返回信息的函数形参称为 输出参数。

例如：

#include <cmath>    // for std::sin() and std::cos()
#include <iostream>

// sinOut 和 cosOut 是输出参数
void getSinCos(double degrees, double& sinOut, double& cosOut)
{
    // sin() 和 cos() 接受弧度而非角度，因此需要转换
    constexpr double pi { 3.14159265358979323846 }; // π 的值
    double radians = degrees * pi / 180.0;
    sinOut = std::sin(radians);
    cosOut = std::cos(radians);
}
 
int main()
{
    double sin { 0.0 };
    double cos { 0.0 };
 
    double degrees{};
    std::cout << "Enter the number of degrees: ";
    std::cin >> degrees;

    // getSinCos 将返回 sin 和 cos 到变量 sin 和 cos 中
    getSinCos(degrees, sin, cos);
 
    std::cout << "The sin is " << sin << '\n';
    std::cout << "The cos is " << cos << '\n';

    return 0;
}

该函数有一个形参 degrees （其实参通过值传递）作为输入，并“返回”两个形参（通过引用）作为输出。

我们给这些输出参数添加了后缀“out”以表示它们是输出参数。这有助于提醒调用者，传递给这些参数的初始值无关紧要，并且我们应该期望它们被覆盖。按照惯例，输出参数通常是右侧的参数。

让我们更详细地探讨这是如何工作的。首先，main 函数创建局部变量 sin 和 cos。这些变量通过引用（而不是值）传递给函数 getSinCos() 这意味着函数 getSinCos() 可以访问实际的 sin 和 cos 变量在 main()中，而不仅仅是副本。 getSinCos() 相应地给 sin 和 cos （通过引用 sinOut 和 cosOut 分别）赋予新值，这会覆盖 sin 和 cos。函数 main() 中的旧值。

如果 sin 和 cos 如果通过值而不是引用传递， getSinCos() 会改变 sin 和 cos的副本，导致任何更改在函数结束时被丢弃。但由于 sin 和 cos 是通过引用传递的，对 sin 或 cos （通过引用）所做的任何更改都会在函数之外持续存在。因此，我们可以使用这种机制将值返回给调用者。

输出参数具有不自然的使用语法

输出参数虽然功能正常，但有一些缺点。

首先，调用者必须实例化（并初始化）对象并将它们作为实参传递，即使它不打算使用它们。这些对象必须能够被赋值，这意味着它们不能是 const 的。

其次，由于调用者必须传入对象，这些值不能用作临时对象，也不容易在单个表达式中使用。

以下示例展示了这两个缺点：

#include <iostream>

int getByValue()
{
    return 5;
}

void getByReference(int& x)
{
    x = 5;
}

int main()
{
    // 按值返回
    [[maybe_unused]] int x{ getByValue() }; // 可用于初始化对象
    std::cout << getByValue() << '\n';      // 可在表达式中使用临时返回值

    // 通过输出参数返回
    int y{};                // 必须首先分配一个可赋值的对象
    getByReference(y);      // 然后传递给函数以赋值所需的值
    std::cout << y << '\n'; // 然后才能使用该值

    return 0;
}

如您所见，使用输出参数的语法有点不自然。

通过引用传递的输出参数并不明显表明实参将被修改

当我们把函数的返回值赋给一个对象时，很明显该对象的值正在被修改：

x = getByValue(); // 明显 x 被修改

这很好，因为它清楚地表明我们应该期望 x 改变。

然而，让我们再次看看上面例子中对 getSinCos() 的函数调用：

    getSinCos(degrees, sin, cos);

从这个函数调用中并不清楚 degrees 是输入参数，而 sin 和 cos 是输出参数。如果调用者没有意识到 sin 和 cos 会被修改，就很可能导致语义错误。

在某些情况下，使用按地址传递而不是按引用传递，可以通过要求调用者将对象的地址作为参数传入，使输出参数更加明显。

考虑以下示例：

void foo1(int x);  // 按值传递
void foo2(int& x); // 按引用传递
void foo3(int* x); // 按地址传递

int main()
{
    int i{};
 
    foo1(i);  // 不能修改 i
    foo2(i);  // 可以修改 i（不明显）
    foo3(&i); // 可以修改 i

    int *ptr { &i };
    foo3(ptr); // 可以修改 i（不明显）

    return 0;
}

注意，在调用 foo3(&i)时，我们必须传入 &i 对于这个程序，我们有 3 个任务：获取初始塔高，计算球的当前高度，以及打印球的当前高度。根据函数应只做一件事的最佳实践，我们为每个任务编写不同的函数。 i，这有助于更清楚地表明我们应预期 i 会被修改。

然而，这并非万无一失，因为 foo3(ptr) 的前向声明允许 foo3() 来修改 i ，并且不要求调用者取 ptr。

的地址。调用者可能还认为可以传入 nullptr 或空指针作为有效参数，而实际上这是不允许的。而且函数现在需要进行空指针检查和错误处理，这增加了复杂性。这种额外空指针处理的需求往往比坚持使用按引用传递带来更多问题。

基于所有这些原因，除非没有其他好的选择，否则应避免使用输出参数。

最佳实践

避免使用输出参数（除非在极少数情况下没有更好的选择）。

对于非可选的输出参数，优先使用按引用传递。

输入/输出参数

在极少数情况下，函数会在覆盖输出参数的值之前实际使用它的值。这样的参数称为 输入-输出参数。输入-输出参数的工作方式与输出参数完全相同，并且面临所有相同的挑战。

何时按非const引用传递

如果你打算通过引用传递来避免复制参数，那么几乎总是应该按const引用传递。

作者注

在下面的例子中，我们将使用 Foo 来表示我们关心的某种类型。目前，你可以将 Foo 视为你选择的类型的类型别名（例如， std::string)。

然而，有两种主要情况可能更适合使用按非const引用传递。

首先，当参数是输入-输出参数时，使用按非const引用传递。既然我们已经传入了需要返回的对象，通常更直接且性能更好的方式是直接修改该对象。

void someFcn(Foo& inout)
{
    // 修改 inout
}

int main()
{
    Foo foo{};
    someFcn(foo); // 此调用后 foo 被修改，可能不明显

    return 0;
}

给函数起一个好名字会有所帮助：

void modifyFoo(Foo& inout)
{
    // 修改 inout
}

int main()
{
    Foo foo{};
    modifyFoo(foo); // 此调用后 foo 被修改，稍微明显

    return 0;
}

另一种选择是像往常一样按值或const引用传递对象，并通过值返回一个新对象，然后调用者可以将其赋值回原始对象：

Foo someFcn(const Foo& in)
{
    Foo foo { in }; // 在此处复制
    // 修改 foo
    return foo;
}

int main()
{
    Foo foo{};
    foo = someFcn(foo); // 使 foo 被修改变得明显，但此处又进行了一次复制

    return 0;
}

这样做的好处是使用了更传统的返回语法，但需要额外进行两次复制（有时编译器可以优化掉其中一次复制）。

其次，当函数本应通过值向调用者返回一个对象，但复制该对象的代价 极其 高昂时，使用按非const引用传递。特别是在性能关键的代码段中多次调用该函数时。

void generateExpensiveFoo(Foo& out)
{
    // 修改 out
}

int main()
{
    Foo foo{};
    generateExpensiveFoo(foo); // 此调用后 foo 被修改

    return 0;
}

进阶读者

上述情况最常见的例子是，当函数需要用数据填充大型C风格数组或 std::array ，且数组的元素类型复制成本高昂时。我们将在后续章节讨论数组。

尽管如此，很少有对象的复制成本高到值得采用非传统的方法来返回这些对象。
