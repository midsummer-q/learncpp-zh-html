14.2 — 类简介

● 机器译文 课程 14.2 查看英文原文

在上一章中，我们介绍了结构体（13.7 课——结构体、成员和成员选择简介中介绍结构体。），并讨论了它们如何将多个成员变量打包成一个对象，该对象可以作为一个整体进行初始化和传递。换句话说，结构体为存储和移动相关数据值提供了一个便捷的封装。

考虑以下结构体：

#include <iostream>

struct Date
{
    int day{};
    int month{};
    int year{};
};

void printDate(const Date& date)
{
    std::cout << date.day << '/' << date.month << '/' << date.year; // 假设 DMY 格式
}

int main()
{
    Date date{ 4, 10, 21 }; // 使用聚合初始化进行初始化
    printDate(date);        // 可以将整个结构体传递给函数

    return 0;
}

在上面的例子中，我们创建了一个 Date 对象，然后将其传递给一个打印日期的函数。该程序输出：

4/10/21

提醒

在这些教程中，我们所有的结构体都是聚合体。我们在第 13.8 -- 结构体聚合初始化。

课中讨论了聚合体。尽管结构体很有用，但它们存在一些缺陷，在尝试构建大型复杂程序（尤其是由多个开发人员共同开发的程序）时可能会带来挑战。

类不变式问题

结构体最大的困难可能是它们没有提供有效的方式来记录和强制执行类不变式。在第 9.6 -- Assert 和 static_assert课中，我们将不变式定义为“某个组件执行时必须为真的条件”。

在类类型（包括结构体、类和联合体）的上下文中， 类不变式 是在对象的整个生命周期中必须保持为真的条件，以便对象保持有效状态。违反类不变式的对象被称为处于 无效状态，进一步使用该对象可能导致意外或未定义行为。

关键提示

使用类不变式被违反的对象可能导致意外或未定义行为。

首先，考虑以下结构体：

struct Pair
{
    int first {};
    int second {};
};

浮点类型的 first 和 second 成员可以独立设置为任何值，因此 Pair 结构体没有不变式。

现在考虑以下几乎相同的结构体：

struct Fraction
{
    int numerator { 0 };
    int denominator { 1 };
};

我们从数学上知道，分母为 0 的分数在数学上是未定义的（因为分数的值等于分子除以分母——而除以 0 在数学上是未定义的）。因此，我们希望确保 Fraction 对象的 denominator 成员永远不会被设置为 0。如果被设置了，那么该 Fraction 对象就处于无效状态，进一步使用该对象可能导致未定义行为。

例如：

#include <iostream>

struct Fraction
{
    int numerator { 0 };
    int denominator { 1 }; // 类不变式：不应为 0
};

void printFractionValue(const Fraction& f)
{
     std::cout << f.numerator / f.denominator << '\n';
}

int main()
{
    Fraction f { 5, 0 };   // 创建一个分母为零的 Fraction
    printFractionValue(f); // 导致除以零错误

    return 0;
}

在上面的例子中，我们使用注释来记录 Fraction 的不变式。我们还提供了一个默认成员初始化器，以确保如果用户没有提供初始化值，分母被设置为 1 这确保了如果用户决定值初始化一个 Fraction 对象，我们的 Fraction 对象将是有效的。这是一个不错的开始。

但没有什么能阻止我们显式违反这个类不变式：当我们创建 Fraction f时，我们使用聚合初始化显式地将分母初始化为 0。虽然这不会立即导致问题，但我们的对象现在处于无效状态，进一步使用该对象可能导致意外或未定义行为。

这正是我们稍后调用 printFractionValue(f)时所看到的：程序因除以零错误而终止。

顺便说一句……

一个小的改进是在 assert(f.denominator != 0); 的函数体顶部添加 printFractionValue。这为代码增加了文档价值，并使违反的前置条件更加明显。然而，在行为上，这并没有真正改变什么。我们真正想要的是在问题的源头（当成员被初始化或赋值为错误值时）捕获这些问题，而不是在下游（当错误值被使用时）。

鉴于 Fraction 示例的相对简单性，避免创建无效的 Fraction 对象应该不会太难。然而，在更复杂的代码库中，使用许多结构体、具有许多成员的结构体或成员关系复杂的结构体时，理解哪些值的组合可能违反某些类不变式可能并不那么明显。

更复杂的类不变式

Fraction 的类不变式很简单—— denominator 成员不能为 0这在概念上容易理解，并且不难避免。

当结构体的成员必须具有相关值时，类不变性变得更加具有挑战性。

#include <string>

struct Employee
{
    std::string name { };
    char firstInitial { }; // 应始终保存 `name` 的第一个字符（或 `0`）
};

在上述（设计不佳的）结构体中，存储在成员 firstInitial 中的字符值应始终与 name。

的第一个字符匹配。当 Employee 对象被初始化时，用户负责确保类不变性得以维护。并且如果 name 被赋予新值，用户也负责确保 firstInitial 也被更新。这种关联对于使用 Employee 对象的开发者来说可能并不明显，即使明显，他们也可能会忘记这样做。

即使我们编写函数来帮助创建和更新 Employee 对象（确保 firstInitial 始终从 name的第一个字符设置），我们仍然依赖用户了解并使用这些函数。

简而言之，依赖对象的用户来维护类不变性很可能导致有问题的代码。

关键提示

依赖对象的用户来维护类不变性很可能导致问题。

理想情况下，我们希望使我们的类类型坚不可摧，使得对象要么无法进入无效状态，要么能够立即发出信号（而不是让未定义行为在未来的某个随机点发生）。

结构体（作为聚合体）根本没有必要的机制来优雅地解决这个问题。

类简介

在开发 C++ 时，Bjarne Stroustrup 希望引入一些能力，使开发者能够创建更直观使用的程序定义类型。他还对寻找优雅的解决方案感兴趣，以解决困扰大型复杂程序的常见陷阱和维护挑战（例如前面提到的类不变性问题）。

借鉴他在其他编程语言（特别是 Simula，第一种面向对象编程语言）的经验，Bjarne 确信可以开发一种足够通用和强大的程序定义类型，几乎可以用于任何事情。为了向 Simula 致敬，他将这种类型称为 class。

就像结构体一样， class 是一种程序定义的复合类型，可以拥有多个不同类型的成员变量。

关键提示

从技术角度来看，结构体和类几乎相同——因此，任何使用结构体实现的示例都可以使用类实现，反之亦然。然而，从实践角度来看，我们使用结构体和类的方式不同。

因为类是一种程序定义的数据类型，所以必须在使用之前定义它。类的定义与结构体类似，只是我们使用 class 关键字而不是 struct。例如，这是一个简单员工类的定义：

class Employee
{
    int m_id {};
    int m_age {};
    double m_wage {};
};

中讨论为什么类的成员变量通常以“m_”为前缀。为了展示类和结构体有多么相似，以下程序与本课程开头展示的程序等效，但 Date 现在是一个类而不是结构体：

#include <iostream>

class Date       // 我们将 struct 改为 class
{
public:          // 并添加了这一行，称为访问说明符
    int m_day{}; // 并为每个成员名称添加了 "m_" 前缀
    int m_month{};
    int m_year{};
};

void printDate(const Date& date)
{
    std::cout << date.m_day << '/' << date.m_month << '/' << date.m_year;
}

int main()
{
    Date date{ 4, 10, 21 };
    printDate(date);

    return 0;
}

这会打印：
