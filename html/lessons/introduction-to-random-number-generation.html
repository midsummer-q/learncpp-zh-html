8.13 — 随机数生成简介

● 机器译文 课程 8.13 查看英文原文

生成随机数的能力在某些类型的程序中非常有用，尤其是在游戏、统计建模程序以及需要加密和解密数据的加密应用中。以游戏为例——如果没有随机事件，怪物总是以相同的方式攻击你，你总是找到相同的宝藏，地牢布局永远不会改变，等等……那将不会是一个好游戏。

在现实生活中，我们通常通过抛硬币、掷骰子或洗牌等方式来产生随机性。这些事件实际上并不是随机的，但涉及如此多的物理变量（例如重力、摩擦力、空气阻力、动量等），以至于它们几乎无法预测或控制，并且（除非你是魔术师）产生的结果在各方面都是随机的。

然而，计算机并不是为了利用物理变量而设计的——你的计算机不能抛硬币、掷骰子或洗真正的牌。现代计算机生活在一个受控的电气世界中，一切都是二进制的（0或1），没有中间状态。就其本质而言，计算机被设计成产生尽可能可预测的结果。当你告诉计算机计算 2 + 2 时，你 总是 希望答案是 4。而不是偶尔的 3 或 5。

因此，计算机通常无法生成真正的随机数（至少通过软件）。相反，现代程序通常 模拟 使用算法来模拟随机性。

在本课中，我们将介绍程序中随机数生成背后的许多理论，并介绍一些我们将在未来课程中使用的术语。

算法与状态

首先，让我们绕道了解一下算法和状态的概念。

一种 算法 是一个有限的指令序列，可以遵循这些指令来解决某个问题或产生一些有用的结果。

例如，假设你的老板给你一个包含一堆未排序名字的小文本文件（每行一个），并要求你对列表进行排序。由于列表很小，而且你不打算经常这样做，你决定手动排序。有多种方法可以对列表进行排序，但你可以这样做：

  • 创建一个新的空列表来保存排序后的结果
  • 扫描未排序的名字列表，找到按字母顺序排在最前面的名字
  • 将该名字从未排序列表中剪切出来，并粘贴到排序列表的底部
  • 重复前两个步骤，直到未排序列表中没有名字为止

上述步骤描述了一个排序算法（使用自然语言）。本质上，算法是可重用的——如果你的老板明天要求你排序另一个列表，你可以将相同的算法应用于新列表。

由于计算机执行指令和处理数据的速度比我们快得多，算法通常用编程语言编写，使我们能够自动化任务。在 C++ 中，算法通常实现为可重用的函数。

这是一个生成数字序列的简单算法，其中每个连续的数字递增 1：

#include <iostream>

int plusOne()
{
    static int s_state { 3 }; // 仅在首次调用此函数时初始化

    // 生成下一个数字

    ++s_state;      // 首先我们修改状态
    return s_state; // 然后我们使用新状态生成序列中的下一个数字
}

int main()
{
    std::cout << plusOne() << '\n';
    std::cout << plusOne() << '\n';
    std::cout << plusOne() << '\n';

    return 0;
}

这会打印：

4
5
6

这个算法非常简单。第一次调用 plusOne()， s_state 被初始化为值 3。然后生成并返回输出序列中的下一个数字。

如果一个算法在调用之间保留了一些信息，则认为它是 有状态的 相反， 无状态的 算法不存储任何信息（并且每次调用时必须提供其工作所需的所有信息）。我们的 plusOne() 函数是有状态的，因为它使用静态变量 s_state 来存储最后生成的数字。当应用于算法时，术语 状态 指的是有状态变量（那些在调用之间保留的变量）中保存的当前值。

为了生成序列中的下一个数字，我们的算法使用了一个两步过程：

  • 首先，当前状态（从起始值初始化，或从先前调用中保留）被修改以产生新状态。
  • 然后，从新状态生成序列中的下一个数字。

我们的算法被认为是 确定性的，这意味着对于给定的输入（为 start提供的值），它总是产生相同的输出序列。

伪随机数生成器（PRNG）

为了模拟随机性，程序通常使用伪随机数生成器。 伪随机数生成器（PRNG） 是一种算法，它生成一个数字序列，其属性模拟随机数序列。

编写一个基本的PRNG算法很容易。下面是一个简短的PRNG示例，生成100个16位伪随机数：

#include <iostream>

// 仅供说明之用，请勿使用此代码
unsigned int LCG16() // 我们的PRNG
{
    static unsigned int s_state{ 0 }; // 仅在首次调用此函数时初始化

    // 生成下一个数字

    // 我们使用大常数和故意溢出修改状态，以使
    // 他人难以随意确定序列中的下一个数字。

    s_state = 8253729 * s_state + 2396403; // 首先我们修改状态
    return s_state % 32768; // 然后我们使用新状态生成序列中的下一个数字
}

int main()
{
    // 打印100个随机数
    for (int count{ 1 }; count <= 100; ++count)
    {
        std::cout << LCG16() << '\t';

        // 如果已经打印了10个数字，开始新的一行
        if (count % 10 == 0)
            std::cout << '\n';
    }

    return 0;
}

注意 LCG16() 与上面的 plusOne() 示例有多么相似！状态初始设置为值 0。然后，为了生成输出序列中的下一个数字，当前状态被修改（通过应用一些数学运算）以产生新状态，并从该新状态生成序列中的下一个数字。

事实证明，这个特定的算法作为随机数生成器并不太好（注意每个结果如何在偶数和奇数之间交替——这不太随机！）。但大多数PRNG的工作方式与 LCG16() 类似——它们通常使用更多的状态变量和更复杂的数学运算来生成更高质量的结果。

播种PRNG

PRNG生成的“随机数”序列根本不是随机的。就像我们的 plusOne() 函数内部， LCG16() 也是确定性的。给定某个初始状态值（例如 0），PRNG每次都会生成相同的数字序列。如果你运行上述程序3次，你会发现它每次生成相同的值序列。

为了生成不同的输出序列，PRNG的初始状态需要变化。用于设置PRNG初始状态的值（或一组值）称为 随机种子 （或 种子 （简称种子）。当PRNG的初始状态使用种子设置后，我们说它已被 播种。

关键提示

因为PRNG的初始状态由种子值设置，PRNG将产生的所有值都是从种子值确定性地计算出来的。

种子值通常由使用PRNG的程序提供。下面是一个示例程序，它从用户请求一个种子值，然后使用该种子值生成10个随机数（使用我们的 LCG16() 函数）。

#include <iostream>

unsigned int g_state{ 0 };

void seedPRNG(unsigned int seed)
{
    g_state = seed;
}

// 仅供说明之用，请勿使用此代码
unsigned int LCG16() // 我们的PRNG
{
    // 我们使用大常数和故意溢出修改状态，以使
    // 他人难以随意确定序列中的下一个数字。

    g_state = 8253729 * g_state + 2396403; // 首先我们修改状态
    return g_state % 32768; // 然后我们使用新状态生成序列中的下一个数字
}

void print10()
{
    // 打印10个随机数
    for (int count{ 1 }; count <= 10; ++count)
    {
        std::cout << LCG16() << '\t';
    }   

    std::cout << '\n';
}

int main()
{
    unsigned int x {};
    std::cout << "Enter a seed value: ";
    std::cin >> x;

    seedPRNG(x); // 为我们的PRNG播种
    print10();   // 生成10个随机值

    return 0;
}

种子质量和欠播种

如果我们希望程序每次运行时产生不同的随机数，那么我们需要某种方法来每次运行时改变种子。要求用户提供种子值并不好，因为他们每次都可以输入相同的值。程序确实需要某种方法来每次运行时生成随机化的种子值。不幸的是，我们不能使用PRNG来生成随机种子，因为我们需要随机化的种子来生成随机数。相反，我们通常会使用一种设计用于产生种子值的种子生成算法。我们将在下一课中讨论（并实现）这样的算法。

PRNG可以生成的唯一序列的理论最大数量由PRNG状态的位数决定。例如，一个具有128位状态的PRNG理论上可以生成多达2^128（340,282,366,920,938,463,463,374,607,431,768,211,456）个唯一的输出序列。这很多！

然而，生成哪个输出序列 实际 取决于PRNG的初始状态，而初始状态由种子决定。因此，实际上，PRNG可以 实际 生成的唯一输出序列的数量受限于使用PRNG的程序可以提供的唯一种子值的数量。例如，如果某个种子生成算法只能生成4个不同的种子值，那么PRNG最多只能生成4个不同的输出序列。

如果PRNG没有获得足够数量的高质量种子数据，我们说它是 欠播种的。欠播种的PRNG可能开始产生质量以某种方式受损的随机化结果——欠播种越严重，结果质量受损越严重。

例如，欠播种的PRNG可能表现出以下任何问题：

  • 连续运行生成的随机序列可能彼此高度相关。
  • 在生成第N个随机数时，某些值永远无法生成。例如，以特定方式欠播种的梅森旋转算法将永远不会生成值7或13作为其第一个输出。
  • 有人可能根据生成的初始随机值（或前几个随机值）猜出种子。这将使他们能够生成生成器将要生成的所有未来随机数。这可能使他们能够作弊或操纵系统。

进阶读者

理想的种子应具有以下特征：

  • 种子应至少包含与PRNG状态相同数量的位，以便PRNG状态中的每一位都可以由种子中的独立位初始化。
  • 种子中的每一位应独立随机化。
  • 种子应在所有位中均匀分布0和1。
  • 种子中不应有始终为0或始终为1的位。这些“固定位”不提供任何价值。
  • 种子应与先前生成的种子具有低相关性。

在实践中，我们可能会在某些特性上妥协。一些PRNG具有巨大的状态（例如，梅森旋转算法的状态有19937位），生成如此大的高质量种子可能很困难。因此，具有大状态的PRNG通常被设计为能够容忍用较少位数进行播种。粘滞位也很常见。例如，如果我们使用系统时钟作为种子的一部分，最终会得到一些粘滞位，因为表示较大时间单位（如年）的位实际上是粘滞的。

不熟悉正确播种实践的开发者常常尝试使用单个32位或64位值来初始化PRNG（不幸的是，C++标准随机库的设计无意中鼓励了这种做法）。这通常会导致PRNG严重欠播种。

用64字节的优质种子数据播种PRNG（如果PRNG状态较小，则更少）通常足以生成8字节的随机值，用于非敏感用途（例如，非统计模拟或密码学）。

什么造就了一个好的PRNG？（可选阅读）

为了成为一个好的PRNG，PRNG需要具备若干特性：

  • PRNG应以大致相同的概率生成每个数。

这称为分布均匀性。如果某些数比其他数更频繁地生成，使用该PRNG的程序的结果将会有偏差！为了检查分布均匀性，我们可以使用直方图。直方图是一种跟踪每个数被生成次数的图表。由于我们的直方图是基于文本的，我们将使用*符号来表示每个给定数被生成一次。

考虑一个生成1到6之间数字的PRNG。如果我们生成36个数，一个具有分布均匀性的PRNG应该生成类似这样的直方图：

4|******
5|******
6|******

或者这样：

甚至可能这样：

假设你正在为游戏编写一个随机物品生成器。当怪物被杀死时，你的代码生成一个1到6之间的随机数，如果结果是6，怪物会掉落稀有物品而不是普通物品。你期望这种情况发生的概率是1/6。但如果底层的PRNG不均匀，生成的6比应有的多得多（像上面的第二个直方图），你的玩家最终会得到比你预期更多的稀有物品，可能使游戏难度变得微不足道，或者破坏游戏内经济。

找到产生均匀结果的PRNG算法是困难的。

  • 生成序列中下一个数的方法不应是可预测的。

例如，考虑以下PRNG算法： return ++num这个PRNG完全均匀，但也完全可预测——作为随机数序列并不十分有用！

即使那些看起来随机的数字序列（例如上述 LCG16() 的输出）对于有动机的人来说也可能很容易预测。通过检查从上述 LCG16() 函数生成的几个数字，就有可能确定用于修改状态的常量（8253729 和 2396403）。一旦知道这些，就可以轻松计算该PRNG将生成的所有未来数字。

现在，想象你经营一个博彩网站，用户可以在上面下注100美元。你的网站生成一个0到32767之间的随机数。如果数字大于20000，客户获胜，你返还双倍赌注。否则，他们输掉，你保留赌注。由于客户只有12767/32767（39%）的胜率，你的网站应该能赚很多钱，对吧？然而，如果客户能够确定接下来会生成哪些数字，他们就可以策略性地下注，从而总是（或通常）获胜。恭喜，现在你可以申请破产了！

  • PRNG应具有良好的数字维度分布。

这意味着PRNG应在整个可能结果范围内随机返回数字。例如，PRNG应看似随机地生成低数字、中数字、高数字、偶数和奇数。

一个先返回所有低数字，然后所有高数字的PRNG可能是均匀且不可预测的，但它仍然会导致有偏差的结果，特别是当你实际使用的随机数数量很少时。

  • PRNG应对所有种子具有高周期

所有PRNG都是周期性的，这意味着在某个时刻，生成的数字序列将开始重复。PRNG开始重复之前的序列长度称为 周期。

你会注意到，它生成了9作为第二个数字，再次作为第16个数字，然后每14个数字之后重复。这个PRNG陷入了重复生成以下序列：9-130-97-64-31-152-119-86-53-20-141-108-75-42-（重复）。

这是因为PRNG是确定性的。一旦PRNG的状态与先前状态相同，PRNG将开始产生与之前相同的输出序列——导致循环。

一个好的PRNG应对所有 所有 种子数具有长周期。设计满足这一特性的算法可能极其困难——许多PRNG仅对某些种子具有长周期，而对其他种子则不然。如果用户恰好选择了导致状态周期短的种子，那么当需要大量随机数时，PRNG将无法很好地工作。

  • PRNG应高效

大多数PRNG的状态大小小于4096字节，因此总内存使用通常不是问题。然而，内部状态越大，PRNG越可能欠播种，并且初始播种速度越慢（因为需要初始化更多状态）。

其次，为了生成序列中的下一个数，PRNG必须通过应用各种数学运算来混合其内部状态。这需要的时间因PRNG和架构而异（某些PRNG在某些架构上表现更好）。如果你只是偶尔生成随机数，这并不重要，但如果你需要大量随机性，则会产生巨大影响。

有许多不同类型的PRNG算法

多年来，已经开发了许多不同类型的PRNG算法（维基百科有一个很好的列表 这里）。每种PRNG算法都有其优缺点，可能使其更适合或不适合特定应用，因此为你的应用选择合适的算法很重要。

许多PRNG现在被认为相对较差——既然使用一个性能良好的PRNG同样容易，就没有理由使用性能不佳的PRNG。

那么我们应该使用梅森旋转算法，对吗？

很可能。对于大多数应用来说，梅森旋转算法在性能和品质方面都表现良好。

然而，值得注意的是，按照现代PRNG标准，梅森旋转算法已经 有些过时了。梅森旋转算法最大的问题在于，其生成的结果在观察到624个数字后就可以被预测，因此不适用于任何需要不可预测性的应用。

如果你正在开发一个需要最高质量随机结果（例如统计模拟）、最快速度，或者需要不可预测性（例如密码学）的应用，那么你需要使用第三方库。

截至撰写本文时，流行的选择包括：

  • 浮点类型的 Xoshiro系列 和 Wyrand 用于非密码学PRNG。
  • 浮点类型的 Chacha系列 用于密码学（不可预测）PRNG。
