5.2 — 字面量

● 机器译文 课程 5.2 查看英文原文

字面量 是直接插入到代码中的值。例如：

return 5;                     // 5 是一个整数字面量
bool myNameIsAlex { true };   // true 是一个布尔字面量
double d { 3.4 };             // 3.4 是一个 double 字面量
std::cout << "Hello, world!"; // "Hello, world!" 是一个 C 风格字符串字面量

字面量有时被称为 字面常量 ，因为它们的含义不能被重新定义（5 始终表示整数值 5）。

字面量的类型

就像对象有类型一样，所有字面量也有类型。字面量的类型是根据字面量的值推导出来的。例如，一个整数字面量（如 5）被推导为类型 int。

默认情况下：

字面量值技术含义默认字面量类型备注
整数值5, 0, -3整型
布尔值true, falsebool
浮点值1.2, 0.0, 3.4double（不是 float！）
字符'a', '\n'char
C 风格字符串“Hello, world!”const char[14]参见下面的 C 风格字符串字面量部分

字面量后缀

如果字面量的默认类型不符合要求，可以通过添加后缀来改变字面量的类型。以下是一些常见的后缀：

数据类型后缀含义
整型u 或 Uunsigned int
整型l 或 L长整型
整型ul, uL, Ul, UL, lu, lU, Lu, LUunsigned long

大多数情况下，不需要后缀（除了 f)。

相关内容

浮点类型的 s 和 sv 后缀需要额外一行代码才能使用。我们将在课程中进一步介绍这些内容 5.7 -- std::string 简介 和 5.8 -- std::string_view 简介。

其他（很少使用的）后缀用于复数和时间字面量。这些内容记录在 这里。

进阶读者

除了 f 后缀外，后缀最常用于涉及类型推导的情况。参见 10.8 -- 使用 auto 关键字进行对象的类型推导 和 13.14 -- 类模板参数推导（CTAD）和推导指南。

后缀的大小写

大多数后缀不区分大小写。例外情况是：

  • s 和 sv 必须是小写。
  • 两个连续的 l 或 L 字符必须具有相同的大小写（lL 和 Ll 不被接受）。

因为小写的 L 在某些字体中看起来像数字 1 ，一些开发者更喜欢使用大写字面量。其他人则使用小写后缀，除了 L。

最佳实践

优先使用字面量后缀 L（大写）而不是 l（小写）。

整型字面量

通常你不需要为整型字面量使用后缀，但这里有一些例子：

#include <iostream>

int main()
{
    std::cout << 5 << '\n';  // 5（无后缀）默认是 int 类型
    std::cout << 5L << '\n'; // 5L 是 long 类型
    std::cout << 5u << '\n'; // 5u 是 unsigned int 类型

    return 0;
}

在大多数情况下，使用无后缀的 int 字面量是可以的，即使初始化非int 类型：

int main()
{
    int a { 5 };          // ok：类型匹配
    unsigned int b { 6 }; // ok：编译器会将 int 值 6 转换为 unsigned int 值 6
    long c { 7 };         // ok：编译器会将 int 值 7 转换为 long 值 7

    return 0;
}

在这种情况下，编译器会将 int 字面量转换为适当的类型。

在第一种情况下， 5 默认已经是 int ，所以编译器可以直接使用这个值来初始化 int 变量 a。在第二种情况下， int 值 6 与 unsigned int b的类型不匹配。编译器会将 int 值 6 切换到 unsigned int 值 6，然后将其用作 b的初始化器。在第三种情况下， int 值 7 与 long c的类型不匹配。编译器会将 int 值 7 切换到 long 值 7，然后将其用作 c。

浮点字面量

默认情况下，浮点字面量的类型是 double。要使它们成为 float 字面量，应使用 f （或 F）后缀：

#include <iostream>

int main()
{
    std::cout << 5.0 << '\n';  // 5.0（无后缀）默认是 double 类型
    std::cout << 5.0f << '\n'; // 5.0f 是 float 类型

    return 0;
}

新手程序员常常困惑为什么以下代码会导致编译器警告：

float f { 4.1 }; // 警告：4.1 是 double 字面量，不是 float 字面量

因为 4.1 没有后缀，字面量的类型是 double，而不是 float。当编译器确定字面量的类型时，它并不关心你如何使用该字面量（例如，在本例中，用它来初始化一个 float 变量）。由于字面量的类型（double）与它要初始化的变量类型（float）不匹配，字面量值必须转换为 float ，然后才能用于初始化变量 f。将值从 double 转换为 float 可能会导致精度损失，因此编译器会发出警告。

解决方案是以下之一：

float f { 4.1f }; // 使用 'f' 后缀使字面量为 float 类型，以匹配 float 类型的变量
double d { 4.1 }; // 将变量改为 double 类型，以匹配 double 类型的字面量

浮点字面量的科学记数法

有两种不同的方式书写浮点字面量。

  1. 在标准记数法中，我们写一个带小数点的数字：
double pi { 3.14159 }; // 3.14159 是标准记数法中的 double 字面量
double d { -1.23 };    // 字面量可以是负数
double why { 0. };     // 语法上可接受，但应避免，因为小数点难以辨认（推荐使用 0.0）
  1. 在科学记数法中，我们添加一个 e 来表示指数：
double avogadro { 6.02e23 }; // 6.02 x 10^23 是科学记数法中的 double 字面量
double protonCharge { 1.6e-19 }; // 质子的电荷为 1.6 x 10^-19

字符串字面量

在编程中， 字符串 是一系列连续的字符，用于表示文本（如名称、单词和句子）。

你写的第一个C++程序可能看起来像这样：

#include <iostream>
 
int main()
{
    std::cout << "Hello, world!";
    return 0;
}

"Hello, world!" 是一个字符串字面量。字符串字面量放在双引号之间，以标识为字符串（与字符字面量相对，字符字面量放在单引号之间）。

由于字符串在程序中常用，大多数现代编程语言都包含一个基本的字符串数据类型。由于历史原因，字符串不是C++中的基本类型。相反，它们有一个奇怪、复杂的类型，难以使用（我们将在未来的课程中介绍如何/为什么，一旦我们涵盖了更多解释它们工作原理所需的基础知识）。这种字符串通常被称为 C字符串 或 C风格字符串，因为它们继承自C语言。

关于C风格字符串字面量，有两件不太明显的事情值得了解。

  1. 所有C风格字符串字面量都有一个隐式的空终止符。考虑一个字符串如 "hello"。虽然这个C风格字符串看起来只有五个字符，但实际上它有六个： 'h'， 'e'， 'l‘， 'l'， 'o'、和 '\0' （一个ASCII码为0的字符）。这个尾随的'\0'字符是一个特殊字符，称为 空终止符，用于指示字符串的结束。以空终止符结尾的字符串称为 空终止字符串。

进阶读者

这就是字符串 "Hello, world!" 的类型为 const char[14] 对于这个程序，我们有 3 个任务：获取初始塔高，计算球的当前高度，以及打印球的当前高度。根据函数应只做一件事的最佳实践，我们为每个任务编写不同的函数。 const char[13] 的原因——隐藏的空终止符算作一个字符。

空终止符的存在也是历史原因：它可以用来确定字符串的结束位置。

  1. 与大多数其他字面量（它们是值，而不是对象）不同，C风格字符串字面量是const对象，在程序开始时创建，并保证在整个程序期间存在。这个事实在几节课后会变得重要，当我们讨论 std::string_view。

关键提示

C风格字符串字面量是const对象，在程序开始时创建，并保证在整个程序期间存在。

与C风格字符串字面量不同， std::string 和 std::string_view 字面量创建临时对象。这些临时对象必须立即使用，因为它们会在创建它们的完整表达式结束时被销毁。

相关内容

魔法数字

一个 魔法数字 是一个字面量（通常是数字），其含义不明确或以后可能需要更改。

以下是两个展示魔法数字的语句：

const int maxStudentsPerSchool{ numClassrooms * 30 };
setMax(30);

字面量 30 在这些上下文中是什么意思？在前者中，你大概能猜到它是每班的学生人数，但并非一目了然。在后者中，谁知道呢。我们必须去查看函数才能知道它的作用。

在复杂程序中，除非有注释解释，否则很难推断字面量代表什么。

使用魔法数字通常被认为是不好的做法，因为除了不提供它们被用于什么的上下文之外，如果值需要更改，还会带来问题。假设学校购买了新桌子，允许他们将班级人数从30增加到35，我们的程序需要反映这一点。

为此，我们需要将一个或多个字面量从 30 切换到 35更新。但是哪些字面量呢？ 30 在初始化器中的 maxStudentsPerSchool 似乎很明显。但是用作 30 参数的 setMax()呢？那个 30 与另一个 30含义相同吗？如果是，它应该被更新。如果不是，它应该保持不变，否则我们可能会在其他地方破坏程序。如果你进行全局搜索和替换，你可能会无意中更新 setMax() 的参数，而它本不应该改变。因此，你必须查看所有代码中字面量 30 的每个实例（可能有数百个），然后单独判断它是否需要更改。这可能非常耗时（且容易出错）。

幸运的是，缺乏上下文和更新相关的问题都可以通过使用符号常量轻松解决：

const int maxStudentsPerClass { 30 };
const int totalStudents{ numClassrooms * maxStudentsPerClass }; // 现在这个 30 的含义很明显了

const int maxNameLength{ 30 };
setMax(maxNameLength); // 现在这个 30 用于不同的上下文很明显了

常量的名称提供了上下文，我们只需要在一个地方更新值，就可以在整个程序中更改该值。

注意，魔法数字不一定是数字——它们也可以是文本（例如名称）或其他类型：

int main()
{
    printAppWelcome("MyCalculator"); // 不好：应用名称可能在其他地方使用或将来会改变
}

在明显上下文中使用且不太可能更改的字面量通常不被视为魔法。值 -1， 0， 0.0、和 1 经常在这样的上下文中使用：

int idGenerator { 0 };         // 可以：我们以值 0 开始 ID 生成器
idGenerator = idGenerator + 1; // 可以：我们只是在递增生成器

其他数字在上下文中也可能很明显（因此不被视为魔法）：

int kmtoM(int km)
{
    return km * 1000; // 可以：很明显 1000 是一个转换因子
}

连续的整数ID通常也不被视为魔法：

int main()
{
    // 可以：这些只是连续的 ID/计数
    printPlayerInfo(1); // `1` 命名为 `player1` 并不会带来真正的好处
    printPlayerInfo(2);
}

最佳实践

避免在代码中使用魔法数字（改用 constexpr 变量，参见课程 5.6 -- Constexpr 变量)。
