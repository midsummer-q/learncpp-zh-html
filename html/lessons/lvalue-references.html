12.3 — 左值引用

● 机器译文 课程 12.3 查看英文原文

在C++中， 引用 是已存在对象的别名。一旦定义了引用，对引用的任何操作都会应用到被引用的对象上。这意味着我们可以使用引用来读取或修改被引用的对象。

尽管引用起初可能看起来愚蠢、无用或多余，但引用在 C++ 中无处不在（我们将在几节课后看到例子）。

关键提示

引用本质上与被引用的对象相同。

你也可以创建对函数的引用，尽管这不太常见。

现代 C++ 包含两种引用：左值引用和右值引用。在本章中，我们将讨论左值引用。

相关内容

因为在本课中我们会讨论左值和右值，请先复习 12.2 -- Value categories (lvalues and rvalues) 如果你需要回顾这些术语。右值引用将在关于移动语义的章节中介绍（第 22 章)。

左值引用类型

一种 左值引用 （通常简称为“引用”，因为在 C++11 之前只有一种引用）充当现有左值（如变量）的别名。

就像对象的类型决定了它可以保存什么类型的值一样，引用的类型决定了它可以引用什么类型的对象。左值引用类型可以通过在类型说明符中使用单个 & 符号来识别：

// 常规类型
int        // 一个普通的int类型（不是引用）
int&       // 一个指向int对象的左值引用
double&    // 一个指向double对象的左值引用
const int& // 一个指向const int对象的左值引用

例如， int& 是 int 类型对象的左值引用类型，而 int int& const int& 是 double 类型对象的左值引用类型。 const int 播种），我们将其用作全局

指定引用的类型（例如 int&int& 引用类型）称为引用类型。可以被引用的类型（例如 intint ）称为被引用类型。。

术语

有两种左值引用：

  • 对非 const 的左值引用通常简称为“左值引用”，但也可以称为 对非 const 的左值引用 变为 非 const 左值引用 （因为它没有使用 const const 关键字定义）。
  • 对 const 的左值引用通常称为 对 const 的左值引用 变为 const 左值引用。

我们将在本课中重点讨论非 const 左值引用，并在下一课中讨论 const 左值引用（12.4 -- 对 const 的左值引用)。

左值引用变量

我们可以用左值引用类型做的一件事是创建左值引用变量。 左值引用变量 是一个充当左值（通常是另一个变量）引用的变量。

要创建左值引用变量，我们只需定义一个具有左值引用类型的变量：

#include <iostream>

int main()
{
    int x { 5 };    // x是一个普通的整型变量
    int& ref { x }; // ref是一个左值引用变量，现在可以作为变量x的别名使用

    std::cout << x << '\n';  // 打印x的值（5）
    std::cout << ref << '\n'; // 通过ref打印x的值（5）

    return 0;
}

在上面的例子中，类型 int& 定义 ref 为 int 的左值引用，然后用左值表达式 x初始化它。此后， ref 和 x 可以互换使用。因此该程序输出：

5
5

从编译器的角度来看，与号是“附着”在类型名（int& ref）还是变量名（int &ref）上并不重要，选择哪种方式只是风格问题。现代 C++ 程序员倾向于将 & 号放在类型旁边，因为这更清楚地表明引用是类型信息的一部分，而不是标识符。

最佳实践

定义引用时，将 & 号放在类型旁边（而不是引用变量名旁边）。

进阶读者

对于已经熟悉指针的人来说，这里的 & 号并不意味着“取地址”，而是“左值引用”。

通过非 const 左值引用修改值

在上面的例子中，我们展示了可以使用引用来读取被引用对象的值。我们也可以使用非 const 引用来修改被引用对象的值：

#include <iostream>

int main()
{
    int x { 5 }; // 普通的整型变量
    int& ref { x }; // ref现在是变量x的别名

    std::cout << x << ref << '\n'; // 打印55

    x = 6; // x现在的值为6

    std::cout << x << ref << '\n'; // 打印66

    ref = 7; // 被引用的对象（x）现在的值为7

    std::cout << x << ref << '\n'; // 打印77

    return 0;
}

这段代码打印：

55
66
77

在上面的例子中， ref 是 x，因此我们能够通过 x 或 x 或 ref。

引用初始化 的初始化形式。当引用用对象（或函数）初始化时，我们说它 绑定 到该对象（或函数）。这种引用绑定的过程称为引用绑定 被引用的对象（或函数）有时称为。

被引用者 非 const 左值引用只能绑定到 可修改的

int main()
{
    int x { 5 };
    int& ref { x };         // 正确：非const左值引用绑定到可修改的左值

    const int y { 5 };
    int& invalidRef { y };  // 无效：非const左值引用不能绑定到不可修改的左值

关键提示

左值。如果非 const 左值引用可以绑定到不可修改的（const）左值或右值，那么你就可以通过引用更改这些值，这将违反它们的 const 性质。

左值引用到 void 是不允许的（有什么意义呢？）。

即使引用的类型（例如 int&）与被绑定对象的类型（例如 int）不完全匹配，这里也不会应用任何转换（即使是平凡转换）——类型差异作为引用初始化过程的一部分来处理。

引用（通常）只绑定到与其引用类型匹配的对象

在大多数情况下，引用只绑定到类型与引用类型匹配的对象（有一些例外，我们将在讨论继承时介绍）。

如果你试图将引用绑定到与其引用类型不匹配的对象，编译器会尝试将对象隐式转换为引用类型，然后将引用绑定到转换结果。

关键提示

由于转换的结果是右值，而非 const 左值引用不能绑定到右值，因此尝试将非 const 左值引用绑定到与其引用类型不匹配的对象会导致编译错误。

int main()
{
    int x { 5 };
    int& ref { x };            // 正确：引用类型（int）与初始化器的类型匹配

    double d { 6.0 };
    int& invalidRef { d };     // 无效：double到int的转换是窄化转换，列表初始化不允许
    double& invalidRef2 { x }; // 无效：非const左值引用不能绑定到右值（将x转换为double的结果）

    return 0;
}

引用不能重新绑定（更改为引用另一个对象）

一旦初始化，C++ 中的引用就不能 重新绑定，这意味着它不能更改为引用另一个对象。

新的 C++ 程序员经常尝试通过赋值来重新绑定引用，为引用提供另一个变量来引用。这可以编译并运行——但不会按预期工作。考虑以下程序：

#include <iostream>

int main()
{
    int x { 5 };
    int y { 6 };

    int& ref { x }; // ref 现在是 x 的别名
    
    ref = y; // 将 6（y 的值）赋给 x（ref 引用的对象）
    // 上面这行并不会将 ref 改为对变量 y 的引用！

    std::cout << x << '\n'; // 用户期望这会打印 5

    return 0;
}

也许令人惊讶的是，这会打印：

6

当引用在表达式中被求值时，它会解析为它所引用的对象。所以 ref = y 并不会改变 ref 使其现在引用 y。相反，因为 ref 是 x，该表达式求值时就如同写成了 x = y ——并且由于 y 求值为值 6， x 被赋值为 6。

引用的作用域和生命周期

引用变量遵循与普通变量相同的作用域和生命周期规则：

#include <iostream>

int main()
{
    int x { 5 }; // 普通整数
    int& ref { x }; // 对变量 value 的引用

     return 0;
} // x 和 ref 在此处销毁

引用和被引用对象具有独立的生命周期

除一个例外（我们将在下一课中介绍），引用的生命周期和被引用对象的生命周期是独立的。换句话说，以下两点都成立：

  • 引用可以在它所引用的对象之前被销毁。
  • 被引用的对象可以在引用之前被销毁。

当引用在被引用对象之前销毁时，被引用对象不受影响。以下程序演示了这一点：

#include <iostream>

int main()
{
    int x { 5 };

    {
        int& ref { x };   // ref 是对 x 的引用
        std::cout << ref << '\n'; // 打印 ref 的值（5）
    } // ref 在此处销毁——x 对此一无所知

    std::cout << x << '\n'; // 打印 x 的值（5）

    return 0;
} // x 在这里销毁

上述代码打印：

5
5

当 ref 消亡，变量 x 照常运行，完全不知道指向它的引用已被销毁。

悬空引用

当被引用的对象在引用之前被销毁时，引用将指向一个不再存在的对象。这样的引用称为 悬空引用。访问悬空引用会导致未定义行为。

悬空引用相当容易避免，但我们将在课程 12.12 -- 返回引用和返回地址。

引用不是对象

也许令人惊讶的是，引用在 C++ 中不是对象。引用不需要存在或占用存储空间。如果可能，编译器会通过将所有出现的引用替换为被引用对象来优化掉引用。然而，这并不总是可能的，在这种情况下，引用可能需要存储空间。

这也意味着术语“引用变量”有点用词不当，因为变量是具有名称的对象，而引用不是对象。

由于引用不是对象，它们不能用于任何需要对象的地方（例如，不能有引用的引用，因为左值引用必须引用一个可识别的对象）。在需要引用是对象或引用可以重新绑定（reseated）的情况下， std::reference_wrapper （我们在课程 23.3 -- 聚合中介绍）提供了一种解决方案。

顺便说一句……

考虑以下变量：

int var{};
int& ref1{ var };  // 绑定到 var 的左值引用
int& ref2{ ref1 }; // 绑定到 var 的左值引用

因为 ref2 （一个引用）用 ref1 （一个引用）初始化，你可能会倾向于认为 ref2 是一个引用的引用。但并非如此。因为 ref1 是对 var的引用，当在表达式（如初始化器）中使用时， ref1 求值为 var。所以 ref2 只是一个普通的左值引用（如其类型 int&所示），绑定到 var。

对引用的引用（对 int）的语法将是 int&& ——但由于C++不支持对引用的引用，这种语法在C++11中被重新用于表示右值引用（我们在课程 22.2 -- 右值引用)。

问题 #1

自行判断以下程序打印什么值（不要编译程序）。

#include <iostream>

int main()
{
    int x{ 1 };
    int& ref{ x };

    std::cout << x << ref << '\n';

    int y{ 2 };
    ref = y;
    y = 3;

    std::cout << x << ref << '\n';

    x = 4;

    std::cout << x << ref << '\n';

    return 0;
}

显示答案

11
22
44

因为 ref 绑定到 x， x 和 ref 是同义词，因此它们总是打印相同的值。行 ref = y 将 y （2）的值赋给 ref ——它不会改变 ref 以引用 y。随后的行 y = 3 只改变 y。
