3.5 — 更多调试策略

● 机器译文 课程 3.5 查看英文原文

在前一课（3.4 -- 基本调试策略），我们开始探讨如何手动调试问题。在那节课中，我们提出了一些关于使用语句打印调试文本的批评：

  1. 调试语句会使你的代码变得杂乱。
  2. 调试语句会使你的程序输出变得杂乱。
  3. 调试语句需要修改代码来添加和删除，这可能会引入新的错误。
  4. 调试语句在使用完后必须删除，这使得它们不可重复使用。

我们可以缓解其中一些问题。在本课中，我们将探讨一些基本技术来实现这一点。

条件化你的调试代码

考虑下面包含一些调试语句的程序：

#include <iostream>
 
int getUserInput()
{
std::cerr << "getUserInput() called\n";
	std::cout << "Enter a number: ";
	int x{};
	std::cin >> x;
	return x;
}
 
int main()
{
std::cerr << "main() called\n";
    int x{ getUserInput() };
    std::cout << "You entered: " << x << '\n';
 
    return 0;
}

当你完成调试语句后，你需要删除它们或将其注释掉。如果以后再次需要它们，你必须重新添加或取消注释。

一种使整个程序更容易禁用和启用调试的方法是使用预处理器指令使调试语句条件化：

#include <iostream>
 
#define ENABLE_DEBUG // 注释掉以禁用调试

int getUserInput()
{
#ifdef ENABLE_DEBUG
std::cerr << "getUserInput() called\n";
#endif
	std::cout << "Enter a number: ";
	int x{};
	std::cin >> x;
	return x;
}
 
int main()
{
#ifdef ENABLE_DEBUG
std::cerr << "main() called\n";
#endif
    int x{ getUserInput() };
    std::cout << "You entered: " << x << '\n';
 
    return 0;
}

现在我们可以通过注释/取消注释来简单地启用调试 #define ENABLE_DEBUG. 这使得我们可以重用之前添加的调试语句，并在完成后只需禁用它们，而不必真正从代码中删除它们。如果是多文件程序，#define ENABLE_DEBUG 将放在一个包含所有代码文件的头文件中，这样我们可以在一个地方注释/取消注释 #define，并将其传播到所有代码文件。

这解决了必须删除调试语句以及这样做带来的风险问题，但代价是代码更加混乱。这种方法的另一个缺点是，如果你打错了字（例如拼错“DEBUG”）或忘记将头文件包含到代码文件中，该文件的某些或全部调试可能无法启用。因此，虽然这比无条件版本更好，但仍然有改进空间。

使用日志记录器

一种替代通过预处理器进行条件化调试的方法是将调试信息发送到日志。一个 日志 是已发生事件的顺序记录，通常带有时间戳。生成日志的过程称为 日志记录。通常，日志被写入磁盘上的文件（称为 日志文件）以便日后查看。大多数应用程序和操作系统都会写入日志文件，用于帮助诊断发生的问题。

日志文件有几个优点。由于写入日志文件的信息与程序输出分离，因此可以避免将正常输出和调试输出混在一起造成的混乱。日志文件也可以轻松地发送给其他人进行诊断——所以如果你软件的用户遇到问题，你可以让他们把日志文件发给你，这可能会帮助你找到问题的线索。

C++ 包含一个名为 std::clog 的输出流，它被设计用来写入日志信息。然而，默认情况下， std::clog 会写入标准错误流（与 std::cerr 相同）。虽然你也可以将其重定向到文件，但通常来说，使用现有的第三方日志工具之一会更好。具体使用哪个由你自己决定。

为了说明起见，我们将展示使用 plog 日志器输出日志的样子。Plog 实现为一组头文件，因此很容易在任何需要的地方包含它，并且它轻量且易于使用。

#include <plog/Log.h> // Step 1: include the logger headers
#include <plog/Initializers/RollingFileInitializer.h>
#include <iostream>

int getUserInput()
{
	PLOGD << "getUserInput() called"; // PLOGD由plog库定义

	std::cout << "Enter a number: ";
	int x{};
	std::cin >> x;
	return x;
}

int main()
{
	plog::init(plog::debug, "Logfile.txt"); // 步骤2：初始化日志记录器

	PLOGD << "main() called"; // 步骤3：向日志输出，就像向控制台写入一样

	int x{ getUserInput() };
	std::cout << "You entered: " << x << '\n';

	return 0;
}

以下是上述日志器的输出（在 Logfile.txt 文件中）：

2018-12-26 20:03:33.295 DEBUG [4752] [main@19] main() called
2018-12-26 20:03:33.296 DEBUG [4752] [getUserInput@7] getUserInput() called

如何包含、初始化和使用日志器将取决于你选择的具体日志器。

注意，使用这种方法也不需要条件编译指令，因为大多数日志器都有减少/消除写入日志输出的方法。这使得代码更容易阅读，因为条件编译行增加了许多杂乱内容。使用 plog，可以通过将初始化语句更改为以下内容来临时禁用日志记录：

	plog::init(plog::none , "Logfile.txt"); // plog::none会消除大多数消息的写入，本质上是关闭日志记录

我们不会在未来的任何课程中使用 plog，所以你不用担心去学习它。

顺便说一句……

如果你想自己编译上面的示例，或者在自己的项目中使用 plog，可以按照以下说明安装它：

首先，获取最新的 plog 版本：

  • 访问 plog 仓库。
  • 点击右上角的绿色 Code 按钮，然后选择“Download zip”

接下来，将整个压缩包解压到 somewhere 你的硬盘上。

最后，对于每个项目，将 somewhere\plog-master\include\ 目录作为 include directory 在你的IDE中。这里有关于如何为Visual Studio执行此操作的说明： A.2 -- 在Visual Studio中使用库 和Code::Blocks的说明在此： A.3 -- 在Code::Blocks中使用库. 由于plog没有预编译的库文件，你可以跳过与预编译库文件相关的部分。

日志文件通常会在与你的可执行文件相同的目录中创建。

提示

在较大或对性能敏感的项目中，可能会更倾向于使用更快且功能更丰富的日志记录器，例如 spdlog。
