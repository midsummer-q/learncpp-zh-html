21.12 — 重载赋值运算符

● 机器译文 课程 21.12 查看英文原文

浮点类型的 拷贝赋值运算符 （operator=）用于将一个对象的值复制到另一个 已存在的对象。

相关内容

从C++11开始，C++也支持“移动赋值”。我们在课程 22.3 -- 移动构造函数和移动赋值。

拷贝赋值 vs 拷贝构造函数

拷贝构造函数和拷贝赋值运算符的目的几乎相同——都是将一个对象复制到另一个对象。然而，拷贝构造函数初始化新对象，而赋值运算符替换现有对象的内容。

拷贝构造函数和拷贝赋值运算符之间的区别让很多新手程序员感到困惑，但实际上并不难。总结如下：

  • 如果在复制发生之前必须创建新对象，则使用拷贝构造函数（注意：这包括按值传递或返回对象）。
  • 如果在复制发生之前不需要创建新对象，则使用赋值运算符。

重载赋值运算符

重载拷贝赋值运算符（operator=）相当直接，但有一个特定的注意事项我们稍后会提到。拷贝赋值运算符必须作为成员函数重载。

#include <cassert>
#include <iostream>

class Fraction
{
private:
	int m_numerator { 0 };
	int m_denominator { 1 };

public:
	// 默认构造函数
	Fraction(int numerator = 0, int denominator = 1 )
		: m_numerator { numerator }, m_denominator { denominator }
	{
		assert(denominator != 0);
	}

	// 拷贝构造函数
	Fraction(const Fraction& copy)
		: m_numerator { copy.m_numerator }, m_denominator { copy.m_denominator }
	{
		// 这里无需检查分母是否为0，因为副本必须是一个有效的 Fraction
		std::cout << "Copy constructor called\n"; // 只是为了证明它有效
	}

	// 重载的赋值运算符
	Fraction& operator= (const Fraction& fraction);

	friend std::ostream& operator<<(std::ostream& out, const Fraction& f1);
        
};

std::ostream& operator<<(std::ostream& out, const Fraction& f1)
{
	out << f1.m_numerator << '/' << f1.m_denominator;
	return out;
}

// operator= 的简单实现（见下方更好的实现）
Fraction& Fraction::operator= (const Fraction& fraction)
{
    // 执行拷贝
    m_numerator = fraction.m_numerator;
    m_denominator = fraction.m_denominator;

    // 返回现有对象以便链式调用该运算符
    return *this;
}

int main()
{
    Fraction fiveThirds { 5, 3 };
    Fraction f;
    f = fiveThirds; // 调用重载的赋值运算符
    std::cout << f;

    return 0;
}

这会打印：

5/3

现在这应该相当简单了。我们重载的 operator= 返回 *this，以便我们可以链式进行多个赋值：

int main()
{
    Fraction f1 { 5, 3 };
    Fraction f2 { 7, 2 };
    Fraction f3 { 9, 5 };

    f1 = f2 = f3; // 链式赋值

    return 0;
}

自赋值导致的问题

这里事情开始变得有趣一些。C++ 允许自赋值：

int main()
{
    Fraction f1 { 5, 3 };
    f1 = f1; // 自赋值

    return 0;
}

这将调用 f1.operator=(f1)，在上述简单实现下，所有成员都将被赋值给自己。在这个特定示例中，自赋值导致每个成员被赋值给自己，除了浪费时间外没有整体影响。在大多数情况下，自赋值根本不需要做任何事情！

然而，在赋值运算符需要动态分配内存的情况下，自赋值实际上可能是危险的：

#include <algorithm> // for std::max and std::copy_n
#include <iostream>

class MyString
{
private:
	char* m_data {};
	int m_length {};

public:
	MyString(const char* data = nullptr, int length = 0 )
		: m_length { std::max(length, 0) }
	{
		if (length)
		{
			m_data = new char[static_cast<std::size_t>(length)];
			std::copy_n(data, length, m_data); // 将 data 的 length 个元素拷贝到 m_data
		}
	}
	~MyString()
	{
		delete[] m_data;
	}

	MyString(const MyString&) = default; // 某些编译器（如 gcc）会在你有指针成员但未声明拷贝构造函数时发出警告

	// 重载的赋值运算符
	MyString& operator= (const MyString& str);

	friend std::ostream& operator<<(std::ostream& out, const MyString& s);
};

std::ostream& operator<<(std::ostream& out, const MyString& s)
{
	out << s.m_data;
	return out;
}

// operator= 的简单实现（请勿使用）
MyString& MyString::operator= (const MyString& str)
{
	// 如果当前字符串中存在数据，则删除它
	if (m_data) delete[] m_data;

	m_length = str.m_length;
	m_data = nullptr;

	// 分配一个适当长度的新数组
	if (m_length)
		m_data = new char[static_cast<std::size_t>(str.m_length)];

	std::copy_n(str.m_data, m_length, m_data); // 将 str.m_data 中的 m_length 个元素拷贝到 m_data

	// 返回现有对象以便链式调用该运算符
	return *this;
}

int main()
{
	MyString alex("Alex", 5); // 认识 Alex
	MyString employee;
	employee = alex; // Alex 是我们最新的员工
	std::cout << employee; // 说出你的名字，员工

	return 0;
}

首先，按原样运行程序。你会看到程序按预期打印“Alex”。

现在运行以下程序：

int main()
{
    MyString alex { "Alex", 5 }; // 认识 Alex
    alex = alex; // Alex 就是他自己
    std::cout << alex; // 说出你的名字，Alex

    return 0;
}

你可能会得到垃圾输出。发生了什么？

考虑在重载的 operator= 中，当隐式对象和传入的参数（str）都是变量 alex 时会发生什么。在这种情况下，m_data 与 str.m_data 相同。首先发生的是函数检查隐式对象是否已经有一个字符串。如果有，它需要删除它，以免造成内存泄漏。在这种情况下，m_data 已分配，所以函数删除 m_data。但由于 str 与 *this 相同，我们想要复制的字符串已被删除，并且 m_data（和 str.m_data）成为悬空指针。

之后，我们为 m_data（和 str.m_data）分配新内存。因此，当我们随后将数据从 str.m_data 复制到 m_data 时，我们复制的是垃圾，因为 str.m_data 从未被初始化。

检测和处理自赋值

幸运的是，我们可以检测何时发生自赋值。以下是 MyString 类重载 operator= 的更新实现：

MyString& MyString::operator= (const MyString& str)
{
	// 自赋值检查
	if (this == &str)
		return *this;

	// 如果当前字符串中存在数据，则删除它
	if (m_data) delete[] m_data;

	m_length = str.m_length;
	m_data = nullptr;

	// 分配一个适当长度的新数组
	if (m_length)
		m_data = new char[static_cast<std::size_t>(str.m_length)];

	std::copy_n(str.m_data, m_length, m_data); // 将 str.m_data 中的 m_length 个元素拷贝到 m_data

	// 返回现有对象以便链式调用该运算符
	return *this;
}

通过检查隐式对象的地址是否与作为参数传入的对象的地址相同，我们可以让赋值运算符立即返回而不做任何其他工作。

由于这只是一个指针比较，应该很快，并且不需要重载 operator==。

何时不处理自赋值

通常，拷贝构造函数会跳过自赋值检查。因为被拷贝构造的对象是新创建的，唯一可能使新创建的对象与被拷贝对象相等的情况是当你尝试用一个自身初始化一个新定义的对象时：

someClass c { c };

在这种情况下，你的编译器应该警告你 c 是一个未初始化的变量。

其次，在能够自然处理自赋值的类中，可以省略自赋值检查。考虑这个带有自赋值保护的 Fraction 类赋值运算符：

// operator= 的更好实现
Fraction& Fraction::operator= (const Fraction& fraction)
{
    // 自赋值保护
    if (this == &fraction)
        return *this;

    // 执行拷贝
    m_numerator = fraction.m_numerator; // 可以处理自赋值
    m_denominator = fraction.m_denominator; // 可以处理自赋值

    // 返回现有对象以便链式调用该运算符
    return *this;
}

如果自赋值保护不存在，该函数在自赋值期间仍然能正确运行（因为函数执行的所有操作都能正确处理自赋值）。

由于自赋值是罕见事件，一些著名的 C++ 专家建议即使在受益于自赋值检查的类中也省略它。我们不建议这样做，因为我们相信防御性编码然后选择性优化是更好的实践。

拷贝并交换惯用法

处理自赋值问题的更好方法是通过所谓的拷贝并交换惯用法。关于这个惯用法如何工作，有一个很好的解释 在 Stack Overflow 上。

隐式拷贝赋值运算符

与其他运算符不同，如果你没有提供用户定义的拷贝赋值运算符，编译器会为你的类提供一个隐式的公有拷贝赋值运算符。这个赋值运算符执行成员逐位赋值（本质上与默认拷贝构造函数执行的成员逐位初始化相同）。

就像其他构造函数和运算符一样，你可以通过将拷贝赋值运算符设为私有或使用 delete 关键字来防止赋值发生：

#include <cassert>
#include <iostream>

class Fraction
{
private:
	int m_numerator { 0 };
	int m_denominator { 1 };

public:
    // 默认构造函数
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator { numerator }, m_denominator { denominator }
    {
        assert(denominator != 0);
    }

	// 拷贝构造函数
	Fraction(const Fraction &copy) = delete;

	// 重载的赋值运算符
	Fraction& operator= (const Fraction& fraction) = delete; // 禁止通过赋值进行拷贝！

	friend std::ostream& operator<<(std::ostream& out, const Fraction& f1);
        
};

std::ostream& operator<<(std::ostream& out, const Fraction& f1)
{
	out << f1.m_numerator << '/' << f1.m_denominator;
	return out;
}

int main()
{
    Fraction fiveThirds { 5, 3 };
    Fraction f;
    f = fiveThirds; // 编译错误，operator= 已被删除
    std::cout << f;

    return 0;
}

注意，如果你的类有 const 成员，编译器将改为定义隐式 operator= 被删除。这是因为 const 成员不能被赋值，所以编译器会假定你的类不可赋值。

如果你希望一个包含 const 成员的类是可赋值的（对于所有非 const 成员），你需要显式重载 operator= 并手动赋值每个非 const 成员。
