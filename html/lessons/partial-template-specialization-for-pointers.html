26.6 — 指针的部分模板特化

● 机器译文 课程 26.6 查看英文原文

在上一节课中 26.4 -- 类模板特化，我们看了一个简单的模板化 Storage 类，以及针对类型 double：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

template<>
void Storage<double>::print() // 完全特化为类型 double
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    // 定义一些存储单位
    Storage i { 5 };
    Storage d { 6.7 }; // 将导致 Storage<double> 被隐式实例化

    // 打印一些值
    i.print(); // 调用 Storage<int>::print（从 Storage<T> 实例化而来）
    d.print(); // 调用 Storage<double>::print（从 Storage<double>::print() 的显式特化中调用）
}

的特化。然而，尽管这个类很简单，但它有一个隐藏的缺陷：当 T 是指针类型时，它能编译但功能异常。例如：

int main()
{
    double d { 1.2 };
    double *ptr { &d };

    Storage s { ptr };
    s.print();
    
    return 0;
}

在作者的机器上，产生了以下结果：

0x7ffe164e0f50

发生了什么？因为 ptr 我们还调用了 double*， s 的类型为 Storage<double*>，这意味着 m_value 的类型为 double*。当构造函数被调用时， m_value 接收到 ptr 所持有的地址的副本，并且当调用 print() 成员函数时，打印的就是这个地址。

那么如何修复这个问题呢？

一种选择是为类型 double*：

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

template<>
void Storage<double*>::print() // 完全特化为类型 double*
{
    if (m_value)
        std::cout << std::scientific << *m_value << '\n';
}

template<>
void Storage<double>::print() // 完全特化为类型 double（用于比较，未使用）
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    double d { 1.2 };
    double *ptr { &d };

    Storage s { ptr };
    s.print(); // 调用 Storage<double*>::print()
    
    return 0;
}

添加一个完全特化。现在打印出正确的结果：

1.200000e+00

但这只解决了当 T 的类型是 double*时的问题。那么当 T 等于 int*，或 char*或任何其他指针类型时呢？

我们真的不想为每个指针类型都创建一个完全特化。事实上，这甚至是不可能的，因为用户总是可以传入指向程序定义类型的指针。

指针的部分模板特化

你可能会想尝试创建一个重载于类型 T*：

// 不起作用
template<typename T>
void Storage<T*>::print()
{
    if (m_value)
        std::cout << std::scientific << *m_value << '\n';
}

的模板函数。这样的函数是一个部分特化的模板函数，因为它限制了 T 可以是什么类型（只能是指针类型），但 T 仍然是一个类型模板参数。

不幸的是，这行不通，原因很简单：截至撰写本文时（C++23），函数不能部分特化。正如我们在课程 26.5 -- 部分模板特化中指出的，只有类可以部分特化。

所以让我们改为部分特化 Storage 类：

#include <iostream>

template <typename T>
class Storage // 这是我们的主模板类（与之前相同）
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

template <typename T> // 我们仍然有一个类型模板参数
class Storage<T*> // 这是针对 T* 的部分特化
{
private:
    T* m_value {};
public:
    Storage(T* value)
      : m_value { value }
    {
    }

    void print();
};

template <typename T>
void Storage<T*>::print() // 这是部分特化类 Storage<T*> 的非特化函数
{
    if (m_value)
        std::cout << std::scientific << *m_value << '\n';
}

int main()
{
    double d { 1.2 };
    double *ptr { &d };

    Storage s { ptr }; // 从部分特化类实例化 Storage<double*>
    s.print(); // 调用 Storage<double*>::print()
    
    return 0;
}

我们在类外部定义了 Storage<T*>::print() ，只是为了展示如何操作，并展示其定义与上面不起作用的部分特化函数 Storage<T*>::print() 相同。然而，既然 Storage<T*> 是一个部分特化的类， Storage<T*>::print() 就不再是部分特化的了——它是一个非特化的函数，这就是为什么它是允许的。

值得注意的是，我们的类型模板参数被定义为 T，而不是 T*。这意味着 T 将被推导为非指针类型，所以我们在任何需要指向 T* 的指针的地方都必须使用 T。同样值得提醒的是，部分特化 Storage<T*> 需要在主模板类 Storage<T>。

之后定义。所有权和生命周期问题

上述部分特化类 Storage<T*> 还有另一个潜在问题。因为 m_value 我们还调用了 T*，它是一个指向传入对象的指针。如果该对象随后被销毁，我们的 Storage<T*> 都会变成悬空。

核心问题在于我们的实现 Storage<T> 具有复制语义（意味着它复制其初始化器），但 Storage<T*> 具有引用语义（意味着它是对其初始化器的引用）。这种不一致性是错误的根源。

有几种不同的方法可以处理此类问题（按复杂度递增顺序）：

  1. 非常清楚地表明 Storage<T*> 是一个视图类（具有引用语义），因此由调用者确保被指向的对象在 Storage<T*> 的生命周期内保持有效。不幸的是，由于这个部分特化类必须与主模板类同名，我们不能给它起一个像 StorageView这样的名字。所以我们只能使用注释或其他可能被忽略的东西。这不是一个好选择。
  2. 完全阻止使用 Storage<T*> 我们可能不需要 Storage<T*> 存在，因为调用者总可以在实例化时解引用指针以使用 Storage<T> 并复制值（这对于存储类在语义上是合适的）。

然而，虽然你可以删除一个重载函数，但C++（截至C++23）不允许你删除一个类。明显的解决方案是部分特化 Storage<T*> ，然后做一些事情使其在模板实例化时无法编译（例如 static_assert），这种方法有一个主要缺点： std::nullptr_t 不是指针类型，所以 Storage<std::nullptr_t> 不会匹配 Storage<T*>！

更好的解决方案是完全避免部分特化，并在我们的主模板上使用 static_assert 来确保 T 是我们认可的类型。以下是该方法的一个示例：

#include <iostream>
#include <type_traits> // for std::is_pointer_v and std::is_null_pointer_v

template <typename T>
class Storage
{
    // 确保 T 不是指针或 std::nullptr_t
    static_assert(!std::is_pointer_v<T> && !std::is_null_pointer_v<T>, "Storage<T*> and Storage<nullptr> disallowed");

private:
    T m_value {};

public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

int main()
{
    double d { 1.2 };

    Storage s1 { d }; // ok
    s1.print();

    Storage s2 { &d }; // static_assert 因为 T 是指针
    s2.print();

    Storage s3 { nullptr }; // static_assert 因为 T 是空指针
    s3.print();
    
    return 0;
}
  1. 让 Storage<T*> 在堆上复制对象。如果你自己管理所有堆内存，这需要重载构造函数、拷贝构造函数、拷贝赋值和析构函数。一个更简单的替代方法是直接使用 std::unique_ptr （我们在课程 22.5 -- std::unique_ptr)：
#include <iostream>
#include <type_traits> // for std::is_pointer_v and std::is_null_pointer_v
#include <memory>

template <typename T>
class Storage
{
    // 确保 T 不是指针或 std::nullptr_t
    static_assert(!std::is_pointer_v<T> && !std::is_null_pointer_v<T>, "Storage<T*> and Storage<nullptr> disallowed");

private:
    T m_value {};

public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

template <typename T>
class Storage<T*>
{
private:
    std::unique_ptr<T> m_value {}; // 使用 std::unique_ptr 在 Storage 销毁时自动释放

public:
    Storage(T* value)
      : m_value { std::make_unique<T>(value ? *value : 0) } // 或当 !value 时抛出异常
    {
    }

    void print()
    {
        if (m_value)
            std::cout << *m_value << '\n';
    }
};

int main()
{
    double d { 1.2 };

    Storage s1 { d }; // ok
    s1.print();

    Storage s2 { &d }; // 好的，将 d 复制到堆上
    s2.print();

    return 0;
}

使用部分模板类特化为一个类创建单独的指针和非指针实现非常有用，当你希望一个类以完全对最终用户透明的方式处理两者时。
