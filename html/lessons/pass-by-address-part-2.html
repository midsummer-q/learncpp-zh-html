12.11 — 按地址传递（第二部分）

● 机器译文 课程 12.11 查看英文原文

本课是 12.10 -- 按地址传递。

按地址传递用于“可选”参数

按地址传递的一个常见用途是允许函数接受一个“可选”参数。通过示例比描述更容易说明：

#include <iostream>

void printIDNumber(const int *id=nullptr)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(&userid); // 我们现在知道用户的 ID 了

    return 0;
}

此示例输出：

Your ID number is not known.
Your ID number is 34.

在这个程序中， printIDNumber() 函数有一个按地址传递的参数，默认值为 nullptr。在 main()中，我们调用了这个函数两次。第一次调用时，我们不知道用户的ID，所以我们调用 printIDNumber() 时不带参数。 id 参数默认为 nullptr，函数打印 Your ID number is not known.。第二次调用时，我们有了一个有效的ID，所以我们调用 printIDNumber(&userid)。这些 id 参数接收了 userid的地址，因此函数打印 Your ID number is 34.。

然而，在许多情况下，函数重载是实现相同结果的更好选择：

#include <iostream>

void printIDNumber()
{
    std::cout << "Your ID is not known\n";
}

void printIDNumber(int id)
{
    std::cout << "Your ID is " << id << "\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(userid); // 我们知道用户是 34 岁

    printIDNumber(62); // 现在也适用于右值参数
    
    return 0;
}

这有很多优点：我们不再需要担心空指针解引用，并且可以传递字面量或其他右值作为参数。

改变指针参数所指向的内容

当我们向函数传递一个地址时，该地址从参数复制到指针参数中（这没问题，因为复制地址很快）。现在考虑以下程序：

#include <iostream>

// [[maybe_unused]] 消除关于 ptr2 被设置但未使用的编译器警告
void nullify([[maybe_unused]] int* ptr2) 
{
    ptr2 = nullptr; // 将函数参数设为空指针
}

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // ptr 指向 x

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");

    nullify(ptr);

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");
    return 0;
}

该程序打印出：

ptr is non-null
ptr is non-null

如你所见，改变指针参数所持有的地址对参数所持有的地址没有影响（ptr 仍然指向 x）。当函数 nullify() 被调用时， ptr2 接收到传入地址的副本（在本例中，是 ptr持有的地址，即 x的地址）。当函数改变 ptr2 所指向的内容时，这只会影响 ptr2。

持有的副本。那么，如果我们想允许函数改变指针参数所指向的内容呢？

按地址传递……通过引用？

是的，这是可行的。就像我们可以通过引用传递普通变量一样，我们也可以通过引用传递指针。下面是与上面相同的程序，但将 ptr2 改为对地址的引用：

#include <iostream>

void nullify(int*& refptr) // refptr 现在是指针的引用
{
    refptr = nullptr; // 将函数参数设为空指针
}

int main()
{
    int x{ 5 };
    int* ptr{ &x }; // ptr 指向 x

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");

    nullify(ptr);

    std::cout << "ptr is " << (ptr ? "non-null\n" : "null\n");
    return 0;
}

该程序打印出：

ptr is non-null
ptr is null

因为 refptr 现在是对指针的引用，当 ptr 作为参数传递时， refptr 绑定到 ptr。这意味着对 refptr 的任何更改都会影响到 ptr。

顺便说一句……

因为对指针的引用相当不常见，所以很容易混淆语法（是 int*& 或 int&*？）。好消息是，如果你写反了，编译器会报错，因为你不能有指向引用的指针（因为指针必须持有对象的地址，而引用不是对象）。然后你可以交换它们。

为什么使用 0 或 NULL 不再被推荐（可选）

在本小节中，我们将解释为什么使用 0 或 NULL 不再被推荐。

字面量 0 可以被解释为整数字面量或空指针字面量。在某些情况下，我们意图使用哪一种可能产生歧义——而在某些情况下，编译器可能假设我们指的是另一种——从而给程序行为带来意想不到的后果。

预处理器宏 NULL 的定义并非由语言标准规定。它可以被定义为 0， 0L， ((void*)0)，或者完全其他东西。

在课程 11.1 -- 函数重载介绍，我们讨论过函数可以被重载（多个函数可以有相同的名称，只要它们能通过参数的数量或类型区分）。编译器可以通过函数调用中传入的参数来判断你想要调用哪个重载函数。

当使用 0 或 NULL时，这可能会导致问题：

#include <iostream>
#include <cstddef> // for NULL

void print(int x) // 此函数接受一个整数
{
	std::cout << "print(int): " << x << '\n';
}

void print(int* ptr) // 此函数接受一个整数指针
{
	std::cout << "print(int*): " << (ptr ? "non-null\n" : "null\n");
}

int main()
{
	int x{ 5 };
	int* ptr{ &x };

	print(ptr);  // 总是调用 print(int*)，因为 ptr 的类型是 int*（好）
	print(0);    // 总是调用 print(int)，因为 0 是整数字面量（希望这是我们期望的）

	print(NULL); // 这条语句可能执行以下任一操作：
	// 调用 print(int)（Visual Studio 这样做）
	// 调用 print(int*)
	// 导致歧义函数调用的编译错误（gcc 和 Clang 这样做）

	print(nullptr); // 总是调用 print(int*)

	return 0;
}

在作者的机器上（使用 Visual Studio），这会打印：

print(int*): non-null
print(int): 0
print(int): 0
print(int*): null

当传递整数值 0 作为参数时，编译器会优先选择 print(int) 而不是 print(int*)。这可能导致当我们意图 print(int*) 被以空指针参数调用时出现意外结果。

在 NULL 被定义为值 0， print(NULL) 的情况下， print(int)，而不是 print(int*) 也会调用 NULL ，就像你对空指针字面量的期望一样。在 0未被定义为 print(int*) 的情况下，可能会产生其他行为，比如调用

使用 nullptr 消除了这种歧义（它总是会调用 print(int*)），因为 nullptr 只会匹配指针类型。

std::nullptr_t（可选）

由于 nullptr 可以在函数重载中与整数值区分开来，因此它必须具有不同的类型。那么 nullptr是什么类型？答案是 nullptr 的类型为 std::nullptr_t （定义在头文件 <cstddef> 中）。 std::nullptr_t 只能保存一个值： nullptr！虽然这看起来有点傻，但在一种情况下它很有用。如果我们想编写一个只接受 nullptr 字面量参数的函数，我们可以将参数设为 std::nullptr_t。

#include <iostream>
#include <cstddef> // for std::nullptr_t

void print(std::nullptr_t)
{
    std::cout << "in print(std::nullptr_t)\n";
}

void print(int*)
{
    std::cout << "in print(int*)\n";
}

int main()
{
    print(nullptr); // 调用 print(std::nullptr_t)

    int x { 5 };
    int* ptr { &x };

    print(ptr); // 调用 print(int*)

    ptr = nullptr;
    print(ptr); // 调用 print(int*)（因为 ptr 的类型是 int*）

    return 0;
}

在上面的例子中，函数调用 print(nullptr) 解析为函数 print(std::nullptr_t) 而不是 print(int*) ，因为它不需要转换。

一个可能有点令人困惑的情况是当我们调用 print(ptr) 当 ptr 时，它保存的值是 nullptr。记住函数重载匹配的是类型而不是值，而 ptr 的类型为 int*。因此， print(int*) 会被匹配。 print(std::nullptr_t) 在这种情况下甚至不在考虑范围内，因为指针类型不会隐式转换为 std::nullptr_t。

你可能永远不需要使用这个，但了解一下总是好的，以防万一。

只有按值传递

既然你已经理解了按引用、按地址和按值传递之间的基本区别，让我们暂时简化一下。 :)

虽然编译器通常可以完全优化掉引用，但在某些情况下这是不可能的，并且实际上需要引用。引用通常由编译器使用指针实现。这意味着在幕后，按引用传递本质上只是按地址传递。

在上一课中，我们提到按地址传递只是将地址从调用者复制到被调用函数——这其实就是按值传递地址。

因此，我们可以得出结论：C++ 实际上一切都是按值传递的！按地址（和引用）传递的特性完全源于我们可以解引用传递的地址来修改参数，而普通的按值参数则不能这样做！
