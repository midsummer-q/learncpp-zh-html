17.9 — 指针算术和下标

● 机器译文 课程 17.9 查看英文原文

在课程 16.1 -- 容器和数组简介，我们提到数组在内存中是顺序存储的。在本课中，我们将更深入地探讨数组索引运算的工作原理。

虽然我们不会在后续课程中使用索引运算，但本课涵盖的主题将让你深入了解基于范围的for循环实际是如何工作的，并且在我们稍后学习迭代器时会再次派上用场。

什么是指针算术？

指针算术 是一个特性，允许我们将某些整数算术运算符（加法、减法、递增或递减）应用于指针，以生成新的内存地址。

给定某个指针 ptr， ptr + 1 返回内存中 下一个对象 的地址（基于所指向的类型）。因此，如果 ptr 是一个 int*，且一个 int 是4字节， ptr + 1 将返回比 ptr、和 ptr + 2 将返回比 ptr。

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // 假设 int 为 4 字节

    std::cout << ptr << ' ' << (ptr + 1) << ' ' << (ptr + 2) << '\n';

    return 0;
}

在作者的机器上，打印了：

00AFFD80 00AFFD84 00AFFD88

注意，每个内存地址比前一个大4字节。

虽然不太常见，但指针算术也支持减法。给定某个指针 ptr， ptr - 1 返回内存中 前一个对象 在内存中的地址（基于所指向的类型）。

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // 假设 int 为 4 字节

    std::cout << ptr << ' ' << (ptr - 1) << ' ' << (ptr - 2) << '\n';

    return 0;
}

在作者的机器上，打印了：

00AFFD80 00AFFD7C 00AFFD78

在这种情况下，每个内存地址比前一个小4字节。

关键提示

指针算术返回的是下一个/前一个对象（基于所指向的类型）的地址，而不是下一个/前一个地址。

对指针应用递增（++）和递减（--）运算符分别与指针加法和指针减法效果相同，但会实际修改指针所持有的地址。

给定某个int值 x， ++x 是 x = x + 1的简写。类似地，给定某个指针 ptr， ++ptr 是 ptr = ptr + 1，它执行指针算术并将结果赋值回 ptr。

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // 假设 int 为 4 字节

    std::cout << ptr << '\n';

    ++ptr; // ptr = ptr + 1
    std::cout << ptr << '\n';

    --ptr; // ptr = ptr - 1
    std::cout << ptr << '\n';

    return 0;
}

在作者的机器上，打印了：

00AFFD80 00AFFD84 00AFFD80

警告

严格来说，上述行为是未定义行为。根据C++标准， 指针算术仅在指针和结果位于同一数组内（或指向末尾后一个位置）时才是定义行为。然而，现代C++实现通常不强制执行此规则，并且通常不会禁止你在数组之外使用指针算术。

下标通过指针算术实现

在上一课（17.8 -- C 风格数组退化），我们注意到 operator[] 可以应用于指针：

#include <iostream>

int main()
{
    const int arr[] { 9, 7, 5, 3, 1 };
    
    const int* ptr{ arr }; // 一个普通指针，保存着元素0的地址
    std::cout << ptr[2];   // 对ptr进行下标操作获取元素2，打印5

    return 0;
}

让我们更深入地看看这里发生了什么。

事实证明，下标操作 ptr[n] 是更冗长的表达式 *((ptr) + (n))的简洁语法。你会注意到，这仅仅是指针算术，加上一些额外的括号以确保运算顺序正确，以及一个隐式解引用以获取该地址处的对象。

首先，我们初始化 ptr 替换为 arr。当 arr 用作初始化器时，它会退化为一个指针，持有索引为0的元素的地址。因此， ptr 现在持有元素0的地址。

接下来，我们打印 ptr[2]。 ptr[2] 等价于 *((ptr) + (2))，这相当于 *(ptr + 2)。 ptr + 2 返回的是该对象之后两个对象的地址 ptr，即索引为2的元素。然后该地址处的对象被返回给调用者。

让我们看另一个例子：

#include <iostream>

int main()
{
    const int arr[] { 3, 2, 1 };

    // 首先，我们使用下标来获取数组元素的地址和值
    std::cout << &arr[0] << ' ' << &arr[1] << ' ' << &arr[2] << '\n';
    std::cout << arr[0] << ' ' << arr[1] << ' ' << arr[2] << '\n';

    // 现在让我们用指针算术来做同样的事
    std::cout << arr<< ' ' << (arr+ 1) << ' ' << (arr+ 2) << '\n';
    std::cout << *arr<< ' ' << *(arr+ 1) << ' ' << *(arr+ 2) << '\n';

    return 0;
}

在作者的机器上，打印了：

00AFFD80 00AFFD84 00AFFD88
3 2 1
00AFFD80 00AFFD84 00AFFD88
3 2 1

你会注意到 arr 持有地址 00AFFD80， (arr + 1) 返回一个4字节后的地址，而 (arr + 2) 返回一个8字节后的地址。我们可以解引用这些地址来获取这些地址处的元素。

因为数组元素在内存中总是连续的，如果 arr 是指向数组第0个元素的指针，那么 *(arr + n) 将返回数组中的第n个元素。

这是数组从0开始而不是从1开始的主要原因。它使计算更高效（因为编译器不必在下标时减1）！

顺便说一句……

作为一个小趣闻，因为编译器会将 ptr[n] 到 *((ptr) + (n)) 当对指针进行下标操作时，这意味着我们也可以将指针下标为 n[ptr]！编译器会将其转换为 *((n) + (ptr))，这在行为上与 *((ptr) + (n))相同。不过不要真的这样做，因为它令人困惑。

指针算术和下标的相对地址

初次学习数组下标时，很自然地会认为索引代表数组中的固定元素：索引0总是第一个元素，索引1总是第二个元素，等等……

这是一种错觉。数组索引实际上是相对位置。索引看起来固定，只是因为我们几乎总是从数组的开头（元素0）开始索引！

记住，给定某个指针 ptr， *(ptr + 1) 和 ptr[1] 都返回内存中的 下一个对象 （基于所指向的类型）。"下一个"是一个相对术语，而不是绝对术语。因此，如果 ptr 指向元素0，那么 *(ptr + 1) 和 ptr[1] 都将返回元素1。但如果 ptr 指向元素3，那么 *(ptr + 1) 和 ptr[1] 都将返回元素4！

下面的例子演示了这一点：

#include <array>
#include <iostream>

int main()
{
    const int arr[] { 9, 8, 7, 6, 5 };
    const int *ptr { arr }; // arr退化为指向元素0的指针

    // 证明我们指向元素0
    std::cout << *ptr << ptr[0] << '\n'; // 打印99
    // 证明ptr[1]是元素1
    std::cout << *(ptr+1) << ptr[1] << '\n'; // 打印88

    // 现在将ptr设置为指向元素3
    ptr = &arr[3];

    // 证明我们指向元素3
    std::cout << *ptr << ptr[0] << '\n'; // 打印66
    // 证明ptr[1]是元素4！
    std::cout << *(ptr+1) << ptr[1] << '\n'; // 打印55
 
    return 0;
}

然而，你也会注意到，如果我们不能假设 ptr[1] 总是索引为1的元素，那么我们的程序会变得更加令人困惑。因此，我们建议仅当从数组开头（元素0）索引时使用下标。仅在进行相对定位时使用指针算术。

最佳实践

当从数组开头（元素0）索引时，优先使用下标，这样数组索引与元素对应。

当从给定元素进行相对定位时，优先使用指针算术。

负索引

在上一课中，我们提到（与标准库容器类不同）C风格数组的索引可以是无符号整数或有符号整数。这不仅仅是为了方便——实际上可以用负下标索引C风格数组。听起来有趣，但这是有道理的。

我们刚刚讲到 *(ptr+1) 返回内存中的 下一个对象 而 ptr[1] 只是实现相同功能的便捷语法。

在本课开头，我们提到 *(ptr-1) 返回内存中的 前一个对象 在内存中。猜猜下标等价形式是什么？没错， ptr[-1]。

#include <array>
#include <iostream>

int main()
{
    const int arr[] { 9, 8, 7, 6, 5 };

    // 将ptr设置为指向元素3
    const int* ptr { &arr[3] };

    // 证明我们指向元素3
    std::cout << *ptr << ptr[0] << '\n'; // 打印66
    // 证明ptr[-1]是元素2！
    std::cout << *(ptr-1) << ptr[-1] << '\n'; // 打印77
 
    return 0;
}

指针算术可用于遍历数组

指针算术最常见的用途之一是在不使用显式索引的情况下遍历 C 风格数组。下面的例子说明了如何做到这一点：

#include <iostream>

int main()
{
	constexpr int arr[]{ 9, 7, 5, 3, 1 };

	const int* begin{ arr };                // begin指向起始元素
	const int* end{ arr + std::size(arr) }; // end指向末尾之后的一个元素

	for (; begin != end; ++begin)           // 从begin迭代到（但不包括）end
	{
		std::cout << *begin << ' ';     // 解引用循环变量以获取当前元素
	}

	return 0;
}

在上面的例子中，我们从指针 begin 所指向的元素开始遍历（这里是指向数组的第 0 个元素）。由于 begin != end ，循环体执行。在循环内部，我们通过 *begin访问当前元素，这只是一个指针解引用。循环体之后，我们执行 ++begin，它使用指针算术将 begin 递增到指向下一个元素。由于 begin != end，循环体再次执行。这样一直持续到 begin != end 等于 false，这发生在 begin == end。

时。因此，上面的代码输出：

9 7 5 3 1

注意 end 被设置为数组的尾后位置。让 end 持有这个地址是可以的（只要我们不解引用 end，因为该地址处没有有效元素）。我们这样做是为了让我们的数学运算和比较尽可能简单（不需要在任何地方加 1 或减 1）。

提示

对于指向 C 风格数组元素的指针，只要结果地址是有效数组元素的地址或最后一个元素的尾后地址，指针算术就是有效的。如果指针算术导致地址超出这些范围，则是未定义行为（即使结果未被解引用）。

在上一课中 17.8 -- C 风格数组退化中，我们提到数组退化使得重构函数变得困难，因为某些东西对未退化的数组有效，但对退化的数组无效（比如 std::size）。以这种方式遍历数组的一个巧妙之处是，我们可以将上面示例的循环部分完全按原样重构到一个单独的函数中，它仍然可以工作：

#include <iostream>

void printArray(const int* begin, const int* end)
{
	for (; begin != end; ++begin)   // 从begin迭代到（但不包括）end
	{
		std::cout << *begin << ' '; // 解引用循环变量以获取当前元素
	}
    
	std::cout << '\n';
}

int main()
{
	constexpr int arr[]{ 9, 7, 5, 3, 1 };

	const int* begin{ arr };                // begin指向起始元素
	const int* end{ arr + std::size(arr) }; // end指向末尾之后的一个元素

	printArray(begin, end);

	return 0;
}

注意，即使我们从未显式地将数组传递给函数，这个程序也能编译并产生正确的结果！而且因为我们没有传递 arr，所以我们不必处理退化的 arr 在 printArray()。相反， begin 和 end 包含了遍历数组所需的所有信息。

在未来的课程中（当我们介绍迭代器和算法时），我们会看到标准库中充满了使用 begin 和 end 对来定义函数应操作哪些容器元素的函数。

基于范围的 for 循环在 C 风格数组上是使用指针算术实现的

考虑以下基于范围的 for 循环：

#include <iostream>

int main()
{
	constexpr int arr[]{ 9, 7, 5, 3, 1 };

	for (auto e : arr)         // 从`begin`迭代到（但不包括）`end`
	{
		std::cout << e << ' '; // 解引用循环变量以获取当前元素
	}

	return 0;
}

如果你查看 文档 中关于基于范围的 for 循环的内容，你会看到它们通常是这样实现的：

{
    auto __begin = begin-expr;
    auto __end = end-expr;

    for ( ; __begin != __end; ++__begin)
    {
        range-declaration = *__begin;
        loop-statement;
    }
}

让我们用这个实现替换前面例子中的基于范围的 for 循环：

#include <iostream>

int main()
{
	constexpr int arr[]{ 9, 7, 5, 3, 1 };

	auto __begin = arr;                // arr是我们的begin-expr
	auto __end = arr + std::size(arr); // arr + std::size(arr)是我们的end-expr

	for ( ; __begin != __end; ++__begin)
	{
		auto e = *__begin;         // e是我们的range-declaration
		std::cout << e << ' ';     // 这里是我们循环语句
	}

	return 0;
}

注意这与我们在上一节中编写的例子有多么相似！唯一的区别是我们赋值给 *__begin 切换到 e 并使用 e 而不是直接使用 *__begin ！

问题 #1

a) 为什么 arr[0] 等同于 *arr？

显示答案

arr[0] 是 *((arr) + (0))，它等于 *(arr + 0)，又等于 *arr。
