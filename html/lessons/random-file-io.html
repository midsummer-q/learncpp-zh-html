28.7 — 随机文件I/O

● 机器译文 课程 28.7 查看英文原文

文件指针

每个文件流类都包含一个文件指针，用于跟踪文件中的当前读/写位置。当从文件读取或写入文件时，读/写操作发生在文件指针的当前位置。默认情况下，当打开文件进行读取或写入时，文件指针被设置在文件的开头。但是，如果文件以追加模式打开，文件指针会移动到文件末尾，这样写入就不会覆盖文件的任何当前内容。

使用 seekg() 和 seekp() 进行随机文件访问

到目前为止，我们所有的文件访问都是顺序的——也就是说，我们按顺序读取或写入文件内容。然而，也可以进行随机文件访问——即跳转到文件中的各个点来读取其内容。当你的文件包含许多记录，并且你想检索特定记录时，这很有用。与其读取所有记录直到找到你想要的那条，不如直接跳转到你想要检索的记录。

随机文件访问通过使用 seekg() 函数（用于输入）和 seekp() 函数（用于输出）来操作文件指针实现。如果你好奇，g 代表“get”，p 代表“put”。对于某些类型的流，seekg()（更改读取位置）和 seekp()（更改写入位置）是独立操作的——然而，对于文件流，读取和写入位置总是相同的，因此 seekg 和 seekp 可以互换使用。

seekg() 和 seekp() 函数接受两个参数。第一个参数是一个偏移量，决定文件指针移动多少字节。第二个参数是一个 ios 标志，指定偏移量参数相对于什么进行偏移。

Ios 查找标志含义
beg偏移量相对于文件开头（默认）
cur偏移量相对于文件指针的当前位置
end偏移量相对于文件末尾

正偏移量表示将文件指针移向文件末尾，而负偏移量表示将文件指针移向文件开头。

以下是一些示例：

inf.seekg(14, std::ios::cur); // 向前移动 14 个字节
inf.seekg(-18, std::ios::cur); // 向后移动 18 个字节
inf.seekg(22, std::ios::beg); // 移动到文件中的第 22 个字节
inf.seekg(24); // 移动到文件中的第 24 个字节
inf.seekg(-28, std::ios::end); // 移动到文件末尾前第 28 个字节

移动到文件开头或末尾很容易：

inf.seekg(0, std::ios::beg); // 移动到文件开头
inf.seekg(0, std::ios::end); // 移动到文件末尾

警告

在文本文件中，查找到文件开头以外的位置可能会导致意外行为。

在编程中，换行符（'\n'）实际上是一种抽象。

  • 在 Windows 上，换行符表示为连续的 CR（回车）和 LF（换行）字符（因此占用 2 字节存储空间）。
  • 在 Unix 上，换行符表示为 LF（换行）字符（因此占用 1 字节存储空间）。

在任一方向越过换行符查找所需的字节数取决于文件是如何编码的，这意味着结果会因使用的编码而异。

此外，在某些操作系统上，文件可能会用尾随零字节（值为 0 的字节）填充。查找到文件末尾（或从文件末尾偏移）会在这样的文件上产生不同的结果。

为了让你了解它们的工作原理，让我们使用 seekg() 和上一课创建的输入文件做一个示例。该输入文件如下所示：

This is line 1
This is line 2
This is line 3
This is line 4

以下是示例：

#include <fstream>
#include <iostream>
#include <string>

int main()
{
    std::ifstream inf{ "Sample.txt" };

    // 如果无法打开输入文件流进行读取
    if (!inf)
    {
        // 打印错误并退出
        std::cerr << "Uh oh, Sample.txt could not be opened for reading!\n";
        return 1;
    }

    std::string strData;

    inf.seekg(5); // 移动到第 5 个字符
    // 获取该行剩余部分并打印，移动到第 2 行
    std::getline(inf, strData);
    std::cout << strData << '\n';

    inf.seekg(8, std::ios::cur); // 再向文件内移动 8 个字节
    // 获取该行剩余部分并打印
    std::getline(inf, strData);
    std::cout << strData << '\n';

    inf.seekg(-14, std::ios::end); // 在文件末尾前移动 14 个字节
    // 获取该行剩余部分并打印
    std::getline(inf, strData); // 未定义行为
    std::cout << strData << '\n';

    return 0;
}

这会产生以下结果：

is line 1
line 2
This is line 4

第三行的结果可能因文件编码方式而异。

seekg() 和 seekp() 更适合用于二进制文件。你可以通过以下方式以二进制模式打开上述文件：

    std::ifstream inf {"Sample.txt", std::ifstream::binary};

另外两个有用的函数是 tellg() 和 tellp()，它们返回文件指针的绝对位置。这可用于确定文件的大小：

std::ifstream inf {"Sample.txt"};
inf.seekg(0, std::ios::end); // 移动到文件末尾
std::cout << inf.tellg();

在作者的机器上，这会打印：

64

这就是 sample.txt 的字节长度（假设最后一行后有换行符）。

作者注

先前示例中的结果 64 发生在 Windows 上。如果你在 Unix 上运行该示例，你会得到 60 ，因为换行符表示更小。如果你的文件用尾随零字节填充，你可能会得到其他结果。

使用 fstream 同时读写文件

fstream 类能够同时读取和写入文件——几乎可以！这里最大的警告是，不能随意在读取和写入之间切换。一旦进行了读取或写入，切换两者的唯一方法是执行修改文件位置的操作（例如 seek）。如果你实际上不想移动文件指针（因为它已经在你想在的位置），你总是可以查找到当前位置：

// 假设 iofile 是 fstream 类型的对象
iofile.seekg(iofile.tellg(), std::ios::beg); // 定位到当前文件位置

如果不这样做，可能会发生各种奇怪和怪异的事情。

（注意：虽然看起来 iofile.seekg(0, std::ios::cur) 也可能有效，但某些编译器可能会优化掉它）。

另一个棘手之处：与 ifstream 不同，我们可以说 while (inf) 来判断是否还有更多内容可读，但这不适用于 fstream。

让我们使用 fstream 做一个文件 I/O 示例。我们将编写一个程序，打开一个文件，读取其内容，并将其中的任何元音字母更改为 '#' 符号。

#include <fstream>
#include <iostream>
#include <string>

int main()
{
    // 注意我们必须同时指定 in 和 out，因为我们使用的是 fstream
    std::fstream iofile{ "Sample.txt", std::ios::in | std::ios::out };

    // 如果无法打开 iofile，打印错误
    if (!iofile)
    {
        // 打印错误并退出
        std::cerr << "Uh oh, Sample.txt could not be opened!\n";
        return 1;
    }

    char chChar{}; // 我们将逐个字符地进行操作

    // 当仍有数据要处理时
    while (iofile.get(chChar))
    {
        switch (chChar)
        {
            // 如果找到元音
            case 'a':
            case 'e':
            case 'i':
            case 'o':
            case 'u':
            case 'A':
            case 'E':
            case 'I':
            case 'O':
            case 'U':

                // 回退一个字符
                iofile.seekg(-1, std::ios::cur);

                // 因为我们执行了 seek，现在可以安全地进行写操作，所以
                // 让我们在元音上写一个 #
                iofile << '#';

                // 现在我们想回到读模式，以便下一次调用
                // get() 能正确执行。我们将 seekg() 到当前
                // 位置，因为我们不想移动文件指针。
                iofile.seekg(iofile.tellg(), std::ios::beg);

                break;
        }
    }

    return 0;
}

运行上述程序后，我们的 Sample.txt 文件将如下所示：

Th#s #s l#n# 1
Th#s #s l#n# 2
Th#s #s l#n# 3
Th#s #s l#n# 4

其他有用的文件函数

要删除文件，只需使用 remove() 函数。

此外，如果流当前处于打开状态，is_open() 函数将返回 true，否则返回 false。

关于将指针写入磁盘的警告

虽然将变量流式传输到文件相当容易，但当处理指针时，事情就变得复杂了。记住，指针只是保存它所指向的变量的地址。虽然可以将地址读写到磁盘，但这样做极其危险。这是因为变量的地址可能因执行而异。因此，尽管一个变量在您将该地址写入磁盘时可能位于地址 0x0012FF7C，但当您重新读回该地址时，它可能不再位于那里！

例如，假设您有一个名为 nValue 的整数，它位于地址 0x0012FF7C。您将 nValue 赋值为 5。您还声明了一个名为 *pnValue 的指针，它指向 nValue。pnValue 保存 nValue 的地址 0x0012FF7C。您想保存这些信息以备后用，因此将值 5 和地址 0x0012FF7C 写入磁盘。

几周后，您再次运行程序并从磁盘读回这些值。您将值 5 读入另一个名为 nValue 的变量，该变量位于 0x0012FF78。您将地址 0x0012FF7C 读入一个新的指针 *pnValue。由于 pnValue 现在指向 0x0012FF7C，而 nValue 位于 0x0012FF78，pnValue 不再指向 nValue，尝试访问 pnValue 将导致麻烦。

警告

不要将内存地址写入文件。最初位于这些地址的变量在您从磁盘读回它们的值时可能位于不同的地址，这些地址将无效。
