15.10 — 引用限定符

● 机器译文 课程 15.10 查看英文原文

作者注

这是一节可选课程。我们建议快速阅读以熟悉材料，但不需要全面理解即可继续后续课程。

在课程 14.7 -- 返回数据成员引用的成员函数中更详细地讨论这个话题。我们讨论了当隐式对象是右值时，调用返回数据成员引用的访问函数可能很危险。以下是快速回顾：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
	std::string m_name{};

public:
	Employee(std::string_view name): m_name { name } {}
	const std::string& getName() const { return m_name; } //  getter 按 const 引用返回
};

// createEmployee() 按值返回一个 Employee（这意味着返回值是一个右值）
Employee createEmployee(std::string_view name)
{
	Employee e { name };
	return e;
}

int main()
{
	// 情况 1：可以：在同一表达式中使用返回的右值类对象成员的引用
	std::cout << createEmployee("Frank").getName() << '\n';

	// 情况 2：不好：保存返回的右值类对象成员的引用以供稍后使用
	const std::string& ref { createEmployee("Garbo").getName() }; // 当 createEmployee() 的返回值被销毁时，引用变为悬垂
	std::cout << ref << '\n'; // 未定义行为

	return 0;
}

在情况2中，从 createEmployee("Garbo") 返回的右值对象在初始化 ref后被销毁，使得 ref 引用了一个刚刚被销毁的数据成员。后续使用 ref 会导致未定义行为。

这带来了一些难题。

  • 如果我们的 getName() 函数按值返回，那么当隐式对象是右值时是安全的，但当隐式对象是左值时（这是最常见的情况），会进行昂贵且不必要的复制。
  • 如果我们的 getName() 函数按const引用返回，这是高效的（因为没有复制 std::string ），但当隐式对象是右值时可能被误用（导致未定义行为）。

由于成员函数通常在左值隐式对象上调用，传统选择是按const引用返回，并简单避免在隐式对象是右值的情况下误用返回的引用。

Vector3d.cpp：

上述挑战的根源在于我们只想要一个函数来处理两种不同的情况（一种是隐式对象是左值，另一种是隐式对象是右值）。对一种情况最优的方案对另一种情况并不理想。

为了帮助解决此类问题，C++11引入了一个鲜为人知的特性，称为 引用限定符 ，它允许我们根据成员函数是在左值还是右值隐式对象上调用进行重载。使用此特性，我们可以创建两个版本的 getName() ——一个用于隐式对象是左值的情况，另一个用于隐式对象是右值的情况。

首先，从非引用限定版本的 getName()

const std::string& getName() const { return m_name; } // 可同时用于左值和右值隐式对象的可调用对象

开始。要添加引用限定，我们添加一个 & 限定符到仅匹配左值隐式对象的重载，以及一个 && 限定符到仅匹配右值隐式对象的重载：

const std::string& getName() const &  { return m_name; } //  & 限定符重载函数以仅匹配左值隐式对象，返回引用
std::string        getName() const && { return m_name; } // && 限定符重载函数以仅匹配右值隐式对象，按值返回

由于这些函数是不同的重载，它们可以有不同的返回类型！左值限定重载按const引用返回，而右值限定重载按值返回。

以下是上述内容的完整示例：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
	std::string m_name{};

public:
	Employee(std::string_view name): m_name { name } {}

	const std::string& getName() const &  { return m_name; } //  & 限定符重载函数以仅匹配左值隐式对象
	std::string        getName() const && { return m_name; } // && 限定符重载函数以仅匹配右值隐式对象
};

// createEmployee() 按值返回一个 Employee（这意味着返回值是一个右值）
Employee createEmployee(std::string_view name)
{
	Employee e { name };
	return e;
}

int main()
{
	Employee joe { "Joe" };
	std::cout << joe.getName() << '\n'; // Joe 是左值，因此调用 std::string& getName() &（返回引用）
    
	std::cout << createEmployee("Frank").getName() << '\n'; // Frank 是右值，因此调用 std::string getName() &&（进行复制）

	return 0;
}

这允许我们在隐式对象是左值时执行高效操作，在隐式对象是右值时执行安全操作。

进阶读者

上述的右值重载 getName() 在隐式对象是非常量临时对象时，从性能角度来看可能不是最优的。在这种情况下，隐式对象将在表达式结束时销毁。因此，与其让右值getter返回一个（可能昂贵的）成员副本，不如让它尝试移动成员（使用 std::move)。

）。这可以通过添加以下非常量右值的重载getter来实现：

        // 如果隐式对象是非常量右值，使用 std::move 尝试移动 m_name
	std::string getName() && { return std::move(m_name); }

这可以与常量右值getter共存，或者你可以只使用这个（因为常量右值相当少见）。

关于引用限定成员函数的一些说明

首先，对于给定的函数，非引用限定重载和引用限定重载不能共存。使用其中一种。

其次，类似于const左值引用可以绑定到右值，如果只存在const左值限定函数，它将接受左值或右值隐式对象。

第三，任一限定重载都可以显式删除（使用 = delete），从而阻止对该函数的调用。例如，删除右值限定版本会阻止在右值隐式对象上使用该函数。

那么为什么我们不推荐使用引用限定符？

虽然引用限定符很巧妙，但以这种方式使用它们有一些缺点。

  • 为每个返回引用的getter添加右值重载会增加类的杂乱，以防范一个不太常见且通过良好习惯容易避免的情况。
  • 让右值重载按值返回意味着即使在我们本可以安全使用引用的情况下（例如本课顶部示例中的情况1），我们也必须支付复制（或移动）的成本。

此外：

  • 大多数 C++ 开发者并不了解这个特性（这可能导致使用中的错误或低效）。
  • 标准库通常不使用这个特性。

基于以上所有原因，我们不推荐将引用限定符作为最佳实践。相反，我们建议始终立即使用访问函数的结果，而不是保存返回的引用以供后续使用。
