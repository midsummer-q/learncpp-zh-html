12.12 — 按引用返回和按地址返回

● 机器译文 课程 12.12 查看英文原文

在前面的课程中，我们讨论了按值传递参数时，会复制实参到函数形参。对于基本类型（复制成本低），这没问题。但复制类类型（如 std::string）通常代价高昂。我们可以通过按（常量）引用传递（或按地址传递）来避免昂贵的复制。

按值返回时也会遇到类似情况：返回值的副本被传回调用者。如果函数的返回类型是类类型，这可能代价高昂。

std::string returnByValue(); // 返回 std::string 的副本（昂贵）

按引用返回

当我们将类类型传回调用者时，可能（也可能不）希望改为按引用返回。 按引用返回 返回一个绑定到被返回对象的引用，从而避免复制返回值。要按引用返回，只需将函数的返回值定义为引用类型：

std::string&       returnByReference(); // 返回对现有 std::string 的引用（廉价）
const std::string& returnByReferenceToConst(); // 返回对现有 std::string 的 const 引用（廉价）

下面是一个学术程序，演示按引用返回的机制：

#include <iostream>
#include <string>

const std::string& getProgramName() // 返回 const 引用
{
    static const std::string s_programName { "Calculator" }; // 具有静态存储期，程序结束时销毁

    return s_programName;
}

int main()
{
    std::cout << "This program is named " << getProgramName();

    return 0;
}

该程序打印出：

This program is named Calculator

因为 getProgramName() 返回一个常量引用，当执行 return s_programName 时， getProgramName() 将返回一个对 s_programName 的常量引用（从而避免复制）。然后调用者可以使用该常量引用来访问 s_programName的值，并将其打印。

被按引用返回的对象必须在函数返回后仍然存在

使用按引用返回有一个主要注意事项：程序员必须 必须 确保被引用的对象比返回引用的函数存活得更久。否则，返回的引用将成为悬空引用（引用一个已被销毁的对象），使用该引用将导致未定义行为。

在上面的程序中，因为 s_programName 具有静态存储期， s_programName 将一直存在到程序结束。当 main() 访问返回的引用时，它实际上是在访问 s_programName，这没问题，因为 s_programName 直到稍后才会被销毁。

现在让我们修改上面的程序，展示函数返回悬空引用时会发生什么：

#include <iostream>
#include <string>

const std::string& getProgramName()
{
    const std::string programName { "Calculator" }; // 现在是非静态局部变量，函数结束时销毁

    return programName;
}

int main()
{
    std::cout << "This program is named " << getProgramName(); // 未定义行为

    return 0;
}

这个程序的结果是未定义的。当 getProgramName() 返回时，一个绑定到局部变量 programName 的引用被返回。然后，因为 programName 是一个具有自动存储期的局部变量， programName 在函数结束时被销毁。这意味着返回的引用现在是悬空的，使用 programName 在 main() 函数的结果是未定义行为。

现代编译器会在你尝试按引用返回局部变量时产生警告或错误（因此上述程序可能甚至无法编译），但编译器有时难以检测更复杂的情况。

警告

按引用返回的对象必须存在于返回引用的函数的作用域之外，否则会导致悬空引用。永远不要按引用返回（非静态）局部变量或临时对象。

生命周期延长不跨函数边界

让我们看一个按引用返回临时对象的例子：

#include <iostream>

const int& returnByConstReference()
{
    return 5; // 返回对临时对象的 const 引用
}

int main()
{
    const int& ref { returnByConstReference() };

    std::cout << ref; // 未定义行为

    return 0;
}

在上面的程序中， returnByConstReference() 返回一个整数字面量，但函数的返回类型是 const int&。这导致创建并返回一个临时引用，该引用绑定到一个持有值5的临时对象。这个返回的引用被复制到调用者作用域中的一个临时引用。然后临时对象离开作用域，使得调用者作用域中的临时引用悬空。

当调用者作用域中的临时引用绑定到常量引用变量 ref （在 main()中）时，已经太晚，无法延长临时对象的生命周期——因为它已经被销毁。因此 ref 是一个悬空引用，使用 ref 的值将导致未定义行为。

这里有一个不那么明显的例子，同样无法工作：

#include <iostream>

const int& returnByConstReference(const int& ref)
{
    return ref;
}

int main()
{
    // 情况 1：直接绑定
    const int& ref1 { 5 }; // 延长生命周期
    std::cout << ref1 << '\n'; // 好的

    // 情况 2：间接绑定
    const int& ref2 { returnByConstReference(5) }; // 绑定到悬垂引用
    std::cout << ref2 << '\n'; // 未定义行为

    return 0;
}

在情况2中，创建了一个临时对象来保存值 5，函数参数 ref 绑定到该临时对象。函数只是将这个引用返回给调用者，然后调用者使用该引用来初始化 ref2。由于这不是直接绑定到临时对象（因为引用是通过函数传递的），生命周期延长不适用。这使得 ref2 成为悬空引用，后续使用会导致未定义行为。

警告

引用生命周期延长不适用于跨函数边界的情况。

不要通过引用返回非常量静态局部变量

在上面的原始示例中，我们通过引用返回了一个常量静态局部变量，以简单说明返回引用的机制。然而，通过引用返回非常量静态局部变量并不常见，通常应避免。下面是一个简化的例子，说明了可能发生的一个问题：

#include <iostream>
#include <string>

const int& getNextId()
{
    static int s_x{ 0 }; // 注意：变量是非 const 的
    ++s_x; // 生成下一个 id
    return s_x; // 并返回对它的引用
}

int main()
{
    const int& id1 { getNextId() }; // id1 是一个引用
    const int& id2 { getNextId() }; // id2 是一个引用

    std::cout << id1 << id2 << '\n';

    return 0;
}

该程序打印出：

22

这是因为 id1 和 id2 引用的是同一个对象（静态变量 s_x），所以当任何东西（例如 getNextId()）修改该值时，所有引用都会访问到修改后的值。

上面的例子可以通过将 id1 和 id2 改为普通变量（而不是引用）来修复，这样它们会保存返回值的副本，而不是对 s_x。

进阶读者

的引用。这是另一个不那么明显的相同问题的例子：

#include <iostream>
#include <string>
#include <string_view>

std::string& getName()
{
    static std::string s_name{};
    std::cout << "Enter a name: ";
    std::cin >> s_name;
    return s_name;
}

void printFirstAlphabetical(const std::string& s1, const std::string& s2)
{
    if (s1 < s2)
        std::cout << s1 << " comes before " << s2 << '\n';
    else
        std::cout << s2 << " comes before " << s1 << '\n';
}

int main()
{
    printFirstAlphabetical(getName(), getName());
    
    return 0;
}

以下是该程序一次运行的结果：

Enter a name: Dave
Enter a name: Stan
Stan comes before Stan

在这个例子中， getName() 返回对静态局部变量 s_name的引用。用对 const std::string& 的引用初始化 s_name 会导致该 std::string& 绑定到 s_name （而不是复制它）。

因此，两个 s1 和 s2 最终都查看 s_name （它被赋值为我们最后输入的名字）。

注意，如果我们使用 std::string_view 参数，第一个 std::string_view 参数会在底层 std::string 改变时失效。

另一个常见的问题是，返回非常量静态局部变量引用的程序没有标准的方法将 s_x 重置回默认状态。这样的程序要么使用非传统的解决方案（例如重置函数参数），要么只能通过退出并重新启动程序来重置。

最佳实践

避免返回对非常量局部静态变量的引用。

有时会返回对 const 局部静态变量的常量引用，如果返回的局部变量创建和/或初始化代价高昂（这样我们就不必在每次函数调用时重新创建变量）。但这很少见。

有时会返回对 const 全局变量有时也会这样做，作为封装对全局变量访问的一种方式。我们在课程 7.8 -- 为什么（非常量）全局变量是邪恶的中讨论这一点。当有意且谨慎使用时，这也是可以的。

用返回的引用初始化或赋值给普通变量会进行复制

如果函数返回一个引用，并且该引用用于初始化或赋值给一个非引用变量，返回值将被复制（就像按值返回一样）。

#include <iostream>
#include <string>

const int& getNextId()
{
    static int s_x{ 0 };
    ++s_x;
    return s_x;
}

int main()
{
    const int id1 { getNextId() }; // id1 现在是一个普通变量，接收从 getNextId() 按引用返回的值的副本
    const int id2 { getNextId() }; // id2 现在是一个普通变量，接收从 getNextId() 按引用返回的值的副本

    std::cout << id1 << id2 << '\n';

    return 0;
}

在上面的例子中， getNextId() 返回一个引用，但 id1 和 id2 是非引用变量。在这种情况下，返回引用的值被复制到普通变量中。因此，该程序输出：

12

还要注意，如果程序返回一个悬垂引用，那么在复制发生之前引用就已经悬垂了，这将导致未定义行为：

#include <iostream>
#include <string>

const std::string& getProgramName() // 将返回一个 const 引用
{
    const std::string programName{ "Calculator" };

    return programName;
}

int main()
{
    std::string name { getProgramName() }; // 复制一个悬垂引用
    std::cout << "This program is named " << name << '\n'; // 未定义行为

    return 0;
}

通过引用返回引用参数是可以的

在很多情况下，通过引用返回对象是有意义的，我们将在未来的课程中遇到许多这样的例子。不过，我们现在可以展示一个有用的例子。

如果参数通过引用传递给函数，那么通过引用返回该参数是安全的。这很合理：为了将实参传递给函数，实参必须存在于调用者的作用域中。当被调用的函数返回时，该对象必须仍然存在于调用者的作用域中。

下面是一个简单的函数示例：

#include <iostream>
#include <string>

// 接受两个 std::string 对象，返回按字母顺序靠前的那个
const std::string& firstAlphabetical(const std::string& a, const std::string& b)
{
	return (a < b) ? a : b; // 我们可以使用 std::string 上的 operator< 来确定哪个按字母顺序靠前
}

int main()
{
	std::string hello { "Hello" };
	std::string world { "World" };

	std::cout << firstAlphabetical(hello, world) << '\n';

	return 0;
}

这会打印：

Hello

在上面的函数中，调用者通过 const 引用传入两个 std::string 对象，其中按字母顺序排在前面的字符串通过 const 引用返回。如果我们使用按值传递和按值返回，我们将制作多达 3 个 std::string 副本（每个参数一个，返回值一个）。通过使用按引用传递/按引用返回，我们可以避免这些副本。

通过 const 引用传入的右值通过 const 引用返回是可以的

当 const 引用参数的实参是右值时，通过 const 引用返回该参数仍然是安全的。

这是因为右值直到创建它们的完整表达式结束才会被销毁。

首先，让我们看这个例子：

#include <iostream>
#include <string>

std::string getHello()
{
    return "Hello"; // 隐式转换为 std::string
}

int main()
{
    const std::string s{ getHello() };

    std::cout << s;
    
    return 0;
}

在这种情况下， getHello() 按值返回一个 std::string ，这是一个右值。然后这个右值被用来初始化 s。在初始化 s之后，创建右值的表达式已经完成求值，右值被销毁。

现在让我们看一个类似的例子：

#include <iostream>
#include <string>

const std::string& foo(const std::string& s)
{
    return s;
}

std::string getHello()
{
    return "Hello"; // 隐式转换为 std::string
}

int main()
{
    const std::string s{ foo(getHello()) };

    std::cout << s;
    
    return 0;
}

这种情况下唯一的区别是，右值通过 const 引用传递给 foo() ，然后在用于初始化 s之前通过 const 引用返回给调用者。其他一切完全相同。

我们在课程中讨论了一个类似的情况 14.6 -- 访问函数。

调用者可以通过引用修改值

当实参通过非 const 引用传递给函数时，函数可以使用引用来修改实参的值。

类似地，当从函数返回非 const 引用时，调用者可以使用引用来修改返回的值。

这里有一个说明性的例子：

#include <iostream>

// 通过非 const 引用接受两个整数，并按引用返回较大的那个
int& max(int& x, int& y)
{
    return (x > y) ? x : y;
}

int main()
{
    int a{ 5 };
    int b{ 6 };

    max(a, b) = 7; // 将 a 或 b 中较大的那个设置为 7

    std::cout << a << b << '\n';
        
    return 0;
}

在上面的程序中， max(a, b) 调用 max() 函数，参数为 a 和 b 引用参数 x 绑定到实参 a，引用参数 y 绑定到实参 b。然后函数确定 x (5）和 y (6中哪个更大。在这种情况下，是 y，所以函数返回 y （仍然绑定到 b）给调用者。然后调用者将值 7 赋给这个返回的引用。

因此，表达式 max(a, b) = 7 实际上解析为 b = 7。

这会打印：

57

按地址返回

按地址返回 的工作方式与按引用返回几乎相同，只是返回的是指向对象的指针而不是对象的引用。按地址返回与按引用返回有相同的主要注意事项——通过地址返回的对象必须比返回地址的函数的作用域存活得更久，否则调用者将收到一个悬垂指针。

按地址返回相对于按引用返回的主要优势是，如果没有有效的对象可返回，函数可以返回 nullptr 例如，假设我们有一个学生列表要搜索。如果我们在列表中找到要找的学生，我们可以返回一个指向表示该匹配学生的对象的指针。如果没有找到匹配的学生，我们可以返回 nullptr 表示未找到匹配的学生对象。

按地址返回的主要缺点是调用者必须记得在解引用返回值之前进行检查，否则可能发生空指针解引用，导致未定义行为。由于这种危险，除非需要返回“无对象”，否则应优先使用按引用返回而非按地址返回。 nullptr 除非需要返回“无对象”的能力，否则应优先使用按引用返回而非按地址返回。

最佳实践

优先使用按引用返回而非按地址返回，除非需要返回“无对象”（使用 nullptr）的能力很重要。
