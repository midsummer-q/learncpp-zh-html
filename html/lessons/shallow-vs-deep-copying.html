21.13 — 浅拷贝与深拷贝

● 机器译文 课程 21.13 查看英文原文

浅拷贝

由于C++对您的类了解不多，它提供的默认拷贝构造函数和默认赋值运算符使用一种称为逐成员拷贝（也称为 浅拷贝）的方法。这意味着C++会逐个拷贝类的每个成员（对于重载的operator=使用赋值运算符，对于拷贝构造函数使用直接初始化）。当类很简单时（例如，不包含任何动态分配的内存），这种方法效果很好。

例如，让我们看看我们的Fraction类：

#include <cassert>
#include <iostream>
 
class Fraction
{
private:
    int m_numerator { 0 };
    int m_denominator { 1 };
 
public:
    // 默认构造函数
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator{ numerator }
        , m_denominator{ denominator }
    {
        assert(denominator != 0);
    }
 
    friend std::ostream& operator<<(std::ostream& out, const Fraction& f1);
};
 
std::ostream& operator<<(std::ostream& out, const Fraction& f1)
{
	out << f1.m_numerator << '/' << f1.m_denominator;
	return out;
}

编译器为这个类提供的默认拷贝构造函数和默认赋值运算符看起来像这样：

#include <cassert>
#include <iostream>
 
class Fraction
{
private:
    int m_numerator { 0 };
    int m_denominator { 1 };
 
public:
    // 默认构造函数
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator{ numerator }
        , m_denominator{ denominator }
    {
        assert(denominator != 0);
    }
 
    // 隐式拷贝构造函数的可能实现
    Fraction(const Fraction& f)
        : m_numerator{ f.m_numerator }
        , m_denominator{ f.m_denominator }
    {
    }

    // 隐式赋值运算符的可能实现
    Fraction& operator= (const Fraction& fraction)
    {
        // 自赋值保护
        if (this == &fraction)
            return *this;
 
        // 执行拷贝
        m_numerator = fraction.m_numerator;
        m_denominator = fraction.m_denominator;
 
        // 返回现有对象以便链式调用该运算符
        return *this;
    }

    friend std::ostream& operator<<(std::ostream& out, const Fraction& f1)
    {
	out << f1.m_numerator << '/' << f1.m_denominator;
	return out;
    }
};

注意，由于这些默认版本对于拷贝这个类来说工作得很好，因此在这种情况下，我们确实没有理由编写自己的这些函数版本。

然而，当设计处理动态分配内存的类时，逐成员（浅）拷贝可能会给我们带来很多麻烦！这是因为指针的浅拷贝只是拷贝指针的地址——它不会分配任何内存，也不会拷贝所指向的内容！

让我们看一个例子：

#include <cstring> // for strlen()
#include <cassert> // for assert()

class MyString
{
private:
    char* m_data{};
    int m_length{};
 
public:
    MyString(const char* source = "" )
    {
        assert(source); // 确保源字符串不为空

        // 查找字符串的长度
        // 加一个字符用于终止符
        m_length = std::strlen(source) + 1;
        
        // 分配一个等于此长度的缓冲区
        m_data = new char[m_length];
        
        // 将参数字符串复制到我们的内部缓冲区
        for (int i{ 0 }; i < m_length; ++i)
            m_data[i] = source[i];
    }
 
    ~MyString() // 析构函数
    {
        // 我们需要释放我们的字符串
        delete[] m_data;
    }
 
    char* getString() { return m_data; }
    int getLength() { return m_length; }
};

上面是一个简单的字符串类，它分配内存来保存我们传入的字符串。注意，我们没有定义拷贝构造函数或重载赋值运算符。因此，C++将提供默认的拷贝构造函数和默认赋值运算符，它们执行浅拷贝。拷贝构造函数看起来像这样：

MyString::MyString(const MyString& source)
    : m_length { source.m_length }
    , m_data { source.m_data }
{
}

注意，m_data只是source.m_data的一个浅指针拷贝，这意味着它们现在都指向同一个东西。

现在，考虑下面的代码片段：

#include <iostream>

int main()
{
    MyString hello{ "Hello, world!" };
    {
        MyString copy{ hello }; // 使用默认拷贝构造函数
    } // copy 是一个局部变量，因此它在此处被销毁。析构函数删除 copy 的字符串，这导致 hello 有一个悬空指针

    std::cout << hello.getString() << '\n'; // 这将导致未定义行为

    return 0;
}

虽然这段代码看起来无害，但它包含一个隐蔽的问题，会导致程序出现未定义行为！

让我们逐行分析这个例子：

    MyString hello{ "Hello, world!" };

这一行完全无害。它调用了MyString构造函数，该构造函数分配了一些内存，将hello.m_data设置为指向它，然后将字符串“Hello, world!”拷贝进去。

    MyString copy{ hello }; // 使用默认拷贝构造函数

这一行看起来也无害，但实际上它是我们问题的根源！当这一行被求值时，C++将使用默认拷贝构造函数（因为我们没有提供自己的）。这个拷贝构造函数将执行浅拷贝，将copy.m_data初始化为与hello.m_data相同的地址。结果，copy.m_data和hello.m_data现在都指向同一块内存！

} // copy 在此处被销毁

当copy离开作用域时，MyString析构函数在copy上被调用。析构函数删除了copy.m_data和hello.m_data都指向的动态分配内存！因此，通过删除copy，我们也（无意中）影响了hello。变量copy随后被销毁，但hello.m_data仍然指向已删除（无效）的内存！

    std::cout << hello.getString() << '\n'; // 这将导致未定义行为

现在你可以看到为什么这个程序有未定义行为。我们删除了hello指向的字符串，现在正试图打印不再分配的内存的值。

这个问题的根源是拷贝构造函数执行的浅拷贝——在拷贝构造函数或重载赋值运算符中对指针值进行浅拷贝几乎总是会带来麻烦。

深拷贝

这个问题的一个答案是对任何非空指针进行深拷贝。 深拷贝 为拷贝分配内存，然后拷贝实际值，这样拷贝就位于与源不同的内存中。这样，拷贝和源是独立的，不会以任何方式相互影响。进行深拷贝需要我们编写自己的拷贝构造函数和重载赋值运算符。

让我们展示一下如何为我们的MyString类做到这一点：

// 假设 m_data 已初始化
void MyString::deepCopy(const MyString& source)
{
    // 首先我们需要释放此字符串持有的任何值！
    delete[] m_data;

    // 因为 m_length 不是指针，我们可以浅拷贝它
    m_length = source.m_length;

    // m_data 是一个指针，所以如果它非空，我们需要深拷贝它
    if (source.m_data)
    {
        // 为我们的副本分配内存
        m_data = new char[m_length];

        // 执行拷贝
        for (int i{ 0 }; i < m_length; ++i)
            m_data[i] = source.m_data[i];
    }
    else
        m_data = nullptr;
}

// 拷贝构造函数
MyString::MyString(const MyString& source)
{
    deepCopy(source);
}

如您所见，这比简单的浅拷贝要复杂得多！首先，我们必须检查source是否真的有字符串（第11行）。如果有，那么我们分配足够的内存来保存该字符串的副本（第14行）。最后，我们必须手动拷贝字符串（第17和18行）。

现在让我们来做重载赋值运算符。重载赋值运算符稍微复杂一些：

// 赋值运算符
MyString& MyString::operator=(const MyString& source)
{
    // 检查自赋值
    if (this != &source)
    {
        // 现在进行深拷贝
        deepCopy(source);
    }

    return *this;
}

注意，我们的赋值运算符与拷贝构造函数非常相似，但有三个主要区别：

  • 我们添加了自赋值检查。
  • 我们返回*this以便可以链式使用赋值运算符。
  • 我们需要显式释放字符串已经持有的任何值（这样当稍后重新分配m_data时就不会有内存泄漏）。这在deepCopy()内部处理。

当重载赋值运算符被调用时，被赋值的对象可能已经包含一个先前的值，我们需要确保在为新值分配内存之前清理它。对于非动态分配的变量（它们是固定大小的），我们不必担心，因为新值只是覆盖旧值。然而，对于动态分配的变量，我们需要在分配任何新内存之前显式释放任何旧内存。如果不这样做，代码不会崩溃，但每次进行赋值时都会出现内存泄漏，吞噬我们的空闲内存！

三法则

还记得三法则吗？如果一个类需要用户定义的析构函数、拷贝构造函数或拷贝赋值运算符，那么它很可能需要全部三个。这就是原因。如果我们用户定义这些函数中的任何一个，很可能是因为我们在处理动态内存分配。我们需要拷贝构造函数和拷贝赋值来处理深拷贝，以及析构函数来释放内存。

更好的解决方案

标准库中处理动态内存的类，如std::string和std::vector，处理它们所有的内存管理，并且有重载的拷贝构造函数和赋值运算符来执行正确的深拷贝。因此，与其自己进行内存管理，您可以像初始化或赋值普通基本变量一样初始化或赋值它们！这使得这些类更易于使用，更不容易出错，并且您不必花时间编写自己的重载函数！

总结

  • 默认拷贝构造函数和默认赋值运算符执行浅拷贝，这对于不包含动态分配变量的类来说是可以的。
  • 具有动态分配变量的类需要具有执行深拷贝的拷贝构造函数和赋值运算符。
  • 优先使用标准库中的类，而不是自己进行内存管理。
