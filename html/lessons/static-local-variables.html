7.11 — 静态局部变量

● 机器译文 课程 7.11 查看英文原文

术语 static 是C++语言中最令人困惑的术语之一，很大程度上是因为 static 在不同语境下有不同的含义。

在之前的课程中，我们介绍了全局变量具有静态持续时间，这意味着它们在程序启动时创建，在程序结束时销毁。

我们还讨论了 static 关键字如何赋予全局标识符内部链接属性，这意味着该标识符只能在其定义所在的文件中使用。

在本课中，我们将探讨 static 关键字应用于局部变量时的用法。

静态局部变量

在课程 2.5 -- 局部作用域简介中，你了解到局部变量默认具有自动持续时间，这意味着它们在定义点创建，在退出块时销毁。

在局部变量上使用 static 关键字会将其持续时间从自动持续时间改为静态持续时间。这意味着该变量现在在程序启动时创建，在程序结束时销毁（就像全局变量一样）。因此，静态变量即使在离开作用域后也会保留其值！

展示自动持续时间和静态持续时间局部变量之间差异的最简单方法是通过示例。

自动持续时间（默认）：

#include <iostream>

void incrementAndPrint()
{
    int value{ 1 }; // 默认自动存储期
    ++value;
    std::cout << value << '\n';
} // 值在此处销毁

int main()
{
    incrementAndPrint();
    incrementAndPrint();
    incrementAndPrint();

    return 0;
}

每次调用 incrementAndPrint() 时，都会创建一个名为 value 的变量，并将其赋值为 1。 incrementAndPrint() 将 value 递增到 2，然后打印 value 的值。 2。当 incrementAndPrint() 执行完毕后，该变量离开作用域并被销毁。因此，该程序输出：

2
2
2

现在考虑一个使用静态局部变量的程序版本。该程序与上述程序之间的唯一区别是，我们通过使用 static 关键字。

关键字将局部变量从自动持续时间改为静态持续时间。 静态持续时间（使用 static 关键字）：

#include <iostream>

void incrementAndPrint()
{
    static int s_value{ 1 }; // 通过 static 关键字实现静态存储期。此初始化只执行一次。
    ++s_value;
    std::cout << s_value << '\n';
} // s_value 在此处未被销毁，但因其超出作用域而变得不可访问

int main()
{
    incrementAndPrint();
    incrementAndPrint();
    incrementAndPrint();

    return 0;
}

在这个程序中，因为 s_value 被声明为 static，所以它在程序启动时创建。

零初始化或具有 constexpr 初始化器的静态局部变量可以在程序启动时初始化。

没有初始化器或具有非 constexpr 初始化器的静态局部变量在程序启动时被零初始化。具有非 constexpr 初始化器的静态局部变量在首次遇到变量定义时重新初始化。在后续调用中跳过该定义，因此不会发生进一步的重新初始化。由于它们具有静态持续时间，未显式初始化的静态局部变量默认会被零初始化。

因为 s_value 具有 constexpr 初始化器 1， s_value 将在程序启动时初始化。

当 s_value 在函数结束时离开作用域，但它不会被销毁。每次调用函数 incrementAndPrint() 时， s_value 的值保持在我们上次离开时的状态。因此，该程序输出：

2
3
4

关键提示

当你需要一个局部变量在函数调用之间记住其值时，可以使用静态局部变量。

最佳实践

初始化你的静态局部变量。静态局部变量只在代码首次执行时初始化，后续调用不会初始化。

提示

就像我们使用“g_”前缀表示全局变量一样，通常使用“s_”前缀表示静态（静态持续时间）局部变量。

ID 生成

静态持续时间局部变量最常见的用途之一是作为唯一 ID 生成器。想象一个程序中有许多相似的对象（例如，一个游戏中你被许多僵尸攻击，或者一个模拟中你显示许多三角形）。如果你发现一个缺陷，几乎不可能区分哪个对象出了问题。但是，如果每个对象在创建时都被赋予一个唯一标识符，那么就可以更容易地区分对象以进行进一步调试。

使用静态持续时间局部变量生成唯一 ID 号非常容易：

int generateID()
{
    static int s_itemID{ 0 };
    return s_itemID++; // 复制 s_itemID，递增真实的 s_itemID，然后返回副本中的值
}

第一次调用此函数时，它返回 0。第二次调用时，它返回 1。每次调用时，它返回的数字比上一次调用时大 1。你可以将这些数字分配为对象的唯一 ID。因为 s_itemID 是一个局部变量，所以其他函数无法“篡改”它。

静态变量兼具全局变量的某些优点（直到程序结束才被销毁），同时将其可见性限制在块作用域内。这使得它们更易于理解且使用更安全。

关键提示

静态局部变量具有与局部变量相同的块作用域，但其生命周期与全局变量一样，持续到程序结束。

静态局部常量

静态局部变量可以声明为 const（或 constexpr）。const 静态局部变量的一个良好用途是：当函数需要使用一个 const 值，但创建或初始化该对象的代价很高时（例如需要从数据库读取值）。如果使用普通局部变量，每次函数执行时都会创建并初始化该变量。而使用 const/constexpr 静态局部变量，可以只创建和初始化一次昂贵的对象，然后在每次调用函数时重复使用。

关键提示

静态局部变量最适合用于避免每次调用函数时昂贵的局部对象初始化。

不要使用静态局部变量来改变流程

考虑以下代码：

#include <iostream>

int getInteger()
{
	static bool s_isFirstCall{ true };

	if (s_isFirstCall)
	{
		std::cout << "Enter an integer: ";
		s_isFirstCall = false;
	}
	else
	{
		std::cout << "Enter another integer: ";
	}

	int i{};
	std::cin >> i;
	return i;
}

int main()
{
	int a{ getInteger() };
	int b{ getInteger() };

	std::cout << a << " + " << b << " = " << (a + b) << '\n';

	return 0;
}

示例输出

Enter an integer: 5
Enter another integer: 9
5 + 9 = 14

这段代码完成了它应该做的事情，但由于使用了静态局部变量，代码变得更难理解。如果有人阅读 main() 中的代码而没有阅读 getInteger()的实现，他们就没有理由假设对 getInteger() 的两次调用会执行不同的操作。但这两次调用确实做了不同的事情，如果差异不仅仅是提示信息的变化，这可能会非常令人困惑。

假设你按下微波炉上的 +1 按钮，微波炉会在剩余时间上增加 1 分钟。你的食物热了，你很高兴。在你把食物从微波炉里拿出来之前，你看到窗外有一只猫，看了一会儿，因为猫很酷。结果这段时间比你预期的要长，当你吃第一口食物时，它又凉了。没问题，只需把它放回微波炉，再按 +1 运行一分钟。但这次微波炉只增加了 1 秒而不是 1 分钟。这时你会想“我什么都没改变，它却坏了”或者“上次还好好的”。如果你再次做同样的事情，你会期望得到和上次一样的行为。函数也是如此。

假设我们想给计算器添加减法功能，使得输出如下所示：

Addition
Enter an integer: 5
Enter another integer: 9
5 + 9 = 14
Subtraction
Enter an integer: 12
Enter another integer: 3
12 - 3 = 9

我们可能会尝试使用 getInteger() 来读取接下来的两个整数，就像我们做加法时那样。

int main()
{
  std::cout << "Addition\n";

  int a{ getInteger() };
  int b{ getInteger() };

  std::cout << a << " + " << b << " = " << (a + b) << '\n';

  std::cout << "Subtraction\n";

  int c{ getInteger() };
  int d{ getInteger() };

  std::cout << c << " - " << d << " = " << (c - d) << '\n';

  return 0;
}

但这不会达到我们的预期，因为输出是：

Addition
Enter an integer: 5
Enter another integer: 9
5 + 9 = 14
Subtraction
Enter another integer: 12
Enter another integer: 3
12 - 3 = 9

（倒数第三行是“Enter another integer”而不是“Enter an integer”）

getInteger() 不可重用，因为它有一个内部状态（静态局部变量 s_isFirstCall），无法从外部重置。 s_isFirstCall 不是一个应该在全局唯一的变量。虽然我们的程序在最初编写时运行良好，但静态局部变量阻止了我们以后重用该函数。

实现 getInteger 的一个更好的方法是将 s_isFirstCall 作为参数传递。这允许调用者选择要打印的提示信息：

#include <iostream>

// 我们将定义一个具有好名字的符号常量
constexpr bool g_firstCall { true };

int getInteger(bool bFirstCall)
{
	if (bFirstCall)
	{
		std::cout << "Enter an integer: ";
	}
	else
	{
		std::cout << "Enter another integer: ";
	}

	int i{};
	std::cin >> i;
	return i;
}

int main()
{
	int a{ getInteger(g_firstCall) };  // 以便更清楚地表明参数在此处的含义
	int b{ getInteger(!g_firstCall) };

	std::cout << a << " + " << b << " = " << (a + b) << '\n';

	return 0;
}

非 const 静态局部变量只应在以下情况下使用：在你的整个程序中以及可预见的未来，该变量是唯一的，并且重置该变量没有意义。

最佳实践

const 静态局部变量通常是可以使用的。

通常应避免使用非 const 静态局部变量。如果确实使用，请确保该变量永远不需要重置，并且不用于改变程序流程。

提示

一个更具可重用性的解决方案是将 bool 参数改为 std::string_view ，让调用者传入将要使用的文本提示！

进阶读者

在需要多个非 const 变量实例来记住其值的情况下（例如，有多个 ID 生成器），仿函数是一个很好的解决方案（参见课程 21.10 -- 重载括号运算符)。

小测验时间

问题 #1

使用关键字 static 对全局变量有什么影响？对局部变量有什么影响？

显示答案

当应用于全局变量时，static 关键字将全局变量定义为具有内部链接，意味着该变量不能导出到其他文件。

当应用于局部变量时，static 关键字将局部变量定义为具有静态存储期，意味着该变量只会被创建一次，并且直到程序结束才会被销毁。
