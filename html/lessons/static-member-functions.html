15.7 — 静态成员函数

● 机器译文 课程 15.7 查看英文原文

在上一节关于 15.6 -- 静态成员变量中，你了解到静态成员变量是属于类而非类的对象的成员变量。如果静态成员变量是公有的，可以直接使用类名和作用域解析运算符来访问：

#include <iostream>

class Something
{
public:
    static inline int s_value { 1 };
};

int main()
{
    std::cout << Something::s_value; // s_value 是公有的，我们可以直接访问它
}

但如果静态成员变量是私有的呢？考虑以下示例：

#include <iostream>

class Something
{
private: // 现在是私有的
    static inline int s_value { 1 };
};

int main()
{
    std::cout << Something::s_value; // 错误：s_value 是私有的，不能在类外部直接访问
}

在这种情况下，我们不能从 Something::s_value 直接访问 main()，因为它是私有的。通常我们通过公有成员函数访问私有成员。虽然我们可以创建一个普通的公有成员函数来访问 s_value，但那样我们需要实例化一个类类型的对象才能使用该函数！

#include <iostream>

class Something
{
private:
    static inline int s_value { 1 };

public:
    int getValue() { return s_value; }
};

int main()
{
    Something s{};
    std::cout << s.getValue(); // 可以工作，但需要实例化一个对象来调用 getValue()
}

我们可以做得更好。

静态成员函数

成员变量并不是唯一可以成为静态的成员类型。成员函数也可以被设为静态。以下是上述示例使用静态成员函数访问器的版本：

#include <iostream>

class Something
{
private:
    static inline int s_value { 1 };

public:
    static int getValue() { return s_value; } // 静态成员函数
};

int main()
{
    std::cout << Something::getValue() << '\n';
}

因为静态成员函数不与特定对象关联，所以可以直接使用类名和作用域解析运算符来调用（例如 Something::getValue()）。与静态成员变量类似，它们也可以通过类类型的对象来调用，但不推荐这样做。

静态成员函数没有 this 指针

静态成员函数有两个值得注意的有趣特性。首先，因为静态成员函数不依附于对象，所以它们没有 this 指针！这很容易理解—— this 指针总是指向成员函数正在操作的对象。静态成员函数不操作对象，因此不需要 this 指针。

其次，静态成员函数可以直接访问其他静态成员（变量或函数），但不能访问非静态成员。这是因为非静态成员必须属于某个类对象，而静态成员函数没有可操作的类对象！

在类定义外部定义静态成员

静态成员函数也可以在类声明外部定义。这与普通成员函数的工作方式相同。

#include <iostream>

class IDGenerator
{
private:
    static inline int s_nextID { 1 };

public:
     static int getNextID(); // 这是静态函数的声明
};

// 这是类外部静态函数的定义。注意这里我们不使用 static 关键字。
int IDGenerator::getNextID() { return s_nextID++; } 

int main()
{
    for (int count{ 0 }; count < 5; ++count)
        std::cout << "The next ID is: " << IDGenerator::getNextID() << '\n';

    return 0;
}

该程序打印出：

The next ID is: 1
The next ID is: 2
The next ID is: 3
The next ID is: 4
The next ID is: 5

注意，由于这个类中的所有数据和函数都是静态的，我们不需要实例化一个类对象就能使用其功能！这个类使用一个静态成员变量来保存下一个要分配的ID的值，并提供一个静态成员函数来返回该ID并递增它。

如第 15.2 -- 类和头文件，在类定义内部定义的成员函数是隐式内联的。在类定义外部定义的成员函数不是隐式内联的，但可以通过使用 inline 关键字使其成为内联函数。因此，在头文件中定义的静态成员函数应该被设为 inline ，以避免如果该头文件被包含到多个翻译单元中时违反单一定义规则（ODR）。

关于全静态成员类的警告

编写全静态成员类时要小心。尽管这种“纯静态类”（也称为“单态类”）可能有用，但它们也有一些潜在的缺点。

首先，因为所有静态成员只实例化一次，所以无法拥有纯静态类的多个副本（除非克隆类并重命名）。例如，如果你需要两个独立的 IDGenerator，纯静态类无法实现。

其次，在关于全局变量的课程中，你了解到全局变量是危险的，因为任何代码都可以改变全局变量的值，从而破坏其他看似无关的代码。纯静态类也是如此。因为所有成员都属于类（而不是类的对象），并且类声明通常具有全局作用域，纯静态类本质上等同于在全局可访问的命名空间中声明函数和全局变量，具有全局变量所有必要的缺点。

与其编写一个全静态成员的类，不如考虑编写一个普通类并实例化一个全局实例（全局变量具有静态持续时间）。这样，全局实例可以在适当的时候使用，但如果需要，仍然可以实例化局部实例。

纯静态类与命名空间

纯静态类与命名空间有很多重叠之处。两者都允许你在其作用域内定义具有静态持续时间的变量和函数。然而，一个显著的区别是类具有访问控制，而命名空间没有。

一般来说，当你需要静态数据成员和/或访问控制时，静态类是更可取的。否则，优先选择命名空间。

C++ 不支持静态构造函数

如果你可以通过构造函数初始化普通成员变量，那么按理说你也应该能够通过静态构造函数初始化静态成员变量。虽然一些现代语言确实支持静态构造函数用于此目的，但不幸的是 C++ 不是其中之一。

如果你的静态变量可以直接初始化，则不需要构造函数：你可以在定义点初始化静态成员变量（即使它是私有的）。我们在上面的 IDGenerator 示例中就是这样做的。这里是另一个示例：

#include <iostream>

struct Chars
{
    char first{};
    char second{};
    char third{};
    char fourth{};
    char fifth{};
};

struct MyClass
{
	static inline Chars s_mychars { 'a', 'e', 'i', 'o', 'u' }; // 在定义点初始化静态变量
};

int main()
{
    std::cout << MyClass::s_mychars.third; // 打印 i

    return 0;
}

如果初始化静态成员变量需要执行代码（例如循环），有许多不同且有些晦涩的方法。一种适用于所有变量（无论是否静态）的方法是使用函数创建一个对象，填充数据，然后返回给调用者。这个返回值可以被复制到正在初始化的对象中。

#include <iostream>

struct Chars
{
    char first{};
    char second{};
    char third{};
    char fourth{};
    char fifth{};
};

class MyClass
{
private:
    static Chars generate()
    {
        Chars c{}; // 创建一个对象
        c.first = 'a'; // 以你喜欢的方式填充值
        c.second = 'e';
        c.third = 'i';
        c.fourth = 'o';
        c.fifth = 'u';
        
        return c; // 返回对象
    }

public:
	static inline Chars s_mychars { generate() }; // 将返回的对象复制到 s_mychars
};

int main()
{
    std::cout << MyClass::s_mychars.third; // 打印 i

    return 0;
}

显示答案

#include <chrono>
#include <random>
#include <iostream>

class Random
{
private: // 如果我们希望这些可访问，可以是公有的
	static std::mt19937 generate()
	{
		std::random_device rd{};

		// 使用高分辨率时钟和来自 std::random_device 的 7 个随机数创建 seed_seq
		std::seed_seq ss{
			static_cast<std::seed_seq::result_type>(std::chrono::steady_clock::now().time_since_epoch().count()),
				rd(), rd(), rd(), rd(), rd(), rd(), rd() };

		return std::mt19937{ ss };
	}

	static inline std::mt19937 mt{ generate() }; // 生成一个已播种的 std::mt19937 并将其复制到我们的全局对象中

public:
	// 生成一个介于 [min, max] 之间的随机整数（包含边界）
	static int get(int min, int max)
	{
		return std::uniform_int_distribution{min, max}(mt);
	}
};

int main()
{
	// 打印一堆随机数
	for (int count{ 1 }; count <= 10; ++count)
		std::cout << Random::get(1, 6) << '\t';

	std::cout << '\n';

	return 0;
}

在命名空间中声明的任何对象都是全局变量。当我们声明 inline std::mt19937 mt 在命名空间内部时，我们声明的是 mt 作为一个内联全局变量。这使得整个程序可以使用单个实例 std::mt19937 （通过全局变量 mt)。

相反，当类对象被实例化时，该类对象包含每个非静态数据成员的副本。我们不希望每个类对象都有自己的副本 std::mt19937。因此，我们声明 static inline std::mt19937 mt，这告诉编译器单个实例 std::mt19937 应该作为 Random 类的一部分存在。定义 mt 为 static inline 使其成为内联变量，允许我们在类定义内部初始化它（我们在课程中讨论这一点 15.6 -- 静态成员变量)。
