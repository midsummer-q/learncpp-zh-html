22.4 — std::move

● 机器译文 课程 22.4 查看英文原文

一旦你开始更频繁地使用移动语义，你会遇到这样的情况：你想调用移动语义，但手头的对象是左值，而不是右值。考虑下面的 swap 函数作为例子：

#include <iostream>
#include <string>

template <typename T>
void mySwapCopy(T& a, T& b) 
{ 
	T tmp { a }; // 调用拷贝构造函数
	a = b; // 调用拷贝赋值运算符
	b = tmp; // 调用拷贝赋值运算符
}

int main()
{
	std::string x{ "abc" };
	std::string y{ "de" };

	std::cout << "x: " << x << '\n';
	std::cout << "y: " << y << '\n';

	mySwapCopy(x, y);

	std::cout << "x: " << x << '\n';
	std::cout << "y: " << y << '\n';

	return 0;
}

传入两个类型为 T（这里为 std::string）的对象，该函数通过三次拷贝来交换它们的值。因此，该程序输出：

x: abc
y: de
x: de
y: abc

正如上一课所示，进行拷贝可能效率低下。而这个版本的 swap 进行了 3 次拷贝。这会导致大量不必要的字符串创建和销毁，速度很慢。

然而，这里并不需要拷贝。我们真正要做的只是交换 a 和 b 的值，这完全可以通过 3 次移动来实现！因此，如果我们从拷贝语义切换到移动语义，可以使代码更高效。

但如何做到呢？问题在于参数 a 和 b 是左值引用，而不是右值引用，所以我们无法调用移动构造函数和移动赋值运算符来代替拷贝构造函数和拷贝赋值运算符。默认情况下，我们得到的是拷贝构造函数和拷贝赋值的行为。我们该怎么办？

std::move

在 C++11 中，std::move 是一个标准库函数，它将参数（使用 static_cast）转换为右值引用，从而可以调用移动语义。因此，我们可以使用 std::move 将左值转换为更倾向于被移动而不是被拷贝的类型。std::move 定义在 utility 头文件中。

下面是相同的程序，但带有一个 mySwapMove() 函数，它使用 std::move 将左值转换为右值，以便调用移动语义：

#include <iostream>
#include <string>
#include <utility> // for std::move

template <typename T>
void mySwapMove(T& a, T& b) 
{ 
	T tmp { std::move(a) }; // 调用移动构造函数
	a = std::move(b); // 调用移动赋值运算符
	b = std::move(tmp); // 调用移动赋值运算符
}

int main()
{
	std::string x{ "abc" };
	std::string y{ "de" };

	std::cout << "x: " << x << '\n';
	std::cout << "y: " << y << '\n';

	mySwapMove(x, y);

	std::cout << "x: " << x << '\n';
	std::cout << "y: " << y << '\n';

	return 0;
}

输出与上面相同：

x: abc
y: de
x: de
y: abc

但效率更高。当初始化 tmp 时，我们不是拷贝 x，而是使用 std::move 将左值变量 x 转换为右值。由于参数是右值，移动语义被调用，x 被移动到 tmp 中。

再经过几次交换，变量 x 的值被移动到 y，y 的值被移动到 x。

另一个示例

我们也可以在填充容器（如 std::vector）的元素时使用 std::move 来处理左值。

在下面的程序中，我们首先使用拷贝语义向 vector 添加一个元素。然后使用移动语义向 vector 添加一个元素。

#include <iostream>
#include <string>
#include <utility> // for std::move
#include <vector>

int main()
{
	std::vector<std::string> v;

	// 我们使用 std::string，因为它是可移动的（std::string_view 不可移动）
	std::string str { "Knock" };

	std::cout << "Copying str\n";
	v.push_back(str); // 调用 push_back 的左值版本，将 str 拷贝到数组元素中
	
	std::cout << "str: " << str << '\n';
	std::cout << "vector: " << v[0] << '\n';

	std::cout << "\nMoving str\n";

	v.push_back(std::move(str)); // 调用 push_back 的右值版本，将 str 移动到数组元素中
	
	std::cout << "str: " << str << '\n'; // 此结果是不确定的
	std::cout << "vector:" << v[0] << ' ' << v[1] << '\n';

	return 0;
}

在作者的机器上，该程序输出：

Copying str
str: Knock
vector: Knock

Moving str
str:
vector: Knock Knock

在第一种情况下，我们向 push_back() 传递了一个左值，因此它使用拷贝语义向 vector 添加元素。因此，str 中的值保持不变。

在第二种情况下，我们向 push_back() 传递了一个右值（实际上是通过 std::move 转换的左值），因此它使用移动语义向 vector 添加元素。这样更高效，因为 vector 元素可以窃取字符串的值，而不必复制它。

被移动的对象将处于有效但可能不确定的状态

当我们从临时对象移动值时，被移动对象留下什么值并不重要，因为临时对象会立即被销毁。但对于我们使用 std::move() 的左值对象呢？因为我们可以继续访问这些对象（例如在上面的例子中，我们在移动后打印了 str 的值），所以知道它们被留下什么值是有用的。

这里有两种观点。一种观点认为，被移动的对象应该重置为某种默认/零状态，即对象不再拥有资源。我们在上面看到了一个例子，其中 str 被清空为空字符串。

另一种观点认为，我们应该做最方便的事情，而不必拘泥于必须清除被移动的对象，如果这样做不方便的话。

那么标准库在这种情况下是怎么做的呢？关于这一点，C++ 标准说：“除非另有说明，被移动的对象（C++ 标准库中定义的类型）应置于有效但未指定的状态。”

在上面的例子中，当作者打印 str 在调用 std::move 后的值时，它打印了一个空字符串。然而，这不是必需的，它可能打印任何有效的字符串，包括空字符串、原始字符串或任何其他有效字符串。因此，我们应该避免使用被移动对象的值，因为结果将是实现特定的。

在某些情况下，我们希望重用值已被移动的对象（而不是分配新对象）。例如，在上面的 mySwapMove() 实现中，我们首先将资源移出 a，然后将另一个资源移入 a。这没问题，因为我们从未在移出资源和赋予 a 新的确定值之间使用 a 的值。

对于被移动的对象，调用任何不依赖于对象当前值的函数都是安全的。这意味着我们可以设置或重置被移动对象的值（使用 operator=，或任何类型的 clear() 或 reset() 成员函数）。我们也可以测试被移动对象的状态（例如使用 empty() 来查看对象是否有值）。然而，我们应该避免像 operator[] 或 front() （返回容器中的第一个元素）这样的函数，因为这些函数依赖于容器有元素，而被移动的容器可能有也可能没有元素。

关键提示

std::move() 向编译器提示程序员不再需要某个对象的值。仅在你想移动值的持久对象上使用 std::move() ，并且不要对之后该对象的值做任何假设。在当前值被移动后，可以给被移动对象赋予新值（例如使用 operator=）。

std::move 还有哪些其他用途？

std::move 在对数组元素进行排序时也很有用。许多排序算法（如选择排序和冒泡排序）通过交换元素对来工作。在之前的课程中，我们不得不使用拷贝语义来进行交换。现在我们可以使用移动语义，效率更高。

如果我们想将一个智能指针管理的内容移动到另一个智能指针，它也会很有用。

相关内容

有一个有用的变体 std::move() 调用 std::move_if_noexcept() ，如果对象有移动构造函数，则返回可移动的右值，否则返回可拷贝的左值。我们在课程 noexcept 中介绍了这一点。 27.10 -- std::move_if_noexcept。

总结

当我们想将左值视为右值以调用移动语义而不是拷贝语义时，可以使用 std::move。
