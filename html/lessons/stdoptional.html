12.15 — std::optional

● 机器译文 课程 12.15 查看英文原文

在课程 9.4 -- 检测和处理错误我们讨论了函数遇到自身无法合理处理的错误的情况。例如，考虑一个计算并返回值的函数：

int doIntDivision(int x, int y)
{
    return x / y;
}

如果调用者传入一个语义上无效的值（例如 y = 0），该函数无法计算要返回的值（因为除以0在数学上是未定义的）。在这种情况下我们该怎么办？由于计算结果函数不应有副作用，该函数无法自行合理解决错误。在这种情况下，通常的做法是让函数检测错误，然后将错误传回给调用者，以便以某种程序适当的方式处理。

在之前链接的课程中，我们介绍了两种让函数向调用者返回错误的方法：

  • 让返回void的函数改为返回bool（表示成功或失败）。
  • 让返回值函数返回一个哨兵值（一个在函数可能返回的其他值集合中不会出现的特殊值）来表示错误。

作为后者的一个例子，下面的 reciprocal() 函数在用户传入语义无效的参数时返回值 0.0 （否则永远不会出现） x：

#include <iostream>

// x 的倒数是 1/x，如果 x=0 则返回 0.0
double reciprocal(double x)
{
    if (x == 0.0) // 如果 x 在语义上无效
       return 0.0; // 返回 0.0 作为哨兵值以指示发生错误

    return 1.0 / x;
}

void testReciprocal(double d)
{
     double result { reciprocal(d) };
     std::cout << "The reciprocal of " << d << " is ";
     if (result != 0.0)
         std::cout << result << '\n';
     else
         std::cout << "undefined\n";
}

int main()
{
    testReciprocal(5.0);
    testReciprocal(-4.0);
    testReciprocal(0.0);

    return 0;
}

虽然这是一个相当有吸引力的解决方案，但存在一些潜在的缺点：

  • 程序员必须知道函数使用哪个哨兵值来表示错误（并且对于使用此方法返回错误的每个函数，该值可能不同）。
  • 同一函数的不同版本可能使用不同的哨兵值。
  • 对于所有可能的哨兵值都是有效返回值的情况，此方法不适用。

考虑我们上面的 doIntDivision() 函数。如果用户传入 0 对于 y，它能返回什么值？我们不能使用 0，因为 0 除以任何数都得到 0 作为有效结果。事实上，没有任何值是我们能返回而不会自然出现的。

那么我们该怎么办？

首先，我们可以选择某个（希望是）不常见的返回值作为哨兵值，并用它来表示错误：

#include <limits> // for std::numeric_limits

// 失败时返回 std::numeric_limits<int>::lowest()
int doIntDivision(int x, int y)
{
    if (y == 0)
        return std::numeric_limits<int>::lowest();
    return x / y;
}

std::numeric_limits<T>::lowest() 是一个返回类型 T最负值的函数。它是 std::numeric_limits<T>::max() 函数（返回类型 T的最大正值）的对应函数，我们在课程 9.5 -- std::cin与处理无效输入。

中介绍过。在上面的例子中，如果 doIntDivision() 无法进行，我们返回 std::numeric_limits<int>::lowest()，它将最负的int值返回给调用者，以表示函数失败。

虽然这基本可行，但它有两个缺点：

  • 每次调用此函数时，我们需要测试返回值是否等于 std::numeric_limits<int>::lowest() 以查看是否失败。这既冗长又丑陋。
  • 这是一个 半谓词问题的例子：如果用户调用 doIntDivision(std::numeric_limits<int>::lowest(), 1)，返回的结果 std::numeric_limits<int>::lowest() 将模糊不清，无法确定函数是成功还是失败。根据函数的实际使用方式，这可能不是问题，但这是我们必须担心的另一件事，也是错误可能潜入程序的另一种潜在方式。

其次，我们可以放弃使用返回值来返回错误，而使用其他机制（例如异常）。然而，异常有其自身的复杂性和性能成本，可能不合适或不被期望。对于这种情况，可能有点过度。

第三，我们可以放弃返回单个值，而是返回两个值：一个（类型为 bool）指示函数是否成功，另一个（所需返回类型）保存实际返回值（如果函数成功）或不确定的值（如果函数失败）。这可能是这些选项中最好的。

在C++17之前，选择后一种选项需要您自己实现。虽然C++提供了多种方法来实现，但任何自行实现的方法都不可避免地会导致不一致和错误。

返回一个 std::optional

C++17 引入了 std::optional，这是一个实现可选值的类模板类型。也就是说，一个 std::optional<T> 要么有一个类型为 T的值，要么没有。我们可以用它来实现上面的第三种选项：

#include <iostream>
#include <optional> // for std::optional (C++17)

// 我们的函数现在可选地返回一个 int 值
std::optional<int> doIntDivision(int x, int y)
{
    if (y == 0)
        return {}; // 或返回 std::nullopt
    return x / y;
}

int main()
{
    std::optional<int> result1 { doIntDivision(20, 5) };
    if (result1) // 如果函数返回了一个值
        std::cout << "Result 1: " << *result1 << '\n'; // 获取值
    else
        std::cout << "Result 1: failed\n";

    std::optional<int> result2 { doIntDivision(5, 0) };

    if (result2)
        std::cout << "Result 2: " << *result2 << '\n';
    else
        std::cout << "Result 2: failed\n";

    return 0;
}

这会打印：

Result 1: 4
Result 2: failed

使用 std::optional 非常简单。我们可以构造一个 std::optional<T> ，无论是否带有值：

std::optional<int> o1 { 5 };            // 用值初始化
std::optional<int> o2 {};               // 无值初始化
std::optional<int> o3 { std::nullopt }; // 无值初始化

要检查一个 std::optional 是否有值，我们可以选择以下方法之一：

if (o1.has_value()) // 调用 has_value() 检查 o1 是否有值
if (o2)             // 使用隐式转换为 bool 来检查 o2 是否有值

要从一个 std::optional中获取值，我们可以选择以下方法之一：

std::cout << *o1;             // 解引用获取 o1 中存储的值（如果 o1 没有值，则为未定义行为）
std::cout << o2.value();      // 调用 value() 获取 o2 中存储的值（如果 o2 没有值，则抛出 std::bad_optional_access 异常）
std::cout << o3.value_or(42); // 调用 value_or() 获取 o3 中存储的值（如果 o3 没有值，则获取值 `42`）

注意 std::optional 的使用语法与指针基本相同：

行为指针std::optional
不持有值初始化/赋值 {} 或 std::nullptr初始化/赋值 {} 或 std::nullopt
持有值初始化/赋值一个地址初始化/赋值一个值
检查是否有值隐式转换为 bool隐式转换为 bool 或 has_value()
获取值解引用解引用或 value()

然而，从语义上讲，指针和 std::optional 是相当不同的。

  • 指针具有引用语义，意味着它引用其他对象，赋值会复制指针本身，而不是对象。如果我们通过地址返回指针，指针会被复制回调用者，而不是被指向的对象。这意味着我们不能通过地址返回局部对象，因为我们会将该对象的地址复制回调用者，然后该对象将被销毁，导致返回的指针悬空。
  • 一个 std::optional 具有值语义，意味着它实际包含其值，赋值会复制该值。如果我们按值返回 std::optional ，则 std::optional （包括包含的值）会被复制回调用者。这意味着我们可以使用 std::optional。

将值从函数返回给调用者。考虑到这一点，让我们看看我们的示例是如何工作的。我们的 doIntDivision() 现在返回一个 std::optional<int> 而不是 int。在函数体内，如果检测到错误，我们返回 {}，它会隐式返回一个 std::optional ，其中不包含任何值。如果我们有值，则返回该值，这会隐式返回一个 std::optional ，其中包含该值。

在 main()，我们使用隐式转换为 bool 来检查返回的 std::optional 是否有值。如果有，则解引用 std::optional 对象以获取值。如果没有，则执行错误处理。就是这样！

返回 std::optional

返回一个 std::optional 的优点和缺点

  • 使用 std::optional 很好，原因如下：
  • 有效地记录了函数可能返回值或不返回值。
  • 使用 std::optional 的语法方便且直观。

返回一个 std::optional 确实有一些缺点：

  • 我们必须确保 std::optional 在获取值之前包含一个值。如果解引用一个不包含值的 std::optional ，会导致未定义行为。
  • std::optional 不提供传递函数失败原因信息的方式。

除非你的函数需要返回关于失败原因的额外信息（以便更好地理解失败或区分不同类型的失败）， std::optional 对于可能返回值或失败的函数来说是一个极好的选择。

最佳实践

返回一个 std::optional （而不是哨兵值）用于可能失败的函数，除非你的函数需要返回关于失败原因的额外信息。

相关内容

std::expected （C++23 引入）旨在处理函数可能返回期望值或意外错误码的情况。请参阅 std::expected 参考 了解更多信息。

使用 std::optional 作为可选函数参数

在课程 12.11 -- 按地址传递（第 2 部分），我们讨论了如何通过地址传递来允许函数接受“可选”参数（即调用者可以传入 nullptr 表示“无参数”或传入一个对象）。然而，这种方法的一个缺点是，非 nullptr 参数必须是左值（以便其地址可以传递给函数）。

也许并不意外（鉴于其名称）， std::optional 是函数接受可选参数（仅用作输入参数）的另一种方式。而不是这样：

#include <iostream>

void printIDNumber(const int *id=nullptr)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(&userid); // 我们现在知道用户的 ID 了

    return 0;
}

您可以这样做：

#include <iostream>
#include <optional>

void printIDNumber(std::optional<const int> id = std::nullopt)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // 我们还不知道用户的 ID

    int userid { 34 };
    printIDNumber(userid); // 我们现在知道用户的 ID 了

    printIDNumber(62); // 我们也可以传递一个右值
    
    return 0;
}

这种方法有两个优点：

  1. 它有效地记录了该参数是可选的。
  2. 我们可以传入一个右值（因为 std::optional 会进行复制）。

然而，因为 std::optional 会复制其参数，因此当 T 是复制开销大的类型（如 std::string）时，这就会成为问题。对于普通函数参数，我们通过将参数设为 const lvalue reference来避免复制。不幸的是，截至 C++23， std::optional 不支持引用。

因此，我们建议仅在 std::optional<T> 通常按值传递时，才使用 T 作为可选参数。否则，请使用 const T*。

进阶读者

尽管 std::optional 不直接支持引用，你可以使用 std::reference_wrapper （我们在课程 17.5 -- 通过 std::reference_wrapper 的引用数组来模拟引用。让我们看看使用 std::string id 和 std::reference_wrapper：

#include <functional>  // for std::reference_wrapper
#include <iostream>
#include <optional>
#include <string>

struct Employee
{
    std::string name{}; // 复制开销大
    int id;
};

void printEmployeeID(std::optional<std::reference_wrapper<Employee>> e=std::nullopt)
{
    if (e)
        std::cout << "Your ID number is " << e->get().id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printEmployeeID(); // 我们还不知道 Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // 我们现在知道 Employee 的 ID 了

    return 0;
}

作为对比，指针版本：

#include <iostream>
#include <string>

struct Employee
{
    std::string name{}; // 复制开销大
    int id;
};

void printEmployeeID(const Employee* e=nullptr)
{
    if (e)
        std::cout << "Your ID number is " << e->id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printEmployeeID(); // 我们还不知道 Employee

    Employee e { "James", 34 };
    printEmployeeID(&e); // 我们现在知道 Employee 的 ID 了

    return 0;
}

这两个程序几乎相同。我们认为前者并不比后者更易读或更易维护，也不值得为此在程序中引入两个额外的类型。

在许多情况下，函数重载提供了更好的解决方案：

#include <iostream>
#include <string>

struct Employee
{
    std::string name{}; // 复制开销大
    int id;
};

void printEmployeeID()
{
    std::cout << "Your ID number is not known.\n";
}

void printEmployeeID(const Employee& e)
{
    std::cout << "Your ID number is " << e.id << ".\n";
}

int main()
{
    printEmployeeID(); // 我们还不知道 Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // 我们现在知道 Employee 的 ID 了

    printEmployeeID( { "Dave", 62 } ); // 我们甚至可以传递右值

    return 0;
}

最佳实践

优先使用 std::optional 用于可选返回类型。

对于可选函数参数，优先使用函数重载（如果可能）。否则，使用 std::optional<T> 用于可选参数，当 T 通常按值传递。优先 const T* 当 T 复制开销很大。
