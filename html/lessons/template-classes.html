26.1 — 模板类

● 机器译文 课程 26.1 查看英文原文

在之前的章节中，我们介绍了函数模板（11.6 -- 函数模板），它允许我们泛化函数以处理多种不同的数据类型。虽然这是迈向泛型编程的良好开端，但它并不能解决我们所有的问题。让我们看一个此类问题的示例，并了解模板还能为我们做些什么。

模板和容器类

在关于 23.6 -- 容器类中，你学习了如何使用组合来实现包含多个其他类实例的类。作为此类容器的一个示例，我们研究了 IntArray 类。以下是该类的简化示例：

#ifndef INTARRAY_H
#define INTARRAY_H

#include <cassert>

class IntArray
{
private:
    int m_length{};
    int* m_data{};

public:

    IntArray(int length)
    {
        assert(length > 0);
        m_data = new int[length]{};
        m_length = length;
    }

    // 我们不想允许创建IntArray的副本。
    IntArray(const IntArray&) = delete;
    IntArray& operator=(const IntArray&) = delete;

    ~IntArray()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // 我们需要确保在此处将m_data设置为0，否则它将
        // 指向已释放的内存！
        m_data = nullptr;
        m_length = 0;
    }

    int& operator[](int index)
    {
        assert(index >= 0 && index < m_length);
        return m_data[index];
    }

    int getLength() const { return m_length; }
};

#endif

虽然这个类提供了一种创建整数数组的简便方法，但如果我们要创建一个双精度浮点数数组呢？使用传统的编程方法，我们必须创建一个全新的类！以下是 DoubleArray 的示例，这是一个用于保存双精度浮点数的数组类。

#ifndef DOUBLEARRAY_H
#define DOUBLEARRAY_H

#include <cassert>

class DoubleArray
{
private:
    int m_length{};
    double* m_data{};

public:

    DoubleArray(int length)
    {
        assert(length > 0);
        m_data = new double[length]{};
        m_length = length;
    }

    DoubleArray(const DoubleArray&) = delete;
    DoubleArray& operator=(const DoubleArray&) = delete;

    ~DoubleArray()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // 我们需要确保在此处将m_data设置为0，否则它将
        // 指向已释放的内存！
        m_data = nullptr;
        m_length = 0;
    }

    double& operator[](int index)
    {
        assert(index >= 0 && index < m_length);
        return m_data[index];
    }

    int getLength() const { return m_length; }
};

#endif

尽管代码清单很长，但你会注意到这两个类几乎完全相同！实际上，唯一实质性的区别是所包含的数据类型（int 与 double）。正如你可能已经猜到的，这是模板可以发挥作用的另一个领域，使我们不必创建绑定到特定数据类型的类。

创建模板类的方式与创建模板函数几乎完全相同，因此我们将通过示例进行说明。这是我们的数组类的模板版本：

Array.h：

#ifndef ARRAY_H
#define ARRAY_H

#include <cassert>

template <typename T> // 已添加
class Array
{
private:
    int m_length{};
    T* m_data{}; // 将类型改为T

public:

    Array(int length)
    {
        assert(length > 0);
        m_data = new T[length]{}; // 分配了一个类型为T的对象数组
        m_length = length;
    }

    Array(const Array&) = delete;
    Array& operator=(const Array&) = delete;

    ~Array()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // 我们需要确保在此处将m_data设置为0，否则它将
        // 指向已释放的内存！
        m_data = nullptr;
        m_length = 0;
    }

    // 模板化的operator[]函数定义如下
    T& operator[](int index); // 现在返回T&

    int getLength() const { return m_length; }
};

// 在类外部定义的成员函数需要自己的模板声明
template <typename T>
T& Array<T>::operator[](int index) // 现在返回T&
{
    assert(index >= 0 && index < m_length);
    return m_data[index];
}

#endif

如你所见，这个版本与 IntArray 版本几乎相同，只是我们添加了模板声明，并将包含的数据类型从 int 改为 T。

注意，我们还将 operator[] 函数定义在类声明之外。这不是必须的，但新手程序员通常第一次尝试这样做时会因为语法而遇到困难，因此提供一个示例是有指导意义的。在类声明之外定义的每个模板成员函数都需要自己的模板声明。另外，请注意模板数组类的名称是 Array<T>，而不是 Array——Array 指的是名为 Array 的非模板版本，除非在类内部使用 Array。例如，拷贝构造函数和拷贝赋值运算符使用了 Array 而不是 Array<T>。当在类内部使用不带模板参数的类名时，参数与当前实例化的参数相同。

以下是使用上述模板数组类的简短示例：

#include <iostream>
#include "Array.h"

int main()
{
	const int length { 12 };
	Array<int> intArray { length };
	Array<double> doubleArray { length };

	for (int count{ 0 }; count < length; ++count)
	{
		intArray[count] = count;
		doubleArray[count] = count + 0.5;
	}

	for (int count{ length - 1 }; count >= 0; --count)
		std::cout << intArray[count] << '\t' << doubleArray[count] << '\n';

	return 0;
}

此示例输出以下内容：

11     11.5
10     10.5
9       9.5
8       8.5
7       7.5
6       6.5
5       5.5
4       4.5
3       3.5
2       2.5
1       1.5
0       0.5

模板类的实例化方式与模板函数相同——编译器按需生成一个副本，将模板参数替换为用户需要的实际数据类型，然后编译该副本。如果你从未使用过模板类，编译器甚至不会编译它。

模板类非常适合实现容器类，因为非常希望容器能够适用于多种数据类型，而模板允许你无需重复代码即可实现这一点。尽管语法丑陋，错误信息可能晦涩难懂，但模板类确实是 C++ 最好、最有用的特性之一。

拆分模板类

模板不是类或函数——它是用于创建类或函数的模板。因此，它的工作方式与普通函数或类不太相同。在大多数情况下，这没什么大问题。然而，有一个领域经常给开发者带来麻烦。

对于非模板类，通常的做法是将类定义放在头文件中，将成员函数定义放在同名的代码文件中。这样，成员函数定义被编译为单独的项目文件。但是，对于模板，这种方法行不通。考虑以下情况：

Array.h：

#ifndef ARRAY_H
#define ARRAY_H

#include <cassert>

template <typename T> // 已添加
class Array
{
private:
    int m_length{};
    T* m_data{}; // 将类型改为T

public:

    Array(int length)
    {
        assert(length > 0);
        m_data = new T[length]{}; // 分配了一个类型为T的对象数组
        m_length = length;
    }

    Array(const Array&) = delete;
    Array& operator=(const Array&) = delete;

    ~Array()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // 我们需要确保在此处将m_data设置为0，否则它将
        // 指向已释放的内存！
        m_data = nullptr;
        m_length = 0;
    }

    // 模板化的operator[]函数定义如下
    T& operator[](int index); // 现在返回T&

    int getLength() const { return m_length; }
};

// Array<T>::operator[]的定义已移至下面的Array.cpp中

#endif

Array.cpp：

#include "Array.h"

// 在类外部定义的成员函数需要自己的模板声明
template <typename T>
T& Array<T>::operator[](int index) // 现在返回T&
{
    assert(index >= 0 && index < m_length);
    return m_data[index];
}

main.cpp:

#include <iostream>
#include "Array.h"

int main()
{
	const int length { 12 };
	Array<int> intArray { length };
	Array<double> doubleArray { length };

	for (int count{ 0 }; count < length; ++count)
	{
		intArray[count] = count;
		doubleArray[count] = count + 0.5;
	}

	for (int count{ length - 1 }; count >= 0; --count)
		std::cout << intArray[count] << '\t' << doubleArray[count] << '\n';

	return 0;
}

上述程序可以编译，但会导致链接器错误：

undefined reference to `Array<int>::operator[](int)'

与函数模板一样，只有当类模板在翻译单元中被使用时（例如作为对象类型如 intArray），编译器才会实例化它。为了执行实例化，编译器必须同时看到完整的类模板定义（不仅仅是声明）和所需的特定模板类型。

还要记住 C++ 是单独编译文件的。当编译 main.cpp 时，Array.h 头文件的内容（包括模板类定义）被复制到 main.cpp 中。当编译器看到我们需要两个模板实例 Array<int> 和 Array<double> 时，它会实例化它们，并将它们作为 main.cpp 翻译单元的一部分进行编译。因为 operator[] 成员函数有声明，编译器会接受对其的调用，假设它将在其他地方定义。

当单独编译 Array.cpp 时，Array.h 头文件的内容被复制到 Array.cpp 中，但编译器在 Array.cpp 中找不到任何需要实例化 Array 类模板或 Array<int>::operator[] 函数模板的代码——因此它不会实例化任何东西。

因此，当程序链接时，我们会得到一个链接器错误，因为 main.cpp 调用了 Array<int>::operator[] 但该模板函数从未被实例化！

有几种方法可以解决这个问题。

最简单的方法是将所有模板类代码放在头文件中（在这种情况下，将 Array.cpp 的内容放在 Array.h 中，位于类定义之后）。这样，当你 #include 头文件时，所有模板代码将位于一处。这种方法的优点是简单。缺点是如果模板类在许多文件中使用，你最终会得到许多模板类的本地实例，这可能会增加编译和链接时间（你的链接器应该会移除重复的定义，因此不会使可执行文件膨胀）。这是我们的首选解决方案，除非编译或链接时间开始成为问题。

如果你觉得将 Array.cpp 代码放入 Array.h 头文件会使头文件过长/混乱，另一种方法是将 Array.cpp 的内容移动到一个名为 Array.inl 的新文件中（.inl 代表内联），然后在 Array.h 头文件的底部（在头文件保护内部）包含 Array.inl。这会产生与将所有代码放在头文件中相同的结果，但有助于保持代码更有条理。

提示

如果你使用 .inl 方法，然后遇到关于重复定义的编译器错误，很可能是你的编译器将 .inl 文件作为项目的一部分进行编译，就像它是一个代码文件一样。这会导致 .inl 的内容被编译两次：一次是编译器编译 .inl 时，另一次是包含 .inl 的 .cpp 文件被编译时。如果 .inl 文件包含任何非内联函数（或变量），那么我们将违反单一定义规则。如果发生这种情况，你需要将 .inl 文件排除在构建编译之外。

通常可以通过在项目视图中右键单击 .inl 文件，然后选择属性来排除 .inl 的构建。设置就在那里。在 Visual Studio 中，将“从生成中排除”设置为“是”。在 Code::Blocks 中，取消选中“编译文件”和“链接文件”。

其他解决方案包括 #include .cpp 文件，但由于 #include 的非标准用法，我们不推荐这样做。

另一种替代方案是使用三文件方法。模板类定义放在头文件中。模板类成员函数放在代码文件中。然后添加第三个文件，其中包含 所有 你需要的所有实例化类：

templates.cpp：

// 确保完整的Array模板定义可见
#include "Array.h"
#include "Array.cpp" // we're breaking best practices here, but only in this one place

// 在此处包含你需要的其他.h和.cpp模板定义

template class Array<int>; // 显式实例化模板Array<int>
template class Array<double>; // 显式实例化模板Array<double>

// 在此处实例化其他模板

“template class”命令导致编译器显式实例化模板类。在上述情况下，编译器将在 templates.cpp 中生成 Array<int> 和 Array<double> 的定义。其他想要使用这些类型的代码文件可以包含 Array.h（以满足编译器），链接器将从 template.cpp 链接这些显式类型定义。

这种方法可能更高效（取决于你的编译器和链接器如何处理模板和重复定义），但需要为每个程序维护 templates.cpp 文件。
