25.3 — override 和 final 说明符，以及协变返回类型

● 机器译文 课程 25.3 查看英文原文

为了解决继承中的一些常见问题，C++ 提供了两个与继承相关的标识符： override 和 final。注意，这些标识符不是关键字——它们是普通的单词，只有在特定上下文中使用时才具有特殊含义。C++ 标准称它们为“具有特殊含义的标识符”，但通常被称为“说明符”。

虽然 final 用得不多，但 override 是一个极好的补充，你应该经常使用它。在本课中，我们将介绍这两者，以及虚函数覆盖返回类型必须匹配这一规则的一个例外。

override 说明符

正如我们在上一课中提到的，派生类的虚函数只有在签名和返回类型完全匹配时才被视为覆盖。这可能导致无意中的问题，即本意是覆盖的函数实际上并没有覆盖。

考虑以下示例：

#include <iostream>
#include <string_view>

class A
{
public:
	virtual std::string_view getName1(int x) { return "A"; }
	virtual std::string_view getName2(int x) { return "A"; }
};

class B : public A
{
public:
	virtual std::string_view getName1(short x) { return "B"; } // 注意：参数是 short 类型
	virtual std::string_view getName2(int x) const { return "B"; } // 注意：函数是 const 的
};

int main()
{
	B b{};
	A& rBase{ b };
	std::cout << rBase.getName1(1) << '\n';
	std::cout << rBase.getName2(2) << '\n';

	return 0;
}

因为 rBase 是一个指向 B 对象的 A 引用，这里的意图是使用虚函数来访问 B::getName1() 和 B::getName2()。然而，由于 B::getName1() 接受不同的参数（short 而不是 int），它不被视为对 A::getName1() 的覆盖。更隐蔽的是，由于 B::getName2() 是 const 而 A::getName2() 不是，B::getName2() 不被视为对 A::getName2() 的覆盖。

因此，该程序输出：

A
A

在这个特定例子中，因为 A 和 B 只是打印它们的名字，很容易看出我们搞砸了覆盖，并且调用了错误的虚函数。然而，在更复杂的程序中，当函数具有不打印的行为或返回值时，这类问题可能非常难以调试。

为了帮助解决本意是覆盖但实际上不是覆盖的函数问题， override 说明符可以应用于任何虚函数，以告诉编译器强制该函数是一个覆盖。 override 说明符放在成员函数声明的末尾（与函数级别的 const 相同的位置）。如果成员函数既是 const 又是覆盖，那么 const 必须放在 override。

之前。如果标记为 override 的函数没有覆盖基类函数（或者应用于非虚函数），编译器将标记该函数为错误。

#include <string_view>

class A
{
public:
	virtual std::string_view getName1(int x) { return "A"; }
	virtual std::string_view getName2(int x) { return "A"; }
	virtual std::string_view getName3(int x) { return "A"; }
};

class B : public A
{
public:
	std::string_view getName1(short int x) override { return "B"; } // 编译错误，函数不是覆盖
	std::string_view getName2(int x) const override { return "B"; } // 编译错误，函数不是覆盖
	std::string_view getName3(int x) override { return "B"; } // 正确，函数是 A::getName3(int) 的覆盖

};

int main()
{
	return 0;
}

上述程序产生两个编译错误：一个针对 B::getName1()，另一个针对 B::getName2()，因为两者都没有覆盖先前的函数。B::getName3() 确实覆盖了 A::getName3()，因此该行不会产生错误。

由于使用 override 说明符没有性能损失，并且它有助于确保你确实覆盖了你认为的函数，所有虚覆盖函数都应该使用 override 说明符标记。此外，因为 override 说明符隐含了 virtual，所以不需要在使用了 override 说明符的函数上再使用 virtual 关键字。

最佳实践

在基类中的虚函数上使用 virtual 关键字。

在派生类的覆盖函数上使用 override 说明符（但不使用 virtual 关键字）。这包括虚析构函数。

规则

如果成员函数既是 const 又是 override， const 必须放在前面。 const override 是正确的， override const 则不是。

final 说明符

在某些情况下，你可能不希望有人能够覆盖虚函数，或者从类继承。final 说明符可以用来告诉编译器强制执行这一点。如果用户试图覆盖一个被指定为 final 的函数，或者继承一个被指定为 final 的类，编译器将给出编译错误。

在希望限制用户覆盖函数的情况下， final 说明符 的使用位置与 override 说明符相同，如下所示：

#include <string_view>

class A
{
public:
	virtual std::string_view getName() const { return "A"; }
};

class B : public A
{
public:
	// 注意下一行使用了 final 说明符——这使得该函数不能在派生类中被覆盖
	std::string_view getName() const override final { return "B"; } // 正确，覆盖了 A::getName()
};

class C : public B
{
public:
	std::string_view getName() const override { return "C"; } // 编译错误：覆盖了 B::getName()，而它是 final 的
};

在上面的代码中，B::getName() 覆盖了 A::getName()，这没问题。但是 B::getName() 有 final 说明符，这意味着任何对该函数的进一步覆盖都应被视为错误。确实，C::getName() 试图覆盖 B::getName()（这里的 override 说明符不相关，只是为了良好的实践），因此编译器将给出编译错误。

在希望防止从类继承的情况下，final 说明符应用于类名之后：

#include <string_view>

class A
{
public:
	virtual std::string_view getName() const { return "A"; }
};

class B final : public A // 注意此处使用了 final 说明符
{
public:
	std::string_view getName() const override { return "B"; }
};

class C : public B // 编译错误：不能从 final 类继承
{
public:
	std::string_view getName() const override { return "C"; }
};

在上面的例子中，类 B 被声明为 final。因此，当 C 试图继承 B 时，编译器将给出编译错误。

协变返回类型

有一种特殊情况，派生类的虚函数覆盖可以具有与基类不同的返回类型，并且仍然被视为匹配的覆盖。如果虚函数的返回类型是指向某个类的指针或引用，覆盖函数可以返回指向派生类的指针或引用。这些被称为 协变返回类型。下面是一个例子：

#include <iostream>
#include <string_view>

class Base
{
public:
	// 这个版本的 getThis() 返回一个指向 Base 类的指针
	virtual Base* getThis() { std::cout << "called Base::getThis()\n"; return this; }
	void printType() { std::cout << "returned a Base\n"; }
};

class Derived : public Base
{
public:
	// 通常覆盖函数必须返回与基函数相同类型的对象
	// 然而，因为 Derived 派生自 Base，所以返回 Derived* 而不是 Base* 是允许的
	Derived* getThis() override { std::cout << "called Derived::getThis()\n";  return this; }
	void printType() { std::cout << "returned a Derived\n"; }
};

int main()
{
	Derived d{};
	Base* b{ &d };
	d.getThis()->printType(); // 调用 Derived::getThis()，返回 Derived*，调用 Derived::printType
	b->getThis()->printType(); // 调用 Derived::getThis()，返回 Base*，调用 Base::printType

	return 0;
}

这会打印：

called Derived::getThis()
returned a Derived
called Derived::getThis()
returned a Base

关于协变返回类型的一个有趣说明：C++ 不能动态选择类型，所以你总是得到与正在调用的实际函数版本匹配的类型。

在上面的例子中，我们首先调用 d.getThis()。由于 d 是 Derived，这调用了 Derived::getThis()，它返回一个 Derived*。这个 Derived* 然后用于调用非虚函数 Derived::printType()。

现在来看有趣的情况。然后我们调用 b->getThis()。变量 b 是一个指向 Derived 对象的 Base 指针。Base::getThis() 是一个虚函数，因此这会调用 Derived::getThis()。尽管 Derived::getThis() 返回一个 Derived*，但由于 Base 版本的函数返回一个 Base*，返回的 Derived* 被向上转型为 Base*。因为 Base::printType() 是非虚函数，所以调用的是 Base::printType()。

换句话说，在上面的例子中，只有当你在最初就使用类型为 Derived 的对象调用 getThis() 时，你才会得到一个 Derived*

注意，如果 printType() 是虚函数而非非虚函数，那么 b->getThis() 的结果（一个类型为 Base*的对象）将经历虚函数解析，并且会调用 Derived::printType()。

协变返回类型通常用于虚成员函数返回指向包含该成员函数的类的指针或引用的情况（例如 Base::getThis() 返回一个 Base*，而 Derived::getThis() 返回一个 Derived*）。但这并非严格必要。协变返回类型可以用于任何覆盖成员函数的返回类型派生自基类虚成员函数返回类型的情况。

问题 #1

以下程序输出什么？

#include <iostream>

class A
{
public:
    void print()
    {
        std::cout << "A";
    }
    virtual void vprint()
    {
        std::cout << "A";
    }
};
class B : public A
{
public:
    void print()
    {
        std::cout << "B";
    }
    void vprint() override
    {
        std::cout << "B";
    }
};


class C
{
private:
    A m_a{};

public:
    virtual A& get()
    {
        return m_a;
    }
};

class D : public C
{
private:
    B m_b{};

public:
    B& get() override // 协变返回类型
    {
        return m_b;
    }
};

int main()
{
    // // 情况1
    D d {};
    d.get().print();
    d.get().vprint();
    std::cout << '\n';
 
    // // 情况2
    C c {};
    c.get().print();
    c.get().vprint();
    std::cout << '\n';

    // // 情况3
    C& ref{ d };
    ref.get().print();
    ref.get().vprint();
    std::cout << '\n';

    return 0;
}

显示答案

BB
AA
AB

在所有情况下，因为 get() 具有协变返回类型，所以 get() 的返回类型将是隐式对象的 get() 成员函数的返回类型。

情况 1 很直接。在两个语句中， d.get() 调用 D::get()，它返回 m_b。因为 get() 被调用在 d上，其类型为 D，因此使用 D::get() 的返回类型，即类型 B&。对 print() 和 vprint() 的调用解析为 B::print() 和 B::vprint()

情况 2 也很直接。在两个语句中， c.get() 调用 C::get()，它返回 m_a。因为 get() 被调用在 c上，其类型为 C，因此使用 C::get() 的返回类型，即类型 A&。对 print() 和 vprint() 的调用解析为 A::print() 和 A::vprint()

情况 3 是有趣的情况。 ref 我们还调用了 C& 引用一个 D。 ref.get() 是一个虚函数，因此 ref.get() 虚解析为 D::get()，它返回 m_b的事实。然而， get() 具有协变返回类型，所以 get() 的返回类型由调用 get() 的隐式对象的类型决定。由于 ref 我们还调用了 C&，因此使用 C::get() 被使用，这意味着 ref.get() 等于 A& （引用对象 m_b，它是一个 B)。

因为 ref.get() 是一个 A&的返回类型，非虚函数调用 ref.get().print() 解析为 A::print()。

当虚函数 ref.get().vprint() 被调用时，使用虚函数解析。尽管 ref.get() 是一个 A&的返回类型，但实际引用的对象是一个 B。因此， B::vprint() 被调用。

问题 #2

何时使用函数重载 vs 函数覆盖？

显示答案

当我们需要一个成员或非成员函数在传入不同类型参数时表现不同，则使用函数重载。

当我们需要一个成员函数在隐式对象是派生类时表现不同，则使用函数覆盖。
