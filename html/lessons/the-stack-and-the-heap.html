20.2 — 栈与堆

● 机器译文 课程 20.2 查看英文原文

程序使用的内存通常被划分为几个不同的区域，称为段：

  • 代码段（也称为文本段），编译后的程序位于内存中。代码段通常是只读的。
  • BSS段（也称为未初始化数据段），存储零初始化的全局变量和静态变量。
  • 数据段（也称为初始化数据段），存储已初始化的全局变量和静态变量。
  • 堆，用于分配动态分配的变量。
  • 调用栈，用于存储函数参数、局部变量以及其他与函数相关的信息。

在本课中，我们将主要关注堆和栈，因为大多数有趣的事情都发生在这里。

堆段

堆段（也称为“自由存储区”）负责跟踪用于动态内存分配的内存。我们在课程 19.1 -- 使用 new 和 delete 进行动态内存分配中已经讨论过堆，这里将进行回顾。

在 C++ 中，当你使用 new 运算符分配内存时，该内存在应用程序的堆段中分配。

假设 int 为 4 字节：

int* ptr { new int }; // new int 在堆上分配 4 字节
int* array { new int[10] }; // new int[10] 在堆上分配 40 字节

该内存的地址由 operator new 返回，然后可以存储在指针中。你无需担心如何定位和分配空闲内存的机制。但值得知道的是，连续的内存请求可能不会导致分配连续的内存地址！

int* ptr1 { new int };
int* ptr2 { new int };
// ptr1 和 ptr2 的地址可能不连续

当动态分配的变量被删除时，内存被“归还”给堆，并可以在未来收到分配请求时重新分配。记住，删除指针并不会删除变量，它只是将关联地址的内存返回给操作系统。

堆有优点和缺点：

  • 在堆上分配内存相对较慢。
  • 分配的内存会一直保持分配状态，直到被显式释放（注意内存泄漏）或程序结束（此时操作系统应清理它）。
  • 动态分配的内存必须通过指针访问。解引用指针比直接访问变量慢。
  • 由于堆是一个大内存池，可以在这里分配大型数组、结构体或类。

调用栈

浮点类型的 调用堆栈 （通常简称为“栈”）扮演着更有趣的角色。调用栈跟踪从程序开始到当前执行点所有活跃的函数（那些已被调用但尚未终止的函数），并处理所有函数参数和局部变量的分配。

调用栈是作为栈数据结构实现的。因此，在讨论调用栈如何工作之前，我们需要了解什么是栈数据结构。

栈数据结构

一个 数据结构 是一种用于组织数据以便高效使用的编程机制。你已经见过几种类型的数据结构，例如数组和结构体。这两种数据结构都提供了存储数据和高效访问数据的机制。还有许多其他常用的数据结构，其中不少在标准库中实现，栈就是其中之一。

考虑自助餐厅里的一摞盘子。由于每个盘子都很重且堆叠在一起，你实际上只能做三件事：

  1. 查看顶部盘子的表面
  2. 从堆中取出顶部盘子（露出下面的盘子，如果有的话）
  3. 在堆顶放一个新盘子（遮住下面的盘子，如果有的话）

在计算机编程中，栈是一种容器数据结构，可以容纳多个变量（很像数组）。然而，数组允许你以任意顺序访问和修改元素（称为 随机访问的容器类型之一），而栈的限制更多。可以在栈上执行的操作对应于上面提到的三件事：

  1. 查看栈顶元素（通常通过名为 top() 的函数完成，有时也称为 peek()）
  2. 从栈中取出顶部元素（通过名为 pop() 的函数完成）
  3. 在栈顶放入一个新元素（通过名为 push() 的函数完成）

栈是一种后进先出（LIFO）结构。最后压入栈的元素将是第一个被弹出的元素。如果你在堆顶放一个新盘子，那么从堆中取出的第一个盘子将是你最后放上去的那个。后进先出。随着元素被压入栈，栈变大；随着元素被弹出，栈变小。

例如，下面是一个简短的序列，展示了压栈和出栈是如何工作的：

Stack: empty
Push 1
Stack: 1
Push 2
Stack: 1 2
Push 3
Stack: 1 2 3
Pop
Stack: 1 2
Pop
Stack: 1

盘子的类比很好地说明了调用栈的工作原理，但我们可以做一个更好的类比。考虑一堆邮箱，一个叠一个。每个邮箱只能容纳一个物品，并且所有邮箱最初都是空的。此外，每个邮箱都钉在下面的邮箱上，因此邮箱的数量不能改变。如果我们不能改变邮箱的数量，如何获得类似栈的行为呢？

首先，我们使用一个标记（比如便利贴）来跟踪最下面的空邮箱的位置。一开始，这将是最低的邮箱（在栈底）。当我们向邮箱栈中压入一个物品时，我们将其放入标记的邮箱（即第一个空邮箱），并将标记向上移动一个邮箱。当我们从栈中弹出一个物品时，我们将标记向下移动一个邮箱（使其指向顶部非空邮箱），并从该邮箱中取出物品。标记以下的任何内容都被视为“在栈上”。标记处或标记以上的内容不在栈上。

调用栈段

调用栈段保存用于调用栈的内存。当应用程序启动时，main()函数被操作系统压入调用栈。然后程序开始执行。

当遇到函数调用时，该函数被压入调用栈。当当前函数结束时，该函数从调用栈中弹出（这个过程有时称为 栈展开）。因此，通过查看当前在调用栈上的函数，我们可以看到为了到达当前执行点而调用的所有函数。

我们上面的邮箱类比与调用栈的工作方式非常相似。栈本身是一个固定大小的内存地址块。邮箱是内存地址，我们在栈上压入和弹出的“物品”称为 栈帧。栈帧跟踪与一个函数调用相关的所有数据。我们稍后会详细讨论栈帧。“标记”是一个寄存器（CPU中的一小块内存），称为栈指针（有时缩写为“SP”）。栈指针跟踪调用栈当前顶部的位置。

我们可以进一步优化：当从调用栈中弹出一个项目时，我们只需向下移动栈指针——我们不必清理或清零弹出的栈帧所使用的内存（相当于清空邮箱）。这块内存不再被视为“在栈上”（栈指针将位于或低于此地址），因此不会被访问。如果我们稍后将新的栈帧压入同一内存，它将覆盖我们从未清理的旧值。

调用栈的实际运作

让我们更详细地检查调用栈是如何工作的。以下是调用函数时发生的步骤序列：

  1. 程序遇到一个函数调用。
  2. 构造一个栈帧并将其压入栈中。栈帧包括：
  • 函数调用之后指令的地址（称为 返回地址）。这是CPU记住在被调用函数退出后返回何处的方式。
  • 所有函数参数。
  • 任何局部变量的内存
  • 函数修改的、需要在函数返回时恢复的寄存器的保存副本
  1. CPU跳转到函数的起始点。
  2. 函数内部的指令开始执行。

当函数终止时，发生以下步骤：

  1. 从调用栈恢复寄存器
  2. 栈帧从栈中弹出。这释放了所有局部变量和参数的内存。
  3. 处理返回值。
  4. CPU在返回地址处恢复执行。

返回值可以通过多种不同的方式处理，具体取决于计算机的架构。有些架构将返回值作为栈帧的一部分。其他架构使用CPU寄存器。

通常，了解调用栈如何工作的所有细节并不重要。然而，理解函数在被调用时被有效地压入栈，并在返回时弹出（展开），这为您提供了理解递归以及调试时有用的其他一些概念所需的基础知识。

技术说明：在某些架构上，调用栈向远离内存地址0的方向增长。在其他架构上，它向内存地址0的方向增长。因此，新压入的栈帧可能比之前的栈帧具有更高或更低的内存地址。

一个快速而粗糙的调用栈示例

考虑以下简单的应用程序：

int foo(int x)
{
    // b
    return x;
} // foo 在此处从调用栈中弹出

int main()
{
    // a
    foo(5); // foo 在此处被压入调用栈
    // c

    return 0;
}

在标记点处，调用栈如下所示：

a:

main()

b:

foo() (including parameter x)
main()

c:

main()

栈溢出

栈的大小是有限的，因此只能容纳有限的信息。在Windows上的Visual Studio中，默认栈大小为1MB。对于Unix变体上的g++/Clang，它可能高达8MB。如果程序试图在栈上放置太多信息，将导致栈溢出。 栈溢出 当栈中的所有内存都已分配时发生——在这种情况下，进一步的分配开始溢出到其他内存区域。

栈溢出通常是由于在栈上分配了太多变量和/或进行了太多嵌套函数调用（其中函数A调用函数B，函数B调用函数C，函数C调用函数D等）造成的。在现代操作系统上，栈溢出通常会导致操作系统发出访问冲突并终止程序。

以下是一个可能导致栈溢出的示例程序。您可以在系统上运行它并观察其崩溃：

#include <iostream>

int main()
{
    int stack[10000000];
    std::cout << "hi" << stack[0]; // 我们将使用 stack[0] 以便编译器不会优化掉数组

    return 0;
}

该程序试图在栈上分配一个巨大的（可能40MB）数组。由于栈不足以容纳该数组，数组分配溢出到程序不允许使用的内存区域。

在 Windows（Visual Studio）上，该程序产生的结果：

HelloWorld.exe (process 15916) exited with code -1073741571.

-1073741571 的十六进制是 c0000005，这是 Windows 操作系统表示访问冲突的代码。注意，“hi”从未被打印，因为程序在此之前已终止。

下面是另一个程序，它会因不同原因导致栈溢出：

// 感谢读者 yellowEmu 提出添加计数器的想法
#include <iostream>

int g_counter{ 0 };

void eatStack()
{
    std::cout << ++g_counter << ' ';

    // 我们在这里使用条件语句以避免编译器关于无限递归的警告
    if (g_counter > 0)
        eatStack(); // 注意 eatStack() 调用自身

    // 需要防止编译器进行尾调用优化
    std::cout << "hi";
}

int main()
{
    eatStack();

    return 0;
}

在上面的程序中，每次调用函数 eatStack() 时，都会在栈上压入一个栈帧。由于 eatStack() 调用自身（并且从不返回给调用者），最终栈会耗尽内存并导致溢出。

作者注

在作者的 Windows 10 机器上（在 Visual Studio Community IDE 中运行），eatStack() 在调试模式下经过 4848 次调用后崩溃，在发布模式下经过 128,679 次调用后崩溃。

栈有优点也有缺点：

  • 在栈上分配内存相对较快。
  • 在栈上分配的内存在栈上时保持作用域有效。当它被弹出栈时被销毁。
  • 在栈上分配的所有内存在编译时都是已知的。因此，这些内存可以通过变量直接访问。
  • 由于栈相对较小，通常不建议做任何消耗大量栈空间的事情。这包括分配或复制大型数组或其他内存密集型结构。
