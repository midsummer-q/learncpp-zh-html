10.9 — 函数的类型推导

● 机器译文 课程 10.9 查看英文原文

考虑以下程序：

int add(int x, int y)
{
    return x + y;
}

当此函数被编译时，编译器将确定 x + y求值为一个 int，然后确保返回值的类型与函数声明的返回类型匹配（或者返回值类型可以转换为声明的返回类型）。

使用 auto

进行返回类型推导 由于编译器已经必须从返回语句推导返回类型（以确保该值可以转换为函数声明的返回类型），在C++14中， auto 关键字被扩展以进行函数返回类型推导。这是通过使用 auto 关键字代替函数的返回类型来实现的。

例如：

auto add(int x, int y)
{
    return x + y;
}

因为返回语句返回一个 int 值，编译器将推导出该函数的返回类型为 int。

当使用 auto 返回类型时，函数内的所有返回语句必须返回相同类型的值，否则将导致错误。例如：

auto someFcn(bool b)
{
    if (b)
        return 5; // 返回类型 int
    else
        return 6.7; // 返回类型 double
}

在上面的函数中，两个返回语句返回不同类型的值，因此编译器将给出错误。

如果出于某种原因需要这种情况，您可以显式指定函数的返回类型（在这种情况下，编译器将尝试隐式转换任何不匹配的返回表达式为显式返回类型），或者您可以显式地将所有返回语句转换为相同类型。在上面的例子中，可以通过将 5 切换到 5.0，但 static_cast 也可以用于非字面量类型。

返回类型推导的好处

返回类型推导的最大优点是让编译器推导函数的返回类型消除了返回类型不匹配的风险（防止意外的转换）。

当函数的返回类型很脆弱（即返回类型可能因实现更改而改变）时，这尤其有用。在这种情况下，显式指定返回类型意味着当实现发生影响性更改时，必须更新所有相关的返回类型。如果幸运的话，编译器会报错直到我们更新相关的返回类型。如果不幸运，我们会在不希望的地方得到隐式转换。

在其他情况下，函数的返回类型可能又长又复杂，或者不那么明显。在这种情况下， auto 可以用来简化：

// 让编译器确定 unsigned short + char 的返回类型
auto add(unsigned short x, char y)
{
    return x + y;
}

我们在课程中进一步讨论这种情况（以及如何表达此类函数的实际返回类型） 11.8 -- 具有多个模板类型的函数模板。

返回类型推导的缺点

返回类型推导有两个主要缺点：

  1. 使用 auto 返回类型的函数必须在使用之前完全定义（前向声明是不够的）。例如：
#include <iostream>

auto foo();

int main()
{
    std::cout << foo() << '\n'; // 此时编译器只看到了前向声明

    return 0;
}

auto foo()
{
    return 5;
}

在作者的机器上，这会产生以下编译错误：

error C3779: 'foo': a function that returns 'auto' cannot be used before it is defined.

这是有道理的：前向声明没有足够的信息让编译器推导函数的返回类型。这意味着返回 auto 的普通函数通常只能从定义它们的文件中调用。

  1. 当对对象使用类型推导时，初始化器总是作为同一语句的一部分存在，因此通常不会过于繁琐地确定推导出的类型。但对于函数的类型推导，情况并非如此——函数原型没有指示函数实际返回的类型。一个好的编程IDE应该能清楚地显示函数的推导类型，但在没有IDE的情况下，用户实际上必须深入函数体本身来确定函数返回的类型。出错的可能性更高。通常我们更倾向于对接口（函数的声明是接口）的一部分类型进行显式指定。

与对象的类型推导不同，关于函数返回类型推导的最佳实践没有太多共识。我们建议通常避免对函数使用返回类型推导。

最佳实践

优先使用显式返回类型而不是返回类型推导（除非返回类型不重要、难以表达或脆弱）。

尾随返回类型语法

浮点类型的 auto 关键字也可以用于使用 尾随返回语法声明函数，其中返回类型在函数原型的其余部分之后指定。

考虑以下函数：

int add(int x, int y)
{
  return (x + y);
}

使用尾随返回语法，可以等效地写成：

auto add(int x, int y) -> int
{
  return (x + y);
}

在这种情况下， auto 不执行类型推导——它只是使用尾随返回类型语法的一部分。

为什么要使用这个？以下是一些原因：

  1. 对于具有复杂返回类型的函数，尾随返回类型可以使函数更易于阅读：
#include <type_traits> // for std::common_type

std::common_type_t<int, double> compare(int, double);         // 更难阅读（函数名在这堆东西里在哪里？）
auto compare(int, double) -> std::common_type_t<int, double>; // 更容易阅读（除非我们关心，否则不必阅读返回类型）
  1. 尾随返回类型语法可用于对齐函数名称，使连续的函数声明更易于阅读：
auto add(int x, int y) -> int;
auto divide(double x, double y) -> double;
auto printSomething() -> void;
auto generateSubstring(const std::string &s, int start, int len) -> std::string;

进阶读者

  1. 如果函数的返回类型必须根据函数参数的类型来推导，那么普通的返回类型语法就不够用了，因为此时编译器尚未看到参数。
#include <type_traits>
// 注意：decltype(x) 求值为 x 的类型

std::common_type_t<decltype(x), decltype(y)> add(int x, double y);         // 编译错误：编译器尚未看到 x 和 y 的定义
auto add(int x, double y) -> std::common_type_t<decltype(x), decltype(y)>; // ok
  1. 尾随返回类型语法也是C++某些高级特性所必需的，例如lambda表达式（我们将在第 20.6 -- lambda（匿名函数）简介)。

目前，我们建议继续使用传统的函数返回类型语法，除非在需要尾随返回类型语法的情况下。

类型推导不能用于函数参数类型

许多学习类型推导的新手程序员会尝试这样写：

#include <iostream>

void addAndPrint(auto x, auto y)
{
    std::cout << x + y << '\n';
}

int main()
{
    addAndPrint(2, 3); // 情况1：使用 int 参数调用 addAndPrint
    addAndPrint(4.5, 6.7); // 情况2：使用 double 参数调用 addAndPrint

    return 0;
}

不幸的是，类型推导不适用于函数参数，在C++20之前，上述程序无法编译（你会得到一个关于函数参数不能具有auto类型的错误）。

在C++20中， auto 关键字被扩展，使得上述程序能够编译并正确运行——然而， auto 在这种情况下并不是调用类型推导。相反，它触发了一个不同的特性，称为 function templates ，该特性正是为了处理此类情况而设计的。
