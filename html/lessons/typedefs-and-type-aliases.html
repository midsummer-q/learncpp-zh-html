10.7 — Typedefs 和类型别名

● 机器译文 课程 10.7 查看英文原文

类型别名

在 C++ 中， using 是一个关键字，用于为现有数据类型创建别名。要创建这样的类型别名，我们使用 using 关键字，后跟类型别名的名称，再跟一个等号和现有数据类型。例如：

using Distance = double; // 将 Distance 定义为 double 类型的别名

一旦定义，类型别名就可以在需要类型的任何地方使用。例如，我们可以使用类型别名名称作为类型来创建一个变量：

Distance milesToDestination{ 3.4 }; // 定义一个 double 类型的变量

当编译器遇到类型别名名称时，它会替换为被别名的类型。例如：

#include <iostream>

int main()
{
    using Distance = double; // 将 Distance 定义为 double 类型的别名

    Distance milesToDestination{ 3.4 }; // 定义一个 double 类型的变量

    std::cout << milesToDestination << '\n'; // 打印一个 double 值

    return 0;
}

这会打印：

3.4

在上面的程序中，我们首先定义 Distance 作为类型 double。

的别名。接下来，我们定义一个名为 milesToDestination 的变量，其类型为别名 Distance。因为编译器知道 Distance 是一个类型别名，它会使用被别名的类型，即 double。因此，变量 milesToDestination 实际上被编译为类型 double的变量，并且它在所有方面都表现为 double

最后，我们打印 milesToDestination的值，它打印为 double 值。

进阶读者

类型别名也可以模板化。我们在课程 13.14 -- 类模板参数推导（CTAD）和推导指南。

命名类型别名

历史上，类型别名的命名方式并不一致。有三种常见的命名约定（你都会遇到）：

  • 以“_t”后缀结尾的类型别名（“_t”是“type”的缩写）。这种约定通常被标准库用于全局作用域的类型名称（如 size_t 和 nullptr_t)。

这种约定继承自 C 语言，曾经在定义自己的类型别名（有时还有其他类型）时最流行，但在现代 C++ 中已不再流行。注意， POSIX 为全局作用域的类型名称保留了“_t”后缀，因此在 POSIX 系统上使用此约定可能会导致类型命名冲突。

  • 以“_type”后缀结尾的类型别名。这种约定被一些标准库类型使用（如 std::string）来命名嵌套类型别名（例如， std::string::size_type)。

但许多这样的嵌套类型别名根本不使用后缀（例如， std::string::iterator），因此这种用法充其量是不一致的。

  • 不使用后缀的类型别名。

在现代 C++ 中，约定是为你自己定义的类型别名（或任何其他类型）命名时以大写字母开头，并且不使用后缀。大写字母有助于区分类型名称与变量和函数名称（以小写字母开头），并防止它们之间的命名冲突。

使用这种命名约定时，常见用法如下：

void printDistance(Distance distance); // Distance 是某个已定义的类型

在这种情况下， Distance 是类型，而 distance 是参数名。C++ 区分大小写，所以这没问题。

最佳实践

将你的类型别名以大写字母开头命名，并且不要使用后缀（除非你有特定的理由不这样做）。

作者注

本教程系列中的一些后续课程仍然使用“_t”或“_type”后缀。请随时在这些课程上留言，以便我们使其与最佳实践保持一致。

类型别名不是不同的类型

别名实际上并没有定义一个新的、不同的类型（即被视为与其他类型分开的类型）——它只是为现有类型引入了一个新的标识符。类型别名与被别名的类型完全可互换。

这允许我们做一些语法上有效但语义上无意义的事情。例如：

int main()
{
    using Miles = long; // 将 Miles 定义为 long 类型的别名
    using Speed = long; // 将 Speed 定义为 long 类型的别名

    Miles distance { 5 }; // distance 实际上只是一个 long
    Speed mhz  { 3200 };  // mhz 实际上只是一个 long

    // 以下语法有效（但语义无意义）
    distance = mhz;

    return 0;
}

虽然从概念上讲，我们打算 Miles 和 Speed 具有不同的含义，但两者都只是类型 long的别名。这实际上意味着 Miles， Speed、和 long 可以互换使用。实际上，当我们将类型 Speed 的值赋给类型 Miles的变量时，编译器只看到我们在赋值类型 long 的值赋给类型 long的值，并且不会报错。

由于编译器不会阻止类型别名的这类语义错误，我们说别名不是 类型安全的。尽管如此，它们仍然有用。

警告

必须注意不要混用语义上本应不同的别名值。

顺便说一句……

某些语言支持 强类型定义 （或强类型别名）的概念。强类型定义实际上创建了一个新类型，它拥有原始类型的所有原始属性，但如果尝试混用别名类型和强类型定义的值，编译器会抛出错误。截至C++20，C++不直接支持强类型定义（尽管枚举类，在课程 13.6 -- 作用域枚举（enum class）中介绍过，类似），但有很多第三方C++库实现了类似强类型定义的行为。

类型别名的作用域

由于作用域是标识符的一个属性，类型别名标识符遵循与变量标识符相同的作用域规则：在块内定义的类型别名具有块作用域，只能在该块内使用，而在全局命名空间中定义的类型别名具有全局作用域，可在文件末尾之前使用。在上面的例子中， Miles 和 Speed 仅在 main() 函数的顶部开始。

中可用。如果需要在多个文件中使用一个或多个类型别名，可以将它们定义在头文件中，并通过#include包含到任何需要使用该定义的代码文件中：

mytypes.h：

#ifndef MYTYPES_H
#define MYTYPES_H

    using Miles = long;
    using Speed = long;

#endif

通过这种方式包含的类型别名将被导入全局命名空间，因此具有全局作用域。

Typedefs

一个 类型定义 （“类型定义”的缩写）是一种较旧的为类型创建别名的方式。要创建typedef别名，我们使用 typedef 关键字成为常量：

// 以下别名相同
typedef long Miles;
using Miles = long;

Typedefs在C++中仍然存在是为了向后兼容，但在现代C++中它们已被类型别名取代。

Typedefs有一些语法问题。首先，很容易忘记是typedef的名称还是要别名的类型名称在前。哪个是正确的？

typedef Distance double; // 错误（typedef 名称在前）
typedef double Distance; // 正确（别名类型名称在前）

很容易搞反。幸运的是，在这种情况下，编译器会报错。

其次，对于更复杂的类型，typedef的语法可能变得难看。例如，这里有一个难以阅读的typedef，以及一个等效（且稍微易读）的类型别名：

typedef int (*FcnType)(double, char); // FcnType 难以找到
using FcnType = int(*)(double, char); // FcnType 更容易找到

在上面的typedef定义中，新类型的名称（FcnType）埋藏在定义的中间，而在类型别名中，新类型的名称和定义的其余部分由等号分隔。

第三，“typedef”这个名称暗示正在定义一个新类型，但事实并非如此。typedef只是一个别名。

最佳实践

优先使用类型别名而不是typedef。

术语

C++标准使用术语“typedef名称”来指代typedef和类型别名的名称。

在常规语言中，术语“typedef”通常用于表示“typedef或类型别名”，因为它们实际上做同样的事情。

何时应该使用类型别名？

现在我们已经介绍了类型别名是什么，让我们谈谈它们的用途。

使用类型别名进行平台无关编码

类型别名的主要用途之一是隐藏平台特定的细节。在某些平台上， int 是2字节，而在其他平台上，它是4字节。因此，在编写平台无关代码时，使用 int 存储超过2字节的信息可能具有潜在危险。

因为 char， short， int、和 long 没有指示它们的大小，跨平台程序通常使用类型别名来定义包含类型大小（以位为单位）的别名。例如， int8_t 将是一个8位有符号整数， int16_t 一个16位有符号整数，以及 int32_t 一个32位有符号整数。以这种方式使用类型别名有助于防止错误，并更清楚地表明对变量大小所做的假设。

为了确保每个别名类型解析为正确大小的类型，这类类型别名通常与预处理器指令一起使用：

#ifdef INT_2_BYTES
using int8_t = char;
using int16_t = int;
using int32_t = long;
#else
using int8_t = char;
using int16_t = short;
using int32_t = int;
#endif

在整数只有2字节的机器上， INT_2_BYTES 可以被#define（作为编译器/预处理器设置），程序将使用上面一组类型别名进行编译。在整数为4字节的机器上，保持 INT_2_BYTES 未定义将导致使用下面一组类型别名。这样，只要 INT_2_BYTES 被正确定义， int8_t 将解析为1字节整数， int16_t 将解析为2字节整数，而 int32_t 将解析为4字节整数（使用适合程序编译机器的 char， short， int、和 long 组合）。

固定宽度整数类型（如 std::int16_t 和 std::uint32_t）和 size_t 类型（均在课程 4.6 课 -- 固定宽度整数和 size_t中介绍）实际上只是各种基本类型的类型别名。

这也是为什么当你使用 std::cout打印8位固定宽度整数时，你很可能得到一个字符值。例如：

#include <cstdint> // for fixed-width integers
#include <iostream>

int main()
{
    std::int8_t x{ 97 }; // int8_t 通常是 signed char 的 typedef
    std::cout << x << '\n';

    return 0;
}

该程序打印出：

a

因为 std::int8_t 通常是 signed char的typedef，变量 x 很可能被定义为 signed char。而char类型将其值打印为ASCII字符而不是整数值。

使用类型别名使复杂类型更易读

虽然我们目前只处理了简单数据类型，但在高级C++中，类型可能很复杂，手动输入也很冗长。例如，你可能会看到这样定义的函数和变量：

#include <string> // for std::string
#include <vector> // for std::vector
#include <utility> // for std::pair

bool hasDuplicates(std::vector<std::pair<std::string, int>> pairlist)
{
    // 此处是一些代码
    return false;
}

int main()
{
     std::vector<std::pair<std::string, int>> pairlist;

     return 0;
}

在需要该类型的每个地方输入 std::vector<std::pair<std::string, int>> 很麻烦，而且容易打错。使用类型别名要容易得多：

#include <string> // for std::string
#include <vector> // for std::vector
#include <utility> // for std::pair

using VectPairSI = std::vector<std::pair<std::string, int>>; // 将 VectPairSI 设为这个复杂类型的别名

bool hasDuplicates(VectPairSI pairlist) // 在函数参数中使用 VectPairSI
{
    // 此处是一些代码
    return false;
}

int main()
{
     VectPairSI pairlist; // 实例化一个 VectPairSI 变量

     return 0;
}

好多了！现在我们只需要输入 VectPairSI 而不是 std::vector<std::pair<std::string, int>>。

如果你还不知道 std::vector， std::pair或所有这些奇怪的尖括号是什么，不用担心。你真正需要理解的是，类型别名允许你将复杂类型赋予一个更简单的名称，使代码更易读并节省输入。

这可能是类型别名的最佳用途。

使用类型别名记录值的含义

类型别名也有助于代码文档化和理解。

对于变量，我们有变量标识符来帮助记录变量的用途。但考虑函数返回值的情况。像 char， int， long， double、和 bool 这样的数据类型描述了函数返回值的 类型 类型，但更多时候我们想知道返回值的 含义 是什么。

例如，给定以下函数：

int gradeTest();

我们可以看到返回值是一个整数，但这个整数是什么意思？一个字母等级？答错的问题数？学生的ID号？一个错误代码？谁知道呢！返回类型 int 并没有告诉我们太多。幸运的话，函数的文档存在某处可供参考。不幸的话，我们必须阅读代码并推断其用途。

现在让我们使用类型别名做一个等效的版本：

using TestScore = int;
TestScore gradeTest();

返回类型 TestScore 使得函数返回一个表示测试分数的类型这一点更加明显。

根据我们的经验，仅仅为了记录单个函数的返回类型而创建类型别名并不值得（改用注释）。但如果你有多个函数传递或返回这样的类型，创建类型别名可能是值得的。

使用类型别名简化代码维护

类型别名还允许你更改对象的底层类型，而无需更新大量硬编码的类型。例如，如果你使用 short 来存储学生ID号，但后来决定需要 long ，那么你必须仔细检查大量代码并替换 short 替换为 long。可能很难确定哪些 short 类型的对象用于存储ID号，哪些用于其他目的。

然而，如果你使用类型别名，更改类型就变得像更新类型别名一样简单（例如从 using StudentId = short; 切换到 using StudentId = long;)。

虽然这看起来是一个不错的好处，但在更改类型时必须谨慎，因为程序的行为也可能改变。当将类型别名的类型更改为不同类型族中的类型时（例如，整数改为浮点数，或有符号改为无符号），这一点尤其重要！新类型可能存在比较或整数/浮点数除法问题，或其他旧类型没有的问题。如果你将现有类型更改为其他类型，应彻底重新测试代码。

缺点与结论

虽然类型别名提供了一些好处，但它们也在代码中引入了另一个需要理解的标识符。如果这没有通过可读性或理解性的提升来抵消，那么类型别名弊大于利。

一个使用不当的类型别名可能会将一个熟悉的类型（如 std::string）隐藏在一个需要查找的自定义名称后面。在某些情况下（例如智能指针，我们将在后续章节中介绍），模糊类型信息也可能有害于理解该类型应如何工作。

因此，类型别名应主要用于对代码可读性或代码维护有明显好处的情况。这既是艺术也是科学。当类型别名可以在代码的许多地方使用，而不是少数地方时，它们最为有用。

最佳实践

明智地使用类型别名，当它们为代码可读性或代码维护提供明显好处时。
