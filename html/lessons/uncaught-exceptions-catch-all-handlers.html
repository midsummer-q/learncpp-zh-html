27.4 — 未捕获的异常和捕获所有处理程序

● 机器译文 课程 27.4 查看英文原文

到目前为止，你应该对异常的工作原理有了合理的了解。在本课中，我们将介绍几个更有趣的异常情况。

未捕获的异常

当一个函数抛出一个它自己不处理的异常时，它假设调用链中的某个函数会处理该异常。在下面的例子中，mySqrt() 假设有人会处理它抛出的异常——但如果实际上没有人处理呢？

这是我们的平方根程序，去掉了 main() 中的 try 块：

#include <iostream>
#include <cmath> // for sqrt() function

// 一个模块化的平方根函数
double mySqrt(double x)
{
    // 如果用户输入了负数，这是一个错误条件
    if (x < 0.0)
        throw "Can not take sqrt of negative number"; // 抛出 const char* 类型的异常

    return std::sqrt(x);
}

int main()
{
    std::cout << "Enter a number: ";
    double x;
    std::cin >> x;

    // 看，没有异常处理器！
    std::cout << "The sqrt of " << x << " is " << mySqrt(x) << '\n';

    return 0;
}

现在，假设用户输入 -4，mySqrt(-4) 引发了一个异常。函数 mySqrt() 不处理该异常，因此程序会查看调用链中是否有某个函数会处理该异常。main() 也没有该异常的处理程序，因此找不到处理程序。

当找不到函数的异常处理程序时，会调用 std::terminate()，应用程序终止。在这种情况下，调用栈可能会也可能不会被展开！如果栈没有被展开，局部变量将不会被销毁，并且任何期望在销毁这些变量时进行的清理操作都不会发生！

警告

如果异常未被处理，调用栈可能会也可能不会被展开。

如果栈没有被展开，局部变量将不会被销毁，如果这些变量具有非平凡的析构函数，这可能会导致问题。

顺便说一句……

尽管在这种情况下不展开栈可能看起来很奇怪，但这样做有一个很好的理由。未处理的异常通常是你要不惜一切代价避免的事情。如果栈被展开，那么所有导致未处理异常抛出的栈状态的调试信息都会丢失！通过不展开，我们保留了这些信息，从而更容易确定未处理异常是如何抛出的，并修复它。

当异常未被处理时，操作系统通常会通知你发生了未处理的异常错误。具体方式取决于操作系统，可能包括打印错误消息、弹出错误对话框或直接崩溃。有些操作系统比其他操作系统更不优雅。通常这是你想要避免的事情！

捕获所有处理程序

现在我们发现自己陷入了一个困境：

  • 函数可能抛出任何数据类型的异常（包括程序定义的数据类型），这意味着有无限多种可能的异常类型需要捕获。
  • 如果异常没有被捕获，你的程序将立即终止（并且栈可能不会被展开，因此你的程序甚至可能无法正确清理自身）。
  • 为每种可能的类型添加显式的 catch 处理程序很繁琐，尤其是对于那些预期只在异常情况下才会到达的类型！

幸运的是，C++ 也为我们提供了一种机制来捕获所有类型的异常。这被称为 捕获所有处理程序。捕获所有处理程序的工作方式与普通的 catch 块类似，只是它不使用特定类型来捕获，而是使用省略号运算符 (…) 作为要捕获的类型。因此，捕获所有处理程序有时也被称为“省略号 catch 处理程序”。

如果你还记得第 20.5 -- 省略号（以及为什么避免使用它们）课，省略号之前用于向函数传递任何类型的参数。在此上下文中，它们表示任何数据类型的异常。这是一个简单的例子：

#include <iostream>

int main()
{
	try
	{
		throw 5; // 抛出一个 int 异常
	}
	catch (double x)
	{
		std::cout << "We caught an exception of type double: " << x << '\n';
	}
	catch (...) // 捕获所有异常处理器
	{
		std::cout << "We caught an exception of an undetermined type\n";
	}
}

因为没有针对 int 类型的特定异常处理程序，所以捕获所有处理程序捕获了这个异常。这个例子产生以下结果：

We caught an exception of an undetermined type

捕获所有处理程序必须放在 catch 块链的最后。这是为了确保异常可以被针对特定数据类型的异常处理程序捕获（如果这些处理程序存在）。

通常，捕获所有处理程序块是空的：

catch(...) {} // 忽略任何未预料的异常

这将捕获任何未预料到的异常，确保栈展开到这一点，并防止程序终止，但不进行特定的错误处理。

使用捕获所有处理程序包装 main()

捕获所有处理程序的一个用途是包装 main() 的内容：

#include <iostream>

struct GameSession
{
    // 游戏会话数据在此
};

void runGame(GameSession&)
{
    throw 1;
}

void saveGame(GameSession&)
{
    // 在此保存用户游戏
}

int main()
{
    GameSession session{};

    try
    {
        runGame(session);
    }
    catch(...)
    {
        std::cerr << "Abnormal termination\n";
    }

    saveGame(session); // 保存用户游戏（即使触发了捕获所有处理器）

    return 0;
}

在这种情况下，如果 runGame() 或它调用的任何函数抛出一个未处理的异常，它将被这个捕获所有处理程序捕获。栈将以有序的方式展开（确保局部变量的销毁）。这也将防止程序立即终止，让我们有机会选择打印错误信息并在退出前保存用户状态。

提示

如果你的程序使用异常，考虑在 main 中使用捕获所有处理程序，以帮助确保在发生未处理异常时行为有序。

如果异常被捕获所有处理程序捕获，你应该假设程序现在处于某种不确定状态，立即执行清理，然后终止。

调试未处理的异常

未处理的异常表明发生了意外情况，我们可能想要诊断为什么首先抛出了未处理的异常。许多调试器会（或可以配置为）在未处理的异常处中断，允许我们在抛出未处理异常的点查看栈。然而，如果我们有一个捕获所有处理程序，那么所有异常都被处理了，并且（因为栈被展开）我们丢失了有用的诊断信息。

因此，在调试构建中，禁用捕获所有处理程序可能很有用。我们可以通过条件编译指令来实现这一点。

这是一种方法：

#include <iostream>

struct GameSession
{
    // 游戏会话数据在此
};

void runGame(GameSession&)
{
    throw 1;
}

void saveGame(GameSession&)
{
    // 在此保存用户游戏
}

class DummyException // 一个无法实例化的虚拟类
{
    DummyException() = delete;
}; 

int main()
{
    GameSession session {}; 

    try
    {
        runGame(session);
    }
#ifndef NDEBUG // 如果处于发布模式
    catch(...) // 编译时包含捕获所有处理器
    {
        std::cerr << "Abnormal termination\n";
    }
#else // 在调试模式下，编译一个永远不会被触发的 catch（出于语法原因）
    catch(DummyException)
    {
    }
#endif

    saveGame(session); // 保存用户游戏（即使触发了捕获所有处理器）

    return 0;
}

从语法上讲，try 块至少需要一个关联的 catch 块。因此，如果捕获所有处理程序被条件编译掉，我们需要要么条件编译掉 try 块，要么条件编译进另一个 catch 块。后者更简洁。

为此，我们创建类 DummyException ，它不能被实例化，因为它的默认构造函数被删除且没有其他构造函数。当 NDEBUG 被定义时，我们编译进一个 catch 处理程序来捕获类型为 DummyException的异常。由于我们不能创建 DummyException，这个 catch 处理程序永远不会捕获任何东西。因此，任何到达此点的异常都不会被处理。
