1.6 — 未初始化的变量与未定义行为

● 机器译文 课程 1.6 查看英文原文

未初始化的变量

与某些编程语言不同，C/C++ 不会自动将大多数变量初始化为给定值（例如零）。当一个未初始化的变量被分配一个内存地址来存储数据时，该变量的默认值就是该内存地址中恰好存在的任何（垃圾）值！一个尚未通过初始化或赋值获得已知值的变量被称为 未初始化变量。

术语

许多读者期望“已初始化”和“未初始化”这两个术语是严格对立的，但事实并非完全如此！在通常的语言中，“已初始化”意味着对象在定义点被赋予了一个初始值。“未初始化”意味着对象尚未通过任何方式（包括赋值）获得已知值。因此，一个未被初始化但随后被赋值的对象不再是 未初始化 （因为它已被赋予了一个已知值）。

总结一下：

  • 已初始化 = 对象在定义点被赋予了一个已知值。
  • 赋值 = 对象在定义点之后被赋予了一个已知值。
  • 未初始化 = 对象尚未被赋予已知值。

相应地，考虑以下变量定义：

int x;

在课程 1.4 -- Variable assignment and initialization，我们注意到，当没有提供初始化器时，变量会被默认初始化。在大多数情况下（例如本例），默认初始化并不执行实际的初始化。因此我们可以说 x 是未初始化的。我们关注的是结果（对象尚未被赋予已知值），而不是过程。

顺便说一句……

这种不初始化的做法是从 C 语言继承而来的性能优化，源自计算机速度较慢的时代。想象一下，如果你要从文件中读取 100,000 个值。在这种情况下，你可能会创建 100,000 个变量，然后用文件中的数据填充它们。

如果 C++ 在创建时对所有变量进行默认值初始化，就会导致 100,000 次初始化（会很慢），而且收益甚微（因为你反正会覆盖这些值）。

目前，你应该始终初始化你的变量，因为这样做相对于收益而言成本微乎其微。当你对这门语言更加熟悉后，在某些情况下为了优化目的，你可以省略初始化。但这始终应该是有选择地、有意识地进行的。

使用未初始化变量的值可能导致意外结果。考虑下面的简短程序：

#include <iostream>

int main()
{
    // 定义一个名为 x 的整型变量
    int x; // 这个变量未初始化，因为我们没有给它一个值
    
    // 将 x 的值打印到屏幕上
    std::cout << x << '\n'; // 谁知道我们会得到什么，因为 x 未初始化

    return 0;
}

在这种情况下，计算机会将一些未使用的内存分配给 x。然后，它会将存储在该内存位置的值发送到 std::cout，它会打印该值（解释为整数）。但会打印什么值呢？答案是“谁知道呢！”，而且答案可能（也可能不）每次运行程序时都会改变。当作者在 Visual Studio 中运行此程序时， std::cout 打印了值 7177728 一次，而 5277592 下一次。请随意自己编译并运行该程序（你的电脑不会爆炸）。

警告

某些编译器，例如 Visual Studio， 会 在你使用调试构建配置时，会将内存内容初始化为某个预设值。使用发布构建配置时不会发生这种情况。因此，如果你想自己运行上述程序，请确保你使用的是 发布构建配置 （请参阅课程 0.9 -- 配置编译器：构建配置 以提醒如何操作）。

例如，如果你在 Visual Studio 调试配置中运行上述程序，它会始终打印 -858993460，因为这就是 Visual Studio 在调试配置中初始化内存的值（解释为整数）。

大多数现代编译器会尝试检测变量是否在未赋值的情况下被使用。如果能够检测到，它们通常会产生编译时警告或错误。例如，在 Visual Studio 上编译上述程序会产生以下警告：

c:\VCprojects\test\test.cpp(11) : warning C4700: uninitialized local variable 'x' used

如果你的编译器不允许你编译并运行上述程序（例如，因为它将此问题视为错误），这里有一个可能的解决方案来解决此问题：

#include <iostream>

void doNothing(int&) // 暂时不用担心 & 是什么，我们只是用它来欺骗编译器，让它认为变量 x 被使用了
{
}

int main()
{
    // 定义一个名为 x 的整型变量
    int x; // 这个变量未初始化

    doNothing(x); // 让编译器认为我们在给这个变量赋值

    // 将 x 的值打印到屏幕上（谁知道我们会得到什么，因为 x 未初始化）
    std::cout << x << '\n';

    return 0;
}

使用未初始化的变量是新手程序员最容易犯的错误之一，不幸的是，它也可能是最难调试的错误之一（因为如果未初始化的变量恰好被分配到一块包含合理值（如0）的内存位置，程序仍然可能正常运行）。

这就是“始终初始化变量”最佳实践的主要原因。

未定义行为

使用未初始化变量的值是我们遇到的第一个未定义行为的示例。 未定义行为 （通常缩写为 UB) 是执行代码的结果，其行为未被 C++ 语言良好定义。在这种情况下，C++ 语言没有任何规则来确定如果你使用一个尚未赋予已知值的变量的值会发生什么。因此，如果你确实这样做了，就会导致未定义行为。

实现未定义行为的代码可能表现出 任何 以下症状：

  • 你的程序每次运行都会产生不同的结果。
  • 你的程序始终产生相同的错误结果。
  • 你的程序行为不一致（有时产生正确结果，有时不正确）。
  • 你的程序看似正常工作，但稍后会产生错误结果。
  • 你的程序崩溃，无论是立即还是稍后。
  • 你的程序在某些编译器上工作，但在其他编译器上不工作。
  • 你的程序正常工作，直到你更改一些看似无关的代码。

或者，你的代码实际上可能仍然产生正确的行为。

作者注

未定义行为就像一盒巧克力。你永远不知道你会得到什么！

C++ 包含许多如果不小心就会导致未定义行为的情况。我们会在未来的课程中遇到它们时指出这些情况。注意这些情况的位置，并确保避免它们。

规则

注意避免所有导致未定义行为的情况，例如使用未初始化的变量。

作者注

我们收到读者最常见的评论之一是：“你说我不能做 X，但我还是做了，我的程序能运行！为什么？”

有两个常见的答案。最常见的答案是，你的程序实际上表现出未定义行为，但这种未定义行为碰巧产生了你想要的的结果……暂时如此。明天（或在另一个编译器或机器上）可能就不行了。

另一种情况是，有时编译器作者会在语言要求可能比所需更严格时随意处理。例如，标准可能说“你必须在 Y 之前做 X”，但编译器作者可能认为这不必要，并让 Y 即使没有先做 X 也能工作。这不应该影响正确编写的程序的操作，但可能导致不正确的程序仍然工作。所以上述问题的另一个答案是，你的编译器可能根本没有遵循标准！这种情况会发生。你可以通过确保关闭编译器扩展来避免很多此类问题，如课程 0.10 -- 配置你的编译器：编译器扩展。

实现定义行为和未指定行为

特定的编译器及其附带的关联标准库被称为 实现 （因为这些实际上实现了C++语言）。在某些情况下，C++语言标准允许实现决定语言某些方面的行为方式，以便编译器可以选择对给定平台高效的行为。由实现定义的行为称为 实现定义行为。实现定义行为必须被记录并在给定实现中保持一致。

让我们看一个实现定义行为的简单示例：

#include <iostream>

int main()
{
	std::cout << sizeof(int) << '\n'; // 打印一个 int 值占用的内存字节数

	return 0;
}

在大多数平台上，这将产生 4，但在其他平台上可能产生 2。

相关内容

我们在 sizeof() 在课程 4.3 -- 对象大小和sizeof运算符。

未指定行为 与实现定义行为几乎相同，行为留给实现定义，但实现不需要记录该行为。

我们通常希望避免实现定义和未指定行为，因为这意味着如果我们的程序在不同的编译器上编译（甚至在同一编译器上，如果我们更改影响实现行为的项目设置！），程序可能无法按预期工作。

最佳实践

尽可能避免实现定义和未指定行为，因为它们可能导致程序在其他实现上出现故障。

小测验时间

问题 #1

什么是未初始化变量？为什么应避免使用它们？

显示答案

未初始化变量是尚未被程序赋予值的变量（通常通过初始化或赋值）。使用存储在未初始化变量中的值将导致未定义行为。

问题 #2

什么是未定义行为，以及如果执行了表现出未定义行为的操作会发生什么？

显示答案

未定义行为是执行行为未被语言明确定义的代码的结果。结果几乎可以是任何情况，包括正确运行的情况。
