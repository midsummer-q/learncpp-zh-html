7.14 — 未命名和内联命名空间

● 机器译文 课程 7.14 查看英文原文

C++ 支持两种值得了解的命名空间变体。我们不会在此基础上深入，所以现在可以将本课视为可选内容。

未命名（匿名）命名空间

一种 未命名命名空间 （也称为一个 匿名命名空间）是一种没有名称的命名空间，定义方式如下：

#include <iostream>

namespace // 未命名命名空间
{
    void doSomething() // 只能在此文件中访问
    {
        std::cout << "v1\n";
    }
}

int main()
{
    doSomething(); // 我们可以不带命名空间前缀调用 doSomething()

    return 0;
}

这会打印：

v1

在未命名命名空间中声明的所有内容都被视为父命名空间的一部分。因此，即使函数 doSomething() 定义在未命名命名空间中，该函数本身也可以从父命名空间（此处为全局命名空间）访问，这就是为什么我们可以不加任何限定符地调用 doSomething() 从 main()

这可能会让未命名命名空间看起来毫无用处。但未命名命名空间的另一个效果是，其中的所有标识符都被视为具有内部链接，这意味着未命名命名空间的内容在定义该命名空间的文件之外不可见。

对于函数而言，这实际上等同于将未命名命名空间中的所有函数定义为静态函数。以下程序与上面的程序实际上相同：

#include <iostream>

static void doSomething() // 只能在此文件中访问
{
    std::cout << "v1\n";
}

int main()
{
    doSomething(); // 我们可以不带命名空间前缀调用 doSomething()

    return 0;
}

未命名命名空间通常用于当你希望大量内容保持局限于某个翻译单元时，因为将这类内容集中在一个未命名命名空间中比单独将所有声明标记为 static更容易。未命名命名空间还会将程序定义的类型（我们将在后续课程中讨论）局限于翻译单元，这是其他等效机制无法做到的。

提示

如果你很硬核，可以采取相反的方法——将所有不明确用于导出/外部的内容放入未命名命名空间。

未命名命名空间通常不应在头文件中使用。 SEI CERT（规则 DCL59-CPP） 提供了一些很好的示例说明原因。

最佳实践

当你有希望保持局限于翻译单元的内容时，优先使用未命名命名空间。

避免在头文件中使用未命名命名空间。

内联命名空间

现在考虑以下程序：

#include <iostream>

void doSomething()
{
    std::cout << "v1\n";
}

int main()
{
    doSomething();

    return 0;
}

这会打印：

v1

很简单，对吧？

但假设你对 doSomething()不满意，想要以某种改变其行为的方式改进它。但如果这样做，你可能会破坏使用旧版本的现有程序。如何处理这种情况？

一种方法是创建一个具有不同名称的新版本函数。但在多次更改后，你可能会得到一组几乎同名的函数（doSomething， doSomething_v2， doSomething_v3，等等……）。

另一种方法是使用内联命名空间。 内联命名空间 是一种通常用于版本控制内容的命名空间。与未命名命名空间类似，内联命名空间中声明的任何内容都被视为父命名空间的一部分。但与未命名命名空间不同，内联命名空间不影响链接。

要定义内联命名空间，我们使用 inline 关键字成为常量：

#include <iostream>

inline namespace V1 // 声明一个名为 V1 的内联命名空间
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

namespace V2 // 声明一个名为 V2 的普通命名空间
{
    void doSomething()
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // 调用 V1 版本的 doSomething()
    V2::doSomething(); // 调用 V2 版本的 doSomething()

    doSomething(); // 调用内联版本的 doSomething()（即 V1）
 
    return 0;
}

这会打印：

V1
V2
V1

在上面的示例中，调用 doSomething() 的调用者将获得 V1（内联版本）的 doSomething()。想要使用更新版本的调用者可以显式调用 V2::doSomething()。这既保留了现有程序的功能，又允许新程序利用更新/更好的变体。

或者，如果你想推送更新版本：

#include <iostream>

namespace V1 // 声明一个名为 V1 的普通命名空间
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace V2 // 声明一个名为 V2 的内联命名空间
{
    void doSomething()
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // 调用 V1 版本的 doSomething()
    V2::doSomething(); // 调用 V2 版本的 doSomething()

    doSomething(); // 调用内联版本的 doSomething()（即 V2）
 
    return 0;
}

这会打印：

V1
V2
V2

在此示例中，所有调用 doSomething() 的调用者默认将获得 v2 版本（更新更好的版本）。仍然想要旧版本 doSomething() 的用户可以显式调用 V1::doSomething() 来访问旧行为。这意味着想要 V1 版本的现有程序需要全局替换 doSomething 替换为 V1::doSomething，但如果函数命名得当，这通常不会成为问题。

混合内联和未命名命名空间 可选

一个命名空间可以同时是内联和未命名的：

#include <iostream>

namespace V1 // 声明一个名为 V1 的普通命名空间
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace // 声明一个内联的未命名命名空间
{
    void doSomething() // 具有内部链接
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // 调用 V1 版本的 doSomething()
    // 此示例中没有 V2，因此我们不能使用 V2:: 作为命名空间前缀

    doSomething(); // 调用内联版本的 doSomething()（即匿名版本）

    return 0;
}

然而，在这种情况下，最好将匿名命名空间嵌套在内联命名空间内。这具有相同的效果（匿名命名空间内的所有函数默认具有内部链接），但仍然为您提供了一个显式的命名空间名称，您可以使用：

#include <iostream>

namespace V1 // 声明一个名为 V1 的普通命名空间
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace V2 // 声明一个名为 V2 的内联命名空间
{
    namespace // 未命名命名空间
    {
        void doSomething() // 具有内部链接
        {
            std::cout << "V2\n";
        }

    }
}

int main()
{
    V1::doSomething(); // 调用 V1 版本的 doSomething()
    V2::doSomething(); // 调用 V2 版本的 doSomething()

    doSomething(); // 调用内联版本的 doSomething()（即 V2）

    return 0;
}
