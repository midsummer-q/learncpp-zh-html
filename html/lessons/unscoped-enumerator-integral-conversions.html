13.3 — 无作用域枚举器的整型转换

● 机器译文 课程 13.3 查看英文原文

在上一课（13.2 -- 无作用域枚举我们提到过枚举器是符号常量。当时我们没有告诉你的是，这些枚举器的值是整型类型的。

这与 char 的情况类似（4.11 -- 字符）。考虑：

char ch { 'A' };

char 实际上只是一个1字节的整型值，字符 'A' 被转换为一个整型值（在这种情况下， 65）并存储。

当我们定义一个枚举时，每个枚举器会根据其在枚举器列表中的位置自动关联一个整数值。默认情况下，第一个枚举器被赋予整数值 0，并且每个后续枚举器的值比前一个枚举器大1：

enum Color
{
    black,   // 0
    red,     // 1
    blue,    // 2
    green,   // 3
    white,   // 4
    cyan,    // 5
    yellow,  // 6
    magenta, // 7
};

int main()
{
    Color shirt{ blue }; // shirt 实际上存储整数值 2

    return 0;
}

可以显式定义枚举器的值。这些整数值可以是正数或负数，并且可以与其他枚举器共享相同的值。任何未定义的枚举器都会被赋予比前一个枚举器大1的值。

enum Animal
{
    cat = -3,    // 值可以为负
    dog,         // -2
    pig,         // -1
    horse = 5,
    giraffe = 5, // 与 horse 共享相同值
    chicken,     // 6 
};

注意在这种情况下， horse 和 giraffe 被赋予了相同的值。当这种情况发生时，枚举器变得不区分——本质上， horse 和 giraffe 是可互换的。尽管C++允许这样做，但通常应避免在同一枚举中为两个枚举器赋予相同的值。

大多数情况下，枚举器的默认值正是你想要的，所以除非有特定原因，否则不要提供自己的值。

最佳实践

除非有令人信服的理由，否则避免为枚举器赋予显式值。

值初始化枚举

如果枚举被零初始化（当我们使用值初始化时会发生），枚举将被赋予值 0，即使没有对应的枚举器具有该值。

#include <iostream>

enum Animal
{
    cat = -3,    // -3
    dog,         // -2
    pig,         // -1
    // 注意：此列表中没有值为 0 的枚举器
    horse = 5,   // 5
    giraffe = 5, // 5
    chicken,     // 6 
};

int main()
{
    Animal a {}; // 值初始化将 a 零初始化为值 0
    std::cout << a; // 打印 0

    return 0;
}

这有两个语义后果：

  • 如果存在值为0的枚举器，值初始化会将枚举默认设置为该枚举器的含义。例如，使用之前的 enum Color 示例，一个值初始化的 Color 将默认为 black）。因此，最好考虑让值为0的枚举器代表枚举的最佳默认含义。

类似这样的东西可能会导致问题：

enum UniverseResult
{
    destroyUniverse, // 默认值 (0)
    saveUniverse
};
  • 如果没有值为0的枚举器，值初始化很容易创建一个语义无效的枚举。在这种情况下，我们建议添加一个值为0的“无效”或“未知”枚举器，以便你记录该状态的含义，并有一个可以显式处理的状态名称。
enum Winner
{
    winnerUnknown, // 默认值 (0)
    player1,
    player2,
};

// 稍后在代码中的某处
if (w == winnerUnknown) // 适当处理情况

最佳实践

让代表0的枚举器成为枚举的最佳默认含义。如果没有好的默认含义，考虑添加一个值为0的“无效”或“未知”枚举器，以便该状态被显式记录，并在适当的地方显式处理。

无作用域枚举会隐式转换为整型值

尽管枚举存储整型值，但它们不被视为整型类型（它们是复合类型）。然而，无作用域枚举会隐式转换为整型值。由于枚举器是编译时常量，这是一个 constexpr 转换（我们在课程 10.4 -- 窄化转换、列表初始化和 constexpr 初始化器)。

考虑以下程序：

#include <iostream>

enum Color
{
    black, // 赋值为 0
    red, // 赋值为 1
    blue, // 赋值为 2
    green, // 赋值为 3
    white, // 赋值为 4
    cyan, // 赋值为 5
    yellow, // 赋值为 6
    magenta, // 赋值为 7
};

int main()
{
    Color shirt{ blue };

    std::cout << "Your shirt is " << shirt << '\n'; // 这做什么？

    return 0;
}

中介绍过）。由于枚举类型持有整型值，正如你所料，这将打印：

Your shirt is 2

当枚举类型用于函数调用或与运算符一起使用时，编译器会首先尝试查找匹配该枚举类型的函数或运算符。例如，当编译器尝试编译 std::cout << shirt时，编译器会首先查看 operator<< 是否知道如何打印类型为 Color 的对象（因为 shirt 的类型是 Color）到 std::cout。它不知道。

由于编译器找不到匹配项，它会接着检查 operator<< 是否知道如何打印无作用域枚举转换成的整型类型的对象。由于它知道， shirt 中的值被转换为整型值并打印为整型值 2。

枚举的大小和底层类型（基础）

枚举值具有整数类型的值。但具体是哪种整数类型？用于表示枚举值的特定整数类型称为枚举的 底层类型 （或 基础)。

对于无作用域枚举，C++ 标准没有指定应使用哪种特定的整数类型作为底层类型，因此选择是由实现定义的。大多数编译器会使用 int 作为底层类型（意味着无作用域枚举的大小与 int相同），除非需要更大的类型来存储枚举值。但你不应假设这对每个编译器或平台都成立。

可以为枚举显式指定底层类型。底层类型必须是整数类型。例如，如果你在某种带宽敏感的环境（例如通过网络发送数据）中工作，你可能希望为枚举指定一个较小的类型：

#include <cstdint>  // for std::int8_t
#include <iostream>

// 使用 8 位整数作为枚举底层类型
enum Color : std::int8_t
{
    black,
    red,
    blue,
};

int main()
{
    Color c{ black };
    std::cout << sizeof(c) << '\n'; // 打印 1（字节）

    return 0;
}

最佳实践

仅在必要时指定枚举的基础类型。

警告

因为 std::int8_t 和 std::uint8_t 通常是 char 类型的类型别名，使用这两种类型中的任何一种作为枚举基础很可能导致枚举值打印为 char 值而不是 int 值。

整数到无作用域枚举值的转换

虽然编译器会隐式地将无作用域枚举转换为整数，但它不会 不是 隐式地将整数转换为无作用域枚举。以下代码会产生编译错误：

enum Pet // 未指定基类型
{
    cat, // 赋值为 0
    dog, // 赋值为 1
    pig, // 赋值为 2
    whale, // 赋值为 3
};

int main()
{
    Pet pet { 2 }; // 编译错误：整数值 2 不会隐式转换为 Pet
    pet = 3;       // 编译错误：整数值 3 不会隐式转换为 Pet

    return 0;
}

有两种方法可以解决这个问题。

首先，你可以使用 static_cast：

enum Pet // 未指定基类型
{
    cat, // 赋值为 0
    dog, // 赋值为 1
    pig, // 赋值为 2
    whale, // 赋值为 3
};

int main()
{
    Pet pet { static_cast<Pet>(2) }; // 将整数 2 转换为 Pet
    pet = static_cast<Pet>(3);       // 我们的猪进化成了鲸鱼！

    return 0;
}

显式地将整数转换为无作用域枚举值。我们将在课程 13.4 -- 枚举与字符串之间的转换 中看到一个使用此方法的示例。

将目标枚举的枚举值所表示的任何整数值进行 static_cast 是安全的。由于我们的 Pet 枚举具有值为 0， 1， 2、和 3的枚举值，因此将整数值 0， 1， 2、和 3 转换为 Pet 进行 static_cast 是有效的。

将目标枚举底层类型范围内的任何整数值进行 static_cast 也是安全的，即使没有枚举值表示该值。将超出底层类型范围的值进行 static_cast 会导致未定义行为。

进阶读者

如果枚举具有显式定义的底层类型，则枚举的范围与底层类型的范围相同。

如果枚举没有显式的底层类型，情况会稍微复杂一些。在这种情况下，编译器可以选择底层类型，并且可以选择任何有符号或无符号类型，只要所有枚举器的值都能放入该类型。鉴于此，只有将适合容纳所有枚举器值的最小位数范围内的整数值进行 static_cast 才是安全的。

让我们用两个例子来说明这一点：

  • 对于值为 2、9 和 12 的枚举器，这些枚举器最小可以放入一个无符号 4 位整数类型，其范围为 0 到 15。因此，只有将整数值 0 到 15 进行 static_cast 到这个枚举类型才是安全的。
  • 对于值为 -28、2 和 6 的枚举器，这些枚举器最小可以放入一个有符号 6 位整数类型，其范围为 -32 到 31。因此，只有将整数值 -32 到 31 进行 static_cast 到这个枚举类型才是安全的。

其次，从 C++17 开始，如果无作用域枚举具有显式指定的基础类型，那么编译器将允许你使用整数值对无作用域枚举进行列表初始化：

enum Pet: int // 我们指定了基类型
{
    cat, // 赋值为 0
    dog, // 赋值为 1
    pig, // 赋值为 2
    whale, // 赋值为 3
};

int main()
{
    Pet pet1 { 2 }; // ok：可以用整数对指定基类型的无作用域枚举进行花括号初始化（C++17）
    Pet pet2 (2);   // 编译错误：不能直接用整数进行直接初始化
    Pet pet3 = 2;   // 编译错误：不能使用整数进行拷贝初始化

    pet1 = 3;       // 编译错误：不能使用整数进行赋值

    return 0;
}
