7.2 — 用户定义命名空间和作用域解析运算符

● 机器译文 课程 7.2 查看英文原文

在课程 2.9 -- 命名冲突和命名空间简介，我们介绍了 naming collisions 和 namespaces的概念。提醒一下，命名冲突发生在两个相同的标识符被引入同一作用域，且编译器无法区分使用哪一个时。发生这种情况时，编译器或链接器会产生错误，因为它们没有足够的信息来解决歧义。

关键提示

随着程序变得越来越大，标识符的数量增加，这反过来导致命名冲突发生的概率显著增加。因为在给定作用域中的每个名称都可能与同一作用域中的其他每个名称冲突，标识符的线性增加将导致潜在冲突的指数级增加！这是尽可能在最小作用域中定义标识符的关键原因之一。

让我们重新审视一个命名冲突的例子，然后展示如何使用命名空间来改进。在下面的例子中， foo.cpp 和 goo.cpp 是包含执行不同功能但具有相同名称和参数的函数的源文件。

foo.cpp：

// 这个 doSomething() 将其参数的值相加
int doSomething(int x, int y)
{
    return x + y;
}

goo.cpp：

// 这个 doSomething() 将其参数的值相减
int doSomething(int x, int y)
{
    return x - y;
}

main.cpp:

#include <iostream>

int doSomething(int x, int y); // doSomething 的前向声明

int main()
{
    std::cout << doSomething(4, 3) << '\n'; // 我们会得到哪个 doSomething？
    return 0;
}

如果这个项目只包含 foo.cpp 或 goo.cpp （但不是两者），它将编译并运行无误。然而，通过将两者编译到同一个程序中，我们现在将两个具有相同名称和参数的不同函数引入了同一作用域（全局作用域），这导致了命名冲突。结果，链接器将发出错误：

goo.cpp:3: multiple definition of `doSomething(int, int)'; foo.cpp:3: first defined here

注意，这个错误发生在重定义时，因此无论函数 doSomething 是否被调用，都会发生。

解决这个问题的一种方法是重命名其中一个函数，使名称不再冲突。但这还需要更改所有函数调用的名称，这可能很麻烦，并且容易出错。避免冲突的更好方法是将你的函数放入你自己的命名空间中。出于这个原因，标准库被移到了 std 命名空间之外的同名函数冲突。

定义你自己的命名空间

C++ 允许我们通过 namespace 关键字定义自己的命名空间。你在自己的程序中创建的命名空间通常被称为 用户定义命名空间 （尽管更准确地说，它们应该被称为 程序定义命名空间)。

）。命名空间的语法如下：

namespace NamespaceIdentifier
{
    // content of namespace here
}

我们从 namespace 关键字开始，后跟命名空间的标识符，然后是用花括号括起来的命名空间内容。

历史上，命名空间名称不大写，许多风格指南仍然推荐这种约定。

进阶读者

一些倾向于命名空间名称以大写字母开头的理由：

  • 约定程序定义类型以大写字母开头。对程序定义命名空间使用相同的约定是一致的（尤其是在使用限定名称如 Foo::x，其中 Foo 时，它可能是一个命名空间或一个类类型）。
  • 它有助于防止与其他系统提供或库提供的小写名称发生命名冲突。
  • C++20 标准文档使用这种风格。
  • C++ 核心指南文档使用这种风格。

我们建议命名空间名称以大写字母开头。然而，两种风格都应被视为可接受的。

命名空间必须在全局作用域或另一个命名空间内部定义。与函数内容类似，命名空间的内容通常缩进一级。你可能会偶尔看到在命名空间的右花括号后放置一个可选的分号。

以下是使用命名空间重写的先前示例中的文件：

foo.cpp：

namespace Foo // 定义一个名为 Foo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Foo
    int doSomething(int x, int y)
    {
        return x + y;
    }
}

goo.cpp：

namespace Goo // 定义一个名为 Goo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Goo
    int doSomething(int x, int y)
    {
        return x - y;
    }
}

现在 doSomething() 在 foo.cpp 内部位于 Foo 命名空间中，而 doSomething() 在 goo.cpp 内部位于 Goo 命名空间。让我们看看重新编译程序时会发生什么。

main.cpp:

int doSomething(int x, int y); // doSomething 的前向声明

int main()
{
    std::cout << doSomething(4, 3) << '\n'; // 我们会得到哪个 doSomething？
    return 0;
}

答案是现在我们得到了另一个错误！

ConsoleApplication1.obj : error LNK2019: unresolved external symbol "int __cdecl doSomething(int,int)" (?doSomething@@YAHHH@Z) referenced in function _main

在这种情况下，编译器满意了（通过我们的前向声明），但链接器在全局命名空间中找不到 doSomething 的定义。这是因为我们的两个版本的 doSomething 不再位于全局命名空间中！它们现在位于各自命名空间的作用域中！

有两种不同的方式告诉编译器使用哪个版本的 doSomething() ，通过 scope resolution operator，或者通过 using statements （我们将在本章后面的一课中讨论）。

在后续示例中，为了便于阅读，我们将把示例简化为单文件解决方案。

使用作用域解析运算符 (::) 访问命名空间

告诉编译器在特定命名空间中查找标识符的最佳方法是使用 作用域解析运算符 (::)。作用域解析运算符告诉编译器，右侧操作数指定的标识符应在左侧操作数的作用域中查找。

下面是一个使用作用域解析运算符告诉编译器我们明确想要使用位于 doSomething() 命名空间中的 Foo 版本的示例：

#include <iostream>

namespace Foo // 定义一个名为 Foo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Foo
    int doSomething(int x, int y)
    {
        return x + y;
    }
}

namespace Goo // 定义一个名为 Goo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Goo
    int doSomething(int x, int y)
    {
        return x - y;
    }
}

int main()
{
    std::cout << Foo::doSomething(4, 3) << '\n'; // 使用存在于命名空间 Foo 中的 doSomething()
    return 0;
}

这会输出预期的结果：

7

如果我们想使用位于 doSomething() 中的 Goo 版本：

#include <iostream>

namespace Foo // 定义一个名为 Foo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Foo
    int doSomething(int x, int y)
    {
        return x + y;
    }
}

namespace Goo // 定义一个名为 Goo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Goo
    int doSomething(int x, int y)
    {
        return x - y;
    }
}

int main()
{
    std::cout << Goo::doSomething(4, 3) << '\n'; // 使用存在于命名空间 Goo 中的 doSomething()
    return 0;
}

这会产生以下结果：

1

作用域解析运算符很棒，因为它允许我们 明确地 选择要查找的命名空间，因此没有潜在的歧义。我们甚至可以这样做：

#include <iostream>

namespace Foo // 定义一个名为 Foo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Foo
    int doSomething(int x, int y)
    {
        return x + y;
    }
}

namespace Goo // 定义一个名为 Goo 的命名空间
{
    // 这个 doSomething() 属于命名空间 Goo
    int doSomething(int x, int y)
    {
        return x - y;
    }
}

int main()
{
    std::cout << Foo::doSomething(4, 3) << '\n'; // 使用存在于命名空间 Foo 中的 doSomething()

    return 0;
}

这会产生以下结果：

使用不带名称前缀的作用域解析运算符

作用域解析运算符也可以放在标识符前面而不提供命名空间名称（例如 ::doSomething）。在这种情况下，标识符（例如 doSomething）将在全局命名空间中查找。

#include <iostream>

void print() // 这个 print() 存在于全局命名空间中
{
	std::cout << " there\n";
}

namespace Foo
{
	void print() // 这个 print() 存在于 Foo 命名空间中
	{
		std::cout << "Hello";
	}
}

int main()
{
	Foo::print(); // 调用 Foo 命名空间中的 print()
	::print();    // 调用全局命名空间中的 print()（在这种情况下等同于直接调用 print()）

	return 0;
}

在上面的例子中， ::print() 与调用不带作用域解析的 print() 相同，因此在这种情况下使用作用域解析运算符是多余的。但下一个示例将展示不带命名空间的作用域解析运算符可能有用的情况。

从命名空间内部解析标识符

如果使用命名空间内的标识符且未提供作用域解析，编译器将首先尝试在同一命名空间中找到匹配的声明。如果未找到匹配的标识符，编译器将依次检查每个包含的命名空间以查看是否找到匹配项，最后检查全局命名空间。

#include <iostream>

void print() // 这个 print() 存在于全局命名空间中
{
	std::cout << " there\n";
}

namespace Foo
{
	void print() // 这个 print() 存在于 Foo 命名空间中
	{
		std::cout << "Hello";
	}

	void printHelloThere()
	{
		print();   // 调用 Foo 命名空间中的 print()
		::print(); // 调用全局命名空间中的 print()
	}
}

int main()
{
	Foo::printHelloThere();

	return 0;
}

这会打印：

Hello there

在上面的例子中， print() 被调用时没有提供作用域解析。由于这个 print() 内部位于 Foo 命名空间中的使用，编译器将首先查看是否可以在 Foo::print() 中找到声明。由于存在一个， Foo::print() 被调用。

如果 Foo::print() 如果没有找到，编译器将检查包含的命名空间（在本例中为全局命名空间）以查看是否可以在那里匹配到 print()

注意，我们还使用了不带命名空间的作用域解析运算符（::print()）来显式调用全局版本的 print()。

在课程 2.11 -- 头文件，我们讨论了如何使用头文件传播前向声明。对于命名空间内的标识符，这些前向声明也需要位于同一命名空间内：

add.h

#ifndef ADD_H
#define ADD_H

namespace BasicMath
{
    // 函数 add() 是命名空间 BasicMath 的一部分
    int add(int x, int y);
}

#endif

add.cpp

#include "add.h"

namespace BasicMath
{
    // 在命名空间 BasicMath 内部定义函数 add()
    int add(int x, int y)
    {
        return x + y;
    }
}

main.cpp

#include "add.h" // for BasicMath::add()

#include <iostream>

int main()
{
    std::cout << BasicMath::add(4, 3) << '\n';

    return 0;
}

如果 add() 的前向声明没有放在命名空间 BasicMath，那么 add() 内，那么它将在全局命名空间中声明，编译器会抱怨没有看到对 BasicMath::add(4, 3)的调用的声明。如果函数 add() 的定义不在命名空间 BasicMath，链接器会抱怨找不到匹配的定义来调用 BasicMath::add(4, 3)。

允许多个命名空间块

在多个位置（跨多个文件，或同一文件内的多个地方）声明命名空间块是合法的。命名空间内的所有声明都被视为该命名空间的一部分。

circle.h:

#ifndef CIRCLE_H
#define CIRCLE_H

namespace BasicMath
{
    constexpr double pi{ 3.14 };
}

#endif

growth.h:

#ifndef GROWTH_H
#define GROWTH_H

namespace BasicMath
{
    // 常量 e 也是命名空间 BasicMath 的一部分
    constexpr double e{ 2.7 };
}

#endif

main.cpp:

#include "circle.h" // for BasicMath::pi
#include "growth.h" // for BasicMath::e

#include <iostream>

int main()
{
    std::cout << BasicMath::pi << '\n';
    std::cout << BasicMath::e << '\n';

    return 0;
}

这完全按预期工作：

3.14
2.7

标准库广泛使用了这一特性，因为每个标准库头文件都将其声明包含在 namespace std 块中，该块位于该头文件内。否则整个标准库就必须定义在单个头文件中！

注意，这一能力也意味着你可以向 std 命名空间添加自己的功能。这样做大多数时候会导致未定义行为，因为 std 命名空间有一条特殊规则，禁止用户代码扩展。

警告

不要向 std 命名空间添加自定义功能。

嵌套命名空间

命名空间可以嵌套在其他命名空间内。例如：

#include <iostream>

namespace Foo
{
    namespace Goo // Goo 是 Foo 命名空间内的一个命名空间
    {
        int add(int x, int y)
        {
            return x + y;
        }
    }
}

int main()
{
    std::cout << Foo::Goo::add(1, 2) << '\n';
    return 0;
}

注意，因为命名空间 Goo 位于命名空间 Foo内部，所以我们访问 add 为 Foo::Goo::add。

从 C++17 开始，嵌套命名空间也可以这样声明：

#include <iostream>

namespace Foo::Goo // Goo 是 Foo 命名空间内的一个命名空间（C++17 风格）
{
    int add(int x, int y)
    {
        return x + y;
    }
}

int main()
{
    std::cout << Foo::Goo::add(1, 2) << '\n';
    return 0;
}

这等价于前面的例子。

如果你以后需要向 Foo 命名空间（仅）添加声明，你可以定义一个单独的 Foo 命名空间来实现：

#include <iostream>

namespace Foo::Goo // Goo 是 Foo 命名空间内的一个命名空间（C++17 风格）
{
    int add(int x, int y)
    {
        return x + y;
    }
}

namespace Foo
{
     void someFcn() {} // 这个函数仅在 Foo 中
}

int main()
{
    std::cout << Foo::Goo::add(1, 2) << '\n';
    return 0;
}

是保留单独的 Foo::Goo 定义还是嵌套 Goo 在 Foo 是一个风格选择。

命名空间别名

由于在嵌套命名空间中输入变量或函数的限定名称可能很繁琐，C++ 允许你创建 命名空间别名，这允许我们临时将一长串命名空间缩短为更短的形式：

#include <iostream>

namespace Foo::Goo
{
    int add(int x, int y)
    {
        return x + y;
    }
}

int main()
{
    namespace Active = Foo::Goo; // active 现在指向 Foo::Goo

    std::cout << Active::add(1, 2) << '\n'; // 这实际上是 Foo::Goo::add()

    return 0;
} // Active 别名在此结束

命名空间别名的一个好处：如果你将来想把 Foo::Goo 中的功能移到其他地方，你只需更新 Active 别名以反映新的目标，而不必查找/替换每一个 Foo::Goo。

#include <iostream>
 
namespace Foo::Goo
{
}

namespace V2
{
    int add(int x, int y)
    {
        return x + y;
    }
}
 
int main()
{
    namespace Active = V2; // active 现在指向 V2
 
    std::cout << Active::add(1, 2) << '\n'; // 我们不必更改这个
 
    return 0;
}

如何使用命名空间

值得注意的是，C++ 中的命名空间最初并非设计为实现信息层次结构——它们主要被设计为一种防止命名冲突的机制。作为证据，请注意整个标准库都位于单个顶级命名空间 std下。引入大量名称的新标准库特性开始使用嵌套命名空间（例如 std::ranges）以避免 std 命名空间之外的同名函数冲突。

  • 为自己使用而开发的小型应用程序通常不需要放入命名空间。然而，对于包含大量第三方库的大型个人项目，将代码放入命名空间有助于防止与未正确命名空间的库发生命名冲突。

作者注

本教程中的示例通常不会使用命名空间，除非我们演示与命名空间相关的特定内容，以保持示例简洁。

  • 任何将分发给他人的代码绝对应该放入命名空间，以防止与集成它的代码发生冲突。通常一个顶级命名空间就足够了（例如 Foologger）。另一个好处是，将库代码放入命名空间还允许用户通过编辑器的自动补全和建议功能查看库的内容（例如，如果你输入 Foologger，自动补全会显示其中的所有名称 Foologger)。
  • 在多团队组织中，通常使用两级甚至三级命名空间来防止不同团队生成的代码之间的命名冲突。这些通常采用以下形式之一：
  1. 项目或库 :: 模块（例如 Foologger::Lang)
  2. 公司或组织 :: 项目或库（例如 Foosoft::Foologger)
  3. 公司或组织 :: 项目或库 :: 模块（例如 Foosoft::Foologger::Lang)

使用模块级命名空间有助于将可能以后可重用的代码与不可重用的应用程序特定代码分开。例如，物理和数学函数可以放入一个命名空间（例如 Math::）。语言和本地化函数放入另一个命名空间（例如 Lang::）。然而，目录结构也可以用于此目的（应用程序特定代码放在项目目录树中，可重用代码放在单独的共享目录树中）。

一般来说，应避免深度嵌套的命名空间（超过3层）。
