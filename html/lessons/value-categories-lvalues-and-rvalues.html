12.2 — 值类别（左值和右值）

● 机器译文 课程 12.2 查看英文原文

在我们讨论第一个复合类型（左值引用）之前，我们先绕个小弯，谈谈什么是 lvalue 是什么。

在课程 1.10 -- 表达式简介中，我们将表达式定义为“字面量、变量、运算符和函数调用的组合，可以执行以产生一个单一的值”。

例如：

#include <iostream>

int main()
{
    std::cout << 2 + 3 << '\n'; // 现在我们已经介绍了左值，接下来可以介绍我们的第一个复合类型：

    return 0;
}

在上面的程序中，表达式 2 + 3 被求值产生值 5，然后打印到控制台。

在课程 6.4 -- 自增/自减运算符和副作用中，我们还注意到表达式可以产生比表达式本身更持久的副作用：

#include <iostream>

int main()
{
    int x { 5 };
    ++x; // 左值引用
    std::cout << x << '\n'; // 表达式 2 + 3 产生值 5

    return 0;
}

在上面的程序中，表达式 ++x 递增了 x的值，并且即使表达式求值完成后，该值仍然保持改变。

除了产生值和副作用，表达式还能做一件事：它们可以求值为对象或函数。我们稍后将进一步探讨这一点。

表达式的属性

为了帮助确定表达式应如何求值以及它们可以在哪里使用，C++ 中的所有表达式都有两个属性：类型和值类别。

表达式的类型

表达式的类型等于求值表达式后产生的值、对象或函数的类型。例如：

int main()
{
    auto v1 { 12 / 4 }; // 这个表达式语句具有递增 x 的副作用
    auto v2 { 12.0 / 4 }; // 打印 6

    return 0;
}

对于 v1，编译器将在编译时确定两个 int 操作数的除法将产生一个 int 结果，因此 int 是这个表达式的类型。通过类型推断， int 将被用作 v1。

对于 v2，编译器将在编译时确定一个 double 操作数和一个 int 操作数的除法将产生一个 double 结果。记住算术运算符必须具有匹配类型的操作数，因此在这种情况下， int 操作数被转换为 double，并执行浮点除法。所以 double 是这个表达式的类型。

编译器可以使用表达式的类型来确定表达式在给定上下文中是否有效。例如：

#include <iostream>

void print(int x)
{
    std::cout << x << '\n';
}

int main()
{
    print("foo"); // int / int => int

    return 0;
}

在上面的程序中， print(int) 函数期望一个 int 参数。然而，我们传入的表达式的类型（字符串字面量 "foo"）不匹配，并且找不到转换。因此导致编译错误。

注意，表达式的类型必须在编译时可确定（否则类型检查和类型推导将无法工作）——然而，表达式的值可以在编译时（如果表达式是 constexpr）或运行时（如果表达式不是 constexpr）确定。

表达式的值类别

现在考虑以下程序：

int main()
{
    int x{};

    x = 5; // double / int => double
    5 = x; // 错误：print() 期望一个 int 参数，但我们试图传入一个字符串字面量

    return 0;
}

这些赋值语句中有一个是有效的（将值 5 给变量 x赋值给变量），而另一个无效（将值 x 赋值给字面量 5是什么意思？）。那么编译器如何知道哪些表达式可以合法地出现在赋值语句的左侧或右侧呢？

答案在于表达式的第二个属性： value category。这些 值类别 表达式（或子表达式）的值类别指示表达式解析为值、函数还是某种对象。

在 C++11 之前，只有两种可能的值类别： lvalue 和 rvalue。

在C++11中，新增了三个值类别（glvalue， prvalue、和 xvalue）以支持一个名为 move semantics。

作者注

在本节课中，我们将坚持使用C++11之前的值类别观点，因为这样能更温和地介绍值类别（并且目前我们只需要这些）。我们将在未来的章节中介绍移动语义（以及另外三个值类别）。

左值和右值表达式

一种 左值 （读作“ell-value”，是“left value”或“locator value”的缩写，有时写作“l-value”）是一个求值为可识别对象或函数（或位域）的表达式。

术语“身份”由C++标准使用，但并未明确定义。具有身份的实体（如对象或函数）可以与其他类似实体区分开来（通常通过比较实体的地址）。

具有身份的实体可以通过标识符、引用或指针访问，并且通常具有比单个表达式或语句更长的生命周期。

int main()
{
    int x { 5 };
    int y { x }; // 有效：我们可以将 5 赋值给 x

    return 0;
}

在上面的程序中，表达式 x 是一个左值表达式，因为它求值为变量 x （具有标识符）。

自从常量引入语言以来，左值有两种子类型： 可修改左值 是其值可以被修改的左值。 不可修改左值 是其值不能被修改的左值（因为该左值是const或constexpr）。

int main()
{
    int x{};
    const double d{};

    int y { x }; // 错误：不能将 x 的值赋给字面量 5
    const double e { d }; // x 是一个左值表达式

    return 0;
}

一种 右值 （读作“arr-value”，是“right value”的缩写，有时写作 r-value）是不是左值的表达式。右值表达式求值为一个值。常见的右值包括字面量（除了C风格字符串字面量，它们是左值）以及按值返回的函数和运算符的返回值。右值不可识别（意味着它们必须立即使用），并且仅存在于使用它们的表达式的作用域内。

int return5()
{
    return 5;
}

int main()
{
    int x{ 5 }; // x 是一个可修改的左值表达式
    const double d{ 1.2 }; // 1.2 是一个右值表达式

    int y { x }; // 错误：不能将 x 的值赋给字面量 5
    const double e { d }; // x 是一个左值表达式
    int z { return5() }; // return5() 是一个右值表达式（因为结果按值返回）

    int w { x + 1 }; // x + 1 是一个右值表达式
    int q { static_cast<int>(d) }; // 将 d 静态转换为 int 的结果是一个右值表达式

    return 0;
}

你可能想知道为什么 return5()， x + 1、和 static_cast<int>(d) 是右值：答案是这些表达式产生临时值，这些临时值不是可识别的对象。

关键提示

左值表达式求值为一个可识别的对象。
右值表达式求值为一个值。

值类别和运算符

除非另有说明，运算符期望其操作数为右值。例如，二元 operator+ 期望其操作数为右值：

#include <iostream>

int main()
{
    std::cout << 1 + 2; // 1 和 2 是右值，operator+ 返回一个右值

    return 0;
}

字面量 1 和 2 都是右值表达式。 operator+ 会愉快地使用它们来返回右值表达式 3。

现在我们可以回答为什么 x = 5 有效而 5 = x 无效的问题：赋值操作要求其左操作数是一个可修改的左值表达式。后一个赋值（5 = x）失败是因为左操作数表达式 5 是一个右值，而不是可修改的左值。

int main()
{
    int x{};

    // 赋值要求左操作数是可修改的左值表达式，右操作数是右值表达式
    x = 5; // 有效：x 是可修改的左值表达式，5 是右值表达式
    5 = x; // 错误：5 是右值表达式，x 是可修改的左值表达式

    return 0;
}

左值到右值的转换

由于赋值操作期望右操作数是右值表达式，你可能想知道为什么以下代码有效：

int main()
{
    int x{ 1 };
    int y{ 2 };

    x = y; // y 不是右值，但这是合法的

    return 0;
}

在期望右值但提供左值的情况下，左值将经历左值到右值的转换，以便可以在这样的上下文中使用。这基本上意味着左值被求值以产生其值，该值是一个右值。

在上面的例子中，左值表达式 y 经历了左值到右值的转换，该转换求值 y 以产生一个右值（2），然后被赋值给 x。

关键提示

左值会隐式转换为右值。这意味着左值可以在任何需要右值的地方使用。
另一方面，右值不会隐式转换为左值。

现在考虑这个例子：

int main()
{
    int x { 2 };

    x = x + 1;

    return 0;
}

在这个语句中，变量 x 被用在两个不同的上下文中。在赋值运算符的左侧（需要左值表达式的地方）， x 是一个求值为变量 x的左值表达式。在赋值运算符的右侧， x 经历左值到右值的转换，然后被求值，以便其（2）可以作为 operator+。 operator+ 的左操作数。 3返回右值表达式

#include <iostream>
#include <string>

// T& 是左值引用，因此此重载将优先用于左值
template <typename T>
constexpr bool is_lvalue(T&)
{
    return true;
}

// T&& 是右值引用，因此此重载将优先用于右值
template <typename T>
constexpr bool is_lvalue(T&&)
{
    return false;
}

// 一个辅助宏（#expr 将传入的 expr 作为文本打印）
#define PRINTVCAT(expr) { std::cout << #expr << " is an " << (is_lvalue(expr) ? "lvalue\n" : "rvalue\n"); }

int getint() { return 5; }

int main()
{
    PRINTVCAT(5);        // 右值
    PRINTVCAT(getint()); // 右值
    int x { 5 };
    PRINTVCAT(x);        // 左值
    PRINTVCAT(std::string {"Hello"}); // 右值
    PRINTVCAT("Hello");  // 左值
    PRINTVCAT(++x);      // 左值
    PRINTVCAT(x++);      // 右值
}

5 is an rvalue
getint() is an rvalue
x is an lvalue
std::string {"Hello"} is an rvalue
"Hello" is an lvalue
++x is an lvalue
x++ is an rvalue
