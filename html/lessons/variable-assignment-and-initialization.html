1.4 — 变量赋值与初始化

● 机器译文 课程 1.4 查看英文原文

在前一课（1.3 -- 对象与变量简介），我们介绍了如何定义一个可用于存储值的变量。在本课中，我们将探讨如何实际将值放入变量中。

提醒一下，下面是一个简短的程序，它首先分配一个名为 x，然后分配两个更多的整数变量，名为 y 和 z：

int main()
{
    int x;    // 定义一个名为 x 的整型变量（推荐）
    int y, z; // 定义两个整型变量，命名为 y 和 z

    return 0;
}

提醒一下，最好每行定义一个变量。我们将在本课后面回到定义多个变量的情况。

变量赋值

定义一个变量后，你可以使用 = 运算符。这个过程称为 赋值，而 = 运算符称为 赋值运算符。

int width; // 定义一个名为 width 的整型变量
width = 5; // 将值 5 赋值给变量 width

// 变量 width 现在的值为 5

默认情况下，赋值会将 = 运算符 复制到运算符左侧的变量。这称为 拷贝赋值。

一旦变量被赋予一个值，该变量的值可以通过 std::cout 以及 << 运算符。

当我们想要改变变量保存的值时，就可以使用赋值。下面是一个使用两次赋值的例子：

#include <iostream>

int main()
{
	int width; // 定义一个名为 width 的变量
	width = 5; // 将值 5 复制赋值给变量 width

	std::cout << width; // 打印 5

	width = 7; // 将变量 width 中存储的值改为 7

	std::cout << width; // 打印 7

	return 0;
}

这会打印：

57

当这个程序运行时，执行从 main 函数开始并顺序执行。首先，为变量 width 分配内存。然后我们赋值 width 值 5。当我们输出 width，它会打印 5 到控制台。然后当我们赋值 7 切换到 width，任何之前的值（在此例中 5）被覆盖。因此当我们输出 width 再次时，这次它会打印 7。

普通变量一次只能保存一个值。

警告

新手程序员最常犯的错误之一是将赋值运算符（=）与相等运算符（==）。赋值（=）用于将值赋给变量。相等（==）用于测试两个操作数的值是否相等。

变量初始化

赋值的一个缺点是，向刚定义的对象赋值需要两条语句：一条用于定义变量，另一条用于赋值。

这两个步骤可以合并。当定义对象时，可以选择为该对象提供一个初始值。为对象指定初始值的过程称为 初始化，而用于初始化对象的语法称为 初始化器。非正式地，初始值也常被称为“初始化器”。

例如，以下语句既定义了一个名为 width （类型为 int）并用值 5：

#include <iostream>

int main()
{
    int width { 5 };    // 定义变量 width 并用初始值 5 初始化
    std::cout << width; // 打印 5

    return 0;
}

在上面对变量 width， { 5 } 是初始化器， 5 是初始值。

关键提示

初始化为变量提供初始值。可以理解为“初始-化”。

不同的初始化形式

与赋值（通常很直接）不同，C++中的初始化出奇地复杂。因此，我们将在这里提供一个简化的视图来入门。

C++中有5种常见的初始化形式：

int a;         // 默认初始化（无初始化器）

// 传统初始化形式：
int b = 5;     // 复制初始化（等号后的初始值）
int c ( 6 );   // 直接初始化（圆括号内的初始值）

// 现代初始化形式（推荐）：
int d { 7 };   // 直接列表初始化（花括号内的初始值）
int e {};      // 值初始化（空花括号）

你可能会看到上述形式使用不同的空格（例如 int b=5; int c(6);， int d{7};， int e{};）。是否为了可读性而使用额外的空格是个人偏好的问题。

从C++17开始，拷贝初始化、直接初始化和直接列表初始化在大多数情况下行为相同。我们将在下面介绍它们不同的最相关情况。

相关内容

我们在课程中介绍了拷贝初始化、直接初始化和列表初始化之间的其余差异 14.15 -- 类初始化与复制省略。

进阶读者

其他形式的初始化包括：

  • 聚合初始化（参见 13.8 -- 结构体聚合初始化)。
  • 复制列表初始化（下文讨论）。
  • 引用初始化（参见 12.3 -- 左值引用)。
  • 静态初始化、常量初始化和动态初始化（参见 7.8 -- 为什么（非常量）全局变量是邪恶的)。
  • 零初始化（下文讨论）。

默认初始化

当未提供初始化值时（例如对于变量 a 以上），这被称为 默认初始化。在许多情况下，默认初始化不执行任何初始化，使得变量拥有一个不确定的值（不可预测的值，有时称为“垃圾值”）。

我们将在课程中进一步讨论这种情况（1.6 -- 未初始化的变量和未定义行为)。

复制初始化

当在等号后提供初始值时，这被称为 复制初始化。这种初始化形式继承自C语言。

int width = 5; // 将值 5 复制初始化到变量 width

与复制赋值非常相似，它将等号右侧的值复制到左侧正在创建的变量中。在上面的代码片段中，变量 width 将使用值进行初始化 5。

复制初始化在现代C++中曾不受青睐，因为对于某些复杂类型，其效率低于其他初始化形式。然而，C++17解决了大部分这些问题，复制初始化现在重新获得了一些支持。你也会在老旧代码（尤其是从C移植的代码）中看到它，或者被那些认为它看起来更自然、更易读的开发者所使用。

进阶读者

复制初始化也用于值被隐式复制的情况，例如按值传递参数给函数、按值从函数返回、或按值捕获异常时。

直接初始化

当初始值放在括号内时，这被称为 直接初始化。

int width ( 5 ); // 直接初始化变量width为值5

直接初始化最初是为了允许更高效地初始化复杂对象（即具有类类型的对象，我们将在后续章节中介绍）。与复制初始化一样，直接初始化在现代C++中也曾不受青睐，主要是因为被直接列表初始化所取代。然而，直接列表初始化本身也有一些古怪之处，因此直接初始化在某些情况下再次得到使用。

进阶读者

直接初始化也用于将值显式转换为另一种类型时（例如通过 static_cast)。

列表初始化

在现代C++中，初始化对象的现代方法是使用一种利用花括号的初始化形式。这被称为 列表初始化 （或 统一初始化 或 花括号初始化)。

列表初始化有两种形式：

int width { 5 };    // 直接列表初始化变量width为初始值5（推荐）
int height = { 6 }; // 复制列表初始化变量height为初始值6（很少使用）

在C++11之前，某些类型的初始化需要使用复制初始化，而其他类型的初始化需要使用直接初始化。复制初始化很难与复制赋值区分（因为两者都使用 =）。而直接初始化很难与函数相关操作区分（因为两者都使用括号）。

引入列表初始化是为了提供一种几乎在所有情况下都适用、行为一致且语法明确、易于识别对象初始化位置的初始化语法。

关键提示

当我们看到花括号时，我们就知道正在列表初始化一个对象。

此外，列表初始化还提供了一种用值列表而不是单个值来初始化对象的方式（这就是它被称为“列表初始化”的原因）。我们在第 16.2 -- std::vector 与列表构造函数简介。

列表初始化禁止窄化转换

对于新接触 C++ 的程序员来说，列表初始化的主要好处之一是禁止“窄化转换”。这意味着，如果你尝试用一个变量无法安全存储的值来列表初始化该变量，编译器必须生成诊断信息（编译错误或警告）来通知你。例如：

int main()
{
    // 整数只能保存非小数值。
    // 用小数4.5初始化int需要编译器将4.5转换为int能保存的值。
    // 这种转换是窄化转换，因为值的小数部分会丢失。

    int w1 { 4.5 }; // 编译错误：列表初始化不允许窄化转换

    int w2 = 4.5;   // 编译通过：w2被复制初始化为值4
    int w3 (4.5);   // 编译通过：w3被直接初始化为值4

    return 0;
}

在上述程序的第 7 行，我们使用一个值（4.5）带有小数部分（.5）来列表初始化一个整型变量（该变量只能保存非小数值）。因为这是一个窄化转换，编译器需要在这种情况下生成诊断信息。

拷贝初始化（第 9 行）和直接初始化（第 10 行）都会默默地丢弃 .5 并用值 4 来初始化变量（这可能不是我们想要的）。你的编译器可能会就此发出警告（因为丢失数据通常不是期望的），但也可能不会。

请注意，对窄化转换的这一限制仅适用于列表初始化，而不适用于对该变量的任何后续赋值：

int main()
{
    int w1 { 4.5 }; // 编译错误：列表初始化不允许将4.5窄化转换为4

    w1 = 4.5;       // 可以：复制赋值允许将4.5窄化转换为4

    return 0;
}

值初始化和零初始化

当使用一对空花括号初始化变量时，会进行一种称为 值初始化 的特殊列表初始化。在大多数情况下，值初始化会隐式地将变量初始化为零（或对于给定类型最接近零的值）。当发生清零时，这称为 零初始化。

int width {}; // 值初始化/零初始化为值0

进阶读者

对于类类型，值初始化（以及默认初始化）可能会将对象初始化为预定义的默认值，这些值可能非零。

列表初始化是现代 C++ 中首选的初始化形式

列表初始化（包括值初始化）通常优于其他初始化形式，因为它在大多数情况下都有效（因此最为一致），它禁止窄化转换（这通常是我们不希望发生的），并且支持使用值列表进行初始化（这将在未来的课程中介绍）。

最佳实践

优先使用直接列表初始化或值初始化来初始化你的变量。

作者注

Bjarne Stroustrup（C++ 的创建者）和 Herb Sutter（C++ 专家）也推荐 使用列表初始化 来初始化你的变量。

在现代C++中，有些情况下列表初始化不能按预期工作。我们在课程中介绍了一个这样的案例 16.2 -- std::vector 与列表构造函数简介。由于这些古怪之处，一些经验丰富的开发者现在主张根据情况混合使用拷贝初始化、直接初始化和列表初始化。一旦你足够熟悉这门语言，理解了每种初始化类型的细微差别以及这些建议背后的理由，你就可以自行判断是否认同这些论点。

问：何时应该用{ 0 }而不是{}进行初始化？

当你确实在使用初始值时，使用直接列表初始化：

int x { 0 };    // 直接列表初始化，初始值为0
std::cout << x; // 我们在这里使用那个0值

当对象的值是临时的并且将被替换时，使用值初始化：

int x {};      // 值初始化
std::cin >> x; // 我们立即替换该值，所以显式写出0没有意义

初始化你的变量

在创建时初始化你的变量。你最终可能会发现某些情况下因为特定原因（例如使用了大量变量的性能关键代码段）想要忽略这一建议，这没问题，只要是有意为之。

相关内容

关于此话题的更多讨论，Bjarne Stroustrup（C++的创建者）和Herb Sutter（C++专家）本人也提出了这一建议 这里。

我们在课程中探讨了如果你尝试使用没有明确定义的变量会发生什么 1.6 -- 未初始化的变量和未定义行为。

最佳实践

在创建时初始化你的变量。

实例化

术语 实例化 是一个术语，表示变量已被创建（分配）并初始化（包括默认初始化）。实例化的对象有时被称为 实例。大多数情况下，这个术语用于类类型对象，但偶尔也用于其他类型的对象。

初始化多个变量

在上一节中，我们注意到可以定义多个变量 相同类型的 在同一语句中通过逗号分隔名称来定义：

int a, b; // 创建变量a和b，但不进行初始化

我们还指出，最佳实践是完全避免这种语法。不过，由于你可能会遇到使用这种风格的其他代码，多讨论一下它仍然是有用的，哪怕只是为了强化你应该避免它的一些理由。

你可以初始化在同一行定义的多个变量：

int a = 5, b = 6;          // 复制初始化
int c ( 7 ), d ( 8 );      // 直接初始化
int e { 9 }, f { 10 };     // 直接列表初始化
int i {}, j {};            // 值初始化

不幸的是，这里有一个常见的陷阱，当程序员错误地尝试使用一条初始化语句来初始化两个变量时就会发生：

int a, b = 5;     // 错误：a未初始化为5！
int a = 5, b = 5; // 正确：a和b都已初始化为5

在上面的语句中，变量 a 将保持未初始化状态，编译器可能会或可能不会报错。如果它不报错，这将是让你的程序间歇性崩溃或产生零散结果的好方法。我们稍后会详细讨论使用未初始化变量会发生什么。

记住这是错误的最佳方法是注意每个变量只能由它自己的初始化器来初始化：

int a = 4, b = 5; // 正确：a和b都有初始化器
int a, b = 5;     // 错误：a没有自己的初始化器

未使用的已初始化变量警告

现代编译器通常会在变量被初始化但未被使用时生成警告（因为这很少是可取的）。如果启用了“将警告视为错误”，这些警告将被提升为错误，导致编译失败。

考虑下面这个看起来无害的程序：

int main()
{
    int x { 5 }; // 变量x已定义

    // 但未在任何地方使用

    return 0;
}

当使用GCC并启用“将警告视为错误”编译时，会生成以下错误：

prog.cc: In function 'int main()':
prog.cc:3:9: error: unused variable 'x' [-Werror=unused-variable]

并且程序编译失败。

有几种简单的方法可以解决这个问题。

  1. 如果变量确实未使用且你不需要它，那么最简单的选项是移除对 x （或将其注释掉）。毕竟，如果它没有被使用，移除它不会影响任何东西。
  2. 另一个选项是简单地在某处使用该变量：
#include <iostream>

int main()
{
    int x { 5 };

    std::cout << x; // 变量现在已在某处使用

    return 0;
}

但这需要付出一些努力来编写使用它的代码，并且有潜在改变程序行为的缺点。

浮点类型的 [[maybe_unused]] 属性 C++17

在某些情况下，上述两种选项都不可取。考虑我们有一套在许多不同程序中使用的数学/物理值的情况：

#include <iostream>

int main()
{
    // 这里是一些从别处复制粘贴的数学/物理值
    double pi { 3.14159 };
    double gravity { 9.8 };
    double phi { 1.61803 };

    std::cout << pi << '\n';  // pi被使用
    std::cout << phi << '\n'; // phi被使用

    // 编译器可能会抱怨gravity被定义但未使用

    return 0;
}

如果我们经常使用这些值，我们可能把它们保存在某个地方，然后一起复制/粘贴/导入。

然而，在任何我们不使用 所有 所有这些值，编译器可能会对每个实际上未使用的变量发出警告。在上面的例子中，我们可以轻松地移除变量 gravity。但如果有20个或30个变量而不是3个呢？而且如果在多个地方使用它们呢？逐一检查变量列表以移除/注释掉未使用的变量需要时间和精力。后续如果我们需要使用之前移除的变量，我们又得花更多时间和精力回去重新添加/取消注释。

为了解决这种情况，C++17引入了 [[maybe_unused]] 属性，它允许我们告诉编译器我们允许变量未使用。编译器将不会对此类变量产生未使用变量警告。

以下程序应不会产生任何警告/错误：

#include <iostream>

int main()
{
    [[maybe_unused]] double pi { 3.14159 };  // 如果pi未使用，不要抱怨
    [[maybe_unused]] double gravity { 9.8 }; // 如果gravity未使用，不要抱怨
    [[maybe_unused]] double phi { 1.61803 }; // 如果phi未使用，不要抱怨

    std::cout << pi << '\n';
    std::cout << phi << '\n';

    // 编译器将不再警告gravity未使用

    return 0;
}

此外，编译器可能会将这些变量优化掉，因此它们不会对性能产生影响。

浮点类型的 [[maybe_unused]] 属性应只应用于那些有特定且合理原因而未使用的变量（例如，因为你需要一个命名值的列表，但在给定程序中实际使用哪些特定值可能会有所不同）。否则，未使用的变量应从程序中移除。

作者注

在未来的课程中，我们经常会定义不再使用的变量，以演示某些概念的语法。利用 [[maybe_unused]] 使我们能够这样做而不产生编译警告/错误。

小测验时间

问题 #1

初始化和赋值之间有什么区别？

显示答案

初始化在变量创建时赋予其一个初始值。赋值在变量创建之后的某个时间点赋予其一个值。

问题 #2

当你想用特定值初始化变量时，应该优先使用哪种初始化形式？

显示答案

直接列表初始化（又称直接花括号初始化）。

问题 #3

什么是默认初始化和值初始化？它们各自的行为是什么？你应该优先使用哪一种？

显示答案

默认初始化是指变量初始化没有初始化器（例如 int x;）。在大多数情况下，变量会保留不确定的值。

值初始化是指变量初始化使用空的花括号初始化器（例如 int x{};）。在大多数情况下，这将执行零初始化。

你应该优先使用值初始化，因为它将变量初始化为一个一致的值。
