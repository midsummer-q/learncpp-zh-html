12.4 — const的左值引用

● 机器译文 课程 12.4 查看英文原文

在前一课（12.3 -- 左值引用），我们讨论了左值引用如何只能绑定到可修改的左值。这意味着以下是非法的：

int main()
{
    const int x { 5 }; // x 是一个不可修改的（const）左值
    int& ref { x }; // 错误：ref 不能绑定到不可修改的左值

    return 0;
}

这是不允许的，因为它会允许我们通过非常量引用（x）修改一个const变量（ref)。

但如果我们想要为一个const变量创建一个引用呢？普通的左值引用（指向非常量值）是做不到的。

const的左值引用

通过使用 const 关键字声明左值引用时，我们告诉左值引用将其引用的对象视为const。这样的引用称为 指向const值的左值引用 （有时称为 指向const的引用 变为 const引用)。

指向const的左值引用可以绑定到不可修改的左值：

int main()
{
    const int x { 5 };    // x 是一个不可修改的左值
    const int& ref { x }; // 可以：ref 是一个指向 const 值的左值引用

    return 0;
}

因为指向const的左值引用将其引用的对象视为const，它们可以用于访问但不能修改被引用的值：

#include <iostream>

int main()
{
    const int x { 5 };    // x 是一个不可修改的左值
    const int& ref { x }; // 可以：ref 是一个指向 const 值的左值引用

    std::cout << ref << '\n'; // 可以：我们可以访问 const 对象
    ref = 6;                  // 错误：我们不能通过 const 引用修改对象
    
    return 0;
}

用可修改的左值初始化指向const的左值引用

指向const的左值引用也可以绑定到可修改的左值。在这种情况下，通过引用访问时，被引用的对象被视为const（即使底层对象是非常量的）：

#include <iostream>

int main()
{
    int x { 5 };          // x 是一个可修改的左值
    const int& ref { x }; // 可以：我们可以将 const 引用绑定到可修改的左值

    std::cout << ref << '\n'; // 可以：我们可以通过 const 引用访问对象
    ref = 7;                  // 错误：我们不能通过 const 引用修改对象

    x = 6;                // 可以：x 是一个可修改的左值，我们仍然可以通过原始标识符修改它

    return 0;
}

在上面的程序中，我们将const引用 ref 绑定到可修改的左值 x。然后我们可以使用 ref 来访问 x，但因为 ref 是const，我们不能通过 x 修改 ref的值。然而，我们仍然可以直接修改 x 的值（使用标识符 x)。

最佳实践

推荐使用 lvalue references to const 而不是 lvalue references to non-const ，除非你需要修改被引用的对象。

用右值初始化指向const的左值引用

也许令人惊讶的是，指向const的左值引用也可以绑定到右值：

#include <iostream>

int main()
{
    const int& ref { 5 }; // 可以：5 是一个右值

    std::cout << ref << '\n'; // 打印 5

    return 0;
}

当这种情况发生时，会创建一个临时对象并用右值初始化，然后const引用绑定到该临时对象。

相关内容

我们在课程 2.5 -- 局部作用域简介。

中介绍了临时对象。

指向const的左值引用甚至可以绑定到不同类型的值，只要这些值可以隐式转换为引用类型：

#include <iostream>

int main()
{
    // // 情况1
    const double& r1 { 5 };  // 临时 double 初始化为值 5，r1 绑定到临时对象

    std::cout << r1 << '\n'; // 打印 5

    // // 情况2
    char c { 'a' };
    const int& r2 { c };     // 临时 int 初始化为值 'a'，r2 绑定到临时对象

    std::cout << r2 << '\n'; // 打印 97（因为 r2 是 int 的引用）

    return 0;
}

在情况1中，创建一个类型为 double 的临时对象并用int值 5。然后 const double& r1 绑定到该临时double对象。

在情况2中，创建一个类型为 int 的临时对象并用char值 a。然后 const int& r2 绑定到该临时int对象。

在这两种情况下，引用的类型和临时对象的类型匹配。

关键提示

如果你试图将const左值引用绑定到不同类型的值，编译器会创建一个与引用类型相同的临时对象，用该值初始化它，然后将引用绑定到该临时对象。

还要注意，当我们打印 r2 它打印为 int 而不是 char。这是因为 r2 是对 int 对象（创建的临时 int）的引用，而不是对 char c。

虽然允许这样做可能看起来很奇怪，但我们将在课程中看到一些例子，说明这很有用 12.6 -- 通过const左值引用传递。

警告

我们通常假设引用与其绑定的对象相同——但当引用绑定到对象的临时副本或对象转换产生的临时对象时，这个假设就被打破了。随后对原始对象所做的任何修改都不会被引用看到（因为它引用的是不同的对象），反之亦然。

这里有一个愚蠢的例子来说明这一点：

#include <iostream>

int main()
{
    short bombs { 1 };         // 我可以有炸弹！（注意：类型是 short）
    
    const int& you { bombs };  // 你也可以有炸弹（注意：类型是 int&）
    --bombs;                   // 炸弹全没了

    if (you)                   // 你还有吗？
    {
        std::cout << "Bombs away!  Goodbye, cruel world.\n"; // Para bailar la bomba
    }

    return 0;
}

在上面的例子中， bombs 我们还调用了 short 和 you 我们还调用了 const int&。因为 you 只能绑定到 int 对象，当 you 用 bombs初始化时，编译器会隐式转换 bombs 到 int，这导致创建一个临时 int 对象（值为 1)。 you 最终绑定到这个临时对象，而不是 bombs。

当 bombs 被递减， you 不受影响，因为它引用的是不同的对象。所以尽管我们期望 if (you) 求值为 false，但实际上它的值是 true。

如果你能停止毁灭世界，那就太好了。

绑定到临时对象的 const 引用会延长临时对象的生命周期

临时对象通常在其创建的表达式的末尾被销毁。

对于语句 const int& ref { 5 };，考虑一下如果用于保存右值 5 的临时对象在初始化 ref的表达式末尾被销毁，会发生什么。引用 ref 将变成悬空（引用一个已被销毁的对象），当我们尝试访问 ref。

时，将导致未定义行为。为了避免这种情况下的悬空引用，C++ 有一个特殊规则：当一个 const 左值引用 直接 绑定到一个临时对象时，临时对象的生命周期会延长以匹配引用的生命周期。

#include <iostream>

int main()
{
    const int& ref { 5 }; // 持有值 5 的临时对象的生命周期被延长以匹配 ref

    std::cout << ref << '\n'; // 因此，我们可以安全地在这里使用它

    return 0;
} // ref 和临时对象都在这里销毁

在上面的例子中，当 ref 用右值 5初始化，创建一个临时对象， ref 绑定到该临时对象。临时对象的生命周期与 ref匹配。因此，我们可以在下一条语句中安全地打印 ref 的值。然后 ref 和临时对象都在块结束时离开作用域并被销毁。

关键提示

左值引用只能绑定到可修改的左值。

const 左值引用可以绑定到可修改的左值、不可修改的左值和右值。这使得它们成为一种更灵活的引用类型。

进阶读者

生命周期延长仅在 const 引用直接绑定到临时对象时有效。从函数返回的临时对象（即使是 const 引用返回的）不符合生命周期延长的条件。

我们在课程中展示了一个例子 12.12 -- 返回引用和返回地址。

对于类类型的右值，将引用绑定到成员会延长整个对象的生命周期。

那么为什么 C++ 允许 const 引用绑定到右值呢？我们将在下一课中回答这个问题！

Constexpr 左值引用 可选

当应用于引用时， constexpr 允许引用在常量表达式中使用。constexpr 引用有一个特定的限制：它们只能绑定到具有静态存储期（全局变量或静态局部变量）的对象。这是因为编译器知道静态对象在内存中的实例化位置，因此可以将该地址视为编译时常量。

constexpr 引用不能绑定到（非静态）局部变量。这是因为局部变量的地址直到其所在的函数被实际调用时才知道。

int g_x { 5 };

int main()
{
    [[maybe_unused]] constexpr int& ref1 { g_x }; // 可以，可以绑定到全局变量

    static int s_x { 6 };
    [[maybe_unused]] constexpr int& ref2 { s_x }; // 可以，可以绑定到静态局部变量

    int x { 6 };
    [[maybe_unused]] constexpr int& ref3 { x }; // 编译错误：不能绑定到非静态对象

    return 0;
}

在定义指向 const 变量的 constexpr 引用时，我们需要同时应用 constexpr （应用于引用）和 const （应用于被引用的类型）。

int main()
{
    static const int s_x { 6 }; // 一个 const int
    [[maybe_unused]] constexpr const int& ref2 { s_x }; // 需要同时使用 constexpr 和 const

    return 0;
}

鉴于这些限制，constexpr 引用通常使用不多。
