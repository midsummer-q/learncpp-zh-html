14.7 — 返回数据成员引用的成员函数

● 机器译文 课程 14.7 查看英文原文

在课程 12.12 -- 返回引用和返回地址我们介绍了按引用返回。特别地，我们指出：“被按引用返回的对象必须在函数返回后仍然存在”。这意味着我们不应该按引用返回局部变量，因为局部变量被销毁后引用将悬空。然而，按引用返回通过引用传递的函数参数或具有静态持续期的变量（无论是静态局部变量还是全局变量）通常是安全的，因为它们通常不会在函数返回后被销毁。

例如：

// 接受两个 std::string 对象，返回按字母顺序靠前的那个
const std::string& firstAlphabetical(const std::string& a, const std::string& b)
{
	return (a < b) ? a : b; // 我们可以使用 std::string 上的 operator< 来确定哪个按字母顺序靠前
}

int main()
{
	std::string hello { "Hello" };
	std::string world { "World" };

	std::cout << firstAlphabetical(hello, world); // 要么 hello 要么 world 将通过引用返回

	return 0;
}

成员函数也可以按引用返回，并且它们遵循与非成员函数相同的安全返回规则。然而，成员函数有一个额外的情况需要讨论：按引用返回数据成员的成员函数。

这最常见于 getter 访问函数，因此我们将使用 getter 成员函数来说明这个主题。但请注意，这个主题适用于任何返回数据成员引用的成员函数。

按值返回数据成员可能代价高昂

考虑以下示例：

#include <iostream>
#include <string>

class Employee
{
	std::string m_name{};

public:
	void setName(std::string_view name) { m_name = name; }
	std::string getName() const { return m_name; } //  getter 按值返回
};

int main()
{
	Employee joe{};
	joe.setName("Joe");
	std::cout << joe.getName();

	return 0;
}

在这个例子中， getName() 访问函数返回 std::string m_name 按值的函数调用或运算符。

虽然这是最安全的做法，但这也意味着每次调用 m_name 时都会产生一次昂贵的 getName() 副本。由于访问函数往往被频繁调用，这通常不是最佳选择。

通过左值引用返回数据成员

成员函数也可以通过（const）左值引用返回数据成员。

数据成员的生命周期与包含它们的对象相同。由于成员函数总是在某个对象上调用，并且该对象必须在调用者的作用域中存在，因此成员函数通过（const）左值引用返回数据成员通常是安全的（因为被按引用返回的成员在函数返回后仍然存在于调用者的作用域中）。

让我们更新上面的例子，使 getName() 返回 m_name 通过 const 左值引用返回：

#include <iostream>
#include <string>

class Employee
{
	std::string m_name{};

public:
	void setName(std::string_view name) { m_name = name; }
	const std::string& getName() const { return m_name; } //  getter 按 const 引用返回
};

int main()
{
	Employee joe{}; // joe 存在直到函数结束
	joe.setName("Joe");

	std::cout << joe.getName(); // 通过引用返回 joe.m_name

	return 0;
}

现在当 joe.getName() 被调用时， joe.m_name 通过引用返回给调用者，避免了复制。调用者随后使用这个引用来打印 joe.m_name 到控制台。

因为 joe 在调用者的作用域中一直存在到 main() 函数结束，因此对 joe.m_name 的引用在同一持续期内也是有效的。

关键提示

返回数据成员的（const）左值引用是安全的。隐式对象（包含数据成员）在函数返回后仍然存在于调用者的作用域中，因此任何返回的引用都是有效的。

返回数据成员引用的成员函数的返回类型应与数据成员的类型匹配

一般来说，按引用返回的成员函数的返回类型应与被返回的数据成员的类型匹配。在上面的例子中， m_name 的类型是 std::string，所以 getName() 返回 const std::string&。

返回一个 std::string_view 将需要每次调用函数时创建并返回一个临时的 std::string_view 这是不必要的低效。如果调用者想要一个 std::string_view，他们可以自己进行转换。

最佳实践

返回引用的成员函数应返回与被返回数据成员相同类型的引用，以避免不必要的转换。

对于 getter，使用 auto 让编译器从被返回的成员推导返回类型是一种确保不发生转换的有用方法：

#include <iostream>
#include <string>

class Employee
{
	std::string m_name{};

public:
	void setName(std::string_view name) { m_name = name; }
	const auto& getName() const { return m_name; } // 使用 `auto` 从 m_name 推导返回类型
};

int main()
{
	Employee joe{}; // joe 存在直到函数结束
	joe.setName("Joe");

	std::cout << joe.getName(); // 通过引用返回 joe.m_name

	return 0;
}

相关内容

我们介绍 auto 返回类型在课程 我们在第。

然而，使用 auto 返回类型会从文档角度模糊 getter 的返回类型。例如：

	const auto& getName() const { return m_name; } // 使用 `auto` 从 m_name 推导返回类型

不清楚这个函数实际返回什么类型的字符串（它可能是 std::string， std::string_view， C-style string，或者其他完全不同的东西！）。

因此，我们通常更倾向于显式返回类型。

右值隐式对象与按引用返回

有一个情况我们需要小心。在上面的例子中， joe 是一个左值对象，一直存在到函数结束。因此，由 joe.getName() 返回的引用也将有效直到函数结束。

但如果我们的隐式对象是一个右值呢（例如某个按值返回的函数的返回值）？右值对象在其创建所在的完整表达式结束时被销毁。当一个右值对象被销毁时，对该右值任何成员的引用都将失效并成为悬垂引用，使用此类引用将导致未定义行为。

因此，对右值对象成员的引用只能安全地用于该右值对象创建所在的完整表达式内。

提示

我们在课程中介绍了什么是完整表达式 1.10 -- 表达式简介。

警告

右值对象在其创建所在的完整表达式结束时被销毁。此时，对右值对象成员的任何引用都将成为悬垂引用。

对右值对象成员的引用只能安全地用于该右值对象创建所在的完整表达式内。

让我们探讨一些与此相关的案例：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
	std::string m_name{};

public:
	void setName(std::string_view name) { m_name = name; }
	const std::string& getName() const { return m_name; } //  getter 按 const 引用返回
};

// createEmployee() 按值返回一个 Employee（这意味着返回值是一个右值）
Employee createEmployee(std::string_view name)
{
	Employee e;
	e.setName(name);
	return e;
}

int main()
{
	// 情况 1：可以：在同一表达式中使用返回的右值类对象成员的引用
	std::cout << createEmployee("Frank").getName();

	// 情况 2：不好：保存返回的右值类对象成员的引用以供稍后使用
	const std::string& ref { createEmployee("Garbo").getName() }; // 当 createEmployee() 的返回值被销毁时，引用变为悬垂
	std::cout << ref; // 未定义行为

	// 情况 3：可以：将引用的值复制到局部变量以供稍后使用
	std::string val { createEmployee("Hans").getName() }; // 复制引用的成员
	std::cout << val; // 可以：val 独立于引用的成员

	return 0;
}

当 createEmployee() 被调用时，它将按值返回一个 Employee 对象。这个返回的 Employee 对象是一个右值，它将存在直到包含对 createEmployee()调用的完整表达式结束。当该右值对象被销毁时，对该对象任何成员的引用都将成为悬垂引用。

在情况1中，我们调用 createEmployee("Frank")，它返回一个右值 Employee 对象。然后我们在这个右值对象上调用 getName() ，它返回一个对 m_name的引用。然后立即使用这个引用来将名字打印到控制台。此时，包含对 createEmployee("Frank") 调用的完整表达式结束，右值对象及其成员被销毁。由于此后不再使用右值对象或其成员，这种情况是安全的。

在情况2中，我们遇到了问题。首先， createEmployee("Garbo") 返回一个右值对象。然后我们调用 getName() 来获取对这个右值的 m_name 成员的引用。这个 m_name 成员随后被用来初始化 ref。此时，包含对 createEmployee("Garbo") 调用的完整表达式结束，右值对象及其成员被销毁。这使得 ref 成为悬垂引用。因此，当我们在后续语句中使用 ref 时，我们访问了一个悬垂引用，导致未定义行为。

关键提示

完整表达式的求值结束于 之后 任何将该完整表达式用作初始化器的使用之后。这允许对象用相同类型的右值进行初始化（因为右值在初始化完成后才会被销毁）。

但是，如果我们想保存一个通过引用返回成员的函数的值以供以后使用呢？我们可以不使用返回的引用来初始化一个局部引用变量，而是使用返回的引用来初始化一个非引用的局部变量。

在情况3中，我们使用返回的引用来初始化非引用局部变量 val。这将导致被引用的成员被复制到 val中。初始化之后， val 独立于该引用存在。因此，当右值对象随后被销毁时， val 不受影响。因此 val 可以在后续语句中安全地输出。

安全使用返回引用的成员函数

尽管右值隐式对象存在潜在危险，但惯例是，对于复制成本高的类型，getter 应通过 const 引用返回，而不是按值返回。

鉴于此，我们来讨论如何安全地使用此类函数的返回值。上面示例中的三种情况说明了三个关键点：

  • 优先立即使用返回引用的成员函数的返回值（如情况1所示）。由于这对左值和右值对象都适用，如果你总是这样做，就能避免麻烦。
  • 不要“保存”返回的引用以供以后使用（如情况2所示），除非你确定隐式对象是左值。如果你对右值隐式对象这样做，使用现已悬垂的引用时会导致未定义行为。
  • 如果你确实需要持久化一个返回的引用以供以后使用，并且不确定隐式对象是否是左值，那么使用返回的引用作为非引用局部变量的初始化器，这将把被引用的成员复制到局部变量中（如情况3所示）。

最佳实践

优先立即使用返回引用的成员函数的返回值，以避免当隐式对象是右值时出现悬垂引用问题。

不要返回对私有数据成员的非 const 引用

因为引用就像被引用的对象一样，返回非 const 引用的成员函数提供了对该成员的直接访问（即使该成员是私有的）。

例如：

#include <iostream>

class Foo
{
private:
    int m_value{ 4 }; // 私有成员

public:
    int& value() { return m_value; } // 返回一个非 const 引用（不要这样做）
};

int main()
{
    Foo f{};                // f.m_value 被初始化为默认值 4
    f.value() = 5;          // 相当于 m_value = 5
    std::cout << f.value(); // 打印 5

    return 0;
}

因为 value() 返回一个非 const 引用到 m_value，调用者可以使用该引用直接访问（并更改） m_value。

这允许调用者破坏访问控制系统。

const 成员函数不能返回对数据成员的非 const 引用

const 成员函数不允许返回对成员的非 const 引用。这是有道理的——const 成员函数不允许修改对象的状态，也不允许调用会修改对象状态的函数。它不应该做任何可能导致对象修改的事情。

如果允许 const 成员函数返回对成员的非 const 引用，它将为调用者提供直接修改该成员的方式。这违反了 const 成员函数的意图。
