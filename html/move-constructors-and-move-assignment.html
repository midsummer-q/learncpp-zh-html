22.3 — 移动构造函数和移动赋值

● 机器译文 课程 22.3 查看英文原文

在课程 22.1 -- 智能指针和移动语义简介中，我们了解了 std::auto_ptr，讨论了移动语义的需求，并探讨了当为复制语义设计的函数（复制构造函数和复制赋值运算符）被重新定义为实现移动语义时出现的一些缺点。

在本课中，我们将更深入地了解 C++11 如何通过移动构造函数和移动赋值来解决这些问题。

回顾复制构造函数和复制赋值

首先，让我们花点时间回顾一下复制语义。

复制构造函数用于通过复制同一类的对象来初始化一个类。复制赋值用于将一个类对象复制到另一个已存在的类对象。默认情况下，如果没有显式提供，C++ 会提供复制构造函数和复制赋值运算符。这些编译器提供的函数执行浅拷贝，这可能会给分配动态内存的类带来问题。因此，处理动态内存的类应该重写这些函数以执行深拷贝。

回到本章第一课中的 Auto_ptr 智能指针类示例，让我们看一个实现了深拷贝的复制构造函数和复制赋值运算符的版本，以及一个使用它们的示例程序：

#include <iostream>

template<typename T>
class Auto_ptr3
{
	T* m_ptr {};
public:
	Auto_ptr3(T* ptr = nullptr)
		: m_ptr { ptr }
	{
	}

	~Auto_ptr3()
	{
		delete m_ptr;
	}

	// 拷贝构造函数
	// 对 a.m_ptr 进行深拷贝到 m_ptr
	Auto_ptr3(const Auto_ptr3& a)
	{
		m_ptr = new T;
		*m_ptr = *a.m_ptr;
	}

	// 复制赋值
	// 对 a.m_ptr 进行深拷贝到 m_ptr
	Auto_ptr3& operator=(const Auto_ptr3& a)
	{
		// 自赋值检测
		if (&a == this)
			return *this;

		// 释放我们持有的任何资源
		delete m_ptr;

		// 复制资源
		m_ptr = new T;
		*m_ptr = *a.m_ptr;

		return *this;
	}

	T& operator*() const { return *m_ptr; }
	T* operator->() const { return m_ptr; }
	bool isNull() const { return m_ptr == nullptr; }
};

class Resource
{
public:
	Resource() { std::cout << "Resource acquired\n"; }
	~Resource() { std::cout << "Resource destroyed\n"; }
};

Auto_ptr3<Resource> generateResource()
{
	Auto_ptr3<Resource> res{new Resource};
	return res; // 此返回值将调用复制构造函数
}

int main()
{
	Auto_ptr3<Resource> mainres;
	mainres = generateResource(); // 此赋值将调用复制赋值

	return 0;
}

在这个程序中，我们使用一个名为 generateResource() 的函数来创建一个智能指针封装的资源，然后将其传回给 main() 函数。main() 函数然后将其赋值给一个现有的 Auto_ptr3 对象。

当这个程序运行时，它会打印：

Resource acquired
Resource acquired
Resource destroyed
Resource acquired
Resource destroyed
Resource destroyed

（注意：如果编译器省略了 generateResource() 函数的返回值，你可能只会得到 4 个输出）

对于一个如此简单的程序来说，发生了大量的资源创建和销毁！这是怎么回事？

让我们仔细看看。这个程序中有 6 个关键步骤（每个打印的消息对应一个）：

  1. 在 generateResource() 内部，局部变量 res 被创建并用动态分配的 Resource 初始化，这导致了第一个“Resource acquired”。
  2. Res 通过值返回给 main()。我们在这里通过值返回，因为 res 是一个局部变量——它不能通过地址或引用返回，因为当 generateResource() 结束时 res 会被销毁。所以 res 被复制构造到一个临时对象中。由于我们的复制构造函数执行深拷贝，这里分配了一个新的 Resource，导致了第二个“Resource acquired”。
  3. Res 超出作用域，销毁最初创建的 Resource，导致了第一个“Resource destroyed”。
  4. 临时对象通过复制赋值被赋值给 mainres。由于我们的复制赋值也执行深拷贝，分配了一个新的 Resource，导致了又一个“Resource acquired”。
  5. 赋值表达式结束，临时对象超出表达式作用域并被销毁，导致了一个“Resource destroyed”。
  6. 在 main() 结束时，mainres 超出作用域，显示了最后一个“Resource destroyed”。

简而言之，因为我们调用复制构造函数一次将 res 复制构造到临时对象，并调用复制赋值一次将临时对象复制到 mainres，我们最终总共分配和销毁了 3 个独立的对象。

效率低下，但至少不会崩溃！

然而，使用移动语义，我们可以做得更好。

移动构造函数和移动赋值

C++11 定义了两个新函数来支持移动语义：移动构造函数和移动赋值运算符。复制构造函数和复制赋值的目标是将一个对象复制到另一个对象，而移动构造函数和移动赋值的目标是将资源的所有权从一个对象移动到另一个对象（这通常比复制便宜得多）。

定义移动构造函数和移动赋值的工作方式与它们的复制对应物类似。然而，复制版本的函数接受 const 左值引用参数（可以绑定到几乎任何东西），而移动版本的函数使用非 const 右值引用参数（只绑定到右值）。

下面是上面相同的 Auto_ptr3 类，添加了移动构造函数和移动赋值运算符。为了比较，我们保留了深拷贝的复制构造函数和复制赋值运算符。

#include <iostream>

template<typename T>
class Auto_ptr4
{
	T* m_ptr {};
public:
	Auto_ptr4(T* ptr = nullptr)
		: m_ptr { ptr }
	{
	}

	~Auto_ptr4()
	{
		delete m_ptr;
	}

	// 拷贝构造函数
	// 对 a.m_ptr 进行深拷贝到 m_ptr
	Auto_ptr4(const Auto_ptr4& a)
	{
		m_ptr = new T;
		*m_ptr = *a.m_ptr;
	}

	// 移动构造函数
	// 将 a.m_ptr 的所有权转移给 m_ptr
	Auto_ptr4(Auto_ptr4&& a) noexcept
		: m_ptr { a.m_ptr }
	{
		a.m_ptr = nullptr; // 我们将在下面进一步讨论这一行
	}

	// 复制赋值
	// 对 a.m_ptr 进行深拷贝到 m_ptr
	Auto_ptr4& operator=(const Auto_ptr4& a)
	{
		// 自赋值检测
		if (&a == this)
			return *this;

		// 释放我们持有的任何资源
		delete m_ptr;

		// 复制资源
		m_ptr = new T;
		*m_ptr = *a.m_ptr;

		return *this;
	}

	// 移动赋值
	// 将 a.m_ptr 的所有权转移给 m_ptr
	Auto_ptr4& operator=(Auto_ptr4&& a) noexcept
	{
		// 自赋值检测
		if (&a == this)
			return *this;

		// 释放我们持有的任何资源
		delete m_ptr;

		// 将 a.m_ptr 的所有权转移给 m_ptr
		m_ptr = a.m_ptr;
		a.m_ptr = nullptr; // 我们将在下面进一步讨论这一行

		return *this;
	}

	T& operator*() const { return *m_ptr; }
	T* operator->() const { return m_ptr; }
	bool isNull() const { return m_ptr == nullptr; }
};

class Resource
{
public:
	Resource() { std::cout << "Resource acquired\n"; }
	~Resource() { std::cout << "Resource destroyed\n"; }
};

Auto_ptr4<Resource> generateResource()
{
	Auto_ptr4<Resource> res{new Resource};
	return res; // 此返回值将调用移动构造函数
}

int main()
{
	Auto_ptr4<Resource> mainres;
	mainres = generateResource(); // 此赋值将调用移动赋值

	return 0;
}

移动构造函数和移动赋值运算符很简单。我们不是将源对象（a）深拷贝到目标对象（隐式对象），而是简单地移动（窃取）源对象的资源。这包括将源指针浅拷贝到隐式对象，然后将源指针设置为空。

运行后，该程序输出：

Resource acquired
Resource destroyed

好多了！

程序的流程与之前完全相同。然而，这个程序调用的是移动构造函数和移动赋值运算符，而不是复制构造函数和复制赋值运算符。更深入地看：

  1. 在 generateResource() 内部，局部变量 res 被创建并用动态分配的 Resource 初始化，这导致了第一个“Resource acquired”。
  2. Res 通过值返回给 main()。Res 被移动构造到一个临时对象，将存储在 res 中的动态创建对象转移到临时对象。我们将在下面讨论为什么会发生这种情况。
  3. Res 超出作用域。因为 res 不再管理指针（它被移动到了临时对象），这里没有发生什么有趣的事情。
  4. 临时对象被移动赋值给 mainres。这将存储在临时对象中的动态创建对象转移到 mainres。
  5. 赋值表达式结束，临时对象超出表达式作用域并被销毁。然而，因为临时对象不再管理指针（它被移动到了 mainres），这里也没有发生什么有趣的事情。
  6. 在 main() 结束时，mainres 超出作用域，显示了最后一个“Resource destroyed”。

因此，我们不是将 Resource 复制两次（一次用于复制构造函数，一次用于复制赋值），而是转移了两次。这更高效，因为 Resource 只被构造和销毁一次，而不是三次。

相关内容

移动构造函数和移动赋值应标记为 noexcept。这告诉编译器这些函数不会抛出异常。

我们介绍 noexcept 在课程 27.9 -- 异常规范和 noexcept 并讨论为什么移动构造函数和移动赋值被标记为 noexcept 在课程 27.10 -- std::move_if_noexcept。

何时调用移动构造函数和移动赋值运算符？

当这些函数已被定义，且构造或赋值的参数是右值时，会调用移动构造函数和移动赋值运算符。最常见的情况是，这个右值是一个字面量或临时值。

否则（当参数是左值，或者参数是右值但未定义移动构造函数或移动赋值运算符时），会使用拷贝构造函数和拷贝赋值运算符。

隐式移动构造函数和移动赋值运算符

如果满足以下所有条件，编译器将生成隐式的移动构造函数和移动赋值运算符：

  • 没有用户声明的拷贝构造函数或拷贝赋值运算符。
  • 没有用户声明的移动构造函数或移动赋值运算符。
  • 没有用户声明的析构函数。

这些函数执行逐成员移动，其行为如下：

  • 如果成员有移动构造函数或移动赋值运算符（视情况而定），则会调用它。
  • 否则，该成员将被拷贝。

值得注意的是，这意味着指针将被拷贝，而不是移动！

警告

隐式移动构造函数和移动赋值运算符会拷贝指针，而不是移动它们。如果你想移动指针成员，你需要自己定义移动构造函数和移动赋值运算符。

移动语义的关键见解

现在你已经有足够的背景知识来理解移动语义的关键见解了。

如果我们构造一个对象或执行赋值操作，且参数是左值，那么我们唯一能合理做的就是拷贝该左值。我们不能假设修改左值是安全的，因为它可能在程序后面再次被使用。如果我们有表达式“a = b”（其中b是左值），我们不会合理地期望b以任何方式被改变。

然而，如果我们构造一个对象或执行赋值操作，且参数是右值，那么我们知道该右值只是某种临时对象。与其拷贝它（这可能很昂贵），我们可以简单地将它的资源转移（这很廉价）到我们正在构造或赋值的对象中。这样做是安全的，因为临时对象无论如何都会在表达式结束时被销毁，所以我们知道它再也不会被使用！

C++11通过右值引用，使我们能够在参数是右值与左值时提供不同的行为，从而让我们能够对我们的对象应该如何行为做出更智能、更高效的决策。

关键提示

移动语义是一个优化机会。

移动函数应始终使两个对象都处于有效状态

在上面的例子中，移动构造函数和移动赋值函数都将a.m_ptr设置为nullptr。这看起来可能是多余的——毕竟，如果 a 是一个临时右值，为什么还要费心做“清理”呢？参数 a 反正要被销毁？

答案很简单：当 a 离开作用域时，析构函数会被调用， a 会被删除。如果此时， a.m_ptr 仍然指向与 a.m_ptr 相同的对象， m_ptr，那么 m_ptr 将成为一个悬空指针。当包含 m_ptr 的对象最终被使用（或销毁）时，我们会得到未定义行为。

在实现移动语义时，确保被移动的对象处于有效状态非常重要，这样它才能正确析构（而不会产生未定义行为）。

按值返回的自动左值可能被移动而不是拷贝

在上面的Auto_ptr4示例的generateResource()函数中，当变量res按值返回时，它被移动而不是拷贝，即使res是一个左值。C++规范有一条特殊规则，即从函数按值返回的自动对象即使它们是左值也可以被移动。这是有道理的，因为res无论如何都会在函数结束时被销毁！我们不妨窃取它的资源，而不是进行昂贵且不必要的拷贝。

尽管编译器可以移动左值返回值，但在某些情况下，它甚至可以通过完全省略拷贝来做得更好（这避免了进行拷贝或移动的需要）。在这种情况下，拷贝构造函数和移动构造函数都不会被调用。

禁用拷贝

在上面的Auto_ptr4类中，我们保留了拷贝构造函数和赋值运算符以便比较。但在支持移动的类中，有时需要删除拷贝构造函数和拷贝赋值函数，以确保不会进行拷贝。以我们的Auto_ptr类为例，我们不想拷贝模板对象T——既因为拷贝很昂贵，也因为T类本身可能不支持拷贝！

这是一个支持移动语义但不支持拷贝语义的Auto_ptr版本：

#include <iostream>

template<typename T>
class Auto_ptr5
{
	T* m_ptr {};
public:
	Auto_ptr5(T* ptr = nullptr)
		: m_ptr { ptr }
	{
	}

	~Auto_ptr5()
	{
		delete m_ptr;
	}

	// 复制构造函数 -- 不允许复制！
	Auto_ptr5(const Auto_ptr5& a) = delete;

	// 移动构造函数
	// 将 a.m_ptr 的所有权转移给 m_ptr
	Auto_ptr5(Auto_ptr5&& a) noexcept
		: m_ptr { a.m_ptr }
	{
		a.m_ptr = nullptr;
	}

	// 复制赋值 -- 不允许复制！
	Auto_ptr5& operator=(const Auto_ptr5& a) = delete;

	// 移动赋值
	// 将 a.m_ptr 的所有权转移给 m_ptr
	Auto_ptr5& operator=(Auto_ptr5&& a) noexcept
	{
		// 自赋值检测
		if (&a == this)
			return *this;

		// 释放我们持有的任何资源
		delete m_ptr;

		// 将 a.m_ptr 的所有权转移给 m_ptr
		m_ptr = a.m_ptr;
		a.m_ptr = nullptr;

		return *this;
	}

	T& operator*() const { return *m_ptr; }
	T* operator->() const { return m_ptr; }
	bool isNull() const { return m_ptr == nullptr; }
};

如果你试图将Auto_ptr5左值按值传递给函数，编译器会报错，因为初始化函数参数所需的拷贝构造函数已被删除。这很好，因为我们可能应该通过const左值引用来传递Auto_ptr5！

Auto_ptr5（终于）是一个好的智能指针类。事实上，标准库中包含一个非常类似的类（你应该使用它），名为std::unique_ptr。我们将在本章后面详细讨论std::unique_ptr。

另一个示例

让我们看看另一个使用动态内存的类：一个简单的动态模板数组。这个类包含一个深拷贝的拷贝构造函数和拷贝赋值运算符。

#include <cstddef> // for std::size_t

template <typename T>
class DynamicArray
{
private:
	T* m_array {};
	int m_length {};

	void alloc(int length)
	{
		m_array = new T[static_cast<std::size_t>(length)];
        	m_length = length;
	}
public:
	DynamicArray(int length)
	{
		alloc(length);
	}

	~DynamicArray()
	{
		delete[] m_array;
	}

	// 拷贝构造函数
	DynamicArray(const DynamicArray &arr)
	{
		alloc(arr.m_length);
		std::copy_n(arr.m_array, m_length, m_array); // 从 arr 复制 m_length 个元素到 m_array
	}

	// 复制赋值
	DynamicArray& operator=(const DynamicArray &arr)
	{
		if (&arr == this)
			return *this;

		delete[] m_array;

		alloc(arr.m_length);

		std::copy_n(arr.m_array, m_length, m_array); // 从 arr 复制 m_length 个元素到 m_array

		return *this;
	}

	int getLength() const { return m_length; }
	T& operator[](int index) { return m_array[index]; }
	const T& operator[](int index) const { return m_array[index]; }
};

现在让我们在程序中使用这个类。为了展示当我们在堆上分配一百万个整数时这个类的性能，我们将利用在课程 18.4 -- 计时你的代码中开发的 Timer 类。我们将使用 Timer 类来计时代码运行的速度，并向你展示复制和移动之间的性能差异。

#include <algorithm> // for std::copy_n
#include <chrono> // for std::chrono functions
#include <iostream>

// 使用上述 DynamicArray 类

class Timer
{
private:
	// 类型别名，使访问嵌套类型更容易
	using Clock = std::chrono::high_resolution_clock;
	using Second = std::chrono::duration<double, std::ratio<1> >;
	
	std::chrono::time_point<Clock> m_beg { Clock::now() };

public:
	void reset()
	{
		m_beg = Clock::now();
	}
	
	double elapsed() const
	{
		return std::chrono::duration_cast<Second>(Clock::now() - m_beg).count();
	}
};

// 返回 arr 的副本，其中所有值都翻倍
DynamicArray<int> cloneArrayAndDouble(const DynamicArray<int> &arr)
{
	DynamicArray<int> dbl(arr.getLength());
	for (int i = 0; i < arr.getLength(); ++i)
		dbl[i] = arr[i] * 2;

	return dbl;
}

int main()
{
	Timer t;

	DynamicArray<int> arr(1000000);

	for (int i = 0; i < arr.getLength(); i++)
		arr[i] = i;

	arr = cloneArrayAndDouble(arr);

	std::cout << t.elapsed();
}

在作者的一台机器上，以发布模式运行，该程序执行时间为 0.00825559 秒。

现在让我们更新 DynamicArray ，将复制构造函数和复制赋值替换为移动构造函数和移动赋值，然后再次运行程序：

#include <cstddef> // for std::size_t

template <typename T>
class DynamicArray
{
private:
	T* m_array {};
	int m_length {};

	void alloc(int length)
	{
		m_array = new T[static_cast<std::size_t>(length)];
		m_length = length;
	}
public:
	DynamicArray(int length)
	{
		alloc(length);
	}

	~DynamicArray()
	{
		delete[] m_array;
	}

	// 拷贝构造函数
	DynamicArray(const DynamicArray &arr) = delete;

	// 复制赋值
	DynamicArray& operator=(const DynamicArray &arr) = delete;

	// 移动构造函数
	DynamicArray(DynamicArray &&arr) noexcept
		:  m_array { arr.m_array }, m_length { arr.m_length }
	{
		arr.m_length = 0;
		arr.m_array = nullptr;
	}

	// 移动赋值
	DynamicArray& operator=(DynamicArray &&arr) noexcept
	{
		if (&arr == this)
			return *this;

		delete[] m_array;

		m_length = arr.m_length;
		m_array = arr.m_array;
		arr.m_length = 0;
		arr.m_array = nullptr;

		return *this;
	}

	int getLength() const { return m_length; }
	T& operator[](int index) { return m_array[index]; }
	const T& operator[](int index) const { return m_array[index]; }
};

#include <iostream>
#include <chrono> // for std::chrono functions

class Timer
{
private:
	// 类型别名，使访问嵌套类型更容易
	using Clock = std::chrono::high_resolution_clock;
	using Second = std::chrono::duration<double, std::ratio<1> >;
	
	std::chrono::time_point<Clock> m_beg { Clock::now() };

public:
	void reset()
	{
		m_beg = Clock::now();
	}
	
	double elapsed() const
	{
		return std::chrono::duration_cast<Second>(Clock::now() - m_beg).count();
	}
};

// 返回 arr 的副本，其中所有值都翻倍
DynamicArray<int> cloneArrayAndDouble(const DynamicArray<int> &arr)
{
	DynamicArray<int> dbl(arr.getLength());
	for (int i = 0; i < arr.getLength(); ++i)
		dbl[i] = arr[i] * 2;

	return dbl;
}

int main()
{
	Timer t;

	DynamicArray<int> arr(1000000);

	for (int i = 0; i < arr.getLength(); i++)
		arr[i] = i;

	arr = cloneArrayAndDouble(arr);

	std::cout << t.elapsed();
}

在同一台机器上，该程序执行时间为 0.0056 秒。

比较两个程序的运行时间，(0.00825559 - 0.0056) / 0.00825559 * 100 = 快了 32.1%！

删除移动构造函数和移动赋值

你可以使用 = delete 语法删除移动构造函数和移动赋值，就像删除复制构造函数和复制赋值一样。

#include <iostream>
#include <string>
#include <string_view>

class Name
{
private:
    std::string m_name {};

public:
    Name(std::string_view name) : m_name{ name }
    {
    }

    Name(const Name& name) = delete;
    Name& operator=(const Name& name) = delete;
    Name(Name&& name) = delete;
    Name& operator=(Name&& name) = delete;

    const std::string& get() const { return m_name; }
};

int main()
{
    Name n1{ "Alex" };
    n1 = Name{ "Joe" }; // 错误：移动赋值被删除

    std::cout << n1.get() << '\n';

    return 0;
}

如果你删除了复制构造函数，编译器将不会生成隐式移动构造函数（使你的对象既不可复制也不可移动）。因此，在删除复制构造函数时，明确说明你对移动构造函数的行为期望是有用的。要么显式删除它们（明确这是期望的行为），要么将它们设为默认（使类成为只移动类型）。

关键提示

浮点类型的 仍然可以被类的其他成员使用，因此除非需要，否则不建议使用这种解决方案。 指出，如果复制构造函数、复制赋值、移动构造函数、移动赋值或析构函数被定义或删除，那么这些函数中的每一个都应该被定义或删除。

虽然只删除移动构造函数和移动赋值似乎是一个好主意，如果你想要一个可复制但不可移动的对象，但这会产生一个不幸的后果：在强制复制省略不适用的情况下，该类无法按值返回。这是因为已删除的移动构造函数仍然是一个声明的函数，因此有资格参与重载决议。而按值返回会优先选择已删除的移动构造函数，而不是未删除的复制构造函数。下面的程序说明了这一点：

#include <iostream>
#include <string>
#include <string_view>

class Name
{
private:
    std::string m_name {};

public:
    Name(std::string_view name) : m_name{ name }
    {
    }

    Name(const Name& name) = default;
    Name& operator=(const Name& name) = default;

    Name(Name&& name) = delete;
    Name& operator=(Name&& name) = delete;

    const std::string& get() const { return m_name; }
};

Name getJoe()
{
    Name joe{ "Joe" };
    return joe; // 错误：移动构造函数被删除
}

int main()
{
    Name n{ getJoe() };

    std::cout << n.get() << '\n';

    return 0;
}

移动语义的问题和 std::swap 高级

在课程 我们在第，我们提到了复制并交换惯用法。复制并交换也适用于移动语义，这意味着我们可以通过将资源与将要销毁的对象交换来实现移动构造函数和移动赋值。

这有两个好处：

  • 持久对象现在控制着之前由即将消亡的对象拥有的资源（这是我们的主要目标）。
  • 即将消亡的对象现在控制着之前由持久对象拥有的资源。当即将消亡的对象实际消亡时，它可以对这些资源进行任何必要的清理。

当想到交换时，通常首先想到的是 std::swap()。然而，使用 std::swap() 实现移动构造函数和移动赋值是有问题的，因为 std::swap() 会在可移动对象上同时调用移动构造函数和移动赋值。这将导致无限递归问题。

你可以在下面的例子中看到这种情况：

#include <iostream>
#include <string>
#include <string_view>

class Name
{
private:
    std::string m_name {}; // std::string 支持移动

public:
    Name(std::string_view name) : m_name{ name }
    {
    }

    Name(const Name& name) = delete;
    Name& operator=(const Name& name) = delete;

    Name(Name&& name) noexcept
    {
        std::cout << "Move ctor\n";

        std::swap(*this, name); // 糟糕！
    }

    Name& operator=(Name&& name) noexcept
    {
        std::cout << "Move assign\n";

        std::swap(*this, name); // 糟糕！

        return *this;
    }

    const std::string& get() const { return m_name; }
};

int main()
{
    Name n1{ "Alex" };   
    n1 = Name{"Joe"}; // 调用移动赋值运算符

    std::cout << n1.get() << '\n';
    
    return 0;
}

这会打印：

Move assign
Move ctor
Move ctor
Move ctor
Move ctor

依此类推……直到栈溢出。

你可以使用自己的 swap 函数实现移动构造函数和移动赋值，只要你的 swap 成员函数不调用移动构造函数或移动赋值。下面是一个如何实现的例子：

#include <iostream>
#include <string>
#include <string_view>

class Name
{
private:
    std::string m_name {};

public:
    Name(std::string_view name) : m_name{ name }
    {
    }

    Name(const Name& name) = delete;
    Name& operator=(const Name& name) = delete;
    
    // 创建我们自己的 swap 友元函数来交换 Name 的成员
    friend void swap(Name& a, Name& b) noexcept
    {
        // 我们通过对 std::string 成员调用 std::swap 来避免递归调用，
        // 而不是对 Name 调用
        std::swap(a.m_name, b.m_name);
    }

    Name(Name&& name) noexcept
    {
        std::cout << "Move ctor\n";

        swap(*this, name); // 现在调用我们自己的 swap，而不是 std::swap
    }

    Name& operator=(Name&& name) noexcept
    {
        std::cout << "Move assign\n";

        swap(*this, name); // 现在调用我们自己的 swap，而不是 std::swap

        return *this;
    }

    const std::string& get() const { return m_name; }
};

int main()
{
    Name n1{ "Alex" };   
    n1 = Name{"Joe"}; // 调用移动赋值运算符

    std::cout << n1.get() << '\n';

    return 0;
}

这按预期工作，并打印：

Move assign
