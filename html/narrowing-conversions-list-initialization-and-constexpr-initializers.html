10.4 — 窄化转换、列表初始化与constexpr初始化器

● 机器译文 课程 10.4 查看英文原文

在前一课（10.3 -- 数值转换），我们介绍了数值转换，它涵盖了基本类型之间各种不同的类型转换。

窄化转换

在C++中， 窄化转换 是一种潜在不安全的数值转换，其中目标类型可能无法容纳源类型的所有值。

以下转换被定义为窄化：

  • 从浮点类型到整数类型。
  • 从浮点类型到更窄或排名更低的浮点类型，除非被转换的值是constexpr且在目标类型的范围内（即使目标类型没有足够的精度来存储该数字的所有有效数字）。
  • 从整数类型到浮点类型，除非被转换的值是constexpr且其值可以精确存储在目标类型中。
  • 从整数类型到另一个无法表示原始类型所有值的整数类型，除非被转换的值是constexpr且其值可以精确存储在目标类型中。这包括从宽到窄的整数转换，以及整数符号转换（有符号到无符号，或反之）。

在大多数情况下，隐式窄化转换会导致编译器警告，但符号/无符号转换除外（是否产生警告取决于编译器的配置）。

应尽可能避免窄化转换，因为它们潜在不安全，因此是潜在错误的来源。

最佳实践

由于它们可能不安全且是错误来源，请尽可能避免窄化转换。

使有意的窄化转换显式化

窄化转换并非总是可以避免——这在函数调用中尤其如此，因为函数参数和实参可能类型不匹配，需要窄化转换。

在这种情况下，最好使用 static_cast将隐式窄化转换转换为显式窄化转换。这样做有助于表明窄化转换是有意的，并且会抑制否则会产生的任何编译器警告或错误。

例如：

void someFcn(int i)
{
}

int main()
{
    double d{ 5.0 };
    
    someFcn(d); // // 不好：隐式窄化转换会生成编译器警告

    // // 好：我们明确告诉编译器这个窄化转换是有意的
    someFcn(static_cast<int>(d)); // // 不生成警告
    
    return 0;
}

最佳实践

如果需要执行窄化转换，请使用 static_cast 将其转换为显式转换。

花括号初始化禁止窄化转换

使用花括号初始化时禁止窄化转换（这是首选这种初始化形式的主要原因之一），尝试这样做会产生编译错误。

例如：

int main()
{
    int i { 3.5 }; // // 无法编译

    return 0;
}

Visual Studio 产生以下错误：

error C2397: conversion from 'double' to 'int' requires a narrowing conversion

如果你确实想在花括号初始化中进行窄化转换，请使用 static_cast 将窄化转换为显式转换：

int main()
{
    double d { 3.5 };

    // // static_cast<int> 将 double 转换为 int，用 int 结果初始化 i
    int i { static_cast<int>(d) }; 

    return 0;
}

某些constexpr转换不被视为窄化

当窄化转换的源值在运行时未知时，转换的结果也无法在运行时确定。在这种情况下，窄化转换是否保留值也无法在运行时确定。例如：

#include <iostream>

void print(unsigned int u) // 注意：无符号
{
    std::cout << u << '\n';
}

int main()
{
    std::cout << "Enter an integral value: ";
    int n{};
    std::cin >> n; // // 输入 5 或 -5
    print(n);      // // 转换为 unsigned 可能保留也可能不保留值

    return 0;
}

在上面的程序中，编译器不知道将为 n。当 print(n) 被调用时，从 int 切换到 unsigned int 的转换将在那时执行，结果可能保留值也可能不保留，具体取决于输入的 n 的值。因此，启用了符号/无符号警告的编译器会对此情况发出警告。

然而，你可能已经注意到，大多数窄化转换的定义都有一个以“除非被转换的值是constexpr且……”开头的例外子句。例如，当转换是“从整数类型到另一个无法表示原始类型所有值的整数类型，除非被转换的值是constexpr且其值可以精确存储在目标类型中”时，该转换是窄化的。

当窄化转换的源值是constexpr时，要转换的具体值必须为编译器所知。在这种情况下，编译器可以自行执行转换，然后检查值是否被保留。如果值未被保留，编译器可以停止编译并报错。如果值被保留，则该转换不被视为窄化（并且编译器可以用转换后的结果替换整个转换，因为这样做是安全的）。

例如：

#include <iostream>

int main()
{
    constexpr int n1{ 5 };   // // 注意：constexpr
    unsigned int u1 { n1 };  // // 可以：由于排除条款，转换不是窄化

    constexpr int n2 { -5 }; // // 注意：constexpr
    unsigned int u2 { n2 };  // // 编译错误：由于值改变，转换是窄化

    return 0;
}

让我们将规则“从整数类型到另一个无法表示原始类型所有值的整数类型，除非被转换的值是constexpr且其值可以精确存储在目标类型中”应用于上述两个转换。

在 n1 和 u1， n1 是一个 int 和 u1 是一个 unsigned int，所以这是从整数类型到另一个无法表示原始类型所有值的整数类型的转换。然而， n1 是constexpr，其值 5 可以精确表示在目标类型中（作为无符号值 5）。因此，这不被视为窄化转换，我们被允许列表初始化 u1 using n1。

在 n2 和 u2，情况类似。尽管 n2 是constexpr，但其值 -5 无法在目标类型中精确表示，因此这被视为窄化转换，并且由于我们使用的是列表初始化，编译器将报错并停止编译。

奇怪的是，从浮点类型到整数类型的转换没有 constexpr 排除条款，因此即使要转换的值是 constexpr 且在目标类型的范围内，这些转换也始终被视为窄化转换：

int n { 5.0 }; // // 编译错误：窄化转换

更奇怪的是，从 constexpr 浮点类型到更窄浮点类型的转换即使存在精度损失也不被视为窄化！

constexpr double d { 0.1 };
float f { d }; // // 不是窄化，即使导致精度损失

警告

从 constexpr 浮点类型到更窄浮点类型的转换即使导致精度损失也不被视为窄化。

使用 constexpr 初始化器的列表初始化

这些 constexpr 异常条款在列表初始化非 int/非 double 对象时非常有用，因为我们可以使用 int 或 double 字面量（或 constexpr 对象）作为初始化值。

这使我们能够避免：

  • 在大多数情况下使用字面量后缀
  • 在初始化中使用 static_cast 造成混乱

例如：

int main()
{
    // // 我们可以避免带后缀的字面量
    unsigned int u { 5 }; // // 可以（我们不需要使用 `5u`）
    float f { 1.5 };      // // 可以（我们不需要使用 `1.5f`）

    // // 我们可以避免 static_cast
    constexpr int n{ 5 };
    double d { n };       // // 可以（这里不需要 static_cast）
    short s { 5 };        // // 可以（short 没有后缀，这里不需要 static_cast）

    return 0;
}

这也适用于拷贝初始化和直接初始化。

值得一提的是一个注意事项：用 constexpr 值初始化更窄或排名更低的浮点类型是允许的，只要该值在目标类型的范围内，即使目标类型没有足够的精度来精确存储该值！

关键提示

浮点类型的排名顺序如下（从高到低）：

  • long double
  • double
  • float

因此，像这样的代码是合法的，不会报错：

int main()
{
    float f { 1.23456789 }; // // 不是窄化转换，即使精度损失！

    return 0;
}

但是，你的编译器在这种情况下可能仍会发出警告（如果使用 -Wconversion 编译标志，GCC 和 Clang 会这样做）。
