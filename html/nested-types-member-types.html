15.3 — 嵌套类型（成员类型）

● 机器译文 课程 15.3 查看英文原文

考虑以下简短程序：

#include <iostream>

enum class FruitType
{
	apple,
	banana,
	cherry
};

class Fruit
{
private:
	FruitType m_type { };
	int m_percentageEaten { 0 };

public:
	Fruit(FruitType type) :
		m_type { type }
	{
	}

	FruitType getType() { return m_type; }
	int getPercentageEaten() { return m_percentageEaten; }

	bool isCherry() { return m_type == FruitType::cherry; }

};

int main()
{
	Fruit apple { FruitType::apple };
	
	if (apple.getType() == FruitType::apple)
		std::cout << "I am an apple";
	else
		std::cout << "I am not an apple";
	
	return 0;
}

这个程序本身没有问题。但是因为 enum class FruitType 旨在与 Fruit 类一起使用，让它独立于类存在会让我们推断它们之间的关联。

嵌套类型（成员类型）

到目前为止，我们已经看到了具有两种不同成员的类类型：数据成员和成员函数。我们的 Fruit 类同时包含这两者。

类类型支持另一种成员： 嵌套类型 （也称为 （成员类型）。要创建嵌套类型，只需在类内部、在适当的访问说明符下定义该类型。以下是上述程序的相同版本，重写为使用定义在

类内部的嵌套类型： Fruit 类：

#include <iostream>

class Fruit
{
public:
	// FruitType 已被移到类内部，位于 public 访问说明符下
        // 我们还将其重命名为 Type，并使其成为枚举而非枚举类
	enum Type
	{
		apple,
		banana,
		cherry
	};

private:
	Type m_type {};
	int m_percentageEaten { 0 };

public:
	Fruit(Type type) :
		m_type { type }
	{
	}

	Type getType() { return m_type;  }
	int getPercentageEaten() { return m_percentageEaten;  }

	bool isCherry() { return m_type == cherry; } // 在 Fruit 的成员内部，我们不再需要为枚举器添加 FruitType:: 前缀
};

int main()
{
	// 注意：在类外部，我们现在通过 Fruit:: 前缀访问枚举器
	Fruit apple { Fruit::apple };
	
	if (apple.getType() == Fruit::apple)
		std::cout << "I am an apple";
	else
		std::cout << "I am not an apple";
	
	return 0;
}

这里有几个值得指出的点。

首先，注意 FruitType 现在定义在类内部，并已重命名为 Type ，原因我们稍后会讨论。

其次，嵌套类型 Type 定义在类的顶部。嵌套类型的名称必须在使用前完全定义，因此通常先定义它们。

最佳实践

将任何嵌套类型定义在类类型的顶部。

第三，嵌套类型遵循正常的访问规则。 Type 定义在 public 访问说明符下，因此类型名称和枚举器可以被公有地直接访问。

第四，类类型作为在其中声明的名称的作用域区域，就像命名空间一样。因此， Type 等于 Fruit::Type的完全限定名是 apple ，而 Fruit::apple。

枚举器的完全限定名是 isCherry() 在类的成员内部，我们不需要使用完全限定名。例如，在成员函数 cherry 中，我们访问 Fruit:: 枚举器时没有使用

作用域限定符。 Fruit::apple在类外部，我们必须使用完全限定名（例如 FruitType 切换到 Type ）。我们将 Fruit::Type 重命名为 Fruit::FruitType)。

，以便可以将其访问为 Fruit::apple （而不是更冗余的 Fruit::Type::apple ）。最后，我们将枚举类型从有作用域改为无作用域。由于类本身现在充当作用域区域，再使用有作用域枚举器有些冗余。改为无作用域枚举意味着我们可以将枚举器访问为

，而不是如果枚举器有作用域则必须使用的更长的

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
public:
    using IDType = int;

private:
    std::string m_name{};
    IDType m_id{};
    double m_wage{};

public:
    Employee(std::string_view name, IDType id, double wage)
        : m_name { name }
        , m_id { id }
        , m_wage { wage }
    {
    }

    const std::string& getName() { return m_name; }
    IDType getId() { return m_id; } // 在类内部可以使用非限定名称
};

int main()
{
    Employee john { "John", 1, 45000 };
    Employee::IDType id { john.getId() }; // 在类外部必须使用完全限定名称

    std::cout << john.getName() << " has id: " << id << '\n';

    return 0;
}

这会打印：

John has id: 1

嵌套的 typedef 和类型别名 IDType类类型也可以包含嵌套的 typedef 或类型别名： Employee::IDType。

注意，在类内部我们可以直接使用 10.7课——Typedefs和类型别名，它们在这里也起到相同的作用。C++ 标准库中的类经常使用嵌套类型定义。截至撰写本文时， std::string 定义了十个嵌套类型定义！

嵌套类与对外部类成员的访问

类中包含其他类作为嵌套类型的情况并不常见，但也是可能的。在 C++ 中，嵌套类无法访问外部（包含）类的 this 指针，因此嵌套类不能直接访问外部类的成员。这是因为嵌套类可以独立于外部类实例化（在这种情况下，没有外部类成员可以访问！）

然而，由于嵌套类是外部类的成员，它们可以访问作用域内的任何外部类私有成员。

让我们通过一个例子来说明：

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
public:
    using IDType = int;

    class Printer
    {
    public:
        void print(const Employee& e) const
        {
            // Printer 无法访问 Employee 的 `this` 指针
            // 所以我们不能直接打印 m_name 和 m_id
            // 相反，我们必须传入一个 Employee 对象来使用
            // 因为 Printer 是 Employee 的成员，
            // 我们可以直接访问私有成员 e.m_name 和 e.m_id
            std::cout << e.m_name << " has id: " << e.m_id << '\n';
        }
    };

private:
    std::string m_name{};
    IDType m_id{};
    double m_wage{};

public:
    Employee(std::string_view name, IDType id, double wage)
        : m_name{ name }
        , m_id{ id }
        , m_wage{ wage }
    {
    }

    // 在此示例中移除了访问函数（因为它们未被使用）
};

int main()
{
    const Employee john{ "John", 1, 45000 };
    const Employee::Printer p{}; // 实例化内部类的对象
    p.print(john);

    return 0;
}

这会打印：

John has id: 1

有一种情况下嵌套类更常用。在标准库中，大多数迭代器类都被实现为它们所设计遍历的容器的嵌套类。例如， std::string::iterator 被实现为 std::string的嵌套类。我们将在未来的章节中介绍迭代器。

嵌套类型与前置声明

嵌套类型可以在其封闭类内部进行前置声明。然后可以在封闭类内部或外部定义该嵌套类型。例如：

#include <iostream>

class outer
{
public:
    class inner1;   // 可以：在封闭类内部进行前置声明
    class inner1{}; // 可以：在封闭类内部定义前置声明的类型
    class inner2;   // 可以：在封闭类内部进行前置声明
};

class inner2 // 可以：在封闭类外部定义前置声明的类型
{
};

int main()
{
    return 0;
}

然而，嵌套类型不能在封闭类定义之前进行前置声明。

#include <iostream>

class outer;         // 可以：可以前置声明非嵌套类型
class outer::inner1; // 错误：不能在外部类定义之前前置声明嵌套类型

class outer
{
public:
    class inner1{}; // 注意：嵌套类型在此处声明
};

class outer::inner1; // 可以（但多余），因为嵌套类型已作为外部类定义的一部分声明

int main()
{
    return 0;
}

虽然你可以在封闭类定义之后对嵌套类型进行前置声明，但由于封闭类已经包含了嵌套类型的声明，这样做是多余的。
