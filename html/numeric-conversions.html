10.3 — 数值转换

● 机器译文 课程 10.3 查看英文原文

在前一课（10.2 -- 浮点数和整型提升），我们介绍了数值提升，即特定较窄数值类型到较宽数值类型的转换（通常 int 或 double），以便能够高效处理。

C++ 支持另一类数值类型转换，称为 数值转换。这些数值转换涵盖了基本类型之间的其他类型转换。

关键提示

任何属于数值提升规则的类型转换（10.2 -- 浮点数和整型提升）称为数值提升，而非数值转换。

数值转换有五种基本类型。

  1. 将整型转换为任何其他整型（不包括整型提升）：
short s = 3; // 将 int 转换为 short
long l = 3; // 将 int 转换为 long
char ch = s; // 将 short 转换为 char
unsigned int u = 3; // 将 int 转换为 unsigned int
  1. 将浮点类型转换为任何其他浮点类型（不包括浮点提升）：
float f = 3.0; // 将 double 转换为 float
long double ld = 3.0; // 将 double 转换为 long double
  1. 将浮点类型转换为任何整型：
int i = 3.5; // 将 double 转换为 int
  1. 将整型转换为任何浮点类型：
double d = 3; // 将 int 转换为 double
  1. 将整型或浮点类型转换为 bool：
bool b1 = 3; // 将 int 转换为 bool
bool b2 = 3.0; // 将 double 转换为 bool

顺便说一句……

由于花括号初始化严格禁止某些类型的数值转换（下一课将详细介绍），本课使用复制初始化（没有此类限制）以保持示例简单。

安全和不安全的转换

与数值提升（始终保留值，因此“安全”）不同，许多数值转换是不安全的。 不安全转换 是指源类型的至少一个值无法转换为目标类型的相等值。

数值转换分为三个一般安全类别：

  1. 保留值的转换 是安全的数值转换，其中目标类型可以精确表示源类型的所有可能值。

例如， int 切换到 long 和 short 切换到 double 是安全的转换，因为源值始终可以转换为目标类型的相等值。

int main()
{
    int n { 5 };
    long l = n; // 可以，产生 long 值 5

    short s { 5 };
    double d = s; // 可以，产生 double 值 5.0

    return 0;
}

编译器通常不会对隐式的保留值转换发出警告。

使用保留值转换的值始终可以转换回源类型，得到与原始值等效的值：

#include <iostream>

int main()
{
    int n = static_cast<int>(static_cast<long>(3)); // 将 int 3 转换为 long 再转回来
    std::cout << n << '\n';                         // 打印 3

    char c = static_cast<char>(static_cast<double>('c')); // 将 'c' 转换为 double 再转回来
    std::cout << c << '\n';                               // 打印 'c'

    return 0;
}
  1. 重新解释转换 是不安全的数值转换，其中转换后的值可能与源值不同，但不会丢失数据。有符号/无符号转换属于此类。

例如，当将 signed int 到 unsigned int：

int main()
{
    int n1 { 5 };
    unsigned int u1 { n1 }; // 可以：将被转换为 unsigned int 5（值保留）

    int n2 { -5 };
    unsigned int u2 { n2 }; // 不好：将产生超出 signed int 范围的大整数

    return 0;
}

在 u1时，有符号 int 值 5 转换为无符号 int 值 5。因此，在这种情况下值被保留。

在 u2时，有符号 int 值 -5 转换为无符号 int。由于无符号 int 无法表示负数，结果将模环绕为一个超出有符号 int 范围的大整数值。在这种情况下值不被保留。

这种值变化通常是不希望的，并且常常会导致程序出现意外或实现定义的行为。

警告

中讨论了超出范围的值如何在有符号和无符号类型之间转换。即使重新解释转换是不安全的，大多数编译器默认情况下会禁用隐式有符号/无符号转换警告。

这是因为在现代 C++ 的某些领域（例如使用标准库数组时），有符号/无符号转换难以避免。而且实际上，大多数此类转换并不会导致值的变化。因此，启用此类警告可能会导致大量关于实际上没问题（淹没了合法警告）的有符号/无符号转换的虚假警告。

如果您选择禁用此类警告，请特别注意这些类型之间的意外转换（尤其是在将参数传递给接受相反符号参数的函数时）。

使用重新解释转换的值可以转换回源类型，得到与原始值等效的值（即使初始转换产生了超出源类型范围的值）。因此，重新解释转换在转换过程中不会丢失数据。

#include <iostream>

int main()
{
    int u = static_cast<int>(static_cast<unsigned int>(-5)); // 将 '-5' 转换为 unsigned 再转回来
    std::cout << u << '\n'; // 打印 -5
    
    return 0;
}

进阶读者

在 C++20 之前，将超出有符号值范围的无符号值转换为有符号值在技术上是实现定义的行为（因为允许有符号整数使用与无符号整数不同的二进制表示）。实际上，这在现代系统上不是问题。

C++20 现在要求有符号整数使用二进制补码。因此，转换规则已更改，使得上述转换现在被明确定义为重新解释转换（超出范围的转换将产生模环绕）。

请注意，虽然此类转换是明确定义的，但有符号算术溢出（当算术运算产生超出可存储范围的值时发生）仍然是未定义行为。

  1. 有损转换 是指在转换过程中可能丢失数据的不安全数值转换。

例如， double 切换到 int 是一种可能导致数据丢失的转换：

int i = 3.0; // 可以：将被转换为 int 值 3（值保留）
int j = 3.5; // 数据丢失：将被转换为 int 值 3（小数部分 0.5 丢失）

从 double 切换到 float 转换也可能导致数据丢失：

float f = 1.2;        // 可以：将被转换为 float 值 1.2（值保留）
float g = 1.23456789; // 数据丢失：将被转换为 float 1.23457（精度丢失）

将丢失数据的值转换回源类型将得到一个与原始值不同的值：

#include <iostream>

int main()
{
    double d { static_cast<double>(static_cast<int>(3.5)) }; // 将 double 3.5 转换为 int 再转回来
    std::cout << d << '\n'; // 打印 3

    double d2 { static_cast<double>(static_cast<float>(1.23456789)) }; // 将 double 1.23456789 转换为 float 再转回来
    std::cout << d2 << '\n'; // 打印 1.23457

    return 0;
}

例如，如果 double 值 3.5 会转换为 int 值 3，小数部分 0.5 丢失了。当 3 被转换回 double, 时，结果是 3.0，而不是 3.5。

当隐式有损转换在运行时发生时，编译器通常会发出警告（在某些情况下是错误）。

警告

某些转换可能因平台不同而属于不同类别。

例如， int 切换到 double 通常是安全转换，因为 int 通常是4字节，而 double 通常是8字节，在这样的系统上，所有可能的 int 值都可以表示为 double。然而，有些架构中 int 和 double 都是8字节。在这样的架构上， int 切换到 double 是一种有损转换！

我们可以通过将 long long 值（必须至少为64位）转换为 double 再转换回来来演示这一点：

#include <iostream>

int main()
{
    std::cout << static_cast<long long>(static_cast<double>(10000000000000001LL));

    return 0;
}

这会打印：

10000000000000000

注意，我们的最后一位数字丢失了！

应尽可能避免不安全转换。然而，这并不总是可能的。当使用不安全转换时，最常见的情况是：

  • 我们可以将要转换的值限制为那些可以转换为相等值的值。例如， int 可以安全地转换为 unsigned int ，当我们能保证 int 为非负时。
  • 我们不介意丢失一些数据，因为它不相关。例如，将 int 转换为 bool 转换为 int 值为 0 会导致数据丢失，但我们通常可以接受，因为我们只是检查

从较大的整型或浮点类型转换为同一系列中较小的类型，只要值在较小类型的范围内，通常可以正常工作。例如： float 对于浮点值，由于较小类型的精度损失，可能会发生一些舍入。例如： double：

0.123456791
  • 从整数转换为浮点数通常只要值在浮点类型的范围内就能正常工作。例如：
    int i{ 10 };
    float f = i;
    std::cout << f << '\n';

这会输出预期的结果：

10
  • 从浮点数转换为整数只要值在整数的范围内就能正常工作，但任何小数部分都会丢失。例如：
    int i = 3.5;
    std::cout << i << '\n';

在这个例子中，小数部分（.5）丢失了，得到以下结果：

3

虽然数值转换规则看起来可能令人害怕，但实际上，如果你试图做一些危险的操作（除了一些有符号/无符号转换），编译器通常会发出警告。
