21.11 — 重载类型转换

● 机器译文 课程 21.11 查看英文原文

在课程 10.6 -- 显式类型转换（强制转换）和 static_cast中，你学习了C++允许你将一种数据类型转换为另一种。下面的例子展示了一个int被转换为double：

int n{ 5 };
auto d{ static_cast<double>(n) }; // int 转换为 double

C++已经知道如何在内置数据类型之间进行转换。然而，默认情况下，C++不知道如何转换我们自定义的类。

重载类型转换

这就是重载类型转换运算符发挥作用的地方。这样的类型转换可以显式使用（通过强制转换）或由编译器隐式使用，以根据需要执行转换。

让我们展示如何重载类型转换来定义从 Cents 切换到 int：

class Cents
{
private:
    int m_cents{};
public:
    Cents(int cents=0)
        : m_cents{ cents }
    {
    }

    // 重载的 int 类型转换
    operator int() const { return m_cents; }

    int getCents() const { return m_cents; }
    void setCents(int cents) { m_cents = cents; }
};

的转换。为此，我们编写了一个新的重载运算符，名为 operator int()。注意，在operator和要转换的类型之间有一个空格。

这里有几件事值得注意：

  • 重载的类型转换必须是非静态成员，并且应该是 const ，以便它们可以与const对象一起使用。
  • 重载的类型转换没有显式参数，因为无法向它们传递显式参数。它们仍然有一个隐藏的 *this 参数，指向隐式对象（即要转换的对象）。
  • 重载的类型转换不声明返回类型。转换的名称（例如 int）被用作返回类型，因为这是唯一允许的返回类型。这避免了声明中的冗余。

现在在我们的例子中，我们可以调用 printInt() 加上前缀，像这样：

#include <iostream>

int main()
{
    Cents cents{ 7 };
    printInt(cents); // 打印 7

    std::cout << '\n';

    return 0;
}

编译器首先会注意到函数 printInt() 有一个 int 参数。然后它会注意到变量 cents 不是一个 int。最后，它会查看我们是否提供了将 Cents 转换为 int转换为 operator int() 的方法。由于我们提供了，它将调用我们的 int函数，该函数返回一个 int ，并且返回的 printInt()。

何时使用转换构造函数与重载类型转换

  • 重载类型转换和转换构造函数执行类似的功能：
  • 转换构造函数是类类型 B 的成员函数，它定义了如何从 A 创建 B。

重载类型转换是类类型 A 的成员函数，它定义了如何将 A 转换为 B。

在这两种情况下，我们从 A 开始，最终得到 B。两者之间的主要区别在于 A 还是 B 拥有转换方式的所有权。

由于两种方式都需要定义成员函数，它们只能用于可修改的类类型。如果 A 不是可修改的类类型，则不能使用重载类型转换。如果 B 不是可修改的类类型，则不能使用转换构造函数。如果两者都不是可修改的类类型，则需要使用非成员转换函数。

一般来说，转换构造函数应优先于重载类型转换。在其他条件相同的情况下，让类类型自己负责构造，而不是依赖另一个类来创建和初始化它，这样更清晰。

最佳实践

尽可能优先使用转换构造函数，避免重载类型转换。

有少数情况应该使用重载类型转换：

  • 当提供到基本类型的转换时（因为你不能为这些类型定义构造函数）。最传统的是，用于提供到 bool 的转换，适用于在条件语句中使用对象有意义的情况。
  • 当转换返回引用或 const 引用时。
  • 当提供到你不能添加成员的类型的转换时（例如，到 std::vector的转换，因为你也不能为这些类型定义构造函数）。
  • 当你不希望被构造的类型知道被转换的类型时。这有助于避免循环依赖。

关于最后一点的例子， std::string 有一个构造函数来创建 std::string 是一个 std::string_view。这意味着 <string> 必须包含 <string_view>。如果 std::string_view 有一个构造函数来创建 std::string_view 是一个 std::string，那么 <string_view> 将需要包含 <string>，这会导致头文件之间的循环依赖。

相反， std::string 有一个重载类型转换来处理从 std::string 切换到 std::string_view 的转换（这没问题，因为它已经包含了 <string_view>)。 std::string_view 完全不知道 std::string ，因此不需要包含 <string>。这样，循环依赖就被避免了。

当转换构造函数和重载类型转换都为同一转换定义时，两者都会在重载解析中被考虑。根据重载类型转换是否为 const、被转换的对象是否为 const，以及使用的转换或初始化类型（拷贝与直接），可能会选择其中一个函数（可能导致类型转换被选为优先于转换构造函数），或者结果可能不明确（导致编译错误）。因此，你应该避免同时定义重载类型转换和转换构造函数来服务于同一转换。

最佳实践

当你需要定义如何将类型 A 转换为类型 B 时：

  • 如果 B 是你可以修改的类类型，优先使用转换构造函数从 A 创建 B。
  • 否则，如果 A 是你可以修改的类类型，使用重载类型转换将 A 转换为 B。
  • 否则，使用非成员函数将 A 转换为 B。
