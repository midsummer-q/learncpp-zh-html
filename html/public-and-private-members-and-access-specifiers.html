14.5 — 公有和私有成员及访问说明符

● 机器译文 课程 14.5 查看英文原文

假设你在一个清爽的秋日里，一边吃着卷饼一边走在街上。你想找个地方坐下，于是环顾四周。左边是一个公园，有修剪过的草坪和遮荫树，几条不太舒服的长椅，附近游乐场上还有尖叫的孩子。右边是一处陌生人的住宅。透过窗户，你看到一把舒适的躺椅和噼啪作响的壁炉。

你重重地叹了口气，选择了公园。

你做出选择的关键因素是公园是公共空间，而住宅是私有的。你（和其他任何人）都可以自由进入公共空间。但只有住宅的成员（或获得明确许可进入的人）才被允许进入私有住宅。

成员访问

类似的概念也适用于类类型的成员。类类型的每个成员都有一个称为 访问级别 的属性，它决定了谁可以访问该成员。

C++ 有三种不同的访问级别： 公有， 私有、和 受保护。在本课中，我们将介绍两种常用的访问级别：公有和私有。

相关内容

我们将在关于继承的章节中讨论受保护的访问级别（课程 24.5 -- 继承和访问说明符)。

每当访问一个成员时，编译器会检查该成员的访问级别是否允许访问。如果不允许访问，编译器将生成编译错误。这种访问级别系统有时非正式地称为 访问控制。

结构体的成员默认是公有的

具有 公有 访问级别的成员称为 公有成员。 公有成员 是类类型的成员，它们对如何被访问没有任何限制。就像我们开头比喻中的公园一样，公有成员可以被任何人访问（只要它们在作用域内）。

公有成员可以被同一类的其他成员访问。值得注意的是，公有成员也可以被 公众访问，公众指的是存在于 函数 给定类类型的成员之外的代码。 公众 的例子包括非成员函数，以及其他类类型的成员。

关键提示

结构体的成员默认是公有的。公有成员可以被类类型的其他成员以及公众访问。

术语“公众”用于指代存在于给定类类型的成员之外的代码。这包括非成员函数，以及其他类类型的成员。

默认情况下，结构体的所有成员都是公有成员。

考虑以下结构体：

#include <iostream>

struct Date
{
    // struct 成员默认为 public，任何人都可以访问
    int year {};       // 默认为 public
    int month {};      // 默认为 public
    int day {};        // 默认为 public

    void print() const // 默认为 public
    {
        // public 成员可以在类类型的成员函数中访问
        std::cout << year << '/' << month << '/' << day;
    }
};

// 非成员函数 main 属于“公众”
int main()
{
    Date today { 2020, 10, 14 }; // 聚合初始化我们的结构体

    // public 成员可以被公众访问
    today.day = 16; // 可以：day 成员是 public
    today.print();  // 可以：print() 成员函数是 public

    return 0;
}

在这个例子中，成员在三个地方被访问：

  • 在成员函数 print()内部，我们访问隐式对象的 year， month、和 day 成员。
  • 在 main()中，我们直接访问 today.day 来设置其值。
  • 在 main()中，我们调用成员函数 today.print()。

所有这三种访问都是允许的，因为公有成员可以从任何地方访问。

因为 main() 不是 Date的成员，它被认为是 公众的一部分。然而，因为 公众 可以访问公有成员， main() 可以直接访问 Date 的成员（包括对 today.print())。

具有 私有 访问级别的成员称为 类的成员默认是私有的。 私有成员 私有成员是类类型的成员，只能被同一个类的其他成员访问。

考虑以下示例，它与上面的示例几乎相同：

#include <iostream>

class Date // 现在使用 class 而不是 struct
{
    // class 成员默认为 private，只能被其他成员访问
    int m_year {};     // 默认为 private
    int m_month {};    // 默认为 private
    int m_day {};      // 默认为 private

    void print() const // 默认为 private
    {
        // private 成员可以在成员函数中访问
        std::cout << m_year << '/' << m_month << '/' << m_day;
    }
};

int main()
{
    Date today { 2020, 10, 14 }; // 编译错误：不能再使用聚合初始化

    // private 成员不能被公众访问
    today.m_day = 16; // 编译错误：m_day 成员是 private
    today.print();    // 编译错误：print() 成员函数是 private

    return 0;
}

在这个示例中，成员在三个相同的位置被访问：

  • 在成员函数 print()内部，我们访问隐式对象的 m_year， m_month、和 m_day 成员。
  • 在 main()中，我们直接访问 today.m_day 来设置其值。
  • 在 main()中，我们调用成员函数 today.print()。

然而，如果你编译这个程序，你会注意到生成了三个编译错误。

在 main()内部，语句 today.m_day = 16 和 today.print() 现在都会生成编译错误。这是因为 main() 是公开的一部分，而公开部分不允许直接访问私有成员。

在 print()，对成员 m_year， m_month、和 m_day 的访问是允许的。这是因为 print() 是类的一个成员，而类的成员允许访问私有成员。

那么第三个编译错误来自哪里？也许令人惊讶的是， today 的初始化现在导致了编译错误。在课程 13.8 -- 结构体聚合初始化中，我们注意到聚合体不能有“私有或受保护的非静态数据成员”。我们的 Date 类有私有数据成员（因为类的成员默认是私有的），所以我们的 Date 类不符合聚合体的条件。因此，我们不能再使用聚合初始化来初始化它。

我们将在接下来的课程 14.9 -- 构造函数简介。

命名你的私有成员变量

在C++中，常见的约定是以“m_”前缀命名私有数据成员。这样做有几个重要的原因。

// 某个成员函数，将私有成员 m_name 设置为参数 name 的值
void setName(std::string_view name)
{
    m_name = name;
}

考虑以“m_”前缀命名你的私有数据成员，以帮助将它们与局部变量、函数参数和成员函数的名称区分开来。

如果需要，类的公开成员也可以遵循这个约定。然而，结构体的公开成员通常不使用这个前缀，因为结构体通常没有很多成员函数（如果有的话）。

然而，我们可以通过使用 访问说明符来显式设置成员的访问级别。访问说明符设置了 所有后续成员 的访问级别。C++ 提供了三个访问说明符： public:， private:、和 protected:。

在下面的例子中，我们同时使用了 public: 访问说明符来确保 print() 成员函数可以被公开使用，以及 private: 访问说明符来使我们的数据成员私有。

class Date
{
// 此处定义的任何成员默认为 private

public: // 这里是我们的 public 访问说明符

    void print() const // 由于上面的 public: 说明符，此处为 public
    {
        // 成员可以访问其他 private 成员
        std::cout << m_year << '/' << m_month << '/' << m_day;
    }

private: // 这里是我们的 private 访问说明符 

    int m_year { 2020 };  // 由于上面的 private: 说明符，此处为 private
    int m_month { 14 }; // 由于上面的 private: 说明符，此处为 private
    int m_day { 10 };   // 由于上面的 private: 说明符，此处为 private
};

int main()
{
    Date d{};
    d.print();  // 可以，main() 允许访问 public 成员

    return 0;
}

这个例子可以编译。因为 print() 由于 public: 访问说明符而成为公有成员， main() （属于公有部分）被允许访问它。

由于我们有私有成员，我们不能聚合初始化 d。对于这个例子，我们改用默认成员初始化（作为临时解决方法）。

由于类默认是私有访问，你可以省略开头的 private: 访问说明符：

class Foo
{
// 此处不需要 private 访问说明符，因为类默认成员为 private
    int m_something {};  // 默认为 private
};

然而，由于类和结构体有不同的默认访问级别，许多开发者更喜欢显式指定：

class Foo
{
private: // 冗余，但明确表明后续内容为 private
    int m_something {};  // 默认为 private
};

虽然这在技术上是冗余的，但使用显式的 private: 说明符可以清楚地表明后续成员是私有的，而无需根据 Foo 是定义为类还是结构体来推断默认访问级别。

访问级别总结

以下是不同访问级别的快速总结表：

访问级别访问说明符成员访问派生类访问公有访问
公有public:是是是
受保护protected:是是否
私有private:是否否

类类型允许以任意顺序使用任意数量的访问说明符，并且可以重复使用（例如，你可以有一些公有成员，然后一些私有成员，然后再一些公有成员）。

大多数类会同时使用私有和公有访问说明符来管理不同的成员。我们将在下一节看到一个例子。

结构体和类的访问级别最佳实践

现在我们已经介绍了访问级别，让我们讨论如何使用它们。

结构体应避免使用访问说明符，这意味着所有结构体成员默认都是公有的。我们希望结构体是聚合体，而聚合体只能有公有成员。使用 public: 访问说明符与默认值重复，使用 private: 或 protected: 会使结构体成为非聚合类型。

类通常应只有私有（或受保护）数据成员（通过使用默认的私有访问级别，或 private: （或 protected:）访问说明符）。我们将在下一课中讨论这样做的理由。 14.6 -- 访问函数。

类通常具有公有成员函数（这样这些成员函数可以在对象创建后被公众使用）。然而，偶尔成员函数会被设为私有（或受保护），如果它们不打算被公众使用的话。

最佳实践

类通常应将成员变量设为私有（或受保护），而成员函数设为公有。

结构体通常应避免使用访问说明符（所有成员默认公有）。

访问级别基于类而非对象

C++ 访问级别的一个常被忽略或误解的细微之处是：对成员的访问是基于类定义的，而不是基于对象。

你已经知道成员函数可以直接访问（隐式对象的）私有成员。然而，由于访问级别是基于类而非对象，成员函数也可以直接访问作用域内任何其他同类对象的私有成员。

让我们用一个例子来说明这一点：

#include <iostream>
#include <string>
#include <string_view>

class Person
{
private:
    std::string m_name{};

public:
    void kisses(const Person& p) const
    {
        std::cout << m_name << " kisses " << p.m_name << '\n';
    }

    void setName(std::string_view name)
    {
        m_name = name;
    }
};

int main()
{
    Person joe;
    joe.setName("Joe");
    
    Person kate;
    kate.setName("Kate");

    joe.kisses(kate);

    return 0;
}

这会打印：

Joe kisses Kate

这里有几件事需要注意。

首先， m_name 已被设为私有，因此只能由 Person 类的成员访问（公众不能访问）。

其次，由于我们的类有私有成员，它不是聚合类型，我们不能使用聚合初始化来初始化 Person 对象。作为变通方法（直到我们介绍这个问题的正确解决方案），我们创建了一个名为 setName() 的公有成员函数，允许我们为 Person 对象赋值一个名字。

第三，因为 kisses() 是一个成员函数，它可以直接访问私有成员 m_name。然而，你可能会惊讶地发现它也可以直接访问 p.m_name！这是因为 p 我们还调用了 Person int& kisses() 可以访问作用域内任何 Person 对象的私有成员！

我们将在运算符重载章节中看到更多利用这一点的例子。

结构体和类的技术及实际区别

既然我们已经介绍了访问级别，终于可以讨论结构体和类的技术区别了。准备好了吗？

类默认其成员为私有，而结构体默认其成员为公有。

作者注

严格来说，还有一个细微的区别——结构体从其他类类型公有继承，而类私有继承。我们将在继承章节中介绍这意味着什么，但这一点实际上无关紧要，因为你不应该依赖继承的默认方式。

在实践中，我们以不同的方式使用结构体和类。

作为经验法则，当以下所有条件都成立时使用结构体：

  • 你有一个简单的数据集合，不需要限制访问。
  • 聚合初始化就足够了。
  • 你没有类不变量、设置需求或清理需求。

一些可能使用结构体的例子：constexpr 全局程序数据、点结构体（一个简单的 int 成员集合，设为私有没有好处）、用于从函数返回一组数据的结构体。

否则使用类。

我们希望结构体是聚合类型。因此，如果你使用任何使结构体成为非聚合类型的特性，你可能应该改用类（并遵循类的所有最佳实践）。

#include <iostream>

class Point3d
{
private:
	int m_x {};
	int m_y {};
	int m_z {};

public:
	void setValues(int x, int y, int z)
	{
		m_x = x;
		m_y = y;
		m_z = z;
	}

	void print() const
	{
		std::cout << '<' << m_x << ", " << m_y << ", " << m_z << '>';
	}

	// 我们可以利用访问控制基于每个类工作的特性
	// 来直接访问 Point3d 参数 p 的私有成员

	}
};

int main()
{

	point1.setValues(1, 2, 3);

	Point3d point2{};
	point2.setValues(1, 2, 3);

	std::cout << "point 1 and point 2 are" << (point1.isEqual(point2) ? "" : " not") << " equal\n";

	Point3d point3{};
	point3.setValues(3, 4, 5);

	std::cout << "point 1 and point 3 are" << (point1.isEqual(point3) ? "" : " not") << " equal\n";
