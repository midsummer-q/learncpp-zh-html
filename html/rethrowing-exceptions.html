27.6 — 重新抛出异常

● 机器译文 课程 27.6 查看英文原文

有时你可能会遇到这样的情况：你想捕获一个异常，但不想（或没有能力）在捕获它的地方完全处理它。当你想要记录错误，但将问题传递给调用者实际处理时，这很常见。

当一个函数可以使用返回码时，这很简单。考虑以下示例：

Database* createDatabase(std::string filename)
{
    Database* d {};

    try
    {
        d = new Database{};
        d->open(filename); // 假设失败时抛出 int 异常
        return d;
    }
    catch (int exception)
    {
        // 数据库创建失败
        delete d;
        // 将错误写入某个全局日志文件
        g_log.logError("Creation of Database failed");
    }

    return nullptr;
}

在上面的代码片段中，函数负责创建 Database 对象，打开数据库，并返回 Database 对象。如果出现问题（例如传入了错误的文件名），异常处理程序会记录错误，然后合理地返回一个空指针。

现在考虑以下函数：

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // 失败时抛出 int 异常
    }
    catch (int exception)
    {
        // 将错误写入某个全局日志文件
        g_log.logError("getIntValueFromDatabase failed");

        // 然而，我们实际上并没有处理这个错误
        // 那么我们在这里该怎么办？
    }
}

如果这个函数成功，它会返回一个整数值——任何整数值都可能是有效值。

但是，如果 getIntValue() 出现问题呢？在这种情况下，getIntValue() 会抛出一个整数异常，该异常会被 getIntValueFromDatabase() 中的 catch 块捕获，并记录错误。但随后我们如何告诉 getIntValueFromDatabase() 的调用者出了问题？与上面的示例不同，这里没有一个好的返回码可以使用（因为任何整数返回值都可能是有效的）。

抛出新的异常

一个明显的解决方案是抛出一个新的异常。

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // 失败时抛出 int 异常
    }
    catch (int exception)
    {
        // 将错误写入某个全局日志文件
        g_log.logError("getIntValueFromDatabase failed");

        // 向上抛出 char 异常 'q' 由调用者处理
        throw 'q'; 
    }
}

在上面的示例中，程序捕获了来自 getIntValue() 的 int 异常，记录了错误，然后抛出一个带有 char 值 'q' 的新异常。虽然从 catch 块中抛出异常可能看起来很奇怪，但这是允许的。记住，只有 try 块内抛出的异常才可能被捕获。这意味着在 catch 块内抛出的异常不会被它所在的 catch 块捕获。相反，它会沿着堆栈向上传播到调用者。

从 catch 块抛出的异常可以是任何类型——它不必与刚刚捕获的异常类型相同。

重新抛出异常（错误的方式）

另一种选择是重新抛出同一个异常。一种方法如下：

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // 失败时抛出 int 异常
    }
    catch (int exception)
    {
        // 将错误写入某个全局日志文件
        g_log.logError("getIntValueFromDatabase failed");

        throw exception;
    }
}

虽然这可行，但这种方法有几个缺点。首先，它不会抛出与捕获的完全相同的异常——而是抛出一个从变量 exception 复制初始化的副本。虽然编译器可以自由地省略复制，但可能不会，因此这可能效率较低。

但更重要的是，考虑以下情况会发生什么：

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // 失败时抛出 Derived 异常
    }
    catch (Base& exception)
    {
        // 将错误写入某个全局日志文件
        g_log.logError("getIntValueFromDatabase failed");

        throw exception; // 危险：这抛出一个 Base 对象，而不是 Derived 对象
    }
}

在这种情况下，getIntValue() 抛出一个 Derived 对象，但 catch 块捕获的是 Base 引用。这没问题，因为我们可以有 Base 引用指向 Derived 对象。然而，当我们抛出异常时，抛出的异常是从变量 exception 复制初始化的。变量 exception 的类型是 Base，因此复制初始化的异常也是 Base 类型（而不是 Derived！）。换句话说，我们的 Derived 对象被切片了！

你可以在以下程序中看到这一点：

#include <iostream>
class Base
{
public:
    Base() {}
    virtual void print() { std::cout << "Base"; }
};

class Derived: public Base
{
public:
    Derived() {}
    void print() override { std::cout << "Derived"; }
};

int main()
{
    try
    {
        try
        {
            throw Derived{};
        }
        catch (Base& b)
        {
            std::cout << "Caught Base b, which is actually a ";
            b.print();
            std::cout << '\n';
            throw b; // Derived 对象在这里被切片
        }
    }
    catch (Base& b)
    {
        std::cout << "Caught Base b, which is actually a ";
        b.print();
        std::cout << '\n';
    }

    return 0;
}

这会打印：

Caught Base b, which is actually a Derived
Caught Base b, which is actually a Base

第二行显示 Base 实际上是 Base 而不是 Derived，这一事实证明了 Derived 对象被切片了。

重新抛出异常（正确的方式）

幸运的是，C++ 提供了一种重新抛出刚刚捕获的完全相同异常的方法。为此，只需在 catch 块中使用 throw 关键字（不带任何关联变量），如下所示：

#include <iostream>
class Base
{
public:
    Base() {}
    virtual void print() { std::cout << "Base"; }
};

class Derived: public Base
{
public:
    Derived() {}
    void print() override { std::cout << "Derived"; }
};

int main()
{
    try
    {
        try
        {
            throw Derived{};
        }
        catch (Base& b)
        {
            std::cout << "Caught Base b, which is actually a ";
            b.print();
            std::cout << '\n';
            throw; // 注意：我们现在在这里重新抛出对象
        }
    }
    catch (Base& b)
    {
        std::cout << "Caught Base b, which is actually a ";
        b.print();
        std::cout << '\n';
    }

    return 0;
}

这会打印：

Caught Base b, which is actually a Derived
Caught Base b, which is actually a Derived

这个看似没有抛出任何东西的 throw 关键字实际上重新抛出了刚刚捕获的完全相同异常。不会进行复制，因此我们不必担心性能损耗或切片。

如果需要重新抛出异常，应优先使用此方法而不是其他替代方法。

规则

当重新抛出同一个异常时，单独使用 throw 关键字
