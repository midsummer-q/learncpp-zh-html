16.5 — 返回 std::vector，以及移动语义简介

● 机器译文 课程 16.5 查看英文原文

当我们需要将 std::vector 传递给函数时，我们通过（const）引用传递，以避免对数组数据进行昂贵的复制。

因此，你可能会惊讶地发现，返回 std::vector 按值的函数调用或运算符。

什么？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？？

复制语义

考虑以下程序：

#include <iostream>
#include <vector>

int main()
{
    std::vector arr1 { 1, 2, 3, 4, 5 }; // // 将 { 1, 2, 3, 4, 5 } 拷贝到 arr1
    std::vector arr2 { arr1 };          // // 将 arr1 拷贝到 arr2

    arr1[0] = 6; // // 我们可以继续使用 arr1
    arr2[0] = 7; // // 并且我们可以继续使用 arr2

    std::cout << arr1[0] << arr2[0] << '\n';

    return 0;
}

当 arr2 用 arr1，会调用 std::vector 的复制构造函数，该函数复制 arr1 到 arr2。

在这种情况下，进行复制是唯一合理的做法，因为我们需要 arr1 和 arr2 独立存在。这个例子最终进行了两次复制，每次初始化一次。

术语 复制语义 指的是决定如何复制对象的规则。当我们说一个类型支持复制语义时，意味着该类型的对象是可复制的，因为已经定义了进行此类复制的规则。当我们说复制语义被调用时，意味着我们做了某些会导致对象复制的事情。

对于类类型，复制语义通常通过复制构造函数（和复制赋值运算符）实现，它定义了如何复制该类型的对象。通常这会导致类类型的每个数据成员都被复制。在前面的例子中，语句 std::vector arr2 { arr1 }; 调用了复制语义，导致调用 std::vector的复制构造函数，然后复制 arr1 到 arr2中。最终结果是 arr1 等价于（但独立于） arr2。

当复制语义不是最优时

现在考虑这个相关的例子：

#include <iostream>
#include <vector>

std::vector<int> generate() // 按值返回
{
    // // 我们故意使用一个命名对象，这样强制拷贝省略不适用
    std::vector arr1 { 1, 2, 3, 4, 5 }; // // 将 { 1, 2, 3, 4, 5 } 拷贝到 arr1
    return arr1;
}

int main()
{
    std::vector arr2 { generate() }; // // generate() 的返回值在表达式结束时消亡

    // // 这里没有办法使用 generate() 的返回值
    arr2[0] = 7; // // 我们只能访问 arr2

    std::cout << arr2[0] << '\n';

    return 0;
}

当 arr2 这次被初始化时，它是用从函数 generate()返回的临时对象初始化的。与之前的情况不同，之前的初始化器是一个可以在后续语句中使用的左值，而在这个例子中，临时对象是一个右值，将在初始化表达式结束时被销毁。临时对象在那之后无法再使用。因为临时对象（及其数据）将在表达式结束时被销毁，我们需要某种方式将数据从临时对象中取出并放入 arr2。

通常的做法与前面的例子相同：使用复制语义并进行可能昂贵的复制。这样 arr2 获得自己的数据副本，即使在临时对象（及其数据）被销毁后也能使用。

然而，这个例子与之前例子的不同之处在于，临时对象无论如何都会被销毁。初始化完成后，临时对象不再需要它的数据（这就是为什么我们可以销毁它）。我们不需要同时存在两组数据。在这种情况下，进行可能昂贵的复制然后销毁原始数据是次优的。

移动语义简介

相反，如果有一种方法可以让 arr2 “窃取”临时对象的数据而不是复制它呢？ arr2 将成为数据的新所有者，并且不需要复制数据。当数据的所有权从一个对象转移到另一个对象时，我们说数据被 移动了。这种移动的成本通常微不足道（通常只是两三个指针赋值，比复制数组数据快得多！）。

额外的好处是，当临时对象在表达式结束时被销毁时，它不再有任何数据需要销毁，因此我们也不必支付销毁成本。

这就是 移动语义的本质，它指的是决定如何将数据从一个对象移动到另一个对象的规则。当调用移动语义时，任何可以移动的数据成员都会被移动，任何不能移动的数据成员则被复制。移动数据而不是复制数据的能力可以使移动语义比复制语义更高效，尤其是当我们可以用廉价的移动替换昂贵的复制时。

关键提示

移动语义是一种优化，允许我们在某些情况下，以低成本将某些数据成员的所有权从一个对象转移到另一个对象（而不是进行更昂贵的复制）。

不能移动的数据成员则被复制。

如何调用移动语义

通常，当一个对象用同类型的对象初始化（或赋值）时，将使用复制语义（假设复制没有被省略）。

相关内容

我们在课程 14.15 -- 类初始化与复制省略。

中介绍了复制省略。然而，当以下所有条件都成立时，将改为调用移动语义：

  • 对象的类型支持移动语义。
  • 该对象正在被同类型的右值（临时）对象初始化（或赋值）。
  • 移动未被省略。

坏消息是：支持移动语义的类型并不多。然而， std::vector 和 std::string 两者都支持！

我们将在 第 22 章中更详细地探讨移动语义的工作原理。目前，了解什么是移动语义以及哪些类型支持移动就足够了。

我们可以返回支持移动的类型，比如 std::vector 按值传递

因为按值返回会返回一个右值，如果返回的类型支持移动语义，那么返回值可以被移动而不是复制到目标对象中。这使得按值返回对这些类型来说极其廉价！

关键提示

我们可以按值返回支持移动的类型（如 std::vector 和 std::string）。这些类型会廉价地移动它们的值，而不是进行昂贵的复制。

这类类型仍应通过 const 引用传递。

等等，等等。昂贵复制的类型不应该按值传递，但如果它们支持移动，就可以按值返回？

正确。

以下讨论是可选的，但可能有助于你理解为什么是这样。

在 C++ 中，我们最常做的事情之一是将一个值传递给某个函数，并得到另一个值返回。当传递的值是类类型时，这个过程涉及 4 个步骤：

  1. 构造要传递的值。
  2. 实际将值传递给函数。
  3. 构造要返回的值。
  4. 实际将返回值传回调用者。

下面是一个使用 std::vector：

#include <iostream>
#include <vector>

std::vector<int> doSomething(std::vector<int> v2)
{
    std::vector v3 { v2[0] + v2[0] }; // // 3 -- 构造要返回给调用者的值
    return v3; // // 4 -- 实际返回值
}

int main()
{
    std::vector v1 { 5 }; // // 1 -- 构造要传递给函数的值
    std::cout << doSomething(v1)[0] << '\n'; // // 2 -- 实际传递值

    std::cout << v1[0] << '\n';

    return 0;
}

的上述过程的例子。首先，假设 std::vector 不支持移动。在这种情况下，上述程序进行了 4 次复制：

  1. 构造要传递的值将初始化列表复制到 v1
  2. 实际将值传递给函数将实参 v1 复制到函数形参 v2。
  3. 构造要返回的值将初始化器复制到 v3
  4. 实际将值返回给调用者将 v3 复制回调用者。

现在我们来讨论如何优化上述过程。我们有很多工具可用：按引用或地址传递、省略、移动语义和输出参数。

我们无法优化复制 1 和 3。我们需要一个 std::vector 传递给函数，也需要一个 std::vector 返回——这些对象必须被构造。 std::vector 是其数据的所有者，因此它必然复制其初始化器。

我们可以影响的是复制 2 和 4。

复制 2 是因为我们从调用者按值传递给被调用函数。我们还有其他选择吗？

  • 我们可以按引用或地址传递吗？可以。我们保证实参在整个函数调用期间存在——调用者不必担心传递的对象意外超出作用域。
  • 这个复制可以被省略吗？不能。省略只在我们进行冗余复制或移动时有效。这里没有冗余的复制或移动。
  • 我们可以在这里使用输出参数吗？不能。我们是将值传递给函数，而不是从函数获取值。
  • 我们可以在这里使用移动语义吗？不能。实参是左值。如果我们从 v1 切换到 v2， v1 中移动数据，那么 v1[0] 会导致未定义行为。

显然，按 const 引用传递是我们这里的最佳选择，因为它避免了拷贝，避免了空指针问题，并且同时适用于左值和右值参数。

拷贝 4 是因为我们通过值从被调用函数返回给调用者。我们这里还有其他什么选择？

  • 我们可以通过引用或地址返回吗？不行。我们返回的对象是在函数内部创建的局部变量，当函数返回时它会被销毁。返回引用或指针会导致调用者收到悬空指针或引用。
  • 这个拷贝可以被省略吗？可以，有可能。如果编译器足够聪明，它会意识到我们在被调用函数的作用域内构造了一个对象并返回它。通过重写代码（在 as-if 规则下），使得 v3 在调用者的作用域内构造，我们可以避免返回时本应发生的拷贝。然而，我们依赖于编译器意识到它可以这样做，所以这并不保证。
  • 我们可以在这里使用输出参数吗？可以。与其构造 v3 作为局部变量，我们可以在调用者的作用域内构造一个空的 std::vector 对象，并通过非 const 引用将其传递给函数。函数可以用数据填充这个参数。当函数返回时，这个对象仍然存在。这避免了拷贝，但也有一些显著的缺点和限制：丑陋的调用语义，不适用于不支持赋值的对象，并且编写能同时处理左值和右值参数的此类函数具有挑战性。
  • 我们可以在这里使用移动语义吗？可以。 v3 在函数返回时将被销毁，所以与其拷贝 v3 回调用者，我们可以使用移动语义将其数据移动到调用者，从而避免拷贝。

省略是这里的最佳选择，但它是否发生不在我们的控制范围内。对于支持移动的类型，次优选择是移动语义，可以在编译器没有省略拷贝的情况下使用。对于支持移动的类型，按值返回时会自动调用移动语义。

总结一下，对于支持移动的类型，我们更倾向于按 const 引用传递，并按值返回。
