7.10 — 在多个文件间共享全局常量（使用内联变量）

● 机器译文 课程 7.10 查看英文原文

在某些应用中，某些符号常量可能需要在整个代码中使用（而不仅仅在一个位置）。这些常量可以包括不变的物理或数学常量（例如 pi 或阿伏伽德罗常数），或特定于应用程序的“调优”值（例如摩擦系数或重力系数）。与其在每个需要这些常量的文件中重新定义它们（违反“不要重复自己”规则），不如在一个中心位置声明一次，然后在需要的地方使用。这样，如果需要更改它们，只需在一个地方更改，这些更改就可以传播出去。

本课讨论最常见的实现方法。

作为内部变量的全局常量

在 C++17 之前，以下是最简单且最常见的解决方案：

  1. 创建一个头文件来保存这些常量
  2. 在这个头文件中，定义一个命名空间（在课程 7.2 -- 用户定义命名空间和作用域解析运算符)
  3. 将所有常量添加到命名空间中（确保它们是 constexpr)
  4. 在需要的地方 #include 该头文件

例如：

constants.h：

#ifndef CONSTANTS_H
#define CONSTANTS_H

// 定义自己的命名空间来保存常量
namespace constants
{
    // 全局常量默认具有内部链接
    constexpr double pi { 3.14159 };
    constexpr double avogadro { 6.0221413e23 };
    constexpr double myGravity { 9.2 }; // m/s^2 -- 这个星球上的重力很轻
    // ... 其他相关常量
}
#endif

然后使用作用域解析运算符 (::)，左边是命名空间名称，右边是变量名，以在 .cpp 文件中访问常量：

main.cpp:

#include "constants.h" // include a copy of each constant in this file

#include <iostream>

int main()
{
    std::cout << "Enter a radius: ";
    double radius{};
    std::cin >> radius;

    std::cout << "The circumference is: " << 2 * radius * constants::pi << '\n';

    return 0;
}

当这个头文件被 #include 到 .cpp 文件中时，头文件中定义的每个变量都会在包含点被复制到该代码文件中。由于这些变量位于函数外部，它们被视为包含它们的文件中的全局变量，因此可以在该文件中的任何位置使用它们。

因为 const 全局变量具有内部链接，每个 .cpp 文件都会获得一个独立的全局变量版本，链接器无法看到。在大多数情况下，由于这些是 constexpr，编译器会直接优化掉这些变量。

虽然这很简单（对于较小的程序来说没问题），但每次 constants.h 被 #include 到不同的代码文件中时，这些变量中的每一个都会被复制到包含它的代码文件中。因此，如果 constants.h 被包含到 20 个不同的代码文件中，每个变量都会被复制 20 次。头文件保护符无法阻止这种情况，因为它们只防止一个头文件被多次包含到同一个包含文件中，而不是防止被包含到多个不同的代码文件中。这带来了两个挑战：

  1. 更改单个常量值需要重新编译每个包含该常量头文件的文件，这可能导致大型项目的重建时间很长。
  2. 如果常量很大且无法被优化掉，这可能会占用大量内存。

优点：

  • 适用于 C++17 之前。
  • 可以在包含它们的任何翻译单元中的常量表达式中使用。

缺点：

  • 更改头文件中的任何内容都需要重新编译包含该头文件的文件。
  • 每个包含该头文件的翻译单元都会获得自己的变量副本。

作为外部变量的全局常量

如果你正在积极更改值或添加新常量，之前的解决方案可能有问题，至少在事情稳定之前。

避免这些问题的一种方法是将这些常量转换为外部变量，因为这样我们可以有一个单一的变量（初始化一次）在所有文件之间共享。在这种方法中，我们将在 .cpp 文件中定义常量（以确保定义只存在于一个地方），并在头文件中放置前向声明（该头文件将被其他文件包含）。

constants.cpp:

#include "constants.h"

namespace constants
{
    // 我们使用 extern 来确保它们具有外部链接
    extern constexpr double pi { 3.14159 };
    extern constexpr double avogadro { 6.0221413e23 };
    extern constexpr double myGravity { 9.2 }; // m/s^2 -- 这个星球上的重力很轻
}

constants.h：

#ifndef CONSTANTS_H
#define CONSTANTS_H

namespace constants
{
    // 由于实际变量在命名空间内，前向声明也需要在命名空间内
    // 我们不能将变量前向声明为 constexpr，但可以将其前向声明为（运行时）const
    extern const double pi;
    extern const double avogadro;
    extern const double myGravity;
}

#endif

在代码文件中的使用保持不变：

main.cpp:

#include "constants.h" // include all the forward declarations

#include <iostream>

int main()
{
    std::cout << "Enter a radius: ";
    double radius{};
    std::cin >> radius;

    std::cout << "The circumference is: " << 2 * radius * constants::pi << '\n';

    return 0;
}

现在符号常量只会被实例化一次（在 constants.cpp中），而不是在每个包含 constants.h 的代码文件中，并且所有对这些常量的使用都将链接到在 constants.cpp中实例化的版本。对 constants.cpp 所做的任何更改只需要重新编译 constants.cpp。

然而，这种方法有几个缺点。首先，因为只有变量定义是 constexpr（前向声明不是，也不能是），这些常量只有在实际定义它们的文件中（constants.cpp）才是常量表达式。在其他文件中，编译器只会看到前向声明，它没有定义 constexpr 值（并且必须由链接器解析）。这意味着在定义它们的文件之外，这些变量不能在常量表达式中使用。其次，由于常量表达式通常可以比运行时表达式进行更多优化，编译器可能无法对这些变量进行同样程度的优化。

关键提示

为了使变量能在编译时上下文中使用（例如数组大小），编译器必须看到变量的定义（而不仅仅是前向声明）。

因为编译器逐个编译每个源文件，它只能看到正在编译的源文件中出现的变量定义（包括任何包含的头文件）。例如，当编译器编译 constants.cpp 时， main.cpp中的变量定义是不可见的。因此，constexpr 变量不能分离到头文件和源文件中，它们必须在头文件中定义。

鉴于上述缺点，建议将常量定义在头文件中（根据前一节或下一节的方法）。如果你发现常量的值变化频繁（例如因为调优程序）导致编译时间过长，可以临时将那些频繁变化的常量移到 .cpp 文件中（使用此方法）。

优点：

  • 适用于 C++17 之前。
  • 每个变量只需要一个副本。
  • 如果某个常量的值发生变化，只需要重新编译一个文件。

缺点：

  • 前向声明和变量定义位于不同的文件中，必须保持同步。
  • 变量不能在定义它的文件之外用于常量表达式。

全局常量作为内联变量 C++17

在课程 7.9 -- 内联函数和变量我们介绍了内联变量，即可以有多个定义，只要这些定义相同即可。通过将 constexpr 变量设为内联，我们可以在头文件中定义它们，然后 #include 到任何需要它们的 .cpp 文件中。这既避免了 ODR 违规，也避免了重复变量的缺点。

提醒

Constexpr 函数是隐式内联的，但 constexpr 变量不是隐式内联的。如果你想要一个内联 constexpr 变量，必须显式将其标记为 inline。

关键提示

内联变量默认具有外部链接，以便链接器可见。这是必要的，以便链接器可以去除重复的定义。

非内联 constexpr 变量具有内部链接。如果包含到多个翻译单元中，每个翻译单元都会得到自己的变量副本。这不是 ODR 违规，因为它们不会暴露给链接器。

constants.h：

#ifndef CONSTANTS_H
#define CONSTANTS_H

// 定义自己的命名空间来保存常量
namespace constants
{
    inline constexpr double pi { 3.14159 }; // 注意：现在是 inline constexpr
    inline constexpr double avogadro { 6.0221413e23 };
    inline constexpr double myGravity { 9.2 }; // m/s^2 -- 这个星球上的重力很轻
    // ... 其他相关常量
}
#endif

main.cpp:

#include "constants.h"

#include <iostream>

int main()
{
    std::cout << "Enter a radius: ";
    double radius{};
    std::cin >> radius;

    std::cout << "The circumference is: " << 2 * radius * constants::pi << '\n';

    return 0;
}

我们可以将 constants.h 包含到任意多的代码文件中，但这些变量只会被实例化一次，并在所有代码文件之间共享。

这种方法仍然有一个缺点：如果任何常量值发生变化，所有包含该常量头文件的文件都需要重新编译。

优点：

  • 可以在包含它们的任何翻译单元中的常量表达式中使用。
  • 每个变量只需要一个副本。

缺点：

  • 仅适用于 C++17 及更高版本。
  • 更改头文件中的任何内容都需要重新编译包含该头文件的文件。

最佳实践

如果你需要全局常量，并且你的编译器支持 C++17，建议在头文件中定义内联 constexpr 全局变量。
