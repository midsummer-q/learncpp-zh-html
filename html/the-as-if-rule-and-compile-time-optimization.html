5.4 — as-if 规则与编译时优化

● 机器译文 课程 5.4 查看英文原文

优化简介

在编程中， 优化 是指修改软件以使其更高效运行（例如，运行更快或使用更少资源）的过程。优化可以对应用程序的整体性能水平产生巨大影响。

某些类型的优化通常由人工完成。一种称为 性能分析器 的程序可用于查看程序各部分运行所需的时间，以及哪些部分影响了整体性能。然后程序员可以寻找缓解这些性能问题的方法。由于手工优化速度较慢，程序员通常专注于进行能产生较大影响的高级改进（例如选择性能更优的算法、优化数据存储和访问、减少资源利用、并行化任务等）。

其他类型的优化可以自动执行。优化其他程序的程序称为 优化器。优化器通常在低层次工作，通过重写、重新排序或消除语句或表达式来寻找改进它们的方法。例如，当你编写 i = i * 2;时，优化器可能会将其重写为 i *= 2;， i += i;，或 i <<= 1;。对于整数值，所有这些产生相同的结果，但在给定架构上，其中一个可能比其他更快。程序员可能不知道哪个是性能最佳的选择（答案可能因架构而异），但针对特定系统的优化器会知道。单个低层次优化可能只带来微小的性能提升，但它们的累积效果可以导致整体性能的显著提升。

现代 C++ 编译器是优化编译器，这意味着它们能够在编译过程中自动优化你的程序。就像预处理器一样，这些优化不会修改你的源代码文件——相反，它们作为编译过程的一部分透明地应用。

关键提示

优化编译器允许程序员专注于编写可读且可维护的代码，而无需牺牲性能。

由于优化涉及一些权衡（我们将在课程底部讨论），编译器通常支持多个优化级别，这些级别决定是否优化、优化的激进程度以及优先考虑哪种优化（例如速度 vs 大小）。

大多数编译器默认不进行优化，因此如果你使用命令行编译器，你需要自己启用优化。如果你使用 IDE，IDE 可能会自动配置发布版本以启用优化，而调试版本则禁用优化。

对于 gcc 和 Clang 用户

参见 0.9 -- 配置编译器：构建配置 了解如何启用优化。

as-if 规则

在 C++ 中，编译器有很大的自由度来优化程序。 as-if 规则 规定编译器可以任意修改程序以生成更优化的代码，只要这些修改不影响程序的“可观察行为”。

进阶读者

as-if 规则有一个显著的例外：对复制（或移动）构造函数的不必要调用可以被省略（忽略），即使这些构造函数具有可观察行为。我们在课程 14.15 -- 类初始化与复制省略。

中讨论这个主题。现代编译器采用多种不同的技术来有效优化程序。哪些技术可以应用取决于程序以及编译器和优化器的质量。

相关内容

维基百科 列出了编译器使用的具体技术。

一个优化机会

考虑以下简短程序：

#include <iostream>

int main()
{
	int x { 3 + 4 };
	std::cout << x << '\n';

	return 0;
}

输出很简单：

7

然而，其中隐藏着一个有趣的优化可能性。

如果这个程序完全按照编写的方式编译（不进行优化），编译器将生成一个可执行文件，在运行时（程序运行时）计算 3 + 4 的结果。如果程序执行一百万次， 3 + 4 将被计算一百万次，并且 7 的结果值被生成一百万次。

因为 3 + 4 的结果从不改变（它总是 7），每次运行程序时重新计算这个结果是浪费的。

编译时求值

现代 C++ 编译器能够在编译时（而不是运行时）完全或部分地求值某些表达式。当编译器在编译时完全或部分地求值一个表达式时，这被称为 编译时求值。

关键提示

编译时求值允许编译器在编译时完成本应在运行时完成的工作。由于这些表达式不再需要在运行时求值，生成的可执行文件更快且更小（代价是编译时间稍慢）。

为了说明问题，在本课中我们将介绍一些利用编译时求值的简单优化技术。然后，我们将在后续课程中继续讨论编译时求值。

常量折叠

编译时求值的最初形式之一被称为“常量折叠”。 常量折叠 是一种优化技术，编译器将具有字面量操作数的表达式替换为表达式的结果。使用常量折叠，编译器会识别出表达式 3 + 4 具有常量操作数，然后将表达式替换为结果 7。

结果将等价于以下代码：

#include <iostream>

int main()
{
	int x { 7 };
	std::cout << x << '\n';

	return 0;
}

该程序产生与前一个版本相同的输出（7），但生成的可执行文件不再需要在运行时花费CPU周期来计算 3 + 4 ！

常量折叠也可以应用于子表达式，即使整个表达式必须在运行时执行。

#include <iostream>

int main()
{
	std::cout << 3 + 4 << '\n';

	return 0;
}

在上面的例子中， 3 + 4 是整个表达式的一个子表达式 std::cout << 3 + 4 << '\n';。编译器可以将其优化为 std::cout << 7 << '\n';。

常量传播

以下程序包含另一个优化机会：

#include <iostream>

int main()
{
	int x { 7 };
	std::cout << x << '\n';

	return 0;
}

当 x 被初始化时，值 7 将存储在分配给 x的内存中。然后在下一行，程序将再次访问内存以获取值 7 以便打印。这需要两次内存访问操作（一次存储值，一次获取值）。

常量传播 是一种优化技术，编译器将已知具有常量值的变量替换为其值。使用常量传播，编译器会意识到 x 始终具有常量值 7，并将变量 x 的任何使用替换为值 7。

结果将等价于以下代码：

#include <iostream>

int main()
{
	int x { 7 };
	std::cout << 7 << '\n';

	return 0;
}

这消除了程序访问内存以获取 x。

值的需要。常量传播可能产生一个结果，然后可以通过常量折叠进一步优化：

#include <iostream>

int main()
{
	int x { 7 };
	int y { 3 };
	std::cout << x + y << '\n';

	return 0;
}

在这个例子中，常量传播会将 x + y 到 7 + 3转换为，然后可以常量折叠为值 10。

死代码消除

死代码消除 是一种优化技术，编译器移除可能被执行但对程序行为没有影响的代码。

回到之前的例子：

#include <iostream>

int main()
{
	int x { 7 };
	std::cout << 7 << '\n';

	return 0;
}

在这个程序中，变量 x 被定义并初始化，但从未在任何地方使用，因此对程序行为没有影响。死代码消除会移除 x。

结果将等价于以下代码：

#include <iostream>

int main()
{
	std::cout << 7 << '\n';

	return 0;
}

的定义。当一个变量因为不再需要而从程序中被移除时，我们说该变量已被 优化掉 （或 优化掉)。

与原始版本相比，这个优化版本不再需要运行时计算表达式 3 + 4，也不需要两次内存访问操作（一次初始化变量 x ，一次从 x读取值）。这意味着程序将更小且更快。

常量变量更容易优化

在某些情况下，我们可以做一些简单的事情来帮助编译器更有效地优化。

常量传播对编译器来说可能具有挑战性。在常量传播部分，我们提供了这个例子：

#include <iostream>

int main()
{
	int x { 7 };
	std::cout << x << '\n';

	return 0;
}

由于 x 被定义为一个非常量变量，为了应用这种优化，编译器必须意识到 x 实际上不会改变（尽管它可能改变）。编译器能否做到这一点取决于程序的复杂程度以及编译器优化例程的复杂程度。

我们可以通过尽可能使用常量变量来帮助编译器更有效地优化。例如：

#include <iostream>

int main()
{
	const int x { 7 }; // x 现在是 const
	std::cout << x << '\n';

	return 0;
}

因为 x 现在是 const，编译器有保证 x 在初始化后不能被改变。这使得编译器更有可能应用常量传播，然后完全优化掉该变量。

关键提示

使用 const 变量可以帮助编译器更有效地优化。

优化可能使程序更难调试

如果优化使程序更快，为什么默认不开启？

当编译器优化程序时，结果是变量、表达式、语句和函数调用可能被重新排列、修改、替换或完全移除。这样的变化可能使有效调试程序变得困难。

在运行时，调试与原始源代码不再很好关联的编译代码可能很困难。例如，如果你试图监视一个已被优化掉的变量，调试器将无法定位该变量。如果你试图单步进入一个已被优化掉的函数，调试器将直接跳过它。因此，如果你正在调试代码且调试器行为异常，这很可能是原因。

在编译时，我们几乎没有可见性，也几乎没有工具来帮助我们理解编译器在做什么。如果一个变量或表达式被替换为一个值，而该值是错误的，我们该如何调试这个问题？这是一个持续的挑战。

为了帮助最小化此类问题，调试构建通常会关闭优化，以便编译后的代码更接近源代码。

术语：编译时常量与运行时常量

C++ 中的常量有时被分为两个非正式类别。

一个 编译时常量 是其值在编译时已知的常量。示例包括：

  • 字面量。
  • 初始化器是编译时常量的常量对象。

一个 运行时常量 是其值在运行时上下文中确定的常量。示例包括：

  • 常量函数参数。
  • 初始化器是非常量或运行时常量的常量对象。

例如：

#include <iostream>

int five()
{
    return 5;
}

int pass(const int x) // x 是一个运行时常量
{
    return x;
}

int main()
{
    // 以下是非常量：
    [[maybe_unused]] int a { 5 };

    // 以下是编译时常量：
    [[maybe_unused]] const int b { 5 };
    [[maybe_unused]] const double c { 1.2 };
    [[maybe_unused]] const int d { b };       // b 是一个编译时常量

    // 以下是运行时常量：
    [[maybe_unused]] const int e { a };       // a 是非常量
    [[maybe_unused]] const int f { e };       // e 是一个运行时常量
    [[maybe_unused]] const int g { five() };  // 返回值直到运行时才可知
    [[maybe_unused]] const int h { pass(5) }; // 返回值直到运行时才可知

    return 0;
}

尽管你会在实际中遇到这些术语，但在 C++ 中这些定义并不那么有用：

  • 一些运行时常量（甚至非常量）可以在编译时求值以进行优化（根据 as-if 规则）。
  • 一些编译时常量（例如 const double d { 1.2 };）不能用于编译时特性（根据语言标准的定义）。我们将在课程 5.5 -- 常量表达式。

中进一步讨论。因此，我们建议避免使用这些术语。我们将在下一课中讨论你应该使用的术语。
