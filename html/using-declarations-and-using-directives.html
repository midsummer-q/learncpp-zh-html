7.13 — 使用声明与使用指令

● 机器译文 课程 7.13 查看英文原文

你可能在很多教科书和教程中见过这个程序：

#include <iostream>

using namespace std;

int main()
{
    cout << "Hello world!\n";

    return 0;
}

如果你看到这个，快跑。你的教科书或教程可能已经过时了。在本节课中，我们将探讨原因。

提示

有些 IDE 也会自动用类似的程序填充新的 C++ 项目（这样你可以立即编译某些内容，而不是从空白文件开始）。

一段简短的历史课

早在 C++ 支持命名空间之前，现在位于 std 命名空间中的所有名称都位于全局命名空间中。这导致了程序标识符和标准库标识符之间的命名冲突。在某个 C++ 版本下能正常工作的程序，可能会与更新的 C++ 版本产生命名冲突。

1995 年，命名空间被标准化，标准库的所有功能都从全局命名空间移到了命名空间 std中。这一改动破坏了仍然使用不带 std::。

的名称的旧代码。任何在大型代码库上工作过的人都知道，对代码库的任何改动（无论多么微小）都有破坏程序的风险。将每个现在被移入 std 命名空间的名称都更新为使用 std:: 前缀，是一个巨大的风险。于是人们请求一个解决方案。

快进到今天——如果你大量使用标准库，在每次使用标准库的内容前都输入 std:: 可能会变得重复，并且在某些情况下会使代码更难阅读。

C++ 为这两个问题提供了一些解决方案，即使用语句（using-statements）。

但首先，让我们定义两个术语。

限定名与非限定名

一个名称可以是限定的或非限定的。

一个 限定名称 是包含关联作用域的名称。大多数情况下，名称通过作用域解析运算符（::）与命名空间限定。例如：

std::cout // 标识符 cout 由命名空间 std 限定
::foo // 标识符 foo 由全局命名空间限定

进阶读者

名称也可以通过作用域解析运算符（::）由类名限定，或者通过成员选择运算符（. 或 ->）由类对象限定。例如：

class C; // 某个类

C::s_member; // s_member 由类 C 限定
obj.x; // x 由类对象 obj 限定
ptr->y; // y 由指向类对象的指针 ptr 限定

一种 非限定名 是不包含作用域限定符的名称。例如， cout 和 x 都是非限定名，因为它们不包含关联的作用域。

使用声明（Using-declarations）

减少重复输入 std:: 的一种方法是使用使用声明语句。 使用声明 允许我们将一个非限定名（无作用域）作为限定名的别名。

下面是我们基本的 Hello world 程序，在第 5 行使用了使用声明：

#include <iostream>

int main()
{
   using std::cout; // 这个 using 声明告诉编译器 cout 应解析为 std::cout
   cout << "Hello world!\n"; // 所以这里不需要 std:: 前缀！

   return 0;
} // using 声明在当前作用域结束时失效

使用声明 using std::cout; 告诉编译器我们将要使用 cout 来自... std 命名空间中的对象。因此，每当它看到 cout时，就会假定我们指的是 std::cout。如果 std::cout 与 cout 的其他可见用法之间存在命名冲突， main()， std::cout 将被优先考虑。因此，在第 6 行，我们可以输入 cout 而不是 std::cout。

在这个简单的例子中，这并没有节省多少精力，但如果你在函数内部多次使用 cout ，使用声明可以使代码更易读。注意，每个名称都需要一个单独的使用声明（例如，一个用于 std::cout，一个用于 std::cin，等等……）。

using声明从声明点开始生效，直到其所在作用域的末尾。

虽然using声明不如使用 std:: 前缀明确，但它们通常被认为是安全且可接受的，可以在源（.cpp）文件中使用，但有一个例外我们将在下面讨论。

Using指令

另一种简化方式是使用using指令。一个 using 指令 的前向声明允许 所有 允许在using指令的作用域内无需限定符即可引用给定命名空间中的标识符。

进阶读者

由于技术原因，using指令实际上并不会在当前作用域中引入名称的新含义——而是在某个外层作用域中引入名称的新含义（关于选择哪个外层作用域的更多细节可以参见 这里)。

这是我们的Hello world程序，在第5行有一个using指令：

#include <iostream>

int main()
{
   using namespace std; // 现在 std 命名空间中的所有名称无需限定即可访问
   cout << "Hello world!\n"; // 所以这里不需要 std:: 前缀

   return 0;
} // using 指令在当前作用域结束时失效

using指令 using namespace std; 告诉编译器， std 命名空间中的所有名称在当前作用域（这里是函数 main()）中都可以无需限定符访问。当我们使用未限定的标识符 cout时，它将解析为 std::cout。

Using指令是为旧的、使用命名空间之前的代码库提供的解决方案，这些代码库对标准库功能使用未限定的名称。与其手动将每个未限定名称更新为限定名称（这有风险），不如在每个文件顶部放置一个using指令（using namespace std;），这样所有已移至 std 命名空间的名称仍然可以不加限定地使用。

Using指令的问题（即为什么应该避免“using namespace std;”）

在现代C++中，using指令通常带来的好处（节省一些打字）与风险相比微乎其微。这有两个原因：

  1. Using指令允许不加限定地访问 所有 命名空间中的所有名称（可能包括许多你永远不会使用的名称）。
  2. Using指令不会优先选择using指令所标识的命名空间中的名称。

最终结果是，名称冲突的可能性显著增加（特别是如果你导入了 std 命名空间）。

首先，让我们看一个说明性的例子，其中using指令导致了名称冲突：

#include <iostream>

namespace A
{
	int x { 10 };
}

namespace B
{
	int x{ 20 };
}

int main()
{
	using namespace A;
	using namespace B;

	std::cout << x << '\n';

	return 0;
}

在上面的例子中，编译器无法确定 x 在 main 指的是 A::x 或 B::x。在这种情况下，编译将失败，并出现“ambiguous symbol”错误。我们可以通过移除其中一个using指令、改用using声明或限定 x （如 A::x 或 B::x)。

这是另一个更微妙的例子：

#include <iostream> // imports the declaration of std::cout

int cout() // 声明我们自己的 "cout" 函数
{
    return 5;
}

int main()
{
    using namespace std; // 使 std::cout 可以作为 "cout" 访问
    cout << "Hello, world!\n"; // 哦！我们这里想要哪个 cout？是 std 命名空间中的那个，还是我们上面定义的那个？

    return 0;
}

在这个例子中，编译器无法确定我们对 cout 表示 std::cout 还是我们定义的 cout 函数，同样会编译失败，出现“ambiguous symbol”错误。虽然这个例子很简单，但如果我们显式地给 std::cout 加上前缀，像这样：

    std::cout << "Hello, world!\n"; // 告诉编译器我们指的是 std::cout

或者使用using声明而不是using指令：

    using std::cout; // 告诉编译器 cout 表示 std::cout
    cout << "Hello, world!\n"; // 所以这表示 std::cout

那么我们的程序一开始就不会有任何问题。虽然你可能不太可能编写一个名为“cout”的函数，但 std 命名空间中还有数百个其他名称正等着与你的名称冲突。

即使using指令今天没有导致名称冲突，它也会使你的代码更容易受到未来冲突的影响。例如，如果你的代码包含某个库的using指令，而该库随后更新，那么更新后的库中引入的所有新名称都可能与你的现有代码发生名称冲突。

例如，以下程序可以正常编译和运行：

FooLib.h（某个第三方库的一部分）：

#ifndef FOOLIB
#define FOOLIB

namespace Foo
{
    int a { 20 };
}

#endif

main.cpp:

#include <iostream>
#include <FooLib.h> // a third-party library we installed outside our project directory, thus angled brackets used

void print()
{
    std::cout << "Hello\n";
}

int main()
{
    using namespace Foo; // 因为我们很懒，想访问 Foo:: 限定的名称而不写 Foo:: 前缀

    std::cout << a << '\n'; // 使用 Foo::a
    print(); // 调用 ::print()

    return 0;
}

现在假设你将FooLib更新到新版本，并且FooLib.h变成了这样：

FooLib.h（更新后）：

#ifndef FOOLIB
#define FOOLIB

namespace Foo
{
    int a { 20 };
    void print() { std::cout << "Timmah!"; } // 此函数已添加
}
#endif

你的 main.cpp 没有改变，但它将无法再编译！这是因为我们的 using 指令使得 Foo::print() 可以直接作为 print()访问，并且现在对 print() 表示 ::print() 或 Foo::print()。

还有一个更隐蔽的版本也可能发生。更新后的库可能引入一个函数，它不仅同名，而且实际上是某个函数调用的更佳匹配。在这种情况下，编译器可能会决定优先选择新函数，你的程序行为将意外且无声地改变。

考虑以下程序：

Foolib.h（某个第三方库的一部分）：

#ifndef FOOLIB_H
#define FOOLIB_H

namespace Foo
{
    int a { 20 };
}
#endif

main.cpp:

#include <iostream>
#include <Foolib.h> // a third-party library we installed outside our project directory, thus angled brackets used

int get(long)
{
    return 1;
}

int main()
{
    using namespace Foo; // 因为我们很懒，想访问 Foo:: 限定的名称而不写 Foo:: 前缀
    std::cout << a << '\n'; // 使用 Foo::a

    std::cout << get(0) << '\n'; // 调用 ::get(long)

    return 0;
}

这个程序运行并打印 1。

现在，假设我们更新了 Foolib 库，其中包含一个更新后的 Foolib.h，如下所示：

Foolib.h（更新后）：

#ifndef FOOLIB_H
#define FOOLIB_H

namespace Foo
{
    int a { 20 };

    int get(int) { return 2; } // 新函数已添加
}
#endif

再一次，我们的 main.cpp 文件完全没有改变，但这个程序现在编译、运行并打印 2！

当编译器遇到一个函数调用时，它必须确定应该匹配哪个函数定义。在从一组可能匹配的函数中选择一个函数时，它会优先选择不需要参数转换的函数，而不是需要参数转换的函数。因为字面量 0 是一个整数，C++ 会优先将 print(0) 与新引入的 print(int) （无转换）匹配，而不是 print(long) （需要从 int 切换到 long转换）。这导致程序行为发生意外变化。

在这种情况下，行为的变化相当明显。但在更复杂的程序中，如果返回值不仅仅是打印出来，这个问题可能非常难以发现。

如果我们使用了 using 声明或显式作用域限定符，这种情况就不会发生。

最后，缺少显式作用域前缀使得读者更难分辨哪些函数属于库，哪些属于你的程序。例如，如果我们使用 using 指令：

using namespace NS;

int main()
{
    foo(); // 这个 foo 是用户定义的函数，还是 NS 库的一部分？
}

不清楚对 foo() 的调用实际上是调用 NS::foo() 还是调用一个用户定义的 foo() 现代 IDE 应该能够在你悬停在一个名称上时为你消除歧义，但为了查看每个名称的来源而悬停每个名称是很繁琐的。

没有 using 指令，情况就清晰得多：

int main()
{
    NS::foo(); // 显然是 NS 库的一部分
    foo(); // 很可能是用户定义的函数
}

在这个版本中，对 NS::foo() 的调用显然是库调用。对普通 foo() 的调用可能是对用户定义函数的调用（某些库，包括某些标准库头文件，确实会将名称放入全局命名空间，所以这不是绝对的）。

using 语句的作用域

如果 using 声明或 using 指令在块内使用，则名称仅适用于该块（它遵循正常的块作用域规则）。这是一件好事，因为它将命名冲突的可能性降低到仅在该块内。

如果 using 声明或 using 指令在命名空间（包括全局命名空间）中使用，则名称适用于文件的其余部分（它们具有文件作用域）。

不要在头文件或 #include 指令之前使用 using 语句

一个好的经验法则是，using 语句不应放置在任何可能影响其他文件中代码的位置。也不应放置在任何其他文件的代码可能影响它们的位置。

更具体地说，这意味着 using 语句不应在头文件中使用，也不应在 #include 指令之前使用。

例如，如果你在头文件的全局命名空间中放置了一个 using 语句，那么每个 #include 该头文件的其他文件也会得到那个 using 语句。这显然很糟糕。这也适用于头文件内的命名空间，原因相同。

但是，在头文件内定义的函数中使用 using 语句呢？当然这不会很糟糕，因为 using 语句的作用域仅限于该函数，对吧？即使这样也不行。原因与不应该在 #include 指令之前使用 using 语句相同。

事实证明，using 语句的行为取决于已经引入了哪些标识符。这使得它们具有顺序依赖性，因为如果之前引入的标识符发生变化，它们的功能可能会改变。

我们将用一个例子来说明这一点：

FooInt.h：

namespace Foo
{
    void print(int)
    {
        std::cout << "print(int)\n" << std::endl;
    }
}

FooDouble.h：

namespace Foo
{
    void print(double)
    {
        std::cout << "print(double)\n" << std::endl;
    }
}

main.cpp（正确）：

#include <iostream>

#include "FooDouble.h"
#include "FooInt.h"

using Foo::print; // print 表示 Foo::print

int main()
{
    print(5);  // 调用 Foo::print(int)
}

运行时，该程序调用 Foo::print(int)，它会打印 print(int)。

现在让我们稍微修改 main.cpp。

main.cpp（错误）：

#include <iostream>

#include "FooDouble.h"

using Foo::print; // 我们将 using 语句移到了这里，在 #include 指令之前
#include "FooInt.h"

int main()
{
    print(5);  // 调用 Foo::print(double)
}

我们所做的只是移动了 using Foo::print; 在 #include "FooInt.h"。现在我们的程序打印 print(double)！无论为什么会发生这种情况，你很可能都会同意这是我们想要避免的行为！

所以回到原点，我们不应该在头文件中定义的函数中使用 using 语句，原因相同——我们无法控制哪些其他头文件会在我们的头文件之前被 #include，而且这些头文件可能会做一些改变我们 using 语句行为的事情！

唯一真正安全使用 using 语句的地方是在我们的源文件（.cpp）中，在所有 #include 之后。

进阶读者

这个例子使用了一个我们尚未涉及的概念，称为“函数重载”（我们在课程 11.1 -- 函数重载介绍中介绍）。对于这个例子，你只需要知道同一作用域中的两个函数可以具有相同的名称，只要它们的参数不同即可。由于 int 和 double 是不同的类型，因此同时存在 Foo::print(int) 和 Foo::print(double) 是没有问题的。

在正确的版本中，当编译器遇到 using Foo::print时，它已经看到了 Foo::print(int) 和 Foo::print(double)，因此它使两者都可以作为 print()。因为 Foo::print(int) 比 Foo::print(double)更匹配，因此它调用 Foo::print(int)。

在错误的版本中，当编译器遇到 using Foo::print时，它只看到了 Foo::print(double)的声明，因此它只使 Foo::print(double) 可以无资格调用。所以当我们调用 print(5) 时，只有 Foo::print(double) 有资格被匹配。因此 Foo::print(double) 被调用了！

取消或替换 using 语句

一旦声明了 using 语句，就无法在声明它的作用域内取消或用不同的 using 语句替换它。

int main()
{
    using namespace Foo;

    // 这里无法取消 "using namespace Foo"！
    // 也无法用另一个 using 语句替换 "using namespace Foo"

    return 0;
} // using namespace Foo 在此结束

你能做的最好的事情就是从一开始就使用块作用域规则有意限制 using 语句的作用域。

int main()
{
    {
        using namespace Foo;
        // 此处调用 Foo:: 的内容
    } // using namespace Foo 失效
 
    {
        using namespace Goo;
        // 此处调用 Goo:: 的内容
    } // using namespace Goo 失效

    return 0;
}

当然，所有这些麻烦都可以通过一开始就显式使用作用域解析运算符（::）来避免。

using 语句的最佳实践

最佳实践

优先使用显式命名空间限定符而不是 using 语句。

避免使用 using 指令（除了 using namespace std::literals 访问在 s 和 sv 字面量后缀）。在 .cpp 文件中，在 #include 指令之后使用 using 声明是可以的。不要在头文件中使用 using 语句（尤其是在头文件的全局命名空间中）。
