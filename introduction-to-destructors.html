15.4 — 析构函数简介

● 机器译文 课程 15.4 查看英文原文

清理问题

假设你正在编写一个需要通过网络发送数据的程序。然而，建立与服务器的连接代价高昂，因此你希望收集一批数据后一次性发送。这样的类可能结构如下：

// 此示例无法编译，因为它（故意）不完整
class NetworkData
{
private:
    std::string m_serverName{};
    DataStore m_dataQueue{};

public:
	NetworkData(std::string_view serverName)
		: m_serverName { serverName }
	{
	}

	void addData(std::string_view data)
	{
		m_dataQueue.add(data);
	}

	void sendData()
	{
		// 连接到服务器
		// 发送所有数据
		// 清除数据
	}
};

int main()
{
    NetworkData n("someipAddress");

    n.addData("somedata1");
    n.addData("somedata2");

    n.sendData();

    return 0;
}

然而，这 NetworkData 存在一个潜在问题。它依赖于 sendData() 在程序关闭前被显式调用。如果 NetworkData 的用户忘记这样做，数据将不会发送到服务器，并在程序退出时丢失。现在，你可能会说：“嗯，记住这个并不难！”，在这个特定例子中，你是对的。但考虑一个稍微复杂的例子，比如这个函数：

bool someFunction()
{
    NetworkData n("someipAddress");

    n.addData("somedata1");
    n.addData("somedata2");

    if (someCondition)
        return false;

    n.sendData();
    return true;
}

在这种情况下，如果 someCondition 等于 true，那么函数会提前返回，而 sendData() 将不会被调用。这是一个更容易犯的错误，因为 sendData() 调用是存在的，只是程序在所有情况下都没有执行到它。

概括来说，使用资源（最常见的是内存，但有时也包括文件、数据库、网络连接等）的类通常需要在销毁使用它们的类对象之前显式发送或关闭资源。在其他情况下，我们可能希望在对象销毁前进行一些记录工作，例如将信息写入日志文件，或向服务器发送一条遥测数据。术语“清理”通常指类在对象销毁前必须执行的一组任务，以确保行为符合预期。如果我们必须依赖此类用户确保执行清理的函数在对象销毁前被调用，那么很可能在某些地方出错。

但为什么我们要要求用户确保这一点呢？如果对象正在被销毁，那么我们知道此时需要执行清理。难道清理不应该自动进行吗？

析构函数来拯救

在课程 14.9 -- 构造函数简介 我们介绍了构造函数，它们是在创建非聚合类类型对象时调用的特殊成员函数。构造函数用于初始化成员变量，并执行确保类对象准备好使用所需的其他设置任务。

类似地，类还有另一种特殊成员函数，它在非聚合类类型对象销毁时自动调用。这个函数称为 析构函数。析构函数旨在允许类在对象销毁前执行任何必要的清理。

析构函数命名

与构造函数一样，析构函数有特定的命名规则：

  1. 析构函数必须与类同名，前面加一个波浪号（~）。
  2. 析构函数不能接受参数。
  3. 析构函数没有返回类型。

一个类只能有一个析构函数。

通常你不应该显式调用析构函数（因为它会在对象销毁时自动调用），因为很少有需要多次清理对象的情况。

析构函数可以安全地调用其他成员函数，因为对象在析构函数执行完毕后才会被销毁。

析构函数示例

#include <iostream>

class Simple
{
private:
    int m_id {};

public:
    Simple(int id)
        : m_id { id }
    {
        std::cout << "Constructing Simple " << m_id << '\n';
    }

    ~Simple() // 这是我们的析构函数
    {
        std::cout << "Destructing Simple " << m_id << '\n';
    }

    int getID() const { return m_id; }
};

int main()
{
    // 分配一个 Simple
    Simple simple1{ 1 };
    {
        Simple simple2{ 2 };
    } // simple2 在此处销毁

    return 0;
} // simple1 在此处销毁

该程序产生以下结果：

Constructing Simple 1
Constructing Simple 2
Destructing Simple 2
Destructing Simple 1

注意，当每个 Simple 对象被销毁时，析构函数被调用，打印一条消息。“Destructing Simple 1”在“Destructing Simple 2”之后打印，因为 simple2 在函数结束前被销毁，而 simple1 直到 main()。

结束才被销毁。记住，静态变量（包括全局变量和静态局部变量）在程序启动时构造，在程序关闭时销毁。

改进 NetworkData 程序

回到课程开头的例子，我们可以通过让析构函数调用该函数来消除用户显式调用 sendData() 的需要：

class NetworkData
{
private:
    std::string m_serverName{};
    DataStore m_dataQueue{};

public:
	NetworkData(std::string_view serverName)
		: m_serverName { serverName }
	{
	}

	~NetworkData()
	{
		sendData(); // 确保在对象销毁前所有数据都已发送
	}

	void addData(std::string_view data)
	{
		m_dataQueue.add(data);
	}

	void sendData()
	{
		// 连接到服务器
		// 发送所有数据
		// 清除数据
	}
};

int main()
{
    NetworkData n("someipAddress");

    n.addData("somedata1");
    n.addData("somedata2");

    return 0;
}

有了这样的析构函数，我们的 NetworkData 对象将在销毁前始终发送其拥有的任何数据！清理自动进行，这意味着更少的出错机会，以及更少需要操心的事情。

隐式析构函数

如果非聚合类类型对象没有用户声明的析构函数，编译器将生成一个带有空体的析构函数。这个析构函数称为隐式析构函数，它实际上只是一个占位符。

如果你的类在销毁时不需要执行任何清理，完全可以不定义析构函数，让编译器为你的类生成一个隐式析构函数。

关于 std::exit() 函数

在课程 8.12 -- 暂停（提前退出程序），我们讨论了 std::exit() 函数，它可以用来立即终止程序。当程序立即终止时，程序只是结束。局部变量不会被先销毁，因此不会调用任何析构函数。如果你依赖析构函数在这种情况下进行必要的清理工作，请小心。

进阶读者

未处理的异常也会导致程序终止，并且可能在此之前不会展开堆栈。如果堆栈展开没有发生，则在程序终止之前不会调用析构函数。
