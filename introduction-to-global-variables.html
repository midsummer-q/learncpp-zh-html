7.4 — 全局变量简介

● 机器译文 课程 7.4 查看英文原文

在课程 7.3 -- 局部变量中，我们介绍了局部变量是在函数体内定义的变量。局部变量具有块作用域（仅在其声明的块内可见），并且具有自动存储期（在定义点创建，在退出块时销毁）。

在 C++ 中，变量也可以声明在 函数 外部。这样的变量称为 全局变量。

声明全局变量

按照惯例，全局变量声明在文件顶部，在 include 语句之后，位于全局命名空间中。下面是一个定义全局变量的示例：

#include <iostream>

// 在函数外部声明的变量是全局变量
int g_x {}; // 全局变量 g_x

void doSomething()
{
    // 全局变量可以在文件中的任何地方被看到和使用
    g_x = 3;
    std::cout << g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << g_x << '\n';

    // 全局变量可以在文件中的任何地方被看到和使用
    g_x = 5;
    std::cout << g_x << '\n';

    return 0;
}
// g_x 在此处超出作用域

上面的示例输出：

3
3
5

全局变量的作用域

在全局命名空间中声明的标识符具有 全局命名空间作用域 （通常称为 全局作用域，有时非正式地称为 文件作用域），这意味着它们从声明点开始到声明它们的 文件 结束都是可见的。

一旦声明，全局变量就可以从该点开始在文件中的任何位置使用！在上面的示例中，全局变量 g_x 在两个函数中都被使用 doSomething() 和 main()。

全局变量也可以定义在用户定义的命名空间内。下面是和上面相同的示例，但 g_x 已从全局作用域移到了用户定义的命名空间 Foo：

#include <iostream>

namespace Foo // Foo 定义在全局作用域中
{
    int g_x {}; // g_x 现在位于 Foo 命名空间内，但仍然是一个全局变量
}

void doSomething()
{
    // 全局变量可以在文件中的任何地方被看到和使用
    Foo::g_x = 3;
    std::cout << Foo::g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << Foo::g_x << '\n';

    // 全局变量可以在文件中的任何地方被看到和使用
    Foo::g_x = 5;
    std::cout << Foo::g_x << '\n';

    return 0;
}

中。尽管标识符 g_x 现在仅限于 namespace Foo的作用域，但该名称仍然可以全局访问（通过 Foo::g_x），并且 g_x 仍然是一个全局变量。

关键提示

在命名空间内声明的变量也是全局变量。

最佳实践

优先在命名空间内定义全局变量，而不是在全局命名空间中。

全局变量具有静态存储期

全局变量在程序启动时（在 main() 开始执行之前）创建，并在程序结束时销毁。这称为 静态存储期。具有 静态存储期 的变量有时称为 静态变量。

命名全局变量

按照惯例，一些开发者在全局变量标识符前加上“g”或“g_”前缀，以表明它们是全局的。这个前缀有几个用途：

  • 它有助于避免与全局命名空间中的其他标识符发生命名冲突。
  • 它有助于防止意外的名称隐藏（我们将在课程中进一步讨论这一点） 7.5 课——变量遮蔽（名称隐藏）中讨论了当嵌套块中出现同名变量时会发生什么。)。
  • 这有助于表明带前缀的变量在函数作用域之外仍然存在，因此我们对它们所做的任何更改也将持续存在。

在用户定义的命名空间中定义的全局变量通常省略前缀（因为上述列表中的前两点在这种情况下不是问题，并且当我们看到附加的命名空间名称时，可以推断出变量是全局的）。但是，如果您想保留前缀作为第三点的更明显提醒，那也无妨。

最佳实践

考虑在命名全局变量时使用“g”或“g_”前缀（尤其是在全局命名空间中定义的变量），以帮助将它们与局部变量和函数参数区分开来。

作者注

我们有时会收到读者的反馈，询问像 g_ 这样的前缀是否可以，因为他们被告知前缀是 匈牙利命名法 的一种形式，而“匈牙利命名法不好”。

对匈牙利命名法的反对主要来自于使用匈牙利命名法在变量名中编码变量的 类型 类型。例如， nAge，其中 n 表示 int。这在现代C++中并不是那么有用。

然而，使用前缀（通常是 g/g_， s/s_、和 m/m_）来表示变量的 作用域 或 生存期 作用域确实增加了价值，原因在本节中已说明。

全局变量初始化

与默认未初始化的局部变量不同，具有静态存储期的变量默认是零初始化的。

非常量全局变量可以选择性地初始化：

int g_x;       // 没有显式初始化器（默认零初始化）
int g_y {};    // 值初始化（导致零初始化）
int g_z { 1 }; // 列表初始化，带有特定值

常量全局变量

就像局部变量一样，全局变量可以是常量。与所有常量一样，常量全局变量必须初始化。

#include <iostream>

const int g_x;     // 错误：常量变量必须初始化
constexpr int g_w; // 错误：constexpr 变量必须初始化

const int g_y { 1 };     // const 全局变量 g_y，用值初始化
constexpr int g_z { 2 }; // constexpr 全局变量 g_z，用值初始化

void doSomething()
{
    // 全局变量可以在文件中的任何地方被看到和使用
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';
}

int main()
{
    doSomething();

    // 全局变量可以在文件中的任何地方被看到和使用
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';

    return 0;
}
// g_y 和 g_z 在此处超出作用域

关于（非常量）全局变量的警告

新手程序员常常倾向于使用大量全局变量，因为它们可以在不显式传递给每个需要它们的函数的情况下使用。然而，通常应该完全避免使用非常量全局变量！我们将在接下来的课程中讨论原因 7.8 -- 为什么（非常量）全局变量是邪恶的。

快速总结

// 非常量全局变量
int g_x;                 // 定义未初始化的全局变量（默认零初始化）
int g_x {};              // 定义显式值初始化的全局变量
int g_x { 1 };           // 定义显式初始化的全局变量

// Const 全局变量
const int g_y;           // 错误：const 变量必须初始化
const int g_y { 2 };     // 定义初始化的全局 const

// Constexpr 全局变量
constexpr int g_y;       // 错误：constexpr 变量必须初始化
constexpr int g_y { 3 }; // 定义初始化的全局 constexpr
