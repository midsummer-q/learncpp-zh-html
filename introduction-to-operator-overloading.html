21.1 — 运算符重载简介

● 机器译文 课程 21.1 查看英文原文

在课程 11.1 -- 函数重载介绍你学习了函数重载，它提供了一种机制来创建和解析对多个同名函数的调用，只要每个函数具有唯一的函数原型。这允许你创建函数的变体以处理不同的数据类型，而无需为每个变体想出一个独特的名称。

在C++中，运算符是作为函数实现的。通过对运算符函数使用函数重载，你可以定义自己的运算符版本，使其适用于不同的数据类型（包括你编写的类）。使用函数重载来重载运算符称为 运算符重载。

在本章中，我们将研究与运算符重载相关的主题。

运算符作为函数

考虑以下示例：

int x { 2 };
int y { 3 };
std::cout << x + y << '\n';

编译器内置了一个用于整数操作数的加号运算符（+）版本——这个函数将整数x和y相加并返回一个整数结果。当你看到表达式 x + y时，你可以在脑海中将其翻译为函数调用 operator+(x, y) （其中operator+是函数名）。

现在考虑这个类似的片段：

double z { 2.0 };
double w { 3.0 };
std::cout << w + z << '\n';

编译器也内置了一个用于double操作数的加号运算符（+）版本。表达式w + z变成函数调用 operator+(w, z)，并且使用函数重载来确定编译器应该调用这个函数的double版本而不是整数版本。

现在考虑如果我们尝试将两个程序定义类的对象相加会发生什么：

Mystring string1 { "Hello, " };
Mystring string2 { "World!" };
std::cout << string1 + string2 << '\n';

在这种情况下你期望发生什么？直观的预期结果是字符串“Hello, World!”会被打印到屏幕上。然而，因为Mystring是程序定义的类型，编译器没有内置的加号运算符版本可以用于Mystring操作数。所以在这种情况下，它会给我们一个错误。为了让它像我们期望的那样工作，我们需要编写一个重载函数来告诉编译器+运算符应该如何与两个Mystring类型的操作数一起工作。我们将在下一课中学习如何做到这一点。

解析重载运算符

当计算包含运算符的表达式时，编译器使用以下规则：

  • 如果 所有 的操作数是基本数据类型，编译器将调用内置例程（如果存在）。如果不存在，编译器将产生一个编译器错误。
  • 如果 任何 的操作数是程序定义的类型（例如你的某个类或枚举类型），编译器将使用函数重载解析算法（在课程 11.3 -- 函数重载解析与歧义匹配中描述）来查看是否可以找到明确最佳匹配的重载运算符。这可能涉及隐式转换一个或多个操作数以匹配重载运算符的参数类型。也可能涉及将程序定义的类型隐式转换为基本类型（通过重载的类型转换，我们将在本章后面介绍），以便匹配内置运算符。如果找不到匹配（或找到模糊匹配），编译器将报错。

运算符重载有哪些限制？

首先，C++中几乎任何现有的运算符都可以被重载。例外是：条件运算符（?:）、sizeof、作用域运算符（::）、成员选择运算符（.）、指针成员选择运算符（.*）、typeid以及类型转换运算符。

其次，你只能重载已经存在的运算符。你不能创建新的运算符或重命名现有的运算符。例如，你不能创建一个 operator** 来进行指数运算。

第三，重载运算符中至少有一个操作数必须是用户定义的类型。这意味着你可以重载 operator+(int, Mystring)，但不能是 operator+(int, double)。

因为标准库类被认为是用户定义的，这意味着你可以定义 operator+(double, std::string)。然而，这不是一个好主意，因为未来的语言标准可能会定义这个重载，这可能会破坏任何使用你重载的程序。因此，最佳实践是你的重载运算符应该至少操作一个程序定义的类型。这保证了未来的语言标准不会破坏你的程序。

最佳实践

重载运算符应该至少操作一个程序定义的类型（作为函数的参数或隐式对象）。

第四，不能改变运算符支持的操作数数量。

最后，所有运算符保持其默认优先级和结合性（无论它们用于什么），并且这不能改变。

一些新程序员尝试重载按位异或运算符（^）来进行指数运算。然而，在C++中，operator^的优先级低于基本算术运算符，这会导致表达式计算错误。

在基础数学中，指数运算在基本算术之前解析，所以4 + 3 ^ 2解析为4 + (3 ^ 2) => 4 + 9 => 13。
然而，在C++中，算术运算符的优先级高于operator^，所以4 + 3 ^ 2解析为(4 + 3) ^ 2 => 7 ^ 2 => 49。

你需要显式地将指数部分括起来（例如4 + (3 ^ 2)）每次使用时才能正常工作，这并不直观，并且容易出错。

由于这个优先级问题，通常最好以与其原始意图类似的方式使用运算符。

最佳实践

重载运算符时，最好让运算符的功能尽可能接近运算符的原始意图。

此外，因为运算符没有描述性名称，所以并不总是清楚它们打算做什么。例如，operator+对于字符串类来说可能是连接字符串的合理选择。但是operator-呢？你期望它做什么？这不清楚。

最佳实践

如果重载运算符的含义不清晰且不直观，请改用命名函数。

最后，重载运算符应该以与原始运算符一致的方式返回值。不修改其操作数的运算符（例如算术运算符）通常应按值返回结果。修改其最左侧操作数的运算符（例如前置递增、任何赋值运算符）通常应按引用返回最左侧操作数。

最佳实践

不修改其操作数的运算符（例如算术运算符）通常应按值返回结果。

修改其最左侧操作数的运算符（例如前置递增、任何赋值运算符）通常应按引用返回最左侧操作数。

在这些限制内，你仍然会找到许多有用的功能来为你的自定义类重载！你可以重载+运算符来连接你程序定义的字符串类，或者将两个Fraction类对象相加。你可以重载<<运算符以便轻松地将你的类打印到屏幕（或文件）。你可以重载相等运算符（==）来比较两个类对象。这使得运算符重载成为C++中最有用的特性之一——仅仅因为它允许你以更直观的方式使用你的类。
