2.10 — 预处理器简介

● 机器译文 课程 2.10 查看英文原文

在编译项目时，您可能期望编译器完全按照您编写的方式编译每个代码文件。但实际上并非如此。

相反，在编译之前，每个代码文件(.cpp)都会经历一个 预处理 阶段。在这个阶段，一个称为 预处理器 的程序会对代码文件的文本进行各种更改。预处理器实际上并不会以任何方式修改原始代码文件——相反，预处理器所做的所有更改要么临时在内存中发生，要么使用临时文件。

顺便说一句……

历史上，预处理器是一个独立于编译器的程序，但在现代编译器中，预处理器可能直接内置在编译器本身中。

预处理器所做的大部分工作相当乏味。例如，它会删除注释，并确保每个代码文件以换行符结尾。然而，预处理器确实有一个非常重要的角色：它负责处理 #include 指令（我们稍后会详细讨论）。

当预处理器处理完一个代码文件后，其结果称为 翻译单元这个翻译单元随后由编译器进行编译。

相关内容

预处理、编译和链接的整个过程称为 翻译。

如果您好奇，这里有一个 翻译阶段截至撰写本文时，预处理涵盖阶段 1 到 4，编译是阶段 5 到 7。

预处理器指令

当预处理器运行时，它会扫描代码文件（从上到下），寻找预处理器指令。 预处理器指令 （通常简称为 指令）是以 # 符号并以换行符结尾（不是分号）。

关键提示

预处理器的最终输出不包含任何指令——只有处理后的指令输出被传递给编译器。

顺便说一句……

Using directives （在课程中引入 2.9 -- 命名冲突和命名空间简介）不是预处理器指令（因此不由预处理器处理）。 directive 通常 表示一个 preprocessor directive，但情况并非总是如此。

#Include

你已经见过 #include 指令的实际使用（通常用于 #include <iostream>）。当你 #include 一个文件时，预处理器会将 #include 指令替换为所包含文件的内容。然后对所包含的内容进行预处理（这可能导致额外的 #include 被递归处理），再对文件的其余部分进行预处理。

考虑以下程序：

#include <iostream>

int main()
{
    std::cout << "Hello, world!\n";
    return 0;
}

当预处理器在此程序上运行时，预处理器将替换 #include <iostream> 为名为 “iostream” 的文件的内容，然后预处理包含的内容及文件的其余部分。

由于 #include 几乎专门用于包含头文件，我们将讨论 #include 在下一课中更详细地讨论（届时我们将讨论头文件）。

关键提示

每个翻译单元通常由一个单独的代码(.cpp)文件及其 #include 的所有头文件组成（递归应用，因为头文件可以 #include 其他头文件）。

宏定义

浮点类型的 #define 指令可用于创建宏。在C++中， 宏 是一种规则，定义了如何将输入文本转换为替换输出文本。

宏有两种基本类型： 对象式宏、和 函数式宏。

函数式宏 行为类似函数，服务于类似的目的。它们的使用通常被认为是不安全的，并且它们能做的几乎所有事情都可以通过普通函数来完成。

对象式宏 可以通过两种方式之一定义：

#define IDENTIFIER
#define IDENTIFIER substitution_text

顶部定义没有替换文本，而底部定义有。由于这些是预处理器指令（而非语句），请注意这两种形式都不以分号结束。

宏的标识符使用与普通标识符相同的命名规则：可以使用字母、数字和下划线，不能以数字开头，且不应以下划线开头。按照惯例，宏名通常全部大写，单词之间用下划线分隔。

最佳实践

宏名应全部大写，单词之间用下划线分隔。

具有替换文本的对象式宏

当预处理器遇到这条指令时，会在宏标识符和 substitution_text之间建立关联。此后所有出现的宏标识符（在其他预处理器命令中的使用除外）都被替换为 substitution_text。

考虑以下程序：

#include <iostream>

#define MY_NAME "Alex"

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n';

    return 0;
}

预处理器将上述代码转换为以下内容：

// iostream的内容被插入到这里

int main()
{
    std::cout << "My name is: " << "Alex" << '\n';

    return 0;
}

运行时会输出结果 My name is: Alex。

带替换文本的类对象宏曾（在 C 语言中）用于为字面量赋予名称。如今这已无必要，因为 C++ 提供了更好的方法（参见 7.10 —— 跨多个文件共享全局常量（使用内联变量））。带替换文本的类对象宏如今多见于遗留代码中，我们建议尽可能避免使用它们。

最佳实践

除非没有可行的替代方案，否则应避免使用带替换文本的宏。

不带替换文本的类对象宏

对象式宏 也可以定义为不带替换文本的形式。

例如：

#define USE_YEN

这种形式的宏的工作方式正如你所预期：后续出现的该标识符大多都会被移除并替换为空！

这看似毫无用处，而且它 确实无用 用于文本替换。然而，这并非这种指令形式的常见用途。我们稍后就会讨论这种形式的用途。

与带替换文本的类对象宏不同，这种形式的宏通常被认为是可接受的。

条件编译

浮点类型的 条件编译 预处理指令允许你指定在什么条件下某个内容会被编译或不会被编译。条件编译指令有很多种，但我们只介绍最常用的几种： #ifdef， #ifndef、和 #endif。

浮点类型的 #ifdef 预处理指令允许预处理器检查某个标识符是否已通过 #define 定义过。如果是，则位于 #ifdef 和匹配的 #endif 会被编译。否则，这段代码会被忽略。

考虑以下程序：

#include <iostream>

#define PRINT_JOE

int main()
{
#ifdef PRINT_JOE
    std::cout << "Joe\n"; // 由于定义了PRINT_JOE，这段代码将被编译
#endif

#ifdef PRINT_BOB
    std::cout << "Bob\n"; // 由于未定义PRINT_BOB，这段代码将被排除
#endif

    return 0;
}

因为 PRINT_JOE 已被 #define，所以这行 std::cout << "Joe\n" 将会被编译。因为 PRINT_BOB 未被 #define，所以这行 std::cout << "Bob\n" 将会被忽略。

#ifndef 与……相反 #ifdef，因为它允许你检查一个标识符是否已被 没有 被 #define定义。

#include <iostream>

int main()
{
#ifndef PRINT_BOB
    std::cout << "Bob\n";
#endif

    return 0;
}

这个程序会打印“Bob”，因为 PRINT_BOB 从未 #define定义。

代替 #ifdef PRINT_BOB 和 #ifndef PRINT_BOB，你还会看到 #if defined(PRINT_BOB) 和 #if !defined(PRINT_BOB)。它们的功能相同，但使用了更具 C++ 风格的语法。

你可以在课程 0.13 -- What language standard is my compiler using?。

#if 0

条件编译的另一个常见用途是使用 #if 0 来排除一段代码不被编译（就像它在一个注释块中一样）：

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 0 // Don't compile anything starting here
    std::cout << "Bob\n";
    std::cout << "Steve\n";
#endif // until this point

    return 0;
}

上面的代码只打印“Joe”，因为“Bob”和“Steve”被 #if 0 预处理器指令。

这提供了一种方便的“注释掉”包含多行注释的代码的方法（由于多行注释不可嵌套，因此无法使用另一个多行注释来注释掉它们）：

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 0 // Don't compile anything starting here
    std::cout << "Bob\n";
    /* Some
     * multi-line
     * comment here
     */
    std::cout << "Steve\n";
#endif // until this point

    return 0;
}

要临时重新启用被包裹在 #if 0中的代码，你可以将 #if 0 切换到 #if 1：

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 1 // 始终为真，因此以下代码将被编译
    std::cout << "Bob\n";
    /* 一些
     * 多行
     * 注释
     */
    std::cout << "Steve\n";
#endif

    return 0;
}

其他预处理器命令中的宏替换

现在你可能会好奇，对于以下代码：

#define PRINT_JOE

int main()
{
#ifdef PRINT_JOE
    std::cout << "Joe\n"; // 由于定义了PRINT_JOE，这段代码将被编译
#endif

    return 0;
}

由于我们将 PRINT_JOE 定义为空，为什么预处理器没有将 PRINT_JOE 在 #ifdef PRINT_JOE 替换为空并从编译中排除输出语句？

在大多数情况下，当宏标识符被用于另一个预处理器命令中时，不会发生宏替换。

顺便说一句……

这个规则至少有一个例外：大多数形式的 #if 和 #elif 会在预处理器命令内部进行宏替换。

另一个例子：

#define FOO 9 // 这是一个宏替换

#ifdef FOO // 这个FOO不会被替换成9，因为它属于另一个预处理指令的一部分
    std::cout << FOO << '\n'; // 这个FOO会被替换成9，因为它属于普通代码的一部分
#endif

#define 的作用域

指令在编译之前按文件从上到下依次解析。

考虑以下程序：

#include <iostream>

void foo()
{
#define MY_NAME "Alex"
}

int main()
{
	std::cout << "My name is: " << MY_NAME << '\n';

	return 0;
}

尽管看起来 #define MY_NAME “Alex” 是在函数 foo，预处理器不理解像函数这样的C++概念。因此，这个程序的行为与一个……的程序相同 #define MY_NAME “Alex” 被定义在函数之前或紧挨着函数之后 foo。为了避免混淆，通常应该将#define标识符放在函数外部。

因为#include指令会用被包含文件的内容替换自身，所以#include可以将被包含文件中的指令复制到当前文件中。这些指令随后将按顺序处理。

例如，以下代码的行为也与之前的示例相同：

Alex.h：

#define MY_NAME "Alex"

main.cpp:

#include "Alex.h" // copies #define MY_NAME from Alex.h here
#include <iostream>

int main()
{
	std::cout << "My name is: " << MY_NAME << '\n'; // 预处理器将MY_NAME替换为"Alex"

	return 0;
}

一旦预处理器完成处理，该文件中所有定义的标识符都会被丢弃。这意味着指令只在定义点到其所在文件末尾之间有效。在一个文件中定义的指令不会对其他文件产生影响（除非它们被#included到另一个文件中）。例如：

function.cpp：

#include <iostream>

void doSomething()
{
#ifdef PRINT
    std::cout << "Printing!\n";
#endif
#ifndef PRINT
    std::cout << "Not printing!\n";
#endif
}

main.cpp:

void doSomething(); // 函数doSomething()的前向声明

#define PRINT

int main()
{
    doSomething();

    return 0;
}

上述程序将输出：

Not printing!

尽管PRINT定义在 main.cpp，这对……中的任何代码都没有影响 function.cpp （PRINT仅从定义点到main.cpp末尾之间被#define）。这在未来讨论头文件保护时会很重要。
