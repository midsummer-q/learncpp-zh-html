4.3 — 对象大小与sizeof运算符

● 机器译文 课程 4.3 查看英文原文

对象大小

正如你在课程 4.1 -- 基本数据类型简介中了解到的，现代机器上的内存通常组织为字节大小的单元，每个内存字节都有一个唯一地址。到目前为止，将内存视为一堆可以存放和检索信息的小格子或邮箱，以及将变量视为访问这些小格子或邮箱的名称是很有用的。

然而，这个类比在一个方面并不完全正确——大多数对象实际上占用超过1字节的内存。单个对象可能使用1、2、4、8甚至更多连续的内存地址。对象使用的内存量取决于其数据类型。

因为我们通常通过变量名（而不是直接通过内存地址）访问内存，编译器能够向我们隐藏给定对象使用了多少字节的细节。当我们访问某个变量 x 在我们的源代码中，编译器知道需要检索多少字节的数据（基于变量的类型 x），并会输出适当的机器语言代码来为我们处理这个细节。

即便如此，了解对象使用多少内存有几个有用的原因。

首先，对象使用的内存越多，它能保存的信息就越多。

单个位可以容纳2个可能的值，0或1：

一般化来说，一个具有 n 个位（其中n是整数）的对象可以容纳2n (2的n次方，通常也写作2^n)个唯一值。因此，对于一个8位的字节，一个字节大小的对象可以容纳28 (256)个不同的值。一个使用2字节的对象可以容纳2^16（65536）个不同的值！

因此，对象的大小限制了它可以存储的唯一值的数量——使用更多字节的对象可以存储更多唯一值。我们将在进一步讨论整数时深入探讨这一点。

其次，计算机的可用内存是有限的。每当我们定义一个对象时，该对象存在期间会占用一小部分可用内存。由于现代计算机拥有大量内存，这种影响通常可以忽略不计。然而，对于需要大量对象或数据的程序（例如渲染数百万个多边形的游戏），使用1字节对象和8字节对象之间的差异可能非常显著。

关键提示

新程序员往往过于关注优化代码以尽可能少用内存。在大多数情况下，这种优化带来的差异微乎其微。应专注于编写可维护的代码，仅在能够带来实质性收益的时候和地点进行优化。

基本数据类型的大小

下一个显而易见的问题是“给定数据类型的对象占用多少内存？”。也许令人惊讶的是，C++标准并未定义任何基本类型的确切大小（以位为单位）。

相反，标准规定如下：

  • 一个对象必须至少占用1字节（这样每个对象都有不同的内存地址）。
  • 一个字节必须至少为8位。
  • 整型 char， short， int， long、和 long long 的最小大小分别为8、16、16、32和64位。
  • char 和 char8_t 正好是1字节（至少8位）。

术语

当我们谈论类型的大小时，实际上是指该类型实例化对象的大小。

在本教程系列中，我们将通过一些通常适用于现代架构的合理假设来呈现一个简化的视图：

  • 一个字节是8位。
  • 内存是字节可寻址的（我们可以独立访问每个字节的内存）。
  • 浮点支持符合IEEE-754标准。
  • 我们使用的是32位或64位架构。

提示

为了最大可移植性，你不应该假设对象大于指定的最小尺寸。

或者，如果你想假设某个类型具有非最小尺寸（例如int至少 4 字节），你可以使用 static_assert 来让编译器在编译于不满足此假设的架构时构建失败。我们在课程中介绍了如何做到这一点 9.6 -- Assert 和 static_assert。

sizeof 运算符

为了确定特定机器上数据类型的大小，C++ 提供了一个名为 sizeof。这些 sizeof 运算符 sizeof 运算符是一元运算符，它接受一个类型或一个变量，并返回该类型对象的大小（以字节为单位）。

#include <iomanip> // for std::setw (which sets the width of the subsequent output)
#include <iostream>
#include <climits> // for CHAR_BIT

int main()
{
    std::cout << "A byte is " << CHAR_BIT << " bits\n\n";

    std::cout << std::left; // 左对齐输出

    std::cout << std::setw(16) << "bool:" << sizeof(bool) << " bytes\n";
    std::cout << std::setw(16) << "char:" << sizeof(char) << " bytes\n";
    std::cout << std::setw(16) << "short:" << sizeof(short) << " bytes\n";
    std::cout << std::setw(16) << "int:" << sizeof(int) << " bytes\n";
    std::cout << std::setw(16) << "long:" << sizeof(long) << " bytes\n";
    std::cout << std::setw(16) << "long long:" << sizeof(long long) << " bytes\n";
    std::cout << std::setw(16) << "float:" << sizeof(float) << " bytes\n";
    std::cout << std::setw(16) << "double:" << sizeof(double) << " bytes\n";
    std::cout << std::setw(16) << "long double:" << sizeof(long double) << " bytes\n";

    return 0;
}

以下是作者机器上的输出：

bool:           1 bytes
char:           1 bytes
short:          2 bytes
int:            4 bytes
long:           4 bytes
long long:      8 bytes
float:          4 bytes
double:         8 bytes
long double:    8 bytes

你的结果可能因编译器、计算机架构、操作系统、编译设置（32位与64位）等因素而异……

尝试使用 sizeof 对不完整类型（如 void）会导致编译错误。

对于 gcc 用户

如果你没有禁用编译器扩展，gcc 允许 sizeof(void) 返回1而不是产生诊断（Pointer-Arith）。我们将在课程中展示如何禁用编译器扩展 0.10 -- 配置你的编译器：编译器扩展。

你还可以使用 sizeof 运算符对变量名：

#include <iostream>

int main()
{
    int x{};
    std::cout << "x is " << sizeof(x) << " bytes\n";

    return 0;
}

x is 4 bytes

进阶读者

sizeof sizeof 不包括对象所使用的动态分配内存。我们将在后面的课程中讨论动态内存分配。

基本数据类型性能

在现代机器上，基本数据类型的对象速度很快，因此使用或复制这些类型时的性能通常不必担心。

顺便说一句……

你可能会认为占用内存较少的类型比占用内存较多的类型更快。但这并不总是正确的。CPU 通常针对处理特定大小（例如32位）的数据进行了优化，匹配该大小的类型处理可能更快。在这样的机器上，32位 int 可能比16位 short 或8位 char 更快。
