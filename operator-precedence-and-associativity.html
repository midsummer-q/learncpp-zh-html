6.1 — 运算符优先级与结合性

● 机器译文 课程 6.1 查看英文原文

章节介绍

本章建立在第 1.9 -- 字面量和运算符简介课的概念之上。快速回顾如下：

一种 运算 是一个数学过程，涉及零个或多个输入值（称为 操作数），产生一个新值（称为输出值）。要执行的具体操作由一种结构（通常是符号或符号对）表示，称为 operator。

例如，我们在孩提时都学过 2 + 3 等于 5。在这种情况下，字面量 2 和 3 是操作数，而符号 + 是运算符，它告诉我们对操作数应用数学加法以产生新值 5。因为这里只使用了一个运算符，所以这很简单。

在本章中，我们将讨论与运算符相关的主题，并探索 C++ 支持的许多常见运算符。

复合表达式的求值

现在，让我们考虑一个复合表达式，例如 4 + 2 * 3。它应该被分组为 (4 + 2) * 3 ，计算结果为 18，或 4 + (2 * 3) ，计算结果为 10？使用正常的数学优先级规则（规定乘法先于加法），我们知道上述表达式应分组为 4 + (2 * 3) 得到值 10。但编译器如何知道呢？

为了求值一个表达式，编译器必须做两件事：

  • 在编译时，编译器必须解析表达式并确定操作数如何与运算符分组。这是通过优先级和结合性规则完成的，我们稍后将讨论。
  • 在编译时或运行时，操作数被求值，操作被执行以产生结果。

运算符优先级

为了帮助解析复合表达式，所有运算符都被分配了一个优先级级别。具有更高 优先级 级别的运算符首先与操作数分组。

你可以在下表中看到，乘法和除法（优先级级别 5）的优先级级别高于加法和减法（优先级级别 6）。因此，乘法和除法将在加法和减法之前与操作数分组。换句话说， 4 + 2 * 3 将被分组为 4 + (2 * 3)。

运算符结合性

考虑一个复合表达式，如 7 - 4 - 1。它应该被分组为 (7 - 4) - 1 ，计算结果为 2，或 7 - (4 - 1)，计算结果为 4？由于两个减法运算符具有相同的优先级级别，编译器不能仅使用优先级来确定如何分组。

如果两个具有相同优先级级别的运算符在表达式中相邻，运算符的 结合性 告诉编译器是从左到右还是从右到左求值运算符（不是操作数！）。减法具有优先级级别 6，并且优先级级别 6 中的运算符具有从左到右的结合性。因此，该表达式从左到右分组： (7 - 4) - 1。

您应该已经认识其中的一些运算符，例如 +， -， *， /， ()、和 sizeof。然而，除非您有其他编程语言的经验，否则此表中的大多数运算符现在可能对您来说难以理解。这在目前是预料之中的。我们将在本章中介绍其中的许多运算符，其余的将在需要时引入。

问：指数运算符在哪里？

C++ 不包含执行幂运算的运算符（operator^ 在 C++ 中有不同的功能）。我们将在第 6.3 课 -- 余数和幂运算。

注意 operator<< 处理按位左移和插入，而 operator>> 处理按位右移和提取。编译器可以根据操作数的类型确定执行哪个操作。

括号化

由于优先级规则， 4 + 2 * 3 将被分组为 4 + (2 * 3)。但如果我们实际的意思是 (4 + 2) * 3呢？就像在普通数学中一样，在 C++ 中我们可以显式地使用括号来按我们想要的方式设置操作数的分组。这是因为括号具有最高的优先级之一，因此括号通常在其内部的内容之前求值。

使用括号使复合表达式更易于理解

现在考虑一个像 x && y || z这样的表达式。它是求值为 (x && y) || z 或 x && (y || z)？您可以在表中查找，看到 && 优先于 ||。但是有太多的运算符和优先级级别，很难全部记住。而且您不希望总是查找运算符来理解复合表达式如何求值。

为了减少错误并使代码更易于理解（无需参考优先级表），最好将任何非平凡的复合表达式用括号括起来，以明确您的意图。

最佳实践

使用括号来明确非平凡复合表达式应如何求值（即使它们在技术上不是必需的）。

一个好的经验法则是：除了加法、减法、乘法和除法之外，所有内容都用括号括起来。

上述最佳实践还有一个例外：具有单个赋值运算符（且没有逗号运算符）的表达式不需要将赋值的右操作数用括号括起来。

例如：

x = (y + z + w);   // 而不是这样
x = y + z + w;     // 这样做是可以的

x = ((y || z) && w); // 而不是这样
x = (y || z) && w;   // 这样做是可以的

x = (y *= z); // 包含多个赋值的表达式仍然受益于括号

赋值运算符的优先级第二低（只有逗号运算符更低，而且很少使用）。因此，只要只有一个赋值（且没有逗号），我们就知道右操作数会在赋值之前完全求值。

最佳实践

具有单个赋值运算符的表达式不需要将赋值的右操作数用括号括起来。

操作的值计算

C++ 标准使用术语 值计算 来表示表达式中运算符的执行以产生一个值。优先级和结合性规则决定了值计算的顺序。

例如，给定表达式 4 + 2 * 3，由于优先级规则，它分组为 4 + (2 * 3)。值计算 (2 * 3) 必须首先发生，以便值计算 4 + 6 可以完成。

操作数的求值

C++标准（主要）使用术语 求值 来指代操作数的求值（而不是运算符或表达式的求值！）。例如，给定表达式 a + b， a 将被求值以产生某个值，并且 b 将被求值以产生某个值。这些值随后可以用作 operator+ 的操作数进行值计算。

术语

非正式地，我们通常使用术语“求值”来表示整个表达式的求值（值计算），而不仅仅是表达式的操作数。

操作数（包括函数参数）的求值顺序大多未指定

在大多数情况下，操作数和函数参数的求值顺序是未指定的，这意味着它们可以按任何顺序求值。

考虑以下表达式：

a * b + c * d

根据上面的优先级和结合性规则，我们知道这个表达式将被分组，就像我们输入了：

(a * b) + (c * d)

如果 a 等于 1， b 等于 2， c 等于 3、和 d 等于 4，这个表达式将始终计算值 14。

然而，优先级和结合性规则只告诉我们运算符和操作数如何分组以及值计算发生的顺序。它们并没有告诉我们操作数或子表达式求值的顺序。编译器可以自由地以任何顺序求值操作数 a， b， c，或 d 编译器也可以自由地先计算 a * b 或 c * d

对于大多数表达式，这无关紧要。在我们上面的示例表达式中，变量 a， b， c，或 d 以何种顺序求值并不重要：计算出的值始终是 14。这里没有歧义。

但有可能写出求值顺序确实重要的表达式。考虑这个程序，它包含了一个C++新手常犯的错误：

#include <iostream>

int getValue()
{
    std::cout << "Enter an integer: ";

    int x{};
    std::cin >> x;
    return x;
}

void printCalculation(int x, int y, int z)
{
    std::cout << x + (y * z);
}

int main()
{
    printCalculation(getValue(), getValue(), getValue()); // 这一行有歧义

    return 0;
}

如果你运行这个程序并输入 1， 2、和 3，你可能认为这个程序会计算 1 + (2 * 3) 并打印 7。但这假设了 printCalculation() 的参数会按从左到右的顺序求值（因此参数 x 得到值 1， y 得到值 2、和 z 得到值 3）。如果参数按从右到左的顺序求值（因此参数 z 得到值 1， y 得到值 2、和 x 得到值 3），那么程序将打印 5 的别名。

提示

Clang编译器按从左到右的顺序求值参数。GCC编译器按从右到左的顺序求值参数。

如果你想亲自看到这种行为，可以在 Wandbox上操作。粘贴上述程序，进入 1 2 3 在 Stdin 选项卡，选择GCC或Clang，然后编译程序。输出将出现在页面底部（你可能需要向下滚动才能看到）。你会注意到GCC和Clang的输出不同！

上述程序可以通过将对 getValue() 的每次函数调用改为单独的语句来消除歧义：

#include <iostream>

int getValue()
{
    std::cout << "Enter an integer: ";

    int x{};
    std::cin >> x;
    return x;
}

void printCalculation(int x, int y, int z)
{
    std::cout << x + (y * z);
}

int main()
{
    int a{ getValue() }; // 将先执行
    int b{ getValue() }; // 将第二个执行
    int c{ getValue() }; // 将第三个执行

    printCalculation(a, b, c); // 这一行现在没有歧义了

    return 0;
}

在这个版本中， a 将始终具有值 1， b 将具有值 2、和 c 将具有值 3。当求值 printCalculation() 的参数时，参数求值的顺序无关紧要——参数 x 将始终得到值 1， y 将获得值 2、和 z 将获得值 3。此版本将确定性地打印 7。

关键提示

操作数、函数参数和子表达式可以按任意顺序求值。

一个常见的错误是认为运算符优先级和结合性会影响求值顺序。优先级和结合性仅用于确定操作数如何与运算符分组，以及值计算的顺序。

警告

确保你编写的表达式（或函数调用）不依赖于操作数（或参数）的求值顺序。

小测验时间

问题 #1

从日常数学中你知道，括号内的表达式会先被求值。例如，在表达式 (2 + 3) * 4， (2 + 3) 部分先被求值。

对于这个练习，你得到一组没有括号的表达式。使用上表中的运算符优先级和结合性规则，为每个表达式添加括号，以明确编译器将如何求值该表达式。

显示提示

提示：使用上表中的模式列来确定运算符是一元（有一个操作数）还是二元（有两个操作数）。复习课程 1.9 -- 字面量和运算符简介 如果你需要复习一元和二元运算符是什么。

示例问题：x = 2 + 3 % 4

二元运算符 % 的优先级高于运算符 + 或运算符 =，所以它先被求值：

x = 2 + (3 % 4)

二元运算符 + 的优先级高于运算符 =，所以它接下来被求值：

最终答案：x = (2 + (3 % 4))

我们现在不再需要上表来理解这个表达式将如何求值。

a) x = 3 + 4 + 5;

显示答案

二元运算符 + 的优先级高于 =：

x = (3 + 4 + 5);

二元运算符 + 具有从左到右的结合性：

最终答案：x = ((3 + 4) + 5);

b) x = y = z;

显示答案

二元运算符 = 具有从右到左的结合性：

最终答案：x = (y = z);

c) z *= ++y + 5;

显示答案

一元运算符 ++ 具有最高优先级：

z *= (++y) + 5;

二元运算符 + 具有次高优先级：

最终答案：z *= ((++y) + 5);

d) a || b && c || d;

显示答案

二元运算符 && 的优先级高于 ||：

a || (b && c) || d;

二元运算符 || 具有从左到右的结合性：

最终答案：(a || (b && c)) || d;
