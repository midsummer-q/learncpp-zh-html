12.6 — 通过 const 左值引用传递

● 机器译文 课程 12.6 查看英文原文

与只能绑定到可修改左值的非 const 引用不同，const 引用可以绑定到可修改左值、不可修改左值和右值。因此，如果我们将引用参数设为 const，那么它将能够绑定到任何类型的实参：

#include <iostream>

void printRef(const int& y) // y 是一个 const 引用
{
    std::cout << y << '\n';
}

int main()
{
    int x { 5 };
    printRef(x);   // ok: x 是可修改的左值，y 绑定到 x

    const int z { 5 };
    printRef(z);   // ok: z 是不可修改的左值，y 绑定到 z

    printRef(5);   // ok: 5 是右值字面量，y 绑定到临时 int 对象

    return 0;
}

通过 const 引用传递具有与非 const 引用传递相同的主要优点（避免复制实参），同时保证函数不能 不是 更改被引用的值。

例如，以下操作是不允许的，因为 ref 是 const：

void addOne(const int& ref)
{
    ++ref; // 不允许：ref 是 const
}

在大多数情况下，我们不希望函数修改实参的值。

最佳实践

除非有特定理由（例如函数需要更改实参的值），否则优先选择通过 const 引用传递而非通过非 const 引用传递。

现在我们可以理解允许 const 左值引用绑定到右值的动机：如果没有这种能力，就无法将字面量（或其他右值）传递给使用引用传递的函数！

将不同类型的实参传递给 const 左值引用参数

在课程 12.4 -- 对 const 的左值引用中，我们注意到 const 左值引用可以绑定到不同类型的值，只要该值可转换为引用类型。转换会创建一个临时对象，引用参数随后可以绑定到该对象。

允许这样做的主要动机是，我们可以以完全相同的方式将值作为实参传递给值参数或 const 引用参数：

#include <iostream>

void printVal(double d)
{
    std::cout << d << '\n';
}

void printRef(const double& d)
{
    std::cout << d << '\n';
}

int main()
{
    printVal(5); // 5 转换为临时 double，复制到参数 d
    printRef(5); // 5 转换为临时 double，绑定到参数 d
    
    return 0;
}

对于按值传递，我们期望进行复制，因此如果先发生转换（导致额外的复制），这通常不是问题（编译器很可能会优化掉其中一个复制）。

然而，当我们不希望进行复制时，我们通常使用引用传递。 不 如果先发生转换，通常会导致（可能昂贵的）复制，这可能不是最优的。

警告

使用引用传递时，确保实参的类型与引用的类型匹配，否则会导致意外（且可能昂贵）的转换。

混合按值传递和按引用传递

具有多个参数的函数可以单独决定每个参数是按值传递还是按引用传递。

例如：

#include <string>

void foo(int a, int& b, const std::string& c)
{
}

int main()
{
    int x { 5 };
    const std::string s { "Hello, world!" };

    foo(5, x, s);

    return 0;
}

在上面的示例中，第一个实参按值传递，第二个按引用传递，第三个按 const 引用传递。

何时使用按值传递 vs 按引用传递

对于大多数 C++ 初学者来说，选择按值传递还是按引用传递并不十分明显。幸运的是，有一个简单的经验法则在大多数情况下都适用。

  • 基本类型和枚举类型复制成本低，因此通常按值传递。
  • 类类型复制成本可能很高（有时非常显著），因此通常按 const 引用传递。

最佳实践

作为经验法则，基本类型按值传递，类类型按 const 引用传递。

如果不确定该怎么做，请使用 const 引用传递，因为这样不太可能遇到意外行为。

提示

以下是其他一些有趣情况的列表：

以下类型通常按值传递（因为效率更高）：

  • 枚举类型（无作用域和有作用域枚举）。
  • 视图和跨度（例如 std::string_view， std::span)。
  • 模拟引用或（非拥有）指针的类型（例如迭代器， std::reference_wrapper)。
  • 具有值语义的复制成本低的类类型（例如 std::pair 包含基本类型元素， std::optional， std::expected)。

以下情况应使用引用传递：

  • 需要被函数修改的实参。
  • 不可复制的类型（例如 std::ostream)。
  • 复制具有所有权含义且我们希望避免的类型（例如 std::unique_ptr， std::shared_ptr)。
  • 具有虚函数或可能被继承的类型（由于对象切片问题，在课程 25.9 -- 对象切片)。

按值传递与按引用传递的成本 高级

并非所有类类型都需要通过引用传递（例如 std::string_view，它通常按值传递）。你可能想知道为什么我们不把所有东西都通过引用传递。在本节（可选阅读）中，我们将讨论按值传递与按引用传递的成本，并细化何时使用每种方式的最佳实践。

首先，我们需要考虑初始化函数参数的成本。对于按值传递，初始化意味着进行复制。复制对象的成本通常与两件事成正比：

  • 对象的大小。使用更多内存的对象需要更多时间来复制。
  • 任何额外的设置成本。某些类类型在实例化时会进行额外的设置（例如，打开文件或数据库，或分配一定量的动态内存来保存可变大小的对象）。每次复制对象时都必须支付这些设置成本。

另一方面，将引用绑定到对象总是很快的（大约与复制基本类型的速度相同）。

其次，我们需要考虑使用函数参数的成本。在设置函数调用时，编译器可能能够通过将按值传递的参数（如果尺寸较小）的引用或副本放入CPU寄存器（访问速度快）而不是RAM（访问速度慢）来进行优化。

每次使用值参数时，运行程序可以直接访问复制参数的存储位置（CPU寄存器或RAM）。然而，当使用引用参数时，通常有一个额外的步骤。运行程序必须首先直接访问分配给引用的存储位置（CPU寄存器或RAM），以确定正在引用哪个对象。然后才能访问被引用对象的存储位置（在RAM中）。

因此，每次使用值参数是一次CPU寄存器或RAM访问，而每次使用引用参数是一次CPU寄存器或RAM访问加上第二次RAM访问。

第三，编译器有时可以比使用按引用传递的代码更有效地优化使用按值传递的代码。特别是，当存在任何 别名 （两个或多个指针或引用可以访问同一个对象）的可能性时，优化器必须保守。因为按值传递会导致参数值的复制，所以没有别名发生的可能性，从而允许优化器更加激进。

现在我们可以回答为什么我们不把所有东西都通过引用传递的问题：

  • 对于复制成本低的对象，复制成本与绑定成本相似，但访问对象更快，并且编译器可能能够更好地优化。
  • 对于复制成本高的对象，复制成本主导了其他性能考虑。

最后一个问题是，我们如何定义“复制成本低”？这里没有绝对答案，因为这因编译器、用例和架构而异。然而，我们可以制定一个良好的经验法则：如果一个对象使用2个或更少的“字”内存（其中“字”近似于内存地址的大小）并且没有设置成本，那么它复制成本低。

以下程序定义了一个类似函数的宏，可用于判断类型（或对象）是否复制成本低：

#include <iostream>

// 函数式宏，如果类型（或对象）的大小小于或等于
// 两个内存地址的大小，则求值为 true
#define isSmall(T) (sizeof(T) <= 2 * sizeof(void*))

struct S
{
    double a;
    double b;
    double c;
};

int main()
{
    std::cout << std::boolalpha; // 打印 true 或 false 而不是 1 或 0
    std::cout << isSmall(int) << '\n'; // true

    double d {};
    std::cout << isSmall(d) << '\n'; // true
    std::cout << isSmall(S) << '\n'; // false

    return 0;
}

顺便说一句……

我们在这里使用预处理器的类似函数的宏，以便我们可以提供对象或类型名称作为参数（因为C++函数不允许将类型作为参数传递）。

然而，很难知道类类型对象是否有设置成本。最好假设大多数标准库类都有设置成本，除非你知道它们没有。

提示

类型T的对象复制成本低，如果 sizeof(T) <= 2 * sizeof(void*) 并且没有额外的设置成本。

对于函数参数，在大多数情况下优先选择 std::string_view 而不是 const std::string& 在大多数情况下

在现代C++中经常出现的一个问题是：当编写一个具有字符串参数的函数时，参数的类型应该是 const std::string& 或 std::string_view？

在大多数情况下， std::string_view 是更好的选择，因为它可以高效地处理更广泛的参数类型。 std::string_view 参数还允许调用者传入子字符串，而无需先将该子字符串复制到自己的字符串中。

void doSomething(const std::string&);
void doSomething(std::string_view);   // 大多数情况下首选此方式

在某些情况下，使用 const std::string& 参数可能更合适：

  • 如果你使用的是C++14或更早版本， std::string_view 不可用。
  • 如果你的函数需要调用其他接受C风格字符串或 std::string 参数的函数，那么 const std::string& 可能是更好的选择，因为 std::string_view 不能保证以空字符结尾（C风格字符串函数期望如此），并且不能高效地转换回 std::string。

最佳实践

优先使用 std::string_view （按值）传递字符串，而不是 const std::string&，除非你的函数调用其他需要C风格字符串或 std::string 参数的函数。

为什么 std::string_view 参数比 const std::string& 高级

在C++中，字符串参数通常是 std::string、 std::string_view，或C风格字符串/字符串字面量。

提醒：

  • 如果参数的类型与对应形参的类型不匹配，编译器会尝试将参数隐式转换为形参的类型。
  • 转换值会创建一个转换类型的临时对象。
  • 创建（或复制）一个 std::string_view 是廉价的，因为 std::string_view 不会复制它所查看的字符串。
  • 创建（或复制）一个 std::string 可能很昂贵，因为每个 std::string 对象都会复制字符串。

下表显示了当我们尝试传递每种类型时会发生什么：

参数类型std::string_view 形参const std::string& 形参
std::string廉价转换廉价引用绑定
std::string_view廉价复制昂贵的显式转换为 std::string
C风格字符串/字面量廉价转换昂贵转换

对于 std::string_view 值形参：

  • 如果我们传入一个 std::string 参数，编译器会将 std::string 转换为 std::string_view，这是廉价的，所以没问题。
  • 如果我们传入一个 std::string_view 参数，编译器会将参数复制到形参中，这是廉价的，所以没问题。
  • 如果我们传入C风格字符串或字符串字面量，编译器会将其转换为 std::string_view，这是廉价的，所以没问题。

如你所见， std::string_view 廉价地处理了所有三种情况。

对于 const std::string& 引用形参：

  • 如果我们传入一个 std::string 参数，形参将引用绑定到参数，这是廉价的，所以没问题。
  • 如果我们传入一个 std::string_view 参数，编译器会拒绝进行隐式转换，并产生编译错误。我们可以使用 static_cast 进行显式转换（转换为 std::string），但这种转换是昂贵的（因为 std::string 会复制所查看的字符串）。转换完成后，形参将引用绑定到结果，这是廉价的。但我们已经为了转换进行了昂贵的复制，所以这并不好。
  • 如果我们传入C风格字符串或字符串字面量，编译器会将其隐式转换为 std::string，这是昂贵的。所以这也不好。

因此，一个 const std::string& 形参只廉价地处理 std::string 参数。

同样的内容，以代码形式呈现：

#include <iostream>
#include <string>
#include <string_view>

void printSV(std::string_view sv)
{
    std::cout << sv << '\n';
}

void printS(const std::string& s)
{
    std::cout << s << '\n';
}

int main()
{
    std::string s{ "Hello, world" };
    std::string_view sv { s };

    // 传递给 `std::string_view` 参数
    printSV(s);              // ok: 从 std::string 到 std::string_view 的廉价转换
    printSV(sv);             // ok: std::string_view 的廉价复制
    printSV("Hello, world"); // ok: C 风格字符串字面量到 std::string_view 的廉价转换

    // 传递给 `const std::string&` 参数
    printS(s);              // ok: 廉价绑定到 std::string 实参
    printS(sv);             // 编译错误：无法隐式将 std::string_view 转换为 std::string
    printS(static_cast<std::string>(sv)); // 糟糕：创建 std::string 临时对象代价高昂
    printS("Hello, world"); // 糟糕：创建 std::string 临时对象代价高昂

    return 0;
}

此外，我们还需要考虑在函数内部访问参数的成本。因为 std::string_view 参数是一个普通对象，可以直接访问被查看的字符串。访问 std::string& 参数需要额外一步才能到达被引用的对象，然后才能访问字符串。

最后，如果我们想传入现有字符串（任意类型）的子串，创建 std::string_view 子串相对便宜，然后可以廉价地传递给 std::string_view 参数。相比之下，将子串传递给 const std::string& 更昂贵，因为子串必须在某个时刻被复制到 std::string 引用参数所绑定的
