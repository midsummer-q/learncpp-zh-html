12.5 — 通过左值引用传递

● 机器译文 课程 12.5 查看英文原文

在前面的课程中，我们介绍了左值引用（12.3 -- 左值引用）和指向 const 的左值引用（12.4 -- 对 const 的左值引用）。单独来看，它们似乎没什么用——既然可以直接使用变量，为什么还要创建别名呢？

在本课中，我们终于要揭示引用的用途。从本章后面开始，你会经常看到引用的使用。

首先，一些背景知识。在课程 2.4 -- 函数参数和实参简介 中，我们讨论了 pass by value，即传递给函数的实参被复制到函数的形参中：

#include <iostream>

void printValue(int y)
{
    std::cout << y << '\n';
} // y 在这里被销毁

int main()
{
    int x { 2 };

    printValue(x); // x 按值传递（复制）到参数 y（开销小）

    return 0;
}

在上面的程序中，当 printValue(x) 时， x (2）被 复制 复制到形参 y。然后，在函数结束时，对象 y 被销毁后，它也能拥有一个可用的值。

这意味着当我们调用函数时，我们复制了实参的值，仅仅短暂使用后就销毁了它！幸运的是，由于基础类型复制成本低，这不是问题。

有些对象复制成本高

标准库提供的大多数类型（如 std::string）都是类类型。类类型通常复制成本高。只要可能，我们希望避免不必要的复制那些复制成本高的对象，尤其是当我们几乎立即销毁这些副本时。

考虑以下程序说明这一点：

#include <iostream>
#include <string>

void printValue(std::string y)
{
    std::cout << y << '\n';
} // y 在这里被销毁

int main()
{
    std::string x { "Hello, world!" }; // x 是一个 std::string

    printValue(x); // x 按值传递（复制）到参数 y（开销大）

    return 0;
}

这会打印

Hello, world!

虽然这个程序的行为符合预期，但它效率低下。与前面的例子相同，当调用 printValue() 时，实参 x 被复制到 printValue() 形参 y。然而，在这个例子中，实参是 std::string 而不是 int、和 std::string 是一个复制成本高的类类型。每次调用 printValue() 时都会进行这种昂贵的复制！

我们可以做得更好。

通过引用传递

避免在调用函数时复制昂贵实参的一种方法是使用 pass by reference 而不是 pass by value。当使用 通过引用传递时，我们将函数形参声明为引用类型（或 const 引用类型），而不是普通类型。当函数被调用时，每个引用形参都绑定到相应的实参。由于引用充当实参的别名，因此不会复制实参。

下面是上面的相同示例，使用通过引用传递而不是通过值传递：

#include <iostream>
#include <string>

void printValue(std::string& y) // 类型改为 std::string&
{
    std::cout << y << '\n';
} // y 在这里被销毁

int main()
{
    std::string x { "Hello, world!" };

    printValue(x); // x 现在按引用传递到引用参数 y（开销小）

    return 0;
}

这个程序与之前的相同，只是形参 y 的类型从 std::string 切换到 std::string& （一个左值引用）。现在，当调用 printValue(x) 时，左值引用形参 y 绑定到实参 x。绑定引用总是成本低廉，并且不会复制 x 需要被做出。因为引用作为被引用对象的别名，当 printValue() 使用引用 y时，它访问的是实际的实参 x （而不是实参的副本 x)。

关键提示

按引用传递允许我们将实参传递给函数，而无需在每次调用函数时复制这些实参。

以下程序演示了值参数是与实参分离的对象，而引用参数则被视为实参本身：

#include <iostream>

void printAddresses(int val, int& ref)
{
    std::cout << "The address of the value parameter is: " << &val << '\n';
    std::cout << "The address of the reference parameter is: " << &ref << '\n';   
}

int main()
{
    int x { 5 };
    std::cout << "The address of x is: " << &x << '\n';
    printAddresses(x, x);

    return 0;
}

该程序的一次运行产生了以下输出：

The address of x is: 0x7ffd16574de0
The address of the value parameter is: 0x7ffd16574de4
The address of the reference parameter is: 0x7ffd16574de0

我们可以看到实参与值参数具有不同的地址，这意味着值参数是一个不同的对象。由于它们拥有独立的内存地址，为了使值参数与实参具有相同的值，必须将实参的值复制到值参数所持有的内存中。

另一方面，我们可以看到取引用参数的地址得到的地址与实参的地址相同。这意味着引用参数被视为与实参相同的对象。

按引用传递允许我们改变实参的值

当对象按值传递时，函数参数接收实参的一个副本。这意味着对参数值的任何修改都是对实参副本的修改，而不是对实参本身的修改：

#include <iostream>

void addOne(int y) // y 是 x 的副本
{
    ++y; // 这修改的是 x 的副本，而不是实际对象 x
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x 没有被修改

    return 0;
}

在上面的程序中，因为值参数 y 是 x的一个副本，当我们递增 y时，这只影响 y。该程序输出：

value = 5
value = 5

然而，由于引用与被引用的对象行为相同，当使用按引用传递时，对引用参数所做的任何修改都会 会 影响实参：

#include <iostream>

void addOne(int& y) // y 绑定到实际对象 x
{
    ++y; // 这会修改实际对象 x
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x 已被修改

    return 0;
}

此程序输出：

value = 5
value = 6

在上面的例子中， x 初始值为 5。当 addOne(x) 被调用时，引用参数 y 绑定到实参 x。当 addOne() 函数递增引用 y时，它实际上是在递增实参 x 从 5 切换到 6 （而不是 x的副本）。这个改变后的值即使在 addOne() 执行完毕后也是如此。

关键提示

之后仍然存在。按非const引用传递值允许我们编写能够修改传入实参值的函数。

函数修改传入实参值的能力可能很有用。想象你编写了一个函数，用于判断怪物是否成功攻击了玩家。如果是，怪物应该对玩家的生命值造成一定伤害。如果你通过引用传递玩家对象，函数可以直接修改传入的实际玩家对象的生命值。如果你按值传递玩家对象，你只能修改玩家对象副本的生命值，这就不那么有用了。

按引用传递只能接受可修改的左值实参

因为对非const值的引用只能绑定到可修改的左值（本质上是一个非const变量），这意味着按引用传递只适用于可修改的左值实参。实际上，这极大地限制了按非const引用传递的实用性，因为它意味着我们不能传递const变量或字面量。例如：

#include <iostream>

void printValue(int& y) // y 只接受可修改的左值
{
    std::cout << y << '\n';
}

int main()
{
    int x { 5 };
    printValue(x); // ok: x 是可修改的左值

    const int z { 5 };
    printValue(z); // 错误: z 是不可修改的左值

    printValue(5); // 错误: 5 是右值

    return 0;
}

幸运的是，有一个简单的方法可以解决这个问题，我们将在下一课中讨论。我们还将探讨何时按值传递与按引用传递。
