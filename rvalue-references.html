22.2 — 右值引用

● 机器译文 课程 22.2 查看英文原文

在第12章中，我们介绍了值类别（12.2 -- Value categories (lvalues and rvalues)）的概念，它是表达式的一个属性，有助于确定表达式解析为值、函数还是对象。我们还介绍了左值和右值，以便讨论左值引用。

如果你对左值和右值不太清楚，现在最好复习一下这个主题，因为本章我们将大量讨论它们。

左值引用回顾

在C++11之前，C++中只存在一种引用类型，因此它被称为“引用”。然而，在C++11中，它被称为左值引用。左值引用只能用可修改的左值初始化。

指向const对象的左值引用可以用可修改和不可修改的左值以及右值初始化。但是，这些值不能被修改。

指向const对象的左值引用特别有用，因为它们允许我们将任何类型的参数（左值或右值）传递给函数，而无需复制参数。

右值引用

C++11增加了一种新的引用类型，称为右值引用。右值引用是一种设计为只能用右值初始化的引用。左值引用使用单个&创建，而右值引用使用双&&创建：

int x{ 5 };
int& lref{ x }; // 左值引用用左值 x 初始化
int&& rref{ 5 }; // 右值引用用右值 5 初始化

右值引用不能用左值初始化。

右值引用有两个有用的属性。首先，右值引用将初始化它的对象的生命周期延长到右值引用的生命周期（指向const的左值引用也可以做到这一点）。其次，非const右值引用允许你修改右值！

让我们看一些例子：

#include <iostream>
 
class Fraction
{
private:
	int m_numerator { 0 };
	int m_denominator { 1 };
 
public:
	Fraction(int numerator = 0, int denominator = 1) :
		m_numerator{ numerator }, m_denominator{ denominator }
	{
	}
 
	friend std::ostream& operator<<(std::ostream& out, const Fraction& f1)
	{
		out << f1.m_numerator << '/' << f1.m_denominator;
		return out;
	}
};
 
int main()
{
	auto&& rref{ Fraction{ 3, 5 } }; // 指向临时 Fraction 的右值引用
	
	// operator<< 的 f1 绑定到临时对象，没有创建副本。
	std::cout << rref << '\n';
 
	return 0;
} // rref（以及临时 Fraction）在此处离开作用域

该程序打印出：

3/5

作为一个匿名对象，Fraction(3, 5)通常会在定义它的表达式结束时超出作用域。但是，由于我们用右值引用初始化它，它的持续时间被延长到块结束。然后我们可以使用该右值引用来打印Fraction的值。

现在让我们看一个不太直观的例子：

#include <iostream>

int main()
{
    int&& rref{ 5 }; // 因为我们要用字面量初始化右值引用，所以在此处创建了一个值为 5 的临时对象
    rref = 10;
    std::cout << rref << '\n';

    return 0;
}

该程序打印出：

10

虽然用字面量初始化右值引用然后能够更改该值可能看起来很奇怪，但当用字面量初始化右值引用时，会从字面量构造一个临时对象，以便引用引用的是临时对象，而不是字面量值。

右值引用并不经常以上述两种方式使用。

右值引用作为函数参数

右值引用更常用作函数参数。当你想对左值和右值参数有不同的行为时，这对于函数重载最有用。

#include <iostream>

void fun(const int& lref) // 左值实参将选择此函数
{
	std::cout << "l-value reference to const: " << lref << '\n';
}

void fun(int&& rref) // 右值实参将选择此函数
{
	std::cout << "r-value reference: " << rref << '\n';
}

int main()
{
	int x{ 5 };
	fun(x); // 左值实参调用函数的左值版本
	fun(5); // 右值实参调用函数的右值版本

	return 0;
}

这会打印：

l-value reference to const: 5
r-value reference: 5

如你所见，当传递左值时，重载函数解析为带有左值引用的版本。当传递右值时，重载函数解析为带有右值引用的版本（这被认为比指向const的左值引用更匹配）。

为什么你会想这样做？我们将在下一课中更详细地讨论。不用说，这是移动语义的重要组成部分。

右值引用变量是左值

考虑以下代码片段：

	int&& ref{ 5 };
	fun(ref);

你期望上面的代码调用哪个版本的 fun ： fun(const int&) 或 fun(int&&)？

答案可能会让你惊讶。这调用了 fun(const int&)。

尽管变量 ref 的类型为 int&&，当在表达式中使用时，它是一个左值（所有命名变量都是左值）。对象的类型和它的值类别是独立的。

你已经知道字面量 5 是类型为 int、和 int x 是类型为 int的左值。类似地， int&& ref 是类型为 int&&。

所以不仅 fun(ref) 调用 fun(const int&)，它甚至不匹配 fun(int&&)，因为右值引用不能绑定到左值。

返回右值引用

你几乎永远不应该返回右值引用，原因与你几乎永远不应该返回左值引用相同。在大多数情况下，当被引用的对象在函数结束时离开作用域，你最终会返回一个悬空引用。

小测验时间

问题 #1

指出下列带字母的语句中哪些无法编译：

int main()
{
	int x{};

	// 左值引用
	int& ref1{ x }; // A
	int& ref2{ 5 }; // B

	const int& ref3{ x }; // C
	const int& ref4{ 5 }; // D

	// 右值引用
	int&& ref5{ x }; // E
	int&& ref6{ 5 }; // F

	const int&& ref7{ x }; // G
	const int&& ref8{ 5 }; // H
	
	return 0;
}

显示答案

B、E 和 G 无法编译。

回顾绑定组合：

  • 非 const 左值引用只能绑定到非 const 左值。
  • const 左值引用可以绑定到非 const 左值、const 左值和右值。
  • 右值引用只能绑定到右值。

x 是一个非 const 左值，因此我们可以将非 const 左值引用 (A) 和 const 左值引用 (C) 绑定到它。我们不能将非 const 左值引用绑定到右值 (B)。
5 是一个右值，因此我们可以将 const 左值引用 (D) 和右值引用 (F & H) 绑定到它。我们不能将右值引用绑定到左值 (E & G)。
