15.6 — 静态成员变量

● 机器译文 课程 15.6 查看英文原文

在课程 7.4 -- 全局变量简介中，我们介绍了全局变量，在课程 7.11 -- 静态局部变量中，我们介绍了静态局部变量。这两种变量都具有静态存储期，意味着它们在程序开始时创建，在程序结束时销毁。即使它们离开作用域，也会保留其值。

例如：

#include <iostream>

int generateID()
{
    static int s_id{ 0 }; // 静态局部变量
    return ++s_id;
}

int main()
{
    std::cout << generateID() << '\n';
    std::cout << generateID() << '\n';
    std::cout << generateID() << '\n';

    return 0;
}

该程序打印出：

1
2
3

注意，静态局部变量 s_id 在多次函数调用中保持了它的值。

类类型为 static 关键字带来了另外两种用途：静态成员变量和静态成员函数。幸运的是，这些用途相当直接。我们将在本节课讨论静态成员变量，下一节课讨论静态成员函数。

静态成员变量

在我们将 static 关键字应用于成员变量之前，先考虑以下类：

定义和初始化静态成员变量 1。如果没有提供初始化器，静态成员变量默认会被零初始化。

注意，这个静态成员定义不受访问控制的约束：即使它在类中被声明为私有（或保护），你也可以定义并初始化它的值（因为定义不被视为一种访问形式）。

对于非模板类，如果类定义在头文件（.h）中，静态成员定义通常放在该类的关联代码文件中（例如 Something.cpp）。或者，成员也可以定义为 inline 并放在头文件中类定义的下方（这对于仅头文件的库很有用）。如果类定义在源文件（.cpp）中，静态成员定义通常直接放在类定义的下方。不要将静态成员定义放在头文件中（就像全局变量一样，如果该头文件被多次包含，会导致多重定义，从而引发链接器错误）。

对于模板类，（模板化的）静态成员定义通常直接放在头文件中模板类定义的下方（这不会违反ODR，因为这样的定义是隐式内联的）。

在类定义内部初始化静态成员变量

对于上述情况，有一些捷径。首先，当静态成员是常量整型（包括 char 和 bool）或const枚举时，静态成员可以在类定义内部初始化：

class Whatever
{
public:
    static const int s_value{ 4 }; // 静态 const int 可以直接定义并初始化
};

在上面的例子中，因为静态成员变量是const int，所以不需要显式的定义行。这个捷径是允许的，因为这些特定的const类型是编译时常量。

在课程 7.10 —— 跨多个文件共享全局常量（使用内联变量），我们引入了内联变量，即允许有多个定义的变量。C++17允许静态成员成为内联变量：

class Whatever
{
public:
    static inline int s_value{ 4 }; // 静态内联变量可以直接定义并初始化
};

这样的变量可以在类定义内部初始化，无论它们是否为常量。这是定义和初始化静态成员的首选方法。

因为 constexpr 成员是隐式内联的（自C++17起），静态 constexpr 成员也可以在类定义内部初始化，而无需显式使用 inline 关键字成为常量：

#include <string_view>

class Whatever
{
public:
    static constexpr double s_value{ 2.2 }; // ok
    static constexpr std::string_view s_view{ "Hello" }; // 这甚至适用于支持 constexpr 初始化的类
};

最佳实践

让你的静态成员 inline 或 constexpr ，这样它们就可以在类定义内部初始化。

静态成员变量的示例

为什么在类中使用静态变量？一个用途是为类的每个实例分配唯一的ID。下面是一个例子：

#include <iostream>

class Something
{
private:
    static inline int s_idGenerator { 1 };
    int m_id {};

public:
    // 从 id 生成器中获取下一个值
    Something() : m_id { s_idGenerator++ } 
    {    
    }

    int getID() const { return m_id; }
};

int main()
{
    Something first{};
    Something second{};
    Something third{};

    std::cout << first.getID() << '\n';
    std::cout << second.getID() << '\n';
    std::cout << third.getID() << '\n';
    return 0;
}

该程序打印出：

1
2
3

因为 s_idGenerator 被所有 Something 对象共享，当创建一个新的 Something 对象时，构造函数将 m_id 初始化为当前值 s_idGenerator ，然后递增该值以供下一个对象使用。这保证了每个实例化的 Something 对象获得唯一的id（按创建顺序递增）。

给每个对象一个唯一的ID有助于调试，因为它可以用来区分具有相同数据的对象。在处理数据数组时尤其如此。

当类需要使用查找表（例如，用于存储一组预计算值的数组）时，静态成员变量也很有用。通过将查找表设为静态，所有对象只存在一个副本，而不是为每个实例化的对象创建一个副本。这可以节省大量内存。

只有静态成员可以使用类型推导（auto 和CTAD）

静态成员可以使用 auto 从初始化器推导其类型，或使用类模板参数推导（CTAD）从初始化器推导模板类型参数。

非静态成员不能使用 auto 或CTAD。

做出这种区分的原因相当复杂，但归结为某些非静态成员可能出现的情况会导致歧义或非直观的结果。静态成员不会出现这种情况。因此，非静态成员被限制使用这些特性，而静态成员则不受限制。

#include <utility> // for std::pair<T, U>

class Foo
{
private:
    auto m_x { 5 };           // 非静态成员不允许使用 auto
    std::pair m_v { 1, 2.3 }; // 非静态成员不允许使用 CTAD

    static inline auto s_x { 5 };           // 静态成员允许使用 auto
    static inline std::pair s_v { 1, 2.3 }; // 静态成员允许使用 CTAD

public:
    Foo() {};
};

int main()
{
    Foo foo{};
    
    return 0;
}
