27.10 — std::move_if_noexcept

● 机器译文 课程 27.10 查看英文原文

（感谢读者Koe为本课提供初稿！）

在课程 22.4 -- std::move，我们介绍了 std::move，它将左值参数转换为右值，以便我们可以调用移动语义。在课程 27.9 -- 异常规范和 noexcept中，我们介绍了 noexcept 异常说明符和运算符。本课程将基于这两个概念进行构建。

我们还介绍了 strong exception guarantee，它保证如果函数被异常中断，不会发生内存泄漏，并且程序状态不会改变。特别是，所有构造函数都应遵守强异常保证，这样如果对象构造失败，程序的其余部分就不会处于改变的状态。

移动构造函数的异常问题

考虑我们正在复制某个对象的情况，并且由于某种原因（例如机器内存不足）复制失败。在这种情况下，被复制的对象不会受到任何损害，因为源对象不需要修改即可创建副本。我们可以丢弃失败的副本，然后继续。 strong exception guarantee 得到了维护。

现在考虑我们正在移动对象的情况。移动操作将给定资源的所有权从源对象转移到目标对象。如果在所有权转移后移动操作被异常中断，那么我们的源对象将处于修改状态。如果源对象是临时对象并且无论如何都会在移动后被丢弃，这不是问题——但对于非临时对象，我们已经损坏了源对象。为了遵守 strong exception guarantee，我们需要将资源移回源对象，但如果第一次移动失败，也无法保证移回会成功。

我们如何给移动构造函数提供 strong exception guarantee？避免在移动构造函数体中抛出异常很简单，但移动构造函数可能调用其他 potentially throwing的构造函数。以 std::pair的移动构造函数为例，它必须尝试将源pair中的每个子对象移动到新的pair对象中。

// std::pair 的移动构造函数示例定义
// 接收一个'旧'pair，然后从'旧'的pair中移动构造新pair的'first'和'second'子对象
template <typename T1, typename T2>
pair<T1,T2>::pair(pair&& old)
  : first(std::move(old.first)),
    second(std::move(old.second))
{}

现在让我们使用两个类， MoveClass 和 CopyClass，我们将它们 pair 在一起，以演示移动构造函数的 strong exception guarantee 问题：

#include <iostream>
#include <utility> // For std::pair, std::make_pair, std::move, std::move_if_noexcept
#include <stdexcept> // std::runtime_error

class MoveClass
{
private:
  int* m_resource{};

public:
  MoveClass() = default;

  MoveClass(int resource)
    : m_resource{ new int{ resource } }
  {}

  // 拷贝构造函数
  MoveClass(const MoveClass& that)
  {
    // 深拷贝
    if (that.m_resource != nullptr)
    {
      m_resource = new int{ *that.m_resource };
    }
  }

  // 移动构造函数
  MoveClass(MoveClass&& that) noexcept
    : m_resource{ that.m_resource }
  {
    that.m_resource = nullptr;
  }

  ~MoveClass()
  {
    std::cout << "destroying " << *this << '\n';

    delete m_resource;
  }

  friend std::ostream& operator<<(std::ostream& out, const MoveClass& moveClass)
  {
    out << "MoveClass(";

    if (moveClass.m_resource == nullptr)
    {
      out << "empty";
    }
    else
    {
      out << *moveClass.m_resource;
    }

    out << ')';
    
    return out;
  }
};


class CopyClass
{
public:
  bool m_throw{};

  CopyClass() = default;

  // 当从 m_throw 为 'true' 的 CopyClass 对象复制时，复制构造函数抛出异常
  // 当从 m_throw 为 'true' 的 CopyClass 对象复制时，复制构造函数抛出异常
  CopyClass(const CopyClass& that)
    : m_throw{ that.m_throw }
  {
    if (m_throw)
    {
      throw std::runtime_error{ "abort!" };
    }
  }
};

int main()
{
  // 我们可以毫无问题地创建一个 std::pair：
  std::pair my_pair{ MoveClass{ 13 }, CopyClass{} };

  std::cout << "my_pair.first: " << my_pair.first << '\n';

  // 但当我们尝试将该pair移动到另一个pair时，问题就出现了。
  try
  {
    my_pair.second.m_throw = true; // 触发复制构造函数异常

    // 下面一行将抛出异常
    std::pair moved_pair{ std::move(my_pair) }; // 我们稍后会注释掉这一行
    // std::pair moved_pair{ std::move_if_noexcept(my_pair) }; // 我们稍后会取消注释这一行

    std::cout << "moved pair exists\n"; // 永远不会打印
  }
  catch (const std::exception& ex)
  {
      std::cerr << "Error found: " << ex.what() << '\n';
  }

  std::cout << "my_pair.first: " << my_pair.first << '\n';

  return 0;
}

上面的程序打印：

destroying MoveClass(empty)
my_pair.first: MoveClass(13)
destroying MoveClass(13)
Error found: abort!
my_pair.first: MoveClass(empty)
destroying MoveClass(empty)

让我们探讨发生了什么。第一行打印显示用于初始化 MoveClass 的临时 my_pair 对象在 my_pair 实例化语句执行后立即被销毁。它是 empty ，因为 MoveClass 中的 my_pair 子对象是从它移动构造的，下一行显示 my_pair.first 包含值为 MoveClass 的 13。

对象，这证明了这一点。第三行变得有趣。我们通过复制构造其 moved_pair 子对象创建了 CopyClass （它没有移动构造函数），但由于我们更改了布尔标志，该复制构造抛出了异常。 moved_pair 的构造被异常中止，其已构造的成员被销毁。在这种情况下， MoveClass 成员被销毁，打印 destroying MoveClass(13) variable。接下来我们看到 Error found: abort! 打印的消息 main()。

当我们再次尝试打印 my_pair.first 时，它显示 MoveClass 成员为空。由于 moved_pair 是用 std::move， MoveClass 成员（它有移动构造函数）被移动构造，并且 my_pair.first 被置空了。

最后， my_pair 在 main() 结束时被销毁。

总结上述结果： std::pair 的移动构造函数使用了 CopyClass的会抛异常的拷贝构造函数。这个拷贝构造函数抛出了一个异常，导致 moved_pair 的创建中止，并且 my_pair.first 被永久损坏。 strong exception guarantee 没有被保留。

std::move_if_noexcept 来救场

注意，如果 std::pair 尝试进行拷贝而不是移动，上述问题本可以避免。那样的话， moved_pair 会构造失败，但 my_pair 不会被改变。

但是拷贝代替移动会带来性能开销，我们不想为所有对象付出这个代价——理想情况下，我们希望在安全时进行移动，否则进行拷贝。

幸运的是，C++ 有两种机制，结合使用时可以精确实现这一点。首先，因为 noexcept 函数是 noexcept/no-fail 的，它们隐式满足 strong exception guarantee的条件。因此，一个 noexcept 移动构造函数保证成功。

其次，我们可以使用标准库函数 std::move_if_noexcept() 来决定应该执行移动还是拷贝。 std::move_if_noexcept 是 std::move的对应物，使用方式相同。

如果编译器能判断出作为参数传递给 std::move_if_noexcept 的对象在移动构造时不会抛出异常（或者该对象是只移动的且没有拷贝构造函数），那么 std::move_if_noexcept 的行为与 std::move() 完全相同（并返回转换为右值的对象）。否则， std::move_if_noexcept 将返回对象的普通左值引用。

关键提示

std::move_if_noexcept 如果对象具有 noexcept 移动构造函数，则返回可移动的右值，否则返回可拷贝的左值。我们可以将 noexcept 说明符与 std::move_if_noexcept 结合使用，仅在存在强异常保证时使用移动语义（否则使用拷贝语义）。

让我们将前一个示例中的代码更新如下：

//std::pair moved_pair{std::move(my_pair)}; // 现在注释掉这一行
std::pair moved_pair{std::move_if_noexcept(my_pair)}; // 并取消注释这一行

再次运行程序输出：

destroying MoveClass(empty)
my_pair.first: MoveClass(13)
destroying MoveClass(13)
Error found: abort!
my_pair.first: MoveClass(13)
destroying MoveClass(13)

如您所见，异常抛出后，子对象 my_pair.first 仍然指向值 13。

的移动构造函数不是 std::pair （截至 C++20），所以 noexcept 返回 std::move_if_noexcept 返回 my_pair 作为左值引用。这导致 moved_pair 通过拷贝构造函数（而不是移动构造函数）创建。拷贝构造函数可以安全地抛出异常，因为它不会修改源对象。

标准库使用 std::move_if_noexcept 通常为了优化那些 noexcept。例如， std::vector::resize 如果元素类型有移动构造函数，则会使用移动语义，否则使用复制语义。这意味着 noexcept 通常对于具有移动构造函数的对象，操作会更快。 std::vector 通常对于具有移动构造函数的对象，操作会更快。 noexcept 移动构造函数。

警告

如果某个类型同时具有可能抛异常的移动语义和已删除的复制语义（复制构造函数和复制赋值运算符不可用），那么 std::move_if_noexcept 将放弃强保证并调用移动语义。这种对强保证的条件性放弃在标准库容器类中普遍存在，因为它们经常使用 std::move_if_noexcept。
