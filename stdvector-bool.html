16.12 — std::vector<bool>

● 机器译文 课程 16.12 查看英文原文

在课程 O.1 -- 位标志和通过std::bitset进行位操作中，我们讨论了 std::bitset 能够将8个布尔值压缩到一个字节中。这些位随后可以通过成员函数进行修改。 std::bitset。

std::vector 有一个有趣的技巧。对于 std::vector<bool> 有一个特殊的实现，它可能通过类似地将8个布尔值压缩到一个字节中，从而在空间上更高效。

进阶读者

当模板类针对特定的模板类型参数有不同的实现时，这被称为 类模板特化。我们将在课程 26.4 -- 类模板特化。

与 std::bitset中进一步讨论这个主题。，它专为位操作设计， std::vector<bool> 缺少位操作成员函数。

使用 std::vector<bool>

在大多数情况下， std::vector<bool> 的工作方式与普通的 std::vector：

#include <iostream>
#include <vector>

int main()
{
    std::vector<bool> v { true, false, false, true, true };
    
    for (int i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // 将索引4的布尔值改为false
    v[4] = false;

    for (int i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

类似。在作者的64位机器上，输出如下：

1 0 0 1 1
1 0 0 1 0

std::vector<bool> 权衡

然而， std::vector<bool> 有一些用户应该注意的权衡。

首先， std::vector<bool> 有相当高的开销（sizeof(std::vector<bool>) 在作者的机器上是40字节），所以除非你分配的布尔值数量超过架构的开销，否则你不会节省内存。

其次， std::vector<bool> 的性能高度依赖于实现（因为实现甚至不需要进行优化，更不用说优化得好）。根据 这篇文章，高度优化的实现可能比替代方案快得多。然而，优化不佳的实现会更慢。

第三，也是最重要的一点， std::vector<bool> 不是一个向量（它不要求在内存中连续），也不存储 bool 值（它存储的是位集合），也不符合C++对容器的定义。

尽管 std::vector<bool> 在大多数情况下表现得像向量，但它不能完全与标准库的其他部分兼容。与其他元素类型一起工作的代码可能无法与 std::vector<bool>。

一起工作。例如，以下代码在 T 是除 bool：

template<typename T>
void foo( std::vector<T>& v )
{
    T& first = v[0]; // 获取第一个元素的引用
    // 对first进行操作
}

不幸的是，这个优化版本的 std::vector<bool> 默认是启用的，并且没有办法禁用它以使用非优化版本（后者才是真正的容器）。已经有人呼吁弃用 std::vector<bool>，并且正在努力确定一个替代的压缩向量 bool 可能是什么样子（也许作为未来的 std::dynamic_bitset)。

）。我们的建议如下：

  • 当需要的位数在编译时已知，且布尔值数量不多（例如少于64k），并且有限的运算符和成员函数（例如缺乏迭代器支持）满足你的需求时，使用（constexpr） std::bitset
  • 优先使用 std::vector<char> 当你需要一个可调整大小的布尔值容器且空间节省不是必需时使用。这种类型的行为类似于普通容器。
  • 当你需要一个动态位集进行位操作时，优先使用第三方实现的动态位集（例如 boost::dynamic_bitset）。这样的类型不会在不是标准库容器时假装是。

最佳实践

推荐使用 constexpr std::bitset， std::vector<char>，或第三方动态位集，而不是 std::vector<bool>。
