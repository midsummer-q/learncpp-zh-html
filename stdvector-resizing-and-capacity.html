16.10 — std::vector 调整大小与容量

● 机器译文 课程 16.10 查看英文原文

在本章的前几课中，我们介绍了容器、数组和 std::vector。我们还讨论了如何访问数组元素、获取数组长度以及如何遍历数组等主题。虽然我们在示例中使用了 std::vector ，但我们讨论的概念通常适用于所有数组类型。

在本章的剩余课程中，我们将重点讨论使 std::vector 与大多数其他数组类型显著不同的一个特性：在实例化后调整自身大小的能力。

固定大小数组 vs 动态数组

大多数数组类型都有一个显著的限制：数组的长度必须在实例化时已知，之后无法更改。这样的数组称为 固定大小数组 或 固定长度数组。 std::array 和 C-style arrays 都是固定大小数组类型。我们将在下一章进一步讨论它们。

另一方面， std::vector 是一个动态数组。 动态数组 （也称为 可调整大小数组）是一种在实例化后可以改变大小的数组。这种可调整大小的能力正是 std::vector 的特殊之处。

在运行时调整 std::vector 的大小

一个 std::vector 可以在实例化后通过调用 resize() 成员函数并传入新的期望长度来调整大小：

#include <iostream>
#include <vector>

int main()
{
    std::vector v{ 0, 1, 2 }; // 创建包含3个元素的向量
    std::cout << "The length is: " << v.size() << '\n';

    v.resize(5);              // 调整大小为5个元素
    std::cout << "The length is: " << v.size() << '\n';

    for (auto i : v)
        std::cout << i << ' ';

    std::cout << '\n';

    return 0;
}

这会打印：

The length is: 3
The length is: 5
0 1 2 0 0

这里需要注意两点。首先，当我们调整 vector 大小时，现有的元素值被保留了下来！其次，新元素是值初始化的（对于类类型执行默认初始化，对于其他类型执行零初始化）。因此，两个新的 int 类型元素被零初始化为值 0。

Vector 也可以调整为更小：

#include <iostream>
#include <vector>

void printLength(const std::vector<int>& v)
{
	std::cout << "The length is: "	<< v.size() << '\n';
}

int main()
{
    std::vector v{ 0, 1, 2, 3, 4 }; // 长度初始为5
    printLength(v);

    v.resize(3);                    // 调整大小为3个元素
    printLength(v);

    for (int i : v)
        std::cout << i << ' ';

    std::cout << '\n';

    return 0;
}

这会打印：

The length is: 5
The length is: 3
0 1 2

的长度与容量 std::vector

考虑一排 12 栋房子。我们会说房子的数量（或这排房子的长度）是 12。如果我们想知道哪些房子目前有人居住……我们必须通过其他方式来确定（例如按门铃看是否有人应答）。当我们只有长度时，我们只知道有多少东西存在。

现在考虑一个目前有 5 个鸡蛋的蛋托。我们会说鸡蛋的数量是 5。但在这个上下文中，我们关心另一个维度：如果装满，蛋托能装多少个鸡蛋。我们会说蛋托的容量是 12。蛋托有空间放 12 个鸡蛋，但只用了 5 个——因此，我们可以再添加 7 个鸡蛋而不会溢出蛋托。当我们同时拥有长度和容量时，我们可以区分当前存在多少东西以及有多少空间可用。

到目前为止，我们只讨论了 std::vector的长度。但 std::vector 也有容量。在 std::vector， 的上下文中，容量 是指 std::vector 已分配存储空间的元素数量，而 长度 是当前正在使用的元素数量。

一个 std::vector 容量为 5 的 vector 已分配了 5 个元素的空间。如果 vector 包含 2 个正在使用的元素，则 vector 的长度（大小）为 2。其余 3 个元素已分配内存，但不被视为正在使用。它们可以在以后使用而不会导致 vector 溢出。

关键提示

vector 的长度是“正在使用”的元素数量。
vector 的容量是已分配内存的元素数量。

获取 std::vector

的容量 std::vector 我们可以通过 capacity() 成员函数。

例如：

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
	std::cout << "Capacity: " << v.capacity() << " Length:"	<< v.size() << '\n';
}

int main()
{
    std::vector v{ 0, 1, 2 }; // 长度初始为3

    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    v.resize(5); // 调整大小为5个元素

    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

在作者的机器上，这会打印出以下内容：

Capacity: 3  Length: 3
0 1 2
Capacity: 5  Length: 5
0 1 2 0 0

首先，我们用3个元素初始化了vector。这导致vector为3个元素分配存储空间（容量为3），并且所有3个元素都被视为正在使用（长度为3）。

然后我们调用 resize(5)，这意味着我们现在想要一个长度为5的vector。由于vector只有3个元素的存储空间，但它需要5个，因此vector需要获取更多存储空间来容纳额外的元素。

在调用 resize() 完成后，我们可以看到vector现在有5个元素的空间（容量为5），并且所有5个元素现在都被视为正在使用（长度为5）。

大多数情况下你不需要使用 capacity() 函数，但在接下来的示例中我们会大量使用它，以便观察vector存储空间的变化。

存储空间的重新分配及其昂贵的原因

当一个 std::vector 改变其管理的存储量时，这个过程称为 重新分配。非正式地说，重新分配的过程大致如下：

  • 浮点类型的 std::vector 获取具有所需元素数量的新内存。这些元素会被值初始化。
  • 旧内存中的元素被复制（如果可能，则移动）到新内存中。然后旧内存被归还给系统。
  • 的容量和长度 std::vector 被设置为新值。

从外部看， std::vector 似乎已被调整大小。但在内部，内存（以及所有元素）实际上已被替换！

相关内容

在运行时获取新内存的过程称为动态内存分配。我们在课程 19.1 -- 使用 new 和 delete 进行动态内存分配。

中介绍这一点。由于重新分配通常需要复制数组中的每个元素，因此这是一个昂贵的过程。因此，我们希望尽可能避免重新分配。

关键提示

重新分配通常很昂贵。避免不必要的重新分配。

为什么要区分长度和容量？

一个 std::vector 如果需要，它会重新分配其存储空间，但就像梅尔维尔的巴特比一样，它宁愿不这样做，因为重新分配存储空间的计算成本很高。

如果 std::vector 只跟踪其长度，那么每次 resize() 请求都会导致一次昂贵的重新分配以匹配新长度。将长度和容量分开，使得 std::vector 能够更智能地决定何时需要重新分配。

以下示例说明了这一点：

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
	std::cout << "Capacity: " << v.capacity() << " Length:"	<< v.size() << '\n';
}

int main()
{
    // 创建一个长度为5的向量
    std::vector v{ 0, 1, 2, 3, 4 };
    v = { 0, 1, 2, 3, 4 }; // 好的，数组长度 = 5
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // 将向量大小调整为3个元素
    v.resize(3); // 我们也可以在这里分配一个包含3个元素的列表
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // 将向量大小重新调整为5个元素
    v.resize(5);
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

这将产生以下结果：

Capacity: 5  Length: 5
0 1 2 3 4 
Capacity: 5  Length: 3
0 1 2 
Capacity: 5  Length: 5
0 1 2 0 0

当我们用5个元素初始化向量时，容量被设置为5，表明我们的向量最初为5个元素分配了空间。长度也被设置为5，表明所有这些元素都在使用中。

在我们调用 v.resize(3)之后，长度被改为3以满足我们对更小数组的请求。然而，请注意容量仍然是5，这意味着向量没有进行重新分配！

最后，我们调用了 v.resize(5)。由于向量已经有5的容量，它不需要重新分配。它只是将长度改回5，并对最后两个元素进行了值初始化。

通过分离长度和容量，在这个例子中我们避免了原本会发生的2次重新分配。在下一节课中，我们将看到逐个向vector添加元素的例子。在这种情况下，不每次长度变化都重新分配的能力更为重要。

关键提示

将容量与长度分开跟踪允许 std::vector 在长度改变时避免一些重新分配。

vector索引基于长度，而非容量

你可能会惊讶地发现，下标运算符（operator[]）和 at() 成员函数基于向量的长度，而不是容量。

在上面的例子中，当 v 的容量为5、长度为3时，只有索引0到2是有效的。即使索引在长度3（含）到容量5（不含）之间的元素存在，它们的索引也被视为越界。

警告

下标仅在0到vector的长度（而非容量）之间时才有效！

缩小 std::vector

将vector调整为更大会增加其长度，并在需要时增加其容量。然而，将vector调整为更小只会减少其长度，而不会减少其容量。

仅仅为了回收少量不再需要的元素的内存而重新分配 vector 是一个糟糕的选择。然而，如果 vector 中有大量不再需要的元素，内存浪费可能会很严重。

为了帮助解决这种情况， std::vector 有一个成员函数叫做 shrink_to_fit() 请求 vector 将其容量缩小到与其长度匹配。这个请求是非强制性的，意味着实现可以自由地忽略它。根据实现认为的最佳方式，实现可能决定完全满足请求，可能部分满足（例如减少容量但未完全减少），或者可能完全忽略请求。

下面是一个示例：

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
	std::cout << "Capacity: " << v.capacity() << " Length:"	<< v.size() << '\n';
}

int main()
{

	std::vector<int> v(1000); // 为1000个元素分配空间
	printCapLen(v);

	v.resize(0); // 将大小调整为0个元素
	printCapLen(v);

	v.shrink_to_fit();
	printCapLen(v);

	return 0;
}

在作者的机器上，这产生了以下结果：

Capacity: 1000  Length: 1000
Capacity: 1000  Length: 0
Capacity: 0  Length: 0

如您所见，当 v.shrink_to_fit() 被调用时，vector 将其容量重新分配为 0，释放了 1000 个元素的内存。
