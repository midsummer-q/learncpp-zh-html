13.11 — 结构体杂项

● 机器译文 课程 13.11 查看英文原文

包含程序定义成员的结构体

在C++中，结构体（和类）可以拥有其他程序定义类型的成员。有两种方式可以实现。

首先，我们可以定义一个程序定义类型（在全局作用域中），然后将其用作另一个程序定义类型的成员：

#include <iostream>

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

struct Company
{
    int numberOfEmployees {};
    Employee CEO {}; // Employee 是 Company 结构体中的一个结构体
};

int main()
{
    Company myCompany{ 7, { 1, 32, 55000.0 } }; // 嵌套初始化列表来初始化 Employee
    std::cout << myCompany.CEO.wage << '\n'; // 打印 CEO 的工资

    return 0;
}

在上面的例子中，我们定义了一个 Employee 结构体，然后将其用作 Company 结构体的成员。当我们初始化 Company时，我们也可以使用嵌套的初始化列表来初始化 Employee 如果我们想知道CEO的薪水，只需使用两次成员选择运算符： myCompany.CEO.wage;

其次，类型也可以嵌套在其他类型内部，因此如果Employee只作为Company的一部分存在，那么Employee类型可以嵌套在Company结构体内部：

#include <iostream>

struct Company
{
    struct Employee // 通过 Company::Employee 访问
    {
        int id{};
        int age{};
        double wage{};
    };

    int numberOfEmployees{};
    Employee CEO{}; // Employee 是 Company 结构体中的一个结构体
};

int main()
{
    Company myCompany{ 7, { 1, 32, 55000.0 } }; // 嵌套初始化列表来初始化 Employee
    std::cout << myCompany.CEO.wage << '\n'; // 打印 CEO 的工资

    return 0;
}

这更常用于类，我们将在未来的课程中进一步讨论（15.3 -- 嵌套类型（成员类型）)。

作为所有者的结构体应拥有作为所有者的数据成员

在课程 5.9 -- std::string_view（第 2 部分），我们介绍了所有者和观察者的双重概念。所有者管理自己的数据，并控制其销毁时机。观察者查看他人的数据，不控制其何时被修改或销毁。

在大多数情况下，我们希望结构体（和类）成为其所包含数据的所有者。这带来了一些有用的好处：

  • 数据成员在结构体（或类）存在期间保持有效。
  • 这些数据成员的值不会意外改变。

使结构体（或类）成为所有者的最简单方法是给每个数据成员一个所有者类型（例如，不是观察者、指针或引用）。如果结构体或类的所有数据成员都是所有者，那么结构体或类本身自动成为所有者。

如果结构体（或类）有一个数据成员是观察者，那么该成员所观察的对象可能会在观察它的数据成员之前被销毁。如果发生这种情况，结构体将留下一个悬空成员，访问该成员将导致未定义行为。

最佳实践

在大多数情况下，我们希望结构体（和类）成为所有者。实现这一点的最简单方法是确保每个数据成员具有所有者类型（例如，不是观察者、指针或引用）。

作者注

实践安全的结构体。不要让成员悬空。

这就是为什么字符串数据成员几乎总是类型 std::string （所有者），而不是类型 std::string_view （观察者）。以下示例说明了这一点的重要性：

#include <iostream>
#include <string>
#include <string_view>

struct Owner
{
    std::string name{}; // std::string 是所有者
};

struct Viewer
{
    std::string_view name {}; // std::string_view 是观察者
};

// getName() 返回用户输入的字符串作为临时 std::string
// 这个临时 std::string 将在包含函数调用的完整表达式结束时被销毁。
// 包含函数调用的完整表达式。
std::string getName()
{
    std::cout << "Enter a name: ";
    std::string name{};
    std::cin >> name;
    return name;
}

int main()
{
    Owner o { getName() };  // getName() 的返回值在初始化后立即被销毁
    std::cout << "The owners name is " << o.name << '\n';  // ok

    Viewer v { getName() }; // getName() 的返回值在初始化后立即被销毁
    std::cout << "The viewers name is " << v.name << '\n'; // 未定义行为

    return 0;
}

浮点类型的 getName() 函数返回用户输入的姓名作为一个临时 std::string。这个临时返回值在调用函数的完整表达式结束时被销毁。

在 o，这个临时 std::string 用于初始化 o.name。因为 o.name 我们还调用了 std::string， o.name 制作了临时 std::string的一个副本。临时 std::string 随后消亡，但 o.name 不受影响，因为它是副本。当我们在后续语句中打印 o.name 时，它按预期工作。

在 v，这个临时 std::string 用于初始化 v.name。因为 v.name 我们还调用了 std::string_view， v.name 只是临时 std::string的一个视图，而不是副本。临时 std::string 随后消亡，留下 v.name 悬空。当我们在后续语句中打印 v.name 时，我们得到未定义行为。

结构体大小与数据结构对齐

通常，结构体的大小是其所有成员大小之和，但并非总是如此！

考虑以下程序：

#include <iostream>

struct Foo
{
    short a {};
    int b {};
    double c {};
};

int main()
{
    std::cout << "The size of short is " << sizeof(short) << " bytes\n";
    std::cout << "The size of int is " << sizeof(int) << " bytes\n";
    std::cout << "The size of double is " << sizeof(double) << " bytes\n";

    std::cout << "The size of Foo is " << sizeof(Foo) << " bytes\n";

    return 0;
}

在作者的机器上，打印了：

The size of short is 2 bytes
The size of int is 4 bytes
The size of double is 8 bytes
The size of Foo is 16 bytes

注意， short + int + double 的大小是14字节，但 Foo 的大小是16字节！

事实证明，我们只能说结构体的大小 至少 等于其所有成员变量的大小之和。但它可能更大！出于性能考虑，编译器有时会在结构体中添加间隙（这称为 填充)。

在 Foo 结构体中，编译器在成员 a之后不可见地添加了2字节的填充，使得结构体大小为16字节而不是14字节。

进阶读者

编译器可能添加填充的原因超出了本教程的范围，但想了解更多内容的读者可以阅读 数据结构对齐 的维基百科文章。这是可选阅读，不是理解结构体或C++所必需的！

这实际上会对结构体的大小产生相当大的影响，如下面的程序所示：

#include <iostream>

struct Foo1
{
    short a{}; // 将在 a 之后有 2 字节的填充
    int b{};
    short c{}; // 将在 c 之后有 2 字节的填充
};

struct Foo2
{
    int b{};
    short a{};
    short c{};
};

int main()
{
    std::cout << sizeof(Foo1) << '\n'; // 打印 12
    std::cout << sizeof(Foo2) << '\n'; // 打印 8

    return 0;
}

该程序打印出：

12
8

注意 Foo1 和 Foo2 具有相同的成员，唯一的区别是声明顺序。然而， Foo1 由于添加了填充，体积大了50%。

提示

你可以通过按成员大小递减的顺序定义成员来最小化填充。

C++编译器不允许重新排序成员，因此必须手动完成。
