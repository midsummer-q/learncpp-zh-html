14.13 — 临时类对象

● 机器译文 课程 14.13 查看英文原文

考虑以下示例：

#include <iostream>

int add(int x, int y)
{
    int sum{ x + y }; // 将 x + y 存储在变量中
    return sum;       // 返回该变量的值
}

int main()
{
    std::cout << add(5, 3) << '\n';

    return 0;
}

在 add() 函数中，变量 sum 用于存储表达式的结果 x + y。然后，这个变量在 return 语句中被求值，以产生要返回的值。虽然这有时可能对调试有用（这样我们就可以检查 sum 的值，如果需要的话），但实际上它通过定义一个只使用一次的对象，使函数变得比需要的更复杂。

在大多数情况下，如果一个变量只使用一次，我们实际上并不需要变量。相反，我们可以将用于初始化变量的表达式替换到变量原本被使用的地方。下面是 add() 函数以这种方式重写后的版本：

#include <iostream>

int add(int x, int y)
{
    return x + y; // 直接返回 x + y
}

int main()
{
    std::cout << add(5, 3) << '\n';

    return 0;
}

这不仅适用于返回值，也适用于大多数函数参数。例如，与其这样写：

#include <iostream>

void printValue(int value)
{
    std::cout << value;
}

int main()
{
    int sum{ 5 + 3 };
    printValue(sum);

    return 0;
}

我们可以这样写：

#include <iostream>

void printValue(int value)
{
    std::cout << value;
}

int main()
{
    printValue(5 + 3);

    return 0;
}

注意这使我们的代码变得多么简洁。我们不必定义并给变量命名。我们也不必扫描整个函数来确定该变量是否在其他地方被使用。因为 5 + 3 是一个表达式，我们知道它只在那一行被使用。

请注意，这仅适用于接受右值表达式的情况。在需要左值表达式的情况下，我们必须有一个对象：

#include <iostream>

void addOne(int& value) // 通过非 const 引用传递需要左值
{
    ++value;
}

int main()
{
    int sum { 5 + 3 };
    addOne(sum);   // 可以，sum 是左值

    addOne(5 + 3); // 编译错误：不是左值

    return 0;
}

临时类对象

同样的问题也适用于类类型。

作者注

我们将在这里使用一个类，但本课中所有使用列表初始化的内容同样适用于使用聚合初始化的结构体。

下面的例子与上面的类似，但使用了程序定义的类类型 IntPair 而不是 int：

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const { return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";        
}
        
int main()
{
    // 情况 1：传递变量
    IntPair p { 3, 4 };
    print(p); // 打印 (3, 4)
    
    return 0;
}

在情况1中，我们实例化变量 IntPair p ，然后将 p 的值传递给函数 print()。

然而， p 只使用一次，并且函数 print() 接受右值，所以这里确实没有理由定义一个变量。那么让我们去掉 p。

我们可以通过传递一个临时对象而不是命名变量来实现。一个 临时对象 （有时称为 匿名对象 或 未命名对象）是一个没有名称的对象，并且只存在于单个表达式期间。

有两种常见的方法来创建临时类类型对象：

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const{ return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";        
}
        
int main()
{
    // 情况 1：传递变量
    IntPair p { 3, 4 };
    print(p);

    // 情况 2：构造临时 IntPair 并传递给函数
    print(IntPair { 5, 6 } );

    // 情况 3：隐式将 { 7, 8 } 转换为临时 Intpair 并传递给函数
    print( { 7, 8 } );
    
    return 0;
}

在情况2中，我们告诉编译器构造一个 IntPair 对象，并用 { 5, 6 }初始化它。由于这个对象没有名称，它是一个临时对象。然后临时对象被传递给函数 p 的参数 print()。当函数调用返回时，临时对象被销毁。

在情况3中，我们也创建了一个临时 IntPair 对象传递给函数 print()。然而，由于我们没有明确指定要构造的类型，编译器将从函数参数推导出所需的类型（IntPair），然后隐式地将 { 7, 8 } 到 IntPair 播种），我们将其用作全局

总结一下：

IntPair p { 1, 2 }; // 创建命名对象 p，用 { 1, 2 } 初始化
IntPair { 1, 2 };   // 创建临时对象，用 { 1, 2 } 初始化
{ 1, 2 };           // 编译器会尝试将 { 1, 2 } 转换为与预期类型匹配的临时对象（通常是参数或返回类型）

我们将在课程 14.16 -- 转换构造函数与 explicit 关键字。

中更详细地讨论最后一种情况。

std::string { "Hello" }; // 创建一个临时 std::string，用 "Hello" 初始化
std::string {};          // 创建一个临时 std::string，使用值初始化/默认构造函数

更多例子： 可选

由于我们可以通过直接列表初始化创建临时对象，您可能想知道是否可以通过其他初始化形式创建临时对象。没有语法可以使用复制初始化创建临时对象。

但是，您可以使用直接初始化创建临时对象。例如：

Foo (1, 2); //  临时 Foo，直接初始化为 (1, 2)（类似于 `Foo { 1, 2 }`）

撇开它乍一看像函数调用的事实，这产生与 Foo { 1, 2 } 相同的结果（只是没有窄化转换预防）。相当正常，对吧？

现在我们将花本节剩余的时间向您展示为什么您可能不应该这样做。

作者注

这主要是为了您的阅读乐趣，而不是您需要消化、记忆和能够解释的内容。

即使你读起来没那么有趣，它也可能帮助你理解为什么在现代C++中列表初始化更受青睐！

现在让我们看看没有参数的情况：

Foo();     // 临时 Foo，值初始化（等同于 `Foo {}`）

你可能没想到 Foo() 会像 Foo {} 一样创建一个值初始化的临时对象。这可能是因为这种语法在用于命名变量时具有完全不同的含义！

Foo bar{}; // 变量 bar 的定义，值初始化
Foo bar(); // 函数 bar 的声明，无参数且返回 Foo（与 `Foo bar{}` 和 `Foo()` 不一致）

准备好变得真正奇怪了吗？！

Foo(1);    // 字面量 1 的函数式风格转换，返回临时 Foo（类似于 `Foo { 1 }`）
Foo(bar);  // 定义类型为 Foo 的变量 bar（与 `Foo { bar }` 和 `Foo(1)` 不一致）

等等，什么？

  • 带字面量 1 在括号中的版本与创建临时对象的其他版本语法行为一致。
  • 带标识符 bar 在括号中的版本定义了一个名为 bar 的变量（与 Foo bar;）。如果 bar 已经定义，这将导致重定义编译错误。

编译器知道字面量不能用作变量的标识符，因此它能够一致地处理这种情况。

顺便说一句……

如果你想知道为什么 Foo(bar); 的行为与 Foo bar;…

相同：括号最常见的用途之一是分组。例如，在数学中： (1 + 2) * 3 产生结果 9，这与 1 + 2 * 3不同，后者产生结果 7。如果我们可以做 (1 + 2) * 3，没有理由我们不能做 (3) * 3。

出于类似的原因，声明语法允许基于括号的分组，并且这些组中可以包含单个东西。 Foo(bar) 被解释为一个变量定义，由类型 Foo 后跟一个仅包含标识符 bar的组组成。它看起来很奇怪，主要是因为在这种情况下括号没有任何有用的目的。但没有令人信服的理由禁止这样做（因为这只会使语言的语法更加复杂）。

进阶读者

让我们看一个稍微复杂的情况。考虑语句 Foo * bar();。通过使用（或不使用）括号，我们可以完全改变这个语句的含义：

  • Foo * bar(); （没有额外的括号）默认将 * 替换为 Foo 分组。 Foo* bar(); 是一个名为 bar 的函数声明，没有参数并返回 Foo*。
  • Foo (*bar)(); 显式地将 * 替换为 bar分组。这定义了一个名为 bar 的函数指针，它保存了一个无参数并返回 Foo。
  • Foo (* bar()); 的函数的地址。 Foo * bar(); 与

相同——在这种情况下括号是多余的。

  • (Foo *) bar();最后： Foo* bar()。你可能期望这与 bar()相同，但这实际上是一个表达式语句，它调用函数 Foo*，然后丢弃它！

C++ 有时候真是奇怪。

关键提示

圆括号之所以复杂，是因为它们被过度重载，用于截然不同事物的语法中。这包括函数调用、对象的直接初始化、临时量的值初始化、C风格类型转换、符号/标识符的分组以及变量定义。所以，当你在某些语法中看到圆括号时……并不总是能明显看出你会得到什么！

另一方面，如果我们看到花括号，我们就知道我们在处理对象。

临时对象与按值返回

当函数按值返回时，返回的对象是一个临时对象（使用 return 语句中标识的值或对象进行初始化）。

以下是一些示例：

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const { return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";        
}

// 情况 1：创建命名变量并返回
IntPair ret1()
{
    IntPair p { 3, 4 };
    return p; // 返回临时对象（使用 p 初始化）
}

// 情况 2：创建临时 IntPair 并返回
IntPair ret2()
{
    return IntPair { 5, 6 }; // 返回临时对象（使用另一个临时对象初始化）
}

// 情况 3：隐式将 { 7, 8 } 转换为 IntPair 并返回
IntPair ret3()
{
    return { 7, 8 }; // 返回临时对象（使用另一个临时对象初始化）
}
     
int main()
{
    print(ret1());
    print(ret2());
    print(ret3());

    return 0;
}

在情况1中，当我们 return p时，会创建一个临时对象并使用 p。

进行初始化。此示例中的情况与前一个示例中的情况类似。

几点说明

首先，就像 int的情况一样，当在表达式中使用时，临时类对象是一个右值。因此，这样的对象只能在接受右值表达式的地方使用。

其次，临时对象在定义点创建，并在其定义的完整表达式结束时销毁。完整表达式是指不是子表达式的表达式。

static_cast 与临时对象的显式实例化

在需要将值从一种类型转换为另一种类型但不涉及窄化转换的情况下，我们通常可以选择使用 static_cast 或临时对象的显式实例化。

例如：

#include <iostream>

int main()
{
    char c { 'a' };

    std::cout << static_cast<int>( c ) << '\n'; // static_cast 返回一个临时 int，用 c 的值直接初始化
    std::cout << int { c } << '\n';             // 显式创建一个临时 int，用值 c 列表初始化

    return 0;
}

static_cast<int>(c) 返回一个临时的 int ，它使用 c。 int { c } 创建一个临时的 int ，它使用 c的值进行列表初始化。无论哪种方式，我们都会得到一个临时 int，用 c的值初始化，这正是我们想要的。

让我们展示一个稍微复杂一点的例子：

printString.h：

#include <string>
void printString(const std::string &s)
{
    std::cout << s << '\n';
}

main.cpp:

#include "printString.h"
#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string_view sv { "Hello" };

    // 我们想使用 printString() 函数打印 sv
    
//    printString(sv); // 编译错误：std::string_view 不会隐式转换为 std::string

    printString( static_cast<std::string>(sv) ); // 情况 1：static_cast 返回一个临时 std::string，用 sv 直接初始化
    printString( std::string { sv } );           // 情况 2：显式创建一个临时 std::string，用 sv 列表初始化
    printString( std::string ( sv ) );           // 情况3：C风格转换返回临时std::string，用sv直接初始化（避免这种！）

    return 0;
}

假设头文件 printString.h 中的代码是我们无法修改的（例如，因为它随我们使用的某个第三方库一起分发，并且编写为与不支持 std::string_view的 C++11 兼容）。那么，我们如何调用 printString() 替换为 sv？因为 std::string_view 不会隐式转换为 std::string （出于效率原因），我们不能直接使用 sv 作为参数。我们必须使用某种显式转换形式。

在情况1中， static_cast<std::string>(sv) 调用 static_cast 运算符将 sv 转换为 std::string转换为。这会返回一个临时 std::string ，它使用 sv进行直接初始化，然后用作函数调用的参数。

在情况2中， std::string { sv } 创建一个临时的 std::string ，它使用 sv进行列表初始化。由于这是显式构造，因此允许转换。这个临时对象然后用作函数调用的参数。

在情况3中， std::string ( sv ) 使用 C 风格类型转换将 sv 转换为 std::string转换为。虽然这在这里有效，但 C 风格类型转换通常很危险，应避免使用。注意这与前一种情况看起来多么相似！

最佳实践

作为快速经验法则：当转换为基本类型时，优先使用 static_cast ；当转换为类类型时，优先使用列表初始化的临时对象。

优先使用 static_cast 在以下任一情况下创建临时对象：

  • 我们需要执行窄化转换。
  • 我们想明确表明正在转换为会导致不同行为的类型（例如，一个 char 到 int)。
  • 我们出于某种原因想使用直接初始化（例如，避免列表构造函数优先）。

在以下任一情况下，优先创建新对象（使用列表初始化）来创建临时对象：

  • 我们想使用列表初始化（例如，为了防止窄化转换，或者因为需要调用列表构造函数）。
  • 我们需要向构造函数提供额外参数以促进转换。
