10.8 — 使用 auto 关键字进行对象的类型推导

● 机器译文 课程 10.8 查看英文原文

这个简单的变量定义中隐藏着一个微妙的冗余：

double d{ 5.0 };

在 C++ 中，我们需要为所有对象提供显式类型。因此，我们指定变量 d 的类型为 double。

然而，用于初始化 5.0 的字面量 d 也具有 double 类型（通过字面量的格式隐式确定）。

相关内容

我们在第 5.2 -- 字面量。

课中讨论了字面量类型是如何确定的。

当我们希望变量及其初始化器具有相同类型时，实际上我们提供了两次相同的类型信息。

初始化变量的类型推导 类型推导 （有时也称为类型推断 auto ）是一种允许编译器从对象的初始化器推导出对象类型的特性。定义变量时，可以通过使用

int main()
{
    auto d { 5.0 }; // 5.0 是 double 字面量，因此 d 将被推导为 double
    auto i { 1 + 2 }; // 1 + 2 求值为 int，因此 i 将被推导为 int
    auto x { i }; // i 是 int，因此 x 将被推导为 int

    return 0;
}

关键字代替变量类型来调用类型推导： 5.0 在第一种情况下，因为 d 是 double 字面量，编译器将推导出变量 double的类型应为 1 + 2 在第二种情况下，表达式 i 产生一个 int 结果，因此变量 int的初始化器。在第三种情况下， i 的类型将为 int，所以 x 之前被推导为类型 int。

类型推导会丢弃 const 从推导出的类型中

在大多数情况下，类型推导会从推导出的类型中丢弃 const 例如：

int main()
{
    const int a { 5 }; // a 的类型为 const int
    auto b { a };      // b 的类型为 int（const 被丢弃）

    return 0;
}

在上面的例子中， a 的类型为 const int，但当使用变量 b using a 作为初始化值时，类型推导将类型推导为 int，而不是 const int。

如果你希望推导出的类型是const，你必须在定义中自己提供 const ：

int main()
{
    const int a { 5 };  // a 的类型为 const int
    const auto b { a }; // b 的类型为 const int（const 被丢弃但重新应用）


    return 0;
}

在这个例子中，从 a 推导出的类型将是 int 的返回值（即 const 被丢弃），但由于我们在定义变量 const 时重新添加了 b的typedef，变量 b 将具有类型 const int。

字符串字面量的类型推导

由于历史原因，C++中的字符串字面量具有奇怪的类型。因此，以下代码可能不会按预期工作：

auto s { "Hello, world" }; // s 的类型将是 const char*，而不是 std::string

如果你希望从字符串字面量推导出的类型是 std::string 或 std::string_view，你需要使用 s 或 sv 字面量后缀（在课程 5.7 -- std::string 简介 和 5.8 -- std::string_view 简介)：

#include <string>
#include <string_view>

int main()
{
    using namespace std::literals; // 访问 s 和 sv 后缀的最简单方法

    auto s1 { "goo"s };  // "goo"s 是 std::string 字面量，因此 s1 将被推导为 std::string
    auto s2 { "moo"sv }; // "moo"sv 是 std::string_view 字面量，因此 s2 将被推导为 std::string_view

    return 0;
}

但在这种情况下，最好不使用类型推导。

类型推导与constexpr

因为 constexpr 不是类型系统的一部分，因此不能作为类型推导的一部分被推导出来。然而， constexpr 变量隐式是const，这个const会在类型推导中被丢弃（如果需要可以重新添加）：

int main()
{
    constexpr double a { 3.4 };  // a 的类型为 const double（constexpr 不是类型的一部分，const 是隐式的）

    auto b { a };                // b 的类型为 double（const 被丢弃）
    const auto c { a };          // c 的类型为 const double（const 被丢弃但重新应用）
    constexpr auto d { a };      // d 的类型为 const double（const 被丢弃但由 constexpr 隐式重新应用）

    return 0;
}

类型推导的优点和缺点

类型推导不仅方便，而且还有许多其他好处。

首先，如果两个或多个变量定义在连续行上，变量的名称将对齐，有助于提高可读性：

// 更难阅读
int a { 5 };
double b { 6.7 };

// 更容易阅读
auto c { 5 };
auto d { 6.7 };

其次，类型推导只适用于有初始化值的变量，因此如果你习惯使用类型推导，它可以帮助避免意外未初始化的变量：

int x; // 哎呀，我们忘记初始化 x，但编译器可能不会报错
auto y; // 编译器会报错，因为它无法推导 y 的类型

第三，你可以保证不会发生意外的性能影响转换：

std::string_view getString();   // 某个返回 std::string_view 的函数

std::string s1 { getString() }; // 不好：从 std::string_view 到 std::string 的昂贵转换（假设你不想要这个）
auto s2 { getString() };        // 好：无需转换

类型推导也有一些缺点。

首先，类型推导掩盖了代码中对象的类型信息。虽然一个好的IDE应该能够显示推导出的类型（例如，悬停在变量上时），但使用类型推导时仍然更容易犯基于类型的错误。

例如：

auto y { 5 }; // 哎呀，我们想要一个 double，但意外地提供了一个 int 字面量

在上面的代码中，如果我们明确指定 y 为double类型， y 将是double，即使我们意外地提供了int字面量初始化值。使用类型推导时， y 将被推导为int类型。

另一个例子：

#include <iostream>

int main()
{
     auto x { 3 };
     auto y { 2 };

     std::cout << x / y << '\n'; // 哎呀，我们这里想要的是浮点数除法

     return 0;
}

在这个例子中，不太清楚我们得到的是整数除法而不是浮点数除法。

类似的情况发生在变量是 unsigned时。由于我们不想混合有符号和无符号值，明确知道变量具有无符号类型通常是不应该被掩盖的。

其次，如果初始化值的类型发生变化，使用类型推导的变量的类型也会随之变化，这可能是意外的。考虑：

auto sum { add(5, 6) + gravity };

如果 add 的返回类型从 int 变为 double，或者 gravity 从 int 变为 double， sum 也会从 int 变为 double。

总体而言，现代共识是类型推导对于对象通常是安全的，并且这样做可以通过淡化类型信息来帮助使代码更易读，从而让代码的逻辑更加突出。

最佳实践

当对象的类型不重要时，对变量使用类型推导。

当你需要与初始化器类型不同的特定类型，或者你的对象在需要明确类型的上下文中使用时，优先使用显式类型。
