12.14 — 指针、引用和const的类型推导

● 机器译文 课程 12.14 查看英文原文

在课程 10.8 -- 使用 auto 关键字进行对象的类型推导，我们讨论了如何使用 auto 关键字让编译器从初始化器推导变量的类型：

int main()
{
    int a { 5 };
    auto b { a }; // b 推导为 int

    return 0;
}

我们还指出，默认情况下，类型推导会从类型中移除 const ：

int main()
{
    const double a { 7.8 }; // a 的类型为 const double
    auto b { a };           // b 的类型为 double（const 被丢弃）

    constexpr double c { 7.8 }; // c 的类型为 const double（constexpr 隐式应用 const）
    auto d { c };               // d 的类型为 double（const 被移除）

    return 0;
}

可以通过在推导类型的定义中添加 const （或 constexpr限定符来重新应用const（或constexpr）：

int main()
{
    double a { 7.8 };    // a 的类型为 double
    const auto b { a };  // b 的类型为 const double（const 被应用）

    constexpr double c { 7.8 }; // c 的类型为 const double（constexpr 隐式应用 const）
    const auto d { c };         // d 是 const double（const 被移除，const 被重新应用）
    constexpr auto e { c };     // e 是 constexpr double（const 被移除，constexpr 被重新应用）

    return 0;
}

类型推导移除引用

除了移除const，类型推导也会移除引用：

#include <string>

std::string& getRef(); // 某个返回引用的函数

int main()
{
    auto ref { getRef() }; // 类型推导为 std::string（不是 std::string&）

    return 0;
}

在上面的例子中，变量 ref 使用了类型推导。尽管函数 getRef() 按值返回一个 std::string&，但引用限定符被移除，因此 ref 的类型被推导为 std::string。

就像被移除的 const一样，如果你希望推导的类型是引用，可以在定义点重新应用引用：

#include <string>

std::string& getRef(); // 某个返回引用的函数

int main()
{
    auto ref1 { getRef() };  // std::string（引用被移除）
    auto& ref2 { getRef() }; // std::string&（引用被移除，引用被重新应用）

    return 0;
}

顶层const和底层const

一个 顶层const 是应用于对象本身的const限定符。例如：

const int x;    // 这个 const 应用于 x，因此是顶层 const
int* const ptr; // 这个 const 应用于 ptr，因此是顶层 const
// 引用没有顶层 const 语法，因为它们隐式地是顶层 const

相比之下， 底层const 是应用于被引用或指向的对象的const限定符：

const int& ref; // 这个 const 应用于被引用的对象，因此是底层 const
const int* ptr; // 这个 const 应用于被指向的对象，因此是底层 const

对const值的引用始终是底层const。指针可以有顶层const、底层const或两者兼有：

const int* const ptr; // 左边的 const 是底层 const，右边的 const 是顶层 const

当我们说类型推导移除const限定符时，它只移除顶层const。底层const不会被移除。我们稍后会看到示例。

类型推导与const引用

如果初始化器是对const的引用，则首先移除引用（然后如果适用则重新应用），然后从结果中移除任何顶层const。

#include <string>

const std::string& getConstRef(); // 某个返回 const 引用的函数

int main()
{
    auto ref1{ getConstRef() }; // std::string（引用被移除，然后结果中的顶层 const 被移除）

    return 0;
}

在上面的示例中，由于 getConstRef() 按值返回一个 const std::string&，首先移除引用，剩下 const std::string。这个const现在是顶层const，因此也被移除，推导类型为 std::string。

关键提示

移除引用可能会将底层const变为顶层const： const std::string& 是底层const，但移除引用后得到 const std::string，这是一个顶层const。

我们可以重新应用引用和/或const：

#include <string>

const std::string& getConstRef(); // 某个返回常量引用的函数

int main()
{
    auto ref1{ getConstRef() };        // std::string（引用和顶层const被丢弃）
    const auto ref2{ getConstRef() };  // const std::string（引用被丢弃，const被丢弃，const重新应用）

    auto& ref3{ getConstRef() };       // const std::string&（引用被丢弃并重新应用，底层const未被丢弃）
    const auto& ref4{ getConstRef() }; // const std::string&（引用被丢弃并重新应用，底层const未被丢弃）

    return 0;
}

我们在前面的示例中已经介绍了 ref1 的情况。对于 ref2，这与 ref1 的情况类似，只是我们重新应用了 const 限定符，因此推导类型为 const std::string。

对于 ref3，情况更有趣。通常引用会被移除，但由于我们重新应用了引用，它不会被移除。这意味着类型仍然是 const std::string&。由于这个const是底层const，它不会被移除。因此推导类型为 const std::string&。

浮点类型的 ref4 的情况与 ref3，只是我们重新应用了 const 限定符。由于类型已经被推导为 const 引用，我们在这里重新应用 const 是多余的。也就是说，使用 const 在这里可以明确表明我们的结果是 const（而在 ref3 的情况下，结果的常量性是隐式的，并不明显）。

最佳实践

如果你想要一个 const 引用，即使不是严格必要，也重新应用 const 限定符，因为它能明确你的意图并有助于防止错误。

类型推导与 const 指针 可选

由于指针不会被丢弃，我们不必担心这一点。但对于指针，我们需要考虑 const 指针和指向 const 的指针两种情况，而且我们还有 auto vs auto*。就像引用一样，在指针类型推导中只有顶层 const 会被丢弃。

让我们从一个简单的例子开始：

#include <string>

std::string* getPtr(); // 某个返回指针的函数

int main()
{
    const auto ptr1{ getPtr() };  // std::string* const
    auto const ptr2 { getPtr() }; // std::string* const

    const auto* ptr3{ getPtr() }; // const std::string*
    auto* const ptr4{ getPtr() }; // std::string* const

    return 0;
}

当我们使用 auto const 或 const auto时，我们是在说“使推导出的指针成为 const 指针”。所以在 ptr1 和 ptr2的情况下，推导出的类型是 std::string*，然后应用 const，最终类型变为 std::string* const。这类似于 const int 和 int const 表示相同的意思。

然而，当我们使用 auto*时，const 限定符的顺序很重要。 const 在左边表示“使推导出的指针成为指向 const 的指针”，而 const 在右边表示“使推导出的指针类型成为 const 指针”。因此 ptr3 最终成为指向 const 的指针，而 ptr4 最终成为 const 指针。

现在让我们看一个初始化器是 const 指针指向 const 的例子。

#include <string>

int main()
{
    std::string s{};
    const std::string* const ptr { &s };

    auto ptr1{ ptr };  // const std::string*
    auto* ptr2{ ptr }; // const std::string*

    auto const ptr3{ ptr };  // const std::string* const
    const auto ptr4{ ptr };  // const std::string* const

    auto* const ptr5{ ptr }; // const std::string* const
    const auto* ptr6{ ptr }; // const std::string*

    const auto const ptr7{ ptr };  // 错误：const限定符不能应用两次
    const auto* const ptr8{ ptr }; // const std::string* const

    return 0;
}

浮点类型的 ptr1 和 ptr2 情况很简单。顶层 const（指针本身的 const）被丢弃。被指向对象的底层 const 不会被丢弃。所以在两种情况下，最终类型都是 const std::string*。

浮点类型的 ptr3 和 ptr4 情况也很简单。顶层 const 被丢弃，但我们重新应用它。被指向对象的底层 const 不会被丢弃。所以在两种情况下，最终类型都是 const std::string* const。

浮点类型的 ptr5 和 ptr6 情况类似于我们之前例子中的情况。在两种情况下，顶层 const 都被丢弃。对于 ptr5， auto* const ，重新应用了顶层 const，所以最终类型是 const std::string* const。对于 ptr6， const auto* ，将 const 应用于被指向的类型（在这种情况下已经是 const），所以最终类型是 const std::string*。

在 ptr7 情况，我们应用了两次 const 限定符，这是不允许的，会导致编译错误。

最后，在 ptr8 情况下，我们在指针的两侧都应用了 const（这是允许的，因为 auto* 必须是指针类型），所以结果类型是 const std::string* const。

最佳实践

如果你想要 const 指针、指向 const 的指针或 const 指针指向 const，即使不是严格必要，也要重新应用 const 限定符，因为这能明确你的意图并有助于防止错误。

提示

考虑在推导指针类型时使用 auto* 在这种情况下使用 auto* 可以更清楚地表明我们在推导指针类型，借助编译器确保我们不会推导出非指针类型，并且让你对 const 有更多控制。

总结

很抱歉让你头疼了。让我们快速回顾一下最重要的几点。

顶层 const 与底层 const：

  • 顶层 const 应用于对象本身（例如 const int x 或 int* const ptr)。
  • 底层 const 应用于通过引用或指针访问的对象（例如 const int& ref， const int* ptr)。

类型推导推导出的类型：

  • 类型推导首先移除任何引用（除非推导出的类型被定义为引用）。对于 const 引用，移除引用会导致（底层）const 变为顶层 const。
  • 类型推导然后移除任何顶层 const（除非推导出的类型被定义为 const 或 constexpr)。
  • Constexpr 不是类型系统的一部分，因此永远不会被推导。它必须始终显式地应用于推导出的类型。
  • 类型推导不会移除指针。
  • 始终将推导出的类型显式定义为引用， const，或 constexpr （如适用），即使这些限定符是多余的，因为它们会被推导出来。这有助于防止错误，并明确你的意图。

类型推导与指针：

  • 当使用 auto，推导出的类型仅当初始化器是指针时才是指针。使用 auto*时，推导出的类型始终是指针，即使初始化器不是指针。
  • auto const 和 const auto 都使推导出的指针成为 const 指针。无法使用 auto。
  • auto* const 显式指定底层 const（指向常量的指针）。 const auto* 也使推导出的指针成为 const 指针。 int* const 使推导出的指针成为指向常量的指针。如果这些难以记住， auto* const 是一个 const 指针（指向 int），所以 const int* 必须是一个 const 指针。 const auto* 是一个指向常量的指针（int），所以
  • 考虑在推导指针类型时使用 auto* 而不是 auto 在推导指针类型时，因为它允许你显式地重新应用顶层和底层 const，并且如果未推导出指针类型则会报错。
