13.2 — 无作用域枚举

● 机器译文 课程 13.2 查看英文原文

C++ 包含许多有用的基本和复合数据类型（我们在课程中介绍过 4.1 -- 基本数据类型简介 和 12.1 -- 复合数据类型简介）。但这些类型并不总能满足我们想要做的事情。

例如，假设你正在编写一个程序，需要跟踪苹果是红色、黄色还是绿色，或者衬衫是什么颜色（从预设的颜色列表中）。如果只有基本类型可用，你会怎么做？

你可能会将颜色存储为整数值，使用某种隐式映射（0 = 红色，1 = 绿色，2 = 蓝色）：

int main()
{
    int appleColor{ 0 }; // 我的苹果是红色的
    int shirtColor{ 1 }; // 我的衬衫是绿色的

    return 0;
}

但这根本不直观，而且我们已经讨论过为什么魔法数字不好（5.2 -- 字面量）。我们可以通过使用符号常量来消除魔法数字：

constexpr int red{ 0 };
constexpr int green{ 1 };
constexpr int blue{ 2 };

int main()
{
    int appleColor{ red };
    int shirtColor{ green };

    return 0;
}

虽然这对阅读来说好一点，但程序员仍然需要推断 appleColor 和 shirtColor （类型为 int）旨在保存颜色符号常量集合中定义的值之一（这些常量可能在其他地方定义，可能在单独的文件中）。

我们可以通过使用类型别名使这个程序更清晰一些：

using Color = int; // 定义一个名为 Color 的类型别名

// 以下颜色值应用于 Color
constexpr Color red{ 0 };
constexpr Color green{ 1 };
constexpr Color blue{ 2 };

int main()
{
    Color appleColor{ red };
    Color shirtColor{ green };

    return 0;
}

我们越来越接近了。阅读此代码的人仍然需要理解这些颜色符号常量旨在与类型为 Color的变量一起使用，但至少该类型现在有一个唯一的名称，因此搜索 Color 的人能够找到相关的符号常量集合。

然而，因为 Color 只是 int的别名，我们仍然存在一个问题：没有任何东西强制正确使用这些颜色符号常量。我们仍然可以这样做：

Color eyeColor{ 8 }; // 语法有效，语义无意义

此外，如果我们在调试器中调试这些变量中的任何一个，我们只会看到颜色的整数值（例如 0），而不是符号含义（red），这可能会使判断程序是否正确变得更加困难。

幸运的是，我们可以做得更好。

作为灵感，考虑 bool 类型。是什么让 bool 特别有趣的是它只有两个定义的值： true 和 false。我们可以直接使用 true 或 false （作为字面量），或者实例化一个 bool 对象并让它保存这两个值之一。此外，编译器能够区分 bool 和其他类型。这意味着我们可以重载函数，并自定义这些函数在传递 bool 值。

时的行为。 如果我们有能力定义自己的自定义类型，其中 我们可以定义与该类型关联的命名值集合，那么我们将拥有完美工具来优雅地解决上述挑战……

枚举

一种 枚举 （也称为一个 枚举类型 或 enum）是一种复合数据类型，其值被限制为一组命名的符号常量（称为 枚举项)。

C++ 支持两种枚举：无作用域枚举（我们现在将介绍）和有作用域枚举（我们将在本章后面介绍）。

因为枚举是程序定义的类型 13.1 -- 程序定义（用户定义）类型简介，每个枚举在使用之前都需要完全定义（前向声明是不够的）。

无作用域枚举

无作用域枚举通过 enum 关键字。

枚举类型最好通过示例来讲解，所以让我们定义一个可以保存一些颜色值的无作用域枚举。下面我们将解释它是如何工作的。

// 定义一个新的无作用域枚举，名为 Color
enum Color
{
    // 以下是枚举项
    // 这些符号常量定义了该类型可以持有的所有可能值
    // 每个枚举项用逗号分隔，而不是分号
    red,
    green,
    blue, // 尾随逗号可选但推荐
}; // 枚举定义必须以分号结束

int main()
{
    // 定义几个枚举类型 Color 的变量
    Color apple { red };   // 我的苹果是红色的
    Color shirt { green }; // 我的衬衫是绿色的
    Color cup { blue };    // 我的杯子是蓝色的

    Color socks { white }; // 错误：white 不是 Color 的枚举项
    Color hat { 2 };       // 错误：2 不是 Color 的枚举项

    return 0;
}

我们首先使用 enum 关键字告诉编译器我们正在定义一个无作用域枚举，并将其命名为 Color。

在一对花括号内，我们为 Color 类型定义枚举项： red， green、和 blue。这些枚举项定义了类型 Color 被限制的具体值。每个枚举项必须用逗号（而不是分号）分隔——最后一个枚举项后面的尾随逗号是可选的，但为了保持一致性，建议使用。

通常每行定义一个枚举项，但在简单情况下（枚举项数量少且不需要注释时），它们可以全部定义在一行上。

类型定义 Color 以分号结束。我们现在已经完全定义了枚举类型 Color 是什么！

在 main()内部，我们实例化了三个类型为 Color： apple 的变量 red， shirt 的变量 green、和 cup 的变量 blue初始化为颜色 socks 和 hat 为每个对象分配了内存。请注意，枚举类型的初始化器必须是该类型定义的枚举项之一。变量 white 和 2 会导致编译错误，因为初始化器 Color。

命名枚举和枚举项

按照惯例，枚举类型的名称以大写字母开头（所有程序定义的类型也是如此）。

警告

枚举不必命名，但在现代 C++ 中应避免使用未命名的枚举。

枚举项必须命名。不幸的是，枚举项名称没有通用的命名约定。常见的选择包括以小写开头（例如 red）、以大写开头（Red）、全大写（RED）、全大写加前缀（COLOR_RED），或以“k”为前缀并采用驼峰式（kColorRed）。

现代 C++ 指南通常建议避免全大写的命名约定，因为全大写通常用于预处理器宏，可能会发生冲突。我们还建议避免以大写字母开头的约定，因为以大写字母开头的名称通常保留给程序定义的类型。

最佳实践

枚举类型名称以大写字母开头。枚举项名称以小写字母开头。

枚举类型是 distinct 类型

您创建的每个枚举类型都被视为一个 distinct 类型，这意味着编译器可以将其与其他类型区分开来（与 typedef 或类型别名不同，它们被视为与所别名的类型非 distinct）。

因为枚举类型是 distinct 的，所以作为某个枚举类型一部分定义的枚举项不能与另一个枚举类型的对象一起使用：

enum Pet
{
    cat,
    dog,
    pig,
    whale,
};

enum Color
{
    black,
    red,
    blue,
};

int main()
{
    Pet myPet { black }; // 编译错误：black 不是 Pet 的枚举项
    Color shirt { pig }; // 编译错误：pig 不是 Color 的枚举项

    return 0;
}

反正你可能也不想要一件猪衬衫。

使用枚举

由于枚举项具有描述性，它们有助于增强代码文档和可读性。枚举类型最适合用于有一小组相关常量，并且对象一次只需要保存其中一个值的情况。

常见的枚举包括一周中的天数、基本方向和一副扑克牌的花色：

enum DaysOfWeek
{
    sunday,
    monday,
    tuesday,
    wednesday,
    thursday,
    friday,
    saturday,
};

enum CardinalDirections
{
    north,
    east,
    south,
    west,
};

enum CardSuits
{
    clubs,
    diamonds,
    hearts,
    spades,
};

有时函数会向调用者返回一个状态码，以指示函数是成功执行还是遇到错误。传统上，使用小的负数来表示不同的可能错误代码。例如：

int readFileContents()
{
    if (!openFile())
        return -1;
    if (!readFile())
        return -2;
    if (!parseFile())
        return -3;

    return 0; // 成功
}

然而，像这样使用魔数并不具有描述性。更好的方法是使用枚举类型：

enum FileReadResult
{
    readResultSuccess,
    readResultErrorFileOpen,
    readResultErrorFileRead,
    readResultErrorFileParse,
};

FileReadResult readFileContents()
{
    if (!openFile())
        return readResultErrorFileOpen;
    if (!readFile())
        return readResultErrorFileRead;
    if (!parseFile())
        return readResultErrorFileParse;

    return readResultSuccess;
}

然后调用者可以将函数的返回值与相应的枚举器进行比较，这比测试返回结果是否为特定的整数值更容易理解。

if (readFileContents() == readResultSuccess)
{
    // // 执行某些操作
}
else
{
    // 打印错误消息
}

枚举类型在游戏中也很有用，用于标识不同类型的物品、怪物或地形。基本上，任何一组相关的小型对象都可以使用枚举。

例如：

enum ItemType
{
	sword,
	torch,
	potion,
};

int main()
{
	ItemType holding{ torch };

	return 0;
}

当用户需要在两个或多个选项之间做出选择时，枚举类型也可以作为有用的函数参数：

enum SortOrder
{
    alphabetical,
    alphabeticalReverse,
    numerical,
};

void sortData(SortOrder order)
{
    switch (order)
    {
        case alphabetical:
            // 按字母顺序正向排序数据
            break;
        case alphabeticalReverse:
            // 按字母顺序反向排序数据
            break;
        case numerical:
            // 按数字排序数据
            break;
    }
}

许多语言使用枚举来定义布尔值——毕竟，布尔值本质上就是一个包含两个枚举器的枚举： false 和 true！然而，在 C++ 中， true 和 false 被定义为关键字而不是枚举器。

由于枚举很小且复制成本低，因此按值传递（和返回）它们是没问题的。

在课程 O.1 -- 位标志和通过std::bitset进行位操作，我们讨论了位标志。枚举也可以用于定义一组相关的位标志位置，以便与 std::bitset：

#include <bitset>
#include <iostream>

namespace Flags
{
    enum State
    {
        isHungry,
        isSad,
        isMad,
        isHappy,
        isLaughing,
        isAsleep,
        isDead,
        isCrying,
    };
}

int main()
{
    std::bitset<8> me{};
    me.set(Flags::isHappy);
    me.set(Flags::isLaughing);

    std::cout << std::boolalpha; // 将 bool 打印为 true/false

    // 查询几个状态（我们使用 any() 函数查看是否有任何位仍被设置）
    std::cout << "I am happy? " << me.test(Flags::isHappy) << '\n';
    std::cout << "I am laughing? " << me.test(Flags::isLaughing) << '\n';

    return 0;
}

如果你想知道我们如何在需要整数值的地方使用枚举器，无作用域枚举器会隐式转换为整数值。我们将在下一课中进一步探讨这一点（13.3 -- 无作用域枚举器整型转换)。

无作用域枚举的作用域

无作用域枚举之所以如此命名，是因为它们将枚举器名称放入与枚举定义本身相同的作用域中（而不是像命名空间那样创建一个新的作用域区域）。

例如，对于以下程序：

enum Color // 此枚举定义在全局命名空间中
{
    red, // 所以 red 被放入全局命名空间
    green,
    blue, 
};

int main()
{
    Color apple { red }; // 我的苹果是红色的

    return 0;
}

浮点类型的 Color 枚举定义在全局作用域中。因此，所有枚举名称（red， green、和 blue）也进入全局作用域。这污染了全局作用域，并显著增加了命名冲突的可能性。

一个后果是，枚举器名称不能在同一个作用域内的多个枚举中使用：

enum Color
{
    red,
    green,
    blue, // blue 被放入全局命名空间
};

enum Feeling
{
    happy,
    tired,
    blue, // 错误：与上面的 blue 命名冲突
};

int main()
{
    Color apple { red }; // 我的苹果是红色的
    Feeling me { happy }; // 我现在很开心（尽管我的程序无法编译）

    return 0;
}

在上面的例子中，两个无作用域枚举（Color 和 Feeling）都将同名的枚举器 blue 放入全局作用域。这导致了命名冲突和随后的编译错误。

无作用域枚举也为它们的枚举器提供了一个命名的作用域区域（很像命名空间为其内部声明的名称提供命名作用域区域）。这意味着我们可以通过以下方式访问无作用域枚举的枚举器：

enum Color
{
    red,
    green,
    blue, // blue 被放入全局命名空间
};

int main()
{
    Color apple { red }; // 好的，从全局命名空间访问枚举项
    Color raspberry { Color::red }; // 也可以，从 Color 的作用域访问枚举项

    return 0;
}

大多数情况下，无作用域枚举器在不使用作用域解析运算符的情况下访问。

避免枚举器命名冲突

有几种常见的方法可以防止无作用域枚举器命名冲突。

一种选择是给每个枚举器加上枚举本身的名称作为前缀：

enum Color
{
    color_red,
    color_blue,
    color_green,
};

enum Feeling
{
    feeling_happy,
    feeling_tired,
    feeling_blue, // 不再与 color_blue 有命名冲突
};

int main()
{
    Color paint { color_blue };
    Feeling me { feeling_blue };

    return 0;
}

这仍然会污染命名空间，但通过使名称更长、更独特来减少命名冲突的机会。

一个更好的选择是将枚举类型放在提供单独作用域区域的东西中，例如命名空间：

namespace Color
{
    // 名称 Color、red、blue 和 green 定义在命名空间 Color 内部
    enum Color
    {
        red,
        green,
        blue,
    };
}

namespace Feeling
{
    enum Feeling
    {
        happy,
        tired,
        blue, // Feeling::blue 不会与 Color::blue 冲突
    };
}

int main()
{
    Color::Color paint{ Color::blue };
    Feeling::Feeling me{ Feeling::blue };

    return 0;
}

这意味着我们现在必须用作用域区域的名称作为枚举和枚举器名称的前缀。

进阶读者

类也提供作用域区域，将与类相关的枚举类型放在类的作用域区域内是很常见的。我们在课程 15.3 -- 嵌套类型（成员类型）。

中讨论这一点。一个相关的选项是使用有作用域枚举（它定义了自己的作用域区域）。我们稍后将讨论有作用域枚举（13.6 -- 作用域枚举（enum class）)。

最佳实践

优先将枚举放在命名的作用域区域（如命名空间或类）内，这样枚举器就不会污染全局命名空间。

或者，如果枚举仅在单个函数体内使用，则应在函数内部定义枚举。这将枚举及其枚举器的作用域限制在该函数内。此类枚举的枚举器将隐藏全局作用域中同名的枚举器。

与枚举器比较

我们可以使用相等运算符（operator== 和 operator!=）来测试枚举是否具有特定枚举器的值。

#include <iostream>

enum Color
{
    red,
    green,
    blue,
};

int main()
{
    Color shirt{ blue };

    if (shirt == blue) // 如果衬衫是蓝色的
        std::cout << "Your shirt is blue!";
    else
        std::cout << "Your shirt is not blue!";

    return 0;
}

在上面的例子中，我们使用 if 语句来测试 shirt 是否等于枚举器 blue。这为我们提供了一种根据枚举所持有的枚举器来条件化程序行为的方法。

我们将在下一课中更多地使用这一点。

小测验时间

问题 #1

定义一个名为 MonsterType 的无作用域枚举类型，用于选择以下怪物种族：兽人、哥布林、巨魔、食人魔和骷髅。

显示答案

enum MonsterType
{
    orc,
    goblin,
    troll,
    ogre,
    skeleton,
};

问题 #2

将 MonsterType 枚举放在一个命名空间内。然后，创建一个 main() 函数并实例化一个 troll。程序应能编译。

显示答案

namespace Monster
{
    enum MonsterType
    {
        orc,
        goblin,
        troll,
        ogre,
        skeleton,
    };
}

int main()
{
    // 我们使用 [[maybe_unused]] 来避免未使用变量的警告
    // 你也可以输出怪物本身
    [[maybe_unused]] Monster::MonsterType monster{ Monster::troll };

    return 0;
}

因为 MonsterType 是一个无作用域枚举，其枚举项（例如 troll）被放入枚举本身的命名空间中（在本例中是 namespace Monster）。因此，我们可以访问 troll 为 Monster::troll。

因为无作用域枚举也会将其枚举项放入自己的命名空间， troll 也可以作为 Monster::MonsterType::troll访问。然而，这样做并没有实际好处。
