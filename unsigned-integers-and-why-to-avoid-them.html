4.5 — 无符号整数，以及为何要避免使用它们

● 机器译文 课程 4.5 查看英文原文

无符号整数

在前一课（4.4 -- 有符号整数），我们介绍了有符号整数，这是一组可以表示正负整数（包括0）的类型。

C++ 也支持无符号整数。 无符号整数 是只能表示非负整数的整数。

定义无符号整数

要定义无符号整数，我们使用 unsigned 关键字。按照惯例，它放在类型之前：

unsigned short us;
unsigned int ui;
unsigned long ul;
unsigned long long ull;

无符号整数范围

1字节无符号整数的范围是0到255。与1字节有符号整数的范围-128到127相比，两者都能存储256个不同的值，但有符号整数将其一半的范围用于负数，而无符号整数可以存储两倍大的正数。

下面是展示无符号整数范围的表格：

大小/类型范围
8位无符号0 到 255
16位无符号0 到 65,535
32位无符号0 到 4,294,967,295
64位无符号0 到 18,446,744,073,709,551,615

一个n位无符号变量的取值范围是0到(2n)-1.

当不需要负数时，无符号整数非常适合网络和内存较小的系统，因为无符号整数可以在不占用额外内存的情况下存储更多的正数。

记住有符号和无符号这两个术语

新手程序员有时会把有符号和无符号搞混。下面是一种简单的记忆方法：为了区分负数和正数，我们使用负号。如果没有提供符号，我们假设该数为正数。因此，带符号的整数（有符号整数）能够区分正负。不带符号的整数（无符号整数）则假定所有值都是正数。

无符号整数溢出

如果我们尝试存储数字 280 （需要9位来表示）在一个1字节（8位）的无符号整数中？答案是溢出。

作者注

奇怪的是，C++标准明确表示“涉及无符号操作数的计算永远不会溢出”。这与普遍编程共识相悖，即整数溢出包括有符号和无符号两种情况。 (cite)考虑到大多数程序员会认为这是溢出，尽管C++标准有相反的说法，我们仍将称之为溢出。

如果无符号值超出范围，则将其除以比该类型的最大数大1的数，只保留余数。

数字 280 太大，无法放入我们1字节的0到255范围。比该类型的最大数大1的数是256。因此，我们将280除以256，得到1余24。存储的就是余数24。

这是思考同一问题的另一种方式。任何大于该类型可表示最大数的数字都会“环绕”（有时称为“模环绕”）。 255 在1字节整数的范围内，所以 255 没问题。 256但是超出了范围，所以它环绕到值 0。 257 环绕到值 1。 280 环绕到值 24。

让我们用2字节的short来看看：

#include <iostream>

int main()
{
    unsigned short x{ 65535 }; // 可能的最大16位无符号值
    std::cout << "x was: " << x << '\n';

    x = 65536; // 65536超出范围，所以发生模环绕
    std::cout << "x is now: " << x << '\n';

    x = 65537; // 65537超出范围，所以发生模环绕
    std::cout << "x is now: " << x << '\n';

    return 0;
}

你认为这个程序的结果会是什么？

（注意：如果尝试编译上述程序，您的编译器应会发出关于溢出或截断的警告——您需要禁用“将警告视为错误”来运行程序）

x was: 65535
x is now: 0
x is now: 1

也有可能向另一个方向环绕。0可以用2字节的无符号整数表示，所以没问题。-1无法表示，因此它会回绕到范围顶部，产生值65535。-2回绕到65534。以此类推。

#include <iostream>

int main()
{
    unsigned short x{ 0 }; // 可能的最小2字节无符号值
    std::cout << "x was: " << x << '\n';

    x = -1; // -1超出范围，所以发生模环绕
    std::cout << "x is now: " << x << '\n';

    x = -2; // -2超出范围，所以发生模环绕
    std::cout << "x is now: " << x << '\n';

    return 0;
}

x was: 0
x is now: 65535
x is now: 65534

上述代码在某些编译器中会触发警告，因为编译器检测到整数字面量超出给定类型的范围。如果您仍想编译代码，可以暂时禁用“将警告视为错误”。

关于无符号数的争议

许多开发者（以及一些大型开发公司，如Google）认为开发者通常应避免使用无符号整数。

这主要是因为两种可能导致问题的行为。

首先，对于有符号值，意外溢出范围顶部或底部需要一些条件，因为这些值远离0。而对于无符号数，更容易溢出底部，因为底部是0，接近我们大多数值的位置。

考虑两个无符号数的减法，例如2和3：

#include <iostream>

// 假设int为4字节
int main()
{
	unsigned int x{ 2 };
	unsigned int y{ 3 };

	std::cout << x - y << '\n'; // 打印4294967295（不正确！）

	return 0;
}

您我都知道 2 - 3 等于 -1，但 -1 无法表示为无符号整数，因此发生溢出，得到以下结果：

4294967295

另一种常见的意外回绕发生在无符号整数反复递减1，直到试图递减到负数时。在引入循环时您将看到这样的例子。

其次，更隐蔽的是，当混合使用有符号和无符号整数时，可能出现意外行为。在C++中，如果数学运算（例如算术或比较）涉及一个有符号整数和一个无符号整数，有符号整数通常会被转换为无符号整数，结果也将是无符号的。例如：

#include <iostream>

// 假设int为4字节
int main()
{
	unsigned int u{ 2 };
	signed int s{ 3 };

	std::cout << u - s << '\n'; // 2 - 3 = 4294967295

	return 0;
}

这也产生结果：

4294967295

在这种情况下，如果 u 是有符号的，会得到正确结果。但由于 u 是无符号的（容易被忽略）， s 被转换为无符号数，结果（-1）被视为无符号值。由于 -1 无法存储在无符号值中，因此我们会遇到溢出并得到意外的结果。

这里有另一个例子，事情出错了：

#include <iostream>

// 假设int为4字节
int main()
{
    signed int s { -1 };
    unsigned int u { 1 };

    if (s < u) // -1隐式转换为4294967295，且4294967295 < 1为假
        std::cout << "-1 is less than 1\n";
    else
        std::cout << "1 is less than -1\n"; // 此语句执行

    return 0;
}

这会打印：

1 is less than -1

这个程序格式良好，能编译通过，而且看起来逻辑一致。但它会打印错误的答案。虽然你的编译器在这种情况下应该警告你关于有符号/无符号不匹配的问题，但你的编译器也会为其他不涉及此问题的情形（例如当两个数都为正数时）生成相同的警告，这使得很难检测到实际存在问题的情形。

此外，还有其他难以检测的问题情况。考虑以下例子：

#include <iostream>

// 假设int为4字节
void doSomething(unsigned int x)
{
    // 运行某段代码 x 次

    std::cout << "x is " << x << '\n';
}

int main()
{
    doSomething(-1);

    return 0;
}

doSomething() 的作者期望有人只传入正数来调用这个函数。但是调用者传入了 -1 ——很明显是个错误，但还是发生了。这种情况下会发生什么？

有符号参数 -1 被隐式转换为无符号参数。 -1 不在无符号数的范围内，因此它会绕回到 4294967295。然后你的程序会崩溃。

更成问题的是，防止这种情况发生可能很困难。除非你将编译器配置为积极产生有符号/无符号转换警告（而且你应该这样做），否则你的编译器很可能甚至不会对此发出抱怨。

所有这些问题是常见的，会产生意外行为，并且很难发现，即使使用旨在检测问题情况的自动化工具也是如此。

鉴于以上情况，我们将提倡的一个颇具争议的最佳实践是：除非在特定情况下，否则避免使用无符号类型。

最佳实践

优先使用有符号数而不是无符号数来保存数量（即使数量应该为非负数）和进行数学运算。避免混合使用有符号数和无符号数。

那么何时应该使用无符号数？

在C++中，仍有一些情况适合/必须使用无符号数。

首先，在处理位操作时（将在第O章中介绍——注意是大写字母'O'，不是数字'0'），无符号数是首选。当需要良好定义的环绕行为时（在某些算法如加密和随机数生成中很有用），它们也很有用。

其次，在某些情况下仍然不可避免地要使用无符号数，主要是与数组索引相关的情况。我们将在关于数组和数组索引的课程中进一步讨论。

还要注意，如果你正在为嵌入式系统（如Arduino）或其他处理器/内存受限的环境开发，由于性能原因，使用无符号数更常见且被接受（在某些情况下是不可避免的）。
