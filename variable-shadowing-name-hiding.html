7.5 — 变量遮蔽（名称隐藏）

● 机器译文 课程 7.5 查看英文原文

每个块定义了自己的作用域区域。那么，当我们在嵌套块中有一个变量与外部块中的变量同名时会发生什么？发生这种情况时，嵌套变量在两者都处于作用域的区域中“隐藏”了外部变量。这被称为 名称隐藏 或 遮蔽。

局部变量的遮蔽

#include <iostream>

int main()
{ // 外部块
    int apples { 5 }; // 这里是外部块的apples

    { // 嵌套块
        // 这里的apples指的是外部块的apples
        std::cout << apples << '\n'; // 打印外部块apples的值

        int apples{ 0 }; // 在嵌套块的作用域内定义apples

        // apples现在指的是嵌套块的apples
        // 外部块的apples被暂时隐藏

        apples = 10; // 这将值10赋给嵌套块的apples，而不是外部块的apples

        std::cout << apples << '\n'; // 打印嵌套块apples的值
    } // 嵌套块apples被销毁


    std::cout << apples << '\n'; // 打印外部块apples的值

    return 0;
} // 外部块apples被销毁

如果你运行这个程序，它会打印：

5
10
5

在上面的程序中，我们首先在外部块中声明了一个名为 apples 的变量。这个变量在内部块中是可见的，我们可以通过打印它的值（5）来看到这一点。然后我们在嵌套块中声明了另一个不同的变量（也名为 apples）。从这一点到块结束，名称 apples 指的是嵌套块的 apples，而不是外部块的 apples。

因此，当我们赋值 10 切换到 apples时，我们是在给嵌套块的 apples赋值。打印这个值（10）后，嵌套块结束，嵌套块的 apples 被销毁。外部块的 apples 的存在和值不受影响，我们通过打印外部块的 apples (5)。

的值来证明这一点。注意，如果嵌套块的 apples 没有被定义，那么嵌套块中的名称 apples 仍然会引用外部块的 apples，所以赋值 10 切换到 apples 会应用于外部块的 apples：

#include <iostream>

int main()
{ // 外部块
    int apples{5}; // 这里是外部块的apples

    { // 嵌套块
        // 这里的apples指的是外部块的apples
        std::cout << apples << '\n'; // 打印外部块apples的值

        // 此示例中未定义内部块apples

        apples = 10; // 这适用于外部块apples

        std::cout << apples << '\n'; // 打印外部块apples的值
    } // 即使离开嵌套块，外部块apples仍保留其值

    std::cout << apples << '\n'; // 打印外部块apples的值

    return 0;
} // 外部块apples被销毁

上面的程序打印：

5
10
10

当在嵌套块内部时，无法直接访问来自外部块的被遮蔽变量。

全局变量的遮蔽

类似于嵌套块中的变量可以遮蔽外部块中的变量，与全局变量同名的局部变量会在局部变量作用域内遮蔽全局变量：

#include <iostream>
int value { 5 }; // 全局变量

void foo()
{
    std::cout << "global variable value: " << value << '\n'; // 此处value未被隐藏，因此指的是全局值
}

int main()
{
    int value { 7 }; // 隐藏全局变量value（只要局部变量value在作用域内）

    ++value; // 递增局部value，而非全局value

    std::cout << "local variable value: " << value << '\n';

    foo();

    return 0;
} // 局部value被销毁

这段代码打印：

local variable value: 8
global variable value: 5

然而，因为全局变量是全局命名空间的一部分，我们可以使用不带前缀的作用域运算符（::）来告诉编译器我们指的是全局变量而不是局部变量。

#include <iostream>
int value { 5 }; // 全局变量

int main()
{
    int value { 7 }; // 隐藏全局变量value
    ++value; // 递增局部value，而非全局value

    --(::value); // 递减全局value，而非局部value（添加括号以提高可读性）

    std::cout << "local variable value: " << value << '\n';
    std::cout << "global variable value: " << ::value << '\n';

    return 0;
} // 局部value被销毁

这段代码打印：

local variable value: 8
global variable value: 4

避免变量遮蔽

通常应避免局部变量的遮蔽，因为它可能导致无意中使用或修改了错误的变量，从而引发错误。一些编译器会在变量被遮蔽时发出警告。

出于与建议避免遮蔽局部变量相同的原因，我们也建议避免遮蔽全局变量。如果所有全局名称都使用“g_”前缀，这很容易避免。

对于 gcc 用户

GCC和Clang支持标志 -Wshadow ，该标志会在变量被遮蔽时生成警告。这个标志有几个子变体（-Wshadow=global， -Wshadow=local、和 -Wshadow=compatible-local。请查阅 GCC文档 以了解差异的解释。

Visual Studio默认启用此类警告。
