25.4 — 虚析构函数、虚赋值和覆盖虚化

● 机器译文 课程 25.4 查看英文原文

虚析构函数

虽然C++为你的类提供了一个默认析构函数（如果你没有自己提供的话），但有时你会希望提供自己的析构函数（特别是当类需要释放内存时）。你应该 总是 在处理继承时，将析构函数设为虚函数。考虑以下示例：

#include <iostream>
class Base
{
public:
    ~Base() // 注意：非虚
    {
        std::cout << "Calling ~Base()\n";
    }
};

class Derived: public Base
{
private:
    int* m_array {};

public:
    Derived(int length)
      : m_array{ new int[length] }
    {
    }

    ~Derived() // 注意：非虚（你的编译器可能会对此发出警告）
    {
        std::cout << "Calling ~Derived()\n";
        delete[] m_array;
    }
};

int main()
{
    Derived* derived { new Derived(5) };
    Base* base { derived };

    delete base;

    return 0;
}

注意：如果你编译上面的示例，你的编译器可能会警告你非虚析构函数（本示例中是有意为之）。你可能需要禁用将警告视为错误的编译器标志才能继续。

因为base是一个Base指针，当base被删除时，程序会检查Base的析构函数是否为虚函数。它不是，所以程序假定只需要调用Base的析构函数。我们可以从上面的示例打印的内容中看到这一点：

Calling ~Base()

然而，我们实际上希望delete函数调用Derived的析构函数（它会依次调用Base的析构函数），否则m_array将不会被删除。我们通过将Base的析构函数设为虚函数来实现这一点：

#include <iostream>
class Base
{
public:
    virtual ~Base() // 注意：虚
    {
        std::cout << "Calling ~Base()\n";
    }
};

class Derived: public Base
{
private:
    int* m_array {};

public:
    Derived(int length)
      : m_array{ new int[length] }
    {
    }

    virtual ~Derived() // 注意：虚
    {
        std::cout << "Calling ~Derived()\n";
        delete[] m_array;
    }
};

int main()
{
    Derived* derived { new Derived(5) };
    Base* base { derived };

    delete base;

    return 0;
}

现在这个程序产生以下结果：

Calling ~Derived()
Calling ~Base()

规则

每当你处理继承时，你应该将所有显式析构函数设为虚函数。

与普通的虚成员函数一样，如果基类函数是虚函数，所有派生类的覆盖都将被视为虚函数，无论它们是否被指定为虚函数。没有必要为了标记为虚函数而创建一个空的派生类析构函数。

注意，如果你希望基类有一个虚析构函数但其他方面为空，你可以这样定义你的析构函数：

    virtual ~Base() = default; // 生成一个虚默认析构函数

虚赋值

可以将赋值运算符设为虚函数。然而，与析构函数的情况（虚化总是好主意）不同，虚化赋值运算符确实会打开一个充满问题的潘多拉魔盒，并涉及本教程范围之外的一些高级主题。因此，为了简单起见，我们建议你现在保持赋值运算符非虚。

忽略虚化

极少数情况下，你可能希望忽略函数的虚化。例如，考虑以下代码：

#include <string_view>
class Base
{
public:
    virtual ~Base() = default;
    virtual std::string_view getName() const { return "Base"; }
};

class Derived: public Base
{
public:
    virtual std::string_view getName() const { return "Derived"; }
};

在某些情况下，你可能希望指向Derived对象的Base指针调用Base::getName()而不是Derived::getName()。为此，只需使用作用域解析运算符：

#include <iostream>
int main()
{
    Derived derived {};
    const Base& base { derived };

    // 调用Base::getName()而不是虚化的Derived::getName()
    std::cout << base.Base::getName() << '\n';

    return 0;
}

你可能不会经常使用这个，但知道它至少是可能的还是好的。

我们应该将所有析构函数设为虚函数吗？

这是新程序员常问的问题。如上面的示例所述，如果基类析构函数没有标记为虚函数，那么如果程序员后来删除一个指向派生对象的基类指针，程序就有内存泄漏的风险。避免这种情况的一种方法是将所有析构函数标记为虚函数。但你应该这样做吗？

很容易说“是”，这样你以后就可以将任何类用作基类——但这样做会有性能损失（每个类实例都会添加一个虚指针）。所以你必须权衡这个代价以及你的意图。

我们建议如下：如果一个类不是明确设计为基类，那么通常最好没有虚成员和虚析构函数。该类仍然可以通过组合使用。如果一个类被设计用作基类和/或具有任何虚函数，那么它应该始终有一个虚析构函数。

如果决定让一个类不可继承，那么下一个问题是是否可能强制执行这一点。

传统智慧（最初由备受尊敬的C++大师Herb Sutter提出）建议避免非虚析构函数内存泄漏情况如下：“基类析构函数应该是public和virtual，或者protected和non-virtual。”具有protected析构函数的基类不能通过基类指针删除，这防止了通过基类指针删除派生类对象。

不幸的是，这也阻止了 任何 基类析构函数被公众使用。这意味着：

  • 我们不应该动态分配基类对象，因为我们没有常规的方法来删除它们（有非常规的解决方法，但很糟糕）。
  • 我们甚至不能静态分配基类对象，因为当它们离开作用域时析构函数不可访问。

换句话说，使用这种方法，为了使派生类安全，我们必须使基类本身几乎无法使用。

现在 final 说明符已被引入语言，我们的建议如下：

  • 如果你打算让你的类被继承，确保你的析构函数是虚函数且公开的。
  • 如果你不打算让你的类被继承，将你的类标记为final。这将首先阻止其他类继承它，而不会对类本身施加任何其他使用限制。
